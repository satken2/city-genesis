> **パス表記の基準**: 本文中のパスはワークディレクトリ `S:/city/genesis`(`city-genesis` と `genesis-core` を並べた作業ツリー)を起点とする。`city-genesis` 単体で作業している場合は先頭の `city-genesis/` を読み替えること。`genesis-core/` 配下は非公開のコアシミュレータなので、手元に無ければその項目は読み飛ばしてよい。

このSkillは、素材の取り込みに伴う**出所確認とクレジット追記という必ず守るべき定型作業**を示す道しるべです。

## 前提: なぜ取り込みとクレジット追記を分けてはいけないか

フリー素材サイトの規約には「利用に際してクレジット表記が必要」と定めるものがある(CC BY 系、
Flaticon の無料ライセンスなど)。表記を欠いた状態での配布はライセンス違反であり、本作はSteamでの
**商用配布**を予定しているため、実害のあるリスクになる。

そして出所は**後から思い出せない**。素材をリネームしてしまえば配布元を辿る手掛かりが消え、
「クレジットが必要だったのかどうか」すら判定できなくなる。だから記録は取り込んだその場で行う。

掲載データの所在:

| 項目 | 場所 |
| --- | --- |
| 掲載データ(唯一の正) | `city-genesis/tauri/src/data/credits.ts` の `CREDIT_ENTRIES` |
| 作者名待ちのFlaticonアイコン | 同ファイルの `FLATICON_PENDING_SLUGS` |
| 描画コンポーネント | `city-genesis/tauri/src/components/taskbar/CreditsWindow.tsx` |
| 公開ドキュメント | `city-genesis/docs/docs/programs/素材クレジット管理.md` |
| プレイヤーからの到達経路 | 設定ウィンドウ →「情報」グループ → クレジット |

**クレジットウィンドウが扱うのは素材(アセット)だけ**で、ゲームエンジンやOSSライブラリは載せない
(許諾型ライセンスはライセンス条文全文の同梱で満たすため)。カテゴリは `bgm` / `sfx` / `image` /
`font` / `model` / `texture` の6つで、`CreditCategory` 型が正。

## 絶対にやってはいけないこと

- **自作の素材をクレジットに載せない。** クレジットは**他者の成果物を利用する際の出所表記**であり、
  自前のBlenderスクリプト・AI補助のジオメトリ生成・手描き等で作ったモデル・画像・音は表記すべき相手が
  いない。自作物を `CREDIT_ENTRIES` に入れると「外部素材」に見えて出所調査を混乱させる。
  制作記録は原本 `city-genesis/blender/*.blend` と `genesis-gallery`(非公開の制作ツール)のjobスクリプトに置く。
  AI生成物はクレジットではなく**Steamの開示記録**として別枠で扱う(後述)。
- **ライセンス名・作者名を推測で書かない。** 「たぶんCC0」「アイコンサイトだからFlaticonだろう」で
  `credits.ts` に書くと、誤った表記のまま配布され、かつ「確認済み」に見えてしまう。確認できない項目は
  フィールドを省略する(`author` や `license` は任意)。
- **`requiredText` を翻訳・要約・改変しない。** 「この文面のとおりに表記すること」が条件の素材があるため、
  規約が指定する文面は原文のまま入れる。同じ理由で、作者名・配布元名・ライセンス名も i18n に入れない
  (多言語化するのはカテゴリ見出しと項目ラベル `credits.*` だけ)。
- **出所不明のまま素材を取り込まない。** 後述のとおり、まずユーザーに尋ねる。
- **ブラウザの履歴を勝手に見ない。** 取得元URLの特定に有効だが個人データなので、参照する前に
  必ずユーザーの許可を取る(許可されたら `downloads` テーブルだけを見る)。

## 進め方

### 1. 素材ファイルから分かることを先に取る

リネーム済みでも、埋め込みメタデータに作者名や元ファイル名が残っていることが多い
(PNGの `tEXt`/`iTXt`、JPEGのEXIF、MP3のID3タグ、WAVの `LIST`-`INFO` チャンク)。
同梱スクリプトで一括抽出できる。

```
node city-genesis/.claude/skills/asset-credits/scripts/scan_asset_meta.js <対象ディレクトリ>
```

出力は `相対パス / バイト数 / 推定再生長 / 埋め込みメタデータ` のTSV。読み取り方:

- `TPE1` / `TIT2`(ID3)や `IART` / `INAM`(WAV)に**作者名・素材名がそのまま入っている**ことがある。
- **推定再生長は出所の照合に使える。** 配布サイトのページに載っている再生時間と一致すれば、
  リネーム・再エンコードされていても同一音源だと確定できる(WAVは正確、MP3はCBR前提の概算)。
- `tEXt Software=www.inkscape.org` と `eXIf` + JFIF は、**Flaticon配布PNG自体が持つ痕跡**である
  (Flaticon由来と確定済みのファイルと同じ署名)。自作の証拠ではないので誤読しないこと。

### 2. 出所が確定できないなら、必ずユーザーに尋ねる

**これは省略してはならないステップ。** メタデータやファイル名から配布元・作者・ライセンスが
確定できない場合は、`AskUserQuestion` でユーザーに尋ねる。尋ねる内容は具体的に:

- どの配布サイトから取得したか(候補を挙げる: Flaticon / Freesound / Pixabay / 自作 / AI生成 など)
- ライセンスは何か、クレジット表記が要求されていたか
- 自作かAI生成か(どちらも `credits.ts` には**書かない**。ただし**AI生成はSteamの開示対象**なので区別して記録する)

ユーザーも分からない場合は、**推測で埋めずに次のいずれかを提案する**。

1. ダウンロードフォルダに原本が残っていないか照合する(ハッシュ一致なら確定)。
2. ブラウザのダウンロード履歴で取得元URLを辿る(**許可を取ってから**)。
3. 画像なら画像検索、音声なら配布サイトでの試聴照合で特定する。
4. それでも特定できなければ**素材を差し替える**。出所不明の素材は表記の要否すら判定できず、
   商用配布のリスクを抱え続けることになる。差し替えコストは早いほど安い。

「分からないので空欄のまま取り込む」という選択はしない。

### 3. ライセンスを確認し、使用可否を判断する

配布元ごとの要注意点:

| 配布元 | 注意点 |
| --- | --- |
| Flaticon(無料プラン) | **作者名を含む表記が必須**。フォーマットは `designed by <作者名> from Flaticon`。ゲームの場合は**クレジット画面とストアページの説明の両方**に必要。作者名はアイコンごとに異なるので、アイコン単位で記録する。作者名が未確認のうちは `FLATICON_PENDING_SLUGS` に退避し、`CREDIT_ENTRIES` には入れない。有料プランで取得し直せば表記義務が外れる |
| Freesound | **音源ごとにライセンスが違う**(CC0 / CC BY / CC BY-NC が混在)。CC BY は表記必須。**CC BY-NC は商用利用そのものが不可なので採用しない** |
| Pixabay など規約変更歴のあるサイト | 取得日を `note` に残しておくと、後から「取得時点の規約」を説明できる |
| AI生成 | クレジット表記の義務は基本的に生じないが、**Steamのストアページでの開示対象**。クレジットとは別に記録する |
| 画像検索からの直接保存 | ストックフォトのプレビュー画像など**ライセンスを取得していない素材**が紛れ込みやすい。参考資料として保存したものを制作物へ流用していないか確認する |

**CC BY-NC(非営利限定)や、商用利用不可・再配布不可の素材は採用しない。** 見つけた時点で
ユーザーに報告し、差し替えを提案する。なお `city-genesis` は**公開リポジトリ**なので、
「ゲームに組み込んでいないが素材の原本をリポジトリに置く」ことも再配布に当たり得る。

### 4. credits.ts に追記する

`CREDIT_ENTRIES` に1素材=1エントリを足す。フィールドは `credits.ts` の型定義とコメントが正。

```ts
{
  title: "素材名またはセット名",
  category: "sfx",
  author: "作者名",
  source: "配布サイト名",
  url: "https://example.com/...",
  license: "CC BY 4.0",
  requiredText: "規約が指定する表記文面(あれば、原文のまま)",
  note: "使用箇所",
},
```

- **表記が不要な素材(CC0など)も、出所が分かっているものは載せる。** 後から規約が変わった場合や
  出所を問われた場合に追跡できるようにするため。必須な行だけを選り分けようとすると、判断ミスが
  即ライセンス違反になる。
- `url` を入れると見出しが既定ブラウザで開くリンクになる。
- 素材の追加と `credits.ts` の更新は**同じコミットにまとめる**。

### 5. 検証する

```
cd city-genesis/tauri && npx tsc --noEmit -p tsconfig.json && npx vite build
```

- カテゴリを増やした場合は i18n キー `credits.categories.<カテゴリ>` を**7言語すべて**に足し、
  `python tools/check_i18n_parity.py` を通す。
- 音声・画像をコードから参照するときは、**必ず `import` して得たURLを渡す**。
  `new Audio("src/assets/sounds/x.wav")` のようなパス文字列直指定はバンドル対象から外れ、
  開発実行では鳴るのに本番ビルドだけ無音になる。

## 知らないと絶対わからない注意点

- **Unity側の素材も同じクレジットウィンドウに載せる。** クレジットはゲーム全体のものなので、
  `city-genesis/unity/Assets` 配下の素材(効果音・テクスチャ等)も `credits.ts` に書く。
  UI側のデータファイルだが、UIモジュール専用ではない。
- **どこからも参照されない素材はビルドに入らない。** `city-genesis/tauri/dist` にファイルが
  出ているかで判定できる(4KB未満はJSへインライン化されるので、その場合はハッシュで照合する)。
  未使用ならクレジットは不要だが、**公開リポジトリに原本を置いたままにしない**こと。
- **ディレクトリ単位の出所メモは併存させてよい。** 例として
  `city-genesis/unity/Assets/Resources/Textures/README.md` があり、「コードがファイル名を前提に
  読み込んでいる」等の事情を併記できる。ただし**クレジットウィンドウに出す必要がある行は
  `credits.ts` にも書く**。
- Flaticon はボット対策があり、スクリプトからの連続アクセスは403で遮断される。作者名を機械的に
  集めたい場合はブラウザ経由で、間隔を空けて行うこと。
