# 交差点の回帰検証

`run-unity.ps1 -PlatformEnds` はホーム終端の独立検証。幅3m/5m・前後の接続線路・微小な左右ずれ・逆方向で床幅を維持し、実際の並走線路への侵入はクランプすることを確認する。実FBXで鉄道の車止め・端壁と、モノレール両側の端壁を検査する。

LandmarkPathsの吊り橋検証は、道路幅に比例する主塔の高さと奥行き、柱中心に合わせた主ケーブルの位置・直径も実FBXの生成頂点で確認する。

`run-unity.ps1 -StationHouse` は駅舎橋2001/2011の実FBXを本編生成器で描画し、32m・320m・2048mの両方向12ケースで著作高さの保持、クリック面との一致、道路用の区間LODに入らないことを検査する。長い橋では頂点数上限によるメッシュ分割後も同じ高さを保つ。

Unity でプロジェクトと C# プロジェクトを生成済みの環境で実行する。

```powershell
./run.ps1
./run-unity.ps1
./run-unity.ps1 -PavedModels
```

`run.ps1` は実際の Assembly-CSharp を使い、幅・角度・枝数・長さの162配置、断面境界、入力順序の不変性、切断前後の内部点の保持、保存された制御点を検査する。空間不足の配置は成功例と分けて集計する。

両スクリプトは共通の `Tests/BuildRuntime.ps1` で本編アセンブリを構築する。Unityの生成済みcsprojにまだ列挙されていないソースも、生成済みプロジェクトを書き換えずに検査へ含める。

`run-unity.ps1` は `Temp/IntersectionUnityQA` に独立した Unity プロジェクトを作り、実際の描画コードと FBX を読み込む。異幅・歩道の有無・壁・中央分離帯を含む傾斜した三叉路の本線と交差点の接合端を頂点比較する。路面の許容差は1mm、付属パーツは2mm。道路と線路の混在交差点、複線から単線への全軌道端の接続、レールメッシュ生成も検査する。マスターは検証用の値で、元データを変更しない。p1 にない付属パーツは検証用の箱を使う。

Unity のパスは生成済み csproj から取得する。必要なら `-UnityExe '.../Editor/Unity.exe'` で指定できる。元プロジェクトの Editor を閉じる必要はない。結果は検証用プロジェクトの `result.txt`、詳細は `qa.log`、三叉路の画像は `preview.png` に出力する。Unity の利用可能なライセンスとグラフィックス環境が必要。

`run.ps1` は高速道路の本線とランプ(G文書§11.7)も.NET上で検査する。並走・離れた並走・高さの異なる隣接・路面の重なりの結合判定、隙間の舗装の外端と壁の区間、ランプを本線の高さへ寄せて元の縦断へ戻す量と加わる勾配、合流ノードの板の有無(浅い角度の片側・両側のランプ、保存方向の反転、角度の大きい枝、工事中のランプ、折れた本線、一般道路、折れ線の仮ノード)とランプの切断位置、勾配のある本線の板の高さを確認する。

通常の `run-unity.ps1` は実FBXと本編生成器で高速道路の本線とランプも検査する(`MotorwayMergeQA`)。ランプ角12/25度・保存方向の反転・片側/両側の8ケースで板を作らない合流ノード、本線を切らないこと、ランプの切断位置、左右通行での進入車線を確認する。角度の大きいランプが残る5%勾配のノードでは板の本線部分が本線の縦断と一致することを確認する。並走してから合流するランプでは、本線とランプの間の壁の省略と合流区間外での復帰、隙間の舗装の位置と高さ、本線の路側線の点線区間とランプの本線側の路側線の非表示を確認し、描画例を `merge-top.png` と `merge-perspective.png` に出力する(この検証用プロジェクトは路面シェーダーを持たないので区画線は描かれない)。

この検査は全バリアント・全地形・全LODの検証ではない。近接ノードの統合や、異なる装飾モデル同士の完全な断面モーフィングは現状の対象外。

折れ線道路については、傾斜した90度のウェイポイントの角と、歩道なしでも壁が生成されることを検査する。

`-PavedModels` はp2のモデルを使う。路面高を含む歩道・ラインの原点補正と、歩道終端の幅がゼロにならず外縁中心の四分円を描くことも検査する。

`-Equipment` は道路設備用の独立検査。9バリアント×平地/上り15%/下り15%×両進行方向×架空/地中配電の108道路を実FBXと本編生成器で構築し、描画面の三角形から接地高さを比較する（点設備5mm、柵支柱の底面角2cmの許容差）。街灯の張り出しが左右とも道路内側へ向くこと、点設備のメッシュ下端の接地も検査する。テスト内の地形追従は無効にし、指定勾配を保つ。曲線全般や全地形・全LODを網羅するものではない。

`-Platforms` は451/452/461/462の実FBXを本編ホーム生成器で64m配置し、左右×両方向の16ケースでデッキとモデルの側、上屋柱4m・柵柱1.6mの周期を検査する。

`-Platforms` は実FBXの左右・支柱周期に加え、駅の共通標高のXZ射影、逆方向、地形再読込相当の再適用と、島式デッキの2cm高さ許容値を検証する。

小数の設計標高を相対Yへ変換する吸着、勾配上のXZ射影、複線横移動時の絶対標高保持もPlatformsで検証する。

Platformsは32m/256mの実軌道FBXで枕木の伸長・頂点数上限・分割部の隙間を検査し、接続先の有無による車止め配置とホーム端パネルも検査する。


`-RailYard` は1060の実FBXを本編の車両基地生成器で組み立てる。端子を前後・左右・境界へ移して、左右の斜め集約線が中央直線へ単調に近づくことと配置が全棄却されないことを検査し、空き部分のfloor不在・端子までのリード・外周フェンスの存在・端子前の開口を確認する。`rail-yard-preview.png` と `rail-yard-throat.png` を出力する。`-Platforms` は共用インフラ接続端に車止めがなく、反対側の通常終端には残ることも検査する。

設備検査は201の街灯・ボックス非表示と架空配線時の電柱・電線の存在、211/212の両進行方向での右側街灯、その他の両側街灯も確認する。201/211/212の道路幅(3/3/6m)と、歩道付きの221/222/231の全幅・歩道幅(12m/2.5m、24m/3m、24m/3m)は実マスターと同じ値を使う。専用の歩道モデルは実マスターの歩道幅で著作され、伸縮すると縁石幅も変わるため、別の幅では柵支柱が縁石に載る条件を実際と同じに検査できない。
# 植栽街路・レンガ高架・吊り橋の実FBX検証

吊り橋は桁厚（251=1.1m、252=1.3m、254/256=0.8m）、トラスの車線別有無と下端（3.2/4.2m）、主ケーブルの直径0.50mも実生成頂点から検査する。

`run-unity.ps1 -LandmarkPaths`は241・404・414・251・252・254・256を本編アセンブリと実FBXで組み立てる。中央分離帯の端部が道路内に収まり丸く閉じること、街路樹のなし設定と勾配上の接地、レンガ高架の6m/15mでの地盤接地、吊り橋の40m/160m/960mでの主塔位置とケーブル、各動的メッシュの頂点上限・有限座標を検査する。

初回だけ`-SyncLandmarkPrefabs`を追加すると、検証済みのFBXから本編のModelPrefabGeneratorでラッパープレハブを生成し、新規7種のResourcesへ取り込む。既存プレハブは上書きせず、GUID競合時は停止する。通常の検証はこのオプションを付けず、ゲーム資産へ書き込まない。

レンガ高架は交差するアーチの全体省略・幅広道路・上側道路・同標高・深いトンネル・移動/削除後の復帰と道床維持も検査する。近傍再生成の通知はTests/Pillars/run-unity.ps1で検査する。

RailYardは1064モノレール車庫も検査する。実FBXの架線不在・端子へのリード・細い単桁の曲線合流部の連続性を確認し、monorail-yard-preview.pngとmonorail-yard-throat.pngを出力する。

`-StationHouse` は全6駅舎×3通路方式×3長さ×2方向×3配置端の324ケースを検証する。地下は通路メッシュ・帯コライダーなし、他方式は実FBXの高さとクリック面の一致を検査する。共通通路の新規導入時は独立QA環境で `StationHouseQA.SyncPassagePrefabs` を明示実行できる（`-intersectionSourceRoot` で本編を指定）。既存ModelPrefabGeneratorを使い、GUID衝突時は停止する。
