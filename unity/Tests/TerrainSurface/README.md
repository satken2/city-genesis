# 地形と道路・floorの整合検証

`./run-unity.ps1` をPowerShellから実行する。Unityの実アセンブリをビルドし、`Temp/TerrainSurfaceQA` の独立プロジェクトで検証する。本編シーン・保存データ・マスターは変更しない。Unityのパスは生成済みcsprojから取得し、必要なら `-UnityExe` で指定する。

- 傾斜地の1m未満の異なる座標を逆順で問い合わせ、地形高さが問い合わせ順に依存せず実タイルの高さと一致することを検査する。
- 起伏のある地形に凹形状のfloorを生成し、敷地面積の保存と6,606点の内部高さを検査する。セル境界を跨ぐ配置も2,835点で検査する。
- 実Terrainとfloorを3段階のカメラ倍率で描画する。floor単独画像を参照マスクとし、被覆面の内部に地形色が現れないことを検査する。試験シェーダーは本編と同じ深度オフセット（地形+1,+1／被覆物−1,−1）を持つ単色シェーダーで、材質・照明を検証するものではない。
- 横断方向が水平な造成済み地形に、縦断方向の微起伏を与える。実RoadPathとSplineMesh、検証用bodyモデルで道路を生成し、全幅を4,695点で検査する。

数値検査の貫通許容差は1mm。結果は `result.txt`、描画画像は `floor-only-*.png`／`floor-terrain-*.png`、Unityログは `qa.log` に出力する。失敗時は非ゼロで終了する。

テスト地形では、従来の6m分割floorに約20cm、従来の道路中心線5m・Extrude2.5mに約36cmの貫通を再現する。また、Terrainの描画誤差を5に戻すと格子一致後のfloorでも描画上の貫通を再現する。

これは全マップ・全地形勾配・全道路バリアント・全描画バックエンドの保証ではない。バックエンドの造成範囲、異なる地形データのロード中の過渡状態、大規模都市でのGPU負荷は実ゲームで確認する。交差点の回帰検証は `../Intersections` を使う。
