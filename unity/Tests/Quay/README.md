# 埋立地の岸壁と港の検証

`./run-unity.ps1` を `powershell.exe -NoProfile -ExecutionPolicy Bypass -File` で実行する。`../BuildRuntime.ps1` で本編アセンブリをビルドし、`Temp/QuayQA` の独立プロジェクト（地形と物理の組み込みモジュールだけ）で batchmode の edit mode のまま検証する。本編のシーン・アセット・マスター・保存データは変更せず、`Temp` の外へは何も書かない。Unity のパスは生成済みの csproj から取得し、必要なら `-UnityExe` で指定する。所要は約1分。

結果は `Temp/QuayQA/result.txt`（先頭が `PASS checks=N` か `FAIL`）、Unity のログは `Temp/QuayQA/qa.log`。失敗時は非ゼロで終了する。幅の定数は本編 DLL の `Constants.QUAY_KEEP_WIDTH` / `QUAY_BAND_WIDTH` / `QUAY_PROBE_DISTANCE` / `SEA_GRADING_TOP` を読む。

## A. 地形の漏れ（帯の幅の根拠）

造成の完了時の地形の書き込み規則と、地形タイルの再標本化を鏡写しにしている（genesis-core の造成の完了処理と `terrain_surface.tile`。非公開。片方だけ変えない）。

- 書き込み: 埋立地の中（境界を含む）で、岸壁区間からの距離が `QUAY_KEEP_WIDTH` を超える 1m 格子点を天端の高さ（`SEA_GRADING_TOP`）にし、ほかは元の高さのまま残す。
- タイル: 500m のセルを 513 点（間隔 500/512m）で、1m 格子点の双線形で取り、float32 にする。Unity 側は `(h+200)/1200` で正規化する（`TerrainManager` と同じ）。検証用の Terrain は同じ間隔の 129 点の切り出し。

合成地形は 60×40m の矩形の埋立地で、奥の 12m が元の陸（天端より低い）、手前は −6m の海底から浜へ上がる。岸壁区間は海側の辺と、両側の辺の海岸線までの部分。角度 0/10/22.5/30/45/60/67.5/90°、格子の位相 4×4、タイル内の位置 2通りの 256 ケースを調べる。陸側の辺から 3m 以内（陸側の段差は仕様）は調べない。

- 実 Terrain（`TerrainCollider` のレイ。描画の最も細かい三角形と同じ）で、設定の幅のとき次を満たすこと（許容差 5cm。16bit の高さの量子化を見込む）。
  - 岸壁の外 4m 以内の高さが書き込みの前と変わらない（盛り上がりが漏れない）。
  - 岸壁から `QUAY_BAND_WIDTH` より奥の高さが天端の高さ（天端の先に溝が出ない）。
  - 帯の中の高さが天端の高さを超えない。
- 鏡写しの計算の高さが実 Terrain と一致すること（三角形の対角線は実 Terrain との照合で決める。現行は (0,0)-(1,1)）。
- 同じ計算で最小の幅を報告する。
  - 影響がまったく届かない幅（0.1m 間隔の点で調べた、256 ケースの最大）。
  - 高さの差が 5cm に収まる幅（9m の盛り土の段差で、0.05m 刻み。段差が大きいほど広く要る）。
  - 影響が最も遠くまで届く並び（岸壁の内向きの法線が三角形の対角線と同じ向きで、標本が格子点から 1/128m ずれた所）を作り、そこで要る幅。上限は「標本の対角線 + 格子の対角線 ≒ 2.795m」。設定の幅がこれを覆うこと。
  - 求めた最小の幅の組でも、実 Terrain で盛り上がり・溝が出ないこと。

描画の LOD（`heightmapPixelError`）で粗くなった遠景の三角形や、500m 以外のセル寸法は対象外。

## B. 岸壁メッシュ（`ReclaimedLandMeshBuilder`）

矩形、45°回転と平行移動、凹の L 字（内側の角の帯は円弧）、時計回りの入力、全周が岸壁の島（帯に穴）を検査する。

- 天端: 高さ `SEA_GRADING_TOP`、法線と面が上向き、面積が帯の多角形と一致し、頂点が帯の中。上からのレイは帯の中でだけ天端に当たる。
- 面: 各三角形がいずれかの区間の上の外向きの鉛直面。上端は天端、下端は外側 `QUAY_PROBE_DISTANCE` の地面から `WALL_FOOTING_DEPTH` 下（天端 − `WALL_MIN_HEIGHT` で頭打ち）。区間ごとの面積が列の台形の和と一致する（隙間が無い）。
- 同じ入力で2回作ると一致し、平行移動は頂点をそのまま動かし、回転・向きの反転で面積が変わらない。値はすべて有限。

## C. 港が埋立地の岸壁に面しているかの判定と、面していない港の直線カット

`PortBuildingMeshBuilder.FindFacingReclaimedQuays` と `PortBuildingMeshBuilder.BuildQuayFootprint`（private）をリフレクションで呼ぶ（名前と引数を変えないこと）。埋立地は [0,100]×[−50,0]、元の陸は z>0。

- 面している（区画が岸壁の陸側。埋立地の上の港）: 区画が岸壁を横切る（区画の中の部分だけが返る）、区画の海側の辺が南・東の岸壁に重なる（ぴったり・3cm 内陸・3cm 海へ張り出す）、区画の頂点の向きが逆。
- 面していない: 既存の港の隣の埋立（区画が東の岸壁の海側で辺を共有する。ぴったり・3cm の隙間・3cm の重なり。陸を含む港と海だけの港）、1m 離れている、角で1点だけ接する（矩形と、斜めの辺で元の海岸線を横切る港）、菱形の区画の頂点が岸壁に触れる、菱形の島の頂点が区画の角に触れる。
- 面していない港の直線カット: `CoastlineStore` に元の陸だけの海岸線と、埋立地を和集合した海岸線を順に入れて `BuildQuayFootprint`（突き出し最小）を呼ぶ。隣の埋立地が辺を共有する・3cm 離れる・発注検証が許す 0.008m² だけ重なる・1m 離れる・角で接する場合のいずれも、カット直線が元の海岸線 z=0 と平行で海（−z）を向き、岸壁フットプリントが埋立地の無いときと一致する。陸を含む矩形の港の岸壁フットプリントが [100,150]×[−8,20] になることも確かめる。

クレーンの配置とメッシュの組み立て（パーツの FBX が要る）は対象外で、実機で確認する。
