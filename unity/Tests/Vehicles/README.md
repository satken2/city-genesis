# 車両描画の回帰検証

路上駐車だけの検証は `./run.ps1 -ParkingOnly`。実FBX16外観を使い、接地・車種比率・整数台数と端数・満杯での頭打ち・左右通行/一方通行・歩道/交差点余白・狭幅・曲線と勾配・車体重複を検査する。実PathManagerキャッシュを使った取得後の経路では、同じversionで台数だけが増減するケース、変更なしの行列再利用、道路削除、都市クリアを確認する。HTTP通信自体はこのUnity検証には含まない。`Temp/VehicleUnityQA/parking-preview.png` は実FBXの満車配置を確認する独立シーンの画像で、本編都市のスクリーンショットではない。

`./run.ps1` で本編のC#をビルドし、独立した `Temp/VehicleUnityQA` のUnityから実アセンブリを検証する。本編のEditorを閉じる必要はない。Unityライセンスが必要。実行先は生成済みcsprojから取得し、必要なら `-UnityExe` で上書きする。

円と線分の交差・複数回進入、車線配置、通行方向、交差点の端点と接線、端点通過後の残り時間を検査する。環状路は1辺1/5/20分割を各20分相当走らせ、総台数とパス遷移数を測る。期待0.2台の端数枠、交通量を0へ変更した後の残留車の解消も確認する。

道路スナップショットはテストで注入する。API・地形ロード・全交差点の路面内への収まりは検証範囲外。結果は `result.txt`、Unityログは `qa.log` に出力する。

道路脇への退出は左右通行×前進/後退で90度旋回と道路外への移動を検査し、長時間走行でも退出途中に車が縮小せず、退出後だけフェードすることを確認する。

建物付き接道区画を実キャッシュへ登録し、高速道路・接道不可バリアント・非稼働建物を除外すること、入口への逆経路が全道路へ届くこと、不変データで表を再構築しないことを確認する。退出先のない閉じた環状路では交通量0になっても車を消さない。1000区画の人工データで入口更新の総時間・最大コルーチン処理時間も出力する（実都市の形状・ロード負荷を代表する保証はない）。

LRT・モノレールを含む全10車種46モデルのFBXをコピーし、標準のModelPrefabGeneratorでミラーを同期する。バスは両外観、メトロ・中距離・高速鉄道は3外観と各中間車、貨物は機関車3外観の実FBX参照先、接写・通常・遠景のLOD、実寸・接地中心を検査する。メトロ・中距離の先頭車は接写版の前頭部ガラスが前を向くこと、高速鉄道の先頭車は運転台窓が取り込み後も曲面(前後か左右の法線の広がり)を保つことも確認する。FBXを新しく足した直後の1回目は、ミラーの生成後に検査へ進まず終了することがある(result.txt が RUNNING のまま)。その場合はもう一度実行する。路線の選択外観(`vehicle_model`)が全編成に使われ、公共交通の折り返しでも維持されることを検証し、車両モデル設定を独立プロジェクトへコピーする。

歩行者(`PedestrianManager`)も同じ独立Unityで検証する。歩行帯の解決(歩道あり・歩道なしの路肩・歩行者専用道路・LRT付き歩行者専用道路303の軌道の両外側2帯)、反転しても同じ歩道に留まること、一方通行でも両方向に歩くこと、環状路(1辺1/5分割)を20分相当歩かせて総数と歩道帯内の横位置・高さを検査する。期待0.2人の端数枠は入口のある環状路で確かめる(入口を過ぎた歩行者は1周してから入るので、平均が収まるよう約8時間相当歩かせる)。建物付き接道区画の入口から歩行者が消えること、入口の無い閉じた環状路では交通量0でも歩行者を消さないことも確認する。`Assets/Models/Props/pedestrian_*.fbx` をコピーし、各モデルが400三角形未満・身長1.4〜2.0m・接地・水平中心であることを検査する。FBXの頂点分割を位置で戻して全辺が2面で逆向きに共有されること、三角形と法線の向きが一致すること、接続部位ごとの符号付き体積が正であることも検査する。

歩行姿勢は、各番号に揃い・`_right`・`_left` の3モデルがそろうこと、髪の部位の位置が揃い姿勢と1mm以内で一致すること(差し替えで体が跳ねない)、歩行姿勢の前後幅が揃い姿勢より0.2m以上広いこと、一番前の靴底が名前どおりの足(右=+X)にあることを検査する。`PedestrianManager.ResolvePose` で右足前→揃い→左足前→揃いの順序と半歩ごとの切り替え・停止中の揃いを、環状路の歩行では前進中の歩行者が歩行姿勢で描かれることを確かめる。1000人の `LateUpdate` の処理時間を、全員を揃い姿勢にした場合(描画呼び出しが姿勢で分かれない状態)と並べて出力する。バッチモードのメインスレッドの計測で、描画スレッドとGPUの負荷は含まない。

歩行者FBXだけの検証は `./run.ps1 -PedestrianModelsOnly`。移動・入口のフィクスチャを実行せず、6体×3姿勢の取り込みと形状、姿勢の選択、描画時間を検査する。

公共交通だけの検証は `./run.ps1 -TransitOnly`。走行時計・車両モデル・折り返しに加えて、共通経路の曲線/高さ追従、未ロード部分の非補完、ハイライトOFF相当での車両選択、遮蔽物・プール済み車両の除外、重複路線の候補・画面外の非選択を検査する。APIと実画面の吹き出し配置は対象外。

一般車・バスは、細かな起伏を持つ曲線で線分境界をまたぐ位置とピッチ・ヨーの連続性を検査する。一般車の路肩寄せ、左右通行・前進/後退、バスの公称車長と論理距離の倍率差、交差点前の車線寄せ、道路端の停留所で中心を維持して表示すること、実描画のバスが求めた姿勢を使うことも確認する。この検証は `-TransitOnly` にも含む。

モノレール(車種24)は実FBXの参照先・接写/通常/遠景のLOD(遠景は64三角形以内)と、手動配置プロップ308/309とのバイト一致を検査し、経路の高さが軌道桁の天端(鉄道よりレール頭頂の0.2m低い)になることを確かめる。`TransitLiveryQA.cs` は `transit_vehicle_livery.json` に登録した全車種・外観の先頭車と中間車で、帯の材質が接写・通常モデルにあること、路線色がそのスロットだけに塗られてFBXの共有材質を変えないこと、元の塗装へ戻せることを検査する。

貨物は同じ配置フィクスチャで3路線×3外観×2・3・4・6両を検証する。実FBX/3段階LOD、機関車1両と品目に合う貨車、機関車だけの着色、折り返しの位置・向き・個体の維持、15m/20mの公称長での連結、プール再利用・事前生成を確かめる。

`TransitConsistQA.cs`では1・2・3・6両を曲率半径70mの軌道と細かな起伏へ配置し、論理距離と描画長を異なる倍率にして車端の一致・連続フレームの位置と姿勢・奇数/偶数編成の折り返しを検査する。線分境界の横跳び、異なる距離倍率のパスを結ぶレール接続、接続端の連続性、未ロードの経路・未生成コネクタの非補完も確認する。経路は人工データで、本編都市の実画面や台車の接地を検証するものではない。

ドライブの検証は通常実行に含み、`./run.ps1 -DriveOnly`で関連部分だけを実行できる。自動車のユーザー分岐・直進既定・一方通行・到着予約免除と終了処理、走行中から選んだ車の扱い(到着予約を免除しない・終了後もNPCとして残る・消えたら外れる)、鉄道の開始時計逆算・往復の区別・折り返しで先頭の車両へ移ること・未ロード時の時計待機、編成番号つきの車両選択と時計を保った乗車、一人称の視点位置と三人称の地表からの高さ、カメラ位置/投影/ズーム/入力の復元を確認する。UIの実画面でのキー入力とIPC往復はこの検証の対象外。

道路車両は乗用車10・トラック4・バス2・商用バン2の候補数、各FBX参照先、実寸、接地を検査する。全18外観のLODGroupが接写・通常・遠景の3段階(閾値25%/3.5%)で各段が同じ外観のFBXを参照し、遠景が42三角形以内、接写が通常と同じ配置寸法、遠景が通常の高さの範囲内であることも確かめる。自由配置別名350〜367・370〜395もコピーし、全44組の頂点数・三角形数・寸法、接写と遠景(全別名)の元モデルとの一致、およびPropRenderModelの通常/遠景の描画部品と破棄を確認する。これらは `-TransitOnly` にも含む。
