# DataLoaders フォルダ

バックエンドから取得したデータをUnityのオブジェクトに変換する処理を定義する。
都市全体を一度に描画すると重すぎるため、マップをセル(一辺 `TerrainManager.CellSize`、バックエンドの `/terrain/settings` から取得)に区切り、カメラ周辺のセルだけを詳細に描画する。起点は `CellDataLoader.cs`。

## LODティアとロードの全体フロー(最重要)

セルにはカメラからの距離に応じて4段階のティアが割り当てられる(`LodConfig.cs`)。

| ティア | 距離条件 | 地形(データソース) | 建物 | 道路 |
| --- | --- | --- | --- | --- |
| Dynamic | 400m以内(+先読み100m) かつ **開放(acquire)済みセル** | `/terrain/dynamic` セル単位 | フル詳細 | フル詳細(地形追従) |
| Near | 1000m以内(+先読み100m) | `/terrain/near` BBOX指定 | フル詳細 | フル詳細 |
| Far | それ以遠で視野内(水平±150°) | 遠景キャッシュから切り出し(通信なし) | 白い箱 | 始点終点を結ぶ黒帯 |
| UltraFar | 視野外の遠方 | 陸地シルエットメッシュ(タイルなし) | 非表示 | 非表示 |

**地形タイル(Terrain)の解像度は全ティア共通で513**(`TerrainManager.TILE_RESOLUTION`)。ティアの違いは「タイルの解像度」ではなく「タイルに流し込むデータの世代(far/near/dynamicのどのマップ由来か)」であり、ティア変更は既存TerrainDataへの部分SetHeightsストリーミングだけで行われる(タイルの作り直しは発生しない)。**ティアダウン(Dynamic→Near等)では何もしない**(高精細データをそのまま保持する。`cellLodLevel` は「これまでに適用した最高の世代」)。フル詳細の建物メッシュ生成には視野ゲート+個数上限LRUがある(下記「建物」参照)。

- **`dynamicCells ⊂ nearCells ⊂ farCells` の包含関係**になっている。`farCells` が「ロード対象の全セル」を意味し、TerrainManager はこれを desiredCells として使う。
- **マップ範囲外のセルはロード対象に含めない**: 標高ソースはマップそのものであり、マップ外に地形データは存在しない。`LodConfig.CalculateCellSets` はマップ中心原点で有効な Unity セル index(`-mapWidth/(2*cellSize) <= x < mapWidth/(2*cellSize)`、Zも同様)の外にあるセルを走査段階で除外する。これをやらないと、マップ外セルは Near が404 → Far フォールバックで遠景マップ端値がクランプされ「標高0mの平らな偽地面」が描画されてしまう(防御として `TerrainManager.TryLoadFarResolutionCell` もマップ外セルで失敗を返す)。マップ外はタイルを作らず、下の海面板がそのまま海として見える。バックエンドの `/terrain/dynamic` もマップ範囲外セルには404を返す(未開放セルの404と同じ扱い)。
- 未開放セルには dynamic 地形データが存在しない(404)ため、`LodConfig.CalculateCellSets` の段階で Dynamic → Near に抑制される(開放済みセル一覧は `TerrainManager.FetchAcquiredCells` で取得)。

カメラ移動時のシーケンス:

1. `CameraCellChecker`(Scripts直下)が毎フレーム「カメラ視線中心が向いているセル」を判定。**地形コライダーではなく y=0 数理平面との交点**を使う(地形ロード→コライダー変化→再ロードのフィードバックループを断つため)。同じ新セルが3フレーム連続で検出されたときだけ確定(ヒステリシス)。
2. `CellDataLoader.OnCameraCellChanged` → `LodConfig.CalculateCellSets` でセルごとのティアを計算し、**ティアが変わったセルがある場合のみ**先へ進む。
3. `UpdateManagers`: 冒頭で **`LoadBatch`(`DataLoaders/LoadBatch.cs`)を新規発行し、進行中の旧バッチを `Cancel()`** する。その後 Building → Path → Parcel → Zone の順に各マネージャーの `LoadLodCells` を呼ぶ(それぞれマージBBOXの一括APIで取得。Building/Path/Terrain には `LoadBatch` 付きオーバーロードで同一バッチを渡す)。最後に `TerrainManager.LoadLodCells` を呼ぶ。この間、`PathManager.BeginDeferredTerrainTilePathRebuilds()` と `BuildingManager.BeginDeferredTerrainTileBuildingRebuilds()` で地形タイル生成イベントによる道路・建物再生成を抑制する(同じオブジェクトがセル枚数分再生成されるのを防ぐ)。また `UpdateManagers` 冒頭で、進行中の地形追従コルーチン(後述)があれば `StopCoroutine` でキャンセルしてから新しいロードを始める。
4. 地形の全セルのデータ適用完了で `TerrainManager.OnAllTerrainLodLoaded` が発火 → `CellDataLoader.OnTerrainAllLoaded(updatedCells)`。`updatedCells` は**このロードバッチで実際にハイトマップが適用されたセル**の一覧。これを `CellDataLoader.TerrainFollowUpCoroutine` で**複数フレームに分散**して処理する:
   - CPU高さ配列はハイトマップのストリーミング適用と同期して `TerrainManager` が `HeightmapTextureManager.WriteCellHeightRows` で**行単位に直接書き込む**ため、追従コルーチンでの差分更新は不要(初回ロード時と `ForceReloadAllData` 時のみ全量 `RebuildCpuHeightmap`。これもCPUキャッシュからの再書き込みで、GPU readbackは発生しない)
   - `BuildingManager.AdjustBuildingHeightsForCellsCoroutine(updatedCells ∩ nearCells)` で建物を地形に合わせ直す(Dynamicセルはフェンス・地面パネル地形追従のためメッシュ再生成、Nearセルなど、それ以外はY座標調整のみ)。**dynamicCells ⊂ nearCells のため、対象はNear以上の全ティア**。Farセルの白い箱は高さずれが視認できないため対象外
   - `PathManager.RebuildPathShapesForCellsCoroutine(updatedCells ∩ nearCells)` で道路メッシュを現在のティアで地形追従再生成
   - `PropManager.AdjustPropHeightsForCellsCoroutine(updatedCells ∩ nearCells)` でプロップ(装飾オブジェクト)のY座標を地表に合わせ直す(プロップはメッシュ再生成が不要でY再設定のみ)
   - 各ステップは `PerformanceConfig.FrameBudgetMs` を超えるたびに `yield return null` で次フレームに譲る
   - 完了後に後処理（初期ロード完了フラグの設定など）を実行

**重要: `OnAllTerrainLodLoaded` が「実際に更新されたセル」を渡すため、カメラがセル境界をまたいで可視セルの集合が変わっても、地形が実際に変化していないセルの建物・道路は再生成されない。** 地形不変のセル跨ぎでは追従更新がスキップされ、フレームヒッチ(カメラのカクつき)を防ぐ。`TerrainManager` はストリーミングワーカーが1セル分の適用を完了するたびに `updatedTerrainCellsThisLoad` に記録し、発火時にスナップショットして渡す。ティアダウンではデータを適用しないため記録もされない。

**つまり「地形がロードされたら道路と建物が地形追従する」のはこの 3→4 の2段階処理であり、地形より先に作られた建物・道路は一旦「古い高さ」で生成され、後から追従更新される。追従対象をDynamicセルに限定してはいけない(Nearセルの道路が地形に埋まったまま放置される)。**

**道路の一括ロード完了を待ってから追従する(初回同時ロードの競合防止)**: `TerrainFollowUpCoroutine` は建物・道路の再生成へ進む前に、`PathManager.IsLodBatchActive` が false になるまで待機する(CPU高さ配列の再構築の後)。地形と道路が同時にロードされる初回ロード(セーブ済み都市の起動直後など)では、道路の一括ロード(`LoadMergedPathsAndNodesAndApplyCells`)が地形適用より先に走り、道路が「まだ標高0の地形」を参照して生成されることがある。このとき地形ロード完了で走る追従コルーチンが一括ロードと並走すると、`PathManager.TryRebuildPathOnce` が「このバッチで生成済みの道路」を `lodBatchRebuiltPathIds` で**重複再生成スキップ**してしまい、地形追従の再生成が握りつぶされて誤った高さ(地面の道路が浮く/高架が地面に落ちる)のまま固定される。一括ロードが終わってから追従すれば `isLodPathBatchActive=false` となり、対象道路がすべて正しい標高で再生成される。一括ロードはカメラ移動でキャンセルされても `EndLodPathBatch`/`CancelActiveLodCoroutines` でフラグがリセットされるため、この待機は有界(無限ループしない)。

**協調キャンセル(`LoadBatch`)**: Unity の `StopCoroutine` は `StartCoroutine` で起動した子コルーチンを停止できない。`TerrainManager` の並行ロード(`RunParallelCoroutines`)のように子コルーチンを持つ処理は、`LoadBatch.IsCanceled` を yield をまたぐたびに確認して協調的に停止する。これにより、カメラ連続移動時に旧バッチの残骸(範囲外セルへの SetHeights 等)が新バッチと並走・競合しない。追従コルーチンがキャンセルで取りこぼしたセルは `pendingFollowUpCells` に残り、次回ロード完了時に再処理される。defer 中に破棄された `OnTerrainTileReady` のセルも `EndDeferred...` が返却し、`FinishTerrainFollowUp` が `pendingFollowUpCells` へ合流させる(防御的措置)。

## version差分更新の慣習

- 全マネージャー共通: オブジェクトごとにバックエンドの `version` をキャッシュし(`pathVersionCache` 等)、API応答のversionが同じなら**再生成をスキップ**する(非表示なら再表示するだけ)。
- ただし**HTTP取得そのものはカメラ移動や `ReloadAllData` のたびにBBOX内全件行われる**。versionはあくまで描画スキップ用。
- `CellDataLoader.ReloadAllData()`: 道路・建物・地区の作成/編集確定後に呼ばれる差分更新(カメラが動かなくても全マネージャーを更新)。
- `CellDataLoader.ForceReloadAllData()`: 全オブジェクトをDestroyして完全再取得。開放済みセル一覧も再取得する(しないと全セルが未開放扱いになりDynamicにならない)。

## 地形 (TerrainManager.cs)

- 標高データは **float16(LE) の生バイナリ**で受信し、`ProcessHeightmapAsync` がバックグラウンドスレッドで float[,] への変換・解像度補間(全タイル共通の513へ)を行う。
- **ハイトマップの適用はストリーミング方式(`HeightStreamWorker`)**: 補間済み配列は `ApplyHeightsStreamed` で適用リクエストとしてキューに積まれ、常駐ワーカーが「視野内かつカメラに近いセルから」1セルずつ直列に、57行のバンド単位の部分 `SetHeights` でフレーム予算(`PerformanceConfig.FrameBudgetMs`。カメラ移動ロック中は4倍)内に分割適用する。**新規セルは切り離されたTerrainDataへ不可視のままストリーミングし、完成後に `AttachTerrainTile` が専有フレームでGameObject化する**(コライダーの初期ベイクを他の処理と同一フレームに重ねない)。既存セルは可視のままの既存TerrainDataへin-place適用する(タイルの差し替えは発生しない)。旧実装の「フルSetHeights+コライダーベイクがセル数分同一フレームに積み上がる」ヒッチはこれで解消されている。**タイルの破棄は必ず `DestroyTerrainTileObject` を通す**(TerrainDataはGameObject破棄では解放されず、1枚約1MBリークするため)。
- **解像度リサンプリングは Catmull-Rom(3次)**: 生データ解像度が513と一致しない場合や、遠景ハイトマップを高解像度タイルへ引き伸ばす場合、`CatmullRomInterpolateArray`(`InterpolateHeightmapArray` / Far切り出し / UltraFar `sampleHeight` が使用)で平滑化する。バイリニアだと折れ面で遠方地形がカクつくため。Catmull-Romは格子点を必ず通るのでタイル境界の縁ブレンドは崩れない。オーバーシュート対策で正規化ハイトは `[0,1]` にクランプする。
- **`terrainSize.y`(既定1200m)は全セル共通の標高正規化スパン**: `ConvertFloat16BinaryToHeights` は `(標高 + SeaFloorDepthSpan) / terrainSize.y` で0〜1に正規化し `Mathf.Clamp01` するため、`terrainSize.y - SeaFloorDepthSpan` を超える標高は一律1.0に張り付いてフラットに描画される(山頂が台地状に潰れる)。マップごとの値ではなく `GameScene.unity` にシリアライズされたシーン共通の固定値なので、`terrain_maps.yaml` に最高標高がこの上限を超える地形マップを追加する場合は、シーンの `TerrainManager.terrainSize.y` と `TerrainManager.cs` のフィールド初期値の両方を引き上げること。
- **海底の水深(海面より下の負の標高)は `SeaFloorDepthSpan`(既定200m)で表現する**: バックエンドの `near_map`/`far_map` は海面を標高0とし、海岸線の外側は**負の標高(海底の水深)**を持つ(`terrain.py` の `compute_coastline_polygon` が標高>0を陸とする)。Unity Terrain のハイトマップは [0,1] しか持てず何もしないと負の標高が worldY=0 に潰れて海が水深0=平坦になる(深度ベースの水面シェーダー `Custom/WaterLit` で海が透明になる)。これを避けるため、`ConvertFloat16BinaryToHeights` は `(標高 + SeaFloorDepthSpan)/terrainSize.y` にオフセット正規化し、**地形タイルのベースYを `-SeaFloorDepthSpan` に下げる**(`AttachTerrainTile`)。これにより `worldY = ベースY + normalized×terrainSize.y = 実標高` が保たれ、海面(標高0)は worldY=0、海底は worldY<0(最深 `-SeaFloorDepthSpan`)として描画される。**このオフセットは正規化を読む全経路に一貫して反映すること**: CPU高さ配列 (`HeightmapTextureManager.WriteCellHeights` が `normalized×scale - SeaFloorDepthSpan` を格納)、UltraFar 陸地メッシュのサンプル高さ (`BuildUltraFarTerrain` が `×verticalSpan - SeaFloorDepthSpan`)、フォールバックの `Utils.GetGroundHeight` (`Terrain.SampleHeight + terrain.transform.position.y` でベースYを加味)。`terrainSize.y`(=1200)の内訳は「海面下 `SeaFloorDepthSpan` m + 陸地上限 `terrainSize.y - SeaFloorDepthSpan` m(=1000m)」で、`SeaFloorDepthSpan` を深くするほど陸地の高さ上限が下がる。陸地の道路・建物の高さ追従(実標高)は不変。
- dynamicセルは `/cell-versions` エンドポイントから一括取得したバージョン情報で差分管理（個別確認時は `HEAD` リクエストでのフォールバックも実施）。差分更新が必要なセルのみ `/terrain/dynamic` から `GET` でデータを取得する。
- **並行フェッチ**: `CheckAndRefreshDynamicTerrain`(既存dynamicセルの差分更新)と `LoadCellDataAtTier`(新規/強制/ティアアップセルのロード)は、`RunParallelCoroutines` で全セルのHTTPリクエストを同時発行し完了を一括待機する。ハイトマップの**適用**はストリーミングワーカーが直列化するため競合しない。
- **協調キャンセル**: `RunParallelCoroutines` の子コルーチンは `StartCoroutine` 起動のため、親の `StopCoroutine` では停止しない。各子コルーチン(`LoadCellDataAtTier` / `CheckAndRefreshDynamicTerrain` / `TryLoadDynamicTerrain` 等)は `LoadBatch.IsCanceled` を通信完了後・重い処理(補間)の直前に確認して自発的に停止する。ストリーミングワーカーは「開始前のリクエスト」のみキャンセルで破棄し、適用を開始したセルは原則完走する(裂けたハイトマップを画面に残さないため。残作業は高々9バンドで有界)。例外は不可視の新規タイルで、attach直前にもキャンセルを確認し、キャンセル済みバッチの残骸が範囲外セルへ孤児タイルとして登録されるのを防ぐ。dynamicセルのリフレッシュ(`RefreshDynamicTerrain`)が失敗・キャンセルした場合のみ、先行キャッシュされた `dynamicCellVersions` を取り消して次バッチで再試行させる(取り消さないと「versionは最新・タイルは古いまま」で恒久的に固まる)。ティアのフォールバック連鎖(Dynamic→Near→Far)がキャンセルによる失敗を「404フォールバック」と誤認しないよう、`LoadCellDataAtTier` は各段の後でバッチを確認して抜ける。
- **チラつき防止(可視のままのin-place更新)**: ティア変更・リフレッシュではタイルを差し替えず、可視のままの既存TerrainDataへ新データをストリーミング適用する。タイルが一瞬消えるフレームは原理的に存在しない。UltraFar沈み込みマスク(`UpdateLoadedCellMask`)は `terrainTiles` から構築されるので、ロード中もUltraFarメッシュの浮き上がりは起きない。`pendingDestroyTerrains`(1.5秒後に破棄)はアンロード(範囲外)専用の非表示退避で、こちらは従来通り(破棄は `DestroyTerrainTileObject` 経由)。
- **縁ブレンドは「後から適用する側が既存に合わせる」**: 隣接セル同士で適用済みデータの世代(far/near/dynamic)が異なると境界の標高が食い違うため、これから適用するハイトマップの縁を、既に画面へ出ている隣接タイルの縁の値(`originalHeightsCache`=適用済み配列)に合わせて最大6pxのブレンド帯で馴染ませる(`BlendEdgesTowardAppliedNeighbors`)。ただし、自分または隣接セルのいずれかが `Far` ティアの場合はブレンドを行わない（Farの粗い高さ情報が Near/Dynamic の縫い合わせに混入し、ティアアップ時に段差としてロックされるのを防ぐため。Far同士は同じ粗い遠景マップから滑らかにCatmull-Rom補間されているため、ブレンドなしでも境界の高さは完全に一致する）。適用済みタイルを後から触り直す再縫合は存在しない。GPU readback(`GetHeights`)も行わない。`originalHeightsCache` は「そのセルに現在適用されている縁ブレンド後の配列(=GPU上の内容と同一)」を保持する。
- `Terrain.SetNeighbors` は全タイルが同解像度のため常に全境界で機能する。張り直し(`UpdateNeighbors`)は新規タイルのattach時と「このバッチで適用されたタイル」起点で行う(アンロード側は `UnloadCell` 内の `UpdateNeighborsForAdjacents` が担う)。
- **CPU高さ配列はストリーミング適用と同期して更新する**: 可視タイルへのバンド適用のたびに `HeightmapTextureManager.WriteCellHeightRows` で該当行だけを書き込む(新規タイルはattach後にまとめて行スライスで書く。不可視のうちに書くと中断時に「地形が無いのに高さだけ残る」ゴーストになるため)。`TerrainData.GetHeights`(GPU→CPU同期readback)による読み戻しは行わない。全量再構築(`RebuildCpuHeightmap`)も `TerrainManager.ReplayHeightsToCpuHeightmap`(originalHeightsCache からの再書き込み)で行う。
- セルへのデータ適用完了ごとに static イベント `TerrainManager.OnTerrainTileReady` が発火する。PathManager / BuildingManager / ParcelManager が購読して高さ追従を行う(購読側は `Utils.InvalidateHeightCache()` を先に呼ぶこと)。CPU高さ配列は適用完了時点で更新済みのため、このハンドラは常に最新の高さを参照できる。
- **崖(急傾斜)は岩テクスチャのトリプラナーブレンドで描画する**: 地形シェーダー `Custom/DepthOffsetTerrainLit` は、傾斜(`1 - ジオメトリ法線のY成分`)が閾値を超えたピクセルに岩アルベド+法線マップをワールド座標3軸投影(トリプラナー)でブレンドする(実装は `Assets/Shaders/TerrainCliffRock.hlsl`)。**崖マスクの傾斜判定とトリプラナー投影の基準は、地面の法線マップで擾乱される前のジオメトリ法線を使うこと**(`_NORMALMAP` 有効時は `inputData.tangentToWorld` の第3行から復元)。擾乱後の `inputData.normalWS` で判定すると、法線マップの偏りが傾斜判定に乗って「同じ傾斜なのに特定の向きの斜面だけ岩化する(山の片側だけ岩)」方向依存バグになる。介入は**ライティング前**: `DepthOffsetTerrainLitMacroVariation.hlsl` が `Lighting.hlsl` を先にincludeしたうえで `#define UniversalFragmentPBR CliffTerrainFragmentPBR` のマクロトリックにより、URPの `TerrainLitPasses.hlsl` 内のライティング呼び出し(8引数オーバーロード、1箇所)をラッパーに差し替え、アルベド・法線・スムースネスを書き換えてから本来のライティングを呼ぶ。これにより崖にも太陽光の陰影・法線マップの凹凸が乗る(**ライティング後の色に単色をlerpする旧 `_TerrainSlope*` 方式は陰影が消えるため廃止**。TerrainManager の旧SerializeField `terrainSlopeThreshold` 等もフィールド名ごと廃止しており、シーンに残る旧シリアライズ値は無効)。岩テクスチャは `TerrainManager` の `cliffAlbedoTexture` / `cliffNormalTexture`(Inspector未設定時は `Resources/Textures/cliff-rock-albedo` / `cliff-rock-normal` を `EnsureCliffTextures` が自動ロード。CC0素材、出所は `Resources/Textures/README.md`)で、閾値・遷移幅・境界ノイズ・タイリング(m)・低地岩化の標高範囲(`cliffLowlandStartHeight`/`cliffLowlandFullHeight`)等は `Terrain Cliff Rock Settings` ヘッダのSerializeFieldから `ApplyTerrainMaterialSettings` 経由で全タイルに適用される。傾斜条件に加え**低標高の土地(海岸・浅瀬・海面下 Y<0)は傾斜に関係なく岩化する**(標高マスクと傾斜マスクを `max` 合成。開始標高から海面へ徐々にブレンドし海面下は一律岩)(`[ContextMenu] Refresh Terrain Materials` で実行中に再適用可能)。テクスチャが見つからない場合は単色フォールバック(`_CliffFallbackColor`)で動作継続する。Forward+のForwardLitパス専用で、GBufferパス・UltraFar陸地メッシュ(`DepthOffsetSimpleLitFar`)には適用されない(UltraFarは距離的に崖ディテールの効果が薄いため見送り)。なお `ApplyDefaultTerrainMaterial` は **`defaultNormalTexture` が `defaultDiffuseTexture` と同一の場合、法線マップとして使用しない**(シーンにカラーテクスチャが法線欄へ流用された設定ミスが残っており、これがTerrainLayerに渡ると `_NORMALMAP` が有効化されて地形全体の法線が一方向に傾くため。警告ログを出してスキップする)。
- **地表のスタイライズ表現(手続き的・テクスチャ追加なし)**: 地形シェーダー `Custom/DepthOffsetTerrainLit`(`DepthOffsetTerrainLitMacroVariation.hlsl`)は、単一テクスチャの露骨なタイリングを隠すため崖の岩ブレンドとは別に複数の層を持つ。いずれも `ApplyTerrainMaterialSettings` がタイルごとの `materialTemplate` に値を設定する。(0) **手続きベースアルベド**(地面の基本色を多スケールfbmで生成し拾い物テクスチャの反復を消す。大局モザイクで草↔乾いた土、細かい斑で明色を薄く混ぜる。`_ProceduralGroundBlend`(0=テクスチャ,1=完全手続き)/`_TerrainGroundColorA|B|C`/`_ProceduralGroundScale`、`Terrain Procedural Ground Settings`。**ライティング前(アルベド)**に適用し、崖岩ブレンドはこの上に lerp するので崖の非退行が保たれる)、(1) **マクロバリエーション**(3オクターブfbmで明度・ティントを大スケールに揺らす。`_TerrainMacroVariation*`、`Terrain Macro Variation Settings`。ポストライト)、(2) **カラーグレード**(標高・傾斜ベースの色ランプを最終色に乗算。傾斜は ddx/ddy で面法線を復元。`_TerrainColorGrade* / _TerrainLow|High|SlopeColor`、`Terrain Color Grade Settings`、強度0で無効。ポストライト)、(3) **平地の手続きディテール法線**(ワールドノイズ勾配でライティング前の法線を微小に傾ける。法線マップ不使用。急斜面は平坦度で弱め崖岩法線と競合させない。`_TerrainDetailNormal*`、`Terrain Detail Normal Settings`、強度0で無効)。これらは全て**新規SerializeFieldのためシーンに値が無くコード既定値が反映される**。加えて `defaultSmoothness` を完全マット(0)から弱スペキュラ(0.15)へ上げているが、**これは既存フィールドでシーン(`GameScene.unity`)にシリアライズ済みのため、シーン側の値も更新しないと反映されない**(コード既定値だけ変えても効かない)。プレライティングフックの実行順は 手続きベースアルベド→ディテール法線→崖岩ブレンド。仕様の正は `genesis-docs/docs/geometries/E_LOD処理.md` の「地表のスタイライズ表現」節。
- **開放セル境界の点線オーバーレイは変化時のみ再構築する (`UpdateCellOverlayIfActive`)**: `IsUnlockOverlayActive` は `Start` から常時ONで、開放済みセルの外枠点線を `OverlayMeshRenderer`(ワールド固定幅の点線)で描く。このジオメトリはカメラ非依存の静的メッシュなので、`borderSegmentsDirty`(acquiredCells更新・タイルReady時に立つ)や `ShowCellBordersAndLabels` の変化があったフレームだけ `RebuildBorderSegments`＋`BeginFrame`〜`EndFrame` を回す。カメラ静止・入力なしのアイドル時に毎フレーム同じメッシュを作り直してGPUへ再アップロードするのを避けるための最適化。
- Unityセルインデックス(負値あり・マップ中心原点)とバックエンドセル(0-based・左下原点)の変換は必ず `UnityCellToBackendCell` / `BackendCellToUnityCells` / `WorldPositionToBackendCell` を使う。
- **海岸線(陸地境界ポリゴン)**: `TerrainManager.FetchCoastline` が `GET /terrain/coastline`(GeoJSONライク Polygon/MultiPolygon、ワールド座標)を取得し、静的ストア `CoastlineStore`(`DataLoaders/CoastlineStore.cs`)に格納する。`FetchAcquiredCells` の末尾から呼ばれるため、セッション開始時(建物ロードより前)に一度ロードされる。海岸線は far_map ベースで init_game 時に確定し以降不変。港湾の岸壁メッシュ(`PortBuildingMeshBuilder`, MODEL_PORT)が「底面のどの辺が海岸線に接しているか」の判定(`CoastlineStore.IsNearCoastline`)に使う。また超遠景の陸地メッシュ生成(`UltraFarLandMeshBuilder`)が `CoastlineStore.IsLand`(全リングへの even-odd 点内判定) / `SignedDistance`(符号付き距離) / `TryGetBounds` で陸地形状をクリップする(下記参照)。
- **海面オブジェクトと深度オフセット**: 海面はTerrainManagerが管理しない板ポリゴン(`Sea`)で、シーンのワールドY≈0に手動配置されている。per-cellタイルのベースYは `-SeaFloorDepthSpan`(上記の海底表現)だが、標高0m(海面)は worldY=0 に写像されるため、海岸線ぎわ(標高≈0)では地形と海面板が同深度となり何もしないとZ-fightingする。深度の階層は次の通り: per-cell地形 `Custom/DepthOffsetTerrainLit`(`Offset 1,1`)、**超遠景陸地メッシュ `Custom/DepthOffsetSimpleLitFar`(`Offset 4,4`) ＜最奥**。海面は下記の半透明水シェーダー `Custom/WaterLit` で描画し、`Offset -1,-1`(手前寄せ)を残置している。海面板のマテリアルは `Resources/SeaMaterial.mat`。
- **海面(と湖面)は半透明の水シェーダー `Custom/WaterLit`**: 実装は `Resources/Shaders/WaterLit.shader`(パス定義)＋ `Assets/Shaders/Water.hlsl`(本体)。1つの ForwardLit パス(Transparentキュー・`ZWrite Off`・`Blend SrcAlpha OneMinusSrcAlpha`・`Offset -1,-1`)で以下を行う: ①プロシージャルノイズ(fbm)の高さ場から生成する時間スクロールする**さざ波法線**(テクスチャ不要・タイリング継ぎ目なし)、②シーン深度と水面深度の差(水柱の厚み)による**浅瀬↔深海の色**、③水柱が薄いピクセルの**岸フォーム**(アニメ泡ノイズ)、④`_CameraOpaqueTexture` を波法線でずらす**屈折**(前景を吸わないよう深度ガード)、⑤アルベド=体色・低メタリック・高スムースネスで `UniversalFragmentPBR` を呼ぶことで得る**フレネル反射(空の映り込み)と太陽グレア**。**屈折・深度色は URP の Depth/Opaque テクスチャに依存する**(`PC_RPAsset` は `m_RequireDepthTexture=1`/`m_RequireOpaqueTexture=1`。無効化するとこれらが効かなくなる)。**Z-fight回避は「半透明+水際の深度フェード(`_EdgeFadeDistance`)」が担う**ため、不透明時代のように負Offsetだけに依存しない(ただし水面Y=0と標高0地形の同深度で水側を優先させるため `Offset -1,-1` は残す)。パラメータ(色・深度応答・泡・屈折・波)は `SeaMaterial.mat` の SavedProperties から調整する。旧 `Custom/DepthOffsetLit`(不透明URP Lit + 負Offset)は WaterSurfaceManager のフォールバック経路が参照するため残置。
- **超遠景(UltraFar)は陸地シルエットメッシュ**: UltraFarは Unity Terrain ではなく、海岸線ポリゴンから生成した陸地メッシュ(`UltraFarLandMeshBuilder` / `TerrainManager.BuildUltraFarTerrain`、フィールドは `ultraFarLandObject`/`ultraFarLandMesh`)。海(陸地外)はメッシュを作らず、既存の海面板がそのまま海を担うため、突き抜けやZ-fightが原理的に起きない。生成: 陸地AABBをグリッド(既定80m, `ultraFarGridStep`)に切り、`CoastlineStore.SignedDistance` の符号反転位置を補間するマーチングスクエア的クリップで陸地ポリゴンを切り出し(海岸線がグリッドより細かく滑らかに出る)、頂点Yは far_map 高さで粗い起伏を付け、`ultraFarHeightOffset`(既定1m)持ち上げる。メッシュは `Custom/DepthOffsetSimpleLitFar`(Offset 4,4)で per-cell・海面より奥に描き、per-cellタイルと同じ地面テクスチャをワールドXZ座標UV・同タイリングで貼る(**法線マップは設定しない**。カラーテクスチャが `_BumpMap` に流用されると不正な法線で陰影が濁るため)。**頂点法線は `UltraFarLandMeshBuilder` が位置溶接済みのスムース法線を返す**(`Mesh.RecalculateNormals` は重複頂点を溶接せずセル境界でファセット状の陰影になるため使わない。面積重み付き面法線を同一XZ位置へ集約して正規化)。UltraFarメッシュは far_map 由来の粗い起伏を持ち、near_map 由来の Near/Dynamic タイルとは起伏の激しい場所で数十mずれてタイルの上に突き出るため、**「タイルがロード済みのセル」を1セル=1テクセルのR8マスク(`_LoadedCellMask`、`UpdateLoadedCellMask` が毎フレーム更新)でシェーダーに渡し、該当セルの頂点を `ultraFarSinkAmount`(既定100m)沈めて隠す**(タイルの無いセルは沈めないので海色の穴は開かない)。未開放セルの暗色表示は三角形を開放/未開放の2サブメッシュに分け、未開放サブメッシュの `_BaseColor` に `unacquiredTint` を乗算して「同じ地面を少し暗くした」見た目にする(`RefreshUltraFarLandOverlay`)。per-cellタイル側の暗色化は地形シェーダーの `_TerrainTint`(タイルごとにクローンされる materialTemplate に `ApplyUnlockOverlayToTerrain` が設定。`Terrain.basemapDistance` は実質無効化して遠方でもカスタムシェーダーを使う)で同じ `unacquiredTint` を乗算するため、ティア境界でも未開放の見た目が揃う。表示OFF時は全域が通常色に戻る。**なお以前はUltraFarをマップ全体1枚の解像度33 Unity Terrainで表していたが、(a)粗い地形が海面板を突き抜ける、(b)突き抜け回避でベースY=-10に下げると海岸線が後退する、という根本的トレードオフがあり、メッシュ方式に置き換えた。** 海岸線未ロード(海岸線なしのマップ)時は全域を陸とする平坦メッシュにフォールバック。詳細は `genesis-docs/docs/geometries/E_LOD処理.md` の「超遠景（UltraFar）の陸地シルエットメッシュ」節参照。
- **海面の入力扱い**: Seaは `Terrain` コンポーネントを持たないため、素の状態では `InputHandler.GetObjectType` が TERRAIN 扱いせずクリックが無反応になる。これを解決するため Sea には **`SeaObject` タグ**を付与し、`InputHandler.Start` が実行時に `TerrainInputHandler` を AddComponent する。`GetObjectType` は `SeaObject` を `InputObjectType.TERRAIN` に振り分ける。詳細は `InputHandlers/AGENTS.md` の「海面(Sea)のクリック扱い」節参照。
- **海面以外の水面(湖など)は `WaterSurfaceManager`(`DataLoaders/WaterSurfaceManager.cs`)**: `GET /terrain/water` から水面ポリゴン一覧を取得し、各ポリゴンを `water_level`(絶対Y標高、海面=0)の水平メッシュとして生成する(`AfterSceneLoad` で自己生成する常設マネージャ)。三角形分割は `BuildingMeshBuilder.TriangulateOrFan`(外周のみ。穴付きポリゴンは現状未対応で警告ログ)。頂点はバックエンドのワールド座標をそのまま持ち(UltraFar陸地メッシュ・海面板と同じ座標系)、法線が +Y になるよう巻き方向を反転する。マテリアルはシーンの海面(`SeaObject` タグ)から `sharedMaterial` を借用して見た目を揃える(通常は上記 `Custom/WaterLit`。借用できなければ `Custom/DepthOffsetLit` の不透明フォールバックを生成する — この経路では屈折・深度色・波は出ない簡易表示になる)。生成した水面には `SeaObject` タグと `VisualSeaObject` を付け、地形の透過・非表示モードに海面と同様追従させる。`TerrainManager.FetchCoastline` の末尾から `WaterSurfaceManager.Instance.LoadAndBuild()` が呼ばれ、セッション開始時・全量リロード時に取得・再生成される(水面はマップ固有の静的データ)。仕様の正は `genesis-docs/docs/geometries/D_地形形状.md §D.10` と `E_LOD処理.md`。

## 道路 (PathManager.cs) — 知らないと事故るポイント

- **ノードキャッシュの実変更カウンタ `NodeDataVersion`**: ノードの新規追加・位置/タイプの実変更・削除があった場合にのみインクリメントされる公開カウンタ(カメラのセル跨ぎ再取得は大半が無変更のためインクリメントしない)。ノードは編集モード進入後にも非同期ロードで到着するため、`RoadPlanManager` が背景オーバーレイ(既存ノード表示)の再構築判定にポーリング比較で使う。ノード削除時(`SyncNodesInCells` / `SyncNodesInCell`)は `nodeGrid`(空間ハッシュ)からも必ず除去すること(残すと削除済みノードへ吸着してしまう)。
- **インフラ施設の接続端子ノードの識別は BuildingManager の逆引きで行う**: ノードAPIは所属施設(owner)を公開しない「agent→nodeの片方向参照」の設計のため、`NodeData` に所属施設のプロパティは無い。端子判定は `BuildingManager.TryGetInfraTerminalOwner(nodeId)`(建物側の `infra_node_id` から構築する逆引きインデックス)を使う(`CreateOrUpdateNode` の NodeInputHandler 付与・道路エディタの端子マーカーが使用。なおノードが「インフラノードか」自体は `type` にインフラ財ビットが立っているか=`InfraNetworkUtil.IsInfraMask` で判定できる)。
- ノードとパスはマージBBOXで一括取得(`LoadMergedNodes` / `LoadMergedPaths`)。パスのティアは `DeterminePathLodTier` が「そのパスが覆う全セル」の最高ティアで決める(セル跨ぎ対応)。通過セルは登録済みキャッシュ `pathCellsById` を参照する(`GetPathCoveredCellsCached`)。**version が変わったパスは形状が変わった可能性があるため、`RegisterPathCells` でキャッシュを更新してからティア判定すること**(LoadMergedPaths のフェーズ2はこの順序になっている)。
- **交差点接続パスのO(1)ルックアップ**: 交差点更新時の全パス線形走査を避けるため、`pathsByNodeIndex`（ノードID -> 接続パスIDのHashSet）インデックスが維持されている。キャッシュへの追加・削除は必ず直接 `pathDataCache` を操作せず、`SavePathToCache` / `RemovePathFromCache` ヘルパーを通すこと。
- **地形更新時の全件走査回避**: 地形Ready時に交差するパスを再生成する `OnTerrainTileReadyHandler` では、`pathSegmentsByPathId` の全件走査を避け、すでに通過セル情報を持っている `pathIdsByCell` から影響を受けるセルのパスIDのみに絞り込んでセグメント判定を行う。
- **地形更新起因のパス再生成は視野優先・フレーム予算制のキューで行う**: `OnTerrainTileReadyHandler` はハンドラ内で同期一括再生成せず、`queuedTerrainFollowPathIds` へ積む。常駐ワーカー `TerrainFollowRebuildWorker` が「視野内かつカメラに近い」パスから順に、再生成時点の現在ティアで `TryRebuildPathOnce` する(ロード範囲外に出たパスは再生成しない)。地形ロード完了後の一括追従 `RebuildPathShapesForCellsCoroutine` も、対象パス・交差点ノードを視野優先スコアで昇順ソートしてから処理する(1本の再生成が重く1フレームに1〜数本しか進まないため、「カメラに映っている道路から地形に馴染ませる」順序が体感品質を決める)。
- **交差点と道路端の相互依存**: ノードごとに `NodeMeshFactory`(→`RoadIntersectionMeshGenerator`)が交差点ポリゴンを生成し、`ConnectionPoints`(各接続道路の切断点)を返す。PathManager はこれを `pathStartConnectionPoints` / `pathEndConnectionPoints` にキャッシュし、`CalculatePathPoints` が道路の端点をこの切断点に差し替える。切断点が変わった道路は再生成される。
- **LOD一括更新中(`isLodPathBatchActive`)の遅延処理**: 上記の依存関係のため、一括ロード中は交差点更新を `deferredLodIntersectionNodeIds`、交差点由来の道路再生成を `deferredIntersectionPathRebuildIds` に積み、全パスのデータキャッシュが揃った後のフェーズで処理する。`lodBatchRebuiltPathIds` で同一パスの重複再生成を防ぐ。**この仕組みを迂回してロード中に直接 `CreateOrUpdatePath` を呼ばないこと。**
- 道路の形状計算(`CalculatePathPoints`): すべて三次ベジエ。制御点が未指定のアンカーは Catmull-Rom 接線(`T_i = P_{i+1} − P_{i-1}`、テンション1/6、端点は片側接線。ウェイポイントなしは1/3・2/3内分=直線)から自動計算する。**これはバックエンド `Path._auto_fill_controls` と同一ロジックであり、変える場合は両方変える**(バックエンドは作成・形状更新時に未指定の制御点を同式で埋めて永続化し、ウェイポイントの制御点はAPIの`waypoints`で、端点の制御点は`start_control`/`end_control`で返す。Unityは保存値を優先使用し、無い場合のみ自前計算にフォールバックする。端点制御点の読み取りは`PathSummaryExtensions.GetStartControlList/GetEndControlList`=リフレクション方式で、endpoint_schemasシート未更新でもコンパイルが落ちない。絶対座標化は制御点直下ではなく所属アンカー直下の地形標高を基準にする=`EndpointControlToWorld`/`PathWaypoint.GetControlInAbsolute`)。約5m間隔(`TERRAIN_SAMPLE_INTERVAL`)でサンプリングし、相対Y=0 の区間は各サンプル点を地形高さ+`RoadPartHeights.ROAD_SPLINE_OFFSET`(0.1m)に追従させる(Y座標の考え方はルートAGENTS.md参照。道路パーツの高さオフセット体系は `MeshGenerators/Paths/RoadPartHeights.cs` に集約されている)。交差点の切断点も同じ基準面のYで返ってくる。ノードの相対Yは `UpdateNodeIntersectionMesh` が `NodeMeshFactory.GenerateNodeMesh` へ渡し、高架ノードの交差点は水平面モードで生成される(MeshGenerators/AGENTS.md参照)。交差点歩道コネクタの実体化は `RoadPath.CreateSidewalkConnectorObject`(共通静的メソッド)を使う。
- **線路ノード(ポイント・平面交差)のレールコネクタ**: `NodeMeshResult.RailConnectors`(転回制約を満たす通行可能な線路ペアにのみ計算される。MeshGenerators/AGENTS.md の「線路」の節参照)を `UpdateNodeRailMesh` が NodeMesh の子 `Rail` として実体化する(`TrackPath.CreateRailConnectorObject`)。歩道コネクタ(`UpdateNodeSidewalkMesh`)と同じ「全破棄→作り直し」の差分方針。
- **近接線路の結合描画(複線見え化)の隣接供給と無効化**: `Awake` が `TrackAdjacency.NeighborProvider = GetAdjacentTrackNeighbors` を設定し、TrackPath へ近接候補線路(通過セル+隣接セルの同種線路。工事中除外)の点列(`pathPointsCache`、無ければ `CalculatePathPoints`)と幅を供給する。線路の**データ変更**(LoadMergedPaths フェーズ2の version変化/新規、SyncPathsInCells の削除)時は `EnqueueAdjacentTrackNeighborRebuilds` が近接線路を `pendingTrackNeighborRebuildIds` へ積み、LODバッチ外なら即時・バッチ中なら `EndLodPathBatch` 時(このバッチで生成済みのパスは除外)に `queuedTerrainFollowPathIds` へ流して TerrainFollowRebuildWorker に再生成させる。**並走線路自身の version は変わらないため差分更新では描き直されない**のを補う仕組みで、再生成はデータを変えないため連鎖しない。削除時のエンキューは通過セルキャッシュを参照するため `UnregisterPathCells` より前に行うこと。
- **都市共通設定のストア(`CityInfoStore.cs`)**: `GET /api/v1/city` の `traffic_hand`(通行方向。ゲーム開始後不変)を保持する静的ストア。`PathManager.Start` が `EnsureLoaded(this)` で一度だけ取得する。駅パスのプラットフォーム設置側(platform_side の内側/外側→左右の解決。`TrackPath.ResolvePlatformExtents`)が参照する。取得前・失敗時は既定の左側通行として動作する(車両描画の VehicleManager は自前取得で独立)。
- `curved=false` でウェイポイントを持つ道路は、角を交差点と同じロジックで切断して別メッシュで埋める(`RoadPath.GenerateLinearPathWithCorners`)。**線路(TrackPath)は角の切断・充填を行わず、Broken点の1本スプラインとして描く簡易表現**(線路は通常 curved=true で敷設される想定)。
- セル跨ぎの道路を誤って非表示にしないため、アンロード時は `cellsToKeepVisible` / `pathCellsById` を参照する。アンロードは Destroy ではなく `SetActive(false)`(プーリング)。
- 接続パスが揃わず交差点を作れなかったノードは `awaitingIntersectionNodes` に記録され、後からパスが追加された時に自動再評価される。
- **交差点の接続パス数には防衛的上限がある (`MAX_INTERSECTION_CONNECTED_PATHS`=32)**: 交差点ポリゴン計算(`IntersectionPolygonUtil`)は接続パス全ペアのO(N²)処理のため、バックエンドのデータ異常(1ノードに大量のパスが接続)でメインスレッドがフリーズする。上限超過ノードは交差点メッシュを生成せずエラーログ(ノードごとに1回)を出し、`awaitingIntersectionNodes` にも積まない。
- **地下パス／非追従パスの描画区間分割**: `CreateOrUpdatePath` は `UsesTunnelMesh`（=`IsUndergroundPath` または「実効非追従(`GetPathFollowTerrain(path)`=false)かつ`HasTunnelSection`」）が真のパスを `GenerateUndergroundPathMesh` へ分岐し、点列を `TunnelSectionUtil.SplitDrawableRuns(points, clearance, portals, GetPathFollowTerrain(path))`（深さ=現在地形標高−道路Yがマスターの `height` を超える区間を除外）で分割して区間ごとにメッシュ生成する。トンネル区間はメッシュ・コライダーなし、境界には `portal` パーツを配置。**相対Y=0の非追従パスも丘に潜れば同じ分割対象になる**（谷を渡るだけの非追従橋はトンネル区間が無いので通常メッシュ＝柱付きで描く）。Farティアは `IsUndergroundPath` に加え `FarPathHasHiddenTunnel`（端点直線がトンネル区間を持つ非追従パス）も非表示にし、谷渡りの非追従橋は直線ストリップを描く。掘削は着工時にバックエンドが行い、地形リロード後の再生成で開削区間が自動的に描画対象へ変わる（バックエンド `geo_path_depth.py` の `path_uses_depth_classification` と同一の分類定義）。実効地形追従の解決は `PathManager.GetPathFollowTerrain(PathSummary)`（パス個別`follow_terrain`優先→バリアント既定）で、バックエンド `path_follows_terrain` と一致させる。
- **工事中(STATUS_CONSTRUCTING)パスの専用表示**: `CreateOrUpdatePath` は工事中のパス（`model_type=none` を除く全パス種。線路含む）を `GenerateConstructingPathMesh` へ分岐し、完成パーツの代わりに「土ストリップ(`ConstructionMeshUtil.BuildDirtStripMesh`。相対Yを無視して常に地表に盛る) + 高架の柱のみ(`RoadPath.GeneratePillars`) + トンネル坑口のみ(`PlaceTunnelPortals`。区間分割は地下パスと共通)」を生成する。進捗による見た目の変化はなく、status 変化でプール再利用条件が外れて必ず再生成されるため完成時は自動的に通常メッシュへ戻る。マテリアルは `Resources/ConstructionDirt`(建物の土マウンドと共用)。旧仕様の黄色マテリアル上塗り(VisualModeObject)は廃止済み。仕様の正は `genesis-docs/docs/geometries/G_道路メッシュの生成.md §15`。
- **インフラパス(PATH_ELECTRICITY/PATH_WATER)の垂直結合と垂直コネクタ**: インフラパスの端点は「垂直結合」（端点の相対YとノードYの不一致がデータ上の正規状態）を許容する。このため、(a) **インフラノード(`type`がインフラ財ビットを含む=`InfraNetworkUtil.IsInfraMask`)には交差点アスファルトを生成せず、`ConnectionPoints` によるパス端点の切断・差し替えも行わない**（`UpdateNodeIntersectionMesh` 冒頭のノードタイプ分岐。切断点で端点Yをノード平面の高さに引き戻すと垂直結合が壊れるため）。(b) 端点の絶対高さとノードの絶対高さの差が `INFRA_RISER_MIN_HEIGHT_DIFF`(0.5m) を超える場合、`CreateInfraVerticalConnectors` が高低差を繋ぐ垂直コネクタ（`Models/Paths/p{variant}/riser` プレハブ、無ければ円柱プリミティブ）を pathGO の子として生成する（SetupVisuals より前に生成し、ステータス表示の対象に含める）。ノードがパスより後からロードされた場合は、ノード到着時の `UpdateNodeIntersectionMesh` インフラ分岐 → `RefreshInfraVerticalConnectorsForNode` がコネクタだけを再評価する（パス本体は再生成しない）。

## 建物 (BuildingManager.cs)

- `center_point` が属するセルのティアで Far(白い箱) / フル詳細を選ぶ。
- **建物GameObjectの配置高さ(Y)は model_type で分岐する**: `IsBuildingApplicableForAltitude`(=`BuildingMeshBuilder.IsApplicableModelType`。MODEL_MODULAR_FLAT/HOUSE/GABLE)の建物は土地区画の基準標高 `parcel.altitude`(=接道の路面高さ)、それ以外(GROUND/PREBUILT/PORT)は `center_point` 位置の地形標高に接地する。傾斜地の谷側の隙間はメッシュ生成側のコンクリート基盤が埋める(MeshGenerators/AGENTS.md の「傾斜地対応」の節を参照)。地形追従の高さ再設定(`UpdateBuildingHeight`)も同じ分岐を通るため、altitude接地の建物は地形リロードで上下しない。
- **フル詳細メッシュには視野ゲートと個数上限(LRU)がある**: 生成/再生成が必要になった建物のうち視野外(カメラ前方75°超かつ100m超)のものは即時生成せず、遅延キュー(`deferredDetailBuildings`)へ積む。常駐ワーカー `DetailGenerationWorker` が「視野内かつカメラに近い」ものから順にフレーム予算内で生成する(視野外も上限に余裕があればアイドル生成する。振り向き時のポップイン軽減)。フル詳細オブジェクト数は `maxDetailedBuildingObjects`(既定2000)で上限管理され、超過時は「視野外で最も長く視野に入っていない」建物からGameObjectをLRU破棄する(データキャッシュは保持し、視野に入れば再生成される)。**遅延中の建物にはversionをキャッシュしない**(ワーカーが生成した時点でキャッシュ。次回マージロードでも「未生成」と判定させ、キューを最新データで更新し続けるため)。Far(白い箱)は軽量なので視野に関わらず即時生成し、上限の対象外。
- **ティア変更時の再生成**: セルのティアが Far↔Near/Dynamic または Near↔Dynamic に変化した場合、versionが同じでも建物を再生成する(Far境界は白い箱⇔フル詳細の切り替え、Near↔Dynamicはフェンス・地面パネルの地形追従状態の切り替えのため)。PathManagerの `RebuildCachedPathsForCells` と同様の仕組み。
- **地形追従は2種類ある**: Nearセルでは **transform.position.y を `HeightmapTextureManager.GetTerrainHeight` で再設定するだけ**(メッシュは作り直さない)。Dynamicセルではフェンス・地面パネルを地形に沿わせるため、`CreateOrUpdateBuildingObject(data, isDynamic: true, forceRebuild: true)` で**メッシュごと再生成**する(地形ロード完了後の `AdjustBuildingHeightsForCellsCoroutine` と、Dynamic地形タイル更新時の `OnTerrainTileReadyHandler` から呼ばれる)。この敷地装飾の地形追従は model_type を問わず全建物が対象で、altitude接地の建物(FLAT/HOUSE/GABLE)も本体は水平のまま敷地装飾だけ地形に沿う(MeshGenerators/AGENTS.md の「傾斜地対応」参照)。地面パネルは細分化して内部頂点も地形に追従させる。`AdjustBuildingHeightsForCellsCoroutine` / `PathManager.RebuildPathShapesForCellsCoroutine` はフレーム予算(`PerformanceConfig.FrameBudgetMs`)で分割されるコルーチンであり、`CellDataLoader.TerrainFollowUpCoroutine` から「実際に地形が更新されたセル ∩ nearCells(=Near以上の全ティア。dynamicCells ⊂ nearCells)」を対象に呼ばれる(地形不変のセル跨ぎでは呼ばれない)。**対象をDynamicセルに限定してはいけない**(Nearセルの建物・道路が古い高さのまま放置され、道路の埋まりが発生する)。
- **`CreateOrUpdateBuildingObject` の isDynamic/forceRebuild**: isDynamic はメッシュ生成器(`BuildingMeshBuilder.Generate`)に渡され、フェンス・地面パネルの地形追従を有効化する。`cellBuildingLod` はロードコルーチン完了後の `ApplyLodCellChanges` まで旧ティアのままなので、`LoadMergedBuildings` 中はティア表を参照せず desiredTier を直接渡すこと。また forceRebuild=false の場合、既存オブジェクトのプール再利用(status一致かつ非Far)で early return してメッシュは再生成されないため、メッシュの作り直しが目的の呼び出しでは必ず forceRebuild=true を渡すこと。
- メッシュコライダーは `Physics.BakeMesh` を `Task.Run` でベイクしてから割り当てる(`SetColliderAsync`)。道路も同様。
- **工事中(STATUS_CONSTRUCTING)の建物は毎エポック version が上がり再生成される**: 工事中の建物は進捗に応じた「工事現場」メッシュ(土マウンド+足場+クレーン。`ConstructingBuildingMeshBuilder`、MeshGenerators/AGENTS.md参照)で描画され、バックエンドの建設進捗フェーズ(`progress.py`)が進捗の増えたエポックで version を bump するため、既存の version 差分ロードだけで足場が毎エポック伸びる(BuildingManager側に専用処理は無い)。
- **インフラ接続端子ノードの逆引きインデックス (`buildingIdByInfraNodeId`)**: 端子ノードID(`agents.infra_node_id`)→建物agent_id のインデックス。ノードAPIは所属施設(owner)を公開しない片方向参照の設計のため、フロントの端子ノード識別(スナップ判定・端子マーカー・網互換判定)はこのインデックス経由の `TryGetInfraTerminalOwner` で行う。`buildingDataCache` への登録は必ず `RegisterBuildingDataToCache` を通し、削除は `SyncBuildingsInCells` / `ClearAllCells` で同期すること(`RegisterBuildingCell` 等と同じ管理規約)。
- **土地区画の逆引きインデックス (`buildingIdsByParcel`)**: 区画ID(`agents.parcel_id`)→その区画上の建物agent_id集合。地区拡張ドラッグ中に「街路に面する区画」から「その区画上の建物」を解決し地区色を波及させるために使う(`GetBuildingIdsByParcel`)。`buildingIdByInfraNodeId` と同じ管理規約で、登録は `RegisterBuildingDataToCache`(parcel_id 変更時は旧マッピング除去)、削除は `SyncBuildingsInCells` / `ClearAllCells` で同期する。

## 区画 (ParcelManager.cs) / 地区 (ZoneManager.cs) / 天然資源 (ResourceManager.cs)

- パーセルにティアはない。上面ポリゴンは頂点ごとに地形高さへ追従させる(`BuildParcelTopLocalYOffsets` → `ParcelMeshFactory`)。
- **マウス位置からの区画検索 (`GetParcelIdAtPoint`)**: 指定ワールド座標XZを含む区画IDを2Dポリゴン内外判定で返す公開メソッド。起伏地形では区画のMeshCollider(上面はポリゴン角の頂点でしか地形をサンプルしない)が地形の下に埋まってレイキャストで拾えないため、InputHandler が「最初の有効ヒットが地形だった場合」のフォールバックとして呼ぶ(`InputHandlers/AGENTS.md` の基本フロー参照)。全件走査を避けるため、セル逆引きインデックス `parcelIdsByCell`(セル→BBOXが重なる区画ID集合)→BBOX→内外判定の順で絞り込む。BBOX・変換済みポリゴン・登録セル一覧は `parcelSpatialCache` に保持され(マウス移動フレームごとの `GetPolygonArray` アロケーション回避)、登録は `RegisterParcelDataForLines`(内部で `RegisterParcelSpatialIndex`)、削除は `RemoveParcel` / `ClearAllCells` で同期される。
- **接道街路の逆引きインデックス (`parcelIdsByFrontPath`)**: 街路ID(`front_path_id`)→その街路に面する区画ID集合。地区拡張ドラッグ中に「なぞった街路に面する区画」をフロントだけで解決するために使う(`GetParcelIdsByFrontPath`)。登録は `RegisterParcelSpatialIndex`(`ParcelSpatialEntry.frontPathId` に保持)、削除は `UnregisterParcelSpatialIndex` / `ClearAllCells` で同期する。`front_path_id` は parcels の `VERSION_TRIGGER_PROPS` に含まれるため接道変更時は version が上がり `CreateOrUpdateParcelObject` 経由で再登録される(=version一致分岐での再登録は不要)。**`front_path_id` は `ParcelSummary`(multi_parcel)のフィールドで、`ParcelSummaryExtensions.GetFrontPathId`(リフレクション)経由で読む**(endpoint_schemas シート未再生成でもコンパイルが落ちないための措置。`GetPlatformSide` と同じパターン。未再生成時は 0 を返し index は空=道路のみ色付く)。
- **区画の一時ゾーン上書き (`tempZoneOverrides`)**: 地区拡張ドラッグ中の色プレビュー用(区画ID→ゾーンID)。区画は `VisualModeObject` を持たないため、`VisualModeObject.tempZoneId` ではなくこの辞書で表現する。`ResolveDataVisColor` の `ZONE_COLOR` で `GetZoneIdAtPoint` より優先して参照される。`SetTempZoneOverride` / `ClearTempZoneOverrides`(いずれも `ForceOutlineRedraw` で即時反映)。片付けは `ZoneEditContext.ClearDragTempVisuals` が呼ぶ(VisualHandlers/AGENTS.md参照)。
- パーセルの枠線・ホバーハイライト・データ可視化(地価等)は GameObject ではなく `OverlayMeshRenderer` で一括メッシュ描画する。カメラが1m/2°以上動いたフレームだけ再構築。距離フェードあり(480mで非表示)。
- **枠線/ハイライト/データ可視化は地形に埋もれさせない**: `EnsureOverlayRenderer` が `Custom/OverlayLine` マテリアルインスタンスに `_ZTest = Always(8)` を設定する(RoadPlanManager のギズモと同じ対応)。シェーダー既定の `LEqual`+ポリゴンオフセットでは傾斜地で平板ポリゴンが曲面地形の下に食い込んで埋まったように見えるため。代儝として丘の裏や手前の建物を貫通してX線状に見えるが、強調表示用途なので許容。**シェーダー本体や ZoneManager/TerrainManager のセル枠には影響しない(マテリアルインスタンス限定)。**
- ZoneManager は地区枠線(OverlayMeshRenderer)と地区名ラベル＋建物アイコン(2D UIオーバーレイ)を描画する。地区の塗りつぶし板ポリゴンは通常描画しない(枠線・名称・アイコンのみ)。地区の識別色はバックエンドの `zone.color`(HEX文字列)を `GetZoneColor(zoneId)` でパースして使う。建物/区画/道路の「地区別色塗り」モードもこの色を共有する。
  - **地区のリロード経路は3つ**: ①`LoadCells`(カメラセル更新)は「未ロード時と isForce 時のみ」全件取得する省略設計。②エポック完了・編集確定の `CellDataLoader.ReloadAllData` は isForce=false のため①では再取得されず、代わりに `RequestZoneRefresh()`(version差分の全件リロード。進行中なら完了後に1回だけ追加実行)が明示的に呼ばれる。**地区はエポックごとに自動作成・統合・分離されるため、この呼び出しを外すと Unity の地区表示が起動時スナップショットのまま永久に更新されない**(枠線・ビルボードが表示されないバグの既往原因)。③地区編集確定は `ReloadAllZonesForced()`(version差分バイパス)。
  - **地区編集モードのホバーフィル (`SetHoverFillZone` / `ClearHoverFill`)**: 地区編集中にマウスが既存地区の領域内に入ったとき、その地区ポリゴンを半透明フィルでハイライトする。**枠線用の `overlayRenderer` とは別インスタンスの `hoverFillRenderer`** を使い、マテリアルの `_ZTest=Always` で地形・建物に埋もれず常に手前に塗る(ParcelManager のデータ可視化と同じ採用済みトレードオフ)。ポリゴンは `BuildingMeshBuilder.TriangulateOrFan`(耳切り。凹地区に対応)で三角形化し各頂点Yを地形高さに追従。**ホバー地区が変わったフレームだけ再生成**し(`OverlayMeshRenderer` は次の `BeginFrame` まで前フレームのメッシュを保持するため毎フレームコストは無い)、呼び出しは `InputHandler` のホバー判定(地区編集モード限定)。`ZoneEditContext.Exit` / `ClearAllCells` でクリアする。
- **地区内外判定の高速化**: `GetZoneIdAtPoint` は `IsPointInPolygon` の前に `zoneBboxCache` (BBOXキャッシュ) による早期リターンフィルタリングを行う。また、InputHandler はこの判定を地区編集モード中のみに限定し、通常時の毎フレームオーバーヘッドを排除している。
- ResourceManager は天然資源（油田、鉱脈、レアメタル、森林、水源の5種）の分布を、地形に追従するヒートマップ風オーバーレイとして描画する。ParcelManager/ZoneManager が使う `OverlayMeshRenderer` とは別に、**UVと頂点カラーを持つ専用の MeshFilter/MeshRenderer** と専用シェーダー `Custom/ResourceHeatmap` を使う（プロシージャルノイズで雲/ヒートマップ的な見た目）。
  - **ポリゴンのグリッド細分化**: 各資源ポリゴンのAABB内を `GRID_STEP`(10m)間隔で細分化し、各頂点で地形高さをサンプリングする。ポリゴン頂点だけで貼る板と異なり、丘や山の上でも地形に張り付いて埋もれない。
  - **輪郭はソフトフェード**: `SignedDistanceToPolygon` で各グリッド頂点のポリゴン境界からの距離を求め、`EDGE_FADE`(12m)の範囲で頂点アルファを0へ漸減させる。輪郭線は引かない。
  - **再構築タイミング**: カメラ移動では再構築しない（world-spaceメッシュなので不要）。リソースロード完了時と、`TerrainManager.OnTerrainTileReady`（資源が存在するセルのみ）で再構築。同一フレームの複数イベントは `LateUpdate` で1回にまとめる。
  - **資源名ラベル**: ZoneManager と同じ ScreenSpaceOverlay Canvas 方式で `resource_type_label`(水源・森林等)を表示。`EnsureUICanvas` で専用Canvas(sortingOrder=55, ZoneManager=60より奥)を作り、`resource_type_label` を `Text`+`Outline` で描画。位置は `Update` でカメラが 1m/2° 以上動いたフレームだけ `center_point` を `WorldToScreenPoint` して更新(ZoneManagerと同じ間引き基準)。

## 地形プロップ (PropManager.cs)

- 役割: 配置・散布済みの地形プロップ(森・岩などの装飾。仕様の正は `genesis-docs/docs/geometries/M_地形プロップ.md`)を `GET /props?bbox=` から取得し、GameObjectとして実体化する。ロード範囲は `BaseApiDataManager.LoadLodCells` のデフォルト = **nearCells**(Near以上のティア)。
- **マージBBOXの一括取得+レコード単位レジストリ**: 散布プロップ(scatter)はバックエンドで「散布範囲全体を覆うBBOX」で空間登録されているため、セル単位に取得すると**同じレコードが複数セルの応答に重複して返る**。セルごとに独立生成すると同一座標に重複インスタンスができるため、必要セル全体のマージBBOXで1リクエスト取得し、`scatterStates` / `instanceStates`(レコードID→状態)で一元管理する。
- **version差分更新**: HTTP取得は毎回全件、再生成は version が変わったレコードのみ(他マネージャーと同じ慣習)。応答に含まれないキャッシュ済みレコードは削除済みとして破棄する。これにより `ReloadAllData`(編集確定・エポック完了後)で「配置直後のプロップの出現」「重なり除去による region 変更の再散布」「削除の反映」が機能する。
- **散布点の決定的生成とセル単位の差分実体化**: 散布点(ジッタ・回転・スケール)は `seed` 初期値の乱数を**散布範囲全体のグリッド走査順に、セルの実体化有無にかかわらず必ず消費**して生成する。これにより後から一部のセルだけ実体化しても同じ点列になる(`ScatterState.generatedCells` で生成済みセルを管理し、新たに必要になったセルだけ差分生成)。生成コルーチンが途中キャンセルされたセルは `generatedCells` にマークされず、次回ロードで作り直される。
- **穴つき・複数塊regionの遵守**: `region`(GeoJSON MultiPolygon coordinates)は「各Polygonの先頭リング=外周、以降=穴」としてパースし、散布点は「外周の内側かつどの穴にも入らない」場所にのみ置く(公開ドキュメント M.3 の契約。重なり除去で刳り抜かれた道路・区画の上に散布しないため)。
- **地形追従**: 生成時に `HeightmapTextureManager.GetTerrainHeight` でYをサンプルし、地形ロード完了後は `CellDataLoader.TerrainFollowUpCoroutine` から `AdjustPropHeightsForCellsCoroutine(updatedCells ∩ nearCells)` が呼ばれてY座標を再設定する(建物・道路と同じ2段階ロード。プロップはY再設定のみでメッシュ再生成なし)。
- **セル逆引きインデックス (`scatterIdsByCell` / `instanceIdsByCell`)**: セル単位のアンロード・地形追従で全レコード走査を避けるためのインデックス。登録・削除は必ず `RegisterScatterCell` / `RegisterInstanceCell` / `UnloadCell` / `ClearAllCells` を通して同期すること。
- 生成・破棄・高さ調整はすべて `PerformanceConfig.FrameBudgetMs` のフレーム予算でコルーチン分散する。1散布レコードあたりの生成上限は5000(超過は警告して打ち切り)。
- 未実装(別タスク): GPUインスタンシング等による数万本規模の軽量描画(現状は1本=1GameObject)、既存プロップの削除UI。

## 高さ取得APIの使い分け

- 原則 `HeightmapTextureManager.GetTerrainHeight(pos)` を使う。CPU高さ配列(1m解像度、マップが大きい場合はセル解像度)の O(1) ルックアップで、未構築時・サンプリング結果が0の場合は `Utils.GetGroundHeight` にフォールバックする。
- CPU高さ配列は地形タイルの生成・再縫合のたびに `TerrainManager` が `WriteCellHeights` で直接書き込むため常に最新(GPUからの `GetHeights` readbackは行わない)。全量再構築は `RebuildCpuHeightmap`(初回ロード・強制リロード時のみ。`ReplayHeightsToCpuHeightmap` によるCPUキャッシュからの再書き込み)。
- `Utils.GetGroundHeight` は Terrain.SampleHeight ベース+フレーム単位の1mグリッドキャッシュ。Terrainタイル差し替え後は `Utils.InvalidateHeightCache()` を呼ばないと古い高さを返す。
- **セッションリセット(`session:reset` → `CellDataLoader.ClearAllManagerData`)では `HeightmapTextureManager.Invalidate()` でCPU高さ配列を無効化する**。無効化しないと別セーブのロード直後に前のマップの標高が返り、地形タイル到着前に生成される建物・道路が誤った高さで作られる。無効化後は `Utils.GetGroundHeight` フォールバック(=新規起動時と同じ挙動)となり、初回追従の `RebuildCpuHeightmap` で再確保される。
- **Dreamteck スプラインの `Evaluate`/`Project` に渡すパーセントは [0,1] にクランプすること**(`RoadPath.ClampSplinePercent`)。Dreamteck側はクランプせず、浮動小数点誤差で 1.0 を 1ULP 超えただけで内部サンプル配列の範囲外アクセス(IndexOutOfRangeException)になる。また地形追従の3つの内側コルーチン(`PathManager.RebuildPathShapesForCellsCoroutine` / `BuildingManager.AdjustBuildingHeightsForCellsCoroutine` / `PropManager.AdjustPropHeightsForCellsCoroutine`)は `TerrainFollowUpCoroutine` に直接 yield されるため、パス/ノード・建物・プロップの個体単位の再生成/位置調整はtry/catchで捕捉し、1個の失敗が都市全体の地形追従(残りのオブジェクト調整・`FinishTerrainFollowUp` によるdeferred抑制解除とカメラロック解除)を中断しないようにしている。**yield をまたぐ try/catch は書けないため、包むのは非yieldの再生成/位置調整呼び出しのみ**(フレーム予算による `yield return null` は try の外に置く)。エラーログは `Debug.LogError` で個体ID(agent_id / path_id / node_id / instance_id / scatter_id)を含める。

## アラート (AlertManager.cs)

- 役割: バックエンドの `GET /api/v1/alerts` から、alert ビットフラグが立っている建物(agent)・道路(path)の一覧を取得し、各 `center_point` 上にビット種別ごとのアラートアイコンを表示する。**alert は version 管理外のプロパティ**(VERSION_TRIGGER_PROPS に含めない)なので、BuildingManager/PathManager のような version 差分スキップは行わない。毎回フル再構築し `HashSet<string>` で前回セットとの差分を取って追加/削除する。
- **表示方式は ZoneManager / ResourceManager と同じ ScreenSpaceOverlay Canvas + Image**: 距離に依存せず常に一定のスクリーンサイズで表示する。ワールド座標は毎フレーム `Camera.WorldToScreenPoint` でスクリーン座標に変換して `RectTransform.anchoredPosition` を更新する(カメラ移動が1m/2°未満のフレームはスキップして間引き)。建物/道路の子にはしないため VisualModeObject のステータス連動や LOD アンロードの影響を受けない。
- **1オブジェクトに複数ビットが立っている場合はアイコンを水平に並べる**: 並べ方 `ZoneManager.cs:763` と同じ `(i - (count-1)/2f) * alertIconHorizontalSpacing` 式で中央揃えファンアウト。
- **アイコンSpriteの選択は AlertIconFactory が担当**: `AlertIconFactory.Instance.GetIconForAgent(bit)` / `GetIconForPath(bit)` を呼び出す。AgentとPathで同じビット値(例: CONSTRUCTION_SHORTAGE=1)でも別のアイコンを割り当てられるよう、ファクトリ内部は `Dictionary<(string entityType, int bit), Sprite>` で保持する。未設定ビットのSpriteはnullになりそのビットのアイコンはスキップされる。AlertIconFactory は BuildingIconFactory / AgentIconFactory / PathIconFactory と同じく `Utils/AlertIconFactory.cs` に配置し、Inspector から名前付き `[SerializeField] Sprite` を割り当てるパターンに従う。
- アイコンサイズは `alertIconSize`(既定100px、シーンでは65px)で Inspector 調整可能。Canvas の `sortingOrder` は `canvasSortingOrder`(既定70)で ZoneManager(60)・旧ConstructionWarning(65)より前面、Tooltip(100)より奥。
- **リフレッシュタイミング**: `CellDataLoader.ReloadAllData()` 完了後(エポック完了/編集確定後)、`ForceReloadAllDataCoroutine()` 完了後(全量再取得)、`OnCameraCellChanged()` でティア変更セルがあるとき。`Refresh()` は `refreshCooldownSeconds` で間引かれる。`forceRefresh=true` で強制可能(全量リロード時のみ使用)。
- Image の `raycastTarget=false` により、uGUIの Raycast に干渉しない。3D オブジェクト用の InputHandler には Collider/Tag を持たないのでそちらにも影響しない。
- 詳細・設計理由は `genesis-docs/docs/programs/アラートフラグ管理.md` 参照。

## 公共交通オーバーレイ (TransitOverlayManager.cs)

- 役割: 設置済みの公共交通パス(`PATH_TRANSPORT`)を「路線種別ごとの色帯」として下地道路の上にオーバーレイ描画する。`PATH_TRANSPORT` は `PathMeshFactory` にメッシュ生成器が無く通常描画では非表示だが、`PathManager` のキャッシュには点列込みで存在するため、**`PathManager.GetTransitPathsForOverlay()`**(path_type==`Constants.PATH_TRANSPORT` のキャッシュ済みパスを `CalculatePathPoints` で点列化して返す)で取得して `Utils/OverlayMeshRenderer`(`Custom/OverlayLine`)で細い色帯として描く。色は各パスの `path_variant`(=`transit_master` の `transit_path_id`)から黄金角ベースで安定生成する。
- 表示制御は路線種別(`transit_path_id`)単位。表示オプションの公共交通タブ → `view:change_view`(layer=`transit`, sub_mode=表示する `transit_path_id` のCSV) → `IpcViewCoordinator.ApplyTransitMode` → `SetVisibleVariants(HashSet<int>)`。空集合なら全非表示(メッシュを即クリア)。
- 再構築はカメラ移動(1m/1°)・0.5秒周期・`MarkDirty()`(路線設置確定後に `IpcEventHandler.HandleEditTransitFinish` から呼ぶ)のいずれかで行う。`AlertManager` 等と同じくシーン事前配置不要で、`[RuntimeInitializeOnLoadMethod(AfterSceneLoad)]` で自己生成する。
- 停留所の配置(路線設置エディタ)は `Editors/TransitEditor/TransitPlanManager` 側。

## その他の注意

- **HTTP取得は `ApiClient` に集約されている(UnityWebRequestを直接書かない)**。マージBBOXの一括取得やIDリストのバッチ取得など大きなレスポンスは `ApiClient.GetBulk<T>`(デシリアライズを`Task.Run`で別スレッド実行・timeout/no-cache標準装備・`UNITY_LOG_TIMING`でnetwork/deserialize分離計測)、単体取得や小さいレスポンスは `ApiClient.Get<T>`(メインスレッドのJSONパース)を使う。例外は `TerrainManager` の地形ハイトマップ取得(float16生バイナリ応答でJSONではない)のみ。**`GetBulk`はAcceptヘッダでMessagePackを要求し、バックエンドの対応エンドポイント(buildings/paths/parcels/zones/nodesのbbox一括取得)ではJSONではなくMessagePackバイナリで受信して`API/MsgPackDecoder.cs`でデコードする**(レスポンスのContent-Typeで自動判別するため、呼び出し側・未対応エンドポイントは何も変わらない)。デコード結果の中間表現(`Dictionary<string,object>`/`List<object>`/long/double)はNewtonsoftの非JToken表現と互換で、`GeneratedModelUtils`の座標変換がそのまま機能する。
- `BaseApiDataManager.LoadCells`はLOD非対応マネージャー(ZoneManager)用の仮想ディスパッチポイント。base実装は空で、LOD対応マネージャー(Building/Path/Parcel/Terrain)は`LoadLodCells`を直接オーバーライドするため通らない。(旧セル単位ロードの抽象メソッド `LoadCellData` は呼び出し元が無くなったため削除済み)
- `ApplyDepthOffsetShader` / `DestroyObjectAfterFrames` / `CalculateAverageWidth` は `Utils`(Scripts直下) の共通メソッドに切り出されている。マネージャー固有のものを新たに書かないこと。
- GameObject名にIDを埋め込む: `Building_{agentId}` / `Path_{pathId}` / `Parcel_{parcelId}` / `Node_{nodeId}`。各オブジェクトには `ObjectIdInfo` コンポーネントが付与され、`id` / `status` / `isFarObject` でメタデータを管理する。**名前の文字列パースは行わず、常に `GetComponent<ObjectIdInfo>()` で取得すること。**
- カメラ移動中に `LoadLodCells` が再度呼ばれると進行中のコルーチンは `StopCoroutine` でキャンセルされる。キャンセルで状態が壊れないよう、各マネージャーはフラグ復旧処理を持っている(例: TerrainManager の `settingsLoading` リセット、PathManager の `EndLodPathBatch`)。地形ロード完了後の追従更新コルーチン `CellDataLoader.TerrainFollowUpCoroutine` も `UpdateManagers` 冒頭でキャンセルされる。取りこぼした更新セルは `CellDataLoader.pendingFollowUpCells` に退避され、次回ロード完了時に再処理される。追従コルーチンが建物・道路の内側コルーチンを呼ぶ際は `StartCoroutine` ではなく `IEnumerator` を直接 `yield return` すること(`StartCoroutine` で起動した子は親の `StopCoroutine` では止まらないため)。
- **やむを得ず `StartCoroutine` で子コルーチンを起動する場合(TerrainManager の並行ロード等)は、`LoadBatch`(CellDataLoader が `UpdateManagers` ごとに発行し `LoadLodCells` の4引数オーバーロードで配布、`BaseApiDataManager.currentLoadBatch` に保持)の `IsCanceled` を yield をまたぐたびに確認して協調的に停止すること。** 旧バッチの子が新バッチの状態(`terrainTiles` / `cellLodLevel` 等)と競合するのを防ぐための必須パターン。
- **ロード進行ログ・計測ログは無条件 `Debug.Log` を使わない**。ロード進行は `UnityLog.If(LocalConstants.UNITY_LOG_LOADER, ...)`、`[TIMING]` 計測は `UnityLog.If(LocalConstants.UNITY_LOG_TIMING, ...)` を使う。セル移動ごとにホットパスで多数のログが出るため、無条件 `Debug.Log` はエディタのスタックトレース取得で無視できないコストになる。文字列補間が重い場合は `Func<object>` オーバーロード(`() => $"..."`)を使う。`LogWarning` / `LogError` は無条件で残してよい。
