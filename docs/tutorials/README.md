# チュートリアル設計

このディレクトリはシナリオ作者向けの設計資料。対象は基本5・基本操作8・地区7・インフラ6・鉄道13・埋立4・用地買収4の計47ステップ(旧保存用の用地買収4を含む)。実行定義は `tauri/src/tutorial/definitions/`、基盤の契約は `docs/docs/programs/チュートリアル基盤.md` を参照する。

## 作成の順序

1. シナリオの設計書で学習目的・前提・対象・クリア条件を確認する。
2. `capabilities.md` にある部品でJSONを記述する。未登録の対象名や処理名を推測して作らない。
3. 定義の検証と基盤テストを実行する。新しい機能が必要なら共通部品の追加として扱い、シナリオ固有の分岐を本体へ書かない。
4. 実際のウィンドウの開閉、取消、Unity再接続と通常プレイへの復帰を確認する。

## 共通設計

- シナリオIDとステップIDは順番から独立する。進行の正はTauri。Unityは現在の案内と制限だけを保持する。
- 選択画面と開始時の紹介は、前半に架空の町の困りごと、後半に「このチュートリアルでは、〜を学ぶことができます」と学ぶ操作や流れを明示する。具体的な準備済み施設と操作手順は各ステップの案内に記載する。
- 開始時の導入はステップにせず、説明ウィンドウ(上半分にサムネイル、下半分に「このチュートリアルで何をするか」)で伝える。文言は `tutorial.intro.<シナリオID>`。
- 初期都市は道路と、そこに暮らす町(集合住宅・電気・水道)、教材に必要な既存の施設だけにする。埋立編は土地の確保と都市創設を学ぶため、支援町を置かない。鉄道編はMetroCityの用地買収も扱う。旧保存用の独立用地買収編だけは2つのプラットフォームを既設にする。線路・プラットフォーム・車両基地・路線など、学ぶ対象はプレイヤーに作らせる。
- 各ステップの最初の段階でカメラを次の作業場所へ向ける(`world.camera`)。
- **強調だけ**（highlight）: 操作を制限しない。
- **関係ない操作を制限**（related）: 許可した操作領域内で自由に操作できる。
- **指定操作だけ許可**（strict）: 許可した個別操作だけを実行できる。建物・道路・鉄道・インフラの種別を選んで建てさせるステップと、公共交通の路線を新設させるステップは、パネルを開く段階から確定までのすべての段階を strict にし、案内した種別・カード・確定などの操作だけを許可する(階数や構造などの設定は触らせない)。
- TauriとUnity、さらにステップ内の段階ごとに制限を指定する。強調対象が自動的に許可対象になるとは限らない。
- カメラ、スクロール、ウィンドウ移動・閉じる、チュートリアル終了は逃げ道として確保する。取消後は現在の状態から案内を再評価する。
- 通常の建設可否とチュートリアル制限はANDで合成する。通常の検証失敗をチュートリアルが上書きしない。
- 操作の途中の達成は画面状態・編集状態で確認し、保存を伴う達成はAPI応答または保存済み状態で確認する。
- 初期都市の物体とプレイヤーが作った物体は名前で束縛する。既存の同種施設で新規建設を達成したことにしない。
- 条件判定は読み取り専用。工期スキップは対象を明記した独立アクションとして実行し、失敗時は次へ進まない。
- エポックを進める段階では実行確認・結果・必要な通知の操作も許可する。結果を閉じるまでの演出と競合させない。
- 概要説明は次へボタンで進める。1つのステップ内で説明を何ページかに分けるときは、`page` 条件の段階を並べて「次へ」で送る(最終段階は通常どおり「次へ」でステップ完了)。操作段階は状態に応じて自動進行し、文章の読了を自動で判定しない。
- API失敗と条件未達を分ける。前者は再試行、後者は不足している条件を案内する。

## 設計書と実行定義

設計書は採用する体験と合格条件、JSONは実行の正である。各シナリオ末尾の調査メモは移植時の誤解を避ける資料であり、現在の判定を新しい合格条件として流用しない。全チュートリアルの全ステップを実行定義で書く。設計書のステップIDは定義のステップIDと一致させる(`npm run test:tutorial` が確かめる)。

新しい画面上の文言は既存の7言語の翻訳へ登録する。数値IDは共有定数または明示したマスター属性から解決する。公開資料にバックエンド内部アルゴリズムや認証情報を含めない。
