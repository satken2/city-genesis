    シナリオ制作と配布

    シナリオは、開始時の都市を保存したファイルと紹介情報の組である。通常セーブと同じ .cg 形式を使う。play_mode(通常・神・チュートリアル)は現在のセッションの編集モードであり、保存データへ編集権限として永続化しない。ファイルの中身・暗号化・公式署名はセーブデータ仕様、版と互換性はバージョニングと互換性を参照する。

    シナリオの一覧用メタデータには多言語の都市名初期値と開始設定を持ち、通常セーブの都市名・人口・日時・エポック数は持たない。共通項目と種別固有の項目はセーブデータ仕様を参照する。

    保存元と置き場

    シナリオには3つの保存元がある。形式はどれも同じ .cg で、保存元は「誰がそのファイルを管理するか」を表す。

    保存元(origin) 置き場 一覧・APIでのID
    自作 local ユーザーフォルダの scenarios/<id>.cg local~<id>
    コミュニティ workshop Steam Workshop の購読フォルダ steamapps/workshop/content/<AppID>/<item_id>/<stem>.cg workshop~<item_id>~<stem>
    DLC dlc インストール先の dlc/<pack_id>/<stem>.cg dlc~<pack_id>~<stem>
    • ユーザーフォルダの場所はファイル配置の OS 別の表に従う。
    • IDの各区間は [A-Za-z0-9_-] の1〜128文字。~ を含まないIDは自作としてだけ解決する(インストール先に置かれたファイルを自作と取り違えないため)。ほかの保存元を名乗るIDや形の崩れたIDは INVALID_SAVE_ID になる。
    • コミュニティとDLCのフォルダは Steam が管理し、ゲームは読むだけで書き込まない。これらのシナリオの削除・紹介情報や画像の編集・上書き・アップロードは 422 SCENARIO_READ_ONLY で拒否される。手を加えたいときは「コピーして編集」で自作シナリオにする。
    • Workshop のフォルダは、ゲームが Steam ライブラリの steamapps 配下にインストールされているときだけ決まる。開発・検証では環境変数 GENESIS_WORKSHOP_DIR で別のフォルダを指定できる。
    • 公式かどうか・DLC由来かどうかは置き場では決まらず、ファイルの公式署名と暗号化で決まる(セーブデータ仕様)。置き場が dlc のファイルは、有効な公式署名があり、その署名のパックが必要パックに含まれるときだけ読み込める。
    • 本体に組み込まれたシナリオは無い。本体が同梱する教材はチュートリアルだけで、シナリオの一覧には出ない。

    制作と保存

    1. 出発点を作る。シナリオ管理の「地形を取り込む」で標高ファイルから新しい自作シナリオを作るか、既存のシナリオを「都市を編集」または「コピーして編集」で開く。
    2. 地形(標高・水面・川・資源・プロップ・カメラ・地表・気候)は、自作カードの「地形を編集」から地形エディタで編集し、「シナリオに保存」で書き込む(地形データ作成マニュアル)。
    3. 都市、パラメーター、クエストは神モードのセッションで設定する。達成条件の説明文は紹介用であり、実際の判定は都市内のクエストに設定する。
    4. システムメニューの「シナリオとして保存」で保存する。神モードでなくても使え、プレイ中の都市もそのままシナリオにできる。先に紹介情報ウィンドウ(作成モード)が開き、タイトル・説明・達成条件の説明・初期の都市名(多言語)、作者、開始設定、画像を入力して「保存」を押すと、新しい自作シナリオを作る(POST /api/v1/templates。紹介情報)。「キャンセル」なら何も保存しない。画像を選ばなければ、保存の直前に撮った3Dビューがシナリオの画像になる。
    5. 必要なら設定された投稿先へアップロードする。保存だけでは外部へ送信しない。

    ゲームは標高マップを同梱しない。取り込む標高ファイルは標高だけを持ち、水面・川・資源・プロップ・カメラを持たない(地形形状 §D.14)。取り込んだばかりのシナリオはこれらが空で、地表種別は草原・気候は温暖湿潤で始まる。

    「シナリオとして保存」は通常のセーブ先を変更しない。保存は常に新しいIDの自作シナリオになり、既存のシナリオを上書きしない(「都市を編集」で開いた自作シナリオを保存しても、元のファイルは変わらない)。入力した紹介情報は新しいシナリオにだけ書き、プレイ中の都市の紹介情報は変えない。都市の版情報は作者の入力欄にせず、コアが設定する。

    シナリオ保存と「コピーして編集」は、都市の出自(必要パック required_packs と元のシナリオ derived_from)を引き継ぐ。ユーザー操作で出自を消す経路は無い。DLC由来の都市は自作シナリオとして保存しても暗号化されたままで、そのパックを所有する人だけが開ける。

    紹介情報ウィンドウは保存済みシナリオを編集するため、ゲーム開始前にも利用できる。紹介文はアーカイブの都市情報とメタデータを同時に更新し、プレイ中の達成目標画面と一致させる。画像は .cg 内の thumbnail.png に格納する。紹介情報・画像の更新は暗号化の有無と必要パックをそのまま保つ。

    紹介情報

    紹介情報ウィンドウ(scenario_metadata)は、システムメニューの「シナリオとして保存」(作成モード)と、シナリオ管理の自作カードの「紹介情報を編集」から開く。作成モードはプレイ中の都市の紹介情報・開始設定を初期値にし、「保存」を押すまで何も書かない。紹介文を編集する場所はここだけで、神モードの達成目標ウィンドウは紹介文を表示するだけ(編集の窓口を1つにして、多言語の入力と開始設定を同じ画面で扱うため)。

    • 紹介文と初期の都市名。 タイトル・説明・達成条件の説明・初期の都市名を、言語のタブを切り替えて書く(common/LocalizedTextFields)。タブで切り替わるのはこの4項目だけで、タブ列に接した枠で囲み、枠の外の作者などと見分けられるようにする。表示する言語の文が無ければ英語を出すので、英語のタブを先頭に置いて必須と示す。タイトルは英語が必須で、ほかの項目も1言語でも書けば英語が要る。欠けていれば保存しない(コアも 422 SCENARIO_ENGLISH_REQUIRED で断る)。最初に開くタブは表示言語。文が入っている言語のタブには緑の点が付く。
    • 開始設定。 枠の中に見出しと項目を並べ、各項目は「項目名・値・変更可能」の1行にする。「変更可能」のチェックをオンにした項目は、プレイヤーがゲーム開始時にこの値から変えられ、オフの項目はこの値で始まる(コアへは反転して、固定する項目の一覧 scenario_fixed_options として送る)。
      • 先頭は都市内の名前の言語(地区・施設・住民などの名前が何語で付いているか)。シナリオを作った時点で決まり(標高ファイルから取り込んだシナリオは取り込んだときのアプリ設定の言語、ゲームから保存したシナリオはそのゲームの言語)、ここでは値を変えられない(名前を付け直さずに言語だけを書き換えると、ゲーム開始時の付け直しの判定が狂うため)。プレイヤーは常に変えられるので、「変更可能」はオンのまま外せない。
      • 続いてシミュレーション日数・気候・地表・建物/道路アセットの地域。アセットの地域は今は標準だけ。気候・地表は地形エディタでも変えられ、どちらも同じ値を書き換える。

    ゲーム開始時の言語と開始設定

    ニューゲームの確認ダイアログ(taskbar/NewGameWindow)でシナリオを始めるとき、プレイヤーは次を決める。

    項目 選び方
    都市の言語 常に選べる。既定はアプリ設定の言語。シナリオの言語と違うときは、名前を付け直すことを注記する
    都市名 常に入力できる。初期値は初期の都市名を選んだ言語 → 英語の順に引いた名前(無ければシナリオの都市名)。プレイヤーが書き換えていなければ、言語を変えると引き直す
    シミュレーション日数・気候・地表・アセットの地域 作者が固定した項目は値を表示するだけ(「シナリオで固定」)。固定していない項目はシナリオの値を初期値に選べる

    create_session は固定していない項目の値だけを送る(simulationDays・climate・groundCover・assetRegion。固定した項目は null)。コアは固定した項目にシナリオと違う値が来たら 422 SCENARIO_OPTION_FIXED、値域の外は 422 SCENARIO_OPTION_INVALID で、ロードの前に断る。

    選んだ言語がシナリオの言語と違うと、コアはロードの直後に都市内の固有名詞を新しい言語で付け直す。対象は自動で名前を付ける仕組みがある名前(地区・経済主体・住民・駅舎・公共交通の路線と区間・施設の接続端子・自然発生の道路と、それらの名前を写した開店・閉店履歴と重大通知)で、作者が付けた名前も置き換わる。名前付き道路・インターチェンジ・一般の道路の名前は作者やプレイヤーが付けた名前しか入らないので、そのまま残る。紹介文・クエストは多言語テキストなので付け直さない。付け直しは同じ POST /api/v1/sessions の中で終わるので、グラフィックと UI は付け直した後の名前しか取得しない。神モードで開くとき(「都市を編集」「コピーして編集」)は付け直さない。

    作者名は紹介情報であり、作者の本人確認や公式認定の証明には使わない。公式かどうかは公式署名だけで決まり、メタデータに何を書いても公式にはならない。

    シナリオ管理

    トップメニュー中央のボタンは上から「ニューゲーム」「ロード」「シナリオ管理」。右下は左から D(開発時のみ)・設定・終了、左下は接続先のコア版とUI版を表示する。シナリオ管理(scenario_manager)はUIだけで開き、Unityを起動しない。都市を開くときは create_session が Unity を起動する。

    管理ウィンドウは共通の FlatTabs で「シナリオ」「地形を取り込む」の2タブに分かれる。ウィンドウ枠・再利用・閉じる操作は既存のレジストリ方式に従う。

    シナリオタブ

    GET /api/v1/scenarios の全保存元を1つの一覧にしたカードを並べる。カードには画像(ScenarioThumbnail)、保存元と公式の札(ScenarioOriginBadges)、タイトル・説明・作者、版情報と必要パック・所有状況(SaveVersionInfo)を出す。版不明・破損・パック未所有も一覧に残し、読み込めない理由を表示する。クリックしたカードは選択状態になり、左端の実線ブロックで強調して見える位置までスクロールする。

    タブの下(カード一覧の上)には、シナリオの作り方(標高マップデータからの作成と、ゲームプレイ中のシステムメニューからの保存)を説明する文を常に出す。更新ボタンは持たない。一覧は scenarios:changed を受けて自動的に取り直す。アップロード先が未設定である旨は、ページには出さず、アップロードのボタンの説明にだけ添える。

    カード ボタン
    自作(origin が local で read_only でない) アイコンのボタン。左から「紹介情報を編集」「地形を編集」「都市を編集」「アップロード」を左詰めに並べ、「削除」だけを右端に離して置く
    コミュニティ・DLC 文字のボタン「コピーして編集」
    • 自作カードのボタンはアイコンだけで、名前はマウスオーバーの説明で示す。押せないときは、その理由(投稿先が未設定・暗号化されたシナリオなど)を説明の2行目に添える。
    • 「削除」以外のボタンは、読み込めないカードでは押せない。「アップロード」は投稿先が設定されているときだけ押せる。
    • 「削除」は、確認ダイアログ(取り消せない旨を伝え、確定ボタンを赤くする)を経て DELETE /api/v1/saves/{id}?template=true を呼ぶ。壊れている・新しすぎるシナリオこそ片付けたいので、読み込めないカードでも押せる。成功したら一覧を取り直し、選択を外して scenarios:changed を送る。失敗したときも、一覧が古いままにならないよう取り直す。コミュニティ・DLCのカードには出さない(コアも422 SCENARIO_READ_ONLY で断る)。
    • 「都市を編集」「コピーして編集」は確認ダイアログとロード前確認(utils/saves.ts の prepareSaveLoad)を経て、create_session {templateId, playMode: PLAY_MODE_SCEARIO, acceptBalanceChange: true} で神モードのセッションを開く。開始すると開いているポップアップをすべて閉じるので、確認文で地形エディタの未保存の編集が失われることを伝える。
    • 「地形を編集」は Tauri コマンド prepare_scenario_terrain_editor でシナリオの地形を作業コピーへ書き出し、返された作業コピーのIDで地形エディタ(terrain_editor)を開く。セッションは使わない。DLC由来の(暗号化された)自作シナリオは地形エディタの対象外で、カードは一覧の要素の encrypted を見てこのボタンを押せなくし、理由をツールチップで示す(コアも409 SCENARIO_ENCRYPTED で断る)。
    • 「紹介情報を編集」は scenario_metadata を開き、params.extra.scenarioId を渡す。

    地形を取り込むタブ

    利用者が任意の場所に置いた標高ファイル(グレースケールPNG 8bit・16bit、または .npy)をファイル選択ダイアログで選び、新しい自作シナリオにする。ゲームは標高マップを同梱しないので、選べる地形の一覧は持たない。

    • 入力は、1画素の距離(m)・最低標高と最高標高(m。PNGのときだけ)・海面の高さ(m)・タイトル(既定は元のファイル名)。ファイルの画素数が分かれば、できるマップの大きさ(1km単位に切り上げた幅と高さ)を表示する。変換の規則は 地形形状 §D.14.1。
    • 都市の外に広がる背景地形(.npy)は任意で、選ぶと1画素の距離(m。既定50)を別に入力する。海面の高さは詳細地形と共通で、背景の大きさ(50m格子に直した幅と高さ。一辺100kmまで)を表示する。「外す」で選び直せる。
    • 右側のプレビューは、選んだファイルの標高を POST /api/v1/scenarios/heightmap-preview(取り込みと同じ読み方で間引いた標高)で受け取って描く。詳細地形は標高で色分け、背景は淡い単色で重ね、標高0m以下(海)は透明にする。ファイル・海面の高さ・PNGの標高範囲が変わったときだけ標高を取り直し、1画素の距離は配置を変えるだけ。読めないファイルの理由は入力欄の下に出す。
    • 「シナリオを作成」は POST /api/v1/scenarios/from-heightmap にファイルの生バイトを送る(クエリは入力値・アプリ設定の言語・元のファイル名)。背景を選んでいれば、本文の末尾へ背景のファイルを続け、background_size と background_spacing を付ける。変換できないファイルは HEIGHTMAP_INVALID を翻訳して表示する。
    • 成功したら、シナリオの地形(GET /api/v1/scenarios/{id}/terrain)から平面図のサムネイルを描いてシナリオの画像として保存し(PUT /api/v1/saves/{id}/thumbnail?template=true。失敗してもシナリオは残る)、一覧を取り直し、シナリオタブへ切り替えて新しいカードを選択状態にし、scenarios:changed を送る。

    自動生成するサムネイルは、北を上にした長辺512画素の平面図で、地形の縦横比を保つ。低地を薄いベージュ、高地を緑で塗り、北西の光による陰影で尾根と谷を表す。配色と陰影は都市マップの標高表示と共通で、元の標高格子の実距離から陰影を求めて縮小する。海は透明にし、海岸の画素は陸地の被覆率に応じて半透明にする。

    投稿先の接続契約

    投稿先サービスは固定しない。コアの実行環境に CITY_GENESIS_SCENARIO_UPLOAD_URL(HTTPSのPOST先)を設定する。必要なら CITY_GENESIS_SCENARIO_UPLOAD_TOKEN を設定し、Bearer認証で送信する。UIへトークンは返さない。未設定のときはアップロードを無効にする。

    投稿できるのは自作シナリオだけで、英語のタイトルと作者名が必要。.cg のバイト列をそのまま Content-Type: application/vnd.city-genesis.cg でPOSTし、ファイルのSHA-256を Idempotency-Key に付ける。DLC由来の都市は暗号化されたまま送られる。サービス側は成功時にJSON { "id": "投稿ID" } を返す。リダイレクトには追従しない。UIでは投稿先ホストへの送信を確認する。エラーでもローカルのシナリオは残る。

    これは接続用の共通HTTP契約であり、Steam WorkshopのSDK実装やコミュニティサイトそのものを含まない。

    API

    API 動作
    GET /api/v1/scenarios scenarios(IDをキーにした一覧)と upload_available・upload_host・max_package_bytes。暗号化されたシナリオも鍵なしで載る
    POST /api/v1/scenarios/from-heightmap 本文の標高ファイル(グレースケールPNG・.npy)とクエリ(spacing・min_height・max_height・sea_level・title・language・source_name)から新しい自作シナリオを作り {"id": "local~<id>", "map_width", "map_height"} を返す。title は英語にだけ入る(language は都市内の名前の言語で、タイトルには使わない)。ゲームは始まらない。変換できないファイルは422 HEIGHTMAP_INVALID。背景地形は本文の末尾へ続けた .npy を background_size(バイト)と background_spacing(m)で渡す(地形形状 §D.14.1)
    POST /api/v1/scenarios/heightmap-preview 本文の標高ファイルを取り込みと同じ読み方で読み、長辺1024画素以下へ間引いた標高(float16 LE の base64)と間引く前の画素数・標高の最小と最大を返す。都市もディスクも使わないのでセッション中でも呼べる。background=true で背景(.npy)として読む(地形形状 §D.14.3)
    GET /api/v1/scenarios/{id}/terrain 自作シナリオの地形を地形エディタの形式で返す(地形形状 §D.14.3)
    PUT /api/v1/scenarios/{id}/terrain 地形エディタの編集内容を自作シナリオへ保存する。content_revision が1つ上がる
    PATCH /api/v1/scenarios/{id} 自作の紹介文(scenario_title・scenario_description・scenario_objective)・初期の都市名 scenario_city_name・作者・開始設定の値(simulation_days・climate・ground_cover・asset_region)・固定した項目 scenario_fixed_options を更新する。送った項目だけを書き換える。都市の言語は変えられない
    POST /api/v1/scenarios/{id}/upload 設定先へ自作シナリオを送信する
    POST /api/v1/templates 現在の都市を新しい自作シナリオとして保存する(神モードでなくてもよい。既存のシナリオは上書きしない)。本文に紹介情報の更新と同じ項目を渡すと、新しいシナリオにだけ書く。成功時に id / save_id を返す
    PUT /api/v1/sessions/thumbnail 次の保存に入れる画像(PNG)を預ける。グラフィックの撮影と、作成モードで作者が選んだ画像
    PUT /api/v1/saves/{id}/thumbnail?template=true 自作シナリオの画像を更新
    DELETE /api/v1/saves/{id}?template=true 自作シナリオを削除
    GET /api/v1/saves/{id}/validation?template=true ロード前検証
    POST /api/v1/sessions?template_id=...&play_mode=... プレイ・編集として開始する。プレイでは language・city_name・simulation_days・climate・ground_cover・asset_region を選べる(固定された項目は変えられない)。言語がシナリオと違えば応答の relocalized に {from, to, counts} が入る

    シナリオの地形APIと取り込み(from-heightmap)はゲームのセッションを使わない。ゲームのセッションが読み込まれている間は409 SESSION_ACTIVE で断る。処理の間はコアが一時的に都市を組み立てるが、GET /api/v1/sessions の current_save_id は null のままで、都市のデータを返すAPIは503 NO_SAVE_LOADED を返す(UnityとUIがゲーム開始と誤認しないため。コンポーネント連携)。対象は自作シナリオだけで、コミュニティ・DLCは SCENARIO_READ_ONLY、存在しない自作シナリオは404 NOT_FOUND、DLC由来の暗号化された自作シナリオは409 SCENARIO_ENCRYPTED(地形形状 §D.14.3)。

    紹介情報・地形の変更や、シナリオの作成・削除の後は、UI内の scenarios:changed イベントで一覧を更新する。画像URLのリビジョンは内容更新によるキャッシュ更新に使い、ランダムなクエリは付けない。

    公式シナリオとミッション定義

    公式シナリオは、開発者が非公開のツールで公式署名を付けたシナリオである。署名だけを付けたもの(無料)と、署名したうえでパック鍵で暗号化したもの(DLC)がある。保存元にかかわらず、有効な署名があれば一覧で official: true になる。公式署名はファイルの全メンバーのハッシュに対する署名なので、中身を1バイトでも変えると無効になる。暗号化されたファイルでは、一覧に出す平文のヘッダー(紹介文とサムネイル)が中身と一致することも条件になる(セーブデータ仕様)。プレイヤーの保存は署名を書かないため、公式シナリオから作った都市やそのコピーは公式にならない。

    公式ミッションにはシナリオとは別に、mission_id、必要レベル、前提ミッション、完了に必要なクエストID、クリア報酬などの開発者用カタログが必要である。配置方針は非公開の開発資料で定める。都市内クエストの数値条件はカタログへ重複定義しない。公式進行カタログ・レベル報酬はこの管理画面には含まれない。 保存元や札だけでレベル報酬を与えず、コミュニティ作品からも公式進行を変更しない。

    検証

    UIのタブ・カード構成、保存元ごとのボタン(アイコンの並びと説明)、削除の確認と失敗時の一覧の取り直し、地形を編集の呼び出し、地形からの作成とカードの選択、投稿可否・紹介情報送信・ロード確認、ニューゲームのタブと開始は tauri/ の npm run test:scenarios で検証する。配布番号の同期検査は node tools/sync-version.mjs --check、翻訳キーは python tools/check_i18n_parity.py。

    開発時の署名と暗号化

    シナリオ管理の自作カードには、バックエンドがデバッグ実行されている間だけ「署名」のアイコンボタンを表示する。判定は GET /api/v1/scenarios の signing_available に従い、UI自体の開発ビルドかどうかには依存しない。Nuitkaでビルドした製品版・モック版では表示しない。フラグが無いバックエンドでも表示しない。コミュニティ・DLCのカードは読み取り専用で、署名するときも先に自作としてコピーする。

    「署名」から開く template/ScenarioSignWindow は、配布するシナリオの種類をラジオボタンで選ぶ。どちらも自作シナリオから書き出せる。

    種類 配布用途と処理 必要な鍵
    公式シナリオ 公式が配布する無料コンテンツ。署名だけを付け、平文の .cg を書き出す 署名用秘密鍵 (.key)
    DLCシナリオ 公式が有料配布するコンテンツ。署名を付け、パック鍵で暗号化した .cg を書き出す 署名用秘密鍵 (.key) と、それとは別の暗号化用パック鍵 (JSON)

    共通の「署名用の鍵」欄には署名用秘密鍵ファイルと署名鍵IDを指定する。DLCではさらに「暗号化用の鍵」欄を表示し、パックIDと、そのIDに対応するAES-256鍵を含むJSONファイル（パック鍵のキーリング）を指定する。署名用秘密鍵を暗号化鍵としては使わない。署名用秘密鍵だけではDLCを書き出せない。

    公式シナリオID、内容の版、出力先 .cg は両方に共通する。IDと内容の版の初期値は制作元から取る。署名鍵IDの公開鍵は、配布先のバックエンドに登録されている必要がある。鍵の新規生成・登録はこの画面では行わない。

    ファイル選択にはTauriのダイアログを使う。WebViewは鍵の中身を読み込まず、パスだけを POST /api/v1/scenarios/{id}/sign へ送る。署名用秘密鍵は private_key_path、暗号化用パック鍵のJSONは keyring_path に対応する。無料の公式シナリオでは pack_id・keyring_path を null にし、DLCでは両方を指定する。処理はゲームのセッションが無くても実行でき、元のシナリオを残して別のファイルへ書き出す。出力先は .cg の絶対パスとし、制作元そのものへの書き出しは拒否する。出力を検証してから保存を確定するので、失敗した場合は既存の出力ファイルも残る。成功時は応答の encrypted に応じて署名だけか署名・暗号化の完了かを示し、出力先を表示する。scenarios:changed で一覧へ通知する。

    既に必要パックを持つシナリオは「DLCシナリオ」に固定する。必要パックと出自を保ち、キーリングには追加するパックだけでなくすべての必要パックの鍵が要る。暗号化の形式は通常のDLCシナリオと同じで、パスワード暗号化ではない。

    tools/scenarios/signing-tests.tsx は、無料の公式シナリオの書き出し、平文の自作シナリオをDLCとして署名・暗号化する操作、2種類の鍵の個別指定、暗号化用の鍵が未選択のときの書き出し不可、既存の暗号化を維持することを確認する。署名画面だけを検証する場合は node tools/scenarios/run.mjs signing-tests を使う。

    配布ビルドからAPIを直接呼んだ場合も 501 DEBUG_DISABLED で拒否する。署名入力の不正は SCENARIO_SIGNING_INVALID、鍵IDと秘密鍵の不一致は SCENARIO_SIGNING_KEY_MISMATCH、鍵ファイルや出力先の問題は SCENARIO_SIGNING_FAILED。保存形式・所有状況に関する失敗は既存の理由コードを使う。
