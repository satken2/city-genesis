    火災エフェクトの描画

    概要

    建物(agent)の火災は、ビルボードアイコンではなく 3D空間のパーティクル表現で描く。バックエンドが立てる2つのアラートビットが、そのまま2種類の見た目に対応する。

    アラートビット 見た目 構成要素
    ALERT_AGENT_ON_FIRE(本格火災) 建物が炎上している 炎 + 火の粉 + 黒煙 + 明滅する点光源
    ALERT_AGENT_ACCIDENTAL_FIRE(失火) 煙だけが立ち上っている 薄い白煙のみ

    両ビットが同時に立っている建物は本格火災を優先する。ただし当エポックで焼け落ちた建物(status == STATUS_COLLAPSED)は、瓦礫の上で炎が燃え盛るのが不自然なためくすぶり(白煙)に落とす。

    アラートビットの意味・ライフサイクル・配信条件は アラートフラグ管理 を参照。火災は当エポック限りの揮発的イベントなので、エフェクトも「火災が発生したエポックの間だけ」表示され、次のエポック実行でビットが落ちると自動的に消える。

    実装ファイル

    ファイル 役割
    DataLoaders/FireEffectManager.cs アラート一覧とエフェクト実体の同期、配置解決、距離カリング、光源制御
    Utils/FireEffectFactory.cs パーティクルシステム一式の組み立て、テクスチャ・マテリアルの手続き生成
    Resources/Shaders/FireParticle.shader パーティクルの描画(前乗算アルファ + ソフトパーティクル)

    データ経路

    専用のHTTPエンドポイントは持たない。AlertManager が GET /api/v1/alerts で取得した応答を、そのまま FireEffectManager.ApplyAlerts(agents, filterMask) へ渡す(同じ情報のために2本リクエストを投げないため)。

    火災系の2ビットは consts.py の ALERT_AGENT_VFX_BITS としてアイコン対象(ALERT_AGENT_ICON_BITS)から分離されており、AlertManager はアイコンは生成しないが表示フィルタのマスクには含める。これにより表示パネルのアラートタブの「火災」「失火」トグルで炎・煙の表示をON/OFFでき、アラートレイヤー全体の表示トグル(AlertManager.IsVisible)にも追従する。

    エフェクトの配置

    エフェクトのルートは建物GameObjectの子にしない。建物はLODの個数上限(maxDetailedBuildingObjects)でGameObjectごと破棄され得るため、子にすると炎まで一緒に消えてしまう。ワールド座標に置いた専用ルート(FireEffects)の下に、建物の設置面(足元)を原点として配置する。

    寸法は建物ごとに解決する。

    値 解決順
    底面半径 建物ポリゴンの外接矩形。中心が矩形中央とは限らない(L字建物など)ため、中心から遠い側の辺で測る。取れなければ既定値
    高さ 実際に描かれているメッシュのAABB上端 − 地表高さ → 階数 × 階高(BuildingMeshUtils.GetFloorHeight) → 既定値

    炎の幅・煙の太さ・パーティクル発生量はすべてこの半径と高さから決まるため、小屋のボヤと工場の大火では規模がはっきり変わる。

    ApplyAlerts はカメラのセル跨ぎ(0.5秒間隔)でも呼ばれる。既に燃えている建物のエフェクトは作り直さず維持する(作り直すと煙柱が根元から生え直して目立つ)。作り直すのは種別が変わったときと、建物メッシュが後からロードされて寸法が 1.35 倍以上変わったときだけ。

    パーティクルの構成

    すべてローカル空間シミュレーション(ParticleSystemSimulationSpace.Local)で組む。発生源の建物は動かないためワールド空間にする利点がなく、ローカルなら親のスケールが煙柱全体に効き、FloatingOrigin によるワールドシフトでも煙が尾を引かない。

    各システムは prewarm = true で、表示された瞬間から煙柱が完成した状態になる。

    AddComponent<ParticleSystem> 直後は playOnAwake により再生状態なので、duration や prewarm を設定する前に必ず Stop する(これらは停止中しか変更できない)。

    炎 (Flames)

    建物上部を覆う厚みのある箱(高さの 0.8 付近、厚み 0.3)から吹き上がる。屋根だけでなく上層階の開口部からも噴き出している見え方にするための形状。発生源のXZは底面半径の 0.85 倍に収める(底面いっぱいに広げると建物より炎の方が大きく見えてしまう)。

    • 加算合成。色は寿命に沿って 白黄 → 橙 → 深紅 → 消滅
    • noise モジュールで揺らぎを与える(炎が「舐める」動き)
    • パーティクルは涙型テクスチャで、ビューアライン かつ allowRoll = false。カメラをロールさせても炎が横倒しにならず、常に上向きの炎として読める

    火の粉 (Embers)

    炎から舞い上がる細かい光点。ParticleSystemRenderMode.Stretch で進行方向に軽く伸ばし、点ではなく「飛んでいる火の粉」に見せる。負の gravityModifier で上昇し、強めのノイズで散る。

    黒煙 (Smoke)

    建物頂部の狭い範囲(底面半径の 0.5 倍)から立ち上り、上昇しながら 0.5 → 1.7 倍まで広がる。色は寿命に沿って 黒 → 灰 → 薄灰(冷えて拡散する表現)。velocityOverLifetime に建物IDごとの一定の水平ドリフトを与え、隣り合う建物の煙柱が同じ向きに揃わないようにする(方向は黄金角で回す)。

    「ゆらゆらと立ち上る」動きは SetSwayNoise が作る。 通常の SetNoise との違いは2点。

    • damping = false: damping は周波数に強度を比例させる設定なので、有効なままだと低周波では揺れがほとんど出ない。大きくゆっくり揺らすには切る必要がある
    • separateAxes = true で水平方向だけ強く揺らす(Y方向の強度は 0.2 倍)。Y方向まで同じ強度で揺らすと上昇速度が波打ち、ゆらゆらではなく上下に痙攣する動きになる

    煙は寿命が長い(6〜11秒)ぶん初速を落としてゆっくり昇らせる。prewarm は duration ぶんだけ空回しする仕様なので、duration は寿命の上限に合わせておく(足りないと表示された瞬間に煙柱が上まで伸びきらない)。

    失火の白煙

    炎・火の粉・光源を持たない単一の煙システム。発生範囲・発生量・上昇速度・不透明度すべてを黒煙より小さくし、「小火がくすぶっている」規模で描く。揺らぎは黒煙と同じ SetSwayNoise で、振幅と速度だけ落とす。

    点光源 (FireLight)

    本格火災のみ。夜間や日陰で炎が発光していることを周囲に伝えるための点光源で、影は落とさない。Light の強度は Perlin ノイズで毎フレーム明滅させ、炎の揺らぎと同期させる。

    URPのレンダラは Forward+ のため多灯自体は許容されるが、点光源は影響範囲が広く重なると白飛びしやすいので、カメラに近い順に maxFireLights(既定6)件までしか点灯しない。

    シェーダー (Custom/FireParticle)

    アルファを常に前乗算するため、通常合成と加算合成の切り替えが _DstBlend だけで済む(煙 = OneMinusSrcAlpha、炎・火の粉 = One)。マテリアルは種別ごとに1つを全エフェクトで共有するので、火災が何件あってもマテリアルは3種類しか存在しない。

    2つのフェードを持つ。

    • ソフトパーティクル: _CameraDepthTexture と自身の深度差でアルファを落とし、板ポリが建物や地形を貫いた断面の直線を隠す。URPアセットの m_RequireDepthTexture に依存する
    • ニアフェード: カメラに寄りすぎた粒子は画面全体を覆ってしまうため、一定距離より手前で薄くする

    描画順は 煙(3000) → 炎(3010) → 火の粉(3020) で、加算合成の炎が煙の上に重なる。

    アセット非依存

    炎・煙・火の粉のテクスチャは起動時に1度だけコード生成する(Mathf.PerlinNoise による fbm を使った涙型・雲状・光点)。アートアセットの追加なしで成立させるための設計で、生成したテクスチャとマテリアルは静的に共有される。

    爆破操作の単発エフェクト

    爆破成功通知 building:exploded は通常火災のアラートと別に扱う。対象建物の個別再取得後、STATUS_COLLAPSED の瓦礫へ即座に切り替え、VisualEffectManager.PlayExplosion が同じ場所で炎・煙・3D音を開始する。瓦礫の生成は既存の 倒壊建物のメッシュ生成 に委ねる。

    FireEffectFactory.CreateExplosion は通常火災と同じコード生成テクスチャ・共有マテリアル・Custom/FireParticle を使う。底面半径は火災と共通の FireEffectManager.ResolveFootprintRadius から取り、2.5〜35mに制限する。設置高さは BuildingManager.ResolveBuildingBaseHeight で瓦礫と揃える。

    • 赤橙の炎30粒を一度だけ放出し、0.3〜0.65秒で消す。
    • 灰色の煙45粒を一度だけ放出し、広がりながら上昇して1.8〜3.2秒で消す。
    • ループとprewarmは無効。画面外でも寿命を進め、3.5秒でルートを破棄する。timeScale=0 でも演出と後始末は実時間で進む。
    • 建物の子にはせず VisualEffectManager の子として管理し、LOD切替に余韻を切らせない。セッションの全消去時は ClearTransientEffects で音も含めて破棄する。破棄するのは VisualEffectManager 自身が生成した演出だけで、同じAppRootに同居する環境音・天候の子オブジェクトには触れない。

    音源は Resources/Audio/Effects/building-explosion.ogg（mitchelkの Explode001、CC0 1.0）。元WAVを44.1kHz・モノラルのOgg Vorbisへ圧縮して同梱する。音量は既存の ambience:volume（master×sfx）に基準ゲイン0.8を掛け、再生途中のミュートも反映する。俯瞰視点で聞き取れるよう距離減衰の範囲を80〜1800mにし、遠端で無音とする。出所・変換コマンドは unity/Assets/Resources/Audio/Effects/README.md、ゲーム内クレジットは tauri/src/data/credits.ts。

    検証は unity/Tests/Explosion/run-unity.ps1。本編のランタイム全体をコンパイルした後、独立Unityで炎→煙→消滅の画像、粒子数・音源インポート・音量変更・停止時間中の寿命・セッション全消去を確認する。本編の都市へ爆破要求は送らない。

    常時火災のパフォーマンス

    • 火災件数は都市規模でも高々数十件だが、煙柱はパーティクル数が多いため maxEffectDistance(既定1400m)より遠いエフェクトは GameObject ごと非アクティブにする
    • 距離判定と光源の割り当ては cullIntervalSeconds(既定0.25秒)ごとにまとめて行う
    • 各パーティクルシステムは ParticleSystemCullingMode.Pause で、画面外ではシミュレーションが止まる
