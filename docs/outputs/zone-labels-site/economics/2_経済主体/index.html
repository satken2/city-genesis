    2. 経済主体

    2.1. 経済主体とは

    経済主体(agent)とは、都市経済シミュレーションの基本単位となる要素であり、都市内の世帯・店舗・企業のみならず、プレイヤーが運営する市政府自身など、金銭や物資のやり取りがあるものはすべてである。 経済主体ごとに、資金や需要・供給などの情報を持つ。

    2.2. 経済主体の分類

    カテゴリ(type)とサブカテゴリ(variant)があり、以下のような階層構造となる。

    10: 一般施設
    ├ 1003: 牧場
    ├ 1009: 飲食店
    ├ 1051: 病院
    ├ 1052: 消防署
    └ 1053: 警察署
20: 共有建物
    ├ 2007: 高層アパート
    └ 2008: ショッピングモール
:

    以下のカテゴリがある。

    種類 定数 説明 作成可 生産 消費 雇用 スポーン
    市政府 TYPE_CITY=1 公共支出を行い、税収を受け取る ● ●
    教育機関 TYPE_EDUCATION=2 市民を教育する ● ● ●
    世帯 TYPE_HOUSEHOLD=3 市民が所属し、消費活動などを行う ● ●
    輸出入拠点 TYPE_TRADE=5 輸出入の際の取引相手。 ● ● ● ●
    一般施設 TYPE_STANDARD=10 店舗、工場、農地などあらゆる生産活動を行う施設 ● ● ● ● ●
    共有建物 TYPE_BUILDING=20 他の経済主体が入居することができる建物 ● ● ●
    オープンスペース TYPE_OPEN_SPACE=30 駐車場・駅前ロータリー・舗装広場・立体駐車場など、何も生産せず誰も雇わない公共の土地利用施設。建物として建設・修繕・解体のライフサイクルを持つが、市場・雇用・利益評価には一切参加しない。通り抜け可能なバリアント（passable）は稼働中に隣接する土地区画と道路の間の通行路になる（4_地区と土地区画 4.8 参照）。造成の整地工事・埋立工事もこのカテゴリで、範囲の地形を書き換えるための一時的な主体として置かれ、完了すると稼働せずに区画ごと消える（造成） ●

    カテゴリ（type）は経済主体の役割の分類であり、個々の施設の性格までを表すものではない。「労働者を一人も雇わない」「商品市場から原材料を仕入れない」といった性質は、カテゴリではなくサブカテゴリ（variant）ごとの係数（必要労働力や必要原材料など）で表現される直交的な性質である。例えば洋上風力発電所（12_建物の海上構造物）は無人で、原材料も市場から調達しないが、カテゴリとしては通常の一般施設であり、専用のカテゴリは追加されていない。同様に、オープンスペースの敷地を通り抜けられるかどうかもサブカテゴリの性質（passable）であり、平面の駐車場や広場は通り抜けられるが、立体駐車場は同じオープンスペースでも通り抜けられない。

    2.3. 経済主体のスポーンと削除

    経済主体のスポーン

    一部の経済主体は、特定の条件を満たした時にスポーンする。

    経済主体サブカテゴリ(variant) スポーンのタイミング
    世帯 世帯のメンバーが一定以上の年齢になったり婚姻した場合。または外部から移民が来た場合。
    一般施設 都市の中で商品の需要があると判定されたり、輸出することが可能だと判定された場合。
    共有建物 経済主体がスポーンしようとしたが、空きフロアがなくてスポーンできなかった場合。

    一般施設のスポーン候補は地区ごとに採算評価されたあと、都市全体で「労働者1人あたり期待利益」の降順に実行される。利益率ではなく労働者1人あたり利益で並べるのは、労働力が希少な局面で資本が奪い合うのは希少資源（労働者）1人が生む利益だからである。利益率で並べると、率は高いが労働集約的な業種（農業など）が労働余剰を先取りし、率は低いが労働をほとんど使わない業種（小売・サービス）が恒久的に劣後してしまう。労働余剰が潤沢な場合は全候補に労働が行き渡るため、実行順は結果に影響しない。

    また、都市内にまだ供給者が存在しない財を初供給する候補は、他の候補より先に実行される（ニッチの優先スポーン）。未供給財には市場価格が存在せず、推定利益率が原価ベースの下限に張り付いて実測利益率を持つ既存業種に常に劣後してしまうため、「競合のいない市場を狙う起業家」の行動として財ごとに一度だけ優先的に種蒔きされる。1号店が建って市場価格が形成された後は、通常の実測利益率ベースの評価に戻る。

    スポーンには採算（需要量・価格競争力・家賃）に加えて、都市の実物・金融資源による参入関門がある。

    • 労働力: 都市の余剰労働力（一般・高スキル別）が最低稼働分を下回ると立地できない
    • 高等教育パイプライン: 高度人材が不可欠な業種は、都市内に当該スキルの高等教育の受け入れ枠（17_教育）があるか、既に十分な規模の高スキル人材の集積が定着している場合にのみ立地する。「大学がハイテク産業を呼ぶ」という集積の因果であり、移民の欠員補充（18_移民）だけでゼロから高度産業を誘致することはできない
    • インフラ・原材料の存在: 電力・水道など輸入できない投入財は、都市内に供給者が存在しなければ立地できない
    • 原材料の調達可能量: 輸入できる原材料も無限には調達できない。都市の国内供給と輸出入拠点の取扱能力を超える生産規模では立地できず、大量の原料を必要とする重工業は大容量の拠点（港湾など）の整備が前提になる
    • 資本調達: 想定初期資本（建設費＋運転資金）が都市に蓄積された民間預金に対する与信の限度を超える案件は参入できない。小さな都市には大型工場のファイナンスが付かず、経済の成長とともに大型産業が解禁される

    経済主体の削除

    経済主体は 直近一定期間の平均利益がマイナスの場合に撤退する。

    • 建物を持つ経済主体の場合、「停止(STATUS_PAUSED)」状態となる。
    • 建物を持たない経済主体の場合、資金を清算した上で、経済主体は削除される。

    資金の清算とは経済主体の持つ資金や借金を都市全体に還元することである。詳細については7_金融システムを参照。

    2.4. 経済主体のステータス変遷

    経済主体は以下のようなステータスを持ち、ステータスによってできることが異なります。

    建物(is_bd=Trueの場合)はすべてのステータスを持つことができ、建物ではない場合(is_bd=Falseの場合)はSTATUS_TEMPORARY, STATUS_ACTIVE, STATUS_PAUSEDのみ持つことができる。

    ステータス 説明 都市シミュレーションでの動作 他のステータスへの変更 ステータス設定時の処理
    STATUS_TEMPORARY プレイヤーが経済主体を作成している途中 シミュレーションには影響せず、ユーザーの画面に表示されるのみ。 ユーザーの操作でSTATUS_SCHEDULED_CONSTRUCTIONに変更できる。オブジェクトを削除することもできる。 何もしない
    STATUS_PENDING プレイヤーが設置したが、まだ着工していない（保留状態） シミュレーションには影響せず、ユーザーの画面に表示されるのみ。 ユーザーの操作でSTATUS_SCHEDULED_CONSTRUCTION（着工）に変更できる。オブジェクトを削除することもできる。 何もしない
    STATUS_SCHEDULED_CONSTRUCTION 建物の建設が計画されたが、まだ着工していない 建物の建設が決定されたが、既存建物の買収が完了していなかったり、取り壊されていないなどの理由により建設が開始されていない。 立地パーセルのusage_idがVALUE_NONE（空き地）になったらSTATUS_CONSTRUCTINGに自動変更される。オブジェクトを削除することもできる。 同じ土地区画に存在する建物を検出し、取り壊し対象としてフラグ付けする
    STATUS_CONSTRUCTING 建物の建設が開始された。 シミュレーションのエポックごとに「建設サービス」財を消費し、消費した分だけ建設が進行する。 「建設サービス」財の調達量が必要量に達したら自動的にSTATUS_ACTIVEに変更される。ユーザーの操作でSTATUS_DEMOLISHINGに変更することができる。 立地する土地区画のusage_idを自エージェントのIDに更新する
    STATUS_ACTIVE 建設や設置が完了している。 経済活動が行われる。建物の場合は、入居が開始される。改修中は under_maintenance が真になり、同じく建設サービス財で進捗する。 市政府所有の建物の場合、ユーザーの操作でSTATUS_PAUSEDまたはSTATUS_DEMOLISHINGに変更することができる。 何もしない
    STATUS_PAUSED 建物が閉鎖されている 経済活動が行われず、テナントは退去させられる。周辺の治安と住環境に悪影響を与える。 市政府所有の建物の場合、ユーザーの操作でSTATUS_ACTIVEまたはSTATUS_DEMOLISHINGに変更することができる。民間建物の場合、フロア需要が増加したらSTATUS_ACTIVEに変わる。 入居テナントに退去フラグ（is_evicted）が設定される
    STATUS_DEMOLISHING 取り壊しが進行している シミュレーションのエポックごとに「建設サービス」財を消費し、消費した分だけ建設が進行する。 ステータスは変更できない。「建設サービス」財の調達量が必要量に達したらSTATUS_EMPTYに変更される。 入居テナントに退去フラグ（is_evicted）が設定される
    STATUS_COLLAPSED 倒壊した（原因はstatus_reasonが表す） 経済活動は行われない。周辺の住民心理に悪影響を与える。 市政府所有の建物の場合、ユーザーの操作でSTATUS_DEMOLISHING（取り壊し）またはSTATUS_CONSTRUCTING（再建）に変更することができる。 何もしない。ステータスを変更するのみ
    STATUS_EMPTY 建物の取り壊しが完了し、更地になった 取り壊し前に持っていたお金を残すために存在する。 買収が行われると資金が清算されて消滅する。 - 何もしない

    ステータス変更日と変更理由

    すべての経済主体は、ステータス本体に加えて以下の2つのプロパティを持つ。ステータスが変わるたびに両方が同時に更新される。

    • status_from … 現在のステータスになったゲーム内日付（1800-01-01起算の経過日数）。稼働中なら稼働開始日、停止中なら停止日、倒壊なら倒壊日を表す。
    • status_reason … 現在のステータスになった理由（REASON_*）。通常の遷移・作成直後はREASON_NONE。
    理由定数 値 意味
    REASON_NONE 0 既定。通常の遷移
    REASON_FIRE 1 火災による倒壊
    REASON_AGING 2 老朽化による倒壊・解体計画
    REASON_DEFICIT 3 低利益率による停止
    REASON_LOW_UTILIZATION 4 低稼働率による停止
    REASON_USER 5 ユーザー（市長）の操作・決定による変更

    2.5. 建物への入居

    経済主体はサブカテゴリ(variant)ごとに建物と、建物ではないものがある。 建物の経済主体は空いている土地に建設され、建物ではない経済主体は、別の共有建物に入居する形となる。

    フロア種別

    建物に入居する経済主体(non-building agent)の場合は、サブカテゴリ(variant)ごとに要求するフロアタイプがある。 フロアタイプが一致しない建物には入居できない。(詳細は12_建物に記載) 世帯でも、住民世帯は住居フロア、観光客世帯(31_観光)はホテルの宿泊フロアを要求する。

    2.6. テナントの退去

    共有建物(TYPE_BUILDING)がSTATUS_PAUSEDまたはSTATUS_DEMOLISHINGになると、入居しているテナントは退去しなければならない。 低利益率・低稼働率を理由に建物がSTATUS_PAUSEDに変更された場合も、直ちにテナントのis_evictedが設定される。
