    A. パス形状

    ロープウェイ（601）とロープウェイ駅（602）は、各中間ウェイポイントで前後のアンカーを結ぶ水平進行方向の変化を5度以内に制限する。直進は0度、折り返しは180度として扱い、高低差による上下勾配は含めない。境界の数値誤差は0.001度まで許容し、水平位置が重複して方向を定義できないウェイポイントは拒否する。Unityは配置・編集時に違反箇所を赤線と角度ラベルで示し確定を禁止する。バックエンドも新設・形状変更・事前検証で同じ判定を行う。送電線の角度や別パスとの接続角にはこの制限を適用しない。

    パスの幾何学的な表現、ベジエ曲線の定義、道路ポリゴンの生成、および道路土地区画の作成について。

    A.1. 形状パラメータ一覧

    パスの形状を決定するパラメータは以下の通り。

    ユーザーが直接指定するパラメータ

    パラメータ プロパティ名 型 説明
    始点アンカー start_point [x, y, z] パスの開始位置。3次元座標で指定する。yは高さ（標高）を表し、省略時は 0.0 となる。ステータスが STATUS_TEMPORARY の間のみ変更可能。
    始点制御点 start_control [x, y, z] または null 始点アンカーの出口方向の制御点。3次ベジエ曲線のP1に相当。未指定の場合は「制御点の自動補完」の規則で自動設定される。
    終点アンカー end_point [x, y, z] パスの終了位置。座標形式・制約は始点に同じ。
    終点制御点 end_control [x, y, z] または null 終点アンカーの入口方向の制御点。3次ベジエ曲線のP2に相当。未指定の場合は「制御点の自動補完」の規則で自動設定される。
    ウェイポイント waypoints [{"position": ..., "control_in": ..., "control_out": ...}, ...] 始点と終点の間に配置する中間アンカー点。0個以上。各ウェイポイントはアンカー位置と2つの制御点を持つ。STATUS_TEMPORARY の間のみ変更可能。
    盛土オフセット embankment_heights [float, ...] 各アンカー(始点・ウェイポイント・終点)の盛土・切土高さ(m)。-5〜+5。長さは waypoints.length + 2。道路のY座標自体は0のままだが、着工時にこの高さだけDynamicティアの地形を変形させる。全道路タイプで指定可能。地形追従しないパス（下記 follow_terrain）では指定できず、相対Yが0でないアンカー（高架・地下）にも設定できない。
    地形追従 follow_terrain int パス個別の地形追従設定。-1（未設定＝バリアント既定に従う）／0（非追従）／1（追従）。上書き（非-1の設定）は height_editable=true のバリアントのみ可能で、STATUS_TEMPORARY／STATUS_PENDING の間だけ変更できる。詳細はA.2を参照。
    パス種別 path_type int PATH_STREET（街路）、PATH_MOTORWAY（高速道路）、PATH_TRACK（線路）など。道路幅や接続先ノードの種類を決定する。
    パス仕様 path_variant int 同一パス種別内での詳細仕様。マスターデータ (path_master) のキーであり、道路幅 (width) やキャパシティ (capacity_base) などの物理パラメータを間接的に決定する。

    ウェイポイントの構造

    各ウェイポイントは以下のプロパティを持つオブジェクトである。

    プロパティ 型 説明
    position [x, y, z] アンカー点の位置。必須。
    control_in [x, y, z] または null アンカー点への入口制御点。前のアンカーからこのアンカーに向かう3次ベジエのP2に相当。未指定時は自動設定。
    control_out [x, y, z] または null アンカー点からの出口制御点。このアンカーから次のアンカーに向かう3次ベジエのP1に相当。未指定時は自動設定。

    システムが算出する派生パラメータ

    パラメータ プロパティ名 型 説明
    道路幅 width float マスターデータの path_variant に紐づく width から取得。道路ポリゴンの生成に用いる。
    物理長 length float 始点から終点までの2次元平面上の直線距離（ユークリッド距離）。ベジエ曲線に沿った実際の弧長ではなく、始点・終点間の直距離である。
    中心点 center_point [x, z] 始点・全ウェイポイントのアンカー点・終点の2次元座標の算術平均。制御点は含めない。R-tree空間インデックスのキーとして使用される。
    キャパシティ path_capacity float パスが1エポックで処理できる交通量の上限。capacity_base、レーンあたり秒間容量、1日の稼働時間から算出される。
    基本通過速度 base_speed float 道路形状のみを考慮した通過速度（km/h）。制限速度、カーブ、勾配の影響を反映し、交差点での減速・停止は含まない。幹線道路と生活道路のみ算出。詳細は通過速度を参照。
    制限速度 max_speed float 都市が定めるパスバリアントごとの制限速度（km/h）。既定値はマスターの default_speed_limit で、規制の変更は敷設済みのパスにも反映される。パス個別に上書きも可能（override_max_speed。この場合は規制の変更より優先される）。

    A.2. 座標系の取り扱い

    パスの座標はゲーム内3次元座標 [x, y, z] で表現される。y は高さ（標高）を表し、不明な場合は 0.0 が補完される。 Shapelyによる幾何計算を行う際は、高さを無視した2次元座標 (x, z) に変換して用いる。座標は normalize_coordinate_3d によって常に [x, y, z] 形式に正規化されてから保持される。

    盛土オフセット(embankment_heights)

    盛土オフセットは、道路のY座標とは独立して指定する地形変形量である。道路のY座標が0（地面張り付き）のままで、地形側を持ち上げたり掘り下げたりすることで、見た目上の道路高さを表現する。

    交差点での接続補正も造成側で行い、道路座標の高架・地下高さへ転記しない。完成時の道路分割・ノード溶接では指定高さと地形追従設定を保持する。保存された造成用縦断には盛土と接続補正が含まれるため、施工済み地形へ盛土量を重ねて加算しない。

    • 高架・地下（height_editable=trueのバリアント）: アンカーのY座標を直接設定して路面を空中に浮かせる／地中に沈める。地上・高架・地下はバリアントではなくアンカーの相対Yで決まり、1本のパスに混在できる。着工時の造成は相対Y=0のアンカーで挟まれた地形追従スパンの区間だけに及び、高架区間の下の地形は変形しない。
    • 盛土道路（embankment_heights指定）: Y座標は0のまま、着工時にDynamicティアの地形を指定された高さに変形する。全道路タイプで指定可能。地形追従しないパスとは併用できず、相対Yが0でないアンカーには設定できない。

    進行方向の平滑化（smooth_factor）

    path_master.smooth_factor は、造成時に進行方向の起伏を均す距離尺度（m）である。大きいほど広い範囲の起伏を均す。0は進行方向の平滑化なしを表し、道幅方向の整地や交差点の平坦化まで無効にする設定ではない。

    パス smooth_factor（m）
    未舗装路 0
    歩行者専用道路 5
    極小路地 10
    1車線生活道路・道路橋・歩行者専用道路(LRT付き) 30
    2車線生活道路 40
    LRT線路付き生活道路・4車線生活道路 50
    モノレール線路 50
    鉄道線路・鉄道橋梁・LRT専用軌道、高速道路、モノレールのホーム 80
    鉄道のホーム 100
    ロープウェイ・ロープウェイ駅（人員搬送。地形非追従のため通常の造成は通らない） 10

    電化の有無では値を変えない。高架・地下のバリアントにも同じ用途の値を設定するが、通常の造成を通らない区間には適用されない。保存済みの駅共通標高がある場合は、その標高が優先される。仮想道路・公共交通の論理路線・インフラ・駅舎の係数は造成に使われない。

    この値は最大勾配の保証ではない。造成済みの地形をマスター変更だけで再平滑化することもない。Unityは造成後の地形に追従して描画するため、進行方向の平滑化を描画側で重ねて行わない。

    勾配検証の地形標高は描画と同じ現在標高を補間して取得する。未舗装路の平滑化0は地形の起伏を均さないという意味であり、格子点へ丸めて階段状に読む設定ではない。編集用セル配列の有無でも標高の読み方は変わらない。

    地形追従（follow_terrain）

    敷設中は造成予定を半透明の体積として重ね、切土を橙、盛土を青で表示する。POST /api/v1/paths/earthwork-previewが返す各セル4隅の[x,z,元標高,造成標高]から柱を作る。操作が250ms止まった後に更新し、編集終了時には消す。実地形を変更するプレビューではなく、切土の底も地形越しに見せる専用表示である。表示形状は間引くが、体積は間引く前の格子から求めた概算で、建設費そのものではない。着工までの周辺変更や完成時の交差点整地によって結果は変わり得る。

    地形追従とは、相対Yが0のスパンを地形の起伏に張り付かせる挙動である。追従するかどうかは2層で決まる。

    • バリアント既定: path_master の follow_terrain（既定 true）。橋バリアント（follow_terrain=false）は相対Yが0でも地形追従しない。
    • パス個別上書き: パスの follow_terrain（-1＝未設定でバリアント既定に従う／0＝非追従／1＝追従）。個別値が最優先され、未設定のときのみバリアント既定に従う。個別上書きは height_editable=true のバリアントに限り、STATUS_TEMPORARY／STATUS_PENDING の間だけ変更できる。

    非追従（実効的に follow_terrain が false）のパスは、Y座標が0のスパンでも地形追従せず、アンカー絶対標高のみからの補間で構成される。これにより、手動で標高を刻まなくても次の挙動が自動的に得られる。

    • 谷を跨ぐ区間は、両端の地盤高を結ぶ水平・斜路デッキ（＝橋）になる。地形は変形しない。
    • 丘に差し掛かる区間は、道路の絶対標高が地形標高を下回るため深さが正になり、切り通し（開削）やトンネルとして扱われる（深さがクリアランス高さを超えるとトンネル、坑口が自動生成される）。1本のパス内で橋⇔トンネルを何度でも遷移できる。詳細な区間分類は3_道路網の地下パス節を参照。

    非追従パスのアンカー自体は従来どおり地形にピン留めされる（絶対標高＝アンカー直下の地形標高＋相対Y）ため、両端の相対Yが0なら前後の地面と面一に接続する。非追従パスが絡む交差の高さ評価は常に絶対標高で行われる。詳細はJ_パスの交差処理を参照。

    直線モード（curved=false）の非追従区間は、各アンカーの絶対標高を直線で結ぶ。地面からの相対高さがノードごとに違っても、絶対標高が一定勾配の直線上にあれば、ノード周辺だけ勾配が増えることはない。縦断面表示・線形検証・造成プレビュー・深度判定でもこの補間を使う。曲線モードでは所属アンカーの地盤を基準に保存制御点を絶対化してベジエ補間する。

    盛土オフセットは各アンカー(始点・ウェイポイント・終点)ごとに設定でき、アンカー間は線形補間される。これにより坂道も作成可能。範囲は -5m（切土）〜 +5m（盛土）。

    着工時(STATUS_CONSTRUCTING)に flatten_terrain_for_path が呼ばれ、道路ポリゴン内の地形を「元地形の中心線標高 + 盛土オフセット」の高さに平坦化し、周辺を滑らかな勾配（SLOPE_RATIO=2.0）で接続する。切土（マイナス）の場合も同様に、道路が低くなる方向に地形を変形する。

    A.3. ベジエ曲線の定義

    3次ベジエ曲線

    パスの形状は3次ベジエ曲線（cubic Bezier curve）の複合セグメントで表現される。直線も3次ベジエ曲線の一種（制御点が直線上にある場合）として統一的に扱われる。

    3次ベジエ曲線は4つの制御点 P0, P1, P2, P3 で定義され、曲線上の点 P(t) は次のように計算される。

    P(t) = (1-t)³·P0 + 3(1-t)²t·P1 + 3(1-t)t²·P2 + t³·P3
    • P0: セグメントの始点（アンカー）
    • P1: P0の出口制御点
    • P2: P3の入口制御点
    • P3: セグメントの終点（アンカー）

    複合ベジエパスの構造

    パスは複数の3次ベジエセグメントを連結した複合ベジエパス（composite Bezier path）として構成される。セグメント数はウェイポイント数によって決まる。

    ウェイポイントなしの場合（1セグメント）:

    start_point → start_control → end_control → end_point
    (P0)          (P1)           (P2)         (P3)

    ウェイポイントがN個の場合（N+1セグメント）:

    セグメント0: start_point → start_control → wp[0].control_in → wp[0].position
セグメントi: wp[i-1].position → wp[i-1].control_out → wp[i].control_in → wp[i].position
セグメントN: wp[N-1].position → wp[N-1].control_out → end_control → end_point

    制御点の自動補完

    フロントエンド（Unity/UI）から制御点が送られてこなかった場合、システムは未指定（null）の制御点だけを自動計算して永続化する。この計算はUnity側の描画（PathManager.CalculatePathPoints）と同一ロジックであり、片方だけ変更するとバックエンドの占有ポリゴン・土地区画の判定と画面に描かれる道路の形状が食い違う。

    • ウェイポイントなし: 始点→終点を1/3・2/3に内分した位置（直線ベジエ）。
    • ウェイポイントあり: アンカー列 A = [始点, ウェイポイント…, 終点] に対するCatmull-Romスプラインの接線から計算する。
      • 接線 T_i = A_{i+1} − A_{i-1}（端点は片側の隣接アンカーとの差分）
      • 出口制御点（control_out / start_control）= A_i + T_i / 6
      • 入口制御点（control_in / end_control）= A_i − T_i / 6

    端点の制御点を自動補完する場合、その端点が既存パスへ接続するときは、接続先パスの端点における接線（延長線方向）へ制御点を整列させる。対象は自動計算した制御点方向との角度差が PATH_TANGENT_ALIGN_MAX_ANGLE_DEG（20°）以内の接続先だけで、複数あれば角度差が最小のものを選ぶ。明示された制御点は変更しない。Unityは整列済みの制御点を明示して送るため、この整列が効くのは制御点を省略したAPI直呼びと内部生成である。

    制御点の手動調整はUnityの3Dビューでのドラッグのほか、UIの2Dパス形状編集パネル（都市マップ上でノード・制御点を真上から動かす）からも行えるが、いずれも形状はUnity側が組み立てて同じ規則で確定送信に載る。手動調整で変わるのは制御点の平面位置だけで、高さはアンカーの縦断勾配から決まる（Unity入力制御「高架の制御点と縦断形状」）。ウェイポイントの制御点（自動計算された値を含む）はAPIレスポンスの waypoints に、端点の制御点はレスポンスの start_control / end_control に含まれ、Unityは保存値を優先使用する。保存値が無い制御点だけを上記と同一式で自前計算するため、ユーザーが制御点をドラッグで調整したパスも含めて、バックエンドの占有ポリゴンと画面に描かれる形状は常に一致する。

    パス形状（始点・終点・ウェイポイント）が更新された場合、リクエストで明示されていない start_control / end_control は旧形状の値を破棄して新しい形状から再計算される。

    端点が既存パスの端点に接続する場合、自動補完された端点の制御点は、その既存パスの延長線方向へ向きを揃える（長さと相対高さは保つ）。揃えるのは自動接線との角度差が20°以内のときだけで、候補が複数あれば角度差が最小のものを採り、明示的に指定された制御点には触れない。この整列もUnity側の敷設プレビューと同じ規則で行う。

    A.4. バックエンドでのベジエ処理

    バックエンドの幾何計算では、3次ベジエ曲線を一定数の点にサンプリングして折れ線（LineString）に変換してから処理する。デフォルトでは各セグメントを12分割してサンプリングする。

    このサンプリング済み折れ線を用いて以下の処理を行う。 - Shapelyによる交差判定と分割 - 道路ポリゴンの生成（中心線のバッファリング） - バウンディングボックスの計算

    De Casteljauのアルゴリズム

    パスが交差して分割される際、De Casteljauのアルゴリズムを用いて元のベジエ曲線の制御点を適切に分割する。これにより、分割後の各パスも正確なベジエ曲線として表現される。

    分割点のパラメータtは、サンプリング済み折れ線上で最も交差点に近いサンプル点から逆算される。

    A.5. 道路ポリゴンの生成

    パスが道路上の土地区画を作成したり、既存の土地区画との重複を検出したりする際、パスから道路の占有領域を表すポリゴンを生成する。

    1. パスの3次ベジエセグメントをサンプリングして中心線 (LineString) を構築する
    2. マスターデータの width から道路幅を取得する
    3. 中心線を道路幅の半分だけ両側にバッファリングし、平坦なキャップスタイルと角張った接合スタイルを用いてポリゴンを生成する

    A.6. 道路土地区画の作成

    パスが STATUS_CONSTRUCTING になると、道路のpolygon属性がセットされる。

    パス沿いの土地区画生成

    パスの建設後、プレイヤーはパスに沿って建物用の土地区画を追加で生成できる（4_地区と土地区画の「パス沿いの区画作成」）。この機能では、パスの左右いずれかの側を指定し、幅と奥行きを与えることで、道路に沿った台形の区画が連続して生成される。

    各区画は、パスの各セグメント（アンカー点同士を結ぶ直線区間）を指定された幅で等分割し、各分割点から道路に対して直交する方向（法線方向）に指定された奥行きだけ伸ばした台形として生成される。折れ線パスの折れ点では帯を区切って角地を作り、曲線パスでは頂点の法線を平均化して1本の帯として接合する（B_土地形状 B.4.2）。

    A.7. パスの交差

    パスがアクティブ化されるとき、既存のアクティブなパスとの交差判定が行われる。2つのパスが交差した場合、交差点にノードが自動作成され、両パスがそのノードで分割される。これにより道路ネットワークのグラフ構造が自動構築される。

    公共交通パス (PATH_TRANSPORT) は交差処理の対象外である。また、同一の既存パスとは最大1か所でしか交差できない。

    インフラパス（送電線 PATH_ELECTRICITY・導水管 PATH_WATER・パイプライン PATH_PIPELINE）は、同じ網（path_master の infra_products に共通の製品を持つバリアント）どうしの場合のみ交差処理の対象になる。異種パスとの交差、および別網どうし（送電線×導水管など）の交差ではノード生成も分割も行われない。端点の溶接（近接する既存ノードへの接続）も同じ網互換の判定でゲートされ、送電線の端点が導水管のノードやインフラ施設の異種の接続端子ノードに接続されることはない（26_インフラ網参照）。

    交差はしていないが距離が閾値以下のパスについても、一方の端点が他方の内点に近い場合はT字路として自動接続される。この判定は対称であり、2つのパスがどちらの順で完成しても（同時でも）接続結果は同じになる（詳細はJ_パスの交差処理を参照）。

    パスが分割された場合、De Casteljauのアルゴリズムによって分割後の各パスのベジエ制御点が計算され、物理長・中心点・キャパシティ・通過速度などの派生値が再計算される。

    プレイヤーが任意の地点でパスを分割する場合も同じDe Casteljau分割を使う。切断位置は指定地点を中心線へ射影した垂線の足で決めるが、サンプリングの量子化で実際の切断点は射影の足から数十cmずれ得るため、レスポンスの分割点には射影の足ではなく実際に切った点を返し、ノード座標と両パスの端点を厳密に一致させる。端点から1m未満の地点では分割しない。

    A.8. 都市境界との処理

    パスの端点が都市限界の外側にある場合、パスの中心線と都市限界ポリゴンの境界との交点のうち、端点に最も近いものに座標がスナップされる。スナップされた位置には、外部接続を示す interconnect フラグが付与されたノードが作成される。都市限界の内側にある端点は、近接する既存ノードに接続されるか、新規ノードが作成される。

    A.9. バリデーション

    接続予定先を含む縦断設計

    既存道路・線路へつながる新設パスは、接合後の高さを敷設前に設計して勾配を判定する。対象は端点近傍の完成済み・建設中パスで、端点への延長とパス途中への合流を扱う。絶対標高が離れた立体交差や互換性のない網は補正しない。

    接続先の絶対標高と接線勾配に合わせ、接続端を含むアンカー間の縦断を補間する。水平な接続先では端部が水平になり、傾斜中の接続先では進入方向へ投影した勾配に接続する。補正後の中央区間も含めて最大勾配を検証するため、短すぎる坂が自動的に許可されるわけではない。駅の共通断面はその設計を維持する。

    完成予定の絶対標高は既存のstation_grade_profileフィールドに保存する（駅専用ではない）。敷設プレビュー・線形検証・土工見積・施工・完成後の描画がこれを参照する。独立した接続縦断のstation_grade_idはconnectionで、駅共通グループとは区別する。竣工時に交差点の水平化で上書きしない。形状を編集した計画は接続条件を再評価する。

    Unityは保存標高の線分へXZで最近接射影し、両端の絶対標高を線形補間する。同距離の線分がある場合は保存点列で先の線分を選ぶため、自己交差や逆向きのパスでも探索順によって高さを変えない。描画と吸着は同じ受信点列の型変換と線分の包囲矩形の索引を共有し、近い範囲から探索する。点列は受信後に変更せず、データ更新時には新しい点列から索引を作る。地形の常駐変更による中心線の再生成では索引を再利用し、数千点の標高列と中心線を総当たりで照合しない。

    道路・軌道の建設パネル共通の PathBuildSections では、盛土・切土高さを -5〜+5m の小数で指定する。増減ボタンは0.1m刻み、手入力は0.01m・0.025mなど刻み幅より細かい値も受け付ける。NumberStepper は小数の増減時に浮動小数点の末尾誤差を除き、手入力値を0.1m単位へ丸めない。IPC・APIも小数の embankment_heights を渡す。ただし実地形への反映精度は地形データの格子間隔と数値型に依存する。

    パスの始点・終点・ウェイポイントのアンカー位置がすべて海岸線ポリゴンの内側に存在しなければならない。いずれかのアンカー点が海岸線の外にある場合、パスの作成は拒否される。制御点の海岸線チェックは行わない。

    ただし path_master の over_water_allowed が立っているバリアント（海底送電線・海底石油パイプライン）は、この検証を免除され、海岸線の外へアンカーを置ける。免除はパス種別単位ではなくバリアント単位であり、同じ送電線でも地上用のバリアントは海へ出せない。海岸線ポリゴンは湖と川の範囲を穴として含む（D_地形形状 D.10.3・D.11.5）ため、この免除は海面だけでなく湖面・川面の上にも効く。形状変更（アンカー・ウェイポイントの更新）でも同じ免除が働き、バリアントと座標を同時に変更する場合は変更後のバリアントで判定する。バリアントの造り替えでも造り替え後のバリアントで検証するため、海上にアンカーを持つパスを免除のないバリアントへ造り替えることはできない。

    アンカーが陸にあっても、アンカー間の区間が海・湖・川の上を通る場合は、その区間が橋（路面が水面より WATER_BRIDGE_MIN_CLEARANCE 以上高い）か完全埋設トンネルでなければならない（J_パスの交差処理 の「川の横断」「海・湖の横断」）。したがって地形追従の道路で入り江や湖をまたぐことはできず、両端を陸に置いた橋か地下で渡る。海・湖の横断の検証は、インフラパスと over_water_allowed のバリアントを対象外とする。

    海岸線ポリゴンは埋立の完了で広がる（D_地形形状 §D.17.4）ので、埋立地の上にはアンカーを置ける。ただし埋立地の岸壁の天端（帯）の中には、高架・地下のパスでもアンカーを置けず、帯を地表で横切る区間も拒否される（J_パスの交差処理 の「埋立地の岸壁の横断」。インフラパスなど地形を書き換えない種別は対象外）。

    線形（曲線半径・勾配）もバリアントの規格で検証される。中心線を1m間隔で再標本化し、前後10mの3点を通る円の半径を局所曲線半径、造成または高架設計後の絶対標高の差を実水平距離で割った値を勾配として、path_master の min_curve_radius（m）を下回る区間や max_grade（%）を超える区間があれば作成・形状変更を拒否する（0は制限なし）。Unity の操作中プレビューはローカル推定し、違反区間を赤い線で示す。規格の一覧と通過速度への影響は3_道路網の線形制約の節を参照。

    A.10. 形状変更後の再計算

    STATUS_TEMPORARY のパスに限り、始点・終点・制御点・ウェイポイント・パス種別・地形追従（follow_terrain）の変更が可能である。形状に関わるフィールドが変更された場合、中心点の再計算が行われる。

    max_speed はパスがアクティブな状態でも変更可能であり、変更されると基本通過速度 (base_speed) が再計算され、周辺500m以内の土地区画の経路キャッシュが更新される。

    駅線路の保存済み絶対標高

    同時敷設した駅線路には station_grade_profile（共通基準線の [x,絶対標高,z]）が付く場合がある。この場合、アンカーの相対Yから地形を足す通常の計算よりも保存済み標高を優先する。XZ最近接射影で高さを補間するため、逆向きや曲線の内外でも同じ断面を参照できる。基準線は分割後も保存し、相方線路の存在や現在の地形から再計算しない。詳細は 線路メッシュの生成。

    地上パスの勾配は、smooth_factorによる造成後の縦断と盛土設定を含めて評価する。地上の複線ホームも同じ平滑化距離で共通標高を設計する。高架・地下は設計標高をそのまま評価し、規格超過を平滑化で隠さない。
