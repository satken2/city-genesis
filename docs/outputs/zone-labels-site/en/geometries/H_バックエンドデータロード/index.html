    バックエンドデータロード

    Unityは、コアのHTTP APIから取得した都市データを常駐範囲内に描く。CellDataLoader がロード全体を調整し、各マネージャーがデータと描画オブジェクトを管理する。常駐範囲と描画品質の判定はLOD処理、各対象のメッシュ生成は個別ページに定義する。

    更新の起点

    起点 更新
    カメラの移動・投影条件の変化 常駐集合の差分を取得・退避する
    エポック完了・編集確定・session:reload ReloadAllData で取得済みデータを要再取得にする
    強制リロード 現在の範囲を取り直す
    セッション切り替え・ゲーム終了 進行中処理と全データを消去する

    更新要求は LoadBatch で管理する。新しい要求は旧バッチを取り消す。カメラ由来の要求は短い間隔で合流させ、最後の視点で常駐集合を計算する。要再取得の記録は要求時に付け、取得・適用の成功後に消すため、途中で取り消されても次のバッチへ引き継がれる。

    取得と差分の基準

    以下のAPIパスは /api/v1 からの相対パスである。

    データ 取得 差分の基準
    表示地形 /terrain/cell-versions → /terrain/surface 編集セルと隣接依存を含む派生版
    全景地形 /terrain/far 地形編集の版
    建物 /buildings/?bbox=...&limit=500&cursor=0 version と描画に影響する形状・状態・敷地・地形
    道路・ノード /paths/?bbox=...&limit=500&cursor=0、ノード一覧 version、接地と接続形状
    区画 /parcels/?bbox=... version、重心の属するセル
    地区 /zones/ の全量 version
    資源 /resources の一覧 分布と地形
    IC/JCT・名前付き道路 /interchanges/、道路一覧 一覧の版・内容
    プロップ 常駐範囲の配置と障害物のスナップショット 配置・障害物の署名

    建物と区画は、新規の常駐セルと要再取得セルを対象にする。建物はティア変更も取得の起点になる。取得矩形からはみ出して届いたデータを取得対象外セルへ生成しない。地区・IC/JCTはエポック完了や編集確定でも一覧を取り直す。

    建物・道路の一覧は next_cursor がnullになるまで取得する。全ページが成功した後に、対象範囲の一覧から消えたIDを削除する。ページの失敗や後退したカーソルでは同期を確定しない。区画一覧が上限に達した場合は対象範囲を分割して取り直す。

    データの受信と描画の完成は別の状態である。生成が中断された同じ版のデータも、描画が未完成なら再処理する。アラートだけの更新はメッシュの版に反映されないため、専用APIを使う。

    地形の取得と公開

    地形APIの標高はfloat32 little-endianの正方格子で、X-Grid-Rows/Cols と X-Cell-Version を伴う。常駐セルの解像度は513格子。版一覧に無いセルは版0として扱う。カメラ移動では短時間の版一覧キャッシュを使い、編集・エポック完了・全消去で無効化する。

    タイルは表示から切り離した TerrainData へ適用し、完成後に差し替える。表示・コライダー・接地の参照先と版は同じ公開時点で更新し、その後に OnTerrainTileReady を通知する。全タイルの完了通知は個別通知の後に出す。取得失敗時は再試行し、必要な地形が未適用のまま後続生成へ進まない。

    タイル取得の寿命はセルの常駐期間であり、バッチの取り消しだけでは止めない。後続バッチは同じジョブを再利用する。セルが常駐外になったときと全消去で取り消す。

    常駐外の完成タイルは、非表示のLRUへ最大24枚保持する。再入場時に版が一致すれば再取得せず復元する。非表示タイルを接地・GPU高さ窓・全景マスクから参照しない。復元でも通知は出るため、依存側は通知の有無ではなく地形の版で再生成を判断する。

    依存する描画の更新順序

    1. 地形を公開し、既存の道路・建物・プロップを追従させる。
    2. 区画を取得・適用する。海上区画の建物は区画の基準標高に依存する。
    3. 建物・道路を取得して生成する。道路の変更に応じて接続ノードの交差点も更新する。
    4. 地区・資源・プロップなどを更新する。

    バッチ中の地形通知は統合し、対象セルとその近傍だけを更新する。中断した追従は未完了分を引き継ぎ、地形やデータが変わった対象の完了記録を無効化する。常駐セルへ戻っただけでは道路の形状世代を進めない。

    TerrainManager.GetTerrainSignature は範囲内のセル版・全景版・全消去の世代を表す。建物・道路・交差点・プロップは生成時の署名と現在値を比較し、同じなら再生成を省く。区画は保持した高さと形状を比較する。接地の共通窓口はLOD処理の接地仕様に従う。

    描画の寿命と時間予算

    生成と退避は RenderWorkScheduler の共通フレーム予算で分割する。セルの離脱時は対象を非表示・退避し、同じ描画キーなら再入場で復元する。複数セルに跨る道路は常駐セルに属する間残す。キャッシュから復元するときも地形の署名を照合する。

    長い道路は本体の作成後に区間パーツを生成する。PathPresentation は新しい全パーツの準備が終わるまで旧道路を保持し、完成時に一括で表示を差し替える。生成途中の候補は表示しない。連続更新でも表示中の旧道路を引き継ぎ、アンロード・全消去で解放する。

    地区名と建設可能建物のアイコンは、地区中心を画面へ投影して固定サイズの2Dオーバーレイとして表示する。アイコンは地区名の下に1行5個まで並べ、各行を中央揃えにする。サイズは ZoneManager の定数で管理し、ラベルの表示可否は枠線の視錐台カリングとは別に判定する。

    地区名・アイコンと道路名の表示距離は、カメラ直下の地表からの高さに応じて変わる。高さ0m以下では100m、1,000m以上では4kmとし、その間は直線的に広げる。Utils.GetMapLabelMaxDistance でこの規則を共用し、カメラからラベルまでの3D距離が上限を超えるものやカメラ背後のものを隠す。

    セッション切り替え

    session:reset から session:reload までカメラ由来の取得を停止する。地形・全景・描画キャッシュ・空間索引・進行中ロードはセッション単位で破棄し、旧セッションの非同期結果を公開しない。別の都市で同じ版番号を使っていても再利用しない。

    全景の標高受信とメッシュ完成も区別する。生成途中で中断した場合は受信済みデータから再開し、完成前に生成済みとして扱わない。session:reload 後は静止したカメラでも新しい都市のロードを開始する。

    初期ロードの完了

    GameStateManager.IsGameStarted() は取得の許可、IsWorldVisible は表示の許可である。暗転中もLOD判定用のカメラは有効に保ち、入力を抑制する。

    CellDataLoader.IsInitialSceneReady は、初期視点の地形・区画・建物・道路・地区・資源・プロップと、関連する区間・敷地装飾・コライダーの準備を待つ。保留中のカメラバッチも未完了として扱う。常駐ワーカーは実行可能な未処理仕事だけを完了判定に含め、視野外の意図的な遅延生成や遠景結合を待ち続けない。

    保存カメラの復元と描画準備の完了を連続3フレーム確認して game:loaded を送る。初期ロードは初期視点の常駐範囲と全景の準備であり、都市全域の詳細モデルの生成ではない。

    実装の入口

    DataLoaders/CellDataLoader.cs が更新要求と依存順序、TerrainManager が地形の公開、各 *Manager が対象データと描画の寿命を管理する。逆引き索引・キャッシュキー・ログ項目の詳細はそれぞれのソースを参照する。

    ロードの性能計測は LocalConstants.UNITY_LOG_TIMING、画面上の描画統計はF8を使う。通信完了・生成要求・表示完了は異なる時点なので、計測値も区別する。
