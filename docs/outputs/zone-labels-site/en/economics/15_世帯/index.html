    15. 世帯

    市民のライフイベントや通勤・通学・教育について。

    都市内の人口動態を制御し、出生・死亡・結婚・独立などのライフイベント、および通勤・通学による交通負荷計算と教育システムを管理する。毎エポック、各市民の状況を更新し、都市の人口構成と経済活動に動的な変化をもたらす。

    15.1 世帯と市民の考え方

    世帯と市民の関係

    世帯は type=household の経済主体として管理される。各世帯には複数の市民（Citizen）が属する。市民は citizen_type として MEMBER_SINGLE（単身）または MEMBER_MARRIED（既婚）のいずれかを持ち、婚姻成立時に MEMBER_MARRIED に更新される。

    市民の属性

    市民は Citizen エンティティとして管理され、以下の主要な属性を持つ。

    • age ... 年齢
    • gender ... 性別
    • citizen_type ... 配偶関係（MEMBER_SINGLE / MEMBER_MARRIED）
    • household_agent_id ... 所属する世帯の経済主体ID
    • employer_agent_id ... 雇用先の経済主体ID（無職の場合は未設定）
    • school_agent_id ... 在籍中の学校の経済主体ID（非学生の場合は未設定）
    • skills ... スキル群（最大6種のスキル値を保持）
    • education_skill ... 高等教育で習得中の専攻スキル
    • is_immigrant ... 移民かどうかを示すフラグ（True=外部からの移民、False=都市内生まれ）

    15.2 市民ライフイベント

    市民のライフイベントは毎エポック実行される。各イベントは独立したフェーズとして処理され、年齢更新→死亡→独立→婚姻→出生の順に実行される。

    年齢更新

    ゲーム内暦で年が変わるタイミングで、全生存市民の age に経過した暦年数を加算する。エポックが年をまたがない場合は更新されない。

    死亡

    加齢・疾病による死亡率は高齢ほど高く、医療充足度が高いと低くなる。医療は主に寿命に影響する。下水・ごみ処理不足が長く続いて衛生状態が著しく悪化すると、全年齢に超過死亡が生じる。食料の充足度だけを理由に餓死することはない。

    死亡後は空世帯を削除する。配偶者を失った市民は再び婚姻できる。所属世帯が存在しない市民はデータ整合性処理の対象となる。

    出生

    出生数は定住している女性の年齢構成と合計特殊出生率から決まる。子供世代が出産年齢に達すると出生が再び増えるため、世代ごとのベビーブームを表現できる。人口が減った分を自動的に補充する方式ではない。

    出生は対象年齢の女性を含む世帯に配分される。婚姻や子供の数は配分の優先度に影響するが、未婚世帯にも出生する。小さな集落でも丸めによって出生が消え続けないよう端数を持ち越し、性別の偏りも抑える。新生児は0歳・単身・都市内生まれとして世帯に加わる。

    独立

    3人以上の世帯に属する成人の単身市民（MEMBER_SINGLE）が独立の対象となる。各世帯ごとに最年少の単身成人1名が候補となり、確率判定に通過した場合に独立が成立する。

    独立成立時、親世帯と同じ地区に新規世帯を作成して移籍する。親世帯の保有資金は独立前の世帯人数で按分され、その分が新世帯に移転される。

    婚姻

    単身市民（MEMBER_SINGLE）同士の婚姻は、適齢範囲内の異性ペアで行われる。

    各世帯から1エポックに代表者1名のみが婚姻候補となり、男女それぞれの候補からランダムにペアが形成される。資産差による婚姻の成立制限は設けない。

    成立したペアは新規世帯を作成し、両者の citizen_type を MEMBER_MARRIED に更新する。資産移転では、元世帯に他の構成員が残る場合は一定割合のみ移転し、元世帯が1人だけの場合は全額移転する。

    独立・婚姻で作られた世帯は、住宅待ちの間も定住住民として人口に含まれる。待機期限による削除はなく、実住宅が見つかるまで転居補助の台帳で待つ。実際の建物に床占有ゼロで入居することはない。

    15.3 通勤・通学

    市民の通勤・通学に伴う交通負荷を道路ネットワークに反映する。

    通勤

    雇用先を持つ市民（employer_agent_id が設定されている市民）は、居住地区から勤務先地区への経路に交通負荷を加算する。1市民あたり1日1トリップ、エポック日数分の負荷となる。幹線道路（地区間経路）と地区内経路の両方に負荷が反映される。

    移動手段は所属世帯の has_automobile（当エポックに自動車レンタルを調達できた実保有。10_消費活動の自動車保有判定を参照）に応じて決まる。自動車を保有する世帯の市民は自動車経路を使用し、保有しない世帯の市民は徒歩経路を使用する。

    通勤先地区には昼間人口が加算され、世帯の訪問履歴（household_visit_map）も更新される。

    通学

    学校に在籍する市民（school_agent_id が設定されている市民）についても、居住地区から通学先地区への交通負荷を同じ仕組みで計算する。移動手段の決定も通勤と同様に世帯の has_automobile に基づく。

    15.4 教育

    就学年齢に達した市民は学校（TYPE_EDUCATION の経済主体）へ入学し、通学を通じてスキルが成長する。基礎教育・高等教育の区分、入学・卒業・退学の条件、スキル成長の仕組みは17_教育を参照。

    15.5. 健康統計

    健康統計の各スコープは sanitation_distribution と healthcare_distribution に世帯の状態分布を返す。死因別死亡年齢分布では sanitation が衛生悪化による死亡を表す。人口タブの減少グラフは死亡数を表示し、定住住民の転出は表示しない。

    15.6. 静止人口モード

    都市パラメータ STATIC_POPULATION_MODE（既定 false）を有効にすると、人口・世帯構成・市民のスキルが完全に固定される。シナリオ制作者向けのモードで、テンプレート作成モードで切り替える（都市創設後のパラメータ変更はテンプレート作成モードでのみ可能）。通常のプレイで人口を育て、望む規模になった都市を凍結して「都市開発に集中するシナリオ」として保存する使い方を想定している。

    有効な間は以下が止まる。

    • 年齢更新・出生・死亡（衛生悪化による超過死亡、交通事故・建物倒壊による死亡を含む）
    • 婚姻・独立による世帯の生成・統合
    • 移民の応募（受け入れ設定にかかわらず。待機中の応募世帯は撤回される。18_移民）
    • 通学状態の更新とスキル成長（17_教育）、就労によるスキル成長（16_労働市場）

    止まらないもの: 衛生・健康・満足度・施政スコア、社会保障、労働市場、不動産、商品市場、建設、観光。交通事故と建物倒壊は発生するが死者は出ない（倒壊建物の住民は転居する）ため、施政スコアの事故死ペナルティは生じない。統計の出生・死亡は 0 のまま、人口ピラミッドは静止する。
