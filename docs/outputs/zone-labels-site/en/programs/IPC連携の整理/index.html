    IPC連携

    前提

    Unityのグラフィックプログラム(以下、graphic)と、TauriのUIプログラム(以下、ui)は、WindowsのMemoryMappedFile（MMF）2本でIPC連携を行う。

    MMF構成

    MMF名 方向 書き込み 読み取り
    genesis-ipc-ui-to-graphic UI→Graphic Tauri Unity
    genesis-ipc-graphic-to-ui Graphic→UI Unity Tauri

    双方とも CreateOrOpen で共有メモリを開く。どちらが先に起動しても新規作成または既存を開くため、起動順序に依存しない。

    同期オブジェクト

    各方向にMutexとEventWaitHandle（AutoResetEvent）を1つずつ使用する。

    名前 種類 用途
    genesis-ipc-mutex-utg Mutex UI→Graphic バッファの排他アクセス
    genesis-ipc-event-utg AutoResetEvent UI→Graphic の書き込み通知
    genesis-ipc-mutex-gtu Mutex Graphic→UI バッファの排他アクセス
    genesis-ipc-event-gtu AutoResetEvent Graphic→UI の書き込み通知

    MMFレイアウト

    各MMFは1MiB（1048576バイト）。

    Offset  0: WritePos  (int32) — 次の書き込み位置（バッファ内オフセット）
Offset  4: ReadPos   (int32) — 次の読み取り位置（バッファ内オフセット）
Offset  8: Ring buffer data (1048568 bytes)
  各メッセージ: [MessageLength (int32)][UTF-8 JSON bytes]
    • 書き込み側がMutexを取得し、リングバッファにメッセージを書き込み、Mutexを解放してEventをSetする。
    • 読み取り側がEventのWaitOneで待機し、通知されたらMutexを取得してメッセージを読み出す。
    • バッファ末尾にメッセージが収まらない場合、ラップマーカー（length = 0）を書き、メッセージを先頭から書く。読み取り側はラップマーカーを見たら（または末尾にlengthが収まらなければ）ReadPosを0にリセットし、同じ通知の中で先頭のメッセージを続けて読む。
    • WritePos == ReadPos は「空」を意味する。ラップ時に先頭の空きをReadPosちょうどまで埋めると満杯と空が区別できなくなるため、書き込み側はその書き込みを拒否する。
    • 読み取り側はlengthが範囲外なら未読分を捨て（ReadPosをWritePosに合わせ）、以降の通信を続ける。
    • 受信側のプロセスが起動していない間の送信もバッファに溜まり、受信側は起動後にまとめて読む。空きが足りない書き込みは MMF buffer full で失敗する。このため一定周期で送り続けるメッセージは置かない。受信側の再起動後の再同期は、グラフィックが送る system:graphic_ready を起点にするか、グラフィック側が起動時に自分から状態を送る。

    イベント種別

    命名規則

    イベント名は全レイヤー（Unity / Rust / フロントエンド）でコロン区切りで統一する（例: edit_path:select_node）。

    イベントを追加・変更するときの変更箇所

    1つのイベントは Unity・Rust・フロントエンドの3箇所にまたがる。どこかが欠けても実行時エラーにはならず、単に届かない。

    • Envelope: unity/Assets/Scripts/IPC/IpcEnvelope.cs と tauri/src-tauri/src/messages.rs の Envelope は同一構造（version / request_id / timestamp / source / destination / event / payload）に保つ。パースできない通知は両側とも捨てる。
    • UI → graphic: フロントエンドの src/utils/ipc.ts から Tauri コマンド send_window_action を呼ぶ。Rust はこれを ui:action Envelope（payload.action にイベント名、payload.params に引数）として汎用転送するので、Rust 側の変更は要らない。Unity は IpcClient の型付きイベント（OnXxx）で受け、IpcEventHandler / IpcStateCoordinator / IpcViewCoordinator が処理する。
    • graphic → UI: Unity は IpcClient.EmitXxx で event 直下の名前として送る。Rust ipc.rs の受信 match に中継の分岐（全ウィンドウへの emit、常駐のコックピットだけが扱うものは emit_to）を追加しないと、どの WebView にも届かない。フロントエンドは同名の Tauri イベントを listen する。
    • 追加・変更したイベントは、このページの一覧と関連する機能のページに反映する。

    一覧

    イベント種類 コール方向 内容
    world:select_object graphic -> ui オブジェクトを選択する
    world:change_state ui -> graphic グラフィックのモード(通常モード、土地区画作成モード、etc.)を切り替え
    view:change_view ui -> graphic 地形、建物、区画、道路、環境、アラートなどの表示モードを切り替え（{layer, mode, sub_mode, flags}）。flags は色モードと独立した表示トグルのCSV文字列（plan=計画中の表示、public=公共施設ハイライト、speed_limit=道路・線路の制限速度標識。road/building レイヤーのみ使用）。flags が null（またはキー欠落）の場合は現在のフラグを維持し、空文字は全トグルOFFを意味する
    view:query_state ui -> graphic グラフィックプログラムに現在の表示状態を問い合わせる
    view:apply_preset ui -> graphic ウィンドウを開いている間だけ表示を差し替える（{preset}）。プリセットの中身はUnity側が持ち、UIは名前だけを指定する。専用の編集ステート（STATE_*）を持たないウィンドウ専用で、ステートを持つ操作ではUnityがステート別の表示プリセットを自動適用する。元の表示への復帰は STATE_NORMAL への復帰、または view:restore_preset が担う（Unity入力制御 §9.1）。現在のプリセットは transit（公共交通の一覧・新設）、parcel_detail（土地区画詳細）
    view:restore_preset ui -> graphic ウィンドウ単位の表示プリセットを解除し、元の表示状態へ復帰する（{preset}）。詳細パネルのように編集ステートを持たず、かつ他の編集ステートと併存しうるウィンドウが、STATE_NORMAL を送らずに自身の表示プリセットのみを安全に解除するために使う
    view:current_state graphic -> ui view:query_stateへの応答、およびステート変更時の表示状態通知。各レイヤーは {mode, sub_mode, flags}（flags はONのトグルのCSV。無ければ空文字）
    view:set_object_filter ui -> graphic 建物・道路をオブジェクト単位で非表示にする集合を送る（{hidden_building_ids, hidden_path_ids}）。差分ではなく毎回「今隠しているものの全集合」を送る。レイヤー単位のview:change_viewとは直交し、こちらが立っているオブジェクトは色モード・計画中表示に関わらず消える（クリックも拾わない）。状態はUnityのセッション内だけに存在し、バックエンドにもセーブにも残らない。詳細は建設プロジェクト管理
    view:query_object_filter ui -> graphic オブジェクト単位の表示フィルタの現在値を問い合わせる（パネルを開いたときに送る）
    view:object_filter_state graphic -> ui view:query_object_filterへの応答、およびフィルタ適用後の通知（{hidden_building_ids, hidden_path_ids}）。表示状態の正はUnity側にあり、複数のパネルがこれを受けて表示を揃える
    view:set_grid ui -> graphic グリッドの表示有無や設定を切り替え。Unity側はグリッド表示とグリッド吸着を連動させる（表示ON=吸着ON）
    view:grid_toggled graphic -> ui 3Dビューのラジアルメニューでグリッド表示がトグルされた（{ visible }）。UI側はパス建設パネルのグリッド設定UIの表示状態を追従させる
    camera:query_state ui -> graphic 3Dカメラの現在位置と視線方位を問い合わせる。2D都市マップがカメラマーカーを描くために、開いたときと再読み込みのときに送る
    camera:capture_thumbnail ui -> graphic セーブ・シナリオ保存の直前に、3Dビューの撮影を頼む({ id })。グラフィックはメインカメラを16:9の小さな画像(480×270)へ直接描き(画面に重ねたUIは写らない)、PNGを PUT /api/v1/sessions/thumbnail でコアへ預ける(次の保存に入る画像)。UIはTauriコマンド request_thumbnail_capture で送り、グラフィックが接続していなければ送らずに撮影なしで保存する
    camera:thumbnail_captured graphic -> ui camera:capture_thumbnailへの応答({ id, success })。撮れなくても送れなくても必ず返す。UIはこの応答か時間切れ(5秒)まで保存を待つ
    camera:state graphic -> ui camera:query_stateへの応答。3Dカメラの現在位置と視線方位（{ position:[x,y,z], yaw }）。yaw は北（ワールド+Z）を0とする時計回りの度。カメラの動きへの追従配信は行わない（問い合わせ1回につき1回だけ送る）
    edit_path:select_node graphic -> ui パス敷設モードにおいて、敷設済みノードを選択した（node_id, height=相対標高, embankment_height を含む。node_id=-1 は次回配置ノードの値）。UIパネルの標高・盛土ステッパーの表示と編集対象ノードを同期する。Unityのキー操作や吸着で値が変わったときも送られる
    edit_path:change_node ui -> graphic パス敷設モードにおいて、パネルの標高ステッパーからノードの相対標高を変更した（node_index, height。node_index=-1 は次回配置値）。曲線/直線・吸着はラジアルメニューが真実源だが、標高・盛土は既存ノードを選んで数値で微調整する用途のためパネルにもステッパーを残し、Unityキー操作と双方向同期する
    edit_path:change_embankment ui -> graphic パス敷設モードにおいて、パネルの盛土ステッパーから盛土オフセット(-5〜+5m)を変更した（node_index, embankment_height。node_index=-1 は次回配置値）
    edit_path:update_shape graphic -> ui パス敷設モードにおいて、敷設中パスの形状が変更された。selected_points（全アンカー [x, 相対高さ, z]）、start_control / end_control（端点のベジエ制御点）、waypoint_controls（中間アンカーごとの {control_in, control_out}。未設定は null）、embankment_heights、is_curved（曲線モードの現在値。真実源はUnity側のラジアルメニューで、点列が空でも常に送られる）、follow_terrain（地形追従の個別設定。-1＝未設定／0＝非追従／1＝追従。真実源はUnity側で常に送られる）を含む。UIは確定送信時にこれらの制御点を start_control / end_control / waypoints として、is_curved を curved として、follow_terrain（-1 以外のときのみ）をそのままバックエンドへ渡し、調整した形状を永続化する。2Dパス形状編集パネル向けの追加フィールド: phase（placing/editing/inactive）、selected_index（3D側で選択中のノード添字。-1=未選択）、lateral_offsets（複線の横オフセット列。単線と、1本で複線を持つ線路（線路・モノレールで lanes≥2）は空）、alignment（検証済み線形、取得待ちではUnityのローカル推定。radius_limit/grade_limit/min_curve_radius/max_grade、約5m間隔の samples=[x, z, 曲線半径(直線はnull), 勾配%, 始点からの距離m, 路面の絶対標高, 地盤の絶対標高]、原因別違反区間の最悪値 labels、アンカーと同順の nodes=[始点からの距離m, アンカー直下の地盤標高]。線形評価の対象外の種別では省略）、height_editable（バリアントが標高編集可能か。縦断面ストリップの表示条件）、min_height（相対高さの下限m）。全WebViewへブロードキャストされるため、敷設パネルと2Dパネルの両方が同じイベントを受ける
    edit_path:change_platform_side ui -> graphic 駅パス敷設モードにおいて、ホーム設置側（platform_side=外側/内側/両側。PLATFORM_SIDE_*）を変更する。Unity側は敷設中プレビューメッシュのプラットフォーム張り出し側を即座に切り替える。駅バリアント（platform_width>0）以外では無視される。初期値は world:change_state（STATE_EDIT_PATH）の platform_side で渡し、以後の切り替えをこのイベントで逐次反映する。UIはホーム設置側を選ぶ単線の駅バリアントの敷設中だけ送る。1本で上下線を持つ複線一体の線路（lanes≥2）の駅は両外側にホームが付くので送らず、STATE_EDIT_PATH の platform_side はバックエンドの既定と同じ外側にする
    edit_path:set_follow_terrain ui -> graphic パス敷設モードにおいて、地形追従の個別設定（value=-1未設定/0非追従/1追従）を変更する。Unity側は敷設中プレビューの地形追従・トンネル可視化を即座に切り替え、確定送信用に edit_path:update_shape の follow_terrain としてUIへ返す。height_editable のバリアント以外では無視される
    edit_path:change_lateral_offsets ui -> graphic パス敷設モードにおいて、複合パス（軌道複線＝単線パス群の平行敷設）の各線の横オフセット（lateral_offsets=float配列。m。敷設方向右が正）と進行方向（travel_directions=int配列。DIR_*。lateral_offsets とindex対応）を変更する。Unity側は敷設中プレビューメッシュを各オフセット位置の平行パス群として即座に描き直す（空配列は単一パス＝中心線1本のプレビューに戻す）。進行方向は駅バリアントのホーム設置側の解決と進行方向矢印の表示に使われる。UIパネルで線路数・進行方向を変えたときに送られ、配置中のノード列は維持される。初期値は world:change_state（STATE_EDIT_PATH）の lateral_offsets / travel_directions で渡し、以後の変更をこのイベントで逐次反映する。確定時の平行展開・一括作成はUI側が行うため、このイベントはプレビュー表示専用。1本で複線を持つ線路バリアント（線路・モノレールで lanes≥2。LRT専用軌道431や、鉄道・モノレールを1本で敷く複線）と人員搬送（PATH_CONVEYOR）は平行展開の対象外で、UIは空の lateral_offsets / travel_directions を送り、Unityは単一パスでプレビューする（lanes 本の軌道はそのパスの中に描かれる）。確定時も1本のパスを travel_direction=DIR_BOTH で作成する
    edit_path:shape_command ui -> graphic 2Dパス形状編集パネル（path_shape_editor）からのノード・制御点操作。op=select_node（index）/ move_node（index,x,z）/ move_control（index,which=in/out,x,z）/ insert_node（edge_index,x,z）/ remove_node（index）。XZだけを動かし、地面相対の高さ・制御点の絶対標高はUnity側が維持する（3DのXZドラッグと同じ規則）。吸着は適用しない。ドラッグ中は送らずドラッグ終了時に1回だけ送る。Unityは Editing フェーズ以外・3Dでドラッグ中は無視し、適用後は edit_path:update_shape（全状態）と、ノード操作なら edit_path:select_node を返す

    world:set_road_focus ui -> graphic 道路詳細パネル（road_detail）が開いている道路の区間を、3Dビューに道路色の帯で強調する（{road_id, color, path_ids}）。帯は区間の中心線に沿って最前面に、画面上で一定の幅で描く。送るたびに全置換する。干渉の警告用の world:highlight_objects とは別の仕組み。詳細は道路の詳細と道路名
    world:clear_road_focus ui -> graphic 道路の強調を消す（{road_id?}）。road_id があれば強調中の道路と同じときだけ消し（道路詳細は道路ごとに同時に開けるため、別のパネルの強調を消さない）、無ければ無条件に消す。道路詳細のウィンドウが閉じられたときは Rust（window.rs）が閉じた道路の road_id を載せて送る
    world:refresh_roads ui -> graphic 道路（名前付き道路）の作成・改名・所属変更・削除のあとに送り、Unity に道路一覧（GET /api/v1/roads/）を取り直させる（{}）。一覧の version が同じなら道路名ラベルは作り直さない
    edit_road:set_members ui -> graphic 道路の区間編集モード（STATE_EDIT_ROAD_MEMBERS）で、所属区間と追加候補の全集合を送る（{road_id, path_ids, preview_path_ids}）。差分ではなく毎回全集合。Unity は所属区間を道路色、候補を半透明の道路色の帯で示す。モード中でない・別の道路宛ての通知は無視する
    edit_road:cancel ui -> graphic 道路の区間編集モードを終える（{road_id}）。Unity はその道路の区間編集モード中のときだけ終了して通常モードへ戻し、モード外・別の道路の編集中・road_id の無い通知は無視する（STATE_NORMAL と違い、道路の敷設など他のモードを巻き込まない）。道路詳細パネルの「完了」と、そのウィンドウが閉じられたときの Rust（window.rs）が送る
    edit_road:toggle_path graphic -> ui 道路の区間編集モードで、街路・高速道路の区間がクリックされた（{path_id, path_name, path_type, shift}。shift は Shift キーの押下で、その区間から直進方向へたどった区間をまとめて追加する操作を表す）。所属の付け外しは道路詳細パネルが道路APIで行い、結果を edit_road:set_members で送り返す（edit_path:select_merge_target と同じ責務分担）。Rust は全ウィンドウへ中継する
    edit_road:ended graphic -> ui 道路の区間編集モードが終わった（{road_id, session_id?}）。完了・Esc・他のステートへの遷移・閉じたパネルの edit_road:cancel・セッションのリセットなど理由を問わず、モードを抜けるたびに1回だけ送る。道路詳細パネルは自分の道路なら何も送り返さずに編集中の表示を落とす。session_id は開始時の STATE_EDIT_ROAD_MEMBERS の session_id を Unity が型を変えずにそのまま返したもので、開始時に無かった（または整数でも文字列でもなかった）ときはキーごと省く。パネルは正の整数の session_id が含まれていれば開始時の値と一致するときだけ受け入れ（遅れて届いた前回の終了で新しい編集を落とさないため）、含まれていなければ道路IDだけで判断する。Rust は全ウィンドウへ中継する
    world:roads_changed graphic -> ui UI を通さずに道路（名前付き道路）の区間が消えたことを知らせる（{}）。送り手はブルドーザでのパスの削除で、削除したパスが道路の区間だったときだけ、削除の成功後、差分リロードのまとめ待ちが明けた時点で1回送る（続けて削除しても1通にまとまる。周期送信はしない）。区間が0本になった道路はバックエンドが削除するので、道路詳細パネルはこれを受けて取り直し、削除済みを表示できる。Rust は Tauri のグローバルイベント roads:changed（UI の道路の変更通知と同じもの。ペイロードはそのまま）として全ウィンドウへ流す。Unity は差分リロードで自分の道路一覧を取り直すので、world:refresh_roads は送り返さない

    確定送信の責務分担

    建物の爆破

    building:exploded（UI → graphic、params: {agent_id: 整数}）は、AgentOperationPanel が確認ダイアログを経て POST /api/v1/agents/{id}/explode に成功した後だけ送る。爆破の確定はHTTP側で完了しており、IPCは描画更新の通知である。

    転送は既存の send_window_action → send_ui_action → ui:action Envelope（payload.action / payload.params）を使用する。Rustの専用コマンドや別のEnvelopeは設けない。Unityの IpcClient.OnBuildingExploded → IpcEventHandler → CellDataLoader.FetchBuilding(id, playExplosion: true) → BuildingManager.FetchBuilding と、既存の個別取得・共通描画スケジューラを通る。

    Unityは GET /buildings/{id} の最新状態が STATUS_COLLAPSED であることを確認し、既存の建物メッシュ生成経路で瓦礫へ切り替える。同じ処理で VisualEffectManager.PlayExplosion を一度だけ呼ぶ。再取得中の重複通知と同じversionの再通知は演出を重ねず、セッション切替中に完了した取得結果も破棄する。爆破前の一括取得が後着した場合、その古いversionで表示を戻さない。

    この操作では session:reload を併送しない。全体リロードが行う海岸線・路線などの取得は不要で、対象1棟の更新と演出だけを同じハンドラで開始する。通常のエポック更新・保存データのロード・解体による状態変化では爆発音を鳴らさない。エフェクトの寿命と音源は 火災エフェクトの描画 を参照。

    建設・編集

    建設・編集の「確定」をバックエンドへ送信する責務は、確定操作を所有する側が持つ。

    • パネル確定型（建物建設・パス敷設・土地区画の作成/形状編集・資源エリア・造成・公共交通・プロップ配置）: UI(Tauri)のパネルに確定ボタンがあるため、UIが直接バックエンドへPOST/PATCHする。成功後に edit_*:finish 系イベント（または session:reload）を送り、Unity側の編集状態をリセットしてデータをリロードさせる。Unityは形状の組み立てと edit_*:update_* 系イベントによるUIへの逐次通知のみを担う。
    • 3Dジェスチャ完結型（地区の塗り分け＝クリック/ドラッグの即時割当、接続端子ノードのドラッグ移動）: パネルの確定ボタンを持たず3D上の操作で完結するため、Unityが直接バックエンドへ送信する。

    確定後の後始末（編集状態のリセット・消えたオブジェクトの破棄・通常モードへの復帰・データの再取得）は edit_*:finish 系の1イベントにまとめ、Unity がその中で順序を持って実行する。session:reload と world:change_state を別々に送ってはいけない。差分リロードは複数フレームにまたがる処理で、後続の状態遷移が割り込むと再生成・削除が中途半端に終わる。確定しないキャンセルは STATE_NORMAL の送信で足りる。

    edit_*:finish 系を送ったパネル自身は、続けて STATE_NORMAL を送らない。ただし確定後にウィンドウを閉じるパネル（造成など）では、閉じる処理が×ボタンと同じ Rust の経路（window.rs の close_window_by_label）を通るので、そのウィンドウ種別が EDIT_MODE_WINDOW_TYPES に載っていれば Rust が STATE_NORMAL を送る。Unity は finish の中で既に通常ステートへ戻しており、STATE_NORMAL の処理は入力と表示の適用し直しだけで差分リロードを取り消さない（取り消すのは新しい再取得・カメラのセル移動・セッションの切り替え）。この STATE_NORMAL は冗長だが、再取得を妨げない。

    • 吸着しない。 頂点の配置・移動・挿入とも道路・ノード・グリッドへ吸着しない。道路の中心線へ吸い付くと範囲がパスに掛かり、発注で必ず拒否されるため（頂点は道路の縁の外に置く）。
    • Esc で抜けない。 Esc で Unity の入力だけが通常に戻ると（ステート遷移もUIへの通知も伴わない）、ウィンドウが開いたまま編集用の表示プリセットも残るため。抜けるのはウィンドウを閉じたとき（Rust が STATE_NORMAL を送る）と、確定後の edit_grading:finish だけ。

    表示はステート別の表示プリセット（区画の境界線・地区・等高線・計画中の道路と建物を表示、プロップを非表示。Unity入力制御 §9.1）。埋立地の岸壁の天端と面は地形としてクリックでき、その上にも頂点を置ける。確定の送信（POST /api/v1/grading）はUI側が直接行い、成功後に造成工事の主体の詳細ウィンドウ（agent_detail）を開いてから edit_grading:finish を送り、造成ウィンドウを閉じる（閉じたときの STATE_NORMAL の扱いは建設・編集）。発注が拒否されたら見積もりを取り直す。パネルのキャンセルはウィンドウを閉じず、STATE_EDIT_GRADING を送り直して作図を初めからやり直させる。

    STATE_EDIT_TRANSIT は公共交通の路線設置モードで、公共交通の新設パネル（transit_creation）で路線種別を選ぶと遷移する。路線詳細の「経路を編集」も同じパネルを経路編集モード（ウィンドウを開くときの params.extra.editLineId）で開いて遷移する。world:change_state の params は次のとおり。

    • path_variant … 路線種別の区間パスのバリアント（＝transit_master の transit_path_id）
    • stop_path_variants … 停留所を設置できる下地パスのバリアント一覧
    • route_path_variants … 車両が走行できる下地パスのバリアント一覧。経由点は stop_path_variants とこれの和に属するパスの上に置ける
    • points … 始めの巡回点（edit_transit:update_points と同じ形）。新設では空、経路編集では路線の現在の巡回点（路線詳細 API の route_points）
    • line_agent_id … 経路を編集する路線（新設は null）。Unity はこの路線の路線色帯を編集中だけ隠し、プレビューと重ならないようにする

    路線は巡回点を順にたどり、最後の点から先頭の点へ戻る閉じたループである（公共交通機関 6.2）。Unity の操作は2フェーズに分かれる。配置フェーズでは左クリックで停留所を末尾に追加し、既存の停留所をクリックすると同じ停留所を再び訪れる停留所として追加し、先頭の停留所をクリックする（停留所2つ以上）か右クリックで編集フェーズへ移る。編集フェーズでは停留所・経由点のドラッグで移動、区間（最後の点から先頭の点への区間を含む）のクリックで停留所の挿入、区間のドラッグで経由点の挿入、停留所・経由点の右クリックで削除ができる。停留所は stop_path_variants、経由点は走行網に属する稼働中パスの上にのみ吸着でき、外れた場所には置けない（路線の作成・経路の更新時にバックエンドが検証する設置制約（公共交通機関 6.4）と一致）。停留所・経由点を置くと効果音を鳴らす（音量はUIの効果音設定 ambience:volume に従う）。

    巡回点が変わるたびに Unity は edit_transit:update_points でUIへ送り、あわせて POST /api/v1/transit/lines/route-preview（都市を変えない経路の試算。公共交通機関 6.8）を少し待ってから呼んで、返った区間ごとの走行データを路線色帯と同じ見た目の帯として実際の道路・線路に沿って描く。下地でつながらない区間は、その区間の巡回点を結ぶ赤い破線で示す。確定時の POST /api/v1/transit/lines（新設。path_variant と points を含む）と PUT /api/v1/transit/lines/{id}/route（経路編集。points を含む）はUI側が直接行う。成功後に edit_transit:finish を送信してUnity側の編集状態をリセットし、新しい公共交通パスをオーバーレイに反映させる。LRT路線の停留所のホームは配置中には描かず、作成後に路線一覧（GET /api/v1/transit/lines）の stop_points から下地パスの再生成で現れる（道路メッシュの生成）。

    設置済みの公共交通パス（PATH_TRANSPORT）は、view:change_view の transit レイヤーで路線種別ごとに表示ON/OFFできる（sub_mode に表示する transit_path_id のCSV文字列を渡す）。Unity は種別色の帯（オーバーレイ）として下地道路の上に描画する。

    STATE_EDIT_PROP は地形プロップ（森・岩・茂みなどの装飾）の配置モードで、プロップ配置パネル（prop_placement）で種別を選ぶと遷移する。world:change_state の params に prop_type・placement_mode（"instance" | "scatter"）・初期設定 rotation/scale（個別）・density/seed（範囲）を含める。配置には2モードある。個別モードは左クリックで1個ずつ配置（カーソル追従は半透明ゴースト、確定すると不透明の実モデル、右クリックで直近を取り消し）し、配置列を edit_prop:update_instances でUIへ送出する。範囲モードは左クリックで散布範囲のポリゴン頂点を置き（3頂点以上でseedベースの散布ゴーストを簡易プレビュー、右クリックで直近頂点を取り消し）、ポリゴンを edit_prop:update_shape でUIへ送出する。回転/スケール/密度/seed の変更は edit_prop:change_settings でプレビューに即反映する。個別モードでは3D側でも中ボタンドラッグで回転、PageUp/PageDown で高さを変えられ、結果は edit_prop:placement_settings でパネルへ書き戻す。確定送信（個別=POST /api/v1/props/instances、範囲=POST /api/v1/props/scatters）はUI側が直接行い、成功後に edit_prop:finish を送信してUnity側の配置状態をリセットする。既存プロップの削除は配置パネルではなく STATE_REMOVE_OBJECTS（ブルドーザ）で行い、範囲配置は remove_object:request_confirm / remove_object:confirm_result の確認を挟む。プロップはゼロコストの装飾のため play_mode == PLAY_MODE_SCEARIO ゲートはない。詳細な仕様は genesis-docs/docs/geometries/M_地形プロップ.md を参照。

    STATE_REMOVE_OBJECTS はブルドーザ（オブジェクト削除）モードで、コックピットのブルドーザボタンで遷移する（ウィンドウは開かず、再度押すと STATE_NORMAL へ戻す。遷移の発信元ラベルは bulldozer）。world:change_state の params は省略可能な instant_remove（bool、既定 false）だけで、UIがセッションの play_mode == PLAY_MODE_SCEARIO（神モード。シナリオ制作とチュートリアルを含む）のときに true を付ける。Unity は神モードかを知らず、この指定に従って削除対象を決める。通常は空き地区画・計画中の建物と道路・地形プロップだけが対象で、instant_remove=true では稼働中の建物と道路も対象になる（市政府・中央銀行・代理主体・国境検問所と、公共交通の区間パスは除く）。削除は Unity が DELETE /api/v1/agents/{id}・/api/v1/paths/{id}・/api/v1/parcels/{id} を直接叩き、バックエンドが神モードのときだけ稼働中の建物・道路を受け付ける。建物はテナントの経済主体と世帯の市民ごと消えて区画は空き地に戻り、道路は端点が孤立したノードも消える（地形は戻さない）。確認ダイアログも取り消しも無い。例外として範囲配置プロップだけは、このモードでも remove_object:request_confirm / remove_object:confirm_result の確認を挟んでから範囲ごと消す。詳細は Unity入力制御 の「建物・道路・区画の削除(ブルドーザ)」を参照。

    STATE_MERGE_PATH / STATE_SPLIT_PATH は既存パスの結合・分割の「対象選択モード」で、パス詳細パネル（path_detail）の操作パネルにある結合／分割ボタンで遷移する。world:change_state の params に操作対象の path_id（結合では結合後に残る側＝survivor、分割では分割元）を含める。どちらも稼働中（STATUS_ACTIVE）のパスにのみ表示される。

    Unity は PathTopologyEditManager が対象選択を担う。結合では対象パスを青、結合できる候補パスを黄で着色し（候補＝対象と端点ノードを共有し、そのノードに他のパスが繋がっておらず、同一バリアントの稼働中パス。曲線の折れ・通行方向の矛盾など残りの条件はバックエンドが判定する）、入力プリセット PATH_MERGE（PATH=MODE_PATH_MERGE、他=MODE_NONE）で候補のクリックだけを受け付ける。分割では入力プリセット PATH_SPLIT（PATH／TERRAIN=MODE_PATH_SPLIT、他=MODE_NONE）でカーソルのワールド座標を対象パスの中心線へ射影し、射影点にマーカー（パスを横切る棒＋円）を描く。パス脇の地形をクリックしても垂線の足が分割点になる（バックエンドの射影と同じ考え方）。このモードでは共通吸着（ノード吸着など）を適用しない——端点ノードへ吸着すると常に「端点に近すぎる」分割になってバックエンドに拒否されるため。

    選択結果は edit_path:select_merge_target / edit_path:select_split_point でUIへ返り、UIは同じエンドポイントの dry_run=true で結合後・分割後の長さを取得してパネルに表示する。プレイヤーが確定するとUIが dry_run なしで再送し、成功後に edit_path:finish_topology_edit を1発だけ送ってUnity側の後始末（着色・マーカーのクリア、消えたパスの破棄、通常モード復帰、再描画）をまとめて行わせる。キャンセル時のみ STATE_NORMAL を送る。長さを確認して確定するパネルを操作し続ける必要があるため、STATE_EDIT_CONNECTOR と同じくこのステートでは Unity ウィンドウを最前面化しない。

    STATE_EDIT_CONNECTOR は施設の接続端子ノード（インフラ接続点 infra_node_id / 走行網接続点 depot_node_id。26_インフラ網の接続端子ノード参照）をドラッグで移動する編集モードで、経済主体詳細パネル（agent_detail）が接続端子ノードを持つ施設を表示すると、edit_connector:show に続けて送って遷移する（トグルボタンは無く、表示している間は常に編集できる）。world:change_state の params に agent_id / infra_node_id / depot_node_id を含める。Unity は ConnectorEditManager が対象ノードを強制表示・逆四角錐マーカーで強調し、入力プリセット CONNECTOR_EDIT（TERRAIN=MODE_EDIT_CONNECTOR、他=MODE_NONE）でマーカーを地形ドラッグとして掴んで移動する（マーカーはノード実体の上空に浮くため、ノードのコライダーへのレイキャストは使わない。Unity入力制御 §5.3）。ドラッグ中のXZは施設が立地する土地区画の内側へクランプし、ドラッグ確定時は NodeInputHandler が PATCH /api/v1/nodes/{node_id}（position）を送る。ノード位置の変更はパスが1本も接続されていない場合のみ許可され、接続済みノードの移動はバックエンドが拒否し、Unity は元位置に自動で戻す（26_インフラ網 §26.3 の端子位置移動制限）。agent_detail パネルを前面に残すため、このステートでは他の編集ステートと異なり Unity ウィンドウを最前面化しない。

    agent_detail は編集ウィンドウ（EDIT_MODE_WINDOW_TYPES）と排他ではないので、接続点編集中に建物建設などを開くと、そちらのステートへ直接遷移する。このとき Unity は端子のドラッグ受付を終え、マーカーを読み取り専用ハイライトとして残す（STATE_NORMAL への復帰でも同じ）。パネルが別エージェントへ遷移したときと閉じられたときは edit_connector:hide だけを送り、STATE_NORMAL は送らない。Unity は接続点編集モード中のときだけ通常モードへ戻すので、後から開いた編集ウィンドウのステートを打ち切らない。

    起動・再接続

    プロセスの起動順序と接続先の受け渡しはコンポーネント連携に従う。UnityとTauriはIPCの版を照合し、再接続時は system:graphic_ready を起点にセッション・表示・編集状態を同期する。版照合を通るまで編集イベントを扱わない。

    天気の表示と選択

    ambience:volume {volume}はTauri→Unityの音量通知（master×sfx、0〜1）。Cockpitが設定変更時とグラフィックの起動通知（system:graphic_ready）の受信時に送り、CameraAmbience（環境音）・ConstructionAmbience（工事音）・VehicleAmbience（走行音）・VisualEffectManager（完成・解体音）が所有するAudioSourceへ適用する。高度と天気の音響制御はUnity内で完結する。

    天気と時刻の正はUnityにあり、バックエンドへの書き込みや経済パラメータは追加しない。都市の気候区分だけはUnityが GET /api/v1/city の climate から読む。Cockpitは購読後に問い合わせ、応答した天気に合わせて表示を更新する。

    イベント 方向 ペイロード・意味
    weather:query Tauri → Unity 現在の天気を問い合わせる
    weather:set Tauri → Unity {id: string または null}。有効なIDは選択して固定、nullは固定を解除。未知のIDは無視
    weather:state Unity → Cockpit {id, locked, rain, snow, presets:[{id, weight, rain, snow}]}。rainは0=なし、1=霧雨、2=雨、3=大雨。snowは0=なし、1=小雪、2=雪、3=吹雪。weightは今の気候・季節での出現割合(%)
    epoch:prepare Tauri → Unity {id: string}。エポック演出の開始。1.5秒の日没と0.5秒の画面フェードを開始し、結果画面を閉じるまで黒幕を保持する
    epoch:darkened Unity → Tauri {id: string}。黒幕描画後の通知。Rustは現在の演出IDのみUIへ中継し、UIは処理の完了状況に応じて結果またはTipsを表示する
    epoch:executing Tauri → Unity {executing: bool}。falseは結果画面のクローズ・結果なし・失敗による演出終了。都市を読み直し、0.5秒のフェードインと1.5秒の日の出へ進む。trueはIDなしの日没開始にも対応する

    天気の送信はutils/ipc.tsのqueryWeather / setWeatherからsend_window_actionへ、weather:stateはRust ipc.rsでCockpitだけに配信する。Unityは天気の切り替わり・固定変更・出現割合の変化のたびに状態を送る。候補と出現割合はUnityが持ち、Tauriに抽選処理を複製しない。テンプレートモードOFF時はUIから固定解除を送る。

    エポック演出はutils/epochPresentation.tsからbegin_epoch_presentationを呼び、RustがIDを保持して開始を送る。HTTP実行は日没と並行し、utils/epochFlow.tsで暗転完了まで応答の表示を保留する。set_epoch_tips_visibleは初期ロードと独立したTipsを開閉する。結果画面のparams.extra.epochPresentationIdを共通クローズ処理が読み、finish_epoch_presentationで演出を終了する。Tauri内のepoch:executingはHUDの無効化に使い、開始から結果画面のクローズまでtrueを維持する。詳細は天気と環境光を参照。

    /paths/validate の alignments は敷設する全線の設計後の線形指標で、費用カードと確定可否の表示に優先する。/paths/earthwork-preview の path_profiles は各線の [x,絶対標高,z] 配列で、Unityは形状確定後の3Dモデルに使用する。道路・地上線路は造成後、高架は設計縦断を表示する。操作中のHUD・2D線形はローカルの近似値である。

    造成の切土・盛土を示すオレンジ／青の半透明ボリュームと体積凡例は表示しない。RoadEarthworkPreviewは造成後のpath_profiles取得だけを担い、道路・線路モデル自体の標高へ反映する。

    経路提案

    経路提案はUnityの編集世代付き絶対座標をTauriから読み取り専用HTTP APIへ送り、成功した候補を既存shape_commandで一括反映する。イベント、固定条件、取消しの詳細は経路提案を参照。

    ノード間距離の上限警告

    edit_path:update_shape.max_span_violations は [{segment_index, distance, limit}]。添字は区間の始点ノードの0始まり、距離と上限はm単位。Unityの赤線と同じ max_span 判定を使い、曲線長や高低差ではなく隣接アンカーのXZ直線距離を比較する。上限と等しい距離は許可する。違反解消時・制限なし・点不足では空配列を送る。

    違反があるとUnityの can_confirm はfalse。Tauriの形状編集パネルは対象区間の中央に、距離・上限を示す引出線付き吹き出しを描く。カーブ・勾配と同じ描画処理を使い、ドラッグ中は再評価前の警告を非表示にする。パス建設パネルの確定欄は「形状にエラーがあります」の簡潔な表示とし、パネル本文と同じ1remの文字サイズを使う。共通の usePathConstruction は違反を受けた時点で確定を禁止し、送信直前のガードにも反映する。

    線形警告と検証結果の共有

    パス建設パネルが確定送信と同じ全線を /paths/validate へ渡し、返された線形指標と描画用の違反区間をUnityへ共有する。形状編集パネルは独自に検証を問い合わせず、Unityから再配信された同じ結果を表示する。単線・複線とも、建設パネルと2Dの要約は全線の最悪値、3Dと2Dの吹き出しは各違反区間の最悪値となる。

    edit_path:update_shape の revision は形状・設定変更で更新される。建設パネルは検証時の世代を付けた edit_path:shape_command（op=apply_alignment、alignment_json に alignments のJSON）を送り、Unityは世代が一致する編集状態でだけ採用する。nullは検証待ちへの切替を表す。応答待ちの操作・取消し・別セッションへの切替後に、以前の検証を採用しない。

    再配信の alignment は authoritative=true、バックエンドと同じ違反フラグ curve_violated / grade_violated、全線の警告折れ線群 warnings を含む。各点は [x, 絶対標高, z]。samples は先頭線の縦断表示用で、警告位置と区間の最悪値は間引き前の評価から作る。上限付近の数値誤差の扱いもサーバーに従う。

    操作中・結果待ちはUnityの暫定推定を使う。造成後縦断の非同期受信でも3Dと2Dを再通知するが、同じ世代の全線検証がすでにあればその結果を維持する。選択や警告だけの通知では建設パネルの検証を再起動せず、往復ループを防ぐ。

    駅舎通路のpassage_mode（elevated/ground/underground）は STATE_EDIT_PATH の params と edit_path:change_passage_mode で渡す。プレビューと保存で同じ方式を使う。

    ドライブの開始

    drive:openはCockpitのブルドーザー右隣からUnityへ送る。paramsはsrc/i18n/<言語>/drive.jsonのdrive辞書（キー→表示文言）。IpcClientはDriveMode.Ensure().Openへ渡す。Unity側が車種/路線・開始位置・乗車HUDを保持し、表示中の再送は終了として扱う。転送には既存Rustのsend_window_actionを使い、新しいEnvelopeやバックエンドAPIは持たない。仕様は車両の走行描画を参照。

    初期ロードの表示契約

    UI→Unityは既存の ui:action Envelopeの payload.action / payload.params を使う。game:loading は黒画面と入力抑制を開始し、表示パネルで選べる表示状態を既定へ戻して view:current_state で通知する(Unity入力制御 9.1)。game:start のparamsは {loading_id: 整数} で、描画準備を開始するが黒画面は維持する。Unity→UIの game:loaded はpayload直下の {loading_id: 整数} を返す。初期描画完了後、表示解禁まで1秒間隔で再送し、Rustは現在の要求世代だけを受理する。UI→Unityの game:reveal は同じloading_idをparamsに載せ、game:loaded を通知済みの世代だけを表示する。受信した瞬間の準備状態は再判定しない（Tipsは既に閉じているため、ここで捨てると黒画面から戻れなくなる）。

    system:graphic_ready はプロセスの起動完了であり、都市の描画完了ではない。遅延起動・再接続ではRustが開始要求を再送する。ゲーム中の再接続でもTipsを使い、初期設定は再表示しない。

    開発時のUnityなし起動: 通常の npm run tauri dev（Rustの cfg(all(debug_assertions, dev))）では、Unityが接続中でない場合に限り、バックエンドの開始要求成功とセッション確認後に描画待ちを省略し、Tipsを開始ボタンへ切り替える。接続中かどうかは system:graphic_ready（接続）と system:graphic_stopped（正常終了・EditorのPlay停止）で追跡し、「一度でも接続したか」では判定しない（それだとPlayを止めた後の再ロードで永遠に待つ）。接続中は描画完了を待ち、待機中にUnityが停止した場合はその時点で開始ボタンへ切り替える。待機中にUnityが接続した場合は開始要求を再送して描画待ちに戻る。tauri build（--debug を含む）およびリリースビルドには省略処理を含めない。環境変数やバックエンドのNuitka／uvicorn判定は使用しない。

    道路・線路の制限速度標識

    表示設定の道路タブの「制限速度標識を表示」は独立したON/OFFボタンで、view:change_viewのlayer=road、flagsのspeed_limitを使う。既定はOFF。通常表示・交通量などの色分けと併用でき、状態照会と編集モード終了時の復元は他の表示トグルと同じ経路を使う。

    UnityのPathSpeedLimitOverlayは、一覧APIのPathSummary.max_speedをkm/hのまま表示する。対象は街路・高速道路・鉄道・モノレールで、公共交通の路線区間は表示しない。都市の規制から適用された値もパス個別に指定された値も、バックエンドが保持する同じフィールドを読む。線形制約後のbase_speedや混雑込みの走行速度は使わず、欠損した値を推定しない。

    標識は道路・線路の中心を指す、赤い円・白地・青い数字の画面アイコン。PathManager.TryGetPathLabelPositionがcenter_pointを実際の描画中心線へ射影し、高架・勾配の標高を保持する。カメラ正面を向き、上下アニメーションは付けない。アラートと同じCanvas生成・多言語フォントを使い、基準サイズ100pxを100m基準で0.3〜1.5倍に縮尺する。マウス入力は遮らない。

    標識は接写・通常モデルが表示される範囲だけで表示する。長い道路は中心区間の描画LODを参照し、遠景・Hidden・差し替え生成待ちでは隠す（LOD処理）。道路の非表示・個別非表示・計画中表示OFF・アンロードにも追従し、都市切り替えで消去する。近傍候補は既存セル逆引きから0.5秒ごとに更新する。表示中のパスの速度変更も通常のデータ再取得後に反映する。

    意匠はSpeedLimitSignStyleとして、数値・位置・表示状態から分離している。現在は全言語で日本式を用い、言語別の意匠はStyle実装とSetSignStyleで差し替えられる。写真・画像アセットは使用しない。実装検証はunity/Tests/SpeedLimitSigns/run.ps1、APIの値の検証はコア側のスキーマ直列化テストで行う。

    道路の区間編集モード

    STATE_EDIT_ROAD_MEMBERS は道路（名前付き道路。道路網）の区間を3Dビューのクリックで付け外しするモードで、道路詳細パネル（road_detail）の設定タブの「区間を編集」で遷移する。world:change_state の params は {state, road_id, color, path_ids, session_id}（path_ids は開始時点の所属区間、session_id は開始のたびにパネルが採番する番号で、edit_road:ended の照合に使う）。

    Unity は RoadMemberEditManager が担う。入力プリセット ROAD_MEMBER_EDIT（PATH=MODE_EDIT_ROAD_MEMBERS、他=MODE_NONE）で街路・高速道路の区間のクリックだけを受け付け、edit_road:toggle_path を UI へ送る。表示は STATE_EDIT_PATH と同じ建設系の表示プリセットで、計画中の区間も選べる。所属の付け外しは UI が POST /api/v1/roads/{id}/members で行い、結果の全集合を edit_road:set_members で送り返すので、Unity は所属を先回りして書き換えない。詳細パネルで結果を見ながら続けて操作するため、STATE_MERGE_PATH と同じくこのステートでは Unity ウィンドウを最前面化しない。

    終了はパネルの「完了」の edit_road:cancel {road_id} で行い、STATE_NORMAL は送らない（UI の知らないうちに Unity が別のモードへ移っていた場合に、それを打ち切らないため）。STATE_NORMAL・他のステートへの直接の遷移・Unity にフォーカスがあるときの Esc・セッションのリセット・別の道路（または同じ道路の別の session_id）での開始でもモードは終わり、どの場合も Unity が edit_road:ended を1回送る。edit_road:ended には、終わったモードの開始時の session_id を型を変えずに添える（開始時に無ければ省く）。モードが終わっても world:set_road_focus の強調は残る。

    道路詳細のウィンドウが閉じられたときは、Rust（window.rs の close_window_by_label）が閉じた道路の road_id を載せて world:clear_road_focus と edit_road:cancel を送る（ポップアップは非表示になるだけでアンマウント処理が走らないため。edit_path:cancel_topology_edit と同じ理由）。road_detail は EDIT_MODE_WINDOW_TYPES に入れない。パネル・3Dの強調帯・道路名ラベルを含む全体の仕様は道路の詳細と道路名を参照。

    起動・再接続時の版照合

    system:graphic_ready のペイロードは frontend_version、ipc_contract_version、core_compatible（Unityがコアの版と照合した結果）。UIは自身のIPC契約番号との一致と core_compatible を検査し、system:ready に自身の frontend_version・ipc_contract_version と accepted を返す。Envelope自体の version: "1.0" は変更しない。

    Unityはコアの版の照合とUIとのIPC契約が成立するまでマスター取得・ゲーム用操作・セッションポーリングによる開始を解禁しない。不一致のUnityを未接続として扱い、開発用の描画待ち省略に流さない。コアの版は各プロセスの起動時に照合し、周期的に取得しない。起動準備中の取得失敗は再試行できる。フロントのMAJORがコアより小さければ、Unityは終了する。詳細はバージョニングと互換性。

    編集の状態同期

    敷設設定の継続

    新規敷設後の STATE_EDIT_PATH は initial_height（小数m）、initial_embankment_height、initial_curved、initial_follow_terrain を任意パラメータとして受け取る。UIの continuePlacement が敷設設定を明示送信し、Unityの InitializeRoadPlacement が最初の形状通知より前に適用する。線路間隔・進行方向・ホーム側は既存の各パラメータで引き継ぐ。座標・制御点と見積りだけをクリアする。未指定の新規開始は既定値、既存パス編集は保存値を使う。

    土地区画作成のモード契約

    STATE_EDIT_PARCEL の parcel_creation_mode は、新規作成では along_path / block / random / empty_area を使う。TauriのボタンとUnityのラジアルメニューはこの順で表示する。既存区画の分割モードは維持する。block は地点選択と従来のプレビューイベントを使い、UIからバックエンドへ探索範囲・間口・奥行き・ばらつきを送る。新規の任意ポリゴン作図は提供しない。既存区画の形状編集イベント（edit_parcel:update_shape と edit_parcel:finish_shape_edit）は引き続き使用する。

    建物直接配置の状態同期

    配置方法の初期値は STATE_EDIT_BUILDING の遷移パラメータ placement_mode（parcel/free/roadside。省略時はparcel）で指定する。既存建物編集・忠実コピーでは無視される。市庁舎の配置（都市創設時と移転）はUIが free を指定する。以後の切り替えはUnityのCtrlラジアルメニューが担い、UIは placement_state の mode に追従する。

    edit_building:placement_command (ui → graphic)のparams.commandにはvariantと変更したフィールドだけを渡す。任意フィールドはwidth/depth/angle、reset=true(位置選択のみ取消し)、labels(翻訳済みCtrlメニュー/HUD文言)。寸法を含まない呼び出しは状態問い合わせとなる。パネルは購読完了後に問い合わせ、初期化通知を取りこぼしても復元できる。

    edit_building:placement_state (graphic → ui)は{variant, revision, mode, position, width, depth, angle, parcel_id}を返す。modeはparcel/free/roadside、positionは[x,0,z]または未固定を示すnull、parcel_id=-1は区画未選択。キーボード寸法変更・Ctrl切替・位置固定・回転終了・Escも同じ状態通知を使う。ホバー移動では常時送信しない。UIはこの通知をパラメータ変更として再送しない。

    直接配置のedit_building:update_shapeには要求元のplacement_revisionを付ける。Unityは現在の世代・階数・位置固定状態と一致する場合だけ描画する。パネルも要求キーで設置可否の鮮度を確認する。既存区画からの建設・編集は世代を付けない従来経路。

    配置方法は位置確定前に明示的に選択する。

    パネルの寸法コマンドにはrequest_idを付け、Unityは対応するplacement_state.request_idにそのまま返す。パネルは最後に送った数値変更への応答が届くまで確定を待つ。これにより連続入力中に先の変更への応答だけで確定可能になることを防ぐ。

    駅舎の建屋配置端

    edit_path:change_house_ends（UI→Unity）のparamsは house_ends（both/start/end）。新規敷設の建設パネルが選択値を管理し、Unityのプレビューへ反映する。初期値は STATE_EDIT_PATH の同名paramsで渡す。既存の形状編集では保存値を使う。

    既存駅の詳細パネルに配置端の変更UIはない。APIでの変更は着工前に限られ、追加する建屋の用地を検証する。駅の概念は駅と駅舎、建屋の配置計算は駅舎メッシュを参照する。

    プロップ個別配置の高さ

    world:change_stateのSTATE_EDIT_PROPとedit_prop:change_settingsはheight（地面からの相対高さm）を受け取る。edit_prop:update_instancesの要素はx/y/z/rotation/scaleで、yにその配置時の相対高さを載せる。Tauriは各点のyをPOST /api/v1/props/instancesへ送り、GETでも同じyを受け取る。高さ指定は全種別共通、0は地表、負値は地中。描画では地形標高へ加算し、モデルの拡大率を掛けない。

    3D側のPageUp/PageDown（0.1m刻み、Shiftで1m）と中ボタンドラッグ回転で変わった値は、Unityがedit_prop:placement_settings（rotation/height）でパネルへ返す。UIはこれをchange_settingsへエコーせず、以後パネルのステッパーを操作したときだけchange_settingsを送る（UnityとUIの往復ループを作らない）。

    2Dパス形状編集パネルの同期

    path_shape_editor ウィンドウ（PathShapeEditorPanel）は、敷設中パスのノードとベジエ制御点を都市マップ（CityMapCanvas）の上で編集する。形状の真実源はUnity（RoadPlanManager）のままで、パネルは edit_path:update_shape を受けて描き、操作の結果だけを edit_path:shape_command で送る（コマンド入力・全状態出力。建物直接配置の placement_command/placement_state と同じ構図）。UIは受信値を再送しないためループしない。

    • 開く: edit_path:update_shape の is_finalized && is_curved（曲線モードでの右クリック確定）を受けた敷設パネル（usePathConstruction）が open_registered_window("path_shape_editor") で自動的に開く。直線モードや配置中は敷設パネルの「2Dで編集」ボタンで手動で開く。
    • 閉じる: 敷設パネルの確定ボタン（close_registered_window("path_shape_editor")）、パス建設パネル（path_build）のクローズ（Rust window.rs の後始末）、update_shape の phase=inactive 受信（パネルが自分を閉じる）。2Dパネルを閉じても敷設セッションは続く（Unityへは何も送らない）。
    • 編集できるのは phase=editing のときだけ。配置中（placing）は表示のみ。標高・盛土は2Dでは編集せず、ノード選択（select_node）で敷設パネルのステッパーの対象を切り替える。
    • 曲率・勾配はUnityのローカル推定（alignment）をそのまま色分け・区間ラベルに使う。権威値は従来どおり /paths/construction-cost を敷設パネルの費用カードが表示する。
    • 高架・地下（height_editable）のバリアントでは地図の下に縦断面ストリップ（PathProfileStrip）を出す。横軸は曲線を伸ばした始点からの距離、縦軸は標高で、alignment.samples の路面・地盤プロファイルと alignment.nodes のアンカー位置から描く（線形評価の対象外の種別では折れ線長と相対高さだけの相対表示）。ここではノードを上下ドラッグで高さ（地面相対）だけ変更し、ドラッグ終了時に既存の edit_path:change_node を1回送る（Unityが min_height でクランプして適用し update_shape／select_node で返す）。横方向には動かせない。勾配の区間ラベル（labels の勾配側）も同じ位置に描く。
    • ノード番号（1始まり）は地図・縦断面ストリップ・Unityの3Dビュー（RoadPlanManager.NodeLabels のIMGUIラベル。選択中は強調色）で共通にし、どのノードを指しているかを対応付ける。

    パスの確定可否

    edit_path:update_shape は can_confirm を常送します。これはUnityの形状確定状態とローカル交差検証（立体交差と川・海・湖の横断）を合わせた真偽値で、形状が未確定または干渉中ならfalseです。Tauriはこの値だけで確定を許可せず、同じ全線ペイロードの /paths/validate 応答も照合します。既存の world:highlight_objects によるパス・建物の警告は、メッシュ着色ではなく半透明の占有箱として描画します。同イベントの params には colliding_river_ids（地表レベルで横切っている川のID文字列の配列。/paths/validate と /paths/interference の同名フィールドをそのまま渡す）も含み、Unity は該当する川の範囲を同じ占有箱で示します。 敷設パネルは /paths/validate の alignment_violations を保持し、線番号（1始まり）と各線の始点からの距離区間を添えて曲率・勾配違反を表示します。パス干渉・川横断・形状未確定・検証待ち・検証エラーを区別し、APIエラーの理由は省略せず再試行ボタンを出します。原因不明の拒否を赤い干渉と断定しません。送信直前の再検証でも同じ説明を使い、古い形状の結果は表示しません。2D表示はUnityの推定値なので、全線検証で拒否された区間を敷設パネルの案内で確認できます。費用欄は確定不可でも2点以上あれば表示します。
