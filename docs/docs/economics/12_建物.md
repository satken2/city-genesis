# 12. 建物
## 12.1 建物の種類

| 建物種類 (`bd_type`) | 値                      |
| ---------------- | ---------------------- |
| 集合住宅             | BUILDING_APARTMENT = 1 |
| 一戸建て住居           | BUILDING_HOUSE = 2     |
| 商業施設             | BUILDING_RETAIL = 4    |
| 工場               | BUILDING_FACTORY = 8   |
| オフィス             | BUILDING_OFFICE = 16   |
| 農地               | BUILDING_FARM = 32     |
| 鉱山               | BUILDING_MINE = 64     |
| 港湾               | BUILDING_PORT = 128    |
| 専用建物             | BUILDING_OTHER = 256   |
| 公共施設             | BUILDING_PUBLIC = 512  |

建物種類は建築規制の単位で、土地区画ごと・地区ごとに建ててよい種類(`allowed_bd_mask`)を指定する。入居できるテナント([2_経済主体](2_経済主体.md))の種類とは一致せず、どのテナントが入れるかは建物のフロア構成で決まる。バリアントは別に、建設する建物を選ぶときの分類(`bd_category`。`BD_CATEGORY_*`)を持つ。分類は「公共施設」にまとまった発電所・病院・駅などを用途で分け直したもので、建物を選ぶときの区分にだけ使い、建築規制やシミュレーションは参照しない。

### 建物と土地区画の種類

建物には、建築規制とは別に、建てられる土地区画の種類(`parcel_type`。[4_地区と土地区画](4_地区と土地区画.md))の制約がある。要求する種類はバリアントごとにマスターの `parcel_type` で決まり(指定が無ければ `PARCEL_LAND`)、建築規制で許可されていても、手動の建設にも民間の自動建設にも掛かる。水面(`PARCEL_WATER`)に建つ海上構造物(洋上風力発電所など)は市政府の公共施設で、生産したインフラ財を海底の送電線・パイプラインで陸へ送るだけの施設である([26_インフラ網](26_インフラ網.md))。

## 12.2 建物のライフサイクル

建物は、計画・着工・建設・稼働・停止・老朽化・修繕・倒壊・取り壊しの順に状態が移る。ステータスの一覧と遷移は[2_経済主体](2_経済主体.md)にあり、この章では建物に固有の条件を述べる。プレイヤーが建てる建物は計画中(`STATUS_SCHEDULED_CONSTRUCTION`)として作られ、確定前の `STATUS_TEMPORARY` の建物はシミュレーションに影響しない。

民間の建物(テナントに床を貸す建物と、工場などの専用建物)は、地区の床の需要が供給を上回ったときにシミュレーションが計画する。供給には停止中・建設中・計画中の建物も数えるので、空き家や工事中の建物があるうちは同じ用途の建物は重ねて建たない。建物の種類と階数は見込める家賃と建設費・土地代の採算で決まり、家賃の低い発展初期は安い簡素な建物が、家賃が上がると耐久性の高い建物や高層の建物が建つ。入居を待つテナントが入れる広さの区画が地区に無いときは区画サイズ不足の通知が出て、続くと隣接する空き区画が自動で結合される([4_地区と土地区画](4_地区と土地区画.md))。

## 12.3 建設の開始（PLANNED → CONSTRUCTING）

計画中の建物は、立地する区画の `usage_id` が `VALUE_NONE`(空き地)になったエポックに自動で建設中(`STATUS_CONSTRUCTING`)になり、区画の `usage_id` と `owner_agent_id` は新しい建物(公共施設なら所有者は市政府)を指す。既存の建物がある区画では、建て替えを決めた時点で新しい建物が旧建物の所有者へ残存価値・土地代・解体費を払って土地を取得し、旧建物の取り壊しが済むと着工する。市有地に民間の建物が建つときの土地代は、市政府ではなく中央銀行が受け取る([7_金融システム](7_金融システム.md))。公共施設の敷地は市有地になる。

公共施設は、区画を選ぶ代わりに、地形上に矩形の底面を直接置ける。置いた矩形には市有の区画が自動で作られ、建物はその全面を使い、計画を取り消すと区画も消える。底面が固定のバリアント(`resizable=false`)は向きだけを指定できる。民間の区画と重なる配置は、買収の承諾(`acknowledge_acquisition`)を添えたときだけ受理され、重なった区画の買収と解体が済むまで建物は計画中で待つ。造成工事(整地・埋立)も同じく範囲の市有区画と一体の公共施設で、完了しても中止しても区画ごと消える([造成](34_造成.md))。

### 建設サービスの自家調達と需給見通し

建設は、建設サービス財(`PRODUCT_CONSTRUCTION_SERVICE`)を商品市場で調達した分だけ進む([建設作業量と施工能力](25_建設作業量と施工能力.md))。無償の自給は無く、公共の工事は建設予算([22_予算管理](22_予算管理.md))、民間の建物は建設を決めた時点で付いた融資から払う。都市内に建設業が無ければ輸出入拠点が輸入する。パスは市場に直接参加できないので、地区の建設代理エージェント(`VARIANT_ZONE_CONSTRUCTION`。修繕は `VARIANT_ZONE_CONSTRUCTION_MAINTENANCE`)が代わりに調達する。

コストプレビューの見積は建設サービス財を毎エポック満額調達できる前提の値で、それとは別に、見積どおりの工期に要る量のうち都市の今の供給力で賄える割合(`construction_supply_ratio`)と、それを織り込んだ見込みの工期を示す。どちらも資金の制約は含まず、公共施設の新設は発注時の資金審査を受ける([22_予算管理](22_予算管理.md))。稼働後のランニングコストの見積は、1エポックあたり・フル稼働時の人件費と原材料費で、家賃と修繕費を含まない。

## 12.4 建設の進行と完了（CONSTRUCTING → ACTIVE）

建設中の建物は、エポックごとに調達した分だけ進み(`construction_progress`。百分率)、必要な量に達すると稼働中(`STATUS_ACTIVE`)になって `status_from` が竣工日になる。工事が進んだエポックには建物の version が上がる。造成工事は完了しても稼働せず、地形を書き換えて消える。

市政府が建てる対象(公共施設とすべてのパス)の工事で、直近のエポックに調達が需要に届かなかったものには、`alert` の建設サービス不足のビット(`ALERT_AGENT_CONSTRUCTION_SHORTAGE`・`ALERT_PATH_CONSTRUCTION_SHORTAGE`)が立ち、不足が解消すると消える。`alert` は version 管理の外にあり、差分ロードでは届かない([アラートフラグ管理](../programs/アラートフラグ管理.md))。

## 12.5 建物の停止（ACTIVE → PAUSED）

稼働中の建物は、利益率(専用建物を持つ一般施設)や稼働率(床を貸す建物)が低い状態が続くと停止(`STATUS_PAUSED`)し、貸し建物のテナントには退去が求められる(`is_evicted`)。公共施設と、稼働を始めて間もない建物は停止しない。停止中の建物は再稼働できる空き床の在庫として残り、テナントの入居が決まるか地区の床の需要が戻ると自動で稼働中に戻る。

## 12.6 老朽化

稼働中と停止中の建物とパスは、エポックごとに耐久度(`durability`。1.0が新品、0.0が完全な劣化)が下がる。下がる速さは耐用年数に反比例し、耐用年数が0の建物(公園・駐車場など)とパス(仮想道路・公共交通の路線)は老朽化しない。

## 12.7 修繕

耐久度が下がった稼働中の建物は修繕に入り、`status` は `STATUS_ACTIVE` のまま `under_maintenance` が1になる。民間の建物は確率的に修繕に入り、使われていない建物ほど放置される。市政府の公共施設は、耐久度がプレイヤーの設定した閾値(`repair_threshold`。パスは `repair_threshold_path`)を下回ると必ず修繕に入り、`under_maintenance` を0にすると取り消せる。修繕も建設サービス財を使い、規模は失った耐久度に比例し、完了すると耐久度は1.0に戻る。パスのコストプレビューの概算維持費(`estimated_maintenance_cost`)は、老朽化と修繕を繰り返したときの修繕費の長期平均である。

市政府は公共施設の建物を放棄(`abandoned`)できる。放棄した建物は修繕されず、稼働中ならその場で停止し、放棄をやめても自動では再稼働しない。

## 12.8 倒壊

稼働中・停止中の建物は、耐久度が低いほど倒壊しやすい(耐久度0でも確実ではない)。倒壊した建物は廃墟(`STATUS_COLLAPSED`)として区画に残り、原因は `status_reason` が表す(老朽化は `REASON_AGING`、火災による焼失は `REASON_FIRE`。[20_事故と災害](20_事故と災害.md))。倒壊すると、そこに住む市民と働く市民が死亡し、事故死として施政スコアを下げる([23_施政スコア](23_施政スコア.md))。廃墟は経済活動をせず、周囲の治安と住環境を悪くする。市政府の廃墟と倒壊したパスは、取り壊す代わりにその場で再建でき、同じ建物のまま建設中に戻る。

市長は民間の稼働中・停止中の建物を爆破して、エポックを待たずにその場で廃墟にできる。記録上は老朽化による倒壊(`REASON_AGING`)になり、残存価値が0になるので用地買収が安くなる。犠牲者と死者数は次のエポックの実行時に確定する。

## 12.9 取り壊し

停止中で古く傷んだ空き建物は、自動で解体計画(`STATUS_SCHEDULED_DEMOLITION`)に入り、テナントが退去してから取り壊し(`STATUS_DEMOLISHING`)に進む。ユーザーは市政府の建物と廃墟の取り壊しを指示できる。取り壊しも建設サービス財を使い、完了すると建物は清算待ち(`STATUS_EMPTY`)になって区画が空く。清算待ちの建物は通常そのエポックのうちに消え、残った現金と土地は中央銀行へ移る(公共施設の現金は市政府へ移り、敷地は市有地のまま)。パスは取り壊しが終わるとその場で削除される。

テンプレート作成モード(神モード)のブルドーザは、この手順を経ずに建物をテナントごとその場で削除する。区画は空き地として残り、地形は戻らない。市政府・中央銀行・市の代理主体・国境検問所は消せない([プレイモード](../programs/プレイモード.md))。

## 12.10 建設コスト

建物の作業量は床面積と階数で決まり、階数が高いほど床面積あたりの作業量が非線形に増えるので、地価や家賃が高くない場所では低層の建物が有利になる。斜面の区画は建設難易度([4_地区と土地区画](4_地区と土地区画.md))の分だけ建設・修繕・取り壊しの作業量が増える。

パスの作業量は、道路の面積(延長×幅)に種別係数(`path_master` の `cost_ratio`)と高架・地下の高さ倍率を掛けたものである。高さ倍率は、指定した相対高さではなく、実際に建つ構造物の地形からの高さ・深さ(3Dで描かれる姿と同じ)で地点ごとに決まり、地形から離れるほど加速度的に大きく、同じ高低差なら地下の方が高い。地上高を持つバリアント(送電線などの `base_height`)は、標準の高さを超えた分だけが高架として扱われる。地形に沿って敷く道路には、路面を平らにする造成の作業量が地形の勾配に応じて加わる([D_地形形状](../geometries/D_地形形状.md))。

## 12.11 市庁舎（市政府建物）

市政府(`VARIANT_CITY`)は都市の会計・予算を司る経済主体で([22_予算管理](22_予算管理.md))、マップ上では市庁舎として表される。市庁舎は老朽化・出火・停止をせず、取り壊せず、市民を雇用しない。中央銀行([7_金融システム](7_金融システム.md))と公共交通の路線エージェント([6_公共交通機関](6_公共交通機関.md))は、事業所を持たないので市庁舎に入居している扱いになる。所在を表すだけで、床の占有や家賃は無い。

### 都市の創設（市庁舎の配置）

新規の都市では市庁舎がまだマップ上に無く、プレイヤーが最初に市庁舎を置くことが都市の創設(`city_hall_placed`)で、これをもって建設の操作とエポックの実行が解禁される。市庁舎は無料・即時に完成し、道路や区画を用意せずに、区画の無い土地か市有の空き地へ置ける(その場所に市有の区画が作られる)。同じ条件で後から移転でき、移転前の敷地は市有の空き地として残る。シナリオとチュートリアルの都市は、保存されたときの創設状態で始まる。

## 12.12 観光名所

建物は、バリアントとは別に観光名所の種別(`landmark`。0は観光名所ではない)を持つ。一点物の名所ごとにバリアントを増やさないための直交した軸で、経済主体のバリアントは「観光名所」の1つだけ、名所の一覧はマスター(`landmark_master`)の行である。名所が決めるのは敷地の寸法・階数・階高・建設費の乗数・モデルだけで、これらは要求された値より優先されるので、フロントもプレビューを名所の値から始める。同じ名所は都市に1つまでで(編集中の建物自身は `exclude_agent_id` で判定から除く)、`landmark` は作成後に変えられず、名所の建物はコピー建設の元にできない。外観は既成建物(`MODEL_PREBUILT`。[F_建物メッシュの生成](../geometries/F_建物メッシュの生成.md))である。

## 12.13 テンプレート専用バリアント

マスター(`agent_master`)の `template_only` が立つバリアント(観光名所・国境検問所など)は、シナリオ(テンプレート)の制作にしか使わない。テンプレート作成モード以外では、作成・編集・削除の確定操作をバックエンドが拒否し(形状プレビューと見積は通る)、民間の自動建設の候補にもならない。

国境検問所は、陸路の国境で出入国と通関を行う建物で、シナリオの作者が都市境界のすぐ外の道路の突き当たりに置く([F3_既成建物のメッシュ生成](../geometries/F3_既成建物のメッシュ生成.md))。輸出入と観光客の発生は、入居する都市外旅客輸送拠点([31_観光](31_観光.md))と陸路輸送([8_商品市場](8_商品市場.md))が担う。この入居は所在だけを表し、床・空き・家賃を持たず、何件でも入れられる([プレイモード](../programs/プレイモード.md))。観光名所と国境検問所は老朽化も出火も停止もせず、置かれた姿のまま残る。

## 12.14 駐車

建物は台数で数える駐車容量(`parking_capacity`)を持つ。容量は敷地の平置き・高い建物の地下・駐車に充てる床(これを持つ立体駐車場などを駐車施設と呼ぶ)の合計で、建物の作成時と形を変える更新時に決まり、エポックでは変わらない。同じ車が昼は勤め先や買い物先に、夜は自宅に停まるので、使用量は昼と夜に分けて入居先の建物に数える。容量を超えた車は、同じ地区の駐車施設の空き、接道の路上、地区内の生活道路の順に停まり、路上へのあふれ(`parking_overflow`)は昼夜の大きい方の台数で、道路ごとの路上駐車台数は道路側の値である([3_道路網](3_道路網.md))。路上駐車は住環境・交通・事故に影響しない。

使用量とあふれはセーブに含まれず、ロード直後は次のエポックまで0になる。
