# 12. 建物
## 12.1 建物の種類

| 建物種類 (`bd_type`) | 値                      |
| ---------------- | ---------------------- |
| 集合住宅             | BUILDING_APARTMENT = 1 |
| 一戸建て住居           | BUILDING_HOUSE = 2     |
| 商業施設             | BUILDING_RETAIL = 4    |
| 工場               | BUILDING_FACTORY = 8   |
| オフィス             | BUILDING_OFFICE = 16   |
| 農地               | BUILDING_FARM = 32     |
| 鉱山               | BUILDING_MINE = 64     |
| 港湾               | BUILDING_PORT = 128    |
| 専用建物             | BUILDING_OTHER = 256   |
| 公共施設             | BUILDING_PUBLIC = 512  |

**建物の種類と入居できるテナント([[2_経済主体]])の種類(type)は必ずしも一致しない点に注意する。** （例: 集合住宅の一部に商業施設が入居できる場合もある）
どのようなテナント（経済主体）が入居できるかは、その建物が持つフロア構成によって決まる。
この建物種類は建築規制のベースとなる。土地区画ごとまたは地区ごとに建設を許可する建物種類を指定可能。

建物種類と土地区画の種類（`parcel_type`）には、建築規制とは別に物理的な立地制約が存在する。

| 建物種類 | 建設可能な土地区画種類 |
| --- | --- |
| 港湾（`BUILDING_PORT`） | 沿岸土地区画（`PARCEL_SHORE`）のみ |
| それ以外すべて | 通常土地区画（`PARCEL_LAND`）のみ |

水面（`PARCEL_WATER`）や埋立地（`PARCEL_RECLAIMED`）には、いかなる建物も建設できない。この制約は建築規制（`allowed_bd_mask`）とは独立して適用される。つまり、たとえ建築規制で建設が許可されていても、`parcel_type`の物理的制約を満たさなければ建設できない。

## 12.2 建物のライフサイクル

建物は、計画・着工・建設・稼働・老朽化・取り壊しに至る一連のライフサイクルを持つ。
すべての建物は基本的に`STATUS_SCHEDULED_CONSTRUCTION`（計画中）として作成される。プレイヤーが作成をまだ確定させたくない場合は`STATUS_TEMPORARY`で作成することも可能。`STATUS_TEMPORARY`の建物は各種シミュレーションに何の影響も与えず、自動的に他のステータスに変わることもない。

建物のライフサイクルにおける各フェーズの詳細は[[2_経済主体]]のステータス変遷も参照のこと。

## 12.3 建設の開始（PLANNED → CONSTRUCTING）

建物が`STATUS_SCHEDULED_CONSTRUCTION`の状態で、立地する土地区画（[[4_地区と土地区画]]）の`usage_id`が`VALUE_NONE`（空き地）になると、エポックのシミュレーション処理の中で自動的に`STATUS_CONSTRUCTING`に遷移する。ユーザーはこの遷移を直接操作できない。

### 土地・建物の取得（買収）

土地区画には所有者（`owner_agent_id`）が存在し、建物は自らが立地する土地を所有する。土地・建物の取得費用は、取得の状況によって次の2通りに分かれる。

- **建て替え（既存建物のある土地区画への建設）**: 新建物の建設が決定した時点で、新建物から旧建物の所有者へ買収金が支払われ、土地の所有権が新建物へ移転する。買収金は「建物の残存価値（家賃水準・床面積・残存耐用日数に基づく額。倒壊した建物は価値ゼロ）」「土地代」「解体費用」の合計であり、旧建物の解体費用も実質的に新建物側の負担となる。支払い後に旧建物の取り壊しが始まり、更地になり次第着工する。
- **市有地への建設**: 着工時に、新建物から土地代が支払われる（払い下げ）。代金は市政府ではなく**中央銀行**が受け取り、平準化を通じて経済全体へ還流する（[[7_金融システム]]）。土地の売却益が市政府の財源になることはない。市政府自身が建てる公共施設は自己所有地への建設のため無償である。

土地代は土地区画の`land_price`（地価）に基づく。着工が完了すると、土地区画の`owner_agent_id`と`usage_id`は新建物に更新される。

### 着工時の土地区画更新

土地区画の`usage_id`が新建物のエージェントIDに更新され、建物がその土地を占有するようになる。

### 建設サービス財の需要設定

着工すると同時に、建設に必要な建設体積（`construction_volume_required`）が算出される。建設体積は建物の床面積（`realestate_amount`）と階数（`floors`）に基づいて計算され、階数が高いほど建設体積は非線形に増加する。つまり、地価や家賃が高くない場所では高層の建物よりも敷地面積の広い低層建物の方が有利になる。

建設サービス財（`PRODUCT_CONSTRUCTION_SERVICE`）の需要量は、建設体積と推定建設期間から算出され、エポックごとの調達量として設定される。建設サービス財は他の経済商品と同じく市場のマッチングを通じて調達され、その代金は建物の所有者の`reserves`から支払われる。

推定建設期間は建設体積に比例する（道路と同じ枠組み）。建設体積は床面積（建ぺい率で変わる）と階数（階数ペナルティで非線形に増える）の双方で決まるため、**より大きい建物・より高い建物ほど工期が長くなる**。一方で1エポックあたりの調達量（＝1か月あたりの建設コスト）は建物の大きさによらずほぼ一定の速度となり、規模の差は工期と総建設コストに現れる。建設プレビュー（`POST /api/v1/buildings/construction-cost`）では、この推定建設期間・1か月あたりの建設コストを確認できる。

### 建設サービスの自家調達と需給見通し

建設サービス財も他の商品と同じく市場マッチング後の自家供給（[[8_商品市場]]）の対象であり、需要者ごとに一定量までは市場に供給者がいなくても無償で賄われる。このため、小規模な建物・道路は建設業が存在しない都市でも推定建設期間どおりに完成するが、それを超える規模の工事は都市内の建設サービス供給力に応じたペースでしか進まない。パス（道路・線路など）の需要は所属地区の建設代理エージェントに集約されるため、同じ地区で同時に多くのパス工事を行うと自家調達の枠を分け合い、1本あたりの進みはさらに遅くなる。

推定建設期間は建設サービス財を毎エポック満額調達できる前提の値であるため、コストプレビュー（建物 `POST /api/v1/buildings/construction-cost`・パス `POST /api/v1/paths/construction-cost` および `GET /api/v1/paths/{path_id}/construction-cost`）は、都市の現在の供給力から見た**調達充足率**（`construction_supply_ratio`、0〜1）と、それを織り込んだ**見込み建設期間**（`expected_duration_days`）を併せて返す。充足率1.0は推定建設期間どおりに完了する見込みを意味する。なお、建設業者の参入は建設需要に応じて起きるため、需要を出し続ければ供給力が育ち、見込みは以降のエポックで改善し得る。

### 稼働後のランニングコストのプレビュー

一般施設（TYPE_STANDARD）を建てる場合、コストプレビュー（`POST /api/v1/buildings/construction-cost`）は建設コストに加えて、**稼働後に毎エポック発生するランニングコストの推定値**も返す（`estimated_operating_cost`と内訳の`operating_wage_cost`人件費・`operating_material_cost`原料費、および支出元の予算カテゴリ`operating_cost_category`）。算出は新規参入者のスポーン判定と同じ原価推定（`calc_rough_cost`）に一元化されており、延床面積から求めたフル稼働時の生産量に対する人件費（標準/高度ティアの加重平均賃金）と原材料費（地区平均価格。地区未解決なら都市平均）を積み上げる。プレイヤーが建てる施設は専用建物のため家賃は含まれない。また、インフラ財・公共交通の車両財は専用網で無償配送され市場支出が発生しないため、原料費には計上されない。建物建設パネルの施設情報カードはこの値を「1エポックあたり・フル稼働時」の注記つきで表示する。なお、老朽化にともなう修繕費はこの推定に含まれない。

### パスの建設・修繕需要

建物と同様に、パス（道路・線路など）の新規建設・解体・修繕にも建設サービス財が必要である。
ただし、建設中/解体中/修繕中のパスは市場に直接参加できないため、
所属する地区の代表エージェントを経由して建設資材を調達する。

パスの需要を肩代わりする代表エージェントは、需要の種類によって2種類に分かれている。
- **建設代理エージェント（VARIANT_ZONE_CONSTRUCTION）**: 新規建設・解体需要を受け持つ。
- **修繕代理エージェント（VARIANT_ZONE_CONSTRUCTION_MAINTENANCE）**: 修繕需要を受け持つ。

なお、地区にはこの2種類のほかに、市民や店舗の転居時の一時入居先を担う**転居補助エージェント**（VARIANT_ZONE_RELOCATE）も存在するが、これはパスの資材調達には関与しない（[[4_地区と土地区画]] 参照）。

パスの `zone_id` が設定されている場合（生活道路 PATH_STREET など）、
その `zone_id` に紐づく建設代理エージェントに需要が積まれる。
`zone_id` が未設定の場合（幹線道路 PATH_MOTORWAY や線路 PATH_TRACK など）は、
幾何学的に最も近い地区（zone）の建設代理エージェントに需要が積まれる。
これにより、適切な建設代理エージェントを介して資材調達が行われる。

## 12.4 建設の進行と完了（CONSTRUCTING → ACTIVE）

`STATUS_CONSTRUCTING`の建物は、エポックごとに建設サービス財（`PRODUCT_CONSTRUCTION_SERVICE`）を消費して建設が進行する。市場から調達された建設サービス財の量が`construction_volume_acquired`に積算され、これが`construction_volume_required`に到達すると建設が完了する。

建設が完了すると、自動的に`STATUS_ACTIVE`に遷移し、建物の経済活動（テナントの入居など）が開始される。`status_from`（現在のステータスになった日付）が竣工日に更新され、以降の各種判定で参照される。

### 建設サービス不足時のアラート表示

建設サービス財は市場マッチングを通じて調達されるため、供給不足や建設業者のキャパシティ不足等原因により、需要量(`demand_amount`)に対して調達量(`remain_amount`)が満たないエポックが発生し得る。建設が滞留すると工期が伸びるだけでプレイヤーの施政計画に支障が出るため、市政府が建設する対象（公共施設および全道路）については、直近エポックで調達不足が発生した対象を3D空間上にアラートアイコンとして表示する。

アラートは建物・道路それぞれの `alert` ビットフラグ(`ALERT_AGENT_CONSTRUCTION_SHORTAGE` / `ALERT_PATH_CONSTRUCTION_SHORTAGE`)で表現され、該当する建物・道路の `center_point` 上にビルボード形式のアイコンとして常時表示される。調達不足が解消するとビットがクリアされ、アイコンは自動的に消える。アラート対象は `GET /api/v1/alerts`（`?bbox=`で絞り込み可能）で取得できる。`alert` は version 管理外のプロパティであり、通常の BuildingManager / PathManager の version 差分ロード対象外。詳細は [アラートフラグ管理](../programs/アラートフラグ管理.md) を参照。

| 項目 | 説明 |
| --- | --- |
| 対象スコープ | 建物は `is_bd=1 & public_facility=1` のもの、道路は全て。民間建物は対象外。 |
| 対象ステータス | `STATUS_CONSTRUCTING`（着工済み建設中）および `STATUS_DEMOLISHING`（解体中）。`STATUS_SCHEDULED_CONSTRUCTION`（未着工）や修繕中は含まない。 |
| 判定条件 | 直近エポックで建設サービス財の調達量が需要量に満たなかったこと。エポックごとに再判定される。 |
| 表示タイミング | エポック完了後のデータ再取得時・カメラ表示範囲の変更時 |

## 12.5 建物の停止（ACTIVE → PAUSED）

稼働中の建物が経済的に成立しなくなった場合、`STATUS_PAUSED`に遷移して経済活動を停止する。この判定はエポックごとに行われる。

### 停止条件

停止条件は建物の種類（`type`）によって異なる。

- **TYPE_STANDARD**（単独建物）: 直近の平均利益率が一定の閾値を下回った場合に停止する。
- **TYPE_BUILDING**（共有建物）: 直近の平均稼働率が一定の閾値を下回った場合に停止し、入居しているテナントに退去フラグ（`is_evicted`）が設定される。

### 停止免除

以下のいずれかに該当する建物は、上記の停止条件を満たしても`STATUS_PAUSED`に遷移しない。

- **公共施設**（`public_facility=1`）: 公共サービスとしての役割を持ち、入居率や利益率に関わらず維持すべきであるため、低利用率による停止の対象外となる。
- **稼働開始後の猶予期間内**: 稼働開始日（`status_from`。竣工または再開により`STATUS_ACTIVE`になった日付）から一定日数以内の建物は、テナントが集まるための猶予期間として停止判定から免除される。建物が完成してすぐに停止状態になるのを防ぐ仕組みである。

### 停止からの再開（PAUSED → ACTIVE）

`STATUS_PAUSED`の建物は市場から消えるわけではなく、「再稼働可能な休止在庫」として扱われる。

- 休止中もフロアの供給在庫として数えられ、テナントの転居先候補に含まれる。テナントの入居が確定すると、その建物は自動的に`STATUS_ACTIVE`へ復帰する。再開後は稼働開始の猶予期間があらためて適用される。
- 休止中も家賃の空室調整は継続され、募集家賃は時間とともに市場相場へ収斂していく。再開時に家賃が地区相場へ強制的に引き上げられることはない。
- 地区のフロア需要が休止在庫を含めても不足する場合に限り、新しい建物の建設が計画される。休止在庫が残っているうちは、同じ用途の建物が重ねて新設されることはない。
- 入居を待つテナントが既存のどの建物にも入れない（必要な最小面積を満たす空きが1棟も無い）場合は、床面積の合計が足りていても建設が計画される。逆に、そのテナントが入居できない規模の建物が新たに建てられることはない。大きな面積を要求する業種（牧場など）は、十分な広さの土地区画がある場所にだけ立地できる。
- 1世帯用の住宅（`shared_building = false` の一戸建てなど）は、入居を待つ世帯の所要面積に合わせた規模で建てられる。単身世帯しかいない地区に家族向けの大きな家ばかりが建つことはなく、世帯構成が多様な地区では小さな家と大きな家が混在して建つ。
- 民間の建設は、家賃水準と建設コストの採算で建物の種類（グレード）が決まる。家賃水準の低い発展初期の地区では建設コストの安い簡素な住宅から建ち始め、所得と家賃が上昇すると耐久性の高い住宅や、土地をより有効に使う集合住宅へと自然に移行していく。

## 12.6 老朽化

`STATUS_ACTIVE`または`STATUS_PAUSED`の建物は、エポックごとに`durability`（耐久度）が漸次的に減少する。減少速度は建物のvariantごとに定義された`useful_life`（耐用年数）に反比例する。つまり、`useful_life`が短い建物ほど早く老朽化が進む。`useful_life`が0に設定されている建物（公園や駐車場など）は老朽化しない。

`durability`は1.0（新築）から0.0（完全劣化）までの範囲をとり、修繕や建て替えの判断材料となる。耐久度が0に達しても老朽化による倒壊は確率的であり、廃墟になりきらずしぶとく建ち続けることがある（ただし火災による全焼は例外。[[#12.8 倒壊]]参照）。

パス（道路・線路など）も建物と同様に老朽化する。ただし、一般的な道路は`useful_life`が0に設定されているため老朽化しない。高架道路や橋梁など、構造的に耐久性が問題となるパスのみが老朽化の対象となる。

## 12.7 修繕

稼働中（`STATUS_ACTIVE`）の建物の`durability`が低下すると、一定確率で修繕状態に入る。修繕が行われても`status`は`STATUS_ACTIVE`のままであり、代わりに`under_maintenance`が1に設定されて修繕中であることを示す。修繕中も建物の経済活動は継続する。

### 修繕の開始条件

修繕の開始条件は、建物の所有者によって異なる。

- **民間建物**: `durability`が一定の閾値を下回った建物が確率的に修繕対象となる。損傷が深刻なほど修繕が始まりやすく、また利用率（`avg_utilization`）が高い建物ほど修繕確率が高い。誰も利用していない空き建物は放置される傾向がある。これは、採算の合わない建物に投資する動機がないことを表現している。
- **市政府所有の公共建物**（`public_facility=1`）: `durability`が`city.repair_threshold`（プレイヤーが設定可能）を下回ると、即座に修繕が開始される。確率ロールは行わず、閾値を下回った建物は全て修繕対象となる。プレイヤーが閾値を設定している以上、閾値を下回った建物を確率で間引くのはプレイヤーの意図に反するためである。ただし建設サービス財の市場調達が必要なため、修繕の進行速度は建設業者のキャパシティに依存する。公共建物の修繕はエポック結果ウィンドウで確認でき、プレイヤーは個別に修繕をキャンセル（`under_maintenance`を0に設定）することができる。キャンセルされた建物は次エポック以降、再度閾値を下回れば再び修繕候補となる。

パス（道路・線路など）も建物と同様に老朽化により修繕される。パスの修繕閾値は`city.repair_threshold_path`（プレイヤーが設定可能）で、建物とは独立して設定できる。パスの修繕もエポック結果ウィンドウで確認・キャンセル可能である。ただし、`useful_life`が0に設定されている通常の道路は老朽化しないため修繕対象外である。

### 修繕の進行と完了

修繕でも建設と同様に建設サービス財が消費される。修繕体積は、新規建設の体積を基準に損傷の大きさに応じて算出される。損傷が大きいほど修繕規模が大きくなるが、建物全体を建て直すよりは安く済む。

修繕が完了すると、`under_maintenance`が0に戻り、`durability`が1.0にリセットされる。これにより、建物は新品と同等の耐久性を取り戻す。

## 12.8 倒壊

`STATUS_ACTIVE`の建物は、`durability`の低下に伴い倒壊するリスクが高まる。`durability`が低いほど倒壊確率が急激に上昇する。`durability`が1.0（新品）の建物は確率的にも倒壊しない。

倒壊した建物は`STATUS_COLLAPSED`に遷移し、廃墟として土地区画上に残る。倒壊の原因は`status_reason`が表す。

- **老朽化による倒壊**: `status_reason=REASON_AGING`
- **火災による倒壊**: `status_reason=REASON_FIRE`（焼失）。当エポックに火災被害を受けた建物が倒壊した場合はこちらに分類される。特に**全焼**（火災被害で`durability`が0になった建物）は、確率判定を経ずに同エポック内で必ず焼失する（焼け落ちた骨組みが稼働状態のまま残り続けることはない）。

廃墟は経済活動を行わず、周辺の治安や住環境に悪影響を与える。廃墟は他の建物に建て替えられるまでそのままとなるので、土地需要の少ない地域では市政府が買収して取り壊しを行うまで放置される可能性が高い。

市政府所有の廃墟は、取り壊して更地に戻す以外に、その場で**再建**することもできる。再建すると建物は`STATUS_CONSTRUCTING`（建設中）に戻り、同じ土地区画・同じ建物のまま新規建設と同じ枠組みで工事が進む（建設サービス財を消費し、階数・床面積・地形の起伏に応じた建設体積を要する）。建設が完了すると`STATUS_ACTIVE`に戻り、耐久度（`durability`）が新品（1.0）にリセットされる。倒壊した道路・線路も同様に、取り壊さずその場で再建して`STATUS_CONSTRUCTING`に戻すことができる（[[3_道路網]]参照）。

建物の倒壊時には、以下の市民が死亡する。

- **居住者**: 倒壊した建物に入居していた世帯（`building_agent_id == 倒壊建物ID`）に所属する全市民
- **従業員**: 倒壊した建物で就労していた市民（`citizen.employer_agent_id == 倒壊建物ID`）

死亡した市民の数は`City.accident_death_count`に記録され、施政スコアのペナルティ計算に使用される。詳細は[[20_事故と災害]]および[[23_施政スコア]]を参照。

パスも建物と同様に倒壊する可能性がある。ただし、老朽化の対象外である通常の道路は倒壊しない。

なお、`durability`は老朽化以外に**火災**によっても低下する。火災の被害度はそのまま`durability`から差し引かれ、全焼した建物は耐久度がゼロとなって同エポック内に必ず焼失（`STATUS_COLLAPSED` + `REASON_FIRE`）する。部分的な焼損に留まった建物は稼働を続け、修繕（[[#12.7 修繕]]）や本節の倒壊判定の対象となる。火災の仕組み（出火・延焼・消防サービスによる消火）は[[20_事故と災害]]を参照のこと。

## 12.9 取り壊し

建物の取り壊しには、システムによる自動的な取り壊しと、ユーザーによる手動の取り壊しの2つの経路がある。

### 停止建物の解体計画（PAUSED → SCHEDULED_DEMOLITION）

`STATUS_PAUSED`の建物のうち、`durability`が一定の閾値を下回ったものが、確率的に解体計画状態に遷移する。解体計画確率は以下の3つの要素がいずれも大きいほど高くなる。

- **損傷度**（`1.0 - durability`）: 物理的な劣化の程度。損傷が大きいほど建て替えのメリットが大きく、解体計画確率が上がる。
- **経年度合い**（竣工日からの経過年数 / `useful_life`）: 修繕では回復しない不可逆な経年劣化の指標。修繕を繰り返して`durability`を回復させても、経過年数は増え続けるため、古い建物ほど解体計画に含まれやすい。`useful_life`が0の永続施設は経年度合いが0となり、解体計画対象にならない。
- **空室度**（`1.0 - avg_utilization`）: 経済的な需要のなさを表す。誰も利用していない廃れた建物は、維持する価値がないと判断され解体計画が進む。これにより、衰退した地区では更地が増加していく。

テナントの有無に関わらず、確率判定を通過した建物はすべて`STATUS_SCHEDULED_DEMOLITION`に遷移する。テナントがいない建物は、後続の解体開始処理で即座に`STATUS_DEMOLISHING`に進む。

### 解体開始（SCHEDULED_DEMOLITION → DEMOLISHING）

`STATUS_SCHEDULED_DEMOLITION`の建物は、エポックごとに取り壊し可能か判定される。建物の種類（`type`）によって条件が異なる。

- **TYPE_BUILDING**（共有建物）: `building_agent_id`に自身のIDを持つテナント（入居者）が全員退去済みの場合にのみ`STATUS_DEMOLISHING`に遷移する。テナントが残っている場合は`SCHEDULED_DEMOLITION`のまま待機し、テナントの退去・転居が進んだ後に次エポックで再判定される。
- **TYPE_STANDARD**（単独建物）: テナントを持たないため、即座に`STATUS_DEMOLISHING`に遷移する。

前段の解体計画で`SCHEDULED_DEMOLITION`になった建物のうち、テナントが既にいないものは同一エポック内で`DEMOLISHING`まで一気に遷移する。

### ユーザーによる手動取り壊し

ユーザーは、市政府所有の建物について任意のタイミングで取り壊しを指示できる。廃墟（`STATUS_COLLAPSED`）もユーザーの指示で取り壊すことができる。

### 取り壊しの進行（DEMOLISHING → EMPTY）

`STATUS_DEMOLISHING`の建物は、建設と同様に建設サービス財を消費して取り壊しが進行する。取り壊しに必要な体積は新規建設体積より小さく、建設よりも少ない作業量で済む。

取り壊しが完了すると、建物は`STATUS_EMPTY`（清算待ちの過渡状態）に遷移し、土地区画の`usage_id`は`VALUE_NONE`に戻る。土地の所有権はその時点の所有者が保持し続ける。建て替えによる取り壊しの場合、所有権は買収時（[[#土地建物の取得買収]]）に既に新建物へ移転している。

`STATUS_EMPTY`の建物はエポック処理の中で清算・削除される。保有していた`reserves`（現金残高。建て替えで受け取った買収金を含む）は中央銀行に引き継がれ、時間をかけて経済に還流する（[[7_金融システム]]）。`STATUS_EMPTY`の建物がまだ所有していた土地（老朽化による自然解体で所有者を失った土地）も、`reserves`と同様に中央銀行に帰属する。以後その土地に建物が建つ際の土地代は所有者である中央銀行へ支払われ、経済に還流する。

パスの取り壊し完了時は、建物と異なり即座に削除される。`STATUS_EMPTY`の過渡状態を経ない。

## 12.10 建設コスト

### 建物の建設コスト

建物の建設体積は、床面積と階数に基づいて計算される。階数が高いほど建設体積は非線形に増加する。

さらに、建物が立地する土地区画の**地形の起伏**が建設体積に影響する。土地区画は地形の平均勾配に応じた建設難易度（[[4_地区と土地区画]]）を持ち、斜面の区画ほど建設体積が増える。これにより、平地に比べて斜面では建設コストと工期の両方が増加する。この難易度は建設時だけでなく、修繕・取り壊しの体積にも同じように乗算されるため、斜面上の建物は生涯にわたって維持・解体のコストが高くなる。急斜面ではコストが著しく高くなり、経済的に建物が成立しなくなる（建築規制のような明示的な禁止ではなく、コスト増による自然な抑制である）。

### パスの建設コスト

パスの建設体積の基本は**道路の面積**（中心線に沿った延長 × 幅）である。これに加えて、パスの種別と高さに応じた係数が掛かる。

**種別コスト係数**: パスのバリアントごとに施工コスト係数（`path_master`の`cost_ratio`）が定義されている。同じ幅でも、未舗装路はほぼ無償で、舗装道路は標準的なコストが掛かり、防音壁付きの高規格道路や軌道はさらに高い、といった等級差を表現する。

**高架・地下の高さ倍率**: 路面が地形から離れている区間には、高架構造・地下構造の追加コストが発生する。倍率の基準となるのは、パスに設定した地面からの相対高さではなく、**実際に建設される構造物の高さ・深さ**（各地点における路面の絶対標高と地形標高の差。3D上で描画される姿と一致する）である。

- 倍率は地点ごとに評価される。地形から離れるほど（高い高架・深い地下ほど）倍率は加速度的に大きくなる。
- 両端の高さが低くても、**途中に深い谷がある区間を渡る橋は、谷底からの実際の高さで課金される**ため、平坦地の同じ高さの高架よりはるかに高コストになる。同様に、山体を貫くトンネルは山の下の実際の深さで課金される。
- 同じ高低差であれば、高架よりも地下の方が割高になる。掘削・擁壁・換気などの構造的・工法的な制約が高架よりも厳しいことを反映している。
- 路面が地形に沿っている区間は倍率1.0となり、追加コストは発生しない。

この倍率は建設時と修繕時の両方に適用される。修繕体積の計算においても、まず高さを考慮した建設体積を算出し、そこから損傷度と修繕コスト比率を乗じることで、高架・地下パスの修繕コストも適切に反映される。

#### 地形の起伏による造成コスト

上記の高さ倍率とは別に、パスが起伏のある地形を通る場合、道路面を造成（切土・盛土で平坦化）するための**造成コスト**が建設体積に加算される。道路は敷設時に、経路に沿って地形を平坦化し、周囲に盛土・切土の斜面を生成する（[[D_地形形状]]）。この造成コストは、道路が横切る**地形の勾配（急さ）**に応じて決まり、斜面を横切る道路（片側を削り、片側を盛る必要がある）や急な地形を通る道路ほど大きくなる。

重要なのは、このコストが勾配に対して**加速度的に増える**という点である。ほぼ平坦で多少ボコボコしている程度の土地では造成コストはわずか（数割増し程度）だが、急斜面では数倍、断崖絶壁では十数倍以上へと急激に跳ね上がる。道路が舗装で吸収できる細かな凹凸はコストに数えず、地形全体の傾きだけがコストになるため、緩やかな地形に沿って（等高線に沿って）道路を敷くほど安く、地形を無視して急斜面や崖を突っ切るほど極端に高くつく。これは建物の建設難易度が急傾斜地で跳ね上がるのと同じ考え方であり、地形に逆らわない道路計画にインセンティブを与える。

造成コストは建設体積として建物と同じ「建設サービス財」で調達されるため、道路の工期にも反映される。なお、このコストは建設の時点で「まだ変形していない元の地形」の勾配を基準に評価される。道路が完成すると地形は平坦化されるため、竣工後の修繕時には勾配がほぼ無くなり、造成コストは実質的に発生しない。また、地形に接しない高架道路・地下道路（高さ編集可能なバリアント）では、地形を変形しないため造成コストは加算されない（高架・地下構造自体のコストは上記の高さ倍率が担う）。

## 12.11 市庁舎（市政府建物）

市政府（`VARIANT_CITY`）は、都市の会計・税収・予算を司る特別な経済主体である（[[7_金融システム]]・[[22_予算管理]]）。この市政府は、マップ上に存在する象徴的な建物「**市庁舎**」として表現される。市庁舎は建物エージェント（`is_bd=True`）だが、都市の会計主体そのものでもあるため、通常の建物とは異なる特別な扱いを持つ。

### 都市の創設（市庁舎の配置）

新規に都市を始めたとき、都市の会計主体としての市政府エージェントは存在するが、市庁舎という「建物」はまだマップ上に配置されていない。プレイヤーは、ゲーム開始後にまず市庁舎をマップへ配置する。この配置が**都市の創設**であり、これをもって道路・土地区画・建物の建設といった各種操作がアンロックされる（市庁舎を配置するまではエポックを実行できない）。

市庁舎の配置は、他の建物と異なり以下の特別扱いを持つ。

- **無料**: 建設費・土地買収費は一切かからない。
- **即時完成**: 建設期間を経ずに、配置した瞬間に完成した稼働状態（`STATUS_ACTIVE`）になる。
- **道路が不要**: 配置時にはまだ道路が無いため、土地区画を事前に用意する必要はなく、地形上を直接クリックして配置できる（クリック地点に市所有の土地区画が自動生成される）。

この一連の流れは、まっさらな土地に最初の一手を置いて都市が動き出す、というゲーム開始の演出として機能する。

### 市庁舎の性質

市庁舎は都市に恒久的に存在し続ける象徴であるため、通常の建物のライフサイクル（[[12_建物]] 12.6〜12.9）のうち、劣化・喪失につながる挙動を持たない。

- **老朽化しない**: 耐久度は常に最大（新品）を維持し、修繕を必要としない。
- **火災が発生しない**: 出火・延焼の対象にならない。
- **取り壊せない**: プレイヤーが解体することはできず、一時停止（`STATUS_PAUSED`）にもならない。

これらは建物マスターデータの設定（老朽化を無効化する耐用年数・不燃設定）と、市政府エージェントに対する操作ガードによって成立する。

### 市庁舎への入居（中央銀行・公共交通路線）

市庁舎は、物理的な事業所を持たない経済主体の「所在地」としても機能する。具体的には、**中央銀行**（[[7_金融システム]]）と**公共交通の各路線エージェント**（[[6_公共交通機関]]）が市庁舎に入居している扱いになる。これは所在を表す台帳上の紐付け（所在建物への参照）であり、通常のテナントのようにフロアを占有したり家賃を支払ったりはしない。市庁舎の詳細ウィンドウでは、これらの入居主体を一覧として確認できる。

### 市政府は雇用しない

市政府（市庁舎）は象徴的な存在であり、市民を雇用しない。市政の運営費（各公共施設の維持費など）は市予算から支出されるが、市庁舎そのものが従業員を抱えることはない。
