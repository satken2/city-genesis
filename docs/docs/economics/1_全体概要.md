# 1. 全体概要

City Genesis は、プレイヤー(市長)が道路・土地区画・公共施設を整え、その上で人々の経済活動によって街が育っていく都市建設シミュレーションである。都市は人々の営みから自然に生まれるものとして扱い、現実と同じく、いったんできた街は簡単には作り直せない。

## 1.1. エポック

プレイヤーは予算の配分や建設計画をまとめて決めてから、シミュレーションを1エポック実行する。エポックを実行するまで都市の状態は変わらないので、プレイヤーは時間をかけて考えられる。1エポックで進む日数は [25_ゲーム内日付](25_ゲーム内日付.md) を参照。

![epoch.png](../images/epoch.png)

人や車を1つずつ動かさず、需要と供給、交通量などを数値で近似して計算する。重い計算はエポックの実行中だけに起き、都市が大きくなっても計画中の操作は重くならない。画面上の車や歩行者は、コアが計算した交通量などから描く演出である([交通シミュレーションと走行描画の整合](../geometries/T_交通シミュレーションと走行描画の整合.md))。

## 1.2. モジュール構成

ゲームは3つのプロセスで動く。

| モジュール | 担当 |
| --- | --- |
| コア | 都市の状態を持ち、エポックを計算する。HTTP API を提供する |
| UI(Tauri) | ウィンドウ・グラフなどの操作画面。ゲームの起動対象で、コアと Unity を子として起動する |
| グラフィック(Unity) | 都市の3D描画と、地図上での選択・配置などの空間的な入力 |

UI とグラフィックは、それぞれ HTTP でコアから都市データを取得し、編集の確定やエポックの実行もコアへ送る。UI とグラフィックの間は、共有メモリ(MemoryMappedFile)のメッセージで選択や編集の状態を同期する。都市の状態の正はコアだけにあり、UI とグラフィックはエポックの完了や編集の確定のたびにコアから取り直す。詳しくは [コンポーネント連携](../programs/コンポーネント連携.md)・[IPC連携](../programs/IPC連携の整理.md)・[バックエンドデータロード](../geometries/H_バックエンドデータロード.md) を参照。

## 1.3. 都市を構成するデータ

| データ                                | 内容                                                              |
| ---------------------------------- | --------------------------------------------------------------- |
| ノードとパス([3_パスとノード](3_パスとノード.md))          | 道路・線路・インフラの管路・公共交通の路線を表すグラフ。パスは形を持つ線、ノードはパスの端点と交差点              |
| 地区と土地区画([4_地区と土地区画](4_地区と土地区画.md)) | 地区は道路の集まりで決まる街のまとまりで、経済の計算と建築規制の単位。土地区画は建物が建つ土地のポリゴンで、所有者と地価を持つ |
| 経済主体([2_経済主体](2_経済主体.md))          | お金や財をやり取りする基本単位。世帯・店舗・工場・学校・市政府など。建物も経済主体である                    |
| 市民([15_世帯](15_世帯.md))              | 世帯に属する個人。年齢と技能を持ち、学び、働く                                         |
| 商品([8_商品市場](8_商品市場.md))            | 経済主体が生産・消費する財とサービス                                              |

建物は土地区画の上に建ち、世帯や店舗などは建物の床を借りて入居する。経済主体は商品市場で財を売買し、労働市場で市民を雇い、不動産市場で床を借りる。通勤・通学・買い物や財の輸送は道路網を流れ、その交通量や所要時間が住環境・店の集客・住まいや店の立地選びに返ってくる。

## 1.4. 想定する規模

コアとフロントは、15km四方ほどの範囲に道路ノード20万・市民100万・世帯30万・世帯以外の経済主体15万・建物9万がある都市でも動くように作る。
