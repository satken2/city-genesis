# 30. 人員搬送設備

ロープウェイのように、車両や運行主体を持たずに人を運ぶ設備（人員搬送パス）について。

## 30.1 概要

人員搬送パス（`PATH_CONVEYOR`）は、**歩道と公共交通の中間**に位置するパスカテゴリである。ロープウェイが最初のバリアントで、将来の動く歩道・公共エスカレータも同じカテゴリで表現する。

現実のロープウェイには、鉄道やバスにある「路線を敷いて車両を調達し、運行間隔を決める」という運営の層が存在しない。ロープを張れば搬器が連続して回り、人は乗り場から乗って降りるだけである。そのため人員搬送パスは公共交通（[[6_公共交通機関]]）の路線・停留所・車両・運賃の仕組みを一切使わず、**設備の速度で進める「速い歩道」**として住民の徒歩経路に直接組み込まれる。

| 観点 | 歩道（`PATH_WALKWAY`） | 人員搬送（`PATH_CONVEYOR`） | 公共交通（`PATH_TRANSPORT`） |
| --- | --- | --- | --- |
| 実体 | 物理パス（建設・老朽化） | 物理パス（建設・老朽化） | 論理パス（即稼働） |
| 運営主体・車両・運賃 | なし | なし | 路線エージェント |
| ノード層 | 道路と溶接する | 道路と溶接しない独立レイヤー | 独立レイヤー |
| 道路網との接点 | 全ノード | **乗降可能バリアントの端点のみ** | 停留所ノードのみ |
| 通過時間 | 歩行速度 | **バリアントの巡航速度** | 路線の走行時間 |
| 乗車時のコスト | なし | バリアント固定の待ち時間 | 運行間隔/2 + 運賃 |
| 混雑 | なし | 利用率による所要時間増 | 輸送容量による所要時間増 |
| 分岐 | 自由 | 不可（直列の継ぎ足しのみ） | 経路依存 |

人員搬送パスは経済主体ではなく、市場・会計には参加しない。運営費は他のパスと同じく修繕の費用だけであり、運賃も取らない（道路と同じ無料の公共インフラ）。

## 30.2 乗降できる場所

人員搬送パスのノードは道路・線路のノードと溶接されない（ノードのビットフラグが独立。[[3_道路網]]）。したがって「歩道から分岐する」「途中で降りる」ことは構造的に起きない。

住民が乗り降りできるのは、**乗降可能バリアント**（パスマスターの `boardable` が true。ロープウェイでは「ロープウェイ駅」）に接するノードだけである。乗降ノードは公共交通の停留所と同じ仕組みで最寄りの歩行者が通れる道路へ自動的に接続され、プレイヤーが道路とつなぐ操作は必要ない。

- ロープウェイの途中区間（バリアント「ロープウェイ」）どうしをつないだ角度変更点は乗降ノードにならない。
- 乗降ノードから乗るときには、バリアント固定の待ち時間（`board_wait_min`。搬器間隔の半分に相当）が加算される。降りるときには加算されない。
- 乗降区間を含む搬送設備の連結した一続きは、どの地区の住民からも徒歩経路の候補になる（地区をまたぐ幹線として扱われる）。

ロープウェイの駅は乗降区間そのものであり、**駅舎パス（[[29_駅と駅舎]]）を必要としない**。駅名を付けたい場合は乗降区間のパス名を使う。

## 30.3 分岐の禁止と交差

搬送設備は分岐器を持たないため、1つの端点に接続できる人員搬送パスは2本まで（既存の端点への直列の継ぎ足しのみ）である。3本目をつなぐ敷設・形状変更はエラー `CREATEPATH_CONVEYOR_BRANCH` で拒否される。

人員搬送パスはどの種類のパスとも（人員搬送パスどうしでも）交差ノードを作らず、自由に立体交差できる。同じ高さで物理的に重なる場合は他のパスと同じ干渉判定で拒否される（[[3_道路網]]の立体交差の扱い）。

## 30.4 通過時間・容量・土地

- **通過時間**: 区間の長さをバリアントの巡航速度（パスマスターの `default_speed_limit`。ロープウェイは 20km/h）で割った時間。人員搬送パスでは制限速度の変更ではなく設備そのものの速度として扱う。
- **容量と混雑**: 交通量・キャパシティは歩行者カテゴリで計上される（利用者は歩行者トリップ）。利用率が高いと通過時間が伸びる仕組みは道路と共通で、搬器が満員で待たされる状態を表す。統計上の利用者数はパスの歩行者交通量（`path_traffic`）で読める。
- **土地**: 通常のパスと同じく幅いっぱいに土地を占有し、民間区画の上を通す場合は買収が必要になる。ロープウェイのバリアントは地形に追従しない（高さ編集可）ため、谷を渡る区間は支柱付きの高架として描かれ、地形は変形しない。
- **ライフサイクル**: 計画→建設→稼働→老朽化→倒壊の通常のパスの流れ（[[3_道路網]]）に従う。

## 30.5 データモデル

パスマスター（`GET /api/v1/master/paths`）の人員搬送バリアントに固有の項目。

| プロパティ | 内容 |
| --- | --- |
| `type` | `PATH_CONVEYOR`（共有定数） |
| `boardable` | true ならこのバリアントに接するノードから乗降できる（ロープウェイ駅 = true、途中区間 = false） |
| `board_wait_min` | 乗降ノードで乗車時に加算する固定の待ち時間（分） |
| `default_speed_limit` | 巡航速度（km/h）。歩行者の通過時間の算出に使う |

人員搬送パス自体は通常のパスAPI（`GET /api/v1/paths/{id}` 等）で扱い、路線（`/api/v1/transit/...`）には現れない。
