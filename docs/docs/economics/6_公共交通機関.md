# 6. 公共交通機関

都市内の公共交通（路線バス・メトロ・LRT・モノレール・中距離鉄道と貨物列車）の仕組みについて。

## 6.1 概要

公共交通は、自動車を保有しない世帯の移動手段を提供するインフラである。世帯の移動（通勤・通学・買い物）は徒歩か自動車で行われ、公共交通の路線は徒歩の経路の一部として使われる。ロープウェイのように車両・運行主体・運行間隔を持たない設備は、公共交通ではなく人員搬送パスとして扱う（[30_人員搬送設備](30_人員搬送設備.md)）。

| 要素 | 実体 | 役割 |
| --- | --- | --- |
| 停留所 | ノード | 乗客が乗り降りする地点 |
| 経由点 | 路線の設定値（ノードを持たない） | 停車せずに必ず通る地点。路線が走る経路を指定する |
| 区間パス | パス（`PATH_TRANSPORT`） | 巡回順で隣り合う停留所を結ぶ、路線の進行方向の一方通行の運行区間 |
| 路線 | 経済主体（建物ではない） | バスの系統やメトロの路線。車両を借り、運賃を受け取る運営主体 |
| 駅 | パス（駅パス） | 鉄道系の停留所を置けるホームを持つ線路。建物ではない |
| 車両基地 | 経済主体（建物） | 車両を路線に貸し出す公共施設 |
| 車両 | 公共交通の車両財（`GOODS_TRANSIT`） | 路線が車両基地から毎エポック借りるリース財 |

路線の種別（バス路線・メトロ路線・LRT路線など）は公共交通マスターで定義される。種別のキーは区間パスのバリアント（`transit_path_id`）で、路線の `path_variant` はこの値を持つ。種別は、停留所を置ける下地のパス（`stop_path_variants`）、車両が走れる下地のパス（`route_path_variants`）、交通量に載る車種（`vehicle_type`）、車両の性能、貨物路線かどうか（`freight`）を持つ。

## 6.2 路線ネットワークの表現

路線の経路は、停留所と経由点を巡回順に並べた巡回点で表す。路線は巡回点を順にたどって最後の停留所から先頭の停留所へ戻る1周を繰り返し、往復運行も「行きの停留所と帰りの停留所を並べたループ」として表す（停留所 A・B だけの路線は A→B→A と往復する）。区間パスは巡回順で隣り合う停留所の組ごとに1本あり、乗客は路線の進行方向にしか乗れない。停留所ノードは路線の専有物で、同じ場所に停まる路線どうしでも別のノードになるので、乗り継ぎは必ず「降車・歩く・乗車」になる。経路を編集すると停留所ノードと区間パスは作り直され、路線を削除するとそれらと路線エージェントがまとめて消える。

住民は最寄りの歩行者が通れる道路から停留所を使い、歩く・乗る・乗り換えるを組み合わせた行き方のうち、所要時間に乗るたびの待ち時間（運行間隔が長いほど大きい）と時間に換算した運賃を足した負担が最も小さいものを、地区の単位で選ぶ。運賃が高すぎる路線、本数が少なすぎる路線、駅が住民から遠い路線は、線路がつながっていても選ばれない。

### 下地の交通網に沿った物理経路（迂回と運休）

車両は区間パスではなく、種別の走行網に属する下地のパス（道路・線路・駅）の上を走る。路線は1周で走る下地パスの列（`route_path_ids`）を持ち、これはエポックごとに最新の交通網から作り直される。道路や線路が失われても残った網でつながれば自動で迂回し、隣り合う停留所の間が下地パスの通行方向を守ってつながらなくなると、路線全体が運休する。

鉄道・モノレールの線路は、パスと進む向きが決まれば列車が走る軌道が1つに決まる（1本で上下線を持つ複線のパスでは、都市の通行側 `traffic_hand` の軌道）。ノードはどの軌道につながるかを持たないので、1つのノードに集まった線路は進行方向の連続性が許すかぎりすべてつながり、渡り線はノードの上に自動でできる。列車は自分が止まるホームの上でだけ、ホームの通行方向によらず走って向きを変えられる。

### 交差点での進行方向の連続性

線路・モノレールのような案内軌条系の車両は、交差点や合流点で自由に向きを変えられない。別の線路へ移れるかは2本の線路がノードに接する向きのなす角で決まり、鋭角の折り返しや直角の転回はできない。停留所では車両が止まるので折り返せる。そういう向きでしかつながらない停留所どうしを結ぶ路線は運休する。バスはこの制約を受けず、LRTは専用軌道どうしの接続にだけ受ける。3D表示でも、通行できる線路の組の間にだけレールを描く（[N_線路メッシュの生成](../geometries/N_線路メッシュの生成.md)）。

## 6.3 路線と路線エージェント

路線を作成すると、建物を持たない経済主体（[2_経済主体](2_経済主体.md)）である路線エージェントが1つ作られ、区間パスは `line_agent_id` でこれに紐づく。路線エージェントは車両を借り、運賃を受け取り、路線ごとの乗客数と収支の単位になる公共施設で、収支は市予算の公共交通カテゴリ（`LEDGER_TRANSPORT`）に入る（[22_予算管理](22_予算管理.md)）。所在地として市庁舎に入居している扱いだが、床や家賃は持たない（[12_建物](12_建物.md)）。

区間パスは建設・老朽化のライフサイクルをたどらず、作成と同時に稼働する。路線エージェントと区間パスの状態（`status`）は `STATUS_ACTIVE`（運行中）か `STATUS_PAUSED`（運休）だけを取り、運休は路線単位で揃って起きる。路線が走る線路・駅・道路は通常のパスである（[3_パスとノード](3_パスとノード.md)）。

## 6.4 停留所と駅

停留所は目に見えないノードで、種別の `stop_path_variants` に属する稼働中のパスの上（パスの敷地とホームの上）にだけ置ける。乗っている下地のパスは停留所ノードの `station_path_id` に記録される。経由点はノードを持たず、種別の走行網のパスの上に置く。曲がった道路・線路では、両端を結ぶ直線ではなく実際の中心線で位置を判定する。

鉄道系の停留所は駅パスの上に置く。駅パスは線路と同じ操作で建設し、線路と同じライフサイクルに従う特殊なパスで、駅パスが失われれば路線は運休する。プラットフォームは駅パスの敷地を広げる形で表し、どちら側に設けるかを建設時に `platform_side`（`PLATFORM_SIDE_*`。内側・外側は都市の通行側を基準に左右へ解決する）で決める。1本で上下線を持つ駅パスは、上下線の間に中央の間隔（`center_width`）を持てば線路の間に島式のホームを、持たなければ上下線の外側に相対式のホームを持つ。駅パスを1つの駅に束ねるのは駅舎パスである（[29_駅と駅舎](29_駅と駅舎.md)）。

LRTは、LRT線路付きの街路・歩行者専用道路（LRT付き）・LRT専用軌道を走り、走行網のどこにでも停留所を置ける。どのパスも1本で上下線を持つ複線で、街路の区間では交差点で自由に曲がり、街路の混雑を受け、便数は街路の交通量に加わる。

## 6.5 車両と車両基地

車両は公共交通の車両財（`GOODS_TRANSIT`）で、毎エポック更新するリースである。商品市場では取引されず、下地の走行網でつながった車両基地から路線へ配られ、借りられた車両数がそのエポックの路線の運行能力になる。車両の数量は「1両を1日使う量」で数えるので、リース料は両数とエポック日数に比例する。APIが返す車両数（`vehicle_count`・`required_vehicle_count`、収支見込みの `vehicles_required`）は両数である。

車両基地（バス車庫・鉄道車両基地・LRT車両基地・モノレール車庫）は市政府の公共施設で、運転士と整備士を雇い、原料を買って車両を更新する。その敷地・人手・原料が運行できる車両数の上限になり、リース料は基地の原価から決まる。基地は接続端子ノード（`depot_node_id`）で走行網につながり、鉄道系の基地は接続端子へ引き込み線を敷かないと車両を貸せない（バス車庫は近くの街路に自動でつながる）。鉄道車両基地とモノレール車庫は、電化線路（電力を流せる線路・駅パス）から高圧電力を受け、接続端子は走行網とインフラ網の共用接続ノード（`depot_node_id` と `infra_node_id` が同じ）なので、電化線路の引き込み線1本で車両の配送と受電の両方がつながる（[26_インフラ網](26_インフラ網.md)）。

車両は走行網の連結成分（互いにつながった範囲）ごとに、その中の車両基地から路線へ配られる。基地の生産が足りないと各路線の必要車両数に比例して減り、全路線が一律に減便する。配分は編成単位である。

## 6.6 運行能力と混雑

プレイヤーは路線ごとに目標運行間隔（`target_headway`。分）と1編成の車両数（`cars_per_train`）を決める。1周の所要時間と目標運行間隔から必要な編成数（`train_count`）が決まり、車両がそろえば目標運行間隔どおりに走る（それより頻繁には走らない）。車両が足りないと運行間隔が伸び、1編成も組めなければ運休する。1編成の長さが停留所の乗るパス（駅のホーム。LRTでは交差点で区切られた1区間）の長さを超える設定は拒否され、後からホームが短くなった場合は運休になる。

路線の輸送容量（1編成の車両数×種別の1両の定員×便数）は区間パスの容量になり、乗客が容量に近づくと道路の渋滞と同じく乗車の所要時間が伸びる。区間ごとの1日の乗客数を輸送容量で割った値が区間の混雑率で、路線の混雑率は最も混む区間の値である。運行便数分の車両は、乗客の有無によらず下地パスの交通量（`path_traffic`）に種別の車種として加わり、道路の上では一般の自動車と容量を共用する。

### 線路容量

線路とモノレールの軌道には、1日に通せる列車の本数の上限（線路容量。単位は路線の便数と同じ1日あたり編成数）がある。負荷は軌道ごとに「その軌道を走る路線の便数×1周で通る回数」で数え、行き違いのできない双方向の単線では、単線を走り続ける区間に入った列車がその区間全体を占有するものとして数える。線路を走るのは公共交通だけなので、線路容量は操作の事前検証として働き、路線の新設・経路の編集・運行間隔や編成の変更・線路の造り替えで容量を超えるものは拒否される。線路の撤去や倒壊による迂回で超えた場合は、運休させずに通知（`rail_capacity_exceeded`）で警告する（[通知レベル管理](../programs/通知レベル管理.md)）。線路の利用率は、実際に走った便数で数えた軌道の負荷と単線区間の占有時間のうち、最も高い割合である。バスは道路を一般車と共用するので、事前検証の対象外である。

## 6.7 運賃と資金循環

プレイヤーは路線ごとに乗車1回あたりの均一運賃（`fare_price`）を決める。乗車回数は、自動車を持たない世帯の通勤・通学と、徒歩で行く買い物の往復で、行きと帰りに乗る路線ごとに1回と数え、乗り継ぎも新たな乗車になる。運賃は都市の平均賃金で時間に換算されて住民の経路選択に入るので、運賃を上げれば利用者は歩く経路へ流れ、運賃だけで収入を増やすことはできない。公共交通が使われない地区では歩く負担が増え、自動車の保有を後押しする（[10_消費活動](10_消費活動.md)）。

運賃は世帯から路線エージェントへ、リース料は路線エージェントから車両基地へ払われる（[7_金融システム](7_金融システム.md)）。どちらも公共施設なので、収支はエポック末の会計統合で市政府に一元化され、路線の赤字は市政府が負担する。公共交通予算は車両基地の運営を制限し、予算が足りないと基地の生産が縮んで路線が減便する。

路線の設定を確定する前に、その設定での1エポックあたりの収支を試算できる（都市は変わらない）。車両はすべて借りられたものとし、運営原価は車両のリース料、収入見込みは想定乗車率の乗客を乗せたとした額で、設定の採算を比べるための目安である。

## 6.10 車両の走行と共通の所要時間

路線は、停留所の間の方向付きの経路と、加減速・カーブ・停車を含む走行時間（`journeys`）を持ち、必要編成数・運行間隔・乗車時間と車両の描画がこの同じ時間を使う（[交通シミュレーションと走行描画の整合](../geometries/T_交通シミュレーションと走行描画の整合.md)、[車両の走行描画](../geometries/O_車両の走行描画.md)）。走行速度の上限は下地の道路・線路の上限速度と種別の最高速度の小さい方で、線路の制限速度は規制の対象ではないので、鉄道の速度は曲線半径と種別の最高速度で決まる。1本で上下線を持つパスで折り返すと走る軌道が入れ替わり、鉄道とLRTの編成は折り返すたびに向きが反転する。

### バス停とLRT停留所の3D表示

バス停の上屋とLRT停留所のホームは、グラフィックが描く装飾である。シミュレーション上のデータを持たず、停留所の位置、乗り降り・経路探索の判定、土地区画やパスの配置に影響しない。バス停の上屋は `station_path_id` が指す道路に沿って置き、LRTのホームは `stop_points` の停止位置（下地のパスの中心線に沿った水平距離の割合で、両端を結ぶ直線上の割合ではない）を中心に編成長に合わせて描く（[道路メッシュの生成](../geometries/G_道路メッシュの生成.md)、[線路メッシュの生成](../geometries/N_線路メッシュの生成.md)）。

## 6.11 貨物路線

公共交通マスターの `freight` が真の種別は貨物路線で、乗客の代わりに種別ごとに決まった1品目の貨物を運ぶ。作り方・下地経路・線路容量・車両のリースは旅客の鉄道と同じで、列車は貨物列車（`VEHICLE_FREIGHT_TRAIN`）として旅客路線と線路容量を取り合う。違うのは、1編成が機関車1両を含むこと（最低2両）、乗客を乗せず運賃収入が無いこと、輸送能力が重さ（t/日）になること、品目に合った貨物専用のホーム（貨物PF）にだけ停まることである。貨物PF・積み下ろしの施設・国際貨物は[33_貨物輸送](33_貨物輸送.md)にまとめる。
