# 26. インフラ網

電力・水道などの都市インフラと、原油・鉱石の大口輸送は、道路とは別の専用の網(インフラ網)で運ばれる。

## 26.1. インフラ財（GOODS_INFRASTRUCTURE）

インフラ網で運ぶ財を**インフラ財**(`GOODS_INFRASTRUCTURE`。[8_商品市場](8_商品市場.md))と呼ぶ。高圧電力・高圧水道・パイプライン原油などがある。インフラ財は商品市場で取引されず、網でつながった施設の間でだけ移る。送る施設も受け取る施設も市政府の公共施設なので代金のやり取りは無く、民間の自動建設([2_経済主体](2_経済主体.md))では建たない。また蓄えられないので、生産施設は配送の直前にそのエポックの分だけ作り、配れなかった分は捨てられる。消費施設は毎エポック必要量を満額で求める。

高圧電力・高圧水道と貨物(26.6)は、受け取る施設の原価を出すために形式上の単価を持つ。単価は生産施設の稼働コストを配った量で割って求め、施設の原価(価格設定パネルの原価表示や車両のリース料)にだけ効く。市長が決める電気料金・水道料金や予算の見積りには入らない。

### 2段階の構造

```mermaid
graph LR
発電所 -- 高圧電力(インフラ財) --> 送電線網 -- 高圧電力(インフラ財) --> 変電所 -- 電力(サービス財) --> 需要家
```

発電所は高圧電力を作り、送電線の網で変電所へ送る。変電所は高圧電力から電力(サービス財)を作り、商品市場で世帯や施設へ届ける。発電所を建てても、送電線と変電所が無ければ電力は届かず、網が分断されていたり容量が足りなかったりすると停電になる。太陽光・風力の発電量は、そのエポックの天気で変わる([9_生産活動](9_生産活動.md))。

水道(取水施設など → 導水管 → 水道ポンプ)も同じ構造である。海底の油田の原油も、洋上石油プラットフォームから海底石油パイプラインで沿岸の受入基地へ送り、受入基地が原油(工業原料)として商品市場へ出す。出口が工業原料なので、電力と違って取引には輸送コストがかかり、買った側は在庫として持ち越せる。

## 26.2. インフラパス

インフラ網を作るパスの種別は `PATH_ELECTRICITY`(送電線)・`PATH_WATER`(導水管)・`PATH_PIPELINE`(パイプライン)である([3_道路網](3_道路網.md))。どの網に属するかはバリアントの `infra_products`(流せるインフラ財の製品IDのリスト)で決まり、同じ製品を持つパスどうしが同じ網になる。パス1本が1日に流せる量の上限は `infra_capacity` である。`over_water_allowed` が立つバリアント(海底送電線・海底石油パイプライン)だけが、海上構造物へつなぐために海岸線の外にアンカーを置ける。

インフラパスは経路探索・交通に参加せず、他種のパスや別の網のパスとは自由に立体交差する。同じ網のパスどうしが同じ高さで交差したときだけ、交点に分岐ノードができる。端点のノードは流せるインフラ財のビットを持ち、ビットの積で溶接の可否を決める規則([3_道路網](3_道路網.md))によって、送電線は電力のビットを持つノードにしかつながらない。インフラ財ごとのビットは、全インフラ財を製品IDの小さい順に並べた順位で、共有定数 `INFRA_BIT_BASE` の位置から割り当てる。

インフラパスの端点は、XZが合えば高さの差を問わずノードへ溶接でき、端点もノードも元の高さを保つ(垂直結合)。同じ網のパスの中間へ端点を落とすと、高さの差が共有定数 `INFRA_TAP_HEIGHT_TOLERANCE` 以内なら分岐ができ、端点の高さがそろえられる(タップ)。

### 電化線路（インフラ財のキャリアを兼ねる交通パス）

線路・駅パスのバリアントが電力を `infra_products` に持つと、鉄道であると同時に送電線として働く**電化線路**になる。送電線の端点を電化線路の中間へ落とすと、高さの差を問わず電化線路が分割されて送電網とつながる。駅パス(ホーム)は長さを分断しないようタップできないので、駅の前後の本線へ引き込む。網を駅で途切れさせないため、電化する線路は本線と駅パスの両方のバリアントに電力を持たせる。

## 26.3. 施設とインフラ網の接続（接続端子ノード）

インフラ財を授受する施設を置くと**接続端子ノード**が自動で作られ、そのIDが経済主体の `infra_node_id` に記録される。ノードのAPIは所属施設を返さないので、端子は経済主体の側から引く。プレイヤーはその財を流せるパスの端点を端子へ接続して、施設を網に参加させる。端子は建設中から作られ、複数のパスをつなげる。端子に稼働中のパスが1本もつながっていない施設は、配送の対象にならない(停電・断水)。

端子は施設の区画の辺の中点の地表(相対高さ0)に置かれる。区画が長方形なら短辺の中点、それ以外は面している道路から最も遠い辺の中点、接道の無い長方形でない区画は区画の中心である。パスがつながっていない間だけ、区画の中(XZ)で動かせる。

### 共用接続ノード（走行網とインフラ網の両方に接続する施設）

鉄道車両基地・モノレール車庫のように、走行網への接続端子(`depot_node_id`。[6_公共交通機関](6_公共交通機関.md))とインフラ網への接続端子の両方が要る施設には、端子が1つだけ作られ、`infra_node_id` と `depot_node_id` が同じノードを指す。電化線路の引き込み線を1本溶接すれば車両の配送と受電の両方がつながり、非電化の線路では車両だけが届く。

## 26.4. インフラ財の生産と配送

各エポックの商品市場の取引の後に、生産施設がそのエポックの分を作り、網を通して消費施設へ流せるだけ流す。太陽光・風力・原子力・取水施設などは作れるだけ作って配れない分を捨て(出力一定)、石油火力・積込駅などは配れた分だけ作って燃料もその分だけ使う(需要追従)。先に出力一定の施設の分を流し、残りを需要追従の施設が受け持つので、晴れて再エネで足りるエポックは火力が燃料を使わない。

パス1本に流せる量は `infra_capacity` × エポックの日数までで、並べて敷けば合算される。供給や容量が足りないとき、どの消費施設が受け取れるかは網の構造で決まり、末端や細い経路の先ほど不足しやすい。ただし需要の小さい施設(車両基地など)は、大口に供給を取られて受電ゼロにならないよう配分される。

生産施設の `supply_amount` はそのエポックに作れた量、`supply_left_amount` は配れなかった量、`supply_sold_amount` は配った量を表す。パスの `infra_flow` はそのパスを流れた量で、正は始点ノードから終点ノードへの向きである。並行するパスの流量は、容量の比で分けた近似値である。

## 26.5. インフラ網の観測（アラートと統計）

稼働中のインフラ施設の端子に、その施設が授受するインフラ財を流せる稼働中のパスが1本もつながっていなければ、アラートビット `ALERT_AGENT_INFRA_DISCONNECTED` が立つ([アラートフラグ管理](../programs/アラートフラグ管理.md))。建設中の施設は対象外で、毎エポック判定し直す。施設が受け取った量は、全財共通の当エポック獲得量 `received_amount`([8_商品市場](8_商品市場.md))で見る。

### インフラ網統計（GET /api/v1/stats/infrastructure）

製品ごとに生産施設・消費施設・パスの一覧と合計を返す。消費施設の一覧は接続状態を見せるため需要の無い施設も含み、接続状態は未接続アラートと同じ判定である。パスの一覧は建設中のパスも含む。`flow` は折れ線の並び(始点→終点)の向きを正とする流量、`capacity` は1エポックあたりの容量である。消費施設の `demand` はエポック末に立て直した次のエポックの需要で、`received` がそのエポックに受け取った量である。

## 26.6. 貨物（鉱石・原油を運ぶ専用網）

パイプライン原油・鉱石(大口輸送)のように物そのものを専用網で運ぶインフラ財を**貨物**と呼ぶ。電力・水道と同じ仕組みで運ばれるが、貨物路線の区間も網の一部になり(容量は路線の輸送能力で、進行方向にだけ流れる)、積み下ろしの施設は近くの貨物路線の停留所と容量無制限でつながる。運べなかった分は、積み出し施設が原油・鉱石のまま在庫に残す。詳しくは[33_貨物輸送](33_貨物輸送.md)。
