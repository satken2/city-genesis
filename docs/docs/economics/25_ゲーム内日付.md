# 25. ゲーム内日付

本ゲームにおける時間の経過とカレンダー表現、およびエポックシステムにおける日付の進行について解説します。

## 25.1. 仮想暦モデルの基本ルール

シミュレーションの計算負荷の軽減と、カレンダー表示の簡素化のため、ゲーム内では現実の暦とは異なる**仮想暦モデル**を採用しています。

- **1年 = 12ヶ月 = 360日**
- **1ヶ月 = 30日**（固定）
- **基準日（経過日数 0） = 1800年1月1日**

現実の暦に存在する「うるう年」や「月による日数のばらつき（28日〜31日）」、「うるう秒」などはゲーム内には存在しません。すべての月は完全に30日間で構成され、360日経過すると1年が進むシンプルな構造となっています。

### 開始日

新規に都市を開始した時点のゲーム内日付は **2029年4月1日**（経過日数 82530）で固定です。開始日は必ず「月の1日」であり、`simulation_days` が 30 の場合は以降のすべてのエポックも月初（1日）に揃います。

## 25.2. エポック処理と日付の進行

本ゲームでは、ユーザーが「エポック実行」を確定した段階でシミュレーション（1エポック）が実行され、時間が進みます。

- **1エポックあたりの経過日数 (`simulation_days`)**
  - 標準設定では **30日** です。
  - エポックが実行されると、現在のゲーム内日付に対して `simulation_days` 分の日数が進みます。
  - `simulation_days` が 30 の場合、1エポックの実行ごとにゲーム内日付は常に翌月の同日（1ヶ月後）に進みます（例：`2026年10月1日` → `2026年11月1日`）。

## 25.3. UIおよびグラフィックにおける日付表示

フロントエンドおよびグラフィックモジュールは、バックエンドから送信される「基準日からの経過日数 (Days since Epoch)」を元にゲーム内日付を計算して描画します。

### 日付の省略表示（年月表示）

一部のUI（予算管理ウィンドウなど、1エポック単位での予算や実績の計画を扱う画面）においては、情報整理のために日付の「日」部分を省略して「年・月」のみで表示する設計をサポートしています。

- **省略可能条件**: 1エポックあたりのシミュレーション日数 (`simulation_days`) が **30日** の場合に限り、日付（日）の表示を省略できます（例：`2026年10月1日` を `2026年10月` と表示）。
