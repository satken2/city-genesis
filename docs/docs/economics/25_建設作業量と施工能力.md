# 建設作業量と施工能力

建物・道路・線路は同じ建設サービス作業単位を調達する。`construction_volume_required/acquired`は必要作業量と取得済み作業量を表し、物理的なコンクリートの体積ではない。1単位は建設サービス財1単位で、費用は調達量×市場単価。単価が変われば同じ作業量でも費用は変わる。

## 作業量と現場規模

必要作業量は、建物では延床面積に階数・地形・構造等の作業補正、パスでは延長×幅×路盤厚に種別・高低差の補正と土工量を加えた値である。これらはそれぞれの形状を共通のサービス単位へ換算する式であり、工期倍率ではない。

施工能力の入力は難易度を含まない作業面積。建物は延床面積（躯体・内装など複数階の並行作業をまとめた有効作業面積）、パスはアンカーを結ぶ平面延長×幅とする。延床面積すべてを同時に施工する厳密な工程モデルではなく、面積の指数で並列作業の効率低下を表す近似である。造り替えは変更先の幅を使う。

```text
日次施工能力 = CONSTRUCTION_WORK_RATE × (作業面積 / CONSTRUCTION_REFERENCE_WORK_AREA)^CONSTRUCTION_AREA_EXPONENT
標準工期(日) = max(1, 必要作業量 / 日次施工能力)
当期発注量 = min(残作業量, 日次施工能力 × エポック日数 × 施工速度目標)
```

| 共通パラメーター | 初期値 | 単位 |
|---|---:|---|
| CONSTRUCTION_WORK_RATE | 15 | 基準現場の作業単位/日 |
| CONSTRUCTION_REFERENCE_WORK_AREA | 3600 | m² |
| CONSTRUCTION_AREA_EXPONENT | 0.7 | 無次元 |

平地の通常道路（路盤厚0.5、費用係数1）について旧標準工期を維持する初期値。高架・地下専用の工期分岐はない。同じ作業面積で難易度が増えれば作業量だけが増え、月の施工枠は増えない。費用係数を工期調整のためだけに変更すると費用も連動するため、能力の調整には上の共通パラメーターを使う。

## 調達と完成

施工枠は自動的に完成へ加算される量ではない。実際の予算・資金・市場供給の制約を受けて調達できた分だけ進捗し、累積取得量が必要量に達すると完成する。最終発注は残作業量で制限し、速度目標を掛けた後でも過剰発注しない。修繕・解体も同じ能力式を使い、対象作業量が小さい分だけ期間が短い。

建物・道路の費用プレビュー、予算行、次期需要推定、市場移管が同じ入力を使う。Unityの橋脚・桁の表示閾値は工期計算に関与しない。

設定の正本はGoogle Sheetsのgeneral_paramsタブ。生成されたgeneral_params.yamlは直接編集しない。
