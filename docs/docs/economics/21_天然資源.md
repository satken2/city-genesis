# 21. 天然資源

## 21.1. 天然資源とは

天然資源（`Resource`）は、マップ上に配置された鉱脈・油田・水源などの埋蔵資源である。それぞれが固有のポリゴン領域を持ち、その領域内の土地区画（[[4_地区と土地区画]]）に立地する[[2_経済主体]]に対して、特定の物資（`product_id`）を提供する。

各天然資源は、以下の性質を持つ。

- **資源種別**（`resource_type`）: 鉱脈・油田などの分類。マスタデータ（`resource_master`）で定義される。
- **提供物資**（`product_id`）: この資源が提供する商品のID。資源種別ごとに一意に定まる。
- **埋蔵量**（`current_amount`）: 現在の残りの資源量。
- **埋蔵量上限**（`max_amount`）: 資源量が回復する際の上限値。
- **回復率**（`recovery_rate`）: 埋蔵量上限（`max_amount`）に対する1日あたりの回復割合。例えば `0.01` なら「1日で上限の1%が回復する」を意味する。1エポックでの回復量は `recovery_rate × max_amount × simulation_days` となる（エポックの長さに比例する）。`0.0` は回復しない非再生資源（鉱脈・油田など）を表す。

## 21.2. 土地区画との紐づけ

天然資源はポリゴンで表現された領域を持つ。土地区画が作成された時、およびその形状が変更された時に、区画のポリゴンと重複する天然資源が区画に紐づけられる。

紐づけの結果は、土地区画の `resource_id` に資源種別と資源IDの対応として格納される。複数の異なる種類の天然資源が同一の区画と重なっている場合、すべての種別が含まれる。同じ種別の資源が複数重なっている場合は、いずれか一つが優先される。

## 21.3. 物資の分配

エポックの処理の中で、天然資源から経済主体への物資分配が行われる。

### 分配の対象

天然資源に紐づく土地区画に立地する経済主体のうち、その天然資源が提供する物資に対する需要（`demand_amount`）を持つものが分配の対象となる。需要は、[[2_経済主体]]の生産計画において、生産に必要な原材料として計上された時に生じる。需要を持たない経済主体には何も提供されない。

### 分配量の決定

ある天然資源について、対象となる全経済主体の需要の合計が、その資源の現在の埋蔵量（`current_amount`）を超える場合がある。この場合は、需要の比率に応じて按分する。すなわち、需要の大きい経済主体ほど多くの物資を受け取るが、誰もが需要を満たせるわけではない。

埋蔵量が十分にある場合は、すべての需要が満たされる。

分配された物資は、各経済主体の調達済み量（`remain_amount`）と獲得量（`received_amount`）に加算される。これにより、経済主体は市場を通さずに直接、天然資源から原材料を調達したことになる。

## 21.4. 埋蔵量の消費と回復

### 消費

物資の分配が行われた分だけ、天然資源の埋蔵量（`current_amount`）が減少する。埋蔵量がゼロに達した天然資源はそれ以上物資を提供できず、その資源に依存する経済主体は原材料を調達できなくなる。

### 回復

消費の処理が終わった後、すべての天然資源はエポックごとに回復率（`recovery_rate`）に従って埋蔵量が回復する。回復率は埋蔵量上限に対する1日あたりの回復割合として定義されているため、1エポックの回復量はエポックの長さ（`simulation_days`）に比例して `recovery_rate × max_amount × simulation_days` となる。ただし、回復後の埋蔵量が埋蔵量上限（`max_amount`）を超えることはない。回復率は資源ごとに定数として設定されており、枯渇した資源も時間とともに徐々に回復する（`recovery_rate=0.0` の資源は回復せず、採取した分だけ枯渇していく非再生資源となる）。

回復によって完全に枯渇から脱することはできるが、過剰な採取が続く限り埋蔵量は低水準に留まる。この埋蔵量の低下は、次節の立地倍率を通じて生産効率に影響を及ぼす。

## 21.5. 天然資源と立地倍率

天然資源は、物資の分配とは別に、土地区画の立地倍率（`agent_multiplier`）を通じても経済に影響を与える。立地倍率の詳細については[[4_地区と土地区画]]を参照のこと。

**天然資源を原材料に持つ variant** の立地倍率は、天然資源の残量率（`current_amount / max_amount`）に基づいて計算される。残量率が一定の閾値を下回ると、効率が急激に低下する。天然資源に紐づかない土地区画では立地倍率が `0.0` となり、その区画での生産が不可能になる。

つまり、埋蔵量の低下は二重の影響を及ぼす。まず物資の分配量が減ることで直接的な原材料不足が生じ、同時に立地倍率の低下を通じて生産効率も悪化する。

この補正は、採取したものを何として供給するかに依らない。原油や鉱石のように工業原料として市場へ出す施設も、高圧水道やパイプライン原油のようにインフラ財として専用網へ送り出す施設（取水施設・洋上石油プラットフォーム。[[26_インフラ網]]）も、同じ条件で資源の上にしか成立せず、同じように枯渇で効率が落ちる。逆に、天然資源を原材料に持たない施設はこの補正を受けない。海水淡水化プラントは高圧水道を供給するが、投入は電力だけで水資源を使わないため、水源のない沿岸区画にも建てられ、枯渇の影響も受けない（電力の確保が代わりの制約になる）。

## 21.6. 埋蔵量・採取量の履歴（データモデル）

天然資源は、エポックごとの**埋蔵量（残量）**と**採取量（消費量）**を時系列の履歴として保持する。これらは外部から API で観測できる。

- `current_amount`: 各エポック終了時点の残量のスナップショット列。回復後の値が記録される。
- `consumption_amount`: 各エポックに経済主体へ分配された採取量の列。

`GET /api/v1/resources/{resource_id}` がこれらを新しい順（直近のエポックが先頭）のリストとして返す。履歴は過去一定エポック分が保持され、それを超えると古いものから上書きされる。なお `GET /api/v1/resources`（一覧）が返す残量は履歴ではなく、その時点の現在残量（単一値）である。

## 21.7. 天然資源エリアの新規作成

`POST /api/v1/resources` により、任意のポリゴン形状を持つ天然資源エリアを新規作成できる。テンプレート作成モード（`template_mode`）専用の機能で、通常プレイ中は403エラーとなる。

作成時には `polygon`（3点以上の座標列）・`resource_type`（`resource_master` に定義された種別）・`max_amount`（埋蔵量上限）が必須で、`recovery_rate` は任意（未指定時は `0.0`＝非再生資源）。作成直後の埋蔵量（`current_amount`）は `max_amount` と同値（満タン）で初期化される。

Unity(グラフィック)側の編集ステート（`STATE_EDIT_RESOURCE`）との連携は [プログラム間連携（IPC）](../programs/IPC連携の整理.md) を参照。

## 21.8. シナリオの初期配置

天然資源の初期配置はシナリオが持つ。取り込む標高ファイル（シナリオの素材になる標高データ）は資源を持たないので、取り込んだばかりのシナリオには資源が無い。シナリオの作者は、前節のテンプレート作成モードでの資源編集で資源エリアを置く。置いた資源は天然資源として都市に入り、シナリオに保存される。シナリオ管理から開く地形エディタは資源を編集しないが、地形を保存しても資源はそのまま残る。

シナリオから都市を始めると、シナリオの資源がそのまま都市の初期賦存になる。以後の埋蔵量の増減はセーブデータに保存され、シナリオを後から編集しても、すでに始めた都市へは反映されない。

シナリオの地形APIで既存の資源の埋蔵量上限を変えて保存したときは、残量の割合を保つ（満タンの資源は満タンのまま）。新しく置いた資源の埋蔵量は満タンで始まる。データ形式は [D. 地形形状](../geometries/D_地形形状.md) の §D.12 と §D.14.3 を参照。

## 21.9. 埋蔵量と回復率の目安

`max_amount` と `recovery_rate` は、現実の資源の量と速さに対応づけて決めると桁を外さない。本節はその対応と目安の値をまとめる。

### 数量の単位

採取施設は資源1単位から産出物1単位を作る（`agent_master` の `materials` における天然資源の係数が 1.0）。したがって資源の量は、採取施設の産出物の単位で数えることになる。石油資源の1単位は原油1バレル、水資源の1単位は高圧水道1KL（＝1m³）、鉱石資源の1単位は鉱石1kgである。

### 1エポックに採れる量と持続採取量

分配は回復より先に行われる（§21.4）ため、1エポックに採取できるのは、そのエポック開始時点の埋蔵量まで（最大でも `max_amount`）である。回復は1日あたり `recovery_rate × max_amount` で、1エポックの回復量も上限で打ち切られる。そのため、残量を減らさずに採り続けられる1日あたりの量（持続採取量）は次のとおりになる。

```
持続採取量（1日あたり） = min(recovery_rate × max_amount, max_amount ÷ simulation_days)
```

回復率を 1 ÷ `simulation_days` より大きくしても、1エポックに採れる量は上限で頭打ちになり、持続採取量は増えない。たとえば河川の上限を1日分の流量にして回復率を 1.0 にすると、30日のエポックで1日分しか採れない。

これを踏まえ、資源は次の3つの型に分けて値を決める。

| 型 | 例 | `max_amount` | `recovery_rate` |
| --- | --- | --- | --- |
| 非再生型 | 油田・鉱床 | 可採埋蔵量 | 0 |
| 流量型 | 河川 | 1日に取水できる量 × エポック長（30日） | 1 ÷ エポック長（約 0.0334） |
| 貯留型 | 湖沼・ダム湖・地下水 | 利用できる貯留量 | 1日の流入量（涵養量）÷ 貯留量 |

流量型は1エポックに流れてくる分だけを採れ、使った分は次のエポックまでに満タンへ戻るので、採り過ぎても残量率は下がらない（不足は分配量の不足として現れる）。貯留型は流入や涵養を超えて採ると貯留が減っていき、残量率が閾値（既定では3割）を下回ると採取効率が急激に落ちる（§21.5）。

### 現実の規模と目安の値

面積に比例する資源は1m²あたりの量で示す（1m²あたり1 は 1km²あたり100万にあたる）。

| 資源 | 現実の幅 | 目安 |
| --- | --- | --- |
| 油田（在来型） | 可採埋蔵量は層厚・孔隙率・回収率で決まり、1m²あたり1〜20バレル程度。大油田の東テキサス油田は約570km²から累計50億バレル超を産出した（1m²あたり約9バレル） | 1m²あたり5バレル、回復率 0 |
| 鉱床（露天掘り） | 採掘深さ（数十〜百数十m）× 比重（2.5〜3.5）で、1m²あたり数十〜数百t | 1m²あたり200t（採掘深75m × 比重2.7）＝ 200,000kg、回復率 0 |
| 河川 | 取水できる量は小河川で1日数千〜数万m³、中規模河川で数十万m³、大河川で数百万m³（流量1m³/秒 ＝ 1日86,400m³）。河川の維持流量を残す必要があるため、取水できるのは流量の一部に限られる | 1日10万m³（約1.2m³/秒）→ 上限300万、回復率 0.0334 |
| 湖沼・ダム湖 | 利用できる水深は天然湖で1〜3m、ダム湖で10〜40m。流入による入れ替わりは数か月〜数年 | 1m²あたり5m³、回復率 0.01（空から満水まで100日） |
| 地下水 | 利用できる貯留は比産出率（砂礫で0.1〜0.3）× 帯水層の厚さ（10〜50m）で1m²あたり1〜15m³。雨水の涵養は湿潤な平野で年数百mm、乾燥地で年数十mm以下 | 1m²あたり5m³、回復率 0.0002（涵養1日1mm ＝ 年365mm。空から満水まで約14年） |

地下水の持続採取量は1km²あたり1日1,000m³にとどまり、広い帯水層でも大都市の需要は賄えない。汲み過ぎた帯水層は満水に戻るまで十年以上かかる。一方で河川は面積ではなく流量で決まるため、河川の資源エリアの広さは埋蔵量に関係しない。

## 21.10. 露天掘りによる地形の変化

露天掘り（`model_type` が `MODEL_OPEN_PIT`）の施設は、鉱脈などの固体の天然資源を採った分だけ、立地する土地区画の地形を掘り下げる。鉱山（1022）がこれにあたる。

- **掘る体積**: そのエポックに天然資源から分配された鉱石資源・レアメタル資源の質量を、岩の比重（2.7t/m³。§21.9 の鉱床の目安と同じ値）で割った体積。
- **掘る場所**: 土地区画の接道辺から `OPEN_PIT_YARD_DEPTH`（40m）までは設備を並べる前庭で、掘らない。その奥を、区画の境界・前庭・設備・区画にかかるパス（トンネル・送電線などを含む）から一定の余白を残して掘る。隣の区画や道路の地形は変わらない。
- **穴の形**: 掘削範囲の縁から内側へ、高さ10mごとの段（平場と急な法面）を刻んで下る。段の高さは縁のすぐ外側の最も高い地面から数えるので、平地では段々の穴になり、斜面では山側を段々に切り崩した形になる。底は海面より上で止まる（海面より深い穴は掘らない）。
- **進み方**: この最終形を上から水平に削る形で掘り進める。はじめは掘削範囲の全体が浅く削られ、深くなるにつれて縁に段が現れる。最終形を掘り終えると地形はそれ以上変わらず、採掘だけが続く。
- **残るもの**: 地形の書き換えはセーブデータに残る。施設が閉鎖・解体されても穴は埋め戻されない。

地形の書き換えは他の造成と同じ経路で公開されるので、Unity はエポック後の再取得で変わった地形セルを取り直して穴を描く。穴の描画と前庭の設備は [F11. 露天掘りのメッシュ生成](../geometries/F11_露天掘りのメッシュ生成.md) を参照。
