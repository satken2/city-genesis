# 29. 駅と駅舎

複数の駅パス(プラットフォーム)を1つの「駅」として束ねる仕組みと、その駅舎について。

## 29.1 概要

プラットフォームは駅パス([[6_公共交通機関]] 6.4)として表現され、経路探索・停留所の設置・建設ライフサイクルはすべてパスの仕組みで完結する。一方で、プレイヤーが「1つの駅」と認識する単位はパスと一致しない。複線の駅では上下線のホームが別々のパスであり、既存の駅を延長・分割すれば1つのホームが複数のパスに分かれる。

この乖離を埋めるのが**駅**(Station)である。駅は近接する駅パス群を束ねる論理的な単位で、以下を持つ。

| 概念 | 実体 | 持つもの |
| --- | --- | --- |
| ホーム(駅パス) | パス | 停留所ノード・編成長制約・建設/老朽化のライフサイクル([[6_公共交通機関]]) |
| 駅 | 駅エンティティ | 駅名・駅舎・駅単位の統計 |
| 駅舎 | 駅の属性 | 設置位置・向き。グラフィック上の建屋として描画される |

駅は経済主体ではなく、市場・会計には一切参加しない。駅の追加・削除をプレイヤーが直接操作することもない(次節)。

## 29.2 駅の自動管理

駅はプレイヤーの明示操作ではなく、駅パスの敷設に応じて自動で管理される。

- **自動作成・自動編入**: 駅パスを敷設すると、既存の駅のホームに近接(中心線間の最短距離が30m以内)していればその駅に編入され、どの駅にも近接していなければ新しい駅が自動作成される(駅名は自動命名され、後から変更できる)。複線の上下線ホームや島式ホームは、この近接判定によって自然に1つの駅にまとまる。
- **統合**: 新しいホームが複数の既存駅の両方に近接した場合(駅どうしを橋渡しした場合)、それらの駅は物理的にひとつながりになったとみなされ、最寄りの駅へ統合される(駅名・駅舎は統合先のものが残る)。
- **分割への追従**: 交差点の発生などで駅パスが2本に分割されても、両方のパスは同じ駅に属したままになる。
- **自動消滅**: 所属するホームがすべて取り壊し等で失われると、駅は駅舎ごと自動的に消滅する。
- **造り替えとの関係**: パスの造り替え([[3_道路網]])で駅パスバリアントへ変更されたパスは駅に編入され、駅パスでないバリアントへ変更されたパスは駅から外れる。

## 29.3 駅舎

駅舎は駅のグラフィック上の現れとなる建屋である。建物経済主体でも土地区画でもなく、駅の属性(設置位置・向き・モデル)として表現される。駅舎はプレイヤーが明示的に設置するもので、駅の自動作成に伴って自動設置されることはない。駅舎の無い駅パスには「駅舎がありません」というアラートが立ち、プレイヤーが把握できる([[アラートフラグ管理]])。

- 駅ごとに駅舎は最大1つで、設置は任意である。駅舎のない駅は「野ざらしの停留場」として機能上は完全に有効である。
- 駅舎はホーム(所属する駅パスの中心線)から100m以内にのみ設置できる。
- 駅舎のモデル(見た目)はプレイヤーが駅舎カタログ(`house_variant`)から手動で選んで設置する。プラットフォームの規格から自動導出されることはない。

### 土地占有と収用

駅舎はフットプリント(設置位置・向き・モデル別寸法から決まる矩形)ぶんの土地を占有する。これは土地区画・パスに次ぐ第三の占有ソースであり、区画作成やパス着工の干渉判定に参照される(駅舎の上に区画・建物は作れず、地表を走るパスは駅舎を避けて着工する。高架・地下で上空/地下を通過するパスは駅舎と干渉しない)。

駅舎の設置は、通常のパスや建物と同じ収用フローを伴う。

- フットプリントに重なる市有の空き地・更地はその場で収用(撤去)される。
- フットプリントに重なる稼働中などの建物は、市政府が買収して取り壊しに着手する。取り壊しはエポックをまたいで進行する。
- 用地に取り壊し中の建物が残る間、駅舎は**設置予定**(用地の更地化待ち)の状態になり、まだ描画されない。用地が更地になった時点で駅舎の設置が確定し、描画される(駅舎には「建設」の概念はなく、更地化=即設置)。
- 駅舎は道路・他の線路と重なる位置には設置できない(所属ホーム自身との重なりは、ホーム直近に建てるため許容される)。

## 29.4 データモデル

駅の一覧・詳細は API(`GET /api/v1/stations` および `.../stations/{id}`)から取得する。一覧は `?bbox=x1,z1,x2,z2` で駅の中心点による範囲絞り込みができる。駅名と駅舎は `PATCH /api/v1/stations/{id}` で更新できる。駅舎モデルのカタログ(選択肢・寸法)は `GET /api/v1/master/station_houses` から取得する。

| 対象 | プロパティ | 内容 |
| --- | --- | --- |
| 駅パス | `station_id` | 所属する駅のID。駅パス以外のパスはnull相当 |
| 駅 | `station_id` | 駅のID(都市内で一意。削除後も再利用されない) |
| 駅 | `name` | 駅名(自動命名され、プレイヤーが変更できる) |
| 駅 | `version` | 見た目の更新版数。駅名・駅舎・所属ホーム構成が変わるたびに増える |
| 駅 | `center_point` | 駅の中心点 [x, z](所属ホームの中心点の平均) |
| 駅 | `house` | 駅舎の設置情報 `{position: [x, z], rotation}`。**設置が確定した**駅舎だけが非null。未設置・設置予定(用地の更地化待ち)は null。PATCHで `house_position` に [x, z]・`house_rotation`・`house_variant` を渡して設置/移設、`house_position` に null を渡して撤去する |
| 駅 | `house_variant` | 駅舎モデル(`station_house_master` のID)。プレイヤーが手動で選択して設置する。未設置は null |
| 駅 | `house_pending` | 駅舎の設置予定フラグ。フットプリントに重なる建物の買収・取り壊し(収用)が完了しておらず、まだ更地になっていない間 true。更地化が完了すると false になり `house` が設置情報を返す |
| 駅 | `paths` | 所属ホームの一覧(`path_id` / `path_variant` / `status` / `length` / `platform_side`) |
| 駅 | `lines` | この駅に停留所を持つ路線の一覧(`line_agent_id` / `name` / `status`) |
| 駅 | `ridership` | 駅単位の乗降統計(路線の乗車回数から求めた近似値) |

どのパスバリアントが駅パスかは、パスマスターの `platform_width` が設定されているかどうかで決まる(プラットフォームの描画([N_線路メッシュの生成](../geometries/N_線路メッシュの生成.md) §7)と同じ条件)。
