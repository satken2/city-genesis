# 24. 達成クエスト

達成クエストは、シナリオやチュートリアルがプレイヤーに示す目標である。判定条件はコードに書かず、都市の値を読む条件の組み合わせ(データ)で表すので、シナリオ制作者は到達・維持・期限・連鎖・隠しなどの目標を神モードのエディタで自由に作れる。判定はコアが行う。表示と通知は[達成目標ウィンドウ](../programs/達成目標ウィンドウ.md)を参照。

## 24.1. クエストの項目

名前と説明は多言語テキストで、表示言語の文が無ければ英語の文を出すので英語が必須である。クエストは先行クエストがすべて達成されるまで解放されず、期限を過ぎても未達成なら失敗になる。期限はエポック番号(`deadline_epoch`)か、解放からのエポック数(`deadline_within`)で決める。強制完了型(`is_force_completable`)のクエストは条件で判定せず、強制完了の API でだけ達成する。報酬の交付金は、達成時に一度だけ都市外からの交付金として市政府の現預金に入り、都市のお金の総量を増やす([7_金融システム](7_金融システム.md))。

クエストの作成・更新・削除は神モードでだけでき、コアは名前と説明に英語があるか以外を検査しないので、条件の形はエディタの側で正しく保つ。

## 24.2. 判定条件の3層構造

判定条件は「どの値を読むか」「いつと比べるか」「どう組み合わせるか」の3層で表す。値は都市オブジェクトの数値を `budgets.<カテゴリID>` のようなドット区切りのパスで指し、現在の値のほか、前のエポックからの変化や条件を満たし続けたエポック数などを、定数か別の値と比べる。比較は論理演算で入れ子に組み合わせる。比べるための履歴は、クエストが条件ごとに持つ。

読めない値があって真偽が決まらないときは、状態を変えない。

## 24.3. 状態と判定のタイミング

| `status` | 意味 |
| --- | --- |
| `locked` | 先行クエストの達成待ち。判定しない |
| `active` | 判定の対象。期限を過ぎると `failed` になる |
| `completed` | 達成。`latch` が真なら以後変わらず、偽なら条件を満たさなくなると `active` に戻る |
| `failed` | 期限切れ。以後変わらない |

判定はエポックの実行後と `GET /api/v1/quests` の取得時に行う。エポックで新たに達成・失敗したクエストは `POST /api/v1/epochs` の応答で返り、複数のエポックをまとめて実行したときは全エポックの分をまとめて返す。取得時の判定ではエポックが進んでいないので、比べるための履歴は増えない。

## 24.4. シナリオのクリアとプレイヤーの記録

シナリオとチュートリアルは、クエストが1件以上あり、そのすべてが `completed` になったときにクリアとなる(神モードは対象外)。都市は始めたシナリオとクリア済みかどうかをセーブに持ち([セーブデータ仕様](../programs/セーブデータ仕様.md))、クリアの記録は後でクエストが `active` に戻っても取り消さない。

クリアしたシナリオとチュートリアルのIDは、都市とは別のプレイヤーのプロフィールにも記録され、`GET /api/v1/profile` で読める。プロフィールはどのセーブでも共通で、セーブを消しても残る。保存ファイル(`profile.bin`。[ファイル配置](../programs/ファイル配置.md))は暗号化されており、書き換えたファイルや平文のファイルは記録の無い初期値として読む。
