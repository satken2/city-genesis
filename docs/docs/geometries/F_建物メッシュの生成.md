# 建物メッシュの生成

全建物のFarは、共通のprefix解決で選ばれたフォルダの閾値0から `base/mid/top-prebuilt_far` を探し、存在する場合は既成建物と同じ規則で組み立てる。名所・通常の用途・構造種別で経路を分けない。通常のmodel_typeがモジュラー等でも遠景は完成モデルで提供できる。敷地装飾は省略し、遠景用パーツが1つも無い場合は簡易形状へ戻る。工事・解体・倒壊状態は専用の簡易形状を使う。モデル構成は [[F3_既成建物のメッシュ生成]] を参照。

`MODEL_PARKING=10` / `MODEL_ROTARY=11` / `MODEL_PARK=12` は `OpenSpaceBuildingMeshBuilder` が区画内の配置計画から面と実寸装飾を組み立てる。底面はSHAPE_FULL、接地は中心位置の地形標高。`site_*` パーツは独立した閾値走査で解決し、`mid-w1` は不要。遠景モデル未提供時のFarは0.3m板。3003舗装広場はGROUNDでfloorのみを描く。詳細は [[F10_オープンスペースのメッシュ生成]]。

`MODEL_OPEN_PIT=13`（露天掘り）は、コアシミュレータが区画の奥を掘り下げた地形そのものを穴とし、接道側の前庭に並ぶ設備だけをマッシュアップ建物と同じ規則で組み立てる。中心位置の高さに置く形は穴に蓋をするので、遠景は描かず、コライダー・工事中・倒壊の表現もマッシュアップ建物と異なる。詳細は [[F11_露天掘りのメッシュ生成]]。

## 概要

バックエンドの Agent データから、建物の外装メッシュを組み立てて配置する仕様。

建物の3Dモデル生成方法は、`agent_master` に定義された **`model_type`** によって分かれる。`model_type` は3Dモデルの組み立て方式を表すものであり、建物の底面ポリゴンの形状（[[C_建物形状]]）とは全く別軸の話である。

本ドキュメントには**すべての生成方式に共通する仕様**（データフロー、底面形状、パーツの命名規則とフォールバック、壁・角の配置、地面パネル・基盤・フェンス、塔屋・エントランス、結合とコライダー）を記述する。方式ごとの固有ロジックは別ドキュメントに分ける。

| model_type               | 生成方式                   | 詳細                                                                                                                      |
| ------------------------ | ---------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| **MODEL_MODULAR_FLAT**   | モジュラーパーツ組み立て + 平屋根     | [[F1_モジュラー建物のメッシュ生成]] §1                                                                                                |
| **MODEL_MODULAR_HOUSE**  | モジュラーパーツ組み立て + 住宅風三角屋根 | [[F1_モジュラー建物のメッシュ生成]] §2                                                                                                |
| **MODEL_MODULAR_GABLE**  | モジュラーパーツ組み立て + 切妻屋根    | [[F1_モジュラー建物のメッシュ生成]] §3                                                                                                |
| **MODEL_MODULAR_SHED**   | モジュラーパーツ組み立て + 片流れ屋根   | [[F1_モジュラー建物のメッシュ生成]] §4。粗末な小屋・仮設物置など、トタン板1枚を一方向に傾けた粗末な屋根の建物用                                                       |
| **MODEL_MODULAR_GROUND** | モジュラーパーツ組み立て（地面用途）     | [[F2_地面アセットのメッシュ生成]]。建物本体は描画せず、フェンス・地面パネル・タイルオブジェクトを土地区画の形状に沿って配置する                                                     |
| **MODEL_PREBUILT**       | 既成パーツ組み立て              | [[F3_既成建物のメッシュ生成]]。電波塔やオブジェ、銅像、観覧車など、通常の建物とは全く異なる形状の建物に適用する                                                             |
| **MODEL_PORT**           | 厚みのある板（岸壁）をプロシージャル生成し、水際・道路側・ヤードに実寸パーツを配置 | [[F4_港湾岸壁のメッシュ生成]]。海岸土地区画（PARCEL_SHORE）の港用。モジュラーの壁・角パーツは使わない                                            |
| **MODEL_MASHUP**         | 複数のサブ建物を既成パーツで配置       | [[F6_マッシュアップ建物のメッシュ生成]]。学校（校舎＋体育館）のような複数棟の複合施設用。バックエンドが土地区画を8m×8mセルに分割して決めた配置計画（`sub_buildings`）に従い、各棟を既成パーツと同じ規則で積み上げる |
| **MODEL_OPEN_PIT**       | 前庭の設備を既成パーツで配置（穴は地形） | [[F11_露天掘りのメッシュ生成]]。鉱山用。区画の奥はコアシミュレータが掘り下げた地形で、設備は `sub_buildings` としてマッシュアップ建物と同じ規則で組み立てる |
| **MODEL_RAIL_YARD**      | 線路ユニットをプロシージャル配置       | [[F9_車両基地のメッシュ生成]]。鉄道車両基地用。並行線路・架線・車止め・検修庫を敷地に並べ、集約線路を接続端子ノード（`depot_node_id`）の位置へ曲線で収束させる |

model_type とは別軸で、status が `STATUS_CONSTRUCTING` の建物はすべて「工事現場」メッシュに差し替わる（[[F5_工事中建物のメッシュ生成]]）。分岐は model_type 分岐より先にある。

## 描画LODと生成物の寿命

建物の描画LODは投影サイズとヒステリシスで選ぶ。生成済みClose / Normal / FarのGOをLRUへ退避して再利用する。再利用キーには形状・外観・建設状態・区画・接地先の地形版を含める。セル離脱時も建物GOは破棄せず退避し、再入場時にキーで復元する。

BuildingManagerは対応するモジュラー建物とprebuiltの敷地装飾を `BuildingExteriorRenderer` の後続ジョブへ分離する。本体を先に表示し、地面・フェンスなどを共通予算で生成する。地面用途・特殊施設の専用生成は従来の経路を使う。生成した外構Meshは独立所有し、退避からの復帰では未完了ジョブを再開する。敷地装飾のジョブは建物GOではなく共通のホスト(`BuildingExteriorWork`)で実行し、建物GOの無効化(退避)で止める。地形変更時は版付きキーで更新するため、本体まで含むキャッシュの無効化が起きる。

Far建物は256m区画・親・マテリアル別に最大64個を結合する。元のID付きオブジェクトは残し、Rendererだけを抑止する。削除や変化を受けた建物を含む集約だけを直ちに解除し、再結合までは個別描画へ戻す。専用MaterialPropertyBlockを持つものは結合対象外。遠景は共有マテリアル1つで描くので、複数サブメッシュを持つ遠景メッシュ(prebuilt_far)は生成時に単一サブメッシュへ畳む。

詳細建物の Z-fighting 防止用 `DepthOffsetLit` マテリアルは、元マテリアルごとに1つを全建物で共有する。建物ごとの色替えは `VisualModeObject` のマテリアル差し替えとプロパティブロックで行うので、建物レンダラーのマテリアルを個別に書き換えない。

地面パネルは地形へ追従するメッシュ方式を使う。高さの正を別途複製せず、実Terrainサンプルを使う。生成MeshとColliderの所有・解放は `RenderCacheIdentity` が担い、共有FBXは破棄しない。詳細は [E_LOD処理](E_LOD処理.md)。

## 2. 底面形状

### 2.1 polygon データ

バックエンドの Agent データに含まれる `polygon` を使用する。
これは `float[][]`（頂点の配列）で、各頂点は Agent の `center_point` からの相対座標 `[x, y]` である。

### 2.2 頂点の並び順と縮退頂点の間引き

polygon の頂点は **反時計回り（CCW）** に正規化する。
符号付き面積が負の場合は配列を反転させる。

バックエンドのポリゴンは「閉じた輪」の契約（[[B_土地形状]]）であり、末尾=先頭の閉環重複点や、
ほぼ一直線上に並ぶ中間頂点を含むことがある（区画全面を使う建物では底面=土地区画ポリゴンなので、
建物の polygon にも同じ縮退が入る）。壁・角は1頂点=1角パーツで配置するため、縮退頂点を
そのまま使うと角パーツの向き・ボーン変形が破綻する（ゼロ長辺では内角が求まらず角がX字に折れ、
内角180°付近では角が開ききって壁の線を横切る）。そのため、ポリゴンの取り込み時に
**頂点の間引き**を行う。

- 縮退辺（辺長 0.01m 未満。閉環重複点を含む）の頂点を除去する
- 共線頂点を除去する。判定は「最後に残した頂点からの方向」と「次辺の方向」の差が 5° 未満
  （各頂点単独の方向変化で判定すると、緩いカーブ上に並ぶ頂点が全滅して弧が弦に潰れるため、
  累積の方向変化が閾値を超えた時点で頂点を残す）
- 間引き後も**元の頂点順を保つ**（頂点0=前面の辺の規約（§10.3・§11.2）と壁・角の位置番号を守るため）
- 間引き後に3頂点未満になった場合は間引きを適用しない（建物底面）／ポリゴンなしとして扱う（土地区画）

この間引きは建物底面（`GetFootprint`）と土地区画（`ResolveParcelContext`）の両方の取り込みで行われる。

### 2.3 壁・角の番号付け

底面ポリゴンの頂点インデックスをそのまま壁・角の位置番号に対応させる。
頂点 0 = 位置 1、頂点 1 = 位置 2、… とする。

N辺ポリゴンのとき：

| 位置番号 | 壁（辺） | 角（頂点） |
|---|---|---|
| 1 | 辺 0（頂点0 → 頂点1） | 頂点 0 |
| 2 | 辺 1（頂点1 → 頂点2） | 頂点 1 |
| 3 | 辺 2（頂点2 → 頂点3） | 頂点 2 |
| … | … | … |

壁の位置 n に対応する辺は `edge_index = n − 1`。
角の位置 n に対応する頂点は `vertex_index = n − 1`。

### 2.4 ワールド配置

生成されたメッシュの頂点座標はすべて `center_point` 基準の相対座標とする。
配置時に `center_point` のワールド座標と接地高を足して最終位置とする。

接地高（建物の接地面の標高）は model_type によらず **`center_point` 位置の地形標高**である。

- MODEL_MODULAR_FLAT / HOUSE / GABLE / SHED は傾斜地でも建物が水平面に接地し、谷側にできる地形との隙間は基盤（§8.2）が埋める。
- MODEL_MASHUP では、さらに各サブ建物が自分の配置座標の地形標高へ個別に接地する（[[F6_マッシュアップ建物のメッシュ生成]] §4）。
- MODEL_OPEN_PIT も各設備が個別に接地する。中心位置は掘った穴の中にあるので、建物のGameObjectは穴の底の高さに置かれる（[[F11_露天掘りのメッシュ生成]] §4）。

土地区画の基準標高（`parcel.altitude`）は接道の路面標高（接道なしは区画中心の地形標高）を表す値で（[[B_土地形状]] B.2）、陸上の建物の接地には使わない。建物は区画を参照せずに接地高が決まるので、区画を持たない一括取得のデータでもプレビューでも同じ高さに置かれる。

ただし**海上区画（`PARCEL_WATER`）に立地する建物は、model_type によらず区画の基準標高（`parcel.altitude`）を使う**。海上区画の基準標高は海面の `0.0`（[[B_土地形状]] B.5）であるのに対し、その地点の地形標高は海底（ワールドYが負）なので、地形を参照すると洋上風力発電所などが海面下へ沈んでしまう。一括取得の建物データは区画IDを持たないため、中心の地形標高が海面より低い建物だけ、中心点を含む区画を座標から引いて海上区画かどうかを判定する。

区画自身の上面メッシュも同じ基準で置く。陸地では頂点ごとに地形標高をサンプルして起伏に沿わせるが、海上区画では全頂点が基準標高の水平面に載る。さらに海面板はワールドYのごく近く（約1mm上）にあるため、Zファイティング回避用の微小オフセットでは足りず、海上区画の上面・枠線は海面板を確実に上回る量だけ持ち上げる。

### 3.2 パスの構成要素

建物パーツのリソースパス：

```
Models/Buildings/{prefix}/{threshold}/{partName}
```

| 構成要素          | 値                             | 説明                                                        |
| ------------- | ----------------------------- | --------------------------------------------------------- |
| **prefix**    | `landmark-{model_prefix}` / `a{variant}s{structure}` / `a{variant}` / `b{bd_type}s{structure}` / `b{bd_type}` | 観光名所 `landmark`（0=観光名所ではない）のフォルダを最優先し、次に建物の構造種別 `structure`（木造=1・準耐火=2・耐火=3。0=構造なし）ごとのフォルダを優先する。解決順は `landmark-{model_prefix}` → `a{variant}s{structure}` → `a{variant}`（`AgentModelConfig` に定義がある場合） → `b{bd_type}s{structure}` → `b{bd_type}` |
| **threshold** | `0`, `250`, `500`, `750` …    | 外観バリアントの閾値フォルダ                                            |

| **level**    | `base` / `mid` / `top` / `fence` | 1階・中層・屋上・フェンス       |

構造種別つきフォルダ（`a{variant}s{structure}` / `b{bd_type}s{structure}`）は、木造の板壁や RC の打放しのように**構造の差をパーツ・マテリアルの差し替えで表現する**ためのもので、ジオメトリの生成方式（`model_type`）は変えない。中身の構成・命名は無印のフォルダと同じで、構造ごとに用意しなければ無印のフォルダが使われる。どのフォルダが存在するかは `agent_model_config.yaml` の `structure_prefixes` に列挙され（`generate_agent_model_config.py` が実在フォルダから生成する）、`AgentModelConfig.HasStructurePrefix` が参照する。フォルダを追加したら必ず生成器を再実行すること。

工事中表示専用パーツ（scaffold-\* / crane-\*）は、通常の prefix（`a{variant}` / `b{bd_type}`）に加えて、
全建物共通の**標準パーツ置き場 `Models/Buildings/common/`** へのフォールバックを持つ（[[F5_工事中建物のメッシュ生成]] §2）。

観光名所フォルダ（`landmark-{model_prefix}`）は、東京タワーや自由の女神のような一点物の観光施設を

同じで、名所は `MODEL_PREBUILT` なので実際に使われるのは `*-prebuilt` と敷地装飾のパーツである。
どのフォルダが存在するかは `agent_model_config.yaml` の `landmark_prefixes` に列挙され

が参照する。構造種別つきフォルダと同じく、フォルダを追加したら必ず生成器を再実行すること。

### 3.5 接写用パーツ（`_close`）

描画LOD（[E_LOD処理](E_LOD処理.md)「描画LOD（オブジェクト単位）」）が Close の建物は、パーツ名に `_close` を付けた接写用モデルで組み立てる。無印のパーツが Normal（制作の基準）であり、`_close` は任意の上乗せである。Farは全建物共通で `base/mid/top-prebuilt_far` を使い、遠景用パーツが無い場合はコード生成の簡易形状を使う。

- **命名**: `{パーツ名}_close`。無印と**同じ閾値フォルダ**に置く（例: `Models/Buildings/a2000/0/mid-w1_close`）。
- **解決順**: Close のときは同じ閾値フォルダの `{パーツ名}_close` を先に試し、無ければ無印 `{パーツ名}` を使う（`BuildingMeshUtils.GetModelForDrawLod`）。閾値フォルダの選択（§4.2）とパーツの存在判定は無印の名前で行うため、`_close` だけを置いても無印が無ければ使われない。
- **対象**: `BuildingMeshUtils.GetPart` / `GetPartNoPosition` / common パーツ経由で解決されるすべてのパーツ（壁・角・ceil・floor・entrance・roofprop・prebuilt・マッシュアップのサブ建物・common）。
- **規約**: `_close` は無印と原点・配置寸法を一致させ、既存マテリアルを名前で共有する。壁（base/mid/top-w）と玄関は前方（Blender -Y）への追加張り出しを最大1.5m許可するが、幅X・高さZ・背面+Yは維持する。壁の奥行きは配置・伸縮に使われず、玄関は原点へ実寸配置されるため、庇・看板・バルコニーを付けても配置は変わらない。角・既成・タイル・塔屋などは全bboxを一致させる。生成側は配置計算を変えずプレハブを差し替える。
- **仕組み**: `BuildingMeshBuilder.Generate(data, isDynamic, drawLod)` が生成の前後で静的コンテキスト `BuildingMeshUtils.CurrentDrawLod` を設定・復元し、十数箇所あるパーツ取得がこれを参照する（生成は同期的にメインスレッドで行われる）。`isDynamic`（地形追従の互換引数）と `drawLod`（見え方由来）は独立した引数である。`drawLod` が Far の建物は `GenerateFarBuilding` が遠景用prebuiltを共通経路で組み立て、未提供時はフットプリントを階数×階高で押し出した箱を返す（露天掘りは何も描かない。港は区画が海へはみ出しているので箱にせず、岸壁と `_far` パーツを同じ配置で組み立てる。[[F4_港湾岸壁のメッシュ生成]] §9）（工事中・解体中は1階分、倒壊は0.5階分の高さ、`MODEL_MODULAR_GROUND` は0.3mの板）。

## 4. 外観バリアントの選択

### 4.1 バリアント番号の計算

`visual_variant`（0.0〜1.0）を 1000 倍して整数化する。

```
variant_number = floor(visual_variant × 1000)     → 0 〜 1000
```

### 4.2 閾値フォルダの選択ルール

閾値フォルダ名（`0`, `250`, `500`, `750` 等）は閾値を表す。
自身の `variant_number` 以下で最も大きい閾値フォルダを選ぶ。
閾値 `0` のフォルダは必ず用意する。

選択方法：標準閾値候補（0, 100, 200, ..., 1000）の中から `mid-w1` パーツが存在するものを探し、`variant_number` 以下で最大のものを選ぶ。

**例：** `variant_number = 600`、フォルダ `0`, `250`, `500`, `750` が存在 → **500** を選択。

`MODEL_PORT` は `mid-w1` を持たないので、パーツごとに同じ候補から `variant_number` 以下で最大の閾値のフォルダを探す（[[F4_港湾岸壁のメッシュ生成]] §6）。

`MODEL_MASHUP` は建物本体の壁パーツ（mid-w1）を持たないため、この共通ルールではなく
**サブ建物パーツごとに独立して**同じ閾値走査（variant_number 以下で存在する最大閾値）を行う
（[[F6_マッシュアップ建物のメッシュ生成]] §2）。

### 4.3 レベル間のバリアント整合性

閾値フォルダが決まると、建物全体（1階・中層・屋上）で同じフォルダからパーツを取得するため、レベル間の閾値は自動的に一致する。

1. 中層壁1（`mid-w1`）が存在する閾値フォルダを確定 → これが建物全体の閾値になる
2. 該当フォルダに `mid-w1` が存在しない場合：
   - `MODEL_MODULAR_GROUND` 以外 → **白い箱フォールバック**
   - `MODEL_MODULAR_GROUND` → suffix を `0` とし、敷地装飾の描画を継続する（[[F2_地面アセットのメッシュ生成]] §1）

### 4.4 位置番号のフォールバック

指定位置のパーツがない場合は **位置1** にフォールバック。
壁3（`w3`）がない → 壁1（`w1`）を使う。
外階段（`stair`）だけは位置のフォールバックをせず、その位置のパーツが無い辺には何も置かない（§11.4）。

## 5. フォールバック階層

すべて同一の閾値フォルダ内でフォールバックする。
壁パーツ（w）と角パーツ（c）は同じ階層でレベルをまたいでフォールバックする。
最終フォールバック先だけが異なる。
描画LODが Close のときは、各段で `{パーツ名}_close` → 無印の順に試す（§3.5）。次の段へ進むのは無印も無いときだけである。

**壁パーツ（w）**

```
指定レベル・指定位置のパーツ（例: top-w3）
    ↓ ない場合
位置1のパーツ（同じレベル）: top-w1
    ↓ ない場合
中層レベルの同じ位置のパーツ: mid-w3
    ↓ ない場合
中層レベルの位置1のパーツ: mid-w1
    ↓ ない場合
白い箱（底面ポリゴンを高さまで押し出した直方体）
```

**角パーツ（c）**

```
指定レベル・指定位置のパーツ（例: top-c3）
    ↓ ない場合
位置1のパーツ（同じレベル）: top-c1
    ↓ ない場合
中層レベルの同じ位置のパーツ: mid-c3
    ↓ ない場合
中層レベルの位置1のパーツ: mid-c1
    ↓ ない場合
角を描画しない（壁パーツが辺いっぱいに敷かれる）
```

角は建物単位のオプトインである。mid にも角パーツを用意していない建物では角を描画せず、
壁パーツを辺の端まで敷き詰める（角の張り出し量が 0 になる。§6.3・§7.6）。
mid-c1 だけを用意すれば、全レベル・全位置の角がそれで描画される。

**外階段パーツ（stair）**

```
指定レベル・指定位置のパーツ（例: top-stair3）
    ↓ ない場合
中層レベルの同じ位置のパーツ: mid-stair3
```

外階段は辺ごとのオプトインで、`mid-stair{n}` がその辺の有効化スイッチを兼ねる。
`mid-stair{n}` が無い辺には、base/top があっても外階段を置かない。位置1へもフォールバックしない（§11.4）。

## 6. 壁パーツの配置

### 6.1 基本考え方

壁パーツは辺に沿って並べる。1つの辺に複数パーツが並ぶとき、隙間ができないように X 方向（辺の長さ方向）に引き伸ばして埋める。

### 6.2 パーツの座標系と寸法

壁パーツは以下を仮定する：

- ローカル X 軸 = 辺の長さ方向、Y 軸 = 高さ方向、Z 軸 = 外壁の奥行き
- 原点 = 片端の下端角

パーツのメッシュバウンディングボックスから元の寸法を取得する。

### 6.3 スケールと配置の方針

壁パーツの奥行き（Z）はスケールせず、モデリング時の実寸（メートル単位）のまま使用する。幅（X）は下記の敷き詰め調整のぶんだけ伸縮する。

高さ（Y）は**階のレベルによって扱いが分かれる**。

| 階のレベル | Yスケール |
| --- | --- |
| 1階（base） | **なし（著作高さのまま）** |
| 中層（mid） | 階高（`height_per_floor`）に合わせて**Y方向のみ**スケール |
| 最上階（top） | **なし（著作高さのまま）** |

1階と最上階はパーツの著作高さがそのまま描画高さになる。階高が 4m でもパーツが 15m で著作されていれば **15m の高さで描画される**。中層だけは、積む枚数で建物の高さを調整する「詰めもの」の役割を持つため階高にそろえる。

**この判定は「階のレベル」で行う。** 1階に `base-w1` が無く `mid-w1` へフォールバックした場合（§5）でも、その階は1階なのでスケールされない。最上階も同様である。

**スケールしないのはパーツの形状だけで、配置位置は変わらない**（§6.4）。1階のパーツが 1m しかなければ2階との間に 3m の隙間が空き、逆に 10m あれば2階のパーツに埋もれる。これは仕様であり、プログラムは補正しない。

敷き詰めの手順は次のとおり。

1. **有効長を求める** — 辺の全長から、両端の角パーツがその辺へ実際に張り出す長さ（§7.6）を差し引く。壁は**手前の角パーツが終わったところから始まり、次の角パーツが始まるところで終わる**。
2. **枚数を決める** — 有効長をパーツの著作幅で割り、**四捨五入**して敷き詰め枚数とする（最低1枚）。切り捨てにすると端数を必ず引き伸ばす方向にしか吸収できず、最大で 2 倍近くまで間延びしてしまうため、縮小側も使って歪みを抑える。
3. **スロットへ合わせ込む** — 有効長を枚数でちょうど割った幅を1スロットとし、X 方向スケールでパーツをスロット幅に合わせる。合計は常に有効長と厳密に一致するため、**はみ出しも隙間も生じない**。
4. **原点のずれを補正する** — 各ユニットは「メッシュの X 範囲がスロットに一致する」ように置く。幅の中央に原点があるパーツ（規格どおりのパーツ）ではスロットの中央に原点が来る。

ただし、辺の長さが両端の角パーツの張り出し合計以下の場合は、有効長が存在しないため壁パーツは配置しない。この場合、両端の角パーツのみを配置して隙間を埋める。

**寸法の警告**: XZ実寸が 0.3m 未満の壁・角パーツは、cm単位や 1×1 の単位スケールでエクスポートされた疑いが強いため警告ログを出す。パーツはスケールされないので、この場合そのまま極小サイズで描画される。実寸（1 Blenderユニット = 1m）で再エクスポートすること（[[I_建物パーツ作成マニュアル]]）。

各壁ユニットは、変換行列（位置・回転・スケール）をメッシュの全頂点に適用して配置する。
回転はモデルの X 軸を辺の方向に向ける。

### 6.4 階の配置位置と躯体の高さ

**パーツの配置位置は常に階高グリッドに乗る。** パーツの著作高さは配置に影響しない。

```
床面Y(n階) = n × height_per_floor
躯体の高さ  = floors × height_per_floor
```

屋根・塔屋の配置Yとコライダーの高さは、この躯体の高さを使う。

したがって、スケールしない1階・最上階（§6.3）では、パーツの著作高さと階高のズレがそのまま見た目に出る。

- **パーツが階高より低い** — 上の階との間に隙間が空く（階高 4m・`base-w1` が 1m なら 3m の隙間）
- **パーツが階高より高い** — 上の階のパーツに埋もれる（階高 4m・`base-w1` が 10m なら、2階のパーツは 4m の位置から始まるので1階のパーツと重なる）

いずれもプログラムは補正しない。パーツを階高に合わせるか、意図した見た目になるよう著作側で調整する。

1階・最上階で位置ごとに違う高さのパーツを置いた場合（`base-w1` が 4m、`base-w3` が 6m 等）も同様に、パーツはスケールされないため壁面の高さが揃わない。

## 7. 角パーツの配置と変形

### 7.1 基本考え方

角パーツは各頂点に1つ配置する。2つの辺ベクトルから内角を計算し、その角度に合わせてパーツを向ける。

角パーツは建物単位のオプションである（§5）。mid にも角パーツが用意されていない場合は
角を描画せず、壁パーツが辺の端まで敷き詰められる（§7.6）。

### 7.2 内角の計算

角の頂点とその前後の頂点から2つの辺ベクトルを作り、符号付き角度から内角を求める。
CCW ポリゴンでは凸頂点の内角は 0°〜180°。
L字の凹頂点では内角を270°などの180°超として扱い、同じボーン変形で接続する。

### 7.3 向きの決定

**内角側の二等分線（bisector）**方向に角パーツの正面を向ける。
CCWの送り辺（当該頂点→次の頂点）を内角の半分だけ反時計回りに回して求める。
辺の単位ベクトルの和は凹頂点では外側の小さい角を二等分するため使用しない。
L字の270°角でも両アームが対応する辺へ向き、180°の前後でも配置方向が連続する。
壁の張り出し量の計測も、この内角側の二等分線を共有する。

### 7.4 ボーン変形（SkinnedMeshRenderer がある場合）

角パーツがボーンを2本持つ場合、90° を基準に作成されたモデルを任意の角度に変形できる。

ボーン構造：
- `Bone`（bones[0]）：送り側。標準FBXでは Blender +X / Unityメッシュ −X
- `Bone.001`（bones[1]）：受け側。標準FBXでは Blender +Y / Unityメッシュ −Z

変形の考え方：
- 90° からのズレ（angleDiff = 内角 − 90°）を求める
- 各ボーンを angleDiff の半分ずつ Y 軸周りに回転させる
- 0番ボーンは +halfDiff、1番ボーンは −halfDiff
- ボーンの開き角が内角と一致するように調整される

ボーン変形後のメッシュは `SkinnedMeshRenderer.BakeMesh()` でジオメトリを確定させる。
これは最終的なメッシュ結合（ベイク）とは別の、ジオメトリ準備の段階である。

### 7.5 静的メッシュ（ボーンなし）の場合

ボーンがない角パーツは 90° 専用。凸角では内角が90°から離れていても変形せず、そのまま配置する。
**凹角（180°超）では、2本のボーンで開閉できない角パーツは配置しない。**
この頂点の壁オフセットも0にし、隣接する壁を頂点まで敷き詰める。
静的な90°角を凹角へ置いて壁を突き出させることを防ぐためであり、凹角の装飾も必要な場合はボーンを持つパーツを用意する。

特に敷地外周の `fence-c*` は直角を保証できないため、制作時に2本のボーンを付ける
（[[I_建物パーツ作成マニュアル]] §4.1）。角の張り出し量だけを測っても、静的な角の
接続端は辺の方向へ向かないので、壁との隙間を防げない。

### 7.6 スケールと、辺への張り出し量

角パーツは壁パーツと同じ規則でスケールする。アーム長（XZ）は常にモデリング時の実寸のまま使用し、高さ（Y）は中層（mid）の階だけ階高に合わせてY方向スケールする。1階・最上階の角パーツは著作高さのまま描画される（§6.3）。

壁パーツの配置開始・終了オフセット（§6.3 の「有効長」）は、**角パーツを実際に配置したときに、その辺の方向へどれだけ張り出すか**を測って決める。ローカル X/Z 軸のバウンディングボックスを見るのではなく、実配置と同じ回転・スケールを掛けた角パーツの全頂点を辺方向へ射影し、その最大値を採る。これにより

- アームがどちらのローカル軸向きで著作されていても正しい値になる
- 庇や胴差しのような、辺方向へ伸びる造作も張り出しに含まれる
- 角パーツが存在しない建物では張り出しが 0 になり、壁が辺いっぱいに敷かれる

ため、壁が角パーツにめり込んだり、角パーツから離れて隙間ができたりしない。

ボーン変形（§7.4）で角を開閉する場合も、アームは辺と一緒に回転するため張り出し量は変わらない。射影先には**バインドポーズ（内角90°）での辺の向き**（二等分線から ±45°）を使うことで、変形後の実際の張り出し量と一致する。

## 8. 地面パネルと基盤

### 8.1 地面パネル

地面パネルは高さほぼ 0 の位置に配置する（Zファイティング回避で微小量だけ浮かせる）。

**地面パネルはマスターデータの `draw_floor=yes` の建物でのみ描画する（オプトイン。未設定は描画しない）。**
描画時のマテリアルは `floor` パーツから取得し、解決順は **`a{variant}` → `b{bd_type}` → `common`** の
フォールバックチェーン（工事系パーツと同じ規約。`common` は suffix フォルダを挟まず
`Models/Buildings/common/floor`）。**どこにも `floor` パーツが無ければ地面パネルは描画しない**
（既定建物マテリアルにはフォールバックしない）。これにより、地面パネルが不要な地面アセット
（例: `tile` パーツのみのソーラー発電所）に意図しないスラブが敷かれることを防ぐ。
この仕様はモジュラー建物・既成建物（プレビルド）で共通。車両基地（MODEL_RAIL_YARD）だけは `a{variant}` 自身の
`floor` パーツに限り、`b{bd_type}`・`common` へフォールバックしない（共通の舗装が線路の下に敷かれないため。
[[F9_車両基地のメッシュ生成]] §6）。

地面パネルは**土地区画のポリゴン全体**に対して生成する（建物底面だけに張ると、パネルが建物本体の
真下に隠れて見えないため）。土地区画が取得できない場合は建物の底面ポリゴン（`footprint`）に
フォールバックする。この対象ポリゴンの規則はすべての model_type で共通である
（[[F2_地面アセットのメッシュ生成]] §2・[[F3_既成建物のメッシュ生成]] §3・
[[F6_マッシュアップ建物のメッシュ生成]] §5）。
通常の常駐描画ではパネルを実地形の傾斜に沿って生成する（§9.4参照）。
なお、この地面パネルの生成ロジック（対象ポリゴン・地形追従・`floor` パーツをマテリアル供給元として扱い
パーツが無ければ描かない規則）は建物専用ではなく、駅舎パスの専有エリア
（[[Q_駅舎パスのメッシュ生成]] §1）でも共有している。
地形追従時は、敷地ポリゴンを耳切りで三角形に分け、それぞれを描画タイルの格子三角形で切り抜く（`BuildingMeshBuilder.GenerateTerrainSurfaceMesh`）。格子の対角線はXZの最小点から最大点へ結び、切り抜いた境界頂点も同じ三角形上の高さで補間する。頂点だけを接地させる独立した三角形分割では面の内部で地形が突き抜けるため、分割そのものを共有する。

格子頂点の高さは実タイルから取得し、floorはその面から `GROUND_OFFSET`（5mm）浮かせる。交点はローカル座標の0.1mm単位で溶接し、隣接面の法線の継ぎ目を抑える。全タイルが共通解像度で格子を共有するためセル境界でも同じ分割になる。タイル未ロード時のみ最大辺長6mの暫定分割を使い、地形到着後に再生成する。

### 8.2 基盤（コンクリート基盤）

傾斜地では建物が `center_point` 位置の地形標高（§2.4）の水平面に接地するため、谷側では底面と地形の間に
隙間ができて建物が浮いて見える。この隙間を埋めるため、建物の底面ポリゴン（`footprint`）を
Y方向に押し出した柱状のコンクリート基盤を生成する。

- **対象** — MODEL_MODULAR_FLAT / HOUSE / GABLE / SHED のみ。
  MODEL_MODULAR_GROUND・MODEL_PREBUILT・MODEL_PORT・MODEL_MASHUP・MODEL_OPEN_PIT は基盤を生成しない
  （土地区画の形状を押し出すこともしない）。
- **形状** — 上面 = 建物の接地面（ローカルY=0。地面パネルのわずかに下）、
  下面 = 底面頂点でサンプリングした最低地形標高の5m下（最低でも接地面の10m下）。
  頂点間で地形が局所的に落ち込んでも突き抜けないよう、下面には余裕を持たせている。
- **UV** — 上面・側面ともワールドスケール（10mで1タイル）。側面のUは外周に沿った累積距離で、
  辺をまたいでもタイリングが連続する。
- **マテリアル** — 全建物共通のコンクリートマテリアル `Resources/COMMON_CONCRETE`
  （未配置時は警告を出してデフォルト建物マテリアルにフォールバック）。
- 工事中（[[F5_工事中建物のメッシュ生成]] §3）は同じ形状を土マテリアルで生成する。

## 9. フェンス（fence）の配置

`GenerateSiteDecorations` は省略可能な `fenceOpeningCenter` と `fenceOpeningRadius` を受け取る。指定した円が外周辺と交わる区間は壁を分割して空け、円内の角パーツも省く。既定値では開口なし。車両基地は引き込み線の境界通過位置にこの開口を設ける（F9 §6）。

### 9.1 配置対象ポリゴン

フェンスは建物の底面ポリゴンではなく、**土地区画（parcel）のポリゴン**の形状に沿って配置する。
土地区画の頂点列を `fenceFootprint` とする。

土地区画のポリゴンにも縮退頂点の間引き（§2.2）を適用する。間引きは敷地コンテキストの解決
（`BuildingMeshUtils.ResolveParcelContext`）で一括して行われるため、フェンスに限らず、
区画ポリゴンを使うすべての敷地装飾（地面パネル・タイル）とコライダーに適用される。
間引き後に3頂点未満になった場合は区画ポリゴンなしとして扱う（建物底面へフォールバック）。

### 9.2 レベル

フェンスは `fence-w*`（壁）と `fence-c*`（角）のパーツを使用する。
配置ロジック・角の変形・フォールバック階層は `base` / `mid` / `top` と同じである。

### 9.3 スケール

フェンスは**Y方向にはスケールしない**（建物の1階・最上階の壁・角と同じ扱い）。元のメッシュサイズのまま配置する。
X方向（辺の長さ方向）については、建物の壁と同じ敷き詰めロジック（§6.3）を使う。すなわち、両端のフェンス角パーツが辺へ張り出す長さ（§7.6 と同じ射影による計測。フェンス角は無スケールなので実寸がそのまま張り出し量になる）を差し引いた有効長に、四捨五入で決めた枚数を隙間なく敷き詰める。

### 9.4 地形追従

通常の常駐描画では、フェンスと地面パネルとタイルオブジェクトを配置場所の地形に沿って曲げる。この地形追従は**すべての model_type の敷地装飾**が対象である。傾斜地対応の建物（MODEL_MODULAR_FLAT / HOUSE / GABLE / SHED）は建物本体こそ接地高（§2.4）の水平面に接地しコンクリート基盤（§8.2）で谷側を埋めるが、その敷地装飾（フェンス・タイル・地面パネル）は地形に追従させる。追従の基準高さは `center_point` 位置の地形標高で、陸上の建物GameObjectの配置高さ（§2.4）と一致する。車両基地（MODEL_RAIL_YARD）は敷地装飾に加えて、構内の線路・架線・検修庫などの設備も同じ基準で頂点ごとに地形へ沿わせる（[[F9_車両基地のメッシュ生成]] §6.1）。

生成器は地形ティア表を参照しない。BuildingManagerは通常の詳細描画で `isDynamic=true` を渡し、対応するモデルの敷地装飾を別ジョブへ分ける。Far輪郭は敷地装飾の生成自体を省略する。

各メッシュの頂点に対し、その頂点の水平位置（XZ座標）での地形標高を `Utils.GetGroundHeight`（建物GameObjectの配置高さと同じ取得経路）で取得し、頂点のY座標をその標高に合わせる。基準高さは建物の `center_point` 位置の地形標高であり、建物GameObjectがこの高さに配置されることを前提として、各頂点のローカルY座標を「頂点位置の地形標高 − center_point位置の地形標高」を基準にローカル座標化する。

フェンスの場合、元のメッシュ頂点の相対的な高さ関係（上端が下端より高い状態）は維持する。つまり、頂点位置の地形高さに元のローカルY（スケール適用後）を加算した値を新しいY座標とする。

地面パネルの場合、§8.1の地形格子による切り抜きを使い、center_point位置の高さを基準にローカル座標化する。高さの補間だけでなく地形と同じ三角形分割を使うことで、区画内部の起伏にも面として追従する。Terrain自身の描画LODによる形状差は、描画誤差設定と深度オフセットで抑える（[[E_LOD処理]]）。

タイルオブジェクトの場合、まずすべてのタイルを平面上に配置してから、各タイルメッシュの頂点をフェンスと同様に地形に合わせて変形する（元のメッシュ頂点の相対的な高さ関係を維持したまま、頂点位置の地形高さを加算する）。

初回は地形と区画の取得後に建物を生成する。地形編集時は変更した常駐セルの詳細建物を更新し、Far輪郭は配置高さを合わせ直す。接地先の版が変わった古いLODキャッシュは再利用しない（[[E_LOD処理]]参照）。

## 10. 塔屋（roofprop）の配置

### 10.1 配置条件

パーツ `roofprop` が存在する場合のみ配置。なければ配置しない。

### 10.2 位置

`visual_variant2` をシード値として、屋上面上の位置を決定する。
屋上面の重心を中心に、シードから角度と距離を計算してオフセットした位置に置く。

### 10.3 角度

塔屋の向きは底面ポリゴンの最初の辺（頂点0 → 頂点1）の方向に合わせる。

### 10.4 高さ

屋上パネルと同じ高さ（躯体の高さ `floors × height_per_floor`。§6.4）に配置する。最上階のパーツが背高で塔屋を突き抜けても補正はしない。

`MODEL_PORT` は位置・角度・高さをヤードと水際から決めるため、この規則ではなく専用ルールで配置する（[[F4_港湾岸壁のメッシュ生成]] §5.4）。

`MODEL_MASHUP` は塔屋を配置しない（各サブ建物が完成モデルとして頂部まで含む前提のため）。

## 11. エントランス（entrance）の配置

### 11.1 配置条件

パーツ `entrance` が存在する場合のみ、建物1棟につき1つ配置する。なければ配置しない。
対象は MODEL_MODULAR_FLAT / HOUSE / GABLE / SHED（MODEL_MODULAR_GROUND は建物本体を持たないため対象外）。
`building_shape = SHAPE_FULL` の建物は最上階のみを描画する（[[F1_モジュラー建物のメッシュ生成]] §4）ため、地上に壁が存在する1階建ての場合に限って配置する。

### 11.2 位置と向き

前面の辺は、底面ポリゴンの**最初の辺（頂点0 → 頂点1、位置1の壁の辺）**とする（塔屋の向き決定 §10.3 と同じ規約）。

その辺の中央、**地面レベル（ローカルY=0）**に配置する。原点は壁のアライメントライン（前面の辺の直線上）に一致し、回転は壁パーツと同じ規約（辺方向へ向けてY軸まわりに180°反転。§6）を用いる。すなわち、壁パーツと同じ座標系で著作したモデルがそのまま前面の壁面に重なる。

### 11.3 スケール

一切スケールしない（実寸）。庇や階段などの造作が階高・辺長に引き伸ばされるのを防ぐため。

---

### 11.4 外階段・階間スロープ

外階段は辺ごとに置くパーツで、頂点 i → i+1 の辺（位置番号 `i+1`。壁 `w{i+1}` と同じ辺）の外階段は
`base-stair{i+1}` / `mid-stair{i+1}` / `top-stair{i+1}` である。複数の辺に別々の外階段を同時に置ける。
形は階段に限らず、各階に1個ずつ積む付属物なら何でもよい（正面 `stair1` のガラス張りのエレベーターシャフト、背面 `stair3` の鉄骨階段など）。

外階段を持つ通常のモジュラー建物は、元のフットプリントを本体と外階段の合計占有範囲として使う。
`ExteriorStairBuilder` が描画専用の本体輪郭を作り、外階段のある辺の全体を、その辺のパーツの最大奥行きだけ内側へ平行移動する。
隣の辺（そちらにも外階段があれば、その後退線）との交点で頂点を更新し、壁・床・屋根・基盤・塔屋・エントランスに同じ輪郭を渡す。
保存polygon、経済上の面積、クリック用の占有コライダーは元のまま。階段部分だけが突き出す輪郭は生成しない。

- パーツは同じ外観閾値のもの。`mid-stair{n}` がその辺の有効化スイッチで、base/top欠落時は同じ辺のmidを使う。1階建ては壁と同じくbaseを優先する。
- **位置番号のフォールバックはしない。** `mid-stair{n}` が無い辺には外階段を置かない（壁・角のように位置1へ戻らない）。
- **原点は後退前のその辺の終点（頂点 i+1）・各階の床面**。水平方向の再基準化・伸縮・敷き詰めはせず、各階に1個だけ配置する。頂点は0始まり。
- 結合済みUnityパーツの+Xを頂点 i+1 → i、−Zを建物内側へ向ける。Blenderでの規約は [[I_建物パーツ作成マニュアル]] §4.11。
- 各階の配置Yは `階 × height_per_floor`。base/topは実寸、中層だけ `height_per_floor / mid-w1の著作高さ` でYスケールする。
  手すりや床厚が接続高さを変えないよう、階段のbbox高さは倍率に使わない。階段の1段の高低差は壁の著作階高にそろえる。
- その辺の3レベルのパーツを包む水平範囲から奥行きと開口を求める。後退した本体の同じ辺の壁をその幅だけ省略し、開口端に重なる角も省略する。
  開口部の手すり・扉・踊り場は階段モデルが持つ。屋根・各階床は後退した本体だけを覆う。
- 採否は頂点0の辺から順に決める。パーツが元の輪郭に収まらない、本体が潰れる、辺の反転・自己交差が起きる、
  先に採用した外階段や本体と重なる場合は、その辺の外階段とセットバックを省略する（採用済みの辺はそのまま残る）。
  L字などでも対象はパーツの位置番号の辺で、別の辺を探索し直さない。`SHAPE_FULL`、GROUND、PREBUILTには適用しない。
- エントランス（§11.2）と塔屋の向き（§10.3）は後退後の本体輪郭の頂点0→1の辺を使う。`stair1` を置くと、エントランスは外階段の奥の本体正面に付く。
- Closeは同じ原点・bboxで差し替え、Farは既存の遠景経路を使う。外階段が1つも無い建物の輪郭は変えない。

## 12. メッシュの結合とベイク

壁・角・屋上・地面・塔屋のすべてのパーツの配置が完了した後、**一括で**メッシュを結合する。

工事中クレーンの頂部は、本編のClose / Normalで旋回させるため結合対象から分離し、接続点を原点とする子オブジェクトにする。生成側の指定と描画側の所有・アニメーションは [[F5_工事中建物のメッシュ生成]] §5 を参照。

1. 各パーツを `CombineInstance` に変換（サブメッシュごとに個別のインスタンス）
2. `Mesh.CombineMeshes()` でサブメッシュ構造を維持したまま結合
3. 法線とバウンディングボックスを再計算
4. 結合後、同じマテリアルのサブメッシュを統合してドローコールを最小化
5. 一時メッシュを解放

角パーツのボーン変形（BakeMesh）はあくまで個別パーツのジオメトリ準備であり、この最終的な結合ベイクとは別物である。

### 12.1 プレハブ単位の事前結合と頂点の詰め直し

既成建物・マッシュアップの各段、外階段、工事中のクレーン（旋回する頂部を含む）と重機、倒壊片、港湾クレーン、車両基地の素材パーツ、オープンスペースの小物は、配置の前に `BuildingMeshUtils.CombineModuleMeshes` でプレハブ配下の全メッシュを1つにまとめる（ノードのTransform込み。SkinnedMeshRenderer はバインドポーズでベイクする）。

`Mesh.CombineMeshes()` はサブメッシュ単位の `CombineInstance` でも、そのサブメッシュのインデックスの最小〜最大の範囲にある頂点を丸ごと写す。FBX取り込みの頂点溶接は位置・法線・UVが同じ頂点を材質をまたいで1つにするため、同じ向きで面一に接する別材質の面（実寸キューブ投影UVでは頂点が一致する）を持つパーツでは、後のサブメッシュの範囲が前のサブメッシュの区画まで伸び、参照されない頂点まで写される。これを避けるため、`CombineModuleMeshes` の結果は次の形にそろえる。

- 頂点はサブメッシュごとの連続区画に並び、各区画はそのサブメッシュが参照する頂点だけを持つ。区画内は元の頂点順を保つ。
- 複数のサブメッシュが参照する（溶接された）頂点は、サブメッシュごとに1つずつ持つ。
- サブメッシュとマテリアルの順序、三角形の並び、頂点属性とその形式は元のパーツのまま変えない。

この形なので、各ビルダーが結果を再びサブメッシュ単位で結合しても頂点は増えない。壁・角（工事中の足場を含む）・エントランス・塔屋・フェンス・タイルは元のメッシュを直接サブメッシュ単位で積むので、この詰め直しを通らない。

## 13. コライダー

クリック判定のため、底面ポリゴンを建物高さまで押し出した形状の `MeshCollider` を生成する。

- **下面**：CCW の三角形ファン（法線下向き）
- **上面**：CW の三角形ファン（法線上向き）
- **側面**：各辺について、上下の頂点4点で構成する四角形を2つの三角形に分割

高さは躯体の高さ `floors × height_per_floor`（§6.4）である。1階・最上階のパーツがこれをはみ出して著作されていても、コライダーは伸ばさない。

押し出すポリゴンと高さは model_type によって異なる。

| model_type | ポリゴン | 高さ |
| --- | --- | --- |
| MODEL_MODULAR_FLAT / HOUSE / GABLE / SHED | 建物底面 | 躯体の高さ（`floors × height_per_floor`） |
| MODEL_MODULAR_GROUND | 土地区画 | `floorHeight`（[[F2_地面アセットのメッシュ生成]] §4） |
| MODEL_PREBUILT | 建物底面 | 描画された実高さ（[[F3_既成建物のメッシュ生成]] §4） |
| MODEL_PORT | ヤード（岸壁フットプリント、または埋立地の上の港では区画の陸の部分） | 岸壁上面・天端の高さ（[[F4_港湾岸壁のメッシュ生成]] §7） |
| MODEL_MASHUP | 土地区画 | 描画された最も高いサブ建物の天端（[[F6_マッシュアップ建物のメッシュ生成]] §6） |
| MODEL_OPEN_PIT | 押し出さない。地形に沿う土地区画の面＋設備ごとの外接箱 | 設備の天端（[[F11_露天掘りのメッシュ生成]] §4） |
| MODEL_RAIL_YARD | 建物底面 | 固定 7m（架線柱の天端相当。[[F9_車両基地のメッシュ生成]] §7） |
| 工事中（STATUS_CONSTRUCTING） | 建物底面 | 施工済み階の高さ（[[F5_工事中建物のメッシュ生成]] §7） |

## 14. 1階あたりの高さ

マスターデータの `height_per_floor` を使用する。
設定されていなければ `LocalConstants.FLOOR_HEIGHT`（デフォルト: 4.0）を使う。

**すべてのパーツの配置位置（各階の床面Y）と躯体の高さはこの値で決まる**（§6.4）。一方、この値でパーツが**スケール**されるのは中層（mid）だけで、1階（base）・最上階（top）の壁・角と prebuilt の base / top は著作実寸で描画される（§6.3・§7.6・[[F3_既成建物のメッシュ生成]]）。用途は次のとおり。

- 各階の床面Y（`階 × height_per_floor`）と躯体の高さ（`floors × height_per_floor`）（§6.4）
- 中層の壁・角・`mid-prebuilt` のYスケール目標高さ（§6.3・[[F3_既成建物のメッシュ生成]] §1）
- 住宅風三角屋根・切妻屋根の棟の高さ、片流れ屋根の立ち上がり（[[F1_モジュラー建物のメッシュ生成]] §2〜§4）。
  いずれも**建物高さではなく階高**に比例させ、階数の多い建物だけ屋根が巨大にならないようにする
- 白い箱フォールバックの高さ（`floors × height_per_floor`）
- `MODEL_MODULAR_GROUND` のコライダー高さ（[[F2_地面アセットのメッシュ生成]] §4）
- 工事中の足場・クレーンの1段の高さ（[[F5_工事中建物のメッシュ生成]]）

## 16. 道路への接続点と間口

施設側の開口を `BuildingRoadOpening` で表す。`A`・`B` は建物中心から見た舗装端の両端、`Position` は中点、`Width` は両端間の距離、`Outward` は敷地から道路への方向である。1施設に複数持てる。`Flow` は `entry`・`exit`・`both`、`Apron` は敷地内のすり付け舗装の輪郭である。プレイヤーの指定や乱数の再抽選を必要としない。

- 駅前ロータリー3002は、形状生成に使う最終アスファルト面と接道辺の交線から得る。すみ切りを含む実際の開口幅になる（[[F10_オープンスペースのメッシュ生成]]）。
- 既成建物は通常モデル内の非描画マーカーから得る（[[F3_既成建物のメッシュ生成]] §6）。現在の著作済みモデルは国境貨物駅1081で、入口45m・出口10mを持つ。
- 港は施設モジュール（`port_building`）のマーカーを、区画の辺0に揃えたモジュールの置き方で移して得る。舗装高は開口の地面に追従し、海面+2mを下限にする（[[F4_港湾岸壁のメッシュ生成]] §10）。
- その他の生成方式やマーカーのないモデルは開口を返さない。

稼働中・停止中・解体予定の建物が対象で、工事中・解体中・倒壊・建設予定の表示には開口を作らない。開口は建物の描画GOから独立して保持するため、建物がFar表示・視野外になっても位置と幅は変わらない。

`BuildingManager` がデータ登録・更新・削除と索引を同期し、`PathManager` が該当する道路の描画版を進めて再生成を予約する。道路側は間口を片側の距離区間へ変換し、歩道・沿道設備を除き、道路外縁から敷地内へ舗装をすり付ける（[[G_道路メッシュの生成]]「施設への接続」）。交通グラフやシミュレーションの接続ノードには変換しない。
