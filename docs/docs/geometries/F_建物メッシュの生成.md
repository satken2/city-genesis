# 建物メッシュの生成

## 概要

バックエンドの Agent データから、建物の外装メッシュを組み立てて配置する仕様。

建物の3Dモデル生成方法は、`agent_master` に定義された **`model_type`** によって分かれる。`model_type` は3Dモデルの組み立て方式を表すものであり、建物の底面ポリゴンの形状（[[C_建物形状]]）とは全く別軸の話である。

| model_type               | 生成方式                   | 備考                                                                                                                                                                           |
| ------------------------ | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **MODEL_MODULAR_FLAT**   | モジュラーパーツ組み立て + 平屋根     | 1階・中層・屋上の壁・角パーツを底面形状に沿って配置し、最上部に平らな屋根と塔屋を配置する。本ドキュメントの主題                                                                                                                     |
| **MODEL_MODULAR_HOUSE**  | モジュラーパーツ組み立て + 住宅風三角屋根 | 壁・角・地面の生成は MODEL_MODULAR_FLAT と同じ。屋根だけ三角屋根（切妻屋根）を生成する。塔屋も配置する                                                                                                                |
| **MODEL_MODULAR_GABLE**  | モジュラーパーツ組み立て + 切妻屋根    | 壁・角・地面の生成は MODEL_MODULAR_FLAT と同じ。屋根だけ切妻屋根を生成する。塔屋も配置する                                                                                                                     |
| **MODEL_MODULAR_GROUND** | モジュラーパーツ組み立て（地面用途）     | 建物本体は描画せず、フェンス・地面パネル・タイルオブジェクトを土地区画の形状に沿って配置する。畑や庭など、建物の概念がない地面アセットに適用する                                                                                                     |
| **MODEL_PREBUILT**       | 既成パーツ組み立て              | 電波塔やオブジェ、銅像、観覧車など、通常の建物とは全く異なる形状の建物に適用する。base-prebuilt / mid-prebuilt / top-prebuilt を積み上げる（§17）                                                                             |
| **MODEL_PORT**           | 厚みのある板（岸壁）をプロシージャル生成   | 海岸土地区画（PARCEL_SHORE）の港湾（BUILDING_PORT）用。building_shape=SHAPE_FULL の底面ポリゴンを海岸線でカットして上下に押し出し、厚みのある岸壁スラブを作り、塔屋を配置する。モジュラーの壁・角パーツは使わない。visual_variant1/2/3 を閾値選択ではなく幾何パラメータとして使う |

本ドキュメントでは MODEL_MODULAR_FLAT の詳細と、他のモデルタイプとの差分を中心に記述する。

## 1. データフロー

```
バックエンド API  ──→  BuildingSummary
                          ├─ polygon         底面の頂点列（center_point 基準の相対座標）
                          ├─ center_point    ワールド座標
                          ├─ floors          階数
                          ├─ variant         建物バリアント
                          ├─ visual_variant  外観バリアント1（0.0-1.0）
                          ├─ visual_variant2 外観バリアント2（0.0-1.0）
                                │
                                ▼
                     BuildingMeshBuilder.Generate()
                          │
                          ├─ model_type で分岐
                          │    ├─ MODEL_MODULAR_* → ModularBuildingMeshBuilder
                          │    │                      ├─ 1. ModularBodyBuilder で壁・地面を生成
                          │    │                      ├─ 2. FlatRoofBuilder / HouseRoofBuilder / GableRoofBuilder で屋根を生成
                          │    │                      ├─ 3. 塔屋を配置
                          │    │                      └─ 4. 結合・ベイク
                          │    ├─ MODEL_PREBUILT    → PreBuiltBuildingMeshBuilder
                          │    ├─ MODEL_PORT        → PortBuildingMeshBuilder
                          │    │                      ├─ 1. 海岸線ポリゴンを取得
                          │    │                      ├─ 2. 底面ポリゴンを海岸線でカット（visual_variant1/2で突き出し量を補間）
                          │    │                      ├─ 3. 厚みのあるスラブを上下に押し出し
                          │    │                      └─ 4. 塔屋を配置・結合・ベイク
                          │    └─ その他             → BuildingMeshBuilder.GenerateSimpleBuilding（白い箱）
                          │
                                ▼
                     BuildingMeshResult (Mesh + Material[] + ColliderMesh)
```

## 2. 底面形状

### 2.1 polygon データ

バックエンドの Agent データに含まれる `polygon` を使用する。
これは `float[][]`（頂点の配列）で、各頂点は Agent の `center_point` からの相対座標 `[x, y]` である。

### 2.2 頂点の並び順

polygon の頂点は **反時計回り（CCW）** に正規化する。
符号付き面積が負の場合は配列を反転させる。

### 2.3 壁・角の番号付け

底面ポリゴンの頂点インデックスをそのまま壁・角の位置番号に対応させる。
頂点 0 = 位置 1、頂点 1 = 位置 2、… とする。

N辺ポリゴンのとき：

| 位置番号 | 壁（辺） | 角（頂点） |
|---|---|---|
| 1 | 辺 0（頂点0 → 頂点1） | 頂点 0 |
| 2 | 辺 1（頂点1 → 頂点2） | 頂点 1 |
| 3 | 辺 2（頂点2 → 頂点3） | 頂点 2 |
| … | … | … |

壁の位置 n に対応する辺は `edge_index = n − 1`。
角の位置 n に対応する頂点は `vertex_index = n − 1`。

### 2.4 ワールド配置

生成されたメッシュの頂点座標はすべて `center_point` 基準の相対座標とする。
配置時に `center_point` のワールド座標と接地高を足して最終位置とする。

接地高（建物の接地面の標高）は model_type によって異なる。

- **MODEL_MODULAR_FLAT / HOUSE / GABLE** — 所属する土地区画の基準標高（`parcel.altitude`）。
  傾斜地でも建物は水平面に接地し、谷側にできる地形との隙間は基盤（§9.2）が埋める。
  区画が取得できない場合は `center_point` 位置の地形標高にフォールバックする。
- **それ以外（MODEL_MODULAR_GROUND / MODEL_PREBUILT / MODEL_PORT）** — `center_point` 位置の地形標高。

## 3. パーツの配置と命名規則

### 3.1 フォルダ構成

パーツは FBX モデルを Unity プレハブ化したものを `Assets/Resources/Models/` に配置する。
元の FBX ファイルは `Assets/Models/` に同じ構成で置く。

`ModelManager` がリソースパスをキーとしてキャッシュする。

```
Assets/Resources/Models/
├── Buildings/
│   ├── b{bd_type}/
│   │   └── {threshold}/             # 閾値フォルダ（0, 250, 500, 750 等）
│   │       ├── base-w1.prefab       # 1階壁 位置1
│   │       ├── base-w2.prefab       # 1階壁 位置2
│   │       ├── base-c1.prefab       # 1階角 位置1
│   │       ├── base-c2.prefab       # 1階角 位置2
│   │       ├── mid-w1.prefab        # 中層壁 位置1
│   │       ├── mid-c1.prefab        # 中層角 位置1
│   │       ├── top-w1.prefab        # 屋上壁 位置1
│   │       ├── top-c1.prefab        # 屋上角 位置1
│   │       ├── fence-w1.prefab      # フェンス壁 位置1（土地区画ポリゴンに沿って配置）
│   │       ├── fence-c1.prefab      # フェンス角 位置1（ボーンで角度変形／Y方向スケールなし）
│   │       ├── ceil.prefab          # 屋上マテリアル用
│   │       ├── floor.prefab         # 地面マテリアル用
│   │       ├── tile.prefab          # タイルオブジェクト（MODEL_MODULAR_GROUND 専用）
│   │       └── roofprop.prefab      # 塔屋
│   ├── a{agent_variant}/
│   │   └── {threshold}/
│   │       ├── base-prebuilt.prefab
│   │       ├── mid-prebuilt.prefab
│   │       └── top-prebuilt.prefab
│   └── common/                      # 全建物共通の標準パーツ（工事中表示用。§19）。suffix フォルダなし
│       ├── scaffold-wall.prefab       # 足場の辺パーツ
│       ├── scaffold-corner.prefab     # 足場の角パーツ（ボーンで角度変形）
│       ├── crane-base.prefab          # クレーン最下段
│       ├── crane-mid.prefab           # クレーン繰り返しセグメント

│       └── ceil.prefab                # 施工済み階の天面パネル用マテリアル
└── Paths/
    └── p{path_variant}/
        ├── body.prefab
        ├── line.prefab
        ├── sidewalk.prefab
        └── tree.prefab
```

### 3.2 パスの構成要素

建物パーツのリソースパス：

```
Models/Buildings/{prefix}/{threshold}/{partName}
```

| 構成要素          | 値                             | 説明                                                        |
| ------------- | ----------------------------- | --------------------------------------------------------- |
| **prefix**    | `b{bd_type}` または `a{variant}` | `AgentModelConfig` に定義があれば `a{variant}`、なければ `b{bd_type}` |
| **threshold** | `0`, `250`, `500`, `750` …    | 外観バリアントの閾値フォルダ                                            |
| **partName**  | `base-w1`, `mid-c2` 等         | レベル・種類・位置番号をハイフン結合                                        |

partName の構成：

| 構成要素         | 値                              | 説明                  |
| ------------ | ------------------------------ | ------------------- |
| **level**    | `base` / `mid` / `top` / `fence` | 1階・中層・屋上・フェンス       |
| **type**     | `w` / `c`                      | 壁（wall）または角（corner） |
| **position** | `1`, `2`, `3`, `4` …            | ポリゴン頂点インデックス + 1    |

位置番号を持たないパーツ：

```
roofprop         塔屋
ceil             屋上マテリアル用
floor            地面マテリアル用
tile             タイルオブジェクト（MODEL_MODULAR_GROUND 専用）
scaffold-wall    足場の辺パーツ（工事中表示専用。§19）
scaffold-corner  足場の角パーツ（工事中表示専用。§19）
crane-base       クレーン最下段（工事中表示専用。§19）
crane-mid        クレーンの繰り返しセグメント（工事中表示専用。§19）
crane-top        クレーン頂部（工事中表示専用・実寸スケールなし。§19）
```

工事中表示専用パーツ（scaffold-\* / crane-\*）は、通常の prefix（`a{variant}` / `b{bd_type}`）に加えて、
全建物共通の**標準パーツ置き場 `Models/Buildings/common/`** へのフォールバックを持つ（§19.2）。

道路パーツのリソースパス：

```
Models/Paths/p{path_variant}/{partName}
```

partName: `body`, `line`, `sidewalk`, `tree`

Models/Buildings/b16/500/base-c1       1階角1

| 種類 | 数 | 説明 |
|---|---|---|
| 1階壁 (base-w1〜4) | 4 | 1階の各辺 |
| 1階角 (base-c1〜4) | 4 | 1階の各頂点 |
| 中層壁 (mid-w1〜4) | 4 | 中層の各辺 |
| 中層角 (mid-c1〜4) | 4 | 中層の各頂点 |
| 屋上壁 (top-w1〜4) | 4 | 屋上の各辺 |
| 屋上角 (top-c1〜4) | 4 | 屋上の各頂点 |
| 屋上面マテリアル (ceil) | 1 | ポリゴン塗りつぶし用 |
| 塔屋 (roofprop) | 1 | 屋上装飾 |

| 種類 | 数 | 説明 |

| タイルオブジェクト (tile) | 1 | 畑・庭など（`MODEL_MODULAR_GROUND` 専用） |

## 4. 外観バリアントの選択

### 4.1 バリアント番号の計算

`visual_variant`（0.0〜1.0）を 1000 倍して整数化する。

```
variant_number = floor(visual_variant × 1000)     → 0 〜 1000
```

### 4.2 閾値フォルダの選択ルール

閾値フォルダ名（`0`, `250`, `500`, `750` 等）は閾値を表す。
自身の `variant_number` 以下で最も大きい閾値フォルダを選ぶ。
閾値 `0` のフォルダは必ず用意する。

選択方法：標準閾値候補（0, 100, 200, ..., 1000）の中から `mid-w1` パーツが存在するものを探し、`variant_number` 以下で最大のものを選ぶ。

**例：** `variant_number = 600`、フォルダ `0`, `250`, `500`, `750` が存在 → **500** を選択。

### 4.3 レベル間のバリアント整合性

閾値フォルダが決まると、建物全体（1階・中層・屋上）で同じフォルダからパーツを取得するため、レベル間の閾値は自動的に一致する。

1. 中層壁1（`mid-w1`）が存在する閾値フォルダを確定 → これが建物全体の閾値になる
2. 該当フォルダに `mid-w1` が存在しない場合：
   - `MODEL_MODULAR_GROUND` 以外 → **白い箱フォールバック**
   - `MODEL_MODULAR_GROUND` → suffix を `0` とし、フェンス・地面パネル・タイルオブジェクトの描画を継続する

### 4.4 位置番号のフォールバック

指定位置のパーツがない場合は **位置1** にフォールバック。
壁3（`w3`）がない → 壁1（`w1`）を使う。

## 5. フォールバック階層

すべて同一の閾値フォルダ内でフォールバックする。

```
指定レベル・指定位置のパーツ（例: top-w3）
    ↓ ない場合
位置1のパーツ（同じレベル）: top-w1
    ↓ ない場合
中層レベルの同じ位置のパーツ: mid-w3
    ↓ ない場合
中層レベルの位置1のパーツ: mid-w1
    ↓ ない場合
白い箱（底面ポリゴンを高さまで押し出した直方体）
```

## 6. 壁パーツの配置

### 6.1 基本考え方

壁パーツは辺に沿って並べる。1つの辺に複数パーツが並ぶとき、隙間ができないように X 方向（辺の長さ方向）に引き伸ばして埋める。

### 6.2 パーツの座標系と寸法

壁パーツは以下を仮定する：

- ローカル X 軸 = 辺の長さ方向、Y 軸 = 高さ方向、Z 軸 = 外壁の奥行き
- 原点 = 片端の下端角

パーツのメッシュバウンディングボックスから元の寸法を取得する。

### 6.3 スケールと配置の方針

壁パーツは**高さのみ**を目標高さ（通常の階は階高 floorHeight、最上階は後述の top階実高）に合わせて**Y方向スケール**する。幅（X）と奥行き（Z）はスケールせず、モデリング時の実寸（メートル単位）のまま使用する。**等方スケールではない**点に注意。

パーツの著作幅を1ユニットとして、両端の角パーツが占める分を差し引いた「有効長」に何個の壁パーツが入るか求める。
端数分は X 方向に均等に引き伸ばして隙間を埋める。

ただし、辺の長さが両端の角パーツのアーム長合計以下の場合は、有効長が存在しないため壁パーツは配置しない。この場合、両端の角パーツのみを配置して隙間を埋める。

**旧規格パーツの互換描画**: XZ実寸が 0.3m 未満のパーツは、旧規格（1×1で作成して階高で等倍スケールする前提）のアセットとみなし、従来どおりの等方スケール（高さを目標高さに合わせ、幅も同率で拡大）で描画される。この場合は警告ログが出力される。新規パーツは必ず実寸で作成すること（[[I_建物パーツ作成マニュアル]]）。

**top階の実高**: 最上階専用の壁パーツ（top-w1）が実在する（mid へのフォールバックではない）建物では、最上階はY方向スケールを行わず**パーツの著作高さのまま**描画する。これにより背の高い装飾的な最上階（クラウン）を表現できる。この場合、躯体の描画高さは `(floors − 1) × floorHeight + top階の実高` となり、屋根・塔屋・コライダーの高さもこれに追従する。top-w1 が無い建物では従来どおり全階が階高で、躯体高さは `floors × floorHeight`。

各壁ユニットは、変換行列（位置・回転・スケール）をメッシュの全頂点に適用して配置する。
回転はモデルの X 軸を辺の方向に向ける。

## 7. 角パーツの配置と変形

### 7.1 基本考え方

角パーツは各頂点に1つ配置する。2つの辺ベクトルから内角を計算し、その角度に合わせてパーツを向ける。

### 7.2 内角の計算

角の頂点とその前後の頂点から2つの辺ベクトルを作り、符号付き角度から内角を求める。
CCW ポリゴンでは凸頂点の内角は 0°〜180°。
凹頂点（180°超）は警告しつつ処理を続行する。

### 7.3 向きの決定

2つの辺ベクトルの二等分線（bisector）方向に角パーツの正面を向ける。

### 7.4 ボーン変形（SkinnedMeshRenderer がある場合）

角パーツがボーンを2本持つ場合、90° を基準に作成されたモデルを任意の角度に変形できる。

ボーン構造：
- `Bone`（bones[0]）：左側の壁方向
- `Bone.001`（bones[1]）：右側の壁方向

変形の考え方：
- 90° からのズレ（angleDiff = 内角 − 90°）を求める
- 各ボーンを angleDiff の半分ずつ Y 軸周りに回転させる
- 左ボーンは +halfDiff、右ボーンは −halfDiff
- ボーンの開き角が内角と一致するように調整される

ボーン変形後のメッシュは `SkinnedMeshRenderer.BakeMesh()` でジオメトリを確定させる。
これは最終的なメッシュ結合（ベイク）とは別の、ジオメトリ準備の段階である。

### 7.5 静的メッシュ（ボーンなし）の場合

ボーンがない角パーツは 90° 専用。内角が 90° から離れていても変形せず、そのまま配置する。

### 7.6 スケール

角パーツは壁パーツと同じ規則でスケールする: 高さのみを目標高さ（通常の階は階高、top階は top階実高）に合わせて**Y方向スケール**し、アーム長（XZ）はモデリング時の実寸のまま使用する。壁パーツの配置開始・終了オフセットは角パーツのメッシュ頂点から検出した実寸アーム長をそのまま使う。

旧規格（XZ実寸が 0.3m 未満）の角パーツは、従来どおり目標高さの等方スケール（アーム長 = メッシュのアーム長 × 目標高さ）で互換描画される。

## 8. 屋根の生成

model_type に応じて、異なる屋根ビルダーが使用される。

### 8.1 平屋根（MODEL_MODULAR_FLAT）

底面ポリゴンと同じ形状の水平ポリゴンを建物最上部に配置する。
マテリアルは `{prefix}-ceil_{suffix}` パーツから取得する。該当パーツが存在しない場合は、壁面マテリアル等の他の配置済みパーツの有効なマテリアル、または建物全体のデフォルトマテリアルを使用する。
ポリゴンの三角形分割は耳切り法（ear clipping）を用い、失敗時はファン型にフォールバックする。

### 8.2 住宅風三角屋根（MODEL_MODULAR_HOUSE）

建物底面を少し拡張したポリゴンから棟線を求め、二段構成で屋根を押し出してメッシュ化する。
棟線の両端を内側にセットバックし、底面の各頂点を棟線へ射影することで屋根の傾斜面を生成する。
L字建物にも対応する。

### 8.3 切妻屋根（MODEL_MODULAR_GABLE）

壁・角・地面パネル・基盤・塔屋の生成は MODEL_MODULAR_FLAT と同一で、屋根だけを切妻屋根に差し替える。

1. 建物底面を軒の出（0.4m）だけ外側にオフセットしたポリゴンを屋根の軒線とする。
2. 軒線ポリゴンの**最小面積外接矩形**を求め、その長辺方向を棟線方向、短辺の半分を半幅とする。
3. 棟の高さ（軒からの立ち上がり）は `半幅 × 0.5`（勾配 1:2）で、0.6m〜5.0m にクランプする。
4. 棟線は妻側の端まで（外接矩形の長辺いっぱいに）伸ばす。軒線の各頂点を棟線に射影し、
   軒線と棟線を結ぶ四辺形を張ると、平側は二枚の勾配面に、妻側は棟側が 1 点に退化して
   **垂直な三角形（妻壁）**になる。これが住宅風三角屋根（§8.2、妻側も傾斜する寄棟状）との違い。
5. 軒下から屋根裏が透けないよう、軒の高さに下向きの天井面（耳切り法で三角形分割、失敗時はファン型）を張る。

マテリアルは平屋根と同じく `{prefix}-ceil_{suffix}` パーツから取得し、無ければ他の配置済みパーツの
有効なマテリアル、さらに無ければ建物全体のデフォルトマテリアルにフォールバックする。
棟線方向を決定できない退化ポリゴンでは平屋根にフォールバックする。

## 9. 地面パネルと基盤

### 9.1 地面パネル

底面形状のポリゴンを高さほぼ 0 の位置に配置する（Zファイティング回避で微小量だけ浮かせる）。

**地面パネルはマスターデータの `draw_floor=yes` の建物でのみ描画する（オプトイン。未設定は描画しない）。**
描画時のマテリアルは `floor` パーツから取得し、解決順は **`a{variant}` → `b{bd_type}` → `common`** の
フォールバックチェーン（工事系パーツと同じ規約。`common` は suffix フォルダを挟まず
`Models/Buildings/common/floor`）。**どこにも `floor` パーツが無ければ地面パネルは描画しない**
（既定建物マテリアルにはフォールバックしない）。これにより、地面パネルが不要な地面アセット
（例: `tile` パーツのみのソーラー発電所）に意図しないスラブが敷かれることを防ぐ。
この仕様はモジュラー建物・既成建物（プレビルド）で共通。

通常の建物では建物の底面ポリゴン（`footprint`）に対して水平な地面パネルを生成する。
ただし超近景（Dynamic）LODセルでは、水平ではなく地形の傾斜に沿った面として生成する（10.4参照）。
このとき、外周の頂点だけで面を張ると区画内部の起伏を拾えず地形を突き抜けるため、ポリゴンを
三角形分割したうえで一定長（既定6m）を超える辺を中点分割して内部頂点を作り、外周・内部を
問わず全頂点を地形標高に合わせる（中点は辺単位で溶接され、隣り合う三角形の間に隙間はできない）。

### 9.2 基盤（コンクリート基盤）

傾斜地では建物が土地区画の基準標高（§2.4）の水平面に接地するため、谷側では底面と地形の間に
隙間ができて建物が浮いて見える。この隙間を埋めるため、建物の底面ポリゴン（`footprint`）を
Y方向に押し出した柱状のコンクリート基盤を生成する。

- **対象** — MODEL_MODULAR_FLAT / HOUSE / GABLE のみ。
  MODEL_MODULAR_GROUND・MODEL_PREBUILT・MODEL_PORT は基盤を生成しない
  （§2.4 の接地規則で地形標高に直接接地する。土地区画の形状を押し出すこともしない）。
- **形状** — 上面 = 建物の接地面（ローカルY=0。地面パネルのわずかに下）、
  下面 = 底面頂点でサンプリングした最低地形標高の5m下（最低でも接地面の10m下）。
  頂点間で地形が局所的に落ち込んでも突き抜けないよう、下面には余裕を持たせている。
- **UV** — 上面・側面ともワールドスケール（10mで1タイル）。側面のUは外周に沿った累積距離で、
  辺をまたいでもタイリングが連続する。
- **マテリアル** — 全建物共通のコンクリートマテリアル `Resources/COMMON_CONCRETE`
  （未配置時は警告を出してデフォルト建物マテリアルにフォールバック）。
- 工事中（§19.3）は同じ形状を土マテリアルで生成する。

## 10. フェンス（fence）の配置

### 10.1 配置対象ポリゴン

フェンスは建物の底面ポリゴンではなく、**土地区画（parcel）のポリゴン**の形状に沿って配置する。
土地区画の頂点列を `fenceFootprint` とする。

### 10.2 レベル

フェンスは `fence-w*`（壁）と `fence-c*`（角）のパーツを使用する。
配置ロジック・角の変形・フォールバック階層は `base` / `mid` / `top` と同じである。

### 10.3 スケール

フェンスは**Y方向にはスケールしない**。元のメッシュサイズのまま配置する。
X方向（辺の長さ方向）については、角パーツが占める分を差し引いた有効長に対して、壁パーツを並べて隙間を埋める。端数分はX方向に引き伸ばす。

### 10.4 地形追従

フェンスと地面パネルとタイルオブジェクトは、**超近景（Dynamic）LODセルの場合のみ**、配置場所の地形に沿って曲げる。それ以外のセル（NearやFarセルなど）に属する場合は、変形は行わず、水平な状態で配置される。この地形追従は**すべての model_type の敷地装飾**が対象である。傾斜地対応の建物（MODEL_MODULAR_FLAT / HOUSE / GABLE）は建物本体こそ基準標高（§2.4）の水平面に接地しコンクリート基盤（§9.2）で谷側を埋めるが、その敷地装飾（フェンス・タイル・地面パネル）は地形に追従させる。追従の基準高さは建物 `center_point` の配置高さ（傾斜地対応の建物では §2.4 の基準標高、それ以外では地形標高）で、建物GameObjectの配置高さと一致する。

Dynamicセルかどうかの判定はメッシュ生成器側では行わない。ロード処理（`BuildingManager`）が確定済みのティアを `isDynamic` 引数としてメッシュ生成器に渡す。LODロード中はティア表の更新がロード完了後になるため、生成器側からティア表を参照すると古い値を読んでしまうからである。

各メッシュの頂点に対し、その頂点の水平位置（XZ座標）での地形標高を `HeightmapTextureManager.GetTerrainHeight`（建物GameObjectの配置高さと同じ取得経路）で取得し、頂点のY座標をその標高に合わせる。基準高さは建物の `center_point` 位置の地形標高であり、建物GameObjectがこの高さに配置されることを前提として、各頂点のローカルY座標を「頂点位置の地形標高 − center_point位置の地形標高」を基準にローカル座標化する。

フェンスの場合、元のメッシュ頂点の相対的な高さ関係（上端が下端より高い状態）は維持する。つまり、頂点位置の地形高さに元のローカルY（スケール適用後）を加算した値を新しいY座標とする。

地面パネルの場合、ポリゴンを三角形分割したうえで長辺（既定6m超）を中点分割して内部頂点を作り、外周・内部を問わず各頂点でその位置の地形高さを取得し、center_point位置の地形高さを基準としてローカル座標化する。これにより地面パネルは水平ではなく地形の傾斜に沿った面になり、区画が大きくても内部の起伏に追従して地形を突き抜けない。

タイルオブジェクトの場合、まずすべてのタイルを平面上に配置してから、各タイルメッシュの頂点をフェンスと同様に地形に合わせて変形する（元のメッシュ頂点の相対的な高さ関係を維持したまま、頂点位置の地形高さを加算する）。

建物はDynamic地形のロード完了より先に生成されることがあるため、地形ロード完了後（およびDynamic地形タイルの更新時）に、Dynamicセル内の建物はメッシュごと再生成され、最新の地形に追従し直す（[[E_LOD処理]]参照）。

## 11. MODEL_MODULAR_GROUND の処理

`MODEL_MODULAR_GROUND` は畑や庭など、建物の概念がない地面アセットに適用するモデルタイプである。

### 11.1 描画対象

`MODEL_MODULAR_GROUND` の場合、以下のパーツのみを描画する。

- **フェンス**（`fence-w*` / `fence-c*`）
- **タイルオブジェクト**（`tile`）— パーツが存在する場合のみ
- **地面パネル**（`floor`）— マスターの `draw_floor=yes` かつ `floor` パーツが解決できる場合のみ（§9.1）

建物本体の壁・角・屋根・塔屋は一切描画しない。

### 11.2 コライダー

クリック判定用のコライダーは、建物の底面ポリゴンではなく**土地区画のポリゴン形状**で生成する。

### 11.3 フェンスと地面パネルの形状

フェンスと地面パネルは、建物の底面ポリゴンではなく、該当建物が属する土地区画のポリゴン形状に基づいて生成する。
土地区画のポリゴンは `BuildingSummary.parcel_id` から `ParcelManager` を介して取得する。

### 11.4 タイルオブジェクトの配置

`tile` パーツ（`Models/Buildings/{prefix}/{suffix}/tile`）が存在する場合、底面エリアにタイル状に敷き詰める。パーツが存在しない場合は無視し、フェンス（と、`draw_floor=yes` なら地面パネル）のみを描画する。

**配置アルゴリズム:**

1. 底面エリアのポリゴン（フェンス・地面パネルと同じく土地区画ポリゴン）のAABBを計算する
2. `tile` パーツのメッシュバウンディングボックスからサイズ（X, Z）を取得する
3. AABBの端から、タイルサイズを1ステップとしてグリッド上に順次並べる（スケール変更なし）
4. 各グリッド位置について、タイルの中心点がポリゴン内側にある場合のみ配置する（ray casting による内外判定）
5. これにより、台形や三角形など任意の形状のポリゴンに対応できる

**配置順序と地形追従:**

タイルはまず平面上（Y座標を統一して）に配置し、すべての並べ終わった後に、Dynamicセルの場合のみ地形に合わせてメッシュを変形する。配置時に個別に地形高さを適用するのではなく、平面上に並べてから全体を変形する（10.4参照）。

---

## 12. 塔屋（roofprop）の配置

### 12.1 配置条件

パーツ `{prefix}-roofprop_{suffix}` が存在する場合のみ配置。なければ配置しない。

### 12.2 位置

`visual_variant2` をシード値として、屋上面上の位置を決定する。
屋上面の重心を中心に、シードから角度と距離を計算してオフセットした位置に置く。

### 12.3 角度

塔屋の向きは底面ポリゴンの最初の辺（頂点0 → 頂点1）の方向に合わせる。

### 12.4 高さ

屋上パネルと同じ高さ（躯体の描画高さ。§6.3「top階の実高」参照。通常は `floors × floorHeight`）に配置する。

---

## 13. 最上階のみの処理（building_shape = SHAPE_FULL）

`building_shape = SHAPE_FULL` の建物は、モジュラーパーツ組み立て方式を使うが、階の範囲が異なる：

- **最上階のみ**を処理する（1階・中層階はスキップ）
- 最上階では **屋上レベルの壁・角パーツ（top-w*, top-c*）** を使用する
- 屋上面マテリアル・塔屋も通常の MODEL_MODULAR_FLAT と同様に配置する

すなわち、SHAPE_FULL は「1階分の屋上レベル壁・角パーツ + 屋上面 + 塔屋」という構成になる。

---

## 14. メッシュの結合とベイク

壁・角・屋上・地面・塔屋のすべてのパーツの配置が完了した後、**一括で**メッシュを結合する。

1. 各パーツを `CombineInstance` に変換（サブメッシュごとに個別のインスタンス）
2. `Mesh.CombineMeshes()` でサブメッシュ構造を維持したまま結合
3. 法線とバウンディングボックスを再計算
4. 結合後、同じマテリアルのサブメッシュを統合してドローコールを最小化
5. 一時メッシュを解放

角パーツのボーン変形（BakeMesh）はあくまで個別パーツのジオメトリ準備であり、この最終的な結合ベイクとは別物である。

---

## 15. コライダー

クリック判定のため、底面ポリゴンを建物高さまで押し出した形状の `MeshCollider` を生成する。

- **下面**：CCW の三角形ファン（法線下向き）
- **上面**：CW の三角形ファン（法線上向き）
- **側面**：各辺について、上下の頂点4点で構成する四角形を2つの三角形に分割

高さは躯体の描画高さ（§6.3「top階の実高」参照。通常は `floors × floorHeight`）である。

`MODEL_MODULAR_GROUND` の場合は、土地区画のポリゴン形状でコライダーを生成し、高さは `floorHeight` とする。

`MODEL_PREBUILT` の場合は、描画された実高さ（積み上げ高さ + top の実寸高さ）を使用する。top が論理高さ（`floors × floorHeight`）をはみ出す建物でも全体をクリックできるようにするためである。

---

## 16. 1階あたりの高さ

マスターデータの `height_per_floor` を使用する。
設定されていなければ `LocalConstants.FLOOR_HEIGHT`（デフォルト: 4.0）を使う。

## 17. 既成建物（MODEL_PREBUILT）

通常の建物とは全く異なる形状（電波塔、オブジェ、銅像、観覧車など）や、モジュラー組み立てに向かない完成済みモデルの建物に適用する。
base-prebuilt / mid-prebuilt / top-prebuilt の3種類のパーツを下から積み上げて組み立てる。

### 17.1 パーツの意味とスケール規則

| パーツ | 個数 | Yスケール | XZスケール | 用途 |
| --- | --- | --- | --- | --- |
| base-prebuilt | 0〜1 | 階高に合わせる | なし（実寸） | 1階部分（エントランス等） |
| mid-prebuilt | 0〜N回繰り返し | 階高に合わせる | なし（実寸） | 繰り返しフロア1階分 |
| top-prebuilt | 0〜1 | **なし（実寸）** | なし（実寸） | 頂部。尖塔や、完成済みモデル丸ごと |

base / mid は高さが階高（`height_per_floor`）になるよう**Y方向のみ**スケールされる。幅・奥行きは実寸のまま。
top は一切スケールされず、モデリング時の実寸のまま配置される。

### 17.2 積み上げ規則

- base と top はそれぞれ論理階数（floors）のうち **1階分を消費**する。mid は残りの階数分繰り返される: `midCount = max(0, floors − (baseあり?1) − (topあり?1))`
- 各パーツのY位置は **実際に描画したパーツの累積高さ**で決まる。base / mid のファイルが存在しない建物では何も積まれないため、top が地面（y=0）に接地する。**完成済みの建物モデルを top-prebuilt 1つだけで表現できる**（例: 完成済み4階建て庁舎モデル、風力発電所）。
- top の実寸が1階分より大きい場合、描画上の建物はシミュレーション上の高さ（`floors × 階高`）より高くなるが、これは仕様として許容する。コライダーは描画された実高さに合わせる（§15）。
- 積み上げの天面を塞ぐパネルは生成しない。prebuilt パーツはモジュラーの壁パーツと違い完成された3Dモデルなので、上から見える面はモデル側で閉じておくこと。
- 土地区画の外周フェンス（fence-w / fence-c）・敷地内のタイル（tile）・地面パネル（floor）は、モジュラー建物と共通のロジックで配置される。フェンス・タイルは該当パーツを置いた場合のみ描画されるオプション要素。地面パネルはモジュラーと同じく**マスターの `draw_floor=yes` の建物だけ描画**し、マテリアルは `floor` パーツを `a{variant}`→`b{bd_type}`→`common` の順で解決する（無ければ描画しない。§9.1）。既成建物は建物中心位置の地形標高に接地するため、超近景セルではフェンス・タイル・地面パネルが地形に追従する（MODEL_MODULAR_GROUND と同じ扱い）。
- 各パーツはFBXのピボット位置に依存せず積めるよう、メッシュ下端（bounds.min.y）を各段の床面に揃えて配置される。XZはモデルの原点を建物原点（center_point）に重ねる。
- FBXが複数オブジェクトで構成されていても、全メッシュがノードのTransform込みで結合されて描画される。

### 17.3 フォールバック

3種類のパーツがいずれも存在しない場合は白い箱（BuildingMeshBuilder.GenerateSimpleBuilding）にフォールバックする。

## 18. 海岸の岸壁（MODEL_PORT）

`MODEL_PORT` は、海岸土地区画（`PARCEL_SHORE`）に立地する港湾（`BUILDING_PORT`）の建物に適用するモデルタイプである。港の岸壁（コンクリートで固められた水際の壁）をイメージした、厚みのある板状のスラブを生成する。

底面形状としては `SHAPE_FULL`（[[C_建物形状]]）、すなわち土地区画ポリゴンそのものを底面とする方針を前提とするが、メッシュの組み立て方は他の `MODEL_MODULAR_*` とは大きく異なる。モジュラーパーツ（壁・角）は一切使わず、底面ポリゴンを海岸線でカットした形状を上下に押し出して、厚みのあるスラブをプロシージャルに生成する。さらに、`visual_variant`（1）・`visual_variant2`・`visual_variant3` を外観バリアント閾値（§4）の選択ではなく、岸壁の形状を決める**幾何パラメータ**として消費するのが最大の特徴である。

### 18.1 入力データ

岸壁の生成には次の3種類の情報を用いる。

- **底面ポリゴン** — 建物 Agent の `polygon`。`SHAPE_FULL` なので土地区画のポリゴンと一致する。海岸土地区画は作成時に海岸線でクリップされている（[[B_土地形状]] B.5）ため、このポリゴンの**海側の境界は海岸線の曲線そのもの**になっている。陸側の境界は道路に面した直線的な区画辺である。
- **海岸線ポリゴン** — `GET /api/v1/terrain/coastline` で取得する、陸地の境界を表す GeoJSON ライクなポリゴン（ワールド座標、マップ中心が原点。詳細は[[D_地形形状]]）。底面ポリゴンのどの辺が「海側（海岸線）」でどの辺が「陸側」かを判定するために用いる。海岸線は `init_game` 時に確定して以降不変なので、フロントエンドは初回に一度取得してキャッシュしておけばよい。
- **visual_variant1 / visual_variant2 / visual_variant3** — それぞれ岸壁の左端の突き出し量・右端の突き出し量・高さを表す（0.0〜1.0）。他のモデルタイプのように閾値フォルダの選択には使わない。

### 18.2 海岸線エッジの特定

底面ポリゴンの外周頂点列のうち、海岸線ポリゴンの境界と一致（十分に近接）する連続した区間を「**海側境界（海岸線エッジ）**」とみなす。海岸線エッジの両端の頂点を、岸壁の**左端 A** と **右端 B** とする。残りの外周（陸側の区画辺）を「陸側境界」と呼ぶ。

海岸線エッジは海岸線の曲線をなぞった折れ線なので、入り組んだ海岸ではギザギザの形状になる。岸壁はこの海岸線エッジを基準に、後述の突き出し処理で海側へ張り出した形に変形させる。

### 18.3 突き出し（visual_variant1 / visual_variant2）

陸側境界の端点（左端 A・右端 B）を直線で結んだ線分を「**最大突き出し線（弦）**」とする。これは海岸線の入り江を直線でショートカットした基準線であり、岸壁が最も海側へ張り出したときの海側境界に相当する。

海岸線エッジ上の各頂点を、元の海岸線上の位置（突き出し量 0.0）と、最大突き出し線（弦）上の対応点（突き出し量 1.0）との間で線形補間して移動させる。突き出し量は左右で独立に与え、左端 A 側では `visual_variant1`、右端 B 側では `visual_variant2` を用い、その中間の頂点はエッジ沿いの位置に応じて両者を線形補間した値とする。

これにより、

- 両方 0.0 → 海岸線の曲線をそのままなぞった岸壁
- 両方 1.0 → 海岸線を無視し、弦に沿った直線的な岸壁（土地区画とほぼ同じ形状）
- 片側のみ大きい → 一方の端だけが海側へ張り出した非対称な岸壁

といった形状を表現できる。突き出し線は陸側端点を結ぶ弦なので、岸壁は常に土地区画の範囲内に収まる。

突き出し処理後の「陸側境界 + 変形した海側境界」で構成される閉じたポリゴンが、岸壁スラブの新しい底面（以下、岸壁フットプリント）となる。

### 18.4 岸壁スラブ（厚みのある板）の生成

岸壁フットプリントを上下に押し出して、厚みのあるスラブを作る。

- **上面** — 岸壁フットプリントを高さ `H = visual_variant3 × 10m` の水平ポリゴンとして配置する。基準（0m）は海面であり、`visual_variant3 = 0.0` で海面ぴったり、`1.0` で海面から 10m の高さになる。三角形分割は耳切り法（ear clipping）を用い、失敗時はファン型にフォールバックする（§8.1 と同じ）。
- **側面** — 岸壁フットプリントの各辺について、上面（高さ `H`）から下面まで垂直な四角形を張る。
- **下面** — 各頂点の水平位置（XZ座標）での地形標高（＝海底の高さ）を `HeightmapTextureManager.GetTerrainHeight` で取得し（§10.4 と同じ取得経路）、その高さまでスラブを下げる。これにより `visual_variant3 = 0.0`（上面が海面）の場合でも、上面と海底の差分だけ厚みが生まれ、岸壁が「厚みのある壁」として見える。

生成する全頂点は `center_point` 基準の相対座標とし、配置時に `center_point` のワールド座標を足して最終位置を決める（§2.4 と同じ）。

### 18.5 塔屋（roofprop）の配置

パーツ `{prefix}-roofprop_{suffix}` が存在する場合のみ、岸壁の上に塔屋を1つ配置する。`visual_variant` をシードに位置を散らす通常の塔屋（§12）とは異なり、次の固定ルールで配置する。

- **位置** — 岸壁フットプリントの重心。
- **角度** — 海側境界（海岸線エッジ／弦）の方向に合わせる。岸壁の向きに沿わせることで、岸壁の中央に水際と平行に置かれる。
- **高さ** — 上面と同じ高さ `H`。

`visual_variant` は岸壁の幾何（突き出し・高さ）に消費されるため、閾値フォルダ `suffix` の選択には使えない。塔屋を含むパーツは閾値 `0` のフォルダから取得する。

### 18.6 マテリアルとコライダー

- **マテリアル** — 上面は `{prefix}-ceil`、側面・下面は `{prefix}-floor` のマテリアルを流用する。該当パーツがなければ建物全体のデフォルトマテリアルを使う（§8.1・§9 と同方針）。
- **コライダー** — クリック判定のため、岸壁フットプリントを高さ `H` まで押し出した形状の `MeshCollider` を生成する（構成は §15 に準じる）。

## 19. 工事中（STATUS_CONSTRUCTING）の建物表示

### 19.1 分岐とデータフロー

status が `STATUS_CONSTRUCTING` の建物は、`model_type` に関わらず完成品のメッシュを生成せず、専用の「工事現場」メッシュ（土マウンド + 足場 + クレーン）で描画される。分岐は `BuildingMeshBuilder.Generate` の冒頭（model_type 分岐より先）にあり、Near/Far・詳細生成ワーカー・直接呼び出しのすべての生成経路をカバーする（実装は `ConstructingBuildingMeshBuilder`）。

工事の進捗は API の `construction_progress`（= 調達済み建設体積の百分率。サーバー計算値）から取得する。

```
progress01  = clamp01(construction_progress / 100)
builtFloors = clamp(ceil(progress01 × floors), 1, floors)
```

- **0% や未取得（null）でも builtFloors=1** とし、着工済みの現場が視認できるようにする
- バックエンドは建設中に進捗が増えたエポックで建物の version を上げるため、毎エポックの差分ロードで再生成され、足場・クレーンが伸びていく
- 完成（STATUS_ACTIVE への遷移）でも version が上がり、通常メッシュへ自動的に切り替わる

なお、旧仕様の「完成品メッシュに黄色い建設中マテリアルを上塗りする」表示は廃止された。工事中もオブジェクトは常に表示され、ホバーハイライトは通常ステータスと同様に機能する。

### 19.2 パーツのフォールバック（標準パーツ common）

工事中表示専用パーツ（scaffold-\* / crane-\*）は、以下の順で解決される。

```
1. Models/Buildings/{prefix}/{suffix}/{partName}
     prefix は既存の解決（a{variant} → b{bd_type}）、suffix は標準閾値候補（0,100,...,1000）
     のうち variant_number 以下でパーツが存在する最大値
       ↓ ない場合
2. Models/Buildings/common/{partName}   ← 標準パーツ（全建物共通）。common は外観バリアント
     閾値の概念を持たないため suffix フォルダを挟まず直接置く
       ↓ ない場合
3. そのパーツをスキップ
```

`common/` は「バリアント・建物タイプ固有のモデルを用意しなくても、全建物で共通の足場・クレーンが出る」ためのフォールバック先である。

### 19.3 土マウンド（敷地覆い）

敷地（土地区画のポリゴン。区画が取得できない場合は建物底面）全体を、厚みとランダムな凹凸を持つ土で覆う。マテリアルは `Resources/ConstructionDirt`（未配置時は `ConstructionMaterial`（黄色）→ デフォルト建物マテリアルにフォールバック）。

- **細分化** — ポリゴンを耳切り法で三角形分割した後、一定長を超える辺を中点分割して凹凸用の内部頂点を作る（中点は辺単位で溶接され、T字接合の隙間はできない）
- **上面の高さ** = 基本厚み + 土ノイズ × 境界フェード。土ノイズは多オクターブのPerlinノイズ（fbm）で、大きなうねりと細かい土塊を重ねる（パスの土ストリップと共通の `ConstructionMeshUtil.DirtNoise`）。境界フェードは「元ポリゴン境界までの距離」に比例し、**外周頂点では凹凸0**になるため隣接区画との隙間や Z-fighting が起きない。ノイズ入力はワールド座標なので再生成しても模様は安定する
- **外周スカート** — 上面の縁から地面（ローカルY=0）まで側面を張る
- **基盤** — 完成品と同じ「建物底面をY方向に押し出した土台」（§9.2）を土マテリアルで生成する（完成品に基盤が生成される model_type のみ。工事中→完成の切り替えで土台の有無が変わらない）
- **地形追従** — 超近景（Dynamic）セルではフェンス・地面パネル（§10.4）と同様に各頂点を地形に追従させる

### 19.4 足場（scaffold-wall / scaffold-corner）

建物底面ポリゴンの外周に足場を、進捗に応じた階数（builtFloors）分積み上げる。

- **配置は通常建物の壁・角と全く同じロジック**（`GenerateWallSegments` / `GenerateCornerSegment` / `GetCornerArmLengths`）を建物フットプリント上でそのまま使う。**角パーツのヒンジ（原点）はフットプリント頂点にちょうど一致**し、壁は両端を角パーツのアーム長ぶん空けて配置される（オフセットは一切しない）。角は内角に応じたボーン変形（§7.4）もそのまま効く
- scaffold-wall / scaffold-corner は全辺・全頂点で共通の単一パーツ（通常建物の base-w1〜4 のような位置別パーツではない）
- **フェンス（§10）と異なり、各階を階高になるようY方向のみスケールする**（XZは実寸）。各階を floorY = 階×階高 で生成し、builtFloors 段ぶん作る
- scaffold-corner が無い場合は壁のみ（両端の控除なし）。scaffold-wall が無い場合は足場全体をスキップする

### 19.5 クレーン（crane-base / crane-mid / crane-top）

論理階数が一定値（既定4階）以上の建物にのみ、タワークレーンを1基立てる。

| パーツ | Yスケール | 役割 |
| --- | --- | --- |
| crane-base | 階高に合わせる | 最下段1段分。無ければ省略される |
| crane-mid | 階高に合わせる | 繰り返しセグメント。残り段数分積まれる |
| crane-top | **なし（実寸）** | 頂部。ジブ・カウンターウェイト込み |

- **積み上げは「原点（モデルの y=0）＝接続点（下端）」基準**。crane-base / crane-mid はその上に伸びる高さが階高になるようY方向のみスケールし、crane-top は実寸のまま最上段の頂点（＝接続点）に原点を合わせて載せる。原点より下に張り出しのあるパーツでも段どうしの隙間が出ない（prebuilt の「メッシュ下端基準」とはここが異なる。crane 系は接続点を原点に置く前提で著作する）
- 総段数 = `builtFloors + 2`。進捗に連動して伸び、常に現在の足場より少し高く立つ
- crane-base と crane-mid が両方無い場合はクレーン全体をスキップする
- 位置は footprint 重心 + `visual_variant2` シードのオフセット、向きは最初の辺に合わせた Yaw（塔屋 §12 と同じ決め方）

### 19.6 天面（ceil）

施工済み階の天面を footprint 形状の水平パネルで塞ぐ（足場リングは中空なので、これが無いと建物内部が上から覗ける）。高さは `builtFloors × 階高`。マテリアルは ceil パーツ（`a{variant}→b{bd_type}→common` の順に解決）から取り、無ければデフォルト建物マテリアルにフォールバックする。

### 19.7 コライダーと既知の割り切り

- コライダーは建物底面ポリゴンを `max(builtFloors × 階高, 階高)` まで押し出した形状。クレーンのはみ出しはクリック対象外で許容する（prebuilt の top はみ出しと同じ思想）。敷地（土マウンド）のクリックは土地区画側のコライダーが担う
- `MODEL_MODULAR_GROUND`（畑・庭）と `MODEL_PORT`（岸壁）は土マウンドのみで、足場・クレーンは立てない。MODEL_PORT では敷地が海岸線を含むため土が海面上に描かれることがある（既知の制限）
