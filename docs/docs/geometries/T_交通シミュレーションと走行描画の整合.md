# T. 交通シミュレーションと走行描画の整合

## 責任の分離

コアは交通量、物理的な走行時間、停車時間、運行間隔を確定する。Unityは確定結果を道路・線路上の動きとして再現する。描画時計は経済時計から独立しており、計画中も車両は動くが経済状態は変わらない。カメラ位置、描画上限、フレームレートによって都市の経済結果が変化してはいけない。描画の渋滞や車両位置をコアへ書き戻さない。

平均速度は巡航速度ではない。300mを30秒で通過するという結果には、加速、カーブでの減速、前車への追従、停止が含まれ得る。平均速度で30秒走らせ、さらに停止を追加すると、同じ遅延を二重計上する。整合の基準は個々の瞬間速度ではなく、同じ区間と時間単位で測る通過数と平均所要時間である。

## 時間の契約

時間は秒、距離はmを描画用の境界契約にする。自由走行時間、混雑追加時間、駅停車時間を区別する。乗客の乗車待ちと運賃の時間換算は経路選択のコストであり、車両の運動に加算しない。駅間時間と停車時間は車両需要、実効運行間隔、乗客の乗車時間、Unityの走行で同じ計算結果を使う。

位置はパスID、進行方向、パス内の距離割合で指定する。停留所は最寄り端点へ移さずパス途中の位置として扱う。一方通行、途中の転回制約、往路と復路を区別する。表示上の地形高さはUnityのパス形状を正とし、下地経路の決定はコアを正とする。

## 流量と密度

定常状態では、区間内の平均台数は毎秒の流入台数と平均滞在時間の積になる。10秒に1台入り、30秒で抜ければ平均3台、60秒なら平均6台である。流量、速度、表示台数を独立した演出値にしない。日次交通量は活動時間で毎秒の流量へ換算する。

描画上限による間引きは表示の標本化であり、経済上の交通量を変更しない。時間を倍速にする場合は走行、停車、発車間隔を同じ倍率で変換する。台数だけを増やして前車追従を強めると、コアに無い渋滞を作るため避ける。

## 車間距離と実現可能性

前車が止まったら後車も止まり、予定へ追いつくために瞬間移動、すり抜け、制限速度超過を行わない。目標時間は一定区間・一定期間の平均として評価する。恒常的に一致しない場合は、車長、車間、流入量、容量、所要時間が両立しているかを検査する。道路ごとの独立した強制補正は下流から延びる車列を扱えない。

複数路線の合流や双方向単線の列車競合を厳密に扱うには、通過順序と待ち時間をコアの運行計画にも含める必要がある。Unityだけに信号閉塞を追加して経済上の時間と切り離さない。

## 実装と検証の記録

実装済みの範囲は以下のとおり。

| 対象 | 実装 |
| --- | --- |
| 公共交通の経路 | パス途中の停止位置と進行方向を持つ経路。往復・転回制約を考慮 |
| 走行時間 | 区間の始終速度と所要時間をAPIで共有。発着時は停止し、カーブでは減速 |
| 公共交通の混雑時間 | 道路の混雑を走行時間へ反映し、駅停車時間と分離 |
| 経済への反映 | 必要車両数・便数・乗車時間・待ち時間が同じ走行プロファイルを参照 |
| 編成描画 | バス、メトロ、中距離鉄道。車両調達数、編成両数、往復・駅停車を反映 |
| 一般車 | コアの自由時間・混雑時間・活動時間を取得。同一道路・方向・車線内で追従 |

一般車の時間制御は平均の目標であり、有限範囲の発生・到着や前車による遅れを含む通過数の厳密な保証ではない。曲率に応じた局所速度は公共交通で実装し、一般車は自由走行平均速度を上限とする近似である。交差点の競合予約、列車の閉塞・単線交換、バスと一般車の相互追従は未実装。これらの待ち時間を共有するには、コア側の運行・容量モデルも拡張する。

片方向の乗車時間は走行プロファイルに保持するが、既存の公共交通パスの所要時間スロットは方向別ではないため、乗客の経路計算には往復の平均時間を設定する。描画は各方向の時間をそのまま使う。

公共交通の描画用パス形状は0.5秒ごとに更新する。対象は描画可能な路線の経路とカメラ周辺のパスが重なる部分だけとし、無関係な道路・線路の点列は生成しない。路線がない場合や、運休・車両不足などですべての路線が描画対象外の場合は、周辺パスの検索も省略する。路線の更新時に対象経路を作り直すため、運行再開や路線削除にも追従する。

検証では同一パス上の停留所、一方通行、単線往復、曲線、停車、車両不足、運休・復旧、未ロード区間、都市切り替えを扱う。フレーム時間を変えても同じ描画時計で同じ位置になること、速度と台数が同じ時間基準を使うことを確認する。
