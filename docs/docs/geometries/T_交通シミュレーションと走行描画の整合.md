# T. 交通シミュレーションと走行描画の整合

## 責任の分離

コアは交通量、物理的な走行時間、停車時間、運行間隔を確定する。Unityは確定結果を道路・線路上の動きとして再現する。描画時計は経済時計から独立しており、計画中も車両は動くが経済状態は変わらない。カメラ位置、描画上限、フレームレートによって都市の経済結果が変化してはいけない。描画の渋滞や車両位置をコアへ書き戻さない。

平均速度は巡航速度ではない。300mを30秒で通過するという結果には、加速、カーブでの減速、前車への追従、停止が含まれ得る。平均速度で30秒走らせ、さらに停止を追加すると、同じ遅延を二重計上する。整合の基準は個々の瞬間速度ではなく、同じ区間と時間単位で測る通過数と平均所要時間である。

## 時間の契約

時間は秒、距離はmを描画用の境界契約にする。自由走行時間、混雑追加時間、駅停車時間を区別する。乗客の乗車待ちと運賃の時間換算は経路選択のコストであり、車両の運動に加算しない。駅間時間と停車時間は車両需要、実効運行間隔、乗客の乗車時間、Unityの走行で同じ計算結果を使う。編成は目標運行間隔より短い間隔では発車せず、1周の時間が余れば次の発車まで先頭の停留所で待つ。この待ちはコアの便数・線路の負荷とUnityの走行で共通である。

位置はパスID、進行方向、パス内の距離割合で指定する。停留所は最寄り端点へ移さずパス途中の位置として扱う。一方通行、途中の転回制約、往路と復路を区別する。表示上の地形高さはUnityのパス形状を正とし、下地経路の決定はコアを正とする。

## 流量と密度

定常状態では、区間内の平均台数は毎秒の流入台数と平均滞在時間の積になる。10秒に1台入り、30秒で抜ければ平均3台、60秒なら平均6台である。流量、速度、表示台数を独立した演出値にしない。日次交通量は活動時間で毎秒の流量へ換算する。

描画上限による間引きは表示の標本化であり、経済上の交通量を変更しない。時間を倍速にする場合は走行、停車、発車間隔を同じ倍率で変換する。台数だけを増やして前車追従を強めると、コアに無い渋滞を作るため避ける。

## 描画上の近似

一般車は同一道路・方向・車線内で前車に追従する。自由走行平均速度を上限とし、有限範囲の発生・到着や追従の遅れを含むため、通過数と目標平均時間の厳密な一致は保証しない。交差点の競合予約、列車の閉塞・単線交換、バスと一般車の相互追従は描画の対象に含めない。

## 公共交通の共有データ

停留所間の走行プロファイル `journeys` は区間の方向、始終速度、所要時間を持つ。コアの乗車時間・必要車両数・便数とUnityの走行は同じ結果を使う。道路の混雑時間と駅停車時間は分離する。

公共交通は下地の道路・線路と路線種別の上限速度を使い、カーブ・道路の坂で減速する。描画対象は路線経路とカメラ周辺が重なる範囲である。描画の具体的な経路・編成・時計は[車両の走行描画](O_車両の走行描画.md)、経済上の運行条件は[公共交通機関](../economics/6_公共交通機関.md)に定義する。
