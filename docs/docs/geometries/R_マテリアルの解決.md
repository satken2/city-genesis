# マテリアルの解決

メッシュの生成器が組み立てた面に、どのマテリアルの実体を割り当てるかの約束である。建物（[F_建物メッシュの生成](F_建物メッシュの生成.md)）・道路（[G_道路メッシュの生成](G_道路メッシュの生成.md)）・線路（[N_線路メッシュの生成](N_線路メッシュの生成.md)）・駅舎パス（[Q_駅舎パスのメッシュ生成](Q_駅舎パスのメッシュ生成.md)）が共通で従う。マテリアルの名前と、複数のモデルで実体を共有する方法は [P_マテリアル共有とエクスポート](P_マテリアル共有とエクスポート.md) に書く。

## マテリアルの出どころ

モデルを持つ部材は、パーツのプレハブが持つマテリアルを使う。形のパーツを持たない面（屋根面・地面パネル・妻壁・岸壁・オープンスペースの面など）は、形を使わずマテリアルだけを渡すパーツ（`ceil`・`floor`・`generic-wall`・`site_*` など）から取る。パーツによらない共通の面は、`Assets/Resources/` 直下の共通マテリアル（建物の既定の `BuildingMaterial`、基盤などのコンクリート `COMMON_CONCRETE`、工事現場の土 `ConstructionDirt`、倒壊の瓦礫 `CollapsedRubble`・`CollapsedRubbleBurned` など）を使う。`BuildingMaterial` はすべての代替の行き着く先で、建物のメッシュがマテリアル無しで出ることは無い。

地面パネルだけは「描かない」を選べる。マスターの `draw_floor` が有効な建物だけが対象で、`floor` パーツがどこにも無ければ既定のマテリアルへ落とさずに描かない。タイルだけを敷く施設に、要らない板を敷かないためである。駅舎パスの専有エリアの地面も、`floor` パーツの有無で同じように決まる。

## 建物とパスの違い

建物はプレハブのマテリアルを複製せずにそのまま使い、同じパーツを使う建物どうしで同じ実体を共有する。1棟を1つのメッシュに結合し、同じ実体を使う面をまとめて描画の回数を減らすので、名前が同じでも実体が別ならまとめられない。

パスはマテリアルの名前をキーにした共有のプールを必ず通す。`Assets/Resources/` 直下に同名の `.mat` があればそれを、無ければパーツのマテリアルを元に複製を作り、Z ファイティングを避けるために描画の順序を1つ後ろへずらして、名前ごとに1つの実体を共有する。交差点や歩道のつなぎ目のように通常の道路と見た目をそろえる面もこのプールを通し、プレハブのマテリアルを直接使わない。パスマスターの `body_material` は、そのバリアントの路面を代表するマテリアルの名前（`Assets/Resources/` 直下の `.mat`）で、交差点のアスファルトや遠景の板など、プレハブを持たない面に使う。

新しい生成器を書くときもこの2つの方式のどちらかに寄せ、生成器ごとに `Resources` からの読み込みや `new Material` を増やさない。

## 生成後の差し替え

ホバー・状態（計画中・工事中など）の色・地区の色分け・ヒートマップは、生成の後に表示モードの部品がレンダラーのマテリアルを差し替えて表し、モードを解除すると元に戻す（[Unity表示モード](../programs/Unity表示モード.md)）。ここで解決したマテリアルは素の見た目である。
