# 車両基地のメッシュ生成（MODEL_RAIL_YARD）

## 概要

鉄道車両基地のように「施設の敷地内に線路が敷かれ、その線路が施設の接続端子ノードへ収束する」建物の生成方式。実装クラスは `RailYardBuildingMeshBuilder`。

- 共通仕様（データフロー・底面形状・パーツ解決・敷地装飾・結合）は [[F_建物メッシュの生成]] を参照。本書はその差分のみを記述する。
- パーツの制作規格は [[I_建物パーツ作成マニュアル]] §4.9 を参照。
- 接地高は **center_point 位置の地形標高**（PREBUILT / PORT / MASHUP と同じ。`parcel.altitude` 接地・コンクリート基盤の対象外）。敷地内の線路・建屋はすべてローカルY=0の水平面に置かれ、地形の起伏には追従しない。
- モジュラーの壁・角パーツは使わない。建物本体は「線路ユニットパーツのプロシージャル配置」で構成される。

鉄道車両基地は走行網の接続端子ノード（`depot_node_id`。電化前提の施設では送電網と資格を併せ持つ**共用接続ノード**となり `infra_node_id` と同一。[[26_インフラ網]] §26.3）へ引き込み線路を溶接して使う施設であり、この生成方式は**敷地内の線路が端子ノードの位置へ滑らかに繋がって見える**ことを目的とする。

## 1. 入力データ

| 入力 | 用途 |
| --- | --- |
| `polygon`（建物底面。SHAPE_FULL のため土地区画と同形） | レイアウト導出の領域・コライダー・フォールバック時の白い箱 |
| `depot_node_id` / `infra_node_id` | 接続端子ノードの位置解決（depot 優先。共用ノードでは同一値） |
| `parcel_id` → 土地区画ポリゴン | 外周フェンスの敷地装飾 |
| `visual_variant` 系 | **不使用**（レイアウトはフットプリントとノード位置から決定的に決まる） |
| `floors` / `height_per_floor` | **不使用**（1階固定の施設。コライダー高さは固定値） |

端子ノードの位置は `PathManager` のノードキャッシュ（`GetNodeData`）から絶対座標で取得し、center_point 相対のローカルXZへ変換する。**ノードが未ロードの場合（テストシーンを含む）**は、バックエンドの初期配置ロジック（接道辺から最も遠い辺の中点。`crud_agents._connection_node_position`）を模して「前面の辺（頂点0→1）から最も遠い辺の中点」へフォールバックする。ユーザーが端子を移動していない限り両者は一致する。

## 2. レイアウト導出

すべての配置は次のローカル直交基底 **U / V** の上で決める。

- **U（線路方向）** = 底面重心 → 端子ノードの単位ベクトル（退化時は前面辺の法線）
- **V（横方向）** = U の左手垂直

1. 底面頂点を UV 座標へ射影し、V 方向の幅から並行線路の本数を決める：`本数 = clamp(floor((V幅 − 側方マージン×2) / 線路間隔) + 1, 1, 10)`（線路間隔 5m = 線路パスの width と同値）。行は V 方向に中央寄せで等間隔に並べる。
2. 各行について、底面ポリゴンを「V=一定の直線」で切った**弦**を求め、両端に端部マージン（2m）を取った範囲を線路の敷設可能範囲とする（凹形状では最小〜最大交点の弦を採る。敷地外へのはみ出しは許容し、フェンスで視覚的に収める）。
3. **最外側の線路を斜めの集約線として延ばし、ほかの留置線をその途中へ合流させる**。端子から横方向に遠い側を集約線の起点に選ぶ（同距離なら+V側）。集約線の勾配は横移動1mに対してU方向2mで、5m間隔の留置線の合流点はU方向10mずつずれる。
4. 留置線は集約線との交点の6m手前から曲がり、交点の4m先で集約線の接線へ合わせる。集約線を留置線ごとに重複描画しない。各線を端子へ個別にS字で運ぶこともしない。
5. 最後の合流点から端子手前6mのリード始端までは**共通の接続曲線1本**で結ぶ。端子が敷地中央にある場合も、集約線の末端からこの1本だけが横位置を合わせる。接続曲線のU長は `max(18m, 横ずれ×2)`。
6. 留置直線が6m未満、または曲線・集約線・接続線の中心線が敷地外へ出る計画は採用せず、本数を減らして再計画する。1本も成立しなければ白い箱へフォールバックする。

```text
外側線 ━━━━━━━━━╲
留置線 ━━━━━━━━━━━╲
留置線 ━━━━━━━━━━━━━╲
反対側 ━━━━━━━━━━━━━━━╲── 共通接続線 → 端子
                   ↑斜めの集約線は1本
```

## 3. 並行線路ゾーン

- **線路** … `yard_track` タイル（長さ2m・ローカル+Zが線路方向）を直線区間に敷き詰める。タイルはメッシュ bounds で始端を再基準化し、区間長に最も近い整数枚数へ長手方向だけ微調整する。曲線始端まで隙間なく敷き、軌間・高さは変えない。配置は 1 つの Mesh 実体を `CombineInstance` の TRS 行列で複数回参照する方式（[[F4_港湾岸壁のメッシュ生成]] §6 の荷役クレーンと同方式）で、タイル数が多くてもメッシュ複製は発生しない。
- **車止め** … `yard_stop` を各行の行き止まり端（弦の始端）に配置。著作の +Z が線路の内側を向く。
- **架線** … `yard_wire` タイル（長さ2m）を線路タイルと同一の位置・回転で重ねる。トロリ線・吊架線の高さはパーツの著作ジオメトリが持つ（レール面上約5m。[[N_線路メッシュの生成]] の電化線路と同じ高さ体系）。
- **門型架線柱** … 全行の直線区間の共通範囲に `POLE_SPACING`（30m）間隔で `yard_pole` を左右一対配置し、間に `yard_beam` を張る。柱は最外側の線路中心から 2m 外側。`yard_pole` は「右側用」（軌道中心側が −X）著作で、−V 側の柱はヨー180°で向きを合わせる。`yard_beam` は著作幅 6m を柱間へ**Xスケール**する（線路タイルの長手端数調整とは別）。**検修庫の区間には柱を立てない**（梁が庫を貫通するため）。

## 4. 集約・接続ゾーン

- 各留置線の出口曲線はU方向で始まり、斜め集約線と同じ接線で終わる三次ベジエ。最外側線の出口が集約線の起点となり、最後の留置線の合流点まで直線で結ぶ。
- 線路・架線タイルの頂点を、96分割の弧長表とベジエの接線から求める局所フレームへ変形する。タイル境界は同じ位置・接線を使い、タイルを重ねない。長手方向の端数だけを整数枚数に均等配分し、軌間と高さは実寸を保つ。パーツのレール・道床・架線は長手方向0.5m以下に分割しておく。
- 合流側の道床・枕木・締結部は、集約線の支持材外縁（道床は中心から1.55m、枕木は1.3m）で三角形をクリップする。斜めの集約線側の支持材を共有し、二重の枕木や道床の共面重なりを防ぐ。レール・架線は接線が揃う合流点まで描く。
- 変形メッシュは最終結合後に破棄する。直線の留置区間は共有Meshと配置行列で敷設する。
- 端子手前6mのリード線も1本だけ描画し、タイルを端子より先へ突き出さない。

## 5. 検修庫

行が2本以上あり、先頭2行（V最小側）の直線区間に十分な長さがある場合、`yard_shed`（幅11.2m×全長24m。2線分を覆う吹き放ちの上屋）を行き止まり側へ1棟配置する。原点はXZ中心・Y=0接地、著作+Zが線路方向。軒高（7m）はトロリ線（約5.4m）が内部を通り抜けられる高さで、両妻面は全開口のため線路・架線が庫内を貫通して見える。条件を満たさない敷地では配置しない（オプショナル）。

## 6. 敷地装飾・マテリアル

フェンスは `ModularBodyBuilder.GenerateSiteDecorations` の共通処理を使う。**MODEL_RAIL_YARDは敷地全面のfloorパネルを描かない**。`draw_floor` の値や既存の `floor` パーツにかかわらず、道床は `yard_track` が線路直下にだけ持ち、余白は地形が見える。したがって1060のfloorパーツの追加やマスター更新は不要。

線路パーツのマテリアルは線路パス（p4xx）と名前共有（`PATH_RAIL` / `PATH_RAIL_METAL` / `PATH_CONCRETE` / `PATH_ROADBED` / `PATH_METAL`）する。パーツ著作は `genesis-gallery/pipeline/jobs/build_a1060.py`、正本は `library/buildings.blend`。`--only yard_track yard_wire` で曲線用パーツだけ再生成できる。

`Tests/Intersections/run-unity.ps1 -RailYard` は実FBXと本編生成器で、単線〜10線の集約線の共有・合流点の整列・留置長、空き部分のfloor不在、端子までの接続を検査し、全体と合流部の画像を出力する。ギャラリーは同方式の5線見本を表示する。

## 7. コライダー

底面ポリゴンを固定高さ 7m（架線柱の天端相当）まで押し出す（[[F_建物メッシュの生成]] §13）。`floors × height_per_floor` は使わない（1階×4mでは架線・検修庫がクリックできないため）。

## 8. 端子ノードとの連動（再生成）

端子ノードはパス未接続の間、ユーザーが区画内で移動できる（[[26_インフラ網]] §26.3）。移動が確定（`PATCH /nodes/{id}` 成功）すると、`NodeInputHandler.SaveNodePosition` → `BuildingManager.OnTerminalNodeMoved(nodeId)` が呼ばれ、端子の所属施設が MODEL_RAIL_YARD の場合のみ建物メッシュを新しい端子位置で再生成する（version は変わらないため、通常の差分ロードでは再生成されない）。他の model_type は端子位置が見た目に影響しないので何もしない。

既知の制約: ノードが建物より後からロードされた場合、フォールバック位置（=バックエンドの初期配置）で描画される。ユーザーが端子を移動済みのセーブでは、その建物が次に再生成されるまで収束位置がずれたままになる。

## 9. 工事中・倒壊

- 工事中（STATUS_CONSTRUCTING）・解体中は GROUND / PORT と同じく**土マウンドのみ**（足場・クレーンなし。[[F5_工事中建物のメッシュ生成]]）。
- 倒壊（STATUS_COLLAPSED）も瓦礫マウンドのみで躯体片は載せない（[[F8_倒壊建物のメッシュ生成]]）。
