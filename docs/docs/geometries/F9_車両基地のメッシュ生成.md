# 車両基地のメッシュ生成（MODEL_RAIL_YARD）

## 概要

鉄道車両基地のように「施設の敷地内に線路が敷かれ、その線路が施設の接続端子ノードへ収束する」建物の生成方式。実装クラスは `RailYardBuildingMeshBuilder`。

- 共通仕様（データフロー・底面形状・パーツ解決・敷地装飾・結合）は [[F_建物メッシュの生成]] を参照。本書はその差分のみを記述する。
- パーツの制作規格は [[I_建物パーツ作成マニュアル]] §4.9 を参照。
- 接地高は **center_point 位置の地形標高**（全 model_type 共通。コンクリート基盤の対象外）。配置はローカルY=0の水平面で計画し、通常の常駐描画（地形追従）では敷地内の線路・架線・架線柱・車止め・検修庫の頂点を地形に沿わせる（§6.1）。傾斜地でも線路が地面に埋まらない。
- 敷地全面を道床と同じ材質の地面パネル（floor）で覆う（§6）。
- モジュラーの壁・角パーツは使わない。建物本体は「線路ユニットパーツのプロシージャル配置」で構成される。

鉄道車両基地は走行網の接続端子ノード（`depot_node_id`。電化前提の施設では送電網と資格を併せ持つ**共用接続ノード**となり `infra_node_id` と同一。[[26_インフラ網]] §26.3）へ引き込み線路を溶接して使う施設であり、この生成方式は**敷地内の線路が端子ノードの位置へ滑らかに繋がって見える**ことを目的とする。モノレール車庫1064（§11）とLRT車両基地1065（§12）も同じ方式で描く。

## 1. 入力データ

| 入力 | 用途 |
| --- | --- |
| `polygon`（建物底面。SHAPE_FULL のため土地区画と同形） | レイアウト導出の領域・コライダー・フォールバック時の白い箱 |
| `depot_node_id` / `infra_node_id` | 接続端子ノードの位置解決（depot 優先。共用ノードでは同一値） |
| `parcel_id` → 土地区画ポリゴン | 外周フェンス・地面パネルの敷地装飾と、端子未ロード時の初期位置（長方形の判定） |
| `visual_variant` 系 | **不使用**（レイアウトはフットプリントとノード位置から決定的に決まる） |
| `floors` / `height_per_floor` | **不使用**（1階固定の施設。コライダー高さは固定値） |

端子ノードの位置は `PathManager` のノードキャッシュ（`GetNodeData`）から絶対座標で取得し、center_point 相対のローカルXZへ変換する。**ノードが未ロードの場合（テストシーンを含む）**は、バックエンドの初期配置ロジック（`crud_agents._connection_node_position`。[[26_インフラ網]] §26.3）を模した位置へフォールバックする。

1. 土地区画が長方形なら、短辺2本のうち頂点列で番号の若い辺の中点（正方形は辺0）。辺の途中の頂点と重複頂点は角とみなさず、角が直角から1°以内なら長方形とみなす（`TryGetRectangleShortSideMidpoint`。バックエンドの `_rectangle_short_side_midpoint` と同じ規則）。区画は向きを揃える前の頂点列で判定する。区画が未取得なら建物底面で判定する。
2. それ以外は「前面の辺（頂点0→1）から最も遠い辺の中点」（接道辺から最も遠い辺の中点の模倣）。

LRT車両基地は端子が前面辺の中点にあるので、フォールバックも区画の形によらず前面辺の中点になる（§12）。ユーザーが端子を移動していない限り両者は一致する。

## 2. レイアウト導出

すべての配置は次のローカル直交基底 **U / V** の上で決める。

- **U（線路方向）** = 底面重心 → 初期端子位置（§1のフォールバック位置。長方形の敷地では短辺の中点なので、線路は敷地の長手方向に並ぶ。LRT車両基地は前面辺の中点）の単位ベクトル。端子の横移動では回転させない。端子が重心より反対側へ移った場合はUを反転する。
- **V（横方向）** = Uの左手垂直。

1. **端子のV座標を通る中央直線を最初に確保する**。中央線は端子手前6mまで留置区間として敷き、残り6mも同一直線上のリードで結ぶ。複線の引き込み線を受ける基地（§12・§13）では、端子の片側の軌道位置を中央線にする。
2. 中央線から左右へ5m間隔で留置線の候補を置く。上限本数は `clamp(floor((V幅−7m)/5m)+1,1,10)`。近い行から左右交互に採用し、側方マージン3.5mに収まらない行は省く。接続点が中央なら両側、端に寄っていれば主に片側へ展開する。
3. **左右それぞれの最外側線から斜めの集約線を延ばし、同じ側の留置線を途中合流させる**。横移動1m/U方向2mの傾きなので、同じ側の合流点はU方向10m間隔になる。留置線の出口は集約線との交点の6m手前から曲がり、交点の4m先で集約線の接線に揃う。
4. 各集約線は中央線から横2mの位置まで直線で近づき、最後のU方向8mで中央線の接線へ合わせる。横位置は中央線へ単調に近づき、中央線を越えて反対へ曲がらない。左右の合流点はリード始端の6m/18m手前として、三方分岐を避ける。
5. 各留置線は終端を含む敷地内の連続区間にだけ敷く。凹区画の離れた区間をつなげない。曲線と集約線の中心線も敷地内か確認する。
6. **成立しない候補行だけを省く**。1行の失敗を理由に配置全体を空にしない。境界上の水平辺は交点計算から漏れやすいため、±1mmのサンプルも試す。白い箱へのフォールバックは中央直線も成立しない敷地、または必須パーツ欠損の場合に限る。

```text
外側線 ━━━━━━━━━╲
留置線 ━━━━━━━━━━━╲
中央線 ━━━━━━━━━━━━━━━━━━━━━ 端子
留置線 ━━━━━━━━━━━━━╱
外側線 ━━━━━━━━━━━╱
```

## 3. 並行線路ゾーン

- **線路** … `yard_track` タイル（長さ2m・ローカル+Zが線路方向）を直線区間に敷き詰める。タイルはメッシュ bounds で始端を再基準化し、区間長に最も近い整数枚数へ長手方向だけ微調整する。曲線始端まで隙間なく敷き、軌間・高さは変えない。配置は 1 つの Mesh 実体を `CombineInstance` の TRS 行列で複数回参照する方式（[[F4_港湾岸壁のメッシュ生成]] §6 の荷役クレーンと同方式）で、タイル数が多くてもメッシュ複製は発生しない。
- **車止め** … `yard_stop` を各行の行き止まり端（弦の始端）に配置。著作の +Z が線路の内側を向く。
- **架線** … `yard_wire` タイル（長さ2m）を線路タイルと同一の位置・回転で重ねる。トロリ線・吊架線の高さはパーツの著作ジオメトリが持つ（レール面上約5m。[[N_線路メッシュの生成]] の電化線路と同じ高さ体系）。
- **門型架線柱** … 全行の直線区間の共通範囲に `POLE_SPACING`（30m）間隔で `yard_pole` を左右一対配置し、間に `yard_beam` を張る。柱は最外側の線路中心から 2m 外側。`yard_pole` は「右側用」（軌道中心側が −X）著作で、−V 側の柱はヨー180°で向きを合わせる。`yard_beam` は著作幅 6m を柱間へ**Xスケール**する（線路タイルの長手端数調整とは別）。**検修庫の区間には柱を立てない**（梁が庫を貫通するため）。

## 4. 集約・接続ゾーン

- 各留置線の出口曲線はU方向で始まり、斜め集約線と同じ接線で終わる三次ベジエ。左右それぞれの最外側線の出口が集約線の起点となり、中央線の手前まで直線で結ぶ。合流後の中央線は端子まで直進する。
- 線路・架線タイルの頂点を、96分割の弧長表とベジエの接線から求める局所フレームへ変形する。タイル境界は同じ位置・接線を使い、タイルを重ねない。長手方向の端数だけを整数枚数に均等配分し、軌間と高さは実寸を保つ。パーツのレール・道床・架線は長手方向0.5m以下に分割しておく。
- 合流側の道床・枕木・締結部は、集約線の支持材外縁（道床は中心から1.55m、枕木は1.3m）で三角形をクリップする。斜めの集約線側の支持材を共有し、二重の枕木や道床の共面重なりを防ぐ。レール・架線は接線が揃う合流点まで描く。
- 変形メッシュは最終結合後に破棄する。直線の留置区間は共有Meshと配置行列で敷設する。
- 端子手前6mのリード線も1本だけ描画し、タイルを端子より先へ突き出さない。

## 5. 検修庫

行が2本以上あり、先頭2行（V最小側）の直線区間に十分な長さがある場合、`yard_shed`（幅11.2m×全長24m。2線分を覆う吹き放ちの上屋）を行き止まり側へ1棟配置する。原点はXZ中心・Y=0接地、著作+Zが線路方向。軒高（7m）はトロリ線（約5.4m）が内部を通り抜けられる高さで、両妻面は全開口のため線路・架線が庫内を貫通して見える。条件を満たさない敷地では配置しない（オプショナル）。

## 6. 敷地装飾・マテリアル

1060の `fence-w1` は幅2.5m・高さ2.2mの溶接金網フェンスで、`PATH_METAL` と `PATH_CONCRETE` を共有する。区画外周（区画未取得時は建物底面）へ配置し、端子からU方向に延ばした引き込み線と境界の最初の交点に半径3m（複線の引き込み線では軌道の半間隔を足す）の開口を設ける。端子を内側へ動かしても開口は境界上に保つ。角付近では開口にかかる両辺を空ける。`build_a1060.py --only fence-w1` でフェンスだけ再生成でき、マスター更新は不要。

フェンスと地面パネルは `ModularBodyBuilder.GenerateSiteDecorations` の共通処理を使う。地面パネルは区画（区画未取得時は建物底面）の全面に張り、線路の間の余白を道床と同じ見た目にする。描くのは他の生成方式と同じく master の `draw_floor=yes` の場合だけだが、マテリアルは **`a{variant}` 自身の `floor` パーツだけ**から取り、`b{bd_type}`・`common` へフォールバックしない（`BuildingMeshUtils.ResolveFloorMaterialFromMaster(..., ownPartOnly: true)`）。共通の `floor` はアスファルトで、線路の下が舗装に見えるため。1060の `floor` は道床と同じ `PATH_ROADBED`（線路パスの `body` のバラストと同じマテリアル）。1064・1065は `floor` パーツを持たないので地面パネルを描かず、余白は地形が見える。線路直下の道床は `yard_track` が持ち、地面パネル（地形+5mm）より上に出る。

### 6.1 地形追従

通常の常駐描画（`isDynamic`）では、構内の設備（線路・架線・架線柱・門型梁・車止め・検修庫、曲線部の変形タイルを含む）を材質ごとに1つのメッシュへ結合し、各頂点をその水平位置の地形標高まで持ち上げる（`center_point` 位置の地形標高との差を足す）。頂点間の相対的な高さ（レール面・架線高・庫の軒高）は保つので、柱や壁は鉛直のまま地形の傾きに沿って変形する。直線区間は1つのメッシュを配置行列で参照しているため、結合してから頂点を動かす。

地形標高は地形格子の頂点だけを標本化し、格子の三角形（対角線はXZの最小点→最大点）で補間する。地形追従の地面パネル（[[F_建物メッシュの生成]] §8.1）と同じ面になるので、道床と地面パネルの上下関係が崩れない。頂点ごとに地形を引くより標本数が桁違いに少ない（線路タイルは頂点が多い）。地形の未ロード時は1m格子で補間し、地形が届くと建物ごと作り直される。フェンス・地面パネルは共通の敷地装飾の地形追従（§9.4）で沿わせるので、結合の対象に含めない。

引き込み線の端も端子位置の地形標高に載るので、地表の線路（Y=0）とそのまま繋がる。

線路パーツのマテリアルは線路パス（p4xx）と名前共有（`PATH_RAIL` / `PATH_RAIL_METAL` / `PATH_CONCRETE` / `PATH_ROADBED` / `PATH_METAL`）する。パーツ著作は `genesis-gallery/pipeline/jobs/build_a1060.py`、正本は `blender/buildings.blend`。`--only yard_track yard_wire` で曲線用パーツだけ再生成できる。

`Tests/Intersections/run-unity.ps1 -RailYard` は実FBXと本編生成器で、端子を前後・左右・境界へ移す配置で、左右集約線の共有・中央線を越えない合流・配置の維持、端子までの接続、端子未ロード時の初期位置の規則（長方形の短辺）を検査し、全体と合流部の画像を出力する。マスターと地形を読まないので、地面パネルと地形追従は検査しない。ギャラリーは同方式の5線見本を表示する。

## 7. コライダー

底面ポリゴンを固定高さ 7m（架線柱の天端相当）まで押し出す（[[F_建物メッシュの生成]] §13）。`floors × height_per_floor` は使わない（1階×4mでは架線・検修庫がクリックできないため）。地形追従時は、底面の頂点ごとに設備と同じ地形標高の差を足す（傾斜地で高い側の線路がコライダーの天端を超えないため）。

## 8. 端子ノードとの連動（再生成）

端子ノードはパス未接続の間、ユーザーが区画内で移動できる（[[26_インフラ網]] §26.3）。移動操作の対象は電力ビットを持つ共用接続ノードで、電力を変電所から受けるLRT車両基地の端子は前面辺の中点に固定される。移動が確定（`PATCH /nodes/{id}` 成功）すると、`NodeInputHandler.SaveNodePosition` → `BuildingManager.OnTerminalNodeMoved(nodeId)` が呼ばれ、端子の所属施設が MODEL_RAIL_YARD の場合のみ建物メッシュを新しい端子位置で再生成する（version は変わらないため、通常の差分ロードでは再生成されない）。他の model_type は端子位置が見た目に影響しないので何もしない。再生成時は建物の形状リビジョンを進めて再利用キーを変えるので、退避キャッシュや表示中の旧形状は使われない。

既知の制約: ノードが建物より後からロードされた場合、フォールバック位置（=バックエンドの初期配置）で描画される。ユーザーが端子を移動済みのセーブでは、その建物が次に再生成されるまで収束位置がずれたままになる。

端子へつながる線路が追加・変更・削除されたときも、引き込み線の単線・複線（§13）が変わりうるが建物の version は変わらない。PathManager は線路パスの登録・version 変化・削除のたびに両端のノードが車両基地の端子かを調べ（`BuildingManager.IsDepotTerminalNode`）、端子なら `BuildingManager.OnDepotTerminalPathsChanged` を呼ぶ。建物の再利用キーは車両基地の詳細だけ引き込み線の軌道間隔を含むので、表示中の基地のキーが変わったときだけ作り直し、変わらなければ何もしない（退避中・未生成の基地は次の生成で新しい形になる）。

## 9. 工事中・倒壊

- 工事中（STATUS_CONSTRUCTING）・解体中は GROUND / PORT と同じく**土マウンドのみ**（足場・クレーンなし。[[F5_工事中建物のメッシュ生成]]）。
- 倒壊（STATUS_COLLAPSED）も瓦礫マウンドのみで躯体片は載せない（[[F8_倒壊建物のメッシュ生成]]）。

## 11. モノレール車庫1064

1064は同じMODEL_RAIL_YARDを使い、留置線・集約線・端子へのリード・外周フェンスを共通の配置計画から描く。専用パーツはyard_track、yard_shed、yard_stop、fence-w1の4個で、架線は持たない。

軌道は501の単桁と同じ幅0.8m（給電帯込み0.85m）。地上接続に合わせて天端を地面+0.12m、底面を-1.08mに著作する。桁下部は地形に埋まる。幅2m未満の軌道では、合流の支持材切断幅に各サブメッシュの実X断面を使う。通常線路の枕木幅を使うと細い桁の間に空白が生じるため、通常線路とは幅の決定方法を分ける。ギャラリーも狭幅パーツの実断面を参照する。

検修庫は壁外幅11.2m・奥行24m、屋根天端6.05mの2線用。両妻面が開口し、側窓・青帯・屋根換気部・庫内歩廊を持つ。留置中の車両は描かないので、必要なら308/309プロップを手動配置する。コライダーは共通の高さ7mを使う。

著作元は`genesis-gallery/pipeline/jobs/build_a1064.py`と`blender/buildings.blend`。モデル設定はプレハブ取り込み後に自動生成する。経済設定は1060と共通で、供給する車両はモノレール車両（504）。接続端子はモノレール軌道と電力のビットを持つ共用接続ノードで、モノレール軌道の引き込み線を溶接すると車両の配送と受電が同時に成立する（[公共交通機関](../economics/6_公共交通機関.md) 6.5）。

`Tests/Intersections/run-unity.ps1 -RailYard` は1060の検査に加え、1064の実FBXで架線不在・端子へのリード・細い桁の曲線合流部の連続性を確認し、`monorail-yard-preview.png`と`monorail-yard-throat.png`を出力する。

## 12. LRT車両基地1065

1065は同じMODEL_RAIL_YARDを使う。LRTの車両は前面の道路の軌道から門を通って出入りするので、接続端子は区画の形によらず**建物底面の前面辺（頂点0→1）の中点**にある（[公共交通機関](../economics/6_公共交通機関.md) 6.5）。線路方向Uは重心から前面辺の中点へ向き、留置線の行き止まりと検修庫は裏手側、集約線と門は道路側になる。端子は電力ビットを持たないので移動できない。

引き込み線のLRT専用軌道431は1本のパスで上下線の2軌道（軌道中心±1.75m）を持つ。そのため端子の手前も複線にして（§13）、431の2軌道がそのまま門を通って構内へ続くようにする。LRTの走行網の線路は431だけなので、431が未接続の間も複線で描く。

- 端子の位置は、基地が供給する車両財（agent_master.supply）を使う路線種別の走行網から導く。溶接を要する線路（PATH_TRACK・PATH_MONORAIL）と街路・歩行者専用道路の両方を走る網なら端子は前面辺になる。マスター未取得のテストシーンでは鉄道車両基地と同じ描き方になる。

電力ビットを持たない端子は、線路の終端判定でも施設の端子として扱い、431の端に車止めを置かない（[[N_線路メッシュの生成]]）。

専用パーツはyard_pole（丸鋼管の架線柱。天端6.55m）、yard_beam（上下2本の鋼管と束材の軽量な門型梁。長手方向に一様な断面で柱間へXスケールする）、yard_shed（2線の検修庫）の3個。yard_track・yard_wire・yard_stop・fence-w1は1060と同じ形状を共有する。431は電化鉄道411と同じ軌道・架線を使うので、端子で431とレール高・架線高がそろう。

検修庫は外壁の外面で幅11.2m・長さ24m。腰壁・窓帯・金属パネルの側壁に緑の帯を通し、屋根は棟8.0mの円弧のヴォールト。妻面は架線（吊架線6.03m）が通り抜けられる高さ6.2mまで全面を開口にし、2線の間に中柱を立て、梁の上の円弧部はガラスで塞ぐ。庫内は道床の外側を床で埋め、2線の間に高さ3.5mの屋根上作業台（黄色い手すり付き）を置く。留置中の車両は描かないので、必要なら車両プロップを手動配置する。

著作元は`genesis-gallery/pipeline/jobs/build_a1065.py`（非公開の制作ツール）と`blender/buildings.blend`。実FBX・正規プレハブと本編DLLの組み立て（前面辺の端子へ届く複線・渡り線の連続性・門の開口・架線柱と検修庫の有無、1060が裏手の単線のまま変わらないこと）は同ツールの`pipeline/import_depots.ps1`で検査し、ミラーの同期とモデル選択設定の再生成まで行う。

## 13. 複線の引き込み線

端子へ実際につながる線路パス（PATH_TRACK・PATH_MONORAIL。[[N_線路メッシュの生成]] §1.1）の軌道数が2以上なら、端子の手前をその軌道間隔（`TrackPath.GetTrackCenterOffset`）の複線にする。1本のパスで上下線を持つ線路（LRT専用軌道431、通常鉄道・モノレールのまとめた複線）の2軌道が、そのまま構内へ続くようにするためである。同じ走行網に単線と複線の線路が併存するので、網のマスターだけでは決まらない。

- 端子から見て片側（V=−半間隔）の軌道を中央線にし、留置線・集約線をすべてこちらへ集める（§2の手順を中央線の位置だけずらして適用する）。
- 反対側（V=+半間隔）の軌道は、端子から3m直進したあと、走行長16mの渡り線で中央線の直線区間へ合流する。合流側の道床・枕木は§4と同じく中央線の支持材外縁で切る。431（半間隔1.75m）では最小曲線半径は約17m。敷地が浅く中央線の直線区間に合流点が無い場合や、渡り線が敷地に収まらない場合は2本目を省き、中央線の1本だけで端子へ入る。
- 渡り線の区間には門型架線柱を立てない。外周フェンスの開口は半径3m＋半間隔。
- 端子へつながる線路が無い間（未接続・未ロード）は、基地が供給する車両財を使う走行網の線路のうち軌道数の最も少ないもので描く。単線の線路がある網（鉄道・モノレール）は単線、複線の線路しか無いLRTは431の複線になる。マスター未取得のテストシーンでは単線。
- 端子へつながる線路が変わったときの作り直しは§8。
