# 車両基地のメッシュ生成（MODEL_RAIL_YARD）

## 概要

鉄道車両基地のように「施設の敷地内に線路が敷かれ、その線路が施設の接続端子ノードへ収束する」建物の生成方式。実装クラスは `RailYardBuildingMeshBuilder`。

- 共通仕様（データフロー・底面形状・パーツ解決・敷地装飾・結合）は [F_建物メッシュの生成](F_建物メッシュの生成.md) を参照。本書はその差分のみを記述する。
- パーツの制作規格は [I_建物パーツ作成マニュアル](I_建物パーツ作成マニュアル.md) §4.9 を参照。
- 接地高は **center_point 位置の地形標高**（全 model_type 共通。コンクリート基盤の対象外）。配置はローカルY=0の水平面で計画し、通常の常駐描画（地形追従）では敷地内の線路・架線・架線柱・車止め・検修庫の頂点を地形に沿わせる（§6.1）。傾斜地でも線路が地面に埋まらない。
- 敷地全面を道床と同じ材質の地面パネル（floor）で覆う（§6）。
- モジュラーの壁・角パーツは使わない。建物本体は「線路ユニットパーツのプロシージャル配置」で構成される。

鉄道車両基地は走行網の接続端子ノード（`depot_node_id`。電化前提の施設では送電網と資格を併せ持つ**共用接続ノード**となり `infra_node_id` と同一。[26_インフラ網](../economics/26_インフラ網.md) §26.3）へ引き込み線路を溶接して使う施設であり、この生成方式は**敷地内の線路が端子ノードの位置へ滑らかに繋がって見える**ことを目的とする。モノレール車庫1064（§11）とLRT車両基地1065（§12）も同じ方式で描く。

## 1. 入力データ

建物底面・敷地・接続端子ノードからレイアウトを決める。外観値と階数は使わない。端子は `depot_node_id`、無ければ `infra_node_id` で解決し、電化設備では同じ共用ノードを指す。

ノード未取得時は、長方形の敷地では短辺の中点、それ以外では前面から最も遠い辺の中点を初期位置として使う。LRTは前面辺の中点を使う。接続端子の意味と移動条件は[インフラ網](../economics/26_インフラ網.md)を参照する。

## 2. レイアウト導出

敷地重心から初期端子へ向かう線路方向Uと、その垂直方向Vを基準にする。端子の横移動では線路群を回転させず、反対側へ移った場合は方向を反転する。

端子へ直結する中央線を確保し、両側の留置線を集約線へ合流させる。各線路は敷地内の連続区間に収め、成立しない候補だけを省く。凹区画の離れた部分を線路でつながない。

```text
外側線 ━━━━━━━━━╲
留置線 ━━━━━━━━━━━╲
中央線 ━━━━━━━━━━━━━━━━━━━━━ 端子
留置線 ━━━━━━━━━━━━━╱
外側線 ━━━━━━━━━━━╱
```

## 3. 並行線路ゾーン

留置線には共有の線路・架線タイルを敷き、行き止まりに車止めを置く。門型架線柱は線路群の外側に配置し、梁を柱間に伸ばす。検修庫の区間には架線柱を置かない。

パーツの実寸・原点・向きは[車両基地パーツの制作規格](I_建物パーツ作成マニュアル.md#49-車両基地パーツyard_の制作規格)に定義する。

## 4. 集約・接続ゾーン

出口曲線は留置線と集約線の接線を連続させる三次ベジエで、線路・架線タイルを曲線に沿って変形する。軌間と高さは保ち、長手方向の端数だけを調整する。合流する道床・枕木は集約線の外縁で切り、共面の重なりを避ける。

直線区間は共有Meshと配置行列、曲線区間は生成Meshを使う。生成物の解放は建物の共通規則に従う。

## 5. 検修庫

留置線が2本以上あり、連続した直線区間に収まる場合だけ2線用の検修庫を行き止まり側に置く。線路・架線は庫内を通り抜ける。収まらない敷地では検修庫を省く。

## 6. 敷地装飾・マテリアル

フェンスと地面パネルは建物共通の敷地装飾を使う。引き込み線が外周と交わる場所に開口を設け、端子を内側へ動かしても開口は外周上に保つ。角に掛かる場合は両辺を空ける。

地面は `draw_floor=yes` の場合に描き、材質は当該バリアントの `floor` だけから取る。共通アスファルトへは戻さない。1060は道床の材質で敷地を覆い、専用floorを持たない1064・1065では地形を残す。線路直下の道床は線路パーツが持つ。

### 6.1 地形追従

常駐描画では、構内設備を材質ごとに結合して地形の面に沿わせる。レール・架線・庫の相対高さを保ち、引き込み線の端を地表線路へ合わせる。フェンス・地面は共通の追従処理を使う。接地と地形更新の寿命は[LOD処理](E_LOD処理.md#接地)と[データロード](H_バックエンドデータロード.md)に従う。

## 7. コライダー

底面ポリゴンを固定高さ 7m（架線柱の天端相当）まで押し出す（[F_建物メッシュの生成](F_建物メッシュの生成.md) §13）。`floors × height_per_floor` は使わない（1階×4mでは架線・検修庫がクリックできないため）。地形追従時は、底面の頂点ごとに設備と同じ地形標高の差を足す（傾斜地で高い側の線路がコライダーの天端を超えないため）。

## 8. 端子ノードとの連動（再生成）

端子位置と引き込み線の単線・複線は、建物の `version` が変わらずに更新される。端子移動の確定と、接続する線路の追加・変更・削除を建物側へ通知し、描画キーが変わった基地を再生成する。退避した旧形状も再利用しない。

ノードが建物より後から取得された場合は、次に建物が再生成されるまで初期位置への接続を描く。移動済み端子のセーブでは、一時的に収束位置がずれる場合がある。

## 9. 工事中・倒壊

- 工事中（STATUS_CONSTRUCTING）・解体中は GROUND / PORT と同じく**土マウンドのみ**（足場・クレーンなし。[F5_工事中建物のメッシュ生成](F5_工事中建物のメッシュ生成.md)）。
- 倒壊（STATUS_COLLAPSED）も瓦礫マウンドのみで躯体片は載せない（[F8_倒壊建物のメッシュ生成](F8_倒壊建物のメッシュ生成.md)）。

## 10. フォールバック

| 状況 | 挙動 |
| --- | --- |
| `yard_track` パーツが無い | 白い箱（`GenerateSimpleBuilding`） |
| 線路を1本も敷けない敷地形状 | 白い箱 |
| `yard_wire` / `yard_pole` / `yard_beam` / `yard_stop` / `yard_shed` が無い | そのパーツだけスキップ（オプショナル） |
| 端子ノード未ロード | 長方形の区画は短辺の中点、それ以外は前面辺から最も遠い辺の中点（LRT車両基地は前面辺の中点）へフォールバック（§1） |
| `floor` パーツが `a{variant}` に無い・`draw_floor` が yes でない | 地面パネルを描かない（§6） |

## 11. モノレール車庫1064

共通レイアウトを使い、留置線・集約線・リード・フェンスを描く。専用の軌道・検修庫・車止め・フェンスを持ち、架線は持たない。軌道は地表モノレールの桁上面へ接続し、細い桁の合流ではパーツの実断面に沿って支持材を切る。

接続端子はモノレール軌道と電力の共用ノードである。車両の配送と受電の意味は[公共交通機関](../economics/6_公共交通機関.md)に定義する。留置車両は自動では描かない。

## 12. LRT車両基地1065

端子は建物底面の前面辺（頂点0→1）の中点に固定し、集約線と門を道路側へ向ける。電力ビットを持たないため、端子移動の対象外である。

引き込み線の431は1パスに上下2軌道を持つ。未接続時も同じ複線で門から構内へつなぐ。線路・架線・車止め・フェンスは1060の形状を共有し、架線柱・梁・検修庫は専用パーツを使う。端子でレール高・架線高を合わせ、施設端の車止めは置かない。

## 13. 複線の引き込み線

実際に接続する線路パスの軌道数と間隔に合わせて端子手前を描く。片側を中央線にして留置線群を集め、反対側は渡り線で合流させる。渡り線が敷地に収まらない場合は2本目を省く。フェンス開口も軌道間隔を含めて広げる。

未接続・未取得時は、基地の車両を使う走行網で最も少ない軌道数を採る。単線を持つ鉄道・モノレールは単線、複線しか持たないLRTは431の複線になる。マスター未取得時は単線で描く。
