# 地形データ作成マニュアル

標高ファイルを取り込んでシナリオを作り、地形エディタでシナリオの地形を仕上げる手順を説明する。

地形エディタは「シナリオに含まれる地形を編集するツール」である。編集結果はシナリオ(`.cg`)へ保存し、取り込んだ元の標高ファイルは使わない。ゲームは標高マップを同梱せず、地形はシナリオが自己完結で持つ([D_地形形状](D_地形形状.md) §D.14)。

## 1. 全体フロー

```
[トップメニュー →「シナリオ管理」→「地形を取り込む」タブ]
  → 標高ファイル(グレースケールPNG・.npy)を選び、1画素の距離などを入れて「シナリオを作成」(4節)
  → 新しい自作シナリオができる(水面・川・資源・プロップ・カメラは空、地表は草原・気候は温暖湿潤)
[「シナリオ」タブの自作カード →「地形を編集」]
  → Tauriがシナリオの地形を作業コピーへ書き出し(2節)、地形エディタウィンドウを開く
  → エディタで編集(地形・水面・川・カメラ・地表・気候)
  → 「シナリオに保存」でシナリオへ書き込む(3節)
  → シナリオ管理の一覧が更新される(シナリオの版 content_revision が1つ上がる)
```

- 地形を編集できるのは自作シナリオだけ。コミュニティ・DLCのシナリオは、プレイした都市を「シナリオとして保存」して自作シナリオにしてから編集する。
- DLC由来の都市から作ったシナリオは、自作でも暗号化されているので地形エディタで開けない(コアが `SCENARIO_ENCRYPTED` で断る。[D_地形形状](D_地形形状.md) §D.14.3)。シナリオ管理ではそのカードの「地形を編集」を押せなくし、理由をボタンのツールチップで示す。資源・プロップは「都市を編集」で開いた神モードのセッションで編集する。
- ゲームのセッション中は使えない(コアが `SESSION_ACTIVE` で断る)。トップメニューに戻ってから操作する。
- 道路・建物・造成跡・埋立地のあるシナリオでは、標高・水面・川がロックされる。編集できるのはカメラ・地表・気候だけになる(3.2節)。
- 作業コピーは初期データの受け渡し専用で、編集途中の状態を保存したり次回に再開したりする手段は持たない。編集結果を残す操作は「シナリオに保存」だけである(保存に成功すると、作業コピーも保存した内容に合わせて書き換わる。3.1節)。

> **自動編集(侵食シミュレーション):** 「地形編集」の自動編集タブには、雨粒パーティクルが斜面を削りながら流れて谷筋と堆積を作る**水流侵食**と、安息角を超える崖・急斜面を崩してなだらかにする**熱侵食**の2種類がある。選択範囲があればその範囲を起点に、なければマップ全体へ適用される(雨粒の数・侵食の強さ・安息角・反復回数といった主要パラメータは調整可能)。水流侵食は標高0以下を海面として扱い、海面に達した雨粒は流速を失って消滅する。運んでいた土砂は海中の斜面を滑り落ち、安息角より緩い海底で沈降する(深い海に面した断崖から流れ込んだ土砂は、崖のふちではなく崖下の海底に扇状に堆積する)。海中の堆積が積み重なって標高が海面を超えた場合にのみ新しい陸地(河口のデルタ)が生まれるため、海岸線が土砂で際限なく埋め立てられて島が広がることはない。

## 2. 作業コピー

「地形を編集」を押すと、Tauri(Rust)のコマンド `prepare_scenario_terrain_editor` がバックエンドの `GET /api/v1/scenarios/{id}/terrain` からシナリオの地形を取得してローカル(AppData)へ書き出し、エディタウィンドウがそれを読み込む。ファイル配置の詳細は [ファイル配置](../programs/ファイル配置.md) を参照。

| プラットフォーム    | パス                                                                      |
| ----------- | ----------------------------------------------------------------------- |
| **Windows** | `%LOCALAPPDATA%\UrbanGenesis\terrain_editor\{editor_id}\`                |
| **macOS**   | `~/Library/Application Support/UrbanGenesis/terrain_editor/{editor_id}/` |
| **Linux**   | `$XDG_DATA_HOME/UrbanGenesis/terrain_editor/{editor_id}/`                |

`{editor_id}` は作業コピーごとに発行するUUID(小文字・ハイフン区切りの正規形。Tauriはこの形以外のIDを受け付けず、フォルダの外を指させない)で、シナリオのIDとは別物である。地形エディタと3Dプレビューのウィンドウは、この `editor_id` を対象IDとして開く。

- 同じシナリオの地形エディタが表示中なら、新しい作業コピーを作らずにそのウィンドウの `editor_id` を返す。「地形を編集」を押し直しても未保存の編集は消えず、2枚のウィンドウの保存が互いを上書きすることもない。
- どのウィンドウにも結び付かず、作成から1時間を過ぎた作業コピーは、次に「地形を編集」を押したときに Tauri が削除する。

### 2.1. ディレクトリ構成

```
terrain_editor/
└── {editor_id}/
    ├── meta.json       # 編集対象のシナリオ・ロック情報・マップ設定値と、水面・川・資源・プロップ・カメラ・地表・気候
    └── near.bin        # 近景標高マップ(float16 LE の raw バイナリ)
```

### 2.2. meta.json の形式

```json
{
  "scenario_id": "local~0f8fad5b-d9cb-469f-a165-70867728950e",
  "terrain_source": "my_island.png",
  "title": "与論島",
  "locks": { "heights_locked": false, "reasons": [] },
  "map_width": 12000,
  "map_height": 8000,
  "near_spacing": 10,
  "far_spacing": 200,
  "cell_size": 500,
  "grid_rows": 801,
  "grid_cols": 1201,
  "water_surfaces": [],
  "rivers": [],
  "resources": [],
  "props": { "instances": [], "scatters": [] },
  "camera": null,
  "ground_cover": 1,
  "climate": 1
}
```

| フィールド | 内容 |
|---|---|
| `scenario_id` | 保存先のシナリオID。「シナリオに保存」は保存先をUIから受け取らず、ここから引く |
| `terrain_source` / `title` | 元の地形の名前(取り込んだファイル名など)と、シナリオのタイトル(左パネルの見出しに使う) |
| `locks` | 標高のロック `{heights_locked, reasons}`([D_地形形状](D_地形形状.md) §D.14.4)。欠けている・形が崩れているときは、Rust・UIともロックされているものとして扱う(編集できない側に倒す) |
| `map_width` / `map_height` / `near_spacing` / `grid_rows` / `grid_cols` | 標高データのグリッド構造(2.3節) |
| `far_spacing` / `cell_size` | 標高データには影響しないマップ設定値 |
| `water_surfaces` / `rivers` / `resources` / `props` / `camera` | シナリオの配置情報。仕様の正は [D_地形形状](D_地形形状.md) §D.10〜§D.13 と [M_地形プロップ](M_地形プロップ.md)。`resources` の `id` はシナリオの中の資源のIDの文字列。`props` の `id` は保存では使われない(コアが新しいIDを振る)。エディタは `resources` と `props` を編集せず、読み込んだ内容をそのまま保存で送り返す |
| `ground_cover` / `climate` | 地表種別と気候区分([D_地形形状](D_地形形状.md) §D.15・§D.16)。`null` のときエディタは草原・温暖湿潤として扱う |

作業コピーを作るとき、Tauri は標高のバイト数が `grid_rows × grid_cols × 2` と一致することを確かめ、一致しなければ地形エディタを開かない。

### 2.3. near.bin の形式

- **データ型:** float16 (IEEE 754 half precision), リトルエンディアン
- **形状:** `grid_rows` × `grid_cols` の2次元配列(行優先)
  - `grid_rows` = `map_height / near_spacing + 1` (Z方向=縦)
  - `grid_cols` = `map_width / near_spacing + 1` (X方向=横)
- **座標系:** 配列の先頭(行0・列0)がワールド座標 `(-map_width/2, -map_height/2)` の南西隅、末尾が `(map_width/2, map_height/2)` の北東隅に対応する(マップ中心がワールド原点)。行が増えるほど北(ワールド+Z)、列が増えるほど東(+X)へ進むので、画像として見るときは上下を反転すると北が上になる。向きの規約は [D_地形形状](D_地形形状.md) §D.3.1
- **標高0以下のピクセル:** 海面を表す
- **総バイト数:** `grid_rows * grid_cols * 2`

### 2.4. メタデータを確認・編集する

元の地形・遠景グリッド間隔・セルサイズ・地表の種類・気候・マップサイズは編集対象から独立したメタデータで、左パネル上部の「3Dプレビューを開く」の右隣にある「メタデータ編集」ボタンでモーダルダイアログを開いて確認する。閉じるボタンまたはEscapeで編集画面へ戻り、入力した値は保持される。

| フィールド | 編集可否 | 説明 |
|---|---|---|
| 元の地形 | 読み取り専用 | シナリオを作ったときに取り込んだファイルの名前 |
| 遠景グリッド間隔 (`far_spacing`) | 読み取り専用 | 保存APIが受け取らない項目なので、編集しても保存されないため読み取り専用にしている |
| セルサイズ (`cell_size`) | 読み取り専用 | エディタではセル境界グリッドの間隔を決める。ゲーム側では標高の保存単位・地形タイルの生成単位になる([D_地形形状](D_地形形状.md) §D.4) |
| 地表の種類 (`ground_cover`) | 編集可 | 草原・砂漠・濃い草地・雪原・乾燥地から選ぶ。ゲーム内の地表の色と質感、エディタの2D・3Dプレビューの配色が変わる。見た目だけの属性で、シミュレーションには影響しない([D_地形形状](D_地形形状.md) §D.15) |
| 気候 (`climate`) | 編集可 | ケッペンの気候区分のプリセットから選び、月別の気温・降水量・日照と天気の出現割合をコピーする。季節ごとの天気の出方に加え、生産の気候補正にも使われる。地表の種類とは独立に、その土地の実際の気候に合わせて選ぶ([D_地形形状](D_地形形状.md) §D.16、[U_天気と環境光](U_天気と環境光.md)、[気候設定](../programs/気候設定.md)) |
| マップサイズ・近景間隔・グリッド行数/列数 | 読み取り専用 | 標高データのグリッド構造そのもの。シナリオの寸法は変えられない(寸法の違う標高を保存するとコアが `TERRAIN_SIZE_MISMATCH` で拒否する) |

## 3. シナリオに保存する

### 3.1. 保存の流れ

左パネル下部の「シナリオに保存」を押すと、Tauri(Rust)のコマンド `save_scenario_terrain` がその時点の編集内容を `PUT /api/v1/scenarios/{id}/terrain` へ送る。送る内容と、コアでの扱いは次のとおり(仕様の正は [D_地形形状](D_地形形状.md) §D.14.3)。

| 内容 | 送り方 | コアでの扱い |
|---|---|---|
| 標高 | near.bin と同じ float16 LE を base64 にした文字列 | 近景を置き換え、遠景を作り直す |
| 水面・川 | 一覧全体。川は彫り込み済みのものだけ(未彫り込みの川は保存されない) | 一覧全体を置き換え、海岸線を抽出し直す |
| 資源 | 読み込んだ一覧全体をそのまま | IDで差分を適用する(既存は更新、新規は追加、無くなったものは削除)。新規の資源に振ったIDは応答の `resource_ids` で返る |
| プロップ | 読み込んだ個別配置・範囲散布の全体をそのまま | 全置換(IDは保存しない) |
| カメラ・地表・気候 | 値 | そのまま置き換える |

標高・水面・川のどれかを保存すると、コアは土地区画の種別(陸・沿岸・海上)・勾配・基準標高と、サービスの効果範囲も計算し直す。保存は通常のシナリオ保存と同じ経路を通り、シナリオの版(`content_revision`)が1つ上がる。

保存に成功すると、エディタは `scenarios:changed` を送り、シナリオ管理の一覧・画像・版を更新させる。エディタはそのまま開いており、続けて編集して何度でも保存できる。保存中に行った編集は未保存のまま残る。

資源とプロップは地形エディタで編集しないので、読み込んだ内容をそのまま送り返す。コアは資源をIDで差分適用し、プロップを全置換するため、送らないとシナリオの資源とプロップが消えてしまう。Tauri は保存に成功したら作業コピー(`meta.json` と、標高を送ったときは `near.bin`)を保存した内容に合わせる。Rustの `save_scenario_terrain` は応答の `content_revision`・`locks`・`resource_ids` をUIへ返す。

保存対象を変える操作をすると、保存ボタンの上に「未保存の変更があります」と表示する。ウィンドウを×で閉じると未保存の編集は失われる(閉じる前の確認は出ない)。

失敗したときはエラーをエディタに表示する。Rustのコマンドはコアのエラーを「`CODE`: 本文」の形で返し、UIは先頭のコードで翻訳文を引く。主なコードは `TERRAIN_LOCKED`(ロック中に標高・水面・川を送った)、`TERRAIN_SIZE_MISMATCH`(寸法が違う)、`TERRAIN_INVALID`(形の崩れた値)、`RESOURCE_VALIDATION_ERROR` / `PROP_VALIDATION_ERROR`(資源・プロップの値の誤り)、`SESSION_ACTIVE`(ゲームのセッション中)、`SCENARIO_ENCRYPTED`(DLC由来の暗号化されたシナリオ)。

地形エディタはサムネイル画像を作らない。シナリオの画像は紹介情報ウィンドウで設定する([シナリオ制作と配布](../programs/シナリオ制作と配布.md))。

### 3.2. 標高のロック

道路・線路・インフラのパス、形のある建物、超近景セル(造成などで書き換えた標高)、埋立地のどれかがあるシナリオでは、標高・水面・川がロックされる。建設物は建てたときの地形に合わせて造成・接地しているので、下の地形だけを変えると食い違うためである。理由コードは [D_地形形状](D_地形形状.md) §D.14.4 を参照。

ロックされたシナリオを開くと、エディタは地形(自動編集を含む)・水面・川のタブを選べなくし、ロックの理由を表示してカメラのタブを選んだ状態で始まる。保存では標高・水面・川を `null` で送る。Rustの `save_scenario_terrain` も、作業コピーの `locks` がロックを示しているのに標高・水面・川が送られたら、コアへ送る前に `TERRAIN_LOCKED` で拒否する。

地形の作り込みは、道路や建物を置く前(地形から作ったばかりのシナリオ)に済ませておく。

## 4. 標高ファイルを取り込む

シナリオ管理の「地形を取り込む」タブでは、任意の場所に置いた標高ファイルを選んで新しい自作シナリオにする。仕様の正は [D_地形形状](D_地形形状.md) §D.14.1。

| 入力 | 内容 |
|---|---|
| ファイル | グレースケールPNG(8bit・16bit。画像の上が北)、または `.npy`(数値の2次元配列。行0が南端・列0が西端、値はm) |
| 1画素の距離(m) | 1画素が地上で何mにあたるか。マップの一辺は(画素数−1)×この距離を1km単位に切り上げた大きさになる(一辺30kmまで。はみ出す分は縁の標高を延ばす) |
| 最低標高・最高標高(m) | PNGだけで使う。最も暗い色と最も明るい色の標高。`.npy` は値そのものが標高なので、欄にはファイルの実際の最低・最高が表示される(編集できない) |
| 海面の高さ(m) | この標高以下を海にする。海は海岸からの距離に応じた深さの海底に彫られる |
| タイトル | シナリオのタイトル。既定は元のファイル名。後から紹介情報で言語ごとに書き分けられる |
| 背景地形(任意) | 都市の外側に広がる遠景の標高。`.npy`(詳細地形と同じ規約)だけ使える。50m格子に直され、格子の中心が都市の中心に重なる。一辺100kmまで。海面の高さは詳細地形と共通 |
| 背景の1画素の距離(m) | 背景ファイルの1画素が地上で何mにあたるか(既定50) |

- 右側のプレビューで、選んだ地形(標高で色分け)と背景(淡い単色)の重なりを取り込む前に確かめられる。標高0m以下(海)は透明なので、詳細地形の海の下に背景の陸地が残っていれば透けて見える。境界で陸地が途切れていないか、背景の1画素の距離が合っているかを見る。
- 形式が違う・大きすぎる・陸地が無いなどで変換できないファイルは、シナリオを作らずにエラーを表示する。
- できたシナリオの画像(サムネイル)は、取り込んだ地形から自動で描く。
- 背景地形は取り込み後に地形エディタで編集できない。作り直すときは取り込み直す。
- 実在の地形から標高ファイルを作るときは、元データ(数値標高モデル)の規約と出典表示の義務を確認すること。取り込んだ地形はゲームの配布物に含まれないが、作ったシナリオを配布するときは配布者が表示義務を負う。

## 5. 注意事項

- **編集はローカルの作業コピーに対して行われる:** 「シナリオに保存」するまで、シナリオにもゲームのセーブデータにも影響しない。
- **元の標高ファイルは書き換えない:** 地形エディタの保存先は常にシナリオで、取り込んだファイルは作成時に読むだけで以後は使わない。
- **寸法は変えられない:** シナリオのマップサイズ・格子は取り込んだときのまま固定される。別の大きさが必要なら、1画素の距離を変えて取り込み直す。
- **同じシナリオへの保存は上書き:** 保存のたびにシナリオの地形が置き換わり、版が1つ上がる。保存した後で以前の地形へ戻す操作は無い(エディタのUndoは保存前の編集だけが対象)。
