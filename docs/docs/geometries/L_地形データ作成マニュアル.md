# 地形データ作成マニュアル

Tauriの地形エディタで編集した地形データを、ゲームで選択可能な地形マップとして登録するまでの手順を説明する。

## 1. 全体フロー

```
[タスクバーの「エディタ」→ 地形エディタタブで取り込み元を選ぶ]
  ├ 「既存マップを編集」 : ゲーム用マップの標高・川・水面・資源・プロップ・カメラ・初期開放セルを取り込む
  ├ 「オリジナル地形」   : 編集禁止の標高原本から標高だけを取り込む(配置情報は付いてこない)
  └ 「新しい地形を追加」 : 標高-10m・2×2セルの最小マップを生成する(4節)
  → Tauriが取り込みごとに作業コピーを作り(2節)、地形エディタウィンドウを開く
  → エディタで編集(地形・水面・川・資源・プロップ・カメラ・初期開放セル)
  → 「.npyへエクスポート」ボタンで .npy ・サムネイル・付随JSONを書き出す(3.1節、保存先はダイアログで指定)
  → エクスポート先に terrain_maps.yaml があれば、エントリが自動で追記/上書きされる(3.4節)
  → バックエンドを再起動すると「ニューゲーム」で選択可能になる(サムネイルも一覧に表示される)
```

> **編集結果を残す操作はエクスポートだけ:** 作業コピーはエディタウィンドウへ初期データを渡すためのもので、編集途中の状態を保存したり次回に再開したりする手段は持たない。エディタを開くたびに取り込みからやり直す。

> **自動編集(侵食シミュレーション):** 「地形編集」の自動編集タブには、雨粒パーティクルが斜面を削りながら流れて谷筋と堆積を作る**水流侵食**と、安息角を超える崖・急斜面を崩してなだらかにする**熱侵食**の2種類がある。選択範囲があればその範囲を起点に、なければマップ全体へ適用される(雨粒の数・侵食の強さ・安息角・反復回数といった主要パラメータは調整可能)。水流侵食は標高0以下を海面として扱い、海面に達した雨粒は流速を失って消滅する。運んでいた土砂は海中の斜面を滑り落ち、安息角より緩い海底で沈降する(深い海に面した断崖から流れ込んだ土砂は、崖のふちではなく崖下の海底に扇状に堆積する)。海中の堆積が積み重なって標高が海面を超えた場合にのみ新しい陸地(河口のデルタ)が生まれるため、海岸線が土砂で際限なく埋め立てられて島が広がることはない。

## 2. 作業コピーの場所

地形エディタを開くと、Tauriがバックエンドから取り込んだデータをローカル(AppData)へ書き出し、エディタウィンドウがそれを読み込む。ファイル配置の詳細は [[ファイル配置]] を参照。

| プラットフォーム    | パス                                                                      |
| ----------- | ----------------------------------------------------------------------- |
| **Windows** | `%LOCALAPPDATA%\UrbanGenesis\terrain_editor\{editor_id}\`                |
| **macOS**   | `~/Library/Application Support/UrbanGenesis/terrain_editor/{editor_id}/` |
| **Linux**   | `$XDG_DATA_HOME/UrbanGenesis/terrain_editor/{editor_id}/`                |

`{editor_id}` は取り込みのたびに発行されるUUIDであり、マップの登録IDとは別物である(同じマップを2回選べばディレクトリも2つできる)。登録ID — エクスポート先の `terrain_maps.yaml` に書かれるキー — は `meta.json` の `map_id` に入り、エディタの「メタデータ編集」で変更できる(2.4節)。

編集を終えた作業コピーが再び読まれることはないため、不要なディレクトリは手動で削除してよい。

### 2.1. ディレクトリ構成

```
terrain_editor/
└── {editor_id}/
    ├── meta.json       # マップ設定値と、取り込んだ配置情報(川・水面・資源・プロップ・カメラ・初期開放セル)
    └── near.bin        # 近景標高マップ(float16 LE の raw バイナリ)
```

### 2.2. meta.json の形式

```json
{
  "map_id": "my_island",
  "map_width": 12000,
  "map_height": 8000,
  "near_spacing": 10,
  "far_spacing": 200,
  "cell_size": 500,
  "grid_rows": 801,
  "grid_cols": 1201,
  "water_surfaces": [],
  "rivers": [],
  "resources": [],
  "props": { "instances": [], "scatters": [] },
  "camera": null,
  "initial_cells": [[11, 7], [11, 8], [12, 7], [12, 8]]
}
```

| フィールド | 内容 |
|---|---|
| `map_id` | 登録ID。エクスポート先の `terrain_maps.yaml` のキーになる(2.4節) |
| `map_width` / `map_height` / `near_spacing` / `grid_rows` / `grid_cols` | 標高データのグリッド構造(2.3節) |
| `far_spacing` / `cell_size` | 標高データには影響しないマップ設定値 |
| `water_surfaces` / `rivers` / `resources` / `props` / `camera` / `initial_cells` | 取り込み元から引き継いだ配置情報。仕様の正は [[D_地形形状]] §D.10〜§D.15 と [[M_地形プロップ]] |

キーが存在しない配置情報は空(`camera` は未設定)として読み込まれる。「オリジナル地形」からの取り込みは標高だけを持ち、「新しい地形を追加」で作った作業コピーは `initial_cells`(全域の2×2セル)以外の配置情報を持たない。

### 2.3. near.bin の形式

- **データ型:** float16 (IEEE 754 half precision), リトルエンディアン
- **形状:** `grid_rows` × `grid_cols` の2次元配列(行優先)
  - `grid_rows` = `map_height / near_spacing + 1` (Z方向=縦)
  - `grid_cols` = `map_width / near_spacing + 1` (X方向=横)
- **座標系:** 配列の左上がワールド座標 `(-map_width/2, -map_height/2)`、右下が `(map_width/2, map_height/2)` に対応する(マップ中心がワールド原点)
- **標高0以下のピクセル:** 海面を表す
- **総バイト数:** `grid_rows * grid_cols * 2`

### 2.4. 地図メタデータを編集する

マップID・遠景グリッド間隔・セルサイズ・マップサイズ変更は編集対象から独立したメタデータで、左パネル上部の「3Dプレビューを開く」の右隣にある「メタデータ編集」ボタンでモーダルダイアログを開いて編集する。閉じるボタンまたはEscapeで編集画面へ戻り、入力した値は保持される。

| フィールド | 編集可否 | 説明 |
|---|---|---|
| マップID | 編集可 | 登録ID。`terrain_maps.yaml` のキー・`id`・`name` と、エクスポート時の既定ファイル名 `map_{マップID}.npy` に使われる。初期値は取り込み元のID(原本からの取り込みと新規作成ではUUIDを含む機械的なID)なので、読みやすいIDに付け替えてからエクスポートする |
| 遠景グリッド間隔 (`far_spacing`) | 編集可 | 近景標高データ(near.bin)には影響しない独立したメタデータ |
| セルサイズ (`cell_size`) | 編集可 | 変更すると、初期開放セル(2.5節)が同じ土地を指すセル番号へ振り直される |
| マップサイズ・近景間隔・グリッド行数/列数 | **編集不可** | 標高データのグリッド構造そのものと結び付いており、リサンプリングを実装しないまま変更すると `near.bin` との整合性が壊れるため、読み取り専用表示にとどめている |

マップサイズだけは同じダイアログの「マップサイズ変更」から、上下左右のいずれかの端に `2 × cell_size` 単位でセルを追加・削除できる。追加した領域の標高は-10m(海面より低い)で埋まり、既存の地形・川・水面・資源・プロップ・カメラはマップ中心の移動に合わせて平行移動する。

### 2.5. 初期開放セルを決める

左パネル上部の編集対象プルダウンで「初期開放セル」を選ぶと、そのマップで新規都市を始めたときに開放済みで始まるセルを指定できる。セル境界グリッド(`cell_size` 間隔の濃い線)の上を左クリックするとそのセルが追加/解除され、右クリックで解除、左ドラッグは画面移動になる。選択中のセルは水色で塗られ、他の編集対象を選んでいる間も表示される。

未設定(1つも選んでいない状態)のままエクスポートすると、ゲームはマップ中央の2×2セルで始まる。**島がマップ中央にないマップでは、この既定のままだと海のど真ん中から都市が始まってしまう**ため、陸地の上のセルを明示的に選んでおく。陸地を含むかどうかの検証は行わないので、海側から埋め立てて始めるマップも作れる。

セル番号はマップ寸法とセルサイズから決まるため、マップサイズ変更(セルの追加/削除)やセルサイズ変更を行うと、同じ土地を指すようにセル番号が自動で付け替わる。エクスポート時は `terrain_maps.yaml` の `initial_cells` に書き出される(3.4節)。仕様の正は [[D_地形形状]] §D.15。

## 3. 編集結果をゲームで使える地形マップにする

編集した地形を、バックエンドが読み込める `.npy` ファイルとして書き出し、所定の場所に配置する。

### 3.1. .npy へエクスポートする

左パネル下部の「.npyへエクスポート」ボタンを押すと保存先パスを選ぶダイアログが開き(既定のファイル名は `map_{マップID}.npy`)、パスを指定するとその時点の編集内容が次のファイル群として書き出される。いずれも `.npy` と同じディレクトリ・同じファイル名で、拡張子だけが異なる。

| ファイル | 内容 |
|---|---|
| `.npy` | 近景標高マップ(float16、`grid_rows` × `grid_cols`) |
| `.png` | サムネイル画像(160x120のPNG) |
| `.water.json` | 水面ポリゴン(version 1)。[[D_地形形状]] §D.10 |
| `.rivers.json` | 川の範囲ポリゴンと水面標高のプロファイル(version 2)。同 §D.11。川床の彫り込みそのものは `.npy` に含まれる |
| `.resources.json` | 天然資源エリア(version 1)。同 §D.12 |
| `.props.json` | プロップの個別配置・範囲散布(version 1)。[[M_地形プロップ]] |

付随JSONは中身が空でも必ず書き出されるため、以前のエクスポートで残った古い定義が読まれ続けることはない。カメラ初期状態と初期開放セルだけはサイドカーではなく `terrain_maps.yaml` のエントリに書かれる(3.4節)。

サムネイル画像はこのエクスポート時に、その時点の標高データから生成される。生成は3Dプレビューと同じハイトフィールドメッシュ・頂点カラーを、3Dプレビューウィンドウを開かずにオフスクリーンで一度だけ描画する方式で行い、視点も3Dプレビューを開いた直後と同じ「地形全体が収まる斜め上から」になる。

`.npy` への変換はTauri側(Rust)がヘッダを自前で組み立てて行う。外部プロセスも一時ファイルも介さないため、ユーザー環境にPythonは不要である。書き出しに失敗した場合はエディタ画面にエラーメッセージが表示される。

**原本のディレクトリ(`terrains/original/`)へは書き出せない。** 保存先がそこに解決される場合は、1つ目のファイルを書く前にエラーになる([[D_地形形状]] §D.14)。

### 3.2. src_spacing の設定

バックエンドの地形読み込み処理は、`.npy` ファイルを `src_spacing`(ソースデータのグリッド間隔)から `near_map_spacing` にリサンプリングする。

地形エディタの出力は既に `near_map_spacing` 解像度なので、エクスポートは `src_spacing` に `near_map_spacing` と同じ値を書き込み、リサンプリングは実質的に恒等(ズーム1.0)になる。`src_spacing` を自分で決める必要があるのは、外部ツールで作った `.npy` を手で登録する場合だけである。

### 3.3. 出力ファイルを配置する

ゲームが読み込む地形は、バックエンドのインストール先の `assets/terrains/` に集約されている。

```text
assets/
└── terrains/
    ├── original/                      # 編集禁止の標高原本(.npyのみ)
    ├── original_terrains.yaml         # 原本の寸法・解像度
    ├── terrain_maps.yaml              # ゲーム用マップの登録表
    ├── map_yoron.npy                  # 与論島
    ├── map_yoron.png
    ├── map_my_island.npy              # ← 新しく追加されるファイル
    ├── map_my_island.png
    ├── map_my_island.water.json
    ├── map_my_island.rivers.json
    ├── map_my_island.resources.json
    └── map_my_island.props.json
```

**「.npyへエクスポート」の保存先ダイアログで直接 `assets/terrains/` を指定すれば、この配置作業と `terrain_maps.yaml` への追記(3.4節)が1回の操作で完了する。** 別の場所へ書き出した場合は、3.1節のファイルを1つも欠かさず `assets/terrains/` へコピーし、`terrain_maps.yaml` の `file_name` を `terrains/` 付きのパスに直す(欠けたファイルの要素は、そのマップには存在しないものとして読み込まれる)。

サムネイルは `GET /api/v1/terrain/maps/{map_id}/thumbnail` から配信される(`file_name` の拡張子を `.png` に置き換えたパスを機械的に探すため、専用の設定項目は不要)。`.png` が無いマップはこのエンドポイントが404を返し、`NewGameWindow`・`EditorWindow` はプレースホルダー表示にフォールバックする。

### 3.4. terrain_maps.yaml へのエントリ追加(エクスポート時に自動実行)

「.npyへエクスポート」実行時、エクスポート先ディレクトリに `terrain_maps.yaml` が存在するかを確認する。

- **存在する場合:** そのマップIDのエントリを自動で追記する(同じ `map_id` のエントリが既にあれば、その内容を上書きする)。既存の他エントリのコメントや空行区切りはそのまま残る(テキストベースでブロック単位を差し替えているため、YAML全体を再整形することはない)。
- **存在しない場合:** 何も書き換えず、エディタ側に「terrain_maps.yaml が見つからなかった」旨の通知ポップアップが表示される。この場合は以下の手順で手動追加する。

自動生成されるエントリの内容:

```yaml
# my_island
my_island:
  id: my_island
  name: my_island
  file_name: terrains/map_my_island.npy
  src_spacing: 10.0
  settings:
    map_width: 12000
    map_height: 8000
    near_map_spacing: 10
    far_map_spacing: 200
    dynamic_map_spacing: 1
    cell_size: 500
  initial_cells: [[11, 7], [11, 8], [12, 7], [12, 8]]
  camera:
    x: 120.0
    y: 150.0
    z: -340.0
    yaw: 30.0
    pitch: 50.0
```

各フィールドの意味:

| フィールド | 意味 |
|---|---|
| `id` | マップを識別する固有のキー。エディタで指定したマップIDがそのまま入る |
| `name` | ゲーム内で表示される名称。**自動生成時は `id` と同じ文字列が入るため、日本語名等に変更したい場合はエクスポート後に手動で書き換える** |
| `file_name` | `.npy` ファイルの `assets/` 基準の相対パス(エクスポート時の出力先から自動設定される。`terrains/` 直下へ書き出せば `terrains/` 付きになる) |
| `src_spacing` | ソースデータのグリッド間隔(m)。エディタ出力は常に `near_map_spacing` と同じ値が自動設定される |
| `settings` | マップの設定値。エディタの地図メタデータから自動設定される。`dynamic_map_spacing` のみエディタ側に対応する概念がないため常に `1` 固定になる |
| `initial_cells` | 新規都市の開始時に開放しておくセル(`[[cx, cy], ...]`)。エディタの「初期開放セル」タブで選んだセルが入る。未設定ならキー自体が書かれず、ゲームはマップ中央の2×2セルで始まる。詳細は [[D_地形形状]] §D.15 |
| `camera` | 新規都市を始めたときのカメラの位置(`x`/`z`=ワールド座標m、`y`=高さm)と向き(`yaw`=北を0とする時計回りの度、`pitch`=見下ろし角の度)。エディタの「カメラ」タブで設定した値が入る。未設定ならキー自体が書かれず、ゲームはマップ中心の上空の既定視点で始まる。詳細は [[D_地形形状]] §D.13 |

自動追記されない場合(手動で追加する場合)は、上記と同じ形式のエントリを `assets/terrains/terrain_maps.yaml` に追加する。

> **`settings` の整合性ルール:** `map_width` と `map_height` は `cell_size` の2倍の整数倍、`far_map_spacing` は `near_map_spacing` の整数倍、`near_map_spacing` は `dynamic_map_spacing` の整数倍である必要がある。詳細は [[D_地形形状]] を参照。エディタから作成したマップサイズは常にこのルールを満たすため、自動追記されるエントリでは通常意識する必要はない。

### 3.5. ゲームで確認する

登録表はバックエンドの起動時に読み込まれるため、バックエンドを再起動してからゲームの「ニューゲーム」ウィンドウを開く。地形マップ一覧に新しいマップが表示され、選択してゲームを開始すれば、編集した地形が反映される。

## 4. 新規地形をゼロから作る場合

以下のいずれかの方法で新規地形を作成できる:

1. **エディタの「新しい地形を追加」から始める(推奨):** 標高-10m・2×2セル(1000m×1000m)の最小サイズの標高マップが作業コピーとして生成され、地形エディタウィンドウが開く(既存マップ一覧には影響しない)。2.4節のマップサイズ変更で必要な大きさまで拡張しつつ編集する
2. **標高原本を複製する:** 「オリジナル地形」から選ぶと、その島の標高だけを持つ作業コピーができる(川・水面・資源・プロップ・カメラは含まれない)。実在の地形を土台に、配置は自分で作りたい場合に使う
3. **既存マップを土台にする:** 「既存マップを編集」から選び、メタデータ編集でマップIDを別のIDに変えてエクスポートすれば、元のマップを残したまま別のマップとして登録される
4. **外部ツールで作成する:** 標高データを NumPy 配列(`.npy`)として作成し、3.3〜3.5 の手順で配置する。この場合 `src_spacing` は実際のデータのグリッド間隔を指定する

## 5. 注意事項

- **編集はローカルの作業コピーに対して行われる:** バックエンドの `.npy` ファイルやゲームのセーブデータには影響しない。編集結果を残す操作は「.npyへエクスポート」だけで、エクスポートせずにウィンドウを閉じれば編集内容は失われる。
- **原本は書き換えられない:** `terrains/original/` 配下へのエクスポートは書き込み前に拒否され、原本の寸法・解像度を持つ `original_terrains.yaml` もエクスポートでは変更されない。
- **サムネイルは任意:** `.png` が存在しなくてもマップとしては正しく機能する(一覧ではプレースホルダー表示になるだけ)。
- **同じマップIDでのエクスポートは上書きになる:** `terrain_maps.yaml` のエントリと、同名の `.npy`・付随ファイルが置き換わる。作り直す前の状態を残したい場合は、別のマップIDでエクスポートするか、ファイルを退避しておく。
