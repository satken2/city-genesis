# 地形データ作成マニュアル

地形エディタでシナリオの地形を作る手順と、開発者がオリジナル地形を登録する手順を説明する。

地形エディタは「シナリオに含まれる地形を編集するツール」である。編集結果はシナリオ(`.cg`)へ保存し、オリジナル地形(標高・サムネイル・範囲などのメタデータだけを持つ地形の素材)は編集しない。両者の区別とデータの持ち方は [[D_地形形状]] §D.14 を参照。

## 1. 全体フロー

```
[トップメニュー →「シナリオ管理」→「地形を取り込む」タブ]
  → オリジナル地形を選んで「シナリオを作成」
  → 新しい自作シナリオができる(水面・川・資源・プロップ・カメラは空、地表・気候はオリジナル地形の値)
[「シナリオ」タブの自作カード →「地形を編集」]
  → Tauriがシナリオの地形を作業コピーへ書き出し(2節)、地形エディタウィンドウを開く
  → エディタで編集(地形・水面・川・資源・プロップ・カメラ・地表・気候)
  → 「シナリオに保存」でシナリオへ書き込む(3節)
  → シナリオ管理の一覧が更新される(シナリオの版 content_revision が1つ上がる)
```

- 地形を編集できるのは自作シナリオだけ。コミュニティ・DLCのシナリオは「コピーして編集」で自作シナリオにしてから編集する。
- DLC由来の都市から作ったシナリオは、自作でも暗号化されているので地形エディタで開けない(コアが `SCENARIO_ENCRYPTED` で断る。[[D_地形形状]] §D.14.3)。シナリオ管理ではそのカードの「地形を編集」を押せなくし、理由をボタンのツールチップで示す。資源・プロップは「都市を編集」で開いた神モードのセッションで編集する。
- ゲームのセッション中は使えない(コアが `SESSION_ACTIVE` で断る)。トップメニューに戻ってから操作する。
- 道路・建物・造成跡・埋立地のあるシナリオでは、標高・水面・川がロックされる。編集できるのは資源・プロップ・カメラ・地表・気候だけになる(3.2節)。
- 作業コピーは初期データの受け渡し専用で、編集途中の状態を保存したり次回に再開したりする手段は持たない。編集結果を残す操作は「シナリオに保存」だけである(保存に成功すると、作業コピーも保存した内容に合わせて書き換わる。3.1節)。

> **自動編集(侵食シミュレーション):** 「地形編集」の自動編集タブには、雨粒パーティクルが斜面を削りながら流れて谷筋と堆積を作る**水流侵食**と、安息角を超える崖・急斜面を崩してなだらかにする**熱侵食**の2種類がある。選択範囲があればその範囲を起点に、なければマップ全体へ適用される(雨粒の数・侵食の強さ・安息角・反復回数といった主要パラメータは調整可能)。水流侵食は標高0以下を海面として扱い、海面に達した雨粒は流速を失って消滅する。運んでいた土砂は海中の斜面を滑り落ち、安息角より緩い海底で沈降する(深い海に面した断崖から流れ込んだ土砂は、崖のふちではなく崖下の海底に扇状に堆積する)。海中の堆積が積み重なって標高が海面を超えた場合にのみ新しい陸地(河口のデルタ)が生まれるため、海岸線が土砂で際限なく埋め立てられて島が広がることはない。

## 2. 作業コピー

「地形を編集」を押すと、Tauri(Rust)のコマンド `prepare_scenario_terrain_editor` がバックエンドの `GET /api/v1/scenarios/{id}/terrain` からシナリオの地形を取得してローカル(AppData)へ書き出し、エディタウィンドウがそれを読み込む。ファイル配置の詳細は [ファイル配置](../programs/ファイル配置.md) を参照。

| プラットフォーム    | パス                                                                      |
| ----------- | ----------------------------------------------------------------------- |
| **Windows** | `%LOCALAPPDATA%\UrbanGenesis\terrain_editor\{editor_id}\`                |
| **macOS**   | `~/Library/Application Support/UrbanGenesis/terrain_editor/{editor_id}/` |
| **Linux**   | `$XDG_DATA_HOME/UrbanGenesis/terrain_editor/{editor_id}/`                |

`{editor_id}` は作業コピーごとに発行するUUID(小文字・ハイフン区切りの正規形。Tauriはこの形以外のIDを受け付けず、フォルダの外を指させない)で、シナリオのIDとは別物である。地形エディタと3Dプレビューのウィンドウは、この `editor_id` を対象IDとして開く。

- 同じシナリオの地形エディタが表示中なら、新しい作業コピーを作らずにそのウィンドウの `editor_id` を返す。「地形を編集」を押し直しても未保存の編集は消えず、2枚のウィンドウの保存が互いを上書きすることもない。
- どのウィンドウにも結び付かず、作成から1時間を過ぎた作業コピーは、次に「地形を編集」を押したときに Tauri が削除する。

### 2.1. ディレクトリ構成

```
terrain_editor/
└── {editor_id}/
    ├── meta.json       # 編集対象のシナリオ・ロック情報・マップ設定値と、水面・川・資源・プロップ・カメラ・地表・気候
    └── near.bin        # 近景標高マップ(float16 LE の raw バイナリ)
```

### 2.2. meta.json の形式

```json
{
  "scenario_id": "local~0f8fad5b-d9cb-469f-a165-70867728950e",
  "terrain_map_id": "yoron",
  "title": "与論島",
  "locks": { "heights_locked": false, "reasons": [] },
  "map_width": 12000,
  "map_height": 8000,
  "near_spacing": 10,
  "far_spacing": 200,
  "cell_size": 500,
  "grid_rows": 801,
  "grid_cols": 1201,
  "water_surfaces": [],
  "rivers": [],
  "resources": [],
  "props": { "instances": [], "scatters": [] },
  "camera": null,
  "ground_cover": 1,
  "climate": 1
}
```

| フィールド | 内容 |
|---|---|
| `scenario_id` | 保存先のシナリオID。「シナリオに保存」は保存先をUIから受け取らず、ここから引く |
| `terrain_map_id` / `title` | 元のオリジナル地形のIDと、シナリオのタイトル(左パネルの見出しに使う) |
| `locks` | 標高のロック `{heights_locked, reasons}`([[D_地形形状]] §D.14.4)。欠けている・形が崩れているときは、Rust・UIともロックされているものとして扱う(編集できない側に倒す) |
| `map_width` / `map_height` / `near_spacing` / `grid_rows` / `grid_cols` | 標高データのグリッド構造(2.3節) |
| `far_spacing` / `cell_size` | 標高データには影響しないマップ設定値 |
| `water_surfaces` / `rivers` / `resources` / `props` / `camera` | シナリオの配置情報。仕様の正は [[D_地形形状]] §D.10〜§D.13 と [[M_地形プロップ]]。`resources` の `id` はシナリオの中の資源のIDの文字列。`props` の `id` はエディタの中で見分けるためだけに使い、保存では使わない(保存後の作業コピーには、エディタで振ったIDが残る) |
| `ground_cover` / `climate` | 地表種別と気候区分([[D_地形形状]] §D.15・§D.16)。`null` のときエディタは草原・温暖湿潤として扱う |

作業コピーを作るとき、Tauri は標高のバイト数が `grid_rows × grid_cols × 2` と一致することを確かめ、一致しなければ地形エディタを開かない。

### 2.3. near.bin の形式

- **データ型:** float16 (IEEE 754 half precision), リトルエンディアン
- **形状:** `grid_rows` × `grid_cols` の2次元配列(行優先)
  - `grid_rows` = `map_height / near_spacing + 1` (Z方向=縦)
  - `grid_cols` = `map_width / near_spacing + 1` (X方向=横)
- **座標系:** 配列の先頭(行0・列0)がワールド座標 `(-map_width/2, -map_height/2)` の南西隅、末尾が `(map_width/2, map_height/2)` の北東隅に対応する(マップ中心がワールド原点)。行が増えるほど北(ワールド+Z)、列が増えるほど東(+X)へ進むので、画像として見るときは上下を反転すると北が上になる。向きの規約は [[D_地形形状]] §D.3.1
- **標高0以下のピクセル:** 海面を表す
- **総バイト数:** `grid_rows * grid_cols * 2`

### 2.4. メタデータを確認・編集する

元の地形・遠景グリッド間隔・セルサイズ・地表の種類・気候・マップサイズは編集対象から独立したメタデータで、左パネル上部の「3Dプレビューを開く」の右隣にある「メタデータ編集」ボタンでモーダルダイアログを開いて確認する。閉じるボタンまたはEscapeで編集画面へ戻り、入力した値は保持される。

| フィールド | 編集可否 | 説明 |
|---|---|---|
| 元の地形 | 読み取り専用 | シナリオを作ったオリジナル地形の名前 |
| 遠景グリッド間隔 (`far_spacing`) | 読み取り専用 | 保存APIが受け取らない項目なので、編集しても保存されないため読み取り専用にしている |
| セルサイズ (`cell_size`) | 読み取り専用 | エディタではセル境界グリッドの間隔を決める。ゲーム側では標高の保存単位・地形タイルの生成単位になる([[D_地形形状]] §D.4) |
| 地表の種類 (`ground_cover`) | 編集可 | 草原・砂漠・濃い草地・雪原・乾燥地から選ぶ。ゲーム内の地表の色と質感、エディタの2D・3Dプレビューの配色が変わる。見た目だけの属性で、シミュレーションには影響しない([[D_地形形状]] §D.15) |
| 気候 (`climate`) | 編集可 | 温暖湿潤・亜熱帯・湿潤大陸性・地中海性・ステップ・砂漠・亜寒帯から選ぶ。ゲーム内の季節ごとの天気の出方(晴れ・雨・雪の出現割合)が変わる。地表の種類とは独立に、その土地の実際の気候に合わせて選ぶ。見た目だけの属性で、シミュレーションには影響しない([[D_地形形状]] §D.16、[[U_天気と環境光]]) |
| マップサイズ・近景間隔・グリッド行数/列数 | 読み取り専用 | 標高データのグリッド構造そのもの。シナリオの寸法は変えられない(寸法の違う標高を保存するとコアが `TERRAIN_SIZE_MISMATCH` で拒否する) |

## 3. シナリオに保存する

### 3.1. 保存の流れ

左パネル下部の「シナリオに保存」を押すと、Tauri(Rust)のコマンド `save_scenario_terrain` がその時点の編集内容を `PUT /api/v1/scenarios/{id}/terrain` へ送る。送る内容と、コアでの扱いは次のとおり(仕様の正は [[D_地形形状]] §D.14.3)。

| 内容 | 送り方 | コアでの扱い |
|---|---|---|
| 標高 | near.bin と同じ float16 LE を base64 にした文字列 | 近景を置き換え、遠景を作り直す |
| 水面・川 | 一覧全体。川は彫り込み済みのものだけ(未彫り込みの川は保存されない) | 一覧全体を置き換え、海岸線を抽出し直す |
| 資源 | 一覧全体 | IDで差分を適用する(既存は更新、新規は追加、無くなったものは削除)。新規の資源に振ったIDは応答の `resource_ids` で返る |
| プロップ | 個別配置・範囲散布の全体 | 全置換(IDは保存しない) |
| カメラ・地表・気候 | 値 | そのまま置き換える |

標高・水面・川のどれかを保存すると、コアは土地区画の種別(陸・沿岸・海上)・勾配・基準標高と、サービスの効果範囲も計算し直す。保存は通常のシナリオ保存と同じ経路を通り、シナリオの版(`content_revision`)が1つ上がる。

保存に成功すると、エディタは `scenarios:changed` を送り、シナリオ管理の一覧・画像・版を更新させる。エディタはそのまま開いており、続けて編集して何度でも保存できる。保存中に行った編集は未保存のまま残る。

エディタで新しく作った資源は、保存するまでエディタの中だけの仮のIDを持つ。保存に成功すると、エディタは応答の `resource_ids` で仮のIDをシナリオの中のIDに置き換える。置き換えるのは今の資源の一覧と Undo/Redo の履歴の両方で、応答を待つ間に足した資源は仮のIDのまま次の保存を待つ。仮のIDのまま送り直すと、コアは前回作った資源を削除して別のIDで作り直してしまうためである。Tauri も保存に成功したら作業コピー(`meta.json` と、標高を送ったときは `near.bin`)を保存した内容に合わせ、`meta.json` の資源のIDも置き換える。Rustの `save_scenario_terrain` は応答の `content_revision`・`locks`・`resource_ids` をUIへ返す。

保存対象を変える操作をすると、保存ボタンの上に「未保存の変更があります」と表示する。ウィンドウを×で閉じると未保存の編集は失われる(閉じる前の確認は出ない)。

失敗したときはエラーをエディタに表示する。Rustのコマンドはコアのエラーを「`CODE`: 本文」の形で返し、UIは先頭のコードで翻訳文を引く。主なコードは `TERRAIN_LOCKED`(ロック中に標高・水面・川を送った)、`TERRAIN_SIZE_MISMATCH`(寸法が違う)、`TERRAIN_INVALID`(形の崩れた値)、`RESOURCE_VALIDATION_ERROR` / `PROP_VALIDATION_ERROR`(資源・プロップの値の誤り)、`SESSION_ACTIVE`(ゲームのセッション中)、`SCENARIO_ENCRYPTED`(DLC由来の暗号化されたシナリオ)。

地形エディタはサムネイル画像を作らない。シナリオの画像は紹介情報ウィンドウで設定する([シナリオ制作と配布](../programs/シナリオ制作と配布.md))。

### 3.2. 標高のロック

道路・線路・インフラのパス、形のある建物、超近景セル(造成などで書き換えた標高)、埋立地のどれかがあるシナリオでは、標高・水面・川がロックされる。建設物は建てたときの地形に合わせて造成・接地しているので、下の地形だけを変えると食い違うためである。理由コードは [[D_地形形状]] §D.14.4 を参照。

ロックされたシナリオを開くと、エディタは地形(自動編集を含む)・水面・川のタブを選べなくし、ロックの理由を表示して資源タブを選んだ状態で始まる。保存では標高・水面・川を `null` で送る。Rustの `save_scenario_terrain` も、作業コピーの `locks` がロックを示しているのに標高・水面・川が送られたら、コアへ送る前に `TERRAIN_LOCKED` で拒否する。

地形の作り込みは、道路や建物を置く前(地形から作ったばかりのシナリオ)に済ませておく。

## 4. オリジナル地形を登録する(開発者向け)

オリジナル地形は、ゲームに同梱する地形の素材である。登録するのは開発者だけで、ゲームやエディタからは作れない。

### 4.1. ファイルを置く

ゲームが読み込むオリジナル地形は、バックエンドのインストール先の `assets/terrains/` に集約されている。

```text
assets/
└── terrains/
    ├── original/                      # 編集禁止の標高原本の保管庫(ゲームは背景地形以外を読まない)
    ├── original_terrains.yaml         # 原本の寸法・解像度(開発者用)
    ├── terrain_maps.yaml              # オリジナル地形の登録表
    ├── map_yoron.npy                  # 与論島
    ├── map_yoron.png
    ├── map_my_island.npy              # ← 新しく追加するファイル
    └── map_my_island.png              # ← 4.3節で生成する
```

標高は NumPy 配列(`.npy`)で用意する。行0が南端・列0が西端で、標高0m以下が海になる([[D_地形形状]] §D.3.1)。

### 4.2. terrain_maps.yaml に登録する

`assets/terrains/terrain_maps.yaml` にエントリを手で追加する。

```yaml
# my_island
my_island:
  id: my_island
  name: my_island
  file_name: terrains/map_my_island.npy
  src_spacing: 10.0
  settings:
    map_width: 12000
    map_height: 8000
    near_map_spacing: 10
    far_map_spacing: 200
    dynamic_map_spacing: 1
    cell_size: 500
  ground_cover: 1
  climate: 1
```

| フィールド | 意味 |
|---|---|
| `id` | 地形を識別する固有のキー。UIはこのIDで翻訳された名前(`terrainProfiles`)を引く |
| `name` | 翻訳の無い地形の表示名 |
| `file_name` | `.npy` ファイルの `assets/` 基準の相対パス。サムネイルは拡張子を `.png` に置き換えたパスを機械的に探す |
| `src_spacing` | `.npy` のグリッド間隔(m)。読み込み時に `near_map_spacing` へリサンプリングする。`.npy` が既に `near_map_spacing` 解像度なら同じ値にする |
| `settings` | マップの設定値([[D_地形形状]] §D.2.1) |
| `background` | 任意。都市外の背景地形の `{"file_name", "origin"}`([[D_地形形状]] の「都市外の背景地形」) |
| `ground_cover` | 地表の種類(1=草原、2=砂漠、3=濃い草地、4=雪原、5=乾燥地)。キーが無ければ草原。この地形から作る新しい都市の初期値で、既存の都市・シナリオには影響しない([[D_地形形状]] §D.15) |
| `climate` | 気候(1=温暖湿潤、2=亜熱帯、3=湿潤大陸性、4=地中海性、5=ステップ、6=砂漠、7=亜寒帯)。キーが無ければ温暖湿潤。扱いは `ground_cover` と同じ([[D_地形形状]] §D.16) |

水面・川・資源・プロップ・カメラは登録表に書かない。これらはシナリオが持つので、地形からシナリオを作ったあとに地形エディタで作る。

> **`settings` の整合性ルール:** `map_width` と `map_height` は `cell_size` の2倍の整数倍、`far_map_spacing` は `near_map_spacing` の整数倍、`near_map_spacing` は `dynamic_map_spacing` の整数倍である必要がある。詳細は [[D_地形形状]] を参照。

### 4.3. サムネイルを生成する

`tauri/tools/regenerate_terrain_thumbnails.py` に `terrain_maps.yaml` を渡す。Pythonの`numpy`・`Pillow`・`PyYAML`、Node.js、`tauri/`での`npm install`が必要。登録表は`assets/terrains/terrain_maps.yaml`という配置を前提とし、`file_name`を`assets/`基準で解決する。

```sh
python tauri/tools/regenerate_terrain_thumbnails.py /path/to/assets/terrains/terrain_maps.yaml
```

登録済みの全地形について、標高配列と地表種別から`.npy`と同名のPNGを作り直す。`--map-id my_island`のようにIDを指定すると対象を絞れる(複数指定可)。`terrain-thumbnail-render.mjs`を通して`terrainThumbnail.ts`の画素生成を実行するため、配色や海岸処理を別実装として持たない。画像は北が上・東が右の平面図で、地図の全範囲と縦横比を保つ。標高0m以下は透明、陸地は2Dエディタと同じ標高カラーランプで描く。標高・登録表・`original/`は変更しない。

サムネイルは `GET /api/v1/terrain/maps/{id}/thumbnail` から配信される。`.png` が無い地形ではこのAPIが404を返し、UIはプレースホルダーを表示する(地形としては正しく機能する)。

標高データ由来の画像にも元データの出典表記が適用される。収録地形の出典は`src/data/credits.ts`の既存の地形データ項目にまとめて記録する。描画の検証は`tauri/`で`node tools/terrain-thumbnail-test.mjs`を実行する。

### 4.4. ゲームで確認する

登録表はバックエンドの起動時に読み込まれるため、バックエンドを再起動してからシナリオ管理の「地形を取り込む」タブを開く。新しい地形が一覧に表示され、「シナリオを作成」でその地形のシナリオを作れる。表示名を翻訳するには、全7言語の `terrainProfiles.json` と `src/data/terrainProfiles.ts` に追加する([コンポーネント連携](../programs/コンポーネント連携.md#ニューゲームと地形紹介))。

## 5. 注意事項

- **編集はローカルの作業コピーに対して行われる:** 「シナリオに保存」するまで、シナリオにもゲームのセーブデータにも影響しない。
- **オリジナル地形は書き換えられない:** 地形エディタの保存先は常にシナリオで、`terrain_maps.yaml`・`.npy`・`original/` を変更するAPIやコマンドは無い。
- **寸法は変えられない:** シナリオのマップサイズ・格子はオリジナル地形のまま固定される。別の大きさが必要なら、その大きさのオリジナル地形を登録する。
- **同じシナリオへの保存は上書き:** 保存のたびにシナリオの地形が置き換わり、版が1つ上がる。保存した後で以前の地形へ戻す操作は無い(エディタのUndoは保存前の編集だけが対象)。
