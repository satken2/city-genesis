# 地形データ作成マニュアル

Tauriの地形エディタで編集した地形データを、ゲームで選択可能な地形マップとして登録するまでの手順を説明する。

## 1. 全体フロー

```
[既存マップ選択、または「編集途中のデータを開く」から再開]
  → (新規選択時のみ)Tauriエディタがバックエンドから標高データを取得しAppDataに作業コピーを保存
  → エディタで編集(手動編集ツール・自動編集(侵食シミュレーション))
  → 「保存」ボタンで編集結果とサムネイル画像を作業コピー(near.bin / meta.json / thumbnail.png)へ書き戻す(任意。エクスポート前に必須ではない)
  → 「.npyへエクスポート」ボタンで .npy とサムネイル.pngを書き出す(3.1節、保存先はダイアログで指定)
  → エクスポート先が assets/ ディレクトリ(terrain_maps.yamlがある場所)なら、エントリが自動で追記/上書きされる(3.4節)
  → ゲームの「ニューゲーム」で選択可能になる(サムネイルも一覧に表示される)
```

> **現状の実装状況:** 2026年7月時点で、地形エディタの**表示(描画・等高線・グリッド)・手動編集ツール(範囲選択+適用)・自動編集(侵食シミュレーション)・作業コピーへの保存・作業コピーの再オープン(編集途中のデータを開く)・`.npy`への自動エクスポート・サムネイル画像の自動生成・`terrain_maps.yaml`への自動追記は実装済み**である。自動編集には、雨粒パーティクルが斜面を削りながら流れて谷筋と堆積を作る**水流侵食**と、安息角を超える崖・急斜面を崩してなだらかにする**熱侵食**の2種類があり、選択範囲があればその範囲を起点に、なければマップ全体へ適用される(雨粒の数・侵食の強さ・安息角・反復回数といった主要パラメータは調整可能)。水流侵食は標高0以下を海面として扱い、海面に達した雨粒は流速を失って消滅する。運んでいた土砂は海中の斜面を滑り落ち、安息角より緩い海底で沈降する(深い海に面した断崖から流れ込んだ土砂は、崖のふちではなく崖下の海底に扇状に堆積する)。海中の堆積が積み重なって標高が海面を超えた場合にのみ新しい陸地(河口のデルタ)が生まれるため、海岸線が土砂で際限なく埋め立てられて島が広がることはない。`.npy` への変換(3.1節)はエディタの「.npyへエクスポート」ボタンから直接行え、手動でのPythonスクリプト実行は不要。ただしユーザー環境に Python と numpy がインストール済みであることが前提(このアプリ自体はPythonをバンドルしない)。

## 2. 作業コピーの場所

地形エディタを開くと、バックエンドの `GET /api/v1/terrain/maps/{map_id}/near` から標高データを取得し、Tauri管理領域に作業コピーを保存する。ファイル配置の詳細は [[ファイル配置]] を参照。

| プラットフォーム    | パス                                                                    |
| ----------- | --------------------------------------------------------------------- |
| **Windows** | `%LOCALAPPDATA%\UrbanGenesis\terrain_editor\{map_id}\`                |
| **macOS**   | `~/Library/Application Support/UrbanGenesis/terrain_editor/{map_id}/` |
| **Linux**   | `$XDG_DATA_HOME/UrbanGenesis/terrain_editor/{map_id}/`                |

`{map_id}` は `terrain_maps.yaml` に定義されたマップ識別子(例: `yoron`)。

### 2.1. ディレクトリ構成

```
terrain_editor/
└── {map_id}/
    ├── meta.json       # 設定値(マップサイズ・グリッド間隔等)
    ├── near.bin        # 近景標高マップ(float16 LE の raw バイナリ)
    └── thumbnail.png   # サムネイル画像(160x120のPNG。「保存」実行時に生成。任意)
```

### 2.2. meta.json の形式

```json
{
  "map_id": "yoron",
  "map_width": 12000,
  "map_height": 8000,
  "near_spacing": 10,
  "far_spacing": 200,
  "cell_size": 500,
  "grid_rows": 801,
  "grid_cols": 1201
}
```

### 2.3. near.bin の形式

- **データ型:** float16 (IEEE 754 half precision), リトルエンディアン
- **形状:** `grid_rows` × `grid_cols` の2次元配列(行優先)
  - `grid_rows` = `map_height / near_spacing + 1` (Z方向=縦)
  - `grid_cols` = `map_width / near_spacing + 1` (X方向=横)
- **座標系:** 配列の左上がワールド座標 `(-map_width/2, -map_height/2)`、右下が `(map_width/2, map_height/2)` に対応する(マップ中心がワールド原点)
- **標高0以下のピクセル:** 海面を表す
- **総バイト数:** `grid_rows * grid_cols * 2`

### 2.4. エディタでの保存(保存ボタン)

地形エディタの左パネル上部には「地図メタデータ」欄と「保存」ボタンがある。保存ボタンを押すと、編集中の標高データ(メモリ上の `elev` 配列)を float16 に変換し、Tauriコマンド `save_terrain_editor_data` 経由で作業コピーの `meta.json` / `near.bin` に書き戻す。

メタデータ欄の各フィールドは以下の通り:

| フィールド | 編集可否 | 説明 |
|---|---|---|
| マップID | 編集可 | 保存先ディレクトリ名(`meta.json` の `map_id`)。ロード時と同じIDを指定すれば上書き保存、異なるIDを指定すれば `terrain_editor/{新しいID}/` に新規保存される(「別名で保存」)。4節の「既存マップをベースに編集する」フローはこの仕組みを使う |
| 遠景グリッド間隔 (`far_spacing`) | 編集可 | 近景標高データ(near.bin)には影響しない独立したメタデータ |
| セルサイズ (`cell_size`) | 編集可 | 同上 |
| マップサイズ・近景間隔・グリッド行数/列数 | **編集不可** | 標高データのグリッド構造そのものと結び付いており、リサンプリングを実装しないまま変更すると `near.bin` との整合性が壊れるため、読み取り専用表示にとどめている |

> **保存はあくまで作業コピーの更新:** 「保存」ボタンで書き戻されるのはTauriが管理する作業コピー(2節のディレクトリ)のみで、バックエンドの元データやゲームのセーブデータには一切影響しない。編集結果をゲームで使うには、引き続き3節の手順で `.npy` へ変換して `assets/` に配置する必要がある。

> **サムネイル画像の生成:** 「保存」ボタンを押すと、地形全体が収まるように斜め上から見たサムネイル画像(160x120のPNG)も同時に生成され、作業コピーに `thumbnail.png` として書き戻される。生成はTerrain3DPreviewCanvasと同じハイトフィールドメッシュ・頂点カラーを、3Dプレビューウィンドウを開かずにオフスクリーンで一度だけ描画する方式で行う。`EditorWindow`の「編集途中のデータを開く」タイル一覧は、このサムネイルがあればプレースホルダーの代わりに表示する。

### 2.5. 編集を中断・再開する(編集途中のデータを開く)

地形エディタウィンドウを閉じても、作業コピーはAppDataに残ったままになる。`EditorWindow`(タスクバーの「エディタ」)の地形エディタタブを開くと、「新しい地形を追加」ボタンの下に「編集途中のデータを開く」セクションが表示され、AppDataに残っている作業コピー(`{map_id}`ごと)が一覧表示される。

一覧のタイルをクリックすると、Tauriコマンド `list_terrain_editor_maps` で取得した `map_id` を使って地形エディタウィンドウを直接開く。このとき通常の新規選択フロー(`copy_terrain_for_editor` によるバックエンドからの再取得)は経由しない。バックエンドから再取得すると作業コピーが上書きされ編集内容が失われるため、再開時は意図的にこのステップをスキップしている。

## 3. 編集結果をゲームで使える地形マップにする

編集が完了した `near.bin` を、バックエンドが読み込める `.npy` ファイルに変換し、所定の場所に配置する。

### 3.1. near.bin を .npy に変換する(エディタから自動実行)

地形エディタの「地図メタデータ」カードには、「保存」ボタンの隣に「.npyへエクスポート」ボタンがある。押すと保存先パスを選ぶダイアログが開き、パスを指定すると編集中の標高データ(メモリ上の `elev` 配列。事前に「保存」ボタンを押しておく必要はない)がその場で `.npy` に変換され、指定パスに書き出される。

このときサムネイル画像(160x120のPNG。2.4節参照)もこの時点の標高データから改めて生成され、`.npy` と同じディレクトリ・同じファイル名(拡張子だけ `.png`)で書き出される。たとえば `map_my_island.npy` を指定すると `map_my_island.png` も同時に生成される。この命名規則は3.4節の `terrain_maps.yaml` の `file_name` フィールドから機械的に導出できるため、サムネイル専用のフィールドは不要。

変換自体は、アプリに同梱された `height_map_bin2npy.py`(内容は本節末尾のスクリプトと同じ)を、ユーザー環境の `python` / `python3` コマンドで実行することで行われる。**そのため、変換にはユーザー環境に Python と numpy がインストール済みであることが前提となる**(このアプリ自体はPythonをバンドルしない)。Pythonが見つからない、または変換に失敗した場合はエディタ画面にエラーメッセージが表示される。

同梱スクリプトが内部で行っている変換処理は以下の通り(参考):

```python
import json
import numpy as np

# meta.json からグリッド寸法を読み込む
with open("meta.json", "r") as f:
    meta = json.load(f)

rows = meta["grid_rows"]
cols = meta["grid_cols"]

# near.bin を float16 の NumPy 配列として読み込む
with open("near.bin", "rb") as f:
    data = np.frombuffer(f.read(), dtype=np.float16).reshape(rows, cols)

# .npy として保存
np.save("map_my_island.npy", data)
```

### 3.2. src_spacing の設定

バックエンドの地形読み込み処理(`Terrain.load_heightmap_data`)は、`.npy` ファイルを `src_spacing`(ソースデータのグリッド間隔)から `near_map_spacing` にリサンプリングする。

地形エディタの出力は既に `near_map_spacing` 解像度でリサンプリング済みであるため、`terrain_maps.yaml` で `src_spacing` を `near_map_spacing` と同じ値に設定すれば、リサンプリングが実質的に恒等(ズーム1.0)になり、データがそのまま配置される。

### 3.3. .npy ファイルを配置する

変換した `.npy` ファイルと、同時に生成された `.png` サムネイルを、バックエンドのインストール先にある `assets/` ディレクトリに配置する。**「.npyへエクスポート」の保存先ダイアログで直接 `assets/` を指定してエクスポートすれば、この配置作業とterrain_maps.yamlへの追記(3.4節)が1回の操作で完了する。**

```
<インストール先>/
└── assets/
    ├── terrain_maps.yaml     # マップ定義ファイル
    ├── map_yoron.npy         # 与論島
    ├── map_aogashima.npy     # 青ヶ島
    ├── map_my_island.npy     # ← 新しく追加されるファイル
    └── map_my_island.png     # ← 新しく追加されるサムネイル(任意。npyと同名で拡張子だけ.png)
```

サムネイルは `GET /api/v1/terrain/maps/{map_id}/thumbnail` から配信される(`file_name` の拡張子を `.png` に置き換えたパスを機械的に探すため、専用の設定項目は不要)。ファイルが存在しないマップ(与論島・青ヶ島などサムネイル未生成のもの)はこのエンドポイントが404を返し、`NewGameWindow`・`EditorWindow` はプレースホルダー表示にフォールバックする。

### 3.4. terrain_maps.yaml へのエントリ追加(エクスポート時に自動実行)

「.npyへエクスポート」実行時、Tauriコマンド `export_terrain_as_npy` はエクスポート先ディレクトリに `terrain_maps.yaml` が存在するかを確認する。

- **存在する場合:** そのマップIDのエントリを自動で追記する(同じ `map_id` のエントリが既にあれば、その内容を上書きする)。既存の他エントリのコメントや空行区切りはそのまま残る(テキストベースでブロック単位を差し替えているため、YAML全体を再整形することはない)。
- **存在しない場合:** 何も書き換えず、エディタ側に「terrain_maps.yaml が見つからなかった」旨の通知ポップアップが表示される。この場合は以下の手順で手動追加する。

自動生成されるエントリの内容:

```yaml
# my_island
my_island:
  id: my_island
  name: my_island
  file_name: map_my_island.npy
  src_spacing: 10.0
  settings:
    map_width: 12000
    map_height: 8000
    near_map_spacing: 10
    far_map_spacing: 200
    dynamic_map_spacing: 1
    cell_size: 500
  initial_cells: [[11, 7], [11, 8], [12, 7], [12, 8]]
  camera:
    x: 120.0
    y: 150.0
    z: -340.0
    yaw: 30.0
    pitch: 50.0
```

各フィールドの意味:

| フィールド | 意味 |
|---|---|
| `id` | マップを識別する固有のキー。エディタで指定したマップIDがそのまま入る |
| `name` | ゲーム内で表示される名称。**自動生成時は `id` と同じ文字列が入るため、日本語名等に変更したい場合はエクスポート後に手動で書き換える** |
| `file_name` | `assets/` に配置した `.npy` ファイル名(エクスポート時の出力ファイル名から自動設定) |
| `src_spacing` | ソースデータのグリッド間隔(m)。エディタ出力は常に `near_map_spacing` と同じ値が自動設定される |
| `settings` | マップの設定値。エディタの地図メタデータから自動設定される。`dynamic_map_spacing` のみエディタ側に対応する概念がないため常に `1` 固定になる |
| `initial_cells` | ゲーム開始時に開放しておくセル。`map_width`/`map_height`/`cell_size` から中央付近の2×2セルを機械的に算出する近似値のため、必要に応じて手動調整する |
| `camera` | 新規都市を始めたときのカメラの位置(`x`/`z`=ワールド座標m、`y`=高さm)と向き(`yaw`=北を0とする時計回りの度、`pitch`=見下ろし角の度)。エディタの「カメラ」タブで設定した値が入る。未設定ならキー自体が書かれず、ゲームはマップ中心の上空の既定視点で始まる。詳細は [[D_地形形状]] §D.13 |

自動追記されない場合(手動で追加する場合)は、上記と同じ形式のエントリを `assets/terrain_maps.yaml` に追加する。

> **`settings` の整合性ルール:** `map_width` と `map_height` は `cell_size` の2倍の整数倍、`far_map_spacing` は `near_map_spacing` の整数倍、`near_map_spacing` は `dynamic_map_spacing` の整数倍である必要がある。詳細は [[D_地形形状]] を参照。エディタから作成したマップサイズは常にこのルールを満たすため、自動追記されるエントリでは通常意識する必要はない。

### 3.5. ゲームで確認する

バックエンドを再起動し、ゲームの「ニューゲーム」ウィンドウを開くと、地形マップ一覧に新しいマップが表示される。選択してゲームを開始すれば、編集した地形が反映される。

## 4. 新規地形をゼロから作る場合

エディタの「新しい地形を追加」ボタンを押すと、標高-10m・2×2セル(1000m×1000m)の最小サイズの標高マップが作業コピーとして生成され、地形エディタウィンドウが開く(既存マップ一覧には影響しない)。以下のいずれかの方法で新規地形を作成できる:

1. **エディタの「新しい地形を追加」から始める(推奨):** 生成された最小マップを起点に、2節の「マップサイズ変更」で必要な大きさまで拡張しつつ編集する
2. **既存マップをベースに編集する:** 与論島や青ヶ島をベースに選択し、エディタで編集して別名で保存する
3. **外部ツールで作成する:** 標高データを NumPy 配列(`.npy`)として作成し、3.3〜3.5 の手順で配置する。この場合 `src_spacing` は実際のデータのグリッド間隔を指定する

## 5. 注意事項

- **編集はローカルコピーに対して行われる:** エディタでの編集は `AppData` の作業コピーに対して行われ、バックエンドの元の `.npy` ファイルやゲームのセーブデータには影響しない。`.npy` への変換自体はエディタから行えるが、`assets/` への配置(3.3節)は引き続き手動作業が必要(保存先ダイアログで直接 `assets/` を指定すれば実質1手順で済む)。`terrain_maps.yaml` へのエントリ追加(3.4節)は、エクスポート先に `terrain_maps.yaml` があれば自動で行われる。
- **サムネイルは任意:** `thumbnail.png` / `map_my_island.png` が存在しなくてもマップとしては正しく機能する(一覧ではプレースホルダー表示になるだけ)。一度も「保存」または「.npyへエクスポート」を実行していない作業コピーにはサムネイルがない。
- **同じ `map_id` を上書きしても元データは失われない:** `assets/` の元の `.npy` ファイルは別名で残しておくことを推奨する。
- **Steam配布時の同梱:** Steamで配布する場合、`assets/` ディレクトリごとパッケージに含まれる。ユーザーが自作した地形マップを他のユーザーと共有するには、`.npy` と `terrain_maps.yaml` のエントリを配布する必要がある。
