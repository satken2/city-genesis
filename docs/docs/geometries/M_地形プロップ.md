# M. 地形プロップ（装飾オブジェクト）

## M.1. 役割と保存データ

地形プロップは森・茂み・岩などの純粋な装飾で、経済シミュレーション、配置コスト、維持費、天然資源とは接続しない。通常プレイでも未開放セルでも配置できる。

| 型 | 保存する内容 | 用途 |
|---|---|---|
| PropScatter | prop_type、region、density（本/ha）、seed、version | 森などの範囲散布 |
| PropInstance | prop_type、XZ座標、height（地面からの相対高さm）、rotation、scale、version | 明示的な個別配置 |

regionはGeoJSON MultiPolygonのcoordinates形式で、外周・穴・複数パートを保持できる。散布した木ごとの座標は保存しない。地形標高はUnityが表示中の地形から取得し、個別配置では保存したheightを加える。モデルはResources/Models/Props/{prop_type}からModelManager経由で取得する。

## M.2. 非破壊の重なり除外

**重なり除外はPropScatter（範囲配置）だけに適用する。** PropInstance（個別配置）はすべての種別で任意のXZと地面からの高さを指定でき、建物・土地区画・道路・水域・他プロップとの重なりを許可する。高さの正負や種別による浮遊制限は設けない。カーソルプレビュー・仮配置・保存後の描画で同じ扱いにする。地形更新時も相対高さを保ち、常駐セル、候補予算、描画LODは適用する。

**都市の開発ではregionも個別配置レコードも変更・削除しない。** 散布範囲の編集・プロップの撤去はユーザーの明示操作でのみ行う。描画側が現在の障害物と重なる範囲配置の候補点を非表示にする。障害物を撤去すると同じ位置・回転・スケールの個体が再表示される。これは装飾の表示復元であり、樹木の成長シミュレーションではない。

| 対象 | 除外条件 |
|---|---|
| 土地区画 | 建物の有無・建設状態・地面パネルの有無を問わず区画全体 |
| 海・湖などの水域 | 保存済み海岸線の陸地外側と湖の穴。島の陸地は残す |
| 道路・線路などの物理パス | 保存された占有ポリゴン |
| 完全地下のパス | 除外しない |
| 公共交通の論理パス | 除外しない |
| 高架・橋、部分的な地下パス | 初版は占有ポリゴン全体を除外する。高さに応じた部分除外は対象外 |

未建築の区画も開発用地として除外する。建物の有無を検索せず、区画とパスの空間索引だけで判定を完結させるためである。建物の解体後も区画が残る間は除外し、区画を撤去すると同じ候補点が再表示される。計画確定済みのパスも障害物になる。マッシュアップ施設の棟間や敷地内の庭も除外し、敷地外へはみ出した建物の底面は別途判定しない。

境界上も除外し、幹だけが境界の外にあって樹冠が壁に接する状態を抑えるため、モデルの水平半径×0.15×配置スケールを離隔に用いる。離隔上限は8m。バックエンドも取得BBOXを8m拡張し、隣接範囲の障害物を含める。

水域は地形セルサイズの固定格子ごとに陸地ポリゴンを差し引いて返す。カメラ移動で取得BBOXが変わっても、共通セルの形状と署名は変えない。海岸線が未設定なら水域判定を保留し、設定済みで空の陸地なら全域を水域として扱う。海岸線は初期near_mapから作られた固定形状なので、盛土・切土による岸の変化には追従しない。

除外は小区画の生成・障害物変更時にCPUで判定して保持する。毎フレームの木×建物総当たり、全市の障害物のポリゴン結合、散布regionからのdifferenceは行わない。建物のGameObjectやColliderの存在には依存しない。

## M.3. 安定した散布

PropGeometryが永続描画と散布プレビューの共通実装である。密度から候補格子の間隔を求め、ワールド原点に固定した格子番号とseedをハッシュして、各格子内の位置・回転・スケールを生成する。格子間隔は平方根（10000÷density）、下限0.5m。スケールは0.8〜1.2倍である。

候補点は小区画の半開区間に一意に所属する。region内かつ穴の外の点のみ採用し、重なる複数パートでも同じ点を二重生成しない。全範囲の乱数列を先頭から消費する必要がなく、必要な小区画だけ直接生成できる。

同じ密度・seedなら、カメラ移動、ロード順序、描画用分割数、障害物の追加・撤去、散布範囲の編集によって共通部分の候補点は変わらない。密度またはseedの編集では配置が変わる。シーン原点の移動量は描画行列に適用し、保存座標とハッシュには混ぜない。

## M.4. 既存LODとの統合

[E_LOD処理](E_LOD処理.md)の取得範囲・描画LOD・生成保持予算の分離に従う。

| 層 | 管理内容 |
|---|---|
| LodConfig / CellDataLoader | 常駐セル集合、ロード対象、LoadBatch |
| セル内の小区画 | 散布・除外・GPUバッチ生成の単位。独立した地形セルではない |
| DrawLod | 個体ごとのClose / Normal / Far / Hidden |
| フレーム・保持予算 | 生成処理の分散、常駐候補点数の制限 |

PropManagerは最大81の常駐セルをロードする。旧farCells/nearCells/dynamicCellsは同じ集合で、地形ティアによるFar固定は行わない。投影サイズとヒステリシスで個体のLODを選ぶ。正投影にも対応し、距離の上限は実距離で判定する。常駐範囲外のUltraFarにはプロップを描画しない。

候補予算は有効小区画へ配分し、各点のXZ・seedから得た固定順位で均等に選ぶ。列挙順で小区画全体を捨てない。個別配置を優先し、予算変更は安定した部分集合になる。距離・投影サイズによる本数の間引きとHiddenへの遷移は行わない。散布・個別配置ともに常駐候補を保ち、メッシュだけを簡略化する。既存の簡略モデルをインスタンシングし、森専用の全域代理メッシュは使用しない。影を送信するインスタンスは1フレーム4096まで（サブメッシュ分を含む）。更新中は旧バッチを維持し、一時的に旧・新配列を併せて保持する。

セルサイズの正はTerrainManager.CellSize。既定では一辺を8分割する（500mセルなら62.5m）。境界をまたがず、分割数はUnityのsubdivisionsで設定する。地形ハイトマップの513解像度、バックエンドのセルID、Dynamic地形の取得・保存単位には影響しない。

## M.5. GPU描画とモデル

PropRenderModelはプレハブ内のMeshFilter・MeshRenderer・子のローカル変換・サブメッシュ・マテリアルを取り出し、複製したマテリアルのinstancingを有効にする。永続表示では一本ごとのGameObjectやColliderを作らない。

| DrawLod | モデル |
|---|---|
| Close | {prop_type}_closeがあれば使用。なければ無印 |
| Normal | 無印の{prop_type} |
| Far | {prop_type}_farがあれば使用。なければ複雑なサブメッシュの頂点を空間集約して簡略化 |
| Far内の最小モデル | 木の樹冠を6三角形の四角錐にする。本数は維持 |

自動Farは4×8×4の格子で頂点とUVを集約し、縮退・重複三角形を除去する。元のマテリアルを引き継ぐ。128三角形以下の部品、読み取り不可のメッシュ、簡略化しても削減できない部品は元の形状を使う。専用アセットほど輪郭が忠実ではないため、目立つ種類には同じ原点・水平範囲・天端の_farを用意できる。幹を省く場合は底面だけを上げてよい。生成メッシュと複製マテリアルはPropRenderModelが所有し、全消去時に破棄する。共有FBXのメッシュ・マテリアルは変更しない。

GraphicsSettingsのInstancing VariantsはKeep Allに設定する。実行時に複製してinstancingを有効化するため、ビルド時のStrip Unusedでは必要なバリアントが除去され得る。保持によりシェーダービルド量は増える（[Unity Graphics Settings](https://docs.unity3d.com/jp/current/Manual/class-GraphicsSettings.html)）。プレビューも複製マテリアルでURPの透過ブレンドと深度書き込みOFFを明示する。

描画は小区画・種類・LOD・部品ごとにまとめ、Graphics.RenderMeshInstancedで一回最大511インスタンスを送る。バッチのBoundsにはモデルの実寸・回転・スケール・子の変換を含める。影はClose/Normalのカメラから150m未満に制限し、Farは影を落とさない。モデル・プレビューマテリアルのシェーダーはGPUインスタンシング対応が必要。

### M.5.1. モデル制作規約

1種別=1FBXで、`Assets/Models/Props/{prop_type}.fbx` に置く（閾値フォルダ・パーツ分割はない）。`{prop_type}_close.fbx` と `{prop_type}_far.fbx` は任意で、無印と同じ原点・水平bbox・天端で著作する。Farは幹を省いて底面を上げてよい。Closeは底面も無印と一致させる。ソースはBlenderライブラリ `genesis-gallery/library/props.blend`（コレクション名=種別ID）で、FBXは書き出し先である。

| 項目 | 規約 |
|---|---|
| 原点 | 配置基準面。高さ0で地表に置いたときの底面はY=0以下にする。幹を省くFarは樹冠の底面を上げてよい。XZはbboxの中心を原点に合わせる |
| 寸法・向き | 実寸（m）。個別配置は指定のY軸回転・一様スケール。散布は乱数の回転・0.8〜1.2倍スケール。階段本体はUnityの+Z側が下端、-Z側が上端 |
| 離隔 | 散布のみbboxのX/Z半幅の大きい方×0.15×スケール（上限8m）を使う。個別配置には適用しない |
| ノード変換 | ルートノードの位置・回転は打ち消される。子ノードのローカル変換は保持される |
| 遠景 | `_far`が無ければ、サブメッシュのうち128三角形を超えるものだけ4×8×4格子で頂点集約する。軽いモデルはそのまま使う |
| 頂点数 | 常駐候補は最大250,000本をインスタンシングするため、無印は数百頂点以内を目安にする |
| マテリアル | 名前で共有する`PROP_*`。GPUインスタンシング対応シェーダーが必要 |
| 種別登録 | `prop_master`に種別IDと表示名を登録する。モデルが無い種別は配置できるが描画されない |

非対称な形状は、標準FBX書き出しでBlender(x,y,z)がUnity(-x,z,-y)に写ることに注意する。規約の機械検査は `genesis-gallery/validator/rules.py` が行う。

同じ `Props/` には散布用ではない固定名のモデルも置く。工事車両 `construction_*`([道路メッシュの生成](G_道路メッシュの生成.md) §15)、環境演出の航空機・船舶 `ambient_*`([環境演出の乗り物](V_環境演出の乗り物.md))、歩行者 `pedestrian_*`([歩行者の描画](W_歩行者の描画.md))で、固定名のままでは `prop_master` に登録せず、手動配置用には §M.7.2 の数値ID別名を使う(歩行者は別名を持たない)。`ambient_*` と数値ID 201〜399 は接地検査の対象外である。歩行者は接地・水平中心を地形プロップと同じ規約で検査し、頂点予算だけ専用(Normal 700)である。

### M.5.2. 森林用の木モデル

`pipeline/jobs/build_prop_trees.py` が針葉樹・広葉樹と専用Farを `library/props.blend` に著作する。針葉樹は裾の広い4段の枝葉、広葉樹は重なる4個の葉塊で樹冠を作る。葉ごとの面や透過カードを使わず、低ポリゴンの輪郭と陰影に面を割り当てる。幹と葉は既存の2マテリアルを共有する。幹は5角柱のまま、著作座標の根元半径0.46m・上端半径0.24mとし、樹種ごとの寸法倍率を掛ける。幹の太さを調整しても樹冠寸法・高さ・面数は変えない。

葉面はスムーズ法線を使い、幹と針葉樹の枝段の底は平面法線を保つ。大きな三角面の境界で陰影が急変するのを抑えるが、輪郭の頂点数は増やさない。葉材質は非金属・粗さ0.9（UnityのSmoothnessは0.1）とし、針葉樹は深緑、広葉樹は黄緑を抑えた緑にする。`Props/Textures/PROP_*_color.png`の256×256画像に固定乱数の大小の色むらを焼き、無印とFarで共有する。2m基準のキューブ投影UVを使い、透明描画・追加サブメッシュ・専用シェーダーは増やさない。画像はsRGB、材質の乗算色は白にして二重着色を避ける。Blenderのノードだけで成立する質感にはせず、FBXから画像を外部参照する。


| 種別 | 高さ | 樹冠の幅 | 通常の頂点 / 三角形 | Farの頂点 / 三角形 |
|---|---|---|---|---|
| 1 針葉樹 | 12m | 4m | 46 / 72 | 9 / 14 |
| 2 広葉樹 | 9m | 6m | 58 / 96 | 12 / 20 |

頂点数はBlenderの共有頂点であり、Unity取り込み後は面法線などで分割される。専用Farは幹を省き、針葉樹は八角錐、広葉樹は正二十面体を元にした丸い樹冠にする。原点・水平範囲・天端を保ち、底面は樹冠の高さに置く。標準密度400本/haの格子間隔は5mなので、広葉樹は樹冠が部分的に重なって連続した森になる。針葉樹は細身の縦長シルエットを優先し、同じ密度では木の間に空隙が残る。配置座標・密度・乱数はモデルの変更に依存せず、低密度の散布には空隙が残る。Farでも本数を減らさず、水平範囲を維持する。木の投影比が画面高の1%未満になると、PropRenderModelが専用Farの樹冠bboxから生成した6三角形の四角錐へ替える。1.2%以上で元のFarへ戻す。既存のDrawLod.Farの中だけの切り替えであり、地形のUltraFarや共通LOD列挙値を増やさない。輪郭形状が変わるため、被覆面積が近景と完全一致するわけではない。

## M.6. 差分更新と負荷制限

マージBBOXで配置情報と障害物を一括取得する。候補点はプロップID/versionの組み合わせで、表示可否は障害物ID/形状signatureの組み合わせで差分更新する。道路の変更では関係する小区画の表示可否だけを更新し、候補点を再散布しない。削除や移動では旧位置側の小区画も応答との比較で更新される。

生成・高さ調整・描画バッチ構築はPerformanceConfig.FrameBudgetMsでフレーム分散する。LoadBatchと独自の世代番号で旧処理のコミットを防ぐ。同じ小区画のLOD再構築中は前の完成済みバッチを維持し、新しい完成結果へ置き換える。候補・除外データの更新で小区画を置き換える場合は、新バッチ完成まで一時的に非表示になる。

一散布レコード5,000個という上限は設けない。常駐候補点の予算maxResidentCandidates（既定250,000）を有効小区画へ配分し、各点の固定順位で選ぶ。非表示候補も復元用に数える。予算超過で小区画全体を捨てない。更新作業中は旧配列と新配列が一時的に併存するため、瞬間的なメモリ使用量は常駐分を上回る。

高さは `HeightmapTextureManager.GetTerrainHeight`（Utilsへ委譲）で現在のTerrainを参照し、個別配置では候補に保持したheightOffsetを加える。初回・再読み込み・地形編集・タイル完成通知のすべてで同じ式を使う。高さにモデルのスケールを掛けない。

## M.7. APIと配置プレビュー

| メソッド | パス | 内容 |
|---|---|---|
| GET | /api/v1/props?bbox=x1,z1,x2,z2 | scattersとinstancesを取得。既定上限は各10,000レコード |
| GET | /api/v1/props?bbox=…&include_obstacles=true | obstaclesを同梱する完全な描画用スナップショット。件数を途中で切らない |
| POST | /api/v1/props/scatters | polygon、prop_type、density、任意seedで作成 |
| PATCH | /api/v1/props/scatters/{id} | polygon、density、seedを編集 |
| DELETE | /api/v1/props/scatters/{id} | 散布範囲を撤去 |
| POST | /api/v1/props/instances | instances配列を一括作成 |
| DELETE | /api/v1/props/instances/{id} | 個別配置を撤去 |

obstaclesの各項目はkey、signature、ワールド座標のpolygon、floor_variant、visual_variantを持つ。区画は`parcel:{id}`、パスは`path:{id}`をkeyとし、floor_variantとvisual_variantは0で返す。床材に関係なく区画全体を除外する。水域は`water:{x}:{z}:{index}`をkeyとし、`holes`に水域内部の島のリングを保持する。穴の内部は描画可能だが、岸からの離隔と境界の除外は維持する。

PropPlacementManagerは同じPropGeometryとPropManagerの障害物キャッシュで散布プレビューを作り、半透明のインスタンシングで表示する。散布の位置・回転・スケールは確定後と一致する。プレビューは無印モデルを使い、障害物取得済みのロード範囲と候補点予算内に限る。範囲外まで全景プレビューする機能はない。個別配置の編集用ゴーストにはGameObjectを使い、障害物キャッシュの取得状態や重なりで非表示にしない。保存後は共通の永続レンダラが担当し、explicitInstanceの候補は障害物判定を通さず表示する。

個別配置のパネルは「地面からの高さ(m)」を小数・負値で入力できる。値は`world:change_state`のparams.heightと`edit_prop:change_settings`のheightでUnityへ渡る。高さ変更は次に置くゴーストへ即時反映し、すでに打点した仮配置は動かさない。地形クリックのXZには道路・ノード・グリッドへの共通吸着を適用しない。建物や道路の入力は貫通させる。

個別配置では3D側でも回転角と高さを操作できる。マウス中ボタンのドラッグで回転(横移動0.5度/px、1度単位に量子化。ドラッグ中はゴーストの位置を固定し、左クリックの打点も受け付けない)、PageUp/PageDownで高さを0.1m刻み(Shift併用で1m)に増減する。どちらも次に置くゴーストの設定を変えるだけで、打点済みの仮配置は動かさない。変更後の値は`edit_prop:placement_settings`(`{ rotation, height }`。回転は0〜360度に正規化)でパネルへ書き戻し、パネルはステッパー表示を追従させるだけで`edit_prop:change_settings`へエコーしない。中ボタン回転は回転終了時に1回、高さ変更はキー入力のたびに送る。建物の直接配置と同じ操作系で、入力判定の共通実装(中ボタン回転・キー長押しリピート・カメラ操作/UI操作中のブロック)を共有する。

Unityからの`edit_prop:update_instances`とPOST/GETの各個別配置は`x, y, z, rotation, scale`を持つ。yは地面からの相対高さで、バックエンドのheightへ保存する。省略値は0。XZは描画原点のオフセットを除いて送信する。高さは全種別で共通の扱いとし、配置可否のための形状・接続判定はしない。

橋下の散布除外の高さ判定、UltraFarの森林表現、外構・街路樹の自動生成は対象外。配置モデルの種別はマスターのprop_masterに登録する。既存プロップの削除は§M.7.3のブルドーザで行い、配置パネルからは削除しない。

### M.7.3. ブルドーザによる削除

保存済みプロップの撤去は、コックピットのブルドーザ(`STATE_REMOVE_OBJECTS`)で対象をクリックして行う。プロップは個体ごとのGameObject・Colliderを持たないため、物理レイキャストの代わりに常駐候補点ごとのワールドAABB(モデルのbounds×回転×スケール)と画面レイの交差で判定し、同じレイで当たった建物・区画・地形より手前にある最も近い1本を選ぶ。非表示の候補(障害物に除外された散布点)は対象にしない。ホバー中の対象は赤い枠で示し、範囲配置なら散布範囲の外周も地表に沿って赤く描く。

| 対象 | 操作 | 動作 |
|---|---|---|
| PropInstance(個別配置) | 左クリック | その1個を即時に`DELETE /api/v1/props/instances/{id}` |
| PropScatter(範囲配置) | 左クリック | `remove_object:request_confirm`(`{ object_type: "prop_scatter", id, prop_type }`)でUIへ確認を求め、コックピットの確認ダイアログの回答`remove_object:confirm_result`(`{ object_type, id, accepted }`)が承諾のときだけ`DELETE /api/v1/props/scatters/{id}`。散布範囲ごとすべての木が消える |

範囲配置は確認待ちの間、別の範囲配置クリックを受け付けない(取消の回答でも待ちは解除する)。削除に成功した候補は即座に非表示にし、他の削除と同じ差分リロードで常駐データを更新する。同じ対象へ重複してDELETEを出さない。範囲配置の一部の木だけを消すことはできず、密度・範囲の変更はPATCHで行う。

### M.7.1. 駅階段の手動配置

駅の昇降設備は自動生成せず、プレイヤーがプロップを配置して表現する。駅への所属・経路探索・乗降処理には影響しない。通路やホームの開口、壁や上屋の自動除去も行わない。

| 種別 | 造形 | 原寸 |
|---|---|---|
| 101 | 側壁・屋根付きの駅階段（標準幅） | 幅2.4m、長さ7.2m、床の高低差4m、屋根天端6.52m |
| 102 | 側壁・屋根付きの駅階段（広幅） | 幅4m、他は101と同じ |
| 103 | 屋根なしの下り階段入口（標準幅） | 幅2.4m、長さ4m、柵天端1.13m |
| 104 | 屋根なしの下り階段入口（広幅） | 幅4m、他は103と同じ |

階段本体は20段と上端の1.2m踊り場、内側の手すり、不透明な側壁と屋根を持つ。橋上駅舎から下る階段と高架ホームへ上る階段に共用し、下端を置きたい高さで配置する。駅舎側へ少し重ねて接続部分を側壁・屋根で覆う。スケール変更は幅・長さ・高低差を一様に変える。

入口には屋根も階段室の側壁も付けず、三方の柵・低い縁と黒い内部を持たせる。黒い底面は原点から4cm上でホームの連続床を覆い、手前の浅い3段が奥へ下りる印象を作る。原点は入口を置くホーム面に合わせる。

著作元は`genesis-gallery/library/props.blend`、再生成ジョブは`pipeline/jobs/build_prop_station_stairs.py`。道路のPATH_CONCRETE・PATH_METALと駅舎のBD_WHITE_WALLを共有し、黒い内部のみPROP_STAIR_VOIDを使う。新しい外部素材は使わない。

### M.7.2. 乗り物モデルの手動配置

工事車両と環境演出の航空機・船舶は固定名のFBX(`construction_*` / `ambient_*`)で描画されるが、飾りとして自由に置けるよう数値IDの別名でも `prop_master` に登録している。`genesis-gallery/pipeline/jobs/build_prop_aliases.py` が `props.blend` 内でメッシュデータを共有した数値IDコレクションを作り、`Props/{ID}.fbx` として書き出す。元モデルを再著作したら別名も再生成する。

| ID | モデル | 原点 |
|---|---|---|
| 201〜204 | 工事車両(アスファルトフィニッシャー・ロードローラー・油圧ショベル・移動式クレーン) | 接地面 |
| 301〜303 | 旅客機・プロペラ機・ヘリコプター | 接地面(駐機状態) |
| 304〜307 | コンテナ船・石油タンカー・クルーズ客船・漁船 | 喫水線(船体は原点より下) |

配置の高さは他の種別と同じく地形の標高が基準になる。海上に置くと標高は海底なので、船は「地面からの高さ」に海底の深さぶんの正の値を入れて喫水線を海面(標高0)へ合わせる。飛行機は駐機状態の原点なので、空中に置きたい場合も同じ入力で高さを与える。散布(scatter)にも使えるが、離隔はbbox由来なので大型船は互いに大きく離れる。バリデータはID 201〜399を乗り物として扱い、地形プロップの接地検査と頂点予算を適用しない。

### M.7.4. 屋根付き歩道橋（111・112）

111は4車線道路231（幅24m）、112は6車線道路241（幅32m）に合わせた自由配置プロップ。
屋根と手すりを持ち、側壁は持たない。左右の幅3m歩道内に幅2.4mの階段を道路と平行に置き、
階段の屋根幅2.8mも歩道内へ収める。両階段は同じ方向に下り、上から見てコの字になる。
中央の車道には柱を置かない。全幅23.8m/31.8m、道路方向の全長12.845m、
床高6m、桁下5.55m、屋根天端8.97m。階段は15段ずつの二連階段と中間踊り場からなる。

原点は水平bbox中心の接地面。UnityのローカルX軸を道路横断方向に合わせ、スケール1で置く。
階段下端はローカル-Z側、横断通路の中心は原点から+Z側へ5.0225m偏る。
道路との自動接続、通行経路、歩行者の昇降、街路樹や街灯の除去は行わない純装飾である。
専用Farは階段を傾斜床へ替えて屋根・開放側面・橋脚の輪郭を維持する。
個別配置する構造物として、森林向け600頂点目安の警告を許容する。
著作元は`props.blend`、ジョブは`pipeline/jobs/build_prop_footbridges.py`。
既存材質を共有する自作モデルで、外部素材は使用しない。
