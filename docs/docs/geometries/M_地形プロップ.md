# M. 地形プロップ（装飾オブジェクト）

## M.1. 役割と保存データ

地形プロップは森・茂み・岩などの純粋な装飾で、経済シミュレーション、配置コスト、維持費、天然資源とは接続しない。マップ全域のどこにでも配置できる。

| 型 | 保存する内容 | 用途 |
|---|---|---|
| PropScatter | prop_type、region、density（本/ha）、seed、edge_fade_width（m）、allow_water、version | 森などの範囲散布 |
| PropInstance | prop_type、XZ座標、height（地面からの相対高さm）、rotation、scale、version | 明示的な個別配置 |

regionはGeoJSON MultiPolygonのcoordinates形式で、外周・穴・複数パートを保持できる。散布した木ごとの座標は保存しない。地形標高はUnityが表示中の地形から取得し、個別配置では保存したheightを加える。モデルはResources/Models/Props/{prop_type}からModelManager経由で取得する。

## M.2. 非破壊の重なり除外

**重なり除外はPropScatter（範囲配置）だけに適用する。** PropInstance（個別配置）はすべての種別で任意のXZと地面からの高さを指定でき、建物・土地区画・道路・水域・他プロップとの重なりを許可する。高さの正負や種別による浮遊制限は設けない。カーソルプレビュー・仮配置・保存後の描画で同じ扱いにする。地形更新時も相対高さを保ち、常駐セル、候補予算、描画LODは適用する。

**区画・パス・建物の作成や形状変更ではregionも個別配置レコードも変更・削除しない。** 散布範囲の編集・プロップの撤去はユーザーの明示操作と§M.2.1の取り壊しでのみ行う。描画側が現在の障害物と重なる範囲配置の候補点を非表示にする。障害物を撤去すると同じ位置・回転・スケールの個体が再表示される。これは装飾の表示復元であり、樹木の成長シミュレーションではない。

| 対象 | 除外条件 |
|---|---|
| 土地区画 | 建物の有無・建設状態・地面パネルの有無を問わず区画全体 |
| 海・湖などの水域 | allow_water=falseの場合、保存済み海岸線の陸地外側と湖の穴を除外。島の陸地は残す |
| 道路・線路などの物理パス | 保存された占有ポリゴン |
| 完全地下のパス | 除外しない |
| 公共交通の論理パス | 除外しない |
| 高架・橋、部分的な地下パス | 初版は占有ポリゴン全体を除外する。高さに応じた部分除外は対象外 |

未建築の区画も開発用地として除外する。建物の有無を検索せず、区画とパスの空間索引だけで判定を完結させるためである。建物の解体後も区画が残る間は除外し、区画を撤去すると同じ候補点が再表示される。計画確定済みのパスも障害物になる。マッシュアップ施設の棟間や敷地内の庭も除外し、敷地外へはみ出した建物の底面は別途判定しない。

境界上も除外し、幹だけが境界の外にあって樹冠が壁に接する状態を抑えるため、モデルの水平半径×0.15×配置スケールを離隔に用いる。離隔上限は8m。バックエンドも取得BBOXを8m拡張し、隣接範囲の障害物を含める。

水域は地形セルサイズの固定格子ごとに陸地ポリゴンを差し引いて返す。カメラ移動で取得BBOXが変わっても、共通セルの形状と署名は変えない。海岸線が未設定なら水域判定を保留し、設定済みで空の陸地なら全域を水域として扱う。水域は取得のたびにその時点の海岸線から作る。海岸線は新規都市の作成時に初期near_mapから抽出され、以後は埋立の完了でだけ広がる（[D_地形形状](D_地形形状.md) §D.17.4）ので、埋め立てた範囲は次の取得から水域でなくなる（そのセルの水域の署名が変わり、除外が作り直される）。道路の盛土・切土や陸地の整地では海岸線が変わらないので、それによる岸の変化には追従しない。

除外は小区画の生成・障害物変更時にCPUで判定して保持する。毎フレームの木×建物総当たり、全市の障害物のポリゴン結合、散布regionからのdifferenceは行わない。建物のGameObjectやColliderの存在には依存しない。

### M.2.1. 取り壊しに伴う個別配置の削除

建物・パスが取り壊し中（STATUS_DEMOLISHING）へ変わった時点で、その範囲にある個別配置（PropInstance）をバックエンドが削除する。屋上に置いた車両、駅ホームの階段、道路の案内看板のように構造物と一体で置かれた装飾が、構造物の消滅後に宙に浮いたまま残るのを防ぐ。

| 項目 | 扱い |
|---|---|
| 判定範囲 | 建物は底面ポリゴン、パスは占有ポリゴン。境界上の配置も範囲内とする |
| 判定に使う値 | 配置点のXZのみ。高さ（地面からの相対値）・回転・スケール・モデルの水平半径は見ない |
| 対象外 | 完全地下のパス（地表の装飾と無関係なため、§M.2の除外と同じ扱い）。公共交通の論理パスは取り壊しの概念を持たない |
| PropScatter | 削除しない。障害物が消えれば同じ候補点が再表示されるため、永続データを変える必要がない |

削除は取り壊しの**開始**時点であり、解体工事の完了より前である。パスの取り壊しを取りやめても削除済みの個別配置は戻らない。削除は保存データの変更なので、Unityは次のプロップ取得（§M.6の差分更新）で表示から消す。ユーザーが明示的に撤去する操作は§M.7.3のブルドーザで行う。

## M.3. 安定した散布

PropGeometryが永続描画と散布プレビューの共通実装である。密度から候補格子の間隔を求め、ワールド原点に固定した格子番号とseedをハッシュして、各格子内の位置・回転・スケールを生成する。格子間隔は平方根（10000÷density）、下限0.5m。スケールは0.8〜1.2倍である。

候補点は小区画の半開区間に一意に所属する。region内かつ穴の外の点のみ採用し、重なる複数パートでも同じ点を二重生成しない。全範囲の乱数列を先頭から消費する必要がなく、必要な小区画だけ直接生成できる。

同じ密度・seedなら、カメラ移動、ロード順序、描画用分割数、障害物の追加・撤去、散布範囲の編集によって共通部分の候補点は変わらない。密度またはseedの編集では配置が変わる。シーン原点の移動量は描画行列に適用し、保存座標とハッシュには混ぜない。

### M.3.1. 範囲ごとの境界ぼかしと水域設置

境界のぼかし幅（`edge_fade_width`、m）と水域への設置の許可（`allow_water`）は、種別のマスター設定ではなく、範囲散布ごとの設定である。`POST /api/v1/props/scatters` の任意項目で、省略すると0と不許可になる。配置パネルには入力欄が無く、省略して送る。個別配置は水域にも置ける。

`edge_fade_width`は0で無効、正値で有効。範囲の内側で外周・穴の境界までの最短距離を求め、指定幅に達するまで密度をsmoothstepで0から指定密度へ増やす。範囲の外や穴の中には置かない。細い範囲では中央でも指定密度に達しない場合がある。透明度やモデルのサイズを変えず、世界格子とseed由来の固定順位で候補を間引くため、幅だけを変えても残る個体は移動しない。複数パートは各パートの判定のいずれかを通れば採用し、候補を二重生成しない。

`allow_water`は既定false。trueでは水域の除外だけを省略し、海・湖の底の地形へ接地させる。水面に浮かせたり、水深を制限したりする設定ではない。道路・線路・土地区画の除外は引き続き適用する。

両設定は作業コピー、Undo/Redo、シナリオの地形API、シナリオ・通常のセーブ・ロード、プロップAPIに保持される。CPU散布・GPU森林・ブルドーザの選択判定で同じ配置条件を使う。全景の森林被覆にも距離に応じた密度と水域許可を反映する。2Dキャンバスの範囲表示は配置範囲の輪郭であり、一本ごとの間引き結果は3Dプレビューで確認する。

## M.4. 既存LODとの統合

[E_LOD処理](E_LOD処理.md)に従い、共通の最大81常駐セル内を描画する。常駐範囲外のUltraFar森林は扱わない。セルサイズの正はTerrainManager.CellSizeで、既定では一辺を8分割する（500mセルなら62.5m）。小区画は生成・除外・描画の単位であり、地形APIの513格子や保存単位は変えない。

### M.4.1. 範囲配置の森林

種類1（針葉樹）・2（広葉樹）の範囲配置は、既定でForestRendererとForestPlacement.computeを使う。CPUには散布範囲・障害物・小区画を保持し、木ごとの候補配列・高さ取得・描画行列を作らない。GPU上でPropGeometryと同じ世界格子・整数ハッシュから位置、回転、倍率を作る。近景も同じGPU配置を参照するため、遠景から近景へ入る際に位置が移動しない。

範囲の穴・複数パートと、区画・道路・水域の穴・離隔はGPUのポリゴン判定で処理する。低解像度のマスクに丸めない。接地は所属する常駐TerrainのheightmapTextureを直接参照する（Unityの格納値を2倍してsize.yとタイル基準標高を適用）。1536mの地形追従窓には依存しない。タイルが未完成なら生成せず、完成通知・地形編集で対象小区画を再生成する。

| 距離（木の根元からカメラまでの実距離） | 表現 |
|---|---|
| 約100m以内 | 既存の通常モデル（幹と葉） |
| 90〜110m | seed由来の固定値で各木の切替距離を分散する移行帯 |
| 約100〜1,500m | 幹なしの専用Far樹冠。木の粒と山の稜線を立体で残す |
| 1,500m以上・常駐範囲外 | 非表示 |

通常とFarは同じ位置・回転・倍率を使い、同じ個体を二重に描かない。近景の影は既存の1フレーム4096サブメッシュインスタンス予算内に制限し、遠景は影を送信しない。Forest.shaderは既存モデルの葉画像・基色・Smoothness・Metallicを引き継ぎ、URP Litと同じUniversalFragmentPBRで照明を計算する。Forward+の_CLUSTER_LIGHT_LOOP、追加光源、SSAO、影、雲影Cookie、環境反射に対応する。配置用の頂点変換は独自だが、照明を簡略な拡散反射へ置き換えない。近景は通常モデルを使い、接写用_closeと6三角形の最小樹冠はこの経路では使わない。

GPU格子候補は全体で最大2,000,000個（32バイト/個、位置等のバッファは最大約64MB）。予算を小区画×散布レコードへ均等に配分し、超過時だけ元の格子番号を均等抽出する。通常密度で予算内なら分割数・取得順によらず同じ配置となる。予算超過時には取得範囲や分割数によって抽出集合が変わり得るが、残った格子の位置・回転・倍率は変えない。CPU側の250,000候補予算とは別である。

データ・障害物の署名が変わらない再取得ではGPUバッファを再利用し、カメラ移動では再散布・行列再構築をしない。署名には候補予算そのものではなく、予算から決まる小区画ごとの実効本数(`ForestRenderer.PatchCount`)を入れる。常駐小区画数の変化で予算が変わっても、実効本数が変わった小区画だけを再生成する。GPUでの生成(`Generate`)は1フレームあたり262,144点までに抑え、超えた分は次のフレームへ持ち越す。生成済み森林の詳細マスクは、森林パッチの状態(追加・削除・生成・非表示)が変わったフレームだけ作り直す。小区画のBoundsで描画を絞り、Graphics.RenderMeshPrimitivesで共有モデルを描く。地形・障害物変更時には該当区画をGPUで再計算する。撤去・アンロード・都市切替ではバッファを解放する。F8の「森林GPU」は格子候補数と描画バッチ数で、除外後の実本数ではない。

GPUのコンピュート・インスタンシング・専用シェーダーが使えない環境、またはuseGpuForestsが無効の場合は従来のCPU候補経路を使う。個別配置と森林以外の範囲配置も従来経路を使う。

### M.4.2. 個別配置・森林以外・非対応環境

候補はCPUで生成し、投影サイズとヒステリシスでClose / Normal / Farを選ぶ。正投影にも対応する。通常種別はカメラからの実距離1,500m以上でHidden、1,350m未満で復帰する。Hiddenの候補も復元用に保持し、投影サイズによる本数の間引きは行わない。近景専用種別は次節の規則を使う。

常駐候補の予算maxResidentCandidates（既定250,000）を有効小区画へ配分する。各点のXZ・seedによる固定順位で選び、個別配置を優先する。生成・高さ調整・バッチ構築は共通フレーム予算で分散し、更新中は旧バッチを保持する。瞬間的には旧・新配列が併存する。

常駐小区画数の変化で1区画あたりの予算が変わっても、配置の署名は変わらない(予算を署名に含めない)。予算が減ったら既存の点列の先頭を切り詰める。固定順位の昇順に並んでいるので、結果は作り直した場合と同じになる。増えたときは1.25倍以上になったときだけ作り直し、それ未満では本数を据え置く。

描画バッチは、カメラが max(4m, 小区画までの距離×2%) 以上動いたときだけ再評価する(1,000m先の小区画なら20m)。点ごとのLOD・遠景・Hiddenが変わらず、点と原点も変わっていなければ既存のバッチを使い回し、影の対象(150m以内)だけを更新する。描画ワーカーは、カメラの位置・投影と原点が前回の周回と同じで未処理の仕事も無ければ周回を省く。

### M.4.3. 近景専用の草（種別4）

種類ごとの描画方針はUnityの`PropRenderPolicy`が持つ。草（4）はカメラからモデル中心までの実距離100mで非表示、90m未満で再表示する。正投影でも距離を使う。小さいモデルの投影サイズではCloseへ入りにくいため、表示中はCloseモデル（無ければ通常モデル）を使い、Normal/Farへの切り替えは行わない。草自身の影は送信しないが、周囲の影は受ける。遠景地形の森林被覆には含めない。

マップ全域を覆う範囲散布を設定しても、全域の草の座標は生成・保存しない。常駐セル内の範囲定義を保持し、カメラから水平距離125m以内にある小区画だけCPU候補を生成する。離れた小区画は草の候補と描画行列を解放し、再接近時に同じ世界格子・seedで復元する。表示距離より広く先行生成することで、小区画境界での生成待ちを減らす。カメラが静止している間は再生成しない。上空では同じ水平範囲を保持するが、実距離100m以上の草は描画しない。

近景散布の常駐候補予算は通常の250,000候補と別に65,536候補。125mの円と交差し得る小区画数の上界から区画ごとの固定割当てを計算し、超過時は座標・seedによる固定順位で間引く。密度が高すぎる場合は指定密度を下回る。移動・更新中には旧配列と新配列が一時的に併存する。生成・高さ取得・バッチ構築は共通フレーム予算で分散し、道路・区画・水域の除外、境界ぼかし、地形追従は通常の散布規則を使う。個別配置の草は通常の常駐候補予算で保持し、同じ100m/90mの描画制限を適用する。

種別4の散布密度は草株の数/haで、葉の枚数ではない。既存のシナリオや都市へは自動配置されない。

モデルは `Props/4.fbx`、原本は `blender/props.blend` のコレクション `4`。通常モデルで描き、専用Farは持たない。

## M.5. GPU描画とモデル

本節の個体LOD・511個単位の描画はCPU候補経路の仕様である。範囲配置の森林は§M.4.1の描画経路を使い、同じPropRenderModelから通常・Farの共有部品を取得する。

PropRenderModelはプレハブ内のMeshFilter・MeshRenderer・子のローカル変換・サブメッシュ・マテリアルを取り出し、複製したマテリアルのinstancingを有効にする。永続表示では一本ごとのGameObjectやColliderを作らない。

| DrawLod | モデル |
|---|---|
| Close | {prop_type}_closeがあれば使用。なければ無印 |
| Normal | 無印の{prop_type} |
| Far | {prop_type}_farがあれば使用。なければ複雑なサブメッシュの頂点を空間集約して簡略化 |
| Far内の最小モデル | 木の樹冠を6三角形の四角錐にする。本数は維持 |
| Hidden | 描画しない。カメラからの実距離が§M.4の閾値以上の個体。モデルは不要 |

自動Farは4×8×4の格子で頂点とUVを集約し、縮退・重複三角形を除去する。元のマテリアルを引き継ぐ。128三角形以下の部品、読み取り不可のメッシュ、簡略化しても削減できない部品は元の形状を使う。専用アセットほど輪郭が忠実ではないため、目立つ種類には同じ原点・水平範囲・天端の_farを用意できる。幹を省く場合は底面だけを上げてよい。生成メッシュと複製マテリアルはPropRenderModelが所有し、全消去時に破棄する。共有FBXのメッシュ・マテリアルは変更しない。

GraphicsSettingsのInstancing VariantsはKeep Allに設定する。実行時に複製してinstancingを有効化するため、ビルド時のStrip Unusedでは必要なバリアントが除去され得る。保持によりシェーダービルド量は増える（[Unity Graphics Settings](https://docs.unity3d.com/jp/current/Manual/class-GraphicsSettings.html)）。プレビューも複製マテリアルでURPの透過ブレンドと深度書き込みOFFを明示する。

描画は小区画・種類・LOD・部品ごとにまとめ、Graphics.RenderMeshInstancedで一回最大511インスタンスを送る。バッチのBoundsにはモデルの実寸・回転・スケール・子の変換を含める。影はClose/Normalのカメラから150m未満に制限し、Farは影を落とさない。モデル・プレビューマテリアルのシェーダーはGPUインスタンシング対応が必要。

### M.5.1. モデル制作規約

1種別=1FBXで、`Assets/Models/Props/{prop_type}.fbx` に置く（閾値フォルダ・パーツ分割はない）。`{prop_type}_close.fbx` と `{prop_type}_far.fbx` は任意で、無印と同じ原点・水平bbox・天端で著作する。Farは幹を省いて底面を上げてよい。Closeは底面も無印と一致させる。ソースはBlenderライブラリ `blender/props.blend`（コレクション名=種別ID）で、FBXは書き出し先である。

| 項目 | 規約 |
|---|---|
| 原点 | 配置基準面。高さ0で地表に置いたときの底面はY=0以下にする。幹を省くFarは樹冠の底面を上げてよい。XZはbboxの中心を原点に合わせる |
| 寸法・向き | 実寸（m）。個別配置は指定のY軸回転・一様スケール。散布は乱数の回転・0.8〜1.2倍スケール。階段本体はUnityの+Z側が下端、-Z側が上端 |
| 離隔 | 散布のみbboxのX/Z半幅の大きい方×0.15×スケール（上限8m）を使う。個別配置には適用しない |
| ノード変換 | ルートノードの位置・回転は打ち消される。子ノードのローカル変換は保持される |
| 遠景 | `_far`が無ければ、サブメッシュのうち128三角形を超えるものだけ4×8×4格子で頂点集約する。軽いモデルはそのまま使う |
| 頂点数 | 常駐候補は最大250,000本をインスタンシングするため、無印は数百頂点以内を目安にする |
| マテリアル | 名前で共有する。既存の`PROP_*`(建物・パスの材質も流用できる)を使い、新規の材質は分野共通の`MAT_*`にする([マテリアル名](P_マテリアル共有とエクスポート.md#マテリアル名))。GPUインスタンシング対応シェーダーが必要 |
| 種別登録 | `prop_master`に種別IDと表示名を登録する。モデルが無い種別は配置できるが描画されない |

非対称な形状は、標準FBX書き出しでBlender(x,y,z)がUnity(-x,z,-y)に写ることに注意する。

同じ `Props/` には散布用ではない固定名のモデルも置く。工事車両 `construction_*`([道路メッシュの生成](G_道路メッシュの生成.md) §15)、環境演出の航空機・船舶 `ambient_*`([環境演出の乗り物](V_環境演出の乗り物.md))、歩行者 `pedestrian_*`([歩行者の描画](W_歩行者の描画.md))で、固定名のままでは `prop_master` に登録せず、手動配置用には §M.7.2 の数値ID別名を使う(歩行者は別名を持たない)。`ambient_*` と数値ID 201〜399 は接地検査の対象外である。歩行者は接地・水平中心を地形プロップと同じ規約で検査し、頂点予算だけ専用(Normal 700)である。

交差点の信号機 `traffic_signal_{様式}_{pole|arm|head}`([道路メッシュの生成](G_道路メッシュの生成.md) §11.8)も固定名のモデルで、`prop_master` には登録しない。交差点ごとに3部品を1メッシュへ結合して置くため、原点は3部品とも柱の接地面の高さで、アームと灯器は取付高さをモデルが持つ(接地検査は柱だけに適用し、アームの単位長と灯器の下端4.5m以上を検査する)。自作の形状と単色の材質だけで作り、画像素材を持たない。

### M.5.2. 森林用の木モデル

種別1は高さ12m・樹冠幅4mの針葉樹、種別2は高さ9m・樹冠幅6mの広葉樹。通常とFarは原点・水平範囲・天端を揃え、Farでは幹を省いて樹冠の底面を上げてよい。低密度の散布では空隙が残る。

通常・Farは同じ葉の色画像と材質を共有する。透明カードを使わず、立体形状で樹冠を表す。極小投影時はFarの樹冠bboxから四角錐を作り、本数を減らさず簡略化する。品質と非表示距離の判定は§M.4を参照する。

## M.6. 差分更新と負荷制限

マージBBOXで配置情報と障害物を一括取得する。ただし散布プレビューが要求されていない間は、先に `limit=1` のプローブで常駐範囲にプロップがあるかを確かめ、無ければ障害物(全区画・道路のポリゴン)を取得しない。森林GPUは同じ署名で変更小区画の配置・除外を再計算する。CPU候補点はプロップID/versionの組み合わせで、表示可否は障害物ID/形状signatureの組み合わせで差分更新する。道路の変更では関係する小区画の表示可否だけを更新し、候補点を再散布しない。削除や移動では旧位置側の小区画も応答との比較で更新される。

CPU候補経路の生成・高さ調整・描画バッチ構築はPerformanceConfig.FrameBudgetMsでフレーム分散する。森林のGPUバッファ準備も共通スケジューラで分散する。LoadBatchと独自の世代番号で旧処理のコミットを防ぐ。同じ小区画のLOD再構築中は前の完成済みバッチを維持し、新しい完成結果へ置き換える。候補・除外データの更新で小区画を置き換える場合は、新バッチ完成まで一時的に非表示になる。

CPU候補経路では一散布レコード5,000個という上限は設けない。常駐候補点の予算maxResidentCandidates（既定250,000）を有効小区画へ配分し、各点の固定順位で選ぶ。非表示候補も復元用に数える。予算超過で小区画全体を捨てない。更新作業中は旧配列と新配列が一時的に併存するため、瞬間的なメモリ使用量は常駐分を上回る。

CPU候補の高さは `Utils.GetGroundHeight` で現在のTerrainを参照し、個別配置では候補に保持したheightOffsetを加える。初回・再読み込み・地形編集・タイル完成通知のすべてで同じ式を使う。高さにモデルのスケールを掛けない。タイル完成通知では、小区画に記録した地形の版と世代が現在と同じなら(常駐外タイルのLRUから復元されただけなら)、高さの再サンプルも森林の再生成もしない。版が不明なら常に更新する。

## M.7. APIと配置プレビュー

| メソッド | パス | 内容 |
|---|---|---|
| GET | /api/v1/props?bbox=x1,z1,x2,z2 | scattersとinstancesを取得。既定上限は各10,000レコード |
| GET | /api/v1/props?bbox=…&include_obstacles=true | obstaclesを同梱する完全な描画用スナップショット。件数を途中で切らない。常駐範囲にプロップがあるときと、散布プレビューの要求中だけ使う |
| GET | /api/v1/props?bbox=…&limit=1 | 常駐範囲にプロップがあるかのプローブ。scatters・instances が0件なら障害物を取得しない |
| POST | /api/v1/props/scatters | polygon、prop_type、density、任意seedで作成 |
| PATCH | /api/v1/props/scatters/{id} | polygon、density、seedを編集 |
| DELETE | /api/v1/props/scatters/{id} | 散布範囲を撤去 |
| POST | /api/v1/props/instances | instances配列を一括作成 |
| DELETE | /api/v1/props/instances/{id} | 個別配置を撤去 |

obstaclesの各項目はkey、signature、ワールド座標のpolygon、floor_variant、visual_variantを持つ。区画は`parcel:{id}`、パスは`path:{id}`をkeyとし、floor_variantとvisual_variantは0で返す。床材に関係なく区画全体を除外する。水域は`water:{x}:{z}:{index}`をkeyとし、`holes`に水域内部の島のリングを保持する。穴の内部は描画可能だが、岸からの離隔と境界の除外は維持する。

PropPlacementManagerは同じPropGeometryとPropManagerの障害物キャッシュで散布プレビューを作り、半透明のインスタンシングで表示する。散布の位置・回転・スケールは確定後と一致する。プレビューは無印モデルを使い、障害物取得済みのロード範囲と候補点予算内に限る。プロップの無い範囲では障害物を取得していないので、散布プレビューを初めて出すときは常駐範囲全体の障害物の取得が終わるまで空になる。プレビューの要求は、散布モードの間に毎フレーム読まれる版と `PreviewRects` の呼び出しで2秒ずつ延長され、途切れると、以後のロードではプロップの無い範囲の障害物を取得しなくなる。範囲外まで全景プレビューする機能はない。個別配置の編集用ゴーストにはGameObjectを使い、障害物キャッシュの取得状態や重なりで非表示にしない。保存後は共通の永続レンダラが担当し、explicitInstanceの候補は障害物判定を通さず表示する。

個別配置の回転・高さとUIへの同期は[Unity入力制御](../programs/Unity入力制御.md#プロップの自由配置)に定義する。

Unityからの`edit_prop:update_instances`とPOST/GETの各個別配置は`x, y, z, rotation, scale`を持つ。yは地面からの相対高さで、バックエンドのheightへ保存する。省略値は0。XZは描画原点のオフセットを除いて送信する。高さは全種別で共通の扱いとし、配置可否のための形状・接続判定はしない。

橋下の散布除外の高さ判定、UltraFarの森林表現、外構・街路樹の自動生成は対象外。配置モデルの種別はマスターのprop_masterに登録する。既存プロップの削除は§M.7.3のブルドーザで行い、配置パネルからは削除しない（取り壊しに伴う自動削除は§M.2.1）。

### M.7.3. ブルドーザによる削除

個別配置は1個、範囲配置は散布レコード全体を削除する。非表示の候補は選択対象外で、範囲の一部の木だけは削除できない。入力・確認の契約は[Unity入力制御](../programs/Unity入力制御.md#プロップの削除ブルドーザ)に定義する。

### M.7.1. 駅階段の手動配置

101・102は標準幅・広幅の屋根付き階段、103・104は下り入口である。階段はUnity +Z側が下端、-Z側が上端、入口はホーム面を原点にする。

自由配置の装飾であり、駅への所属・経路探索・乗降には影響しない。通路やホームの開口、壁・上屋の除去も自動では行わない。

### M.7.2. 乗り物モデルの手動配置

工事車両201〜204、航空機301〜303、船304〜307は `construction_*`・`ambient_*` の数値ID別名である。モノレール308・309は[走行用アセット](O_車両の走行描画.md#o101-車両アセット)と同じ先頭・中間車を使う。接写・遠景を持つ元モデルは別名も同じLODを持つ。

車両・航空機は接地面、船は喫水線を原点にする。配置高は地形が基準なので、海上では海底から海面までの高さを加える。数値ID201〜399は通常のプロップ接地検査・森林向け頂点予算の対象外である。

### M.7.4. 屋根付き歩道橋（111・112）

111は幅24mの4車線道路、112は幅32mの6車線道路に対応する自由配置の装飾で、道路との接続・通行経路・昇降には影響しない。

原点は水平bbox中心の接地面、ローカルXは道路横断方向、階段下端は-Z側である。スケール1で置き、横断通路は原点より+Z側にある。専用Farは階段を傾斜床へ簡略化し、同じ原点と輪郭を保つ。

### M.7.7. 片持ち道路案内看板（121〜126）

121〜126は青・緑・電光の案内看板で、幅24m・32mの道路に対応する寸法を持つ。原点は水平bbox中心の接地面、表示面はUnity +Z、柱は+X側にある。

看板の文字・矢印は共有画像をUVで貼る固定装飾で、道路の接続や渋滞とは連動しない。配置により街路樹・街灯を自動撤去する処理はない。

### M.7.8. 配置パネルのカテゴリとサムネイル

パネルの分類・選択・仮配置の扱いは[Unity入力制御](../programs/Unity入力制御.md#プロップパネル)に定義する。

`tauri/tools/render_prop_thumbnails.py` は `Assets/Models/Props/{数値ID}.fbx` から `tauri/src/assets/images/props/{ID}.png` を生成する。固定名・接写・遠景モデルは対象外。画像はUIへ同梱し、生成オプションはスクリプトに定義する。

## 地形エディタとプロップ

地形エディタ（`TerrainEditorCanvas`）はプロップを編集も表示もしない。プロップは、神モードのセッション（シナリオ管理の「都市を編集」）の配置パネルで配置する（M.7）。

作業コピーの `meta.json` は、シナリオの地形API（`GET /api/v1/scenarios/{id}/terrain`。[D_地形形状](D_地形形状.md) §D.14.3）から受け取った配置を `props` の `instances`・`scatters` の配列として持つ。個別配置の各要素は `id/prop_type/x/y/z/rotation/scale`、範囲散布は `id/prop_type/polygon/density/seed/edge_fade_width/allow_water` を持つ。polygonはXZ座標の頂点列で、`id` はシナリオの中のIDの文字列である。「シナリオに保存」ではこのプロップ全体を読み込んだまま送り返し、コアは全置換する（送ったIDは保存せず、新しいIDを振る）。複数パートや穴を持つ散布範囲はAPIが最大パートの外周だけを返すので、地形エディタで保存するとその形に置き換わる。

取り込む標高ファイルはプロップを持たない。シナリオから都市を始めると、シナリオのプロップがそのまま初期配置になり、その後は都市のセーブデータが正となる。

### M.7.9. コンテナと街路設備の単品モデル

コンテナ401〜419と街路設備451〜490は個別配置用の独立モデルで、道路・港・建物の自動配置には影響しない。原点・実寸・LODは§M.5.1の規約に従い、種別と表示名はマスター、カテゴリはUIの分類表を参照する。

### M.7.6. 走行車両の自由配置

走行用モデルは道路車両350〜367・鉄道370〜395としても自由配置できる。原点は接地面の水平中心、前方はUnity +Zで、編成末尾には先頭車を180度回して使う。走行・経路探索・輸送力・経済には接続しない。

形状の正本は `blender/vehicles.blend`。配置用の数値ID別名は走行モデルと同じ形状・接写・遠景を持ち、乗り物の制作規約で管理する。車種と走行モデルの構成は[車両アセット](O_車両の走行描画.md#o101-車両アセット)に定義する。

## M.8. バス停の自動配置モデル

`Props/bus_stop.fbx` は停留所ノードから自動配置する固定名モデルで、手動配置マスターには登録しない。`BusStopManager` が共有モデルをGPUインスタンシングで描き、個体ごとのGameObject・Colliderや保存データを作らない。

原点は接地面の水平中心、Unity +Zはベンチ正面、Xは道路の長手方向である。傾斜地に沿わせる支柱を地中まで伸ばす。ガラスは描画側の複製材質だけを透過に設定し、共有材質を変更しない。
