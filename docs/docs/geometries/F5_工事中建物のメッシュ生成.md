# 工事中建物のメッシュ生成（STATUS_CONSTRUCTING）

## 概要

status が `STATUS_CONSTRUCTING` の建物は、`model_type` に関わらず完成品のメッシュを生成せず、専用の「工事現場」メッシュ（土マウンド + 足場 + クレーン）で描画される。

分岐は `BuildingMeshBuilder.Generate` の冒頭（model_type 分岐より先）にあり、Near/Far・詳細生成ワーカー・直接呼び出しのすべての生成経路をカバーする。工事中もオブジェクトは常に表示され、ホバーハイライトは通常ステータスと同様に機能する。

共通仕様（パーツの命名規則・外観バリアントの選択・壁／角の敷き詰めロジック）は
[[F_建物メッシュの生成]] に記述する。

実装は `ConstructingBuildingMeshBuilder`。

---

## 1. 進捗の取り込み

工事の進捗は API の `construction_progress`（= 調達済み建設体積の百分率。サーバー計算値）から取得する。

```
progress01  = clamp01(construction_progress / 100)
builtFloors = clamp(ceil(progress01 × floors), 1, floors)
```

- **0% や未取得（null）でも builtFloors=1** とし、着工済みの現場が視認できるようにする
- バックエンドは建設中に進捗が増えたエポックで建物の version を上げるため、毎エポックの差分ロードで再生成され、足場・クレーンが伸びていく
- 完成（STATUS_ACTIVE への遷移）でも version が上がり、通常メッシュへ自動的に切り替わる

---

## 2. パーツのフォールバック（標準パーツ common）

工事中表示専用パーツ（`scaffold-*` / `crane-*`）は、以下の順で解決される。

```
1. Models/Buildings/{prefix}/{suffix}/{partName}
     prefix は既存の解決（a{variant} → b{bd_type}）、suffix は標準閾値候補（0,100,...,1000）
     のうち variant_number 以下でパーツが存在する最大値
       ↓ ない場合
2. Models/Buildings/common/{partName}   ← 標準パーツ（全建物共通）。common は外観バリアント
     閾値の概念を持たないため suffix フォルダを挟まず直接置く
       ↓ ない場合
3. そのパーツをスキップ
```

`common/` は「バリアント・建物タイプ固有のモデルを用意しなくても、全建物で共通の足場・クレーンが出る」ためのフォールバック先である。

---

## 3. 土マウンド（敷地覆い）

敷地（土地区画のポリゴン。区画が取得できない場合は建物底面）全体を、厚みとランダムな凹凸を持つ土で覆う。マテリアルは `Resources/ConstructionDirt`（未配置時は `ConstructionMaterial`（黄色）→ デフォルト建物マテリアルにフォールバック）。

- **細分化** — ポリゴンを耳切り法で三角形分割した後、一定長を超える辺を中点分割して凹凸用の内部頂点を作る（中点は辺単位で溶接され、T字接合の隙間はできない）
- **上面の高さ** = 基本厚み + 土ノイズ × 境界フェード。土ノイズは多オクターブのPerlinノイズ（fbm）で、大きなうねりと細かい土塊を重ねる（パスの土ストリップと共通）。境界フェードは「元ポリゴン境界までの距離」に比例し、**外周頂点では凹凸0**になるため隣接区画との隙間や Z-fighting が起きない。ノイズ入力はワールド座標なので再生成しても模様は安定する
- **外周スカート** — 上面の縁から地面（ローカルY=0）まで側面を張る
- **基盤** — 完成品と同じ「建物底面をY方向に押し出した土台」（[[F_建物メッシュの生成]] §8.2）を土マテリアルで生成する（完成品に基盤が生成される model_type のみ。工事中→完成の切り替えで土台の有無が変わらない）
- **地形追従** — 超近景（Dynamic）セルではフェンス・地面パネル（[[F_建物メッシュの生成]] §9.4）と同様に各頂点を地形に追従させる

---

## 4. 足場（scaffold-wall / scaffold-corner）

建物底面ポリゴンの外周に足場を、進捗に応じた階数（builtFloors）分積み上げる。

- **配置は通常建物の壁・角と全く同じロジック**（[[F_建物メッシュの生成]] §6・§7）を建物フットプリント上でそのまま使う。**角パーツのヒンジ（原点）はフットプリント頂点にちょうど一致**し、壁は両端を角パーツのアーム長ぶん空けて配置される（オフセットは一切しない）。角は内角に応じたボーン変形（[[F_建物メッシュの生成]] §7.4）もそのまま効く
- `scaffold-wall` / `scaffold-corner` は全辺・全頂点で共通の単一パーツ（通常建物の base-w1〜4 のような位置別パーツではない）
- **フェンス（[[F_建物メッシュの生成]] §9）と異なり、各階を階高になるようY方向のみスケールする**（XZは実寸）。各階を floorY = 階×階高 で生成し、builtFloors 段ぶん作る
- `scaffold-corner` が無い場合は壁のみ（両端の控除なし）。`scaffold-wall` が無い場合は足場全体をスキップする

---

## 5. クレーン（crane-base / crane-mid / crane-top）

論理階数が一定値（既定4階）以上の建物にのみ、タワークレーンを1基立てる。

| パーツ | Yスケール | 役割 |
| --- | --- | --- |
| crane-base | 階高に合わせる | 最下段1段分。無ければ省略される |
| crane-mid | 階高に合わせる | 繰り返しセグメント。残り段数分積まれる |
| crane-top | **なし（実寸）** | 頂部。ジブ・カウンターウェイト込み |

- **積み上げは「原点（モデルの y=0）＝接続点（下端）」基準**。crane-base / crane-mid はその上に伸びる高さが階高になるようY方向のみスケールし、crane-top は実寸のまま最上段の頂点（＝接続点）に原点を合わせて載せる。原点より下に張り出しのあるパーツでも段どうしの隙間が出ない（既成建物の「メッシュ下端基準」（[[F3_既成建物のメッシュ生成]] §2）とはここが異なる。crane 系は接続点を原点に置く前提で著作する）
- 総段数 = `builtFloors + 2`。進捗に連動して伸び、常に現在の足場より少し高く立つ
- crane-base と crane-mid が両方無い場合はクレーン全体をスキップする
- 位置は footprint 重心 + `visual_variant2` シードのオフセット、向きは最初の辺に合わせた Yaw（塔屋 [[F_建物メッシュの生成]] §10 と同じ決め方）

---

## 6. 天面（ceil）

施工済み階の天面を footprint 形状の水平パネルで塞ぐ（足場リングは中空なので、これが無いと建物内部が上から覗ける）。高さは `builtFloors × 階高`。マテリアルは `ceil` パーツ（`a{variant}` → `b{bd_type}` → `common` の順に解決）から取り、無ければデフォルト建物マテリアルにフォールバックする。

---

## 7. コライダーと既知の割り切り

- コライダーは建物底面ポリゴンを `max(builtFloors × 階高, 階高)` まで押し出した形状。クレーンのはみ出しはクリック対象外で許容する（既成建物の top はみ出しと同じ思想。[[F3_既成建物のメッシュ生成]] §4）。敷地（土マウンド）のクリックは土地区画側のコライダーが担う
- `MODEL_MODULAR_GROUND`（畑・庭。[[F2_地面アセットのメッシュ生成]]）と `MODEL_PORT`（岸壁。[[F4_港湾岸壁のメッシュ生成]]）は土マウンドのみで、足場・クレーンは立てない。MODEL_PORT では敷地が海岸線を含むため土が海面上に描かれることがある（既知の制限）
