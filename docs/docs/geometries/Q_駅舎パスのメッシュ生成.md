# Q. 駅舎パスのメッシュ生成

駅舎パス（パスマスターの `type` が `PATH_STATION_HOUSE`、`model_type` が `station_house` のバリアント）は `StationHousePath` が描く。駅舎パスは、ウェイポイント付きの折れ線に沿った通路と、選んだ終端に置く建屋でできている。駅としての意味（ホームの所属・建屋の配置端・通路の方式）は[駅と駅舎](../economics/29_駅と駅舎.md)による。

## 通路

通路の方式はパスごとの `passage_mode`（`elevated`・`ground`・`underground`）で決まる。地下の通路は描かず、クリック判定の面も作らないので、その駅は建屋から選ぶ。

- パーツは `Models/Paths/p{path_variant}/passage_elevated`（上空）または `passage_ground`（地上）を探し、無ければ全駅舎で共通のタイプのフォルダ（`Models/Paths/p{path_type}/`）の同名のパーツを使う。一部のバリアントは、対応する方式でバリアント専用の `body` を使う。
- 通路のモデルは原点を地面に置き、実寸で作る。デッキの地上高・橋脚・欄干はモデルが持ち、コードは通路の高さも幅も変えない。通路の高さはパスの Y ではなくモデルで決まり、建屋の側の接続部にも合わせない。マスターの `width` は、敷地とクリック判定の幅にだけ使う。
- 各アンカー（始点・ウェイポイント・終点）をその真下の地面に置き、アンカーの間を直線で結んで、作った長さのタイルのまま並べる。アンカーの間では地形に沿わせない。

## 建屋

建屋は `house_ends`（`both`・`start`・`end`）で選んだ終端の専有エリアに置く。専有エリアは `house_width` × `house_depth` の矩形で、マスターに無ければ共有定数 `STATION_HOUSE_DEFAULT_WIDTH`・`STATION_HOUSE_DEFAULT_DEPTH` を使う。

- パーツは `Models/Stations/{path_variant}/{パーツ名}` を探し、無ければ全駅舎で共通の `Models/Stations/{パーツ名}` を使う。パーツは建屋の `body` と、地面の材質を与える `floor` の2つである。
- `body` は実寸で置く。原点は矩形の内側の辺（線に近い辺）の中点で、線路を避けてずれていなければパスの端点そのものになる。ローカルの +Z を外向き（線の外側）にし、奥行きと横ずれ（`house_offset`）の形はモデルが持つ。コードは矩形の中心へ寄せたり横ずれを足したりしない。建屋は原点の真下の地面に置くので、基礎を地中へ伸ばし、マスターの専有エリアに収まるように作る。
- `body` が無いバリアントは、専有エリアの矩形の大きさの仮の箱で描く。
- `floor` があれば、専有エリアの矩形に地形に沿った面を張り、その材質で描く。`floor` がどこにも無ければ張らない。
- 建屋もクリックでパスの詳細を開く。駅は駅舎パスそのものだからである。

## 専有エリアの位置

専有エリアの位置は保存されず、パスの形と周囲の線路（鉄道・モノレール）から毎回同じ規則で求める。コアも同じ規則で土地の占有を判定するので、片方だけ変えると土地の占有と見た目が食い違う。線路が増えたり減ったりすれば、位置も変わる。

配置のしかたは、マスターの `house_placement` で決まる。

- `outside`（通常）: 矩形は終端から線の外側へ広がる。線路の敷地（ホームを含む）と重なるなら、重ならなくなるまで外側へずらす。単線の駅のホームは片側にしか無いので、ホームのある側だけを避ける。ずらしたときは、通路も建屋まで延ばす。
- `inside`（高架下）: 終端に最も近い線路の敷地の外側の縁に建屋の外側の辺を合わせ、建屋を高架の下に置く。通路の端は建屋の取り付き位置へ移す。近くに線路が無ければ、終端が建屋の外側の辺になる。

`house_offset` は矩形を横（外向きに見て右が正）へずらす量で、通路の取り付き位置に対して建屋の形が偏っているバリアントに使う。両端の建屋は外向きが逆なので、世界座標では反対の側へずれる。

## 他のパスとの関係

駅舎パスはノードを作らず、道路・線路・ほかのパスと自由に交わる（[J_パスの交差処理](J_パスの交差処理.md)の対象外）。土地を占有するのは専有エリアだけである。敷設中も既存のノードやパスへは吸着せず、グリッドへの吸着だけが効く（[Unity入力制御](../programs/Unity入力制御.md)）。敷設のプレビューも同じ生成器と同じ専有エリアの計算で描くので、確定後の見た目と一致する。
