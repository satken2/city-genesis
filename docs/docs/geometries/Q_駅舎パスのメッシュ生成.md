# Q. 駅舎パスのメッシュ生成

駅舎パス(パスマスターの type=`PATH_STATION_HOUSE`、`model_type: "station_house"`)の描画仕様。駅舎パスは「線に沿った連絡橋」と「両終端の専有エリアに置かれる建屋」で構成される。

## 1. 構成要素

| 要素     | 形状                                | 位置                                 |
| ------ | --------------------------------- | ---------------------------------- |
| 連絡橋(桁) | `body` プレハブをパスの折れ線に沿って実寸で敷き詰めたもの  | 原点(下端)が各アンカーの地形標高。デッキの地上高・橋脚は造形が持つ |
| 建屋     | `house_width` × `house_depth` の矩形 | 線の両終端から外側へ広がる(線路を避けてスライド。§2)       |
| 建屋モデル  | `body` プレハブ(実寸)                    | 原点が矩形の内側の辺の中点(=スライドが無ければパスの端点)        |
| 地面パネル  | 専有エリア矩形と同じ形状の面              | 建屋と同じ位置。地形の傾斜に追従                    |

- 駅舎パスは `curve_allowed: false` のウェイポイント付き折れ線。桁はアンカー(始点・ウェイポイント・終点)を結ぶ直線で架かり、地形の起伏には追従しない(地形追従の細分化をしない)。
- **専有エリアが線路を避けて外側へスライドした場合は、桁もその位置(矩形の内側の辺の中点)まで延長する**。橋がパスの端点で切れて建屋まで届かないのを防ぐ。バックエンドの占有ポリゴンも同じ延長込みの帯で作られる。
- **桁のプレハブ規約は「原点=地面、実寸」**。XZともスケールせず(マスターの `width` に合わせた横方向の引き伸ばしもしない)、原点は各アンカー直下の地形標高に置かれる。デッキの地上高・橋脚・欄干はすべてプレハブ形状が持ち、コードは桁の高さのパラメータを持たない(架線柱・プラットフォームと同じ考え方)。マスターの `width` は敷地ポリゴンとクリック判定の幅にだけ使う。
- 桁は**Z実寸のままアンカー折れ線に沿って敷き詰める**(タイル長の上限は設けない。折れ線スプラインは縦カーブを持たず弦誤差が出ないため)。マスターの `single_span: true` を指定した場合のみ1枚を全長へ引き伸ばすが、Z方向の分割を持たないプレハブではタイルが始点〜終点の弦になりウェイポイントが素通りされるため、造形を持つ桁では `single_span: false` にすること。
- 桁のプレハブ解決とスプライン生成は道路メッシュ([G_道路メッシュの生成](G_道路メッシュの生成.md))の共通ヘルパーを再利用する。プレハブは `Models/Paths/p{path_variant}/` → `p{path_type}/` フォールバック。
- 共通ヘルパー `CreateSplineMesh` には `normalizeBodySurface: false` を渡す。道路用の「body上面をY=0へ揃える補正」を適用すると、モデルが持つ橋の地上高まで消えて地中に埋まるため。スプライン面の帯へ置き換える道路用の区間LODも対象外とし、長い橋でもモデルの高さを維持する。
- 桁は地形基準の深さ判定(トンネル区間分割)の対象外である。スプラインは常に地表にあり、上空の造形はプレハブ側が持つため、地表基準の分割は意味を持たない。
- クリック判定の帯はスプラインではなく、`body` プレハブのメッシュ天端の高さへ持ち上げて置く(実際に見えているデッキの位置でクリックを受けるため)。
- **駅舎のパーツは `Models/Stations/{path_variant}/{パーツ名}` → `Models/Stations/{パーツ名}` の順に解決する**。バリアント専用フォルダに置けばそれが優先され、無ければ全駅舎共通の `Stations` 直下のパーツを使う。パーツは `body`(建屋)と `floor`(地面パネル)の2種。
- 建屋(`body`)は矩形の向き(Y軸回転)で、**実寸で配置する(スケールしない)**。Yは配置位置の地形標高に接地する。`body` が無ければ `house_width` × 8m × `house_depth` の仮箱で代替する(仮箱のみスケールする)。
    - **プレハブの原点は矩形の内側の辺の中点に置く**。線路を避けるスライドが無ければ、これは駅舎パスの端点そのものである。プレハブは奥行き方向の広がり(`house_depth`)も横ずれ(`house_offset`)も造形として持っている前提なので、コード側で矩形の中心へ寄せたりオフセットを足したりしない。
    - 仮箱は矩形の寸法をそのまま可視化する代替表示なので、こちらは**矩形の中心(横ずれ込み)**に置く。
- **地面パネルは専有エリア矩形の範囲に張る**。扱いは建物の地面パネル([F_建物メッシュの生成](F_建物メッシュの生成.md) §8.1)と同じで、`floor` パーツは**マテリアルの供給元にすぎず**、面そのものは矩形から生成する。**`floor` パーツがどこにも無ければ描画しない**(既定マテリアルにはフォールバックしない=不要なスラブを敷かない)。建物と違ってオプトインのマスターフラグ(`draw_floor`)は無く、パーツの有無だけで決まる。
    - 面は**常に地形の傾斜に追従させる**(建物のようなLODティア別の切り替えはしない)。専有エリアは数十m角の矩形なので、水平に張ると傾斜地で地形に埋没・浮上するため。三角形分割したうえで長辺を中点分割して内部頂点を作り、全頂点をその位置の地形標高に合わせる処理は建物の地面パネルと同じ実装を共有する。

## 2. 専有エリア(建屋フットプリント)の算出

専有エリアの位置は保存されず、**パスの形状と周辺の線路から決定的に導出する**。バックエンド(土地占有・収用の判定)とグラフィック(建屋の描画)が同一のアルゴリズムを実装しており、片方だけ変えると土地の占有と見た目が食い違う。

矩形は**終端から外側へ広がる**。すなわち矩形の内側の辺(線に近い側の辺)が終端の上に乗り、そこから `house_depth` ぶん線の外側へ伸びる。矩形が終端を中心に跨ぐことはない。

線の両終端それぞれについて:

1. **外向き方向**: アンカー列(始点・ウェイポイント・終点)から、終端の外向き単位ベクトル `dir` を求める。終端に一致する点が連続する場合は、距離が出るアンカーまで遡る。
2. **座標系**: 終端 `tip` を原点、`dir` を +s 軸、その右手 `right = (dir.z, -dir.x)` を +lat 軸とする(`right` は矩形をY軸回転 `Atan2(dir.x, dir.z)` で置いたときのローカル+X軸に一致する)。
3. **線路の占有区間の収集**: 終端から `STATION_HOUSE_TRACK_SEARCH_RADIUS`(150m)以内にある軌道系パス(鉄道・モノレール)の中心線セグメントを対象に、
    - 線路の占有帯の左右の半幅 `e_left = width/2 + プラットフォームの左張り出し`、`e_right = width/2 + プラットフォームの右張り出し` を求める。左右の張り出しは線路の敷地ポリゴンと同じ解決(`platform_side`・`city.traffic_hand`・`travel_direction` から求める。[N_線路メッシュの生成](N_線路メッシュの生成.md) §7)で、**プラットフォームは片側にしか無いので両側に見込んではいけない**(ホームの無い側で常にホーム1本ぶんの隙間が空き、駅舎が線路に寄れなくなる)。
    - 占有帯の広がりは線路の向きによって s 方向と lat 方向に分配される。セグメントの向き `u` に対する右方向 `u_right = (u.z, -u.x)` を s 軸・lat 軸へ射影した成分を `cs`・`cr`(`cs² + cr² = 1`)とし、各軸方向へのはみ出しを次のように求める(`m` = `STATION_HOUSE_TRACK_CLEARANCE_MARGIN`(1m)):
        - `s_plus = (cs >= 0 ? e_right : e_left) * |cs| + m`、`s_minus = (cs >= 0 ? e_left : e_right) * |cs| + m`
        - `lat_plus = (cr >= 0 ? e_right : e_left) * |cr| + m`、`lat_minus = (cr >= 0 ? e_left : e_right) * |cr| + m`
        - 線路が終端方向と直交していれば(`|cs|=1`)占有半幅がまるごと s 方向のクリアランスになり、並走していれば(`cs=0`)s 方向には広がらず横方向にだけ効く。
    - セグメントを横方向コリドー `lat - house_offset ∈ [-house_width/2 - lat_plus, house_width/2 + lat_minus]` にクリップし、クリップ後の s 範囲を広げた区間 `[s_min - s_minus, s_max + s_plus]` を占有区間として収集する。コリドーは矩形の横ずれ後の位置を中心に取る(避けるべき線路は、実際に矩形が乗る帯の中のものだけであるため)。駅舎パス自身は対象にしない。
4. **スライド距離の決定**: 占有区間を昇順マージし、矩形の内側の辺の位置 `s_in` を、候補「`s_in = 0`(終端そのもの)」および「各マージ済み区間の終端」のうち、占有区間と重ならない(=矩形が占める `[s_in, s_in + house_depth]` がどの区間とも重ならない)最小の `s_in >= 0` とする。区間は有限個なので必ず解がある。
5. **矩形の確定**: 内側の辺の中点 = `tip + dir * s_in`(建屋モデルの原点・橋の取り付き位置)、中心 = `内側の辺の中点 + dir * house_depth/2 + right * house_offset`、向き = `dir`(Y軸回転 = `Atan2(dir.x, dir.z)`)、寸法 = `house_width`(横=`right`方向) × `house_depth`(奥行き=`dir`方向)。

`house_offset` は矩形の横方向のずれ(m、`right` 方向が正)で、連絡橋の取り付き位置に対して建屋の造形が偏心しているバリアントのためのパラメータである。外向き方向は両終端で逆を向くため、同じ `house_offset` でも2つの建屋は世界座標では線の反対側へずれる(建屋から見た偏心の向きは両終端で揃う)。

`house_width` / `house_depth` がマスターに無い場合は `STATION_HOUSE_DEFAULT_WIDTH` / `STATION_HOUSE_DEFAULT_DEPTH` に、`house_offset` が無い場合は0(横ずれなし)にフォールバックする。

この定義により、終端が線路の直前にあれば建屋は線路の向こう側(線の外側)へ押し出され、線が線路群を大きく越えて引かれていれば建屋は終端に接した位置にそのまま建つ。押し出された建屋は、**線路の敷地(プラットフォーム込み)から `STATION_HOUSE_TRACK_CLEARANCE_MARGIN` だけ離れた位置**で止まる。線路が後から増設されると占有区間が変わり、建屋の位置も自動的に再導出される。

## 3. 干渉と交差の規約

- 駅舎パスの線(橋)は上空を通るため、道路・線路・他のパスと自由に交差できる。ノード生成・パス分割・立体交差検証の対象外である([J_パスの交差処理](J_パスの交差処理.md)の適用外)。
- 地上を占有するのは両終端の専有エリアだけで、区画作成・建物の直接配置・地表パスの着工はこの矩形とだけ干渉する。
- 接続を持たないため、**敷設中も既存のノード・パスへ吸着しない**(ノード吸着・パス吸着・直線延長・直角・並行/終端揃えがすべて実効OFF。グリッド吸着のみ有効)。詳細は[Unity入力制御](../programs/Unity入力制御.md) §10。
- 敷設プレビューでも同じ生成器・同じフットプリント算出が走る(プレビュー中のパスは自パス除外の対象にならないだけで、結果は確定後と一致する)。
