# W. 歩行者の描画

## W.1. 概要

歩行者はUnity側だけで生成する描画専用の演出である。バックエンドの歩行者交通量 `path_traffic[VEHICLE_PEDESTRIAN]` に応じた人数をカメラ周辺の歩道・路肩に配置し、道路を連続して歩かせる。経済シミュレーションやサーバーの永続エンティティには影響しない。

考え方は[車両の走行描画](O_車両の走行描画.md)と同じで、**歩行と人数調整は別の処理**である。パスの端に達した歩行者は接続道路へ移るか折り返し、人数超過を理由に端で消さない。不足道路への発生と、過剰な歩行者の建物への到着を一定間隔で調整する。

車両との違いは次のとおり。

| 項目 | 車両 | 歩行者 |
| --- | --- | --- |
| 対象パス | `PATH_MOTORWAY` / `PATH_STREET` | `PATH_STREET` / `PATH_WALKWAY`(バックエンドの歩行者経路グラフと同じ) |
| 横位置 | 車線中心 | 歩道の帯・路肩・歩行者専用道路の全幅の中のランダムな位置 |
| 速度 | コアの平均通過時間に合わせる時間制御と前車追従 | 個体ごとの定数(平均1.1m/s±25%)。混雑倍率・追従・信号は無い |
| 通行方向 | `travel_direction` に従う | 一方通行でも両方向に歩く |
| 折り返し | 街路の行き止まりだけ | どこでも折り返す |
| 到着先 | 通行側の建物入口。逆探索表で誘導 | 進行方向の先に現れた最初の建物入口。同じ側を優先し、無ければ車道を横切る |
| 実体 | 車種別のGameObjectプール | GameObjectを持たず `Graphics.RenderMeshInstanced` で描く |
| 走行音 | `VehicleAmbience` へ通知 | 無し |

衝突判定・信号・横断歩道は扱わない。歩行者は互いにも車にもすり抜ける。駅への出入りやプラットフォーム上の待機は未実装である(§W.9)。

## W.2. 入力データ

既にロードされている `PathManager` の道路データだけを使う。時間APIは呼ばない。

| 入力 | 用途 |
| --- | --- |
| `path_traffic["0"]`(`VEHICLE_PEDESTRIAN`) | 日次の徒歩トリップ数。目標人数と分岐の重み |
| `path_type`・`status` | `PATH_STREET` / `PATH_WALKWAY` かつ `STATUS_ACTIVE` の選別 |
| 始終点ノードID | 同一ノードに接続する次の道路の取得 |
| パスマスターの道路幅・歩道幅 | 歩行帯の横位置(§W.4) |
| 区画の接道ID・建物 | 建物入口(§W.7) |

歩行速度はコアの `GENERAL_PARAMS.PEDESTRIAN_SPEED`(4km/h)と同値の `LocalConstants.PEDESTRIAN_WALK_SPEED`(1.1m/s)を使う。歩行者には混雑倍率が無いので、車両のような `/paths/motion` の取得は不要である。活動時間は車両と同じ `LocalConstants.VEHICLE_ACTIVE_HOURS_PER_DAY`(15h)を既定にする。

交通量は道路合計であり、方向別・左右別の内訳を含まない。発生方向・歩道の左右は等確率とし、分岐は接続道路の歩行者交通量による確率的な演出とする。

## W.3. 管理範囲と道路スナップショット

中心は `CameraCellChecker.CurrentWorldPosition`。管理半径は `renderRadius + despawnMargin`(既定250m + 50m)で、車両より狭い(人は小さく、遠くでは見えないため)。目標人数・発生位置・範囲外の消滅は同じ管理円を使う。

0.5秒ごとに `PathManager.GetPathsNearCircle` で候補を取り、`TryGetPathPolyline` の中心線を累積距離付きの `VehiclePolyline` として共有する。円内区間の求め方、道路更新時の進捗率での移し替え、注視点の大きな移動でのリセットは車両と同じ。

## W.4. 歩行帯(横位置と高さ)

歩行者はパス中心線から `lateral` だけ横へずれ、`surface` だけ上に浮いた位置を歩く。帯は `PedestrianManager.ResolveBand` が道路幅 W・歩道幅 SW から決める。`margin` は帯の縁からの余白(既定0.3m)、`shoulder` は歩道が無い道路で路肩として使う幅(既定1.0m)。

| パス | 歩行帯(中心線からの距離) | 高さ(スプライン基準面から) |
| --- | --- | --- |
| `PATH_STREET`・歩道あり(SW>0) | 左右それぞれ `[W/2 − SW + margin, W/2 − margin]` | `SIDEWALK_ABOVE_SPLINE` + 歩道の造形高さ0.2m(`PEDESTRIAN_SIDEWALK_SURFACE`) |
| `PATH_STREET`・歩道なし(SW=0) | 左右それぞれ `[W/2 − shoulder, W/2 − margin]`(路肩) | `BODY_ABOVE_SPLINE`(路面) |
| `PATH_WALKWAY` | 左右に分けず `[−(W/2 − margin), W/2 − margin]` の1本の帯 | `BODY_ABOVE_SPLINE` |

歩道の造形高さは標準歩道プレハブの値([道路メッシュの生成](G_道路メッシュの生成.md) §8.5)で、バリアントごとの差は数cmの浮き沈みとして許容する。狭い道路で内縁が外縁を超える場合は内縁を外縁に合わせる。

横位置の左右は**パス幾何(始点→終点)に対する左右**で保持する。進行方向を反転しても符号を変えないので、折り返した歩行者は同じ歩道に留まる。歩行者専用道路は左右の区別を持たない(`side = 0`)。

## W.5. 人数と全体枠

道路ごとの期待人数は車両と同じ式で求める。

**期待人数 = 日次歩行者交通量 ÷ (活動時間[h] × 3600) × 管理円内の中心線長[m] ÷ 平均歩行速度[m/s] × 表示倍率**

`renderFraction` は表示倍率で、1が交通量の等倍。2や4にすると人数を増やせる。既定は車両と同じ1。交通量0の道路には最低人数を設けない(データ上歩行者がいない道路に人を出さない)。

全体の枠は車両と同じ `VehiclePopulationBudget` を使う。道路ごとに切り上げず、全道路の期待人数を合算してから整数化し、端数は12秒の時間窓で繰り越す。期待人数の合計が `maxActivePedestrians`(既定1000)を超える場合は全道路に同じ縮小倍率を掛ける。

0.25秒ごとに道路別の現在人数を数え直し、不足なら発生、超過なら到着予約、総数が合っていても2秒ごとに偏りを調整する。偏りの許容幅は `max(0.5人, 期待値の25%)`。到着先(建物入口)も管理円外への出口も無い閉じた網では、既存の歩行者を残して補充を止める。

## W.6. 発生・分岐・折り返し

初期配置は各道路の円内区間の長さに比例して位置を選び、左右の歩道と進行方向を等確率で決める。初期の枠を満たした後の補充は、有効な建物入口か、管理円へ入ってくる境界付近に限る。入口から出る歩行者は敷地内の点から歩道上の位置へ直線で歩いてから通常の歩行に戻る。

パスの端に達したら `GetPathsConnectedToNode` の接続道路のうち、管理範囲内で歩ける道路を候補にし、歩行者交通量を重みに抽選する。交通量0の候補は正の候補が無いときだけ均等抽選で使う。**進行方向に対する左右を保って次の道路の歩道へ移り**、現在位置と次の歩道の入口を三次ベジエ(張り出し係数0.3)で結ぶ。歩道の角のジオメトリはなぞらず、必要なら車道を斜めに横切る。候補が無ければその場で折り返す。接続先が未ロードなら端で立ち止まり、ロード後に再開する。端で消したりフェードしたりしない。

## W.7. 建物への出入り

建物入口の幾何は車両と共有する `RoadsideAccess` が求める。区画の接道辺の中点を道路中心線へ射影し、道路端から3m以上・外縁差−1〜4m・高低差2m以内・辺が道路とほぼ平行・敷地内3mの点が本当に区画内、を満たす辺だけを入口にする(詳細は[車両の走行描画](O_車両の走行描画.md) §O.7)。歩行者向けの差分は次の2点。

- 進行方向・通行側の制約を持たず、パス幾何に対する左右だけを持つ。
- `PATH_STREET` に加えて `PATH_WALKWAY` 沿いの区画も対象にする(`frontage_allowed` のバリアントに限る)。

到着予約を受けた歩行者は、進行方向の先にある最寄りの入口を選ぶ。同じ側の歩道の入口を優先し、無ければ反対側の入口へ車道を横切って入る。入口に達したら区画・建物がまだ有効なことを確かめ、敷地内の点まで直線で歩いてから0.4秒で縮小して消える。発生時は0.4秒で拡大する。

入口表は周辺道路だけを走査し、区画・建物・中心線の版が変わった区画だけ再計算する。約1msごとにコルーチンを次フレームへ譲り、完成した表を一括交換する。車両と違って退出先への逆探索表は持たない(歩行者は交通量重みのランダム歩行で、到着予約中は次に現れた入口へ入る)。

## W.8. 描画とモデル

歩行者はGameObjectを持たない。毎フレーム `LateUpdate` で全員の位置・向き・フェードのスケールを `Matrix4x4` にし、モデル番号×パーツごとに `Graphics.RenderMeshInstanced`(1回1023件まで)で描く。パーツは `PropRenderModel` が固定名 `Models/Props/pedestrian_{n}` から取り出す([地形プロップ](M_地形プロップ.md) §M.5 の固定名モデルと同じ仕組み)。`pedestrian_0` から順に読み、無い番号で打ち切る。1つも無ければ人型の箱で描く。影は落とし、受ける。描画LOD(`_close`/`_far`)は使わない。

モデルは肩・腰を絞った胴、首、顎と頭頂を面取りした頭、袖・前腕・手、膝・足首、つま先のある靴で構成する。1体332三角形(400未満)、身長1.58〜1.78m、体格・衣服色の異なる6体。脚を前後に開き、腕は逆向きに振った固定姿勢である。各部位は上下を含む閉じた立体とし、生成時に面の欠落・巻き順・各部位の外向きを検査する。原点は両足の間の接地点、前方は+Z。著作は `genesis-gallery/library/props.blend`、生成ジョブは `pipeline/jobs/build_pedestrians.py`(寸法は同ディレクトリの `pedestrians.md`)。材質は肌2色・髪2色・衣服6色・靴の単色 `PROP_*` を使う。ミラープレハブは `ModelPrefabGenerator` が生成する。バリデータは `pedestrian_` 接頭辞に専用の頂点予算(Normal 700)を適用し、接地・水平中心は地形プロップと同じ規約で検査する。

## W.9. コンポーネントと調整値

| コンポーネント | 責務 |
| --- | --- |
| `PedestrianManager` | 範囲更新、歩行帯、期待人数、分岐、密度調整、入口表、instanced描画。`AfterSceneLoad` で自己生成する |
| `Pedestrian` | 1人の状態(横位置・接続点列・到着)と残り時間を返す移動 |
| `RoadsideAccess` | 建物入口の幾何と有効性検査。`VehicleManager` と共有 |
| `VehiclePolyline` / `VehiclePopulationBudget` | 車両と共有する点列と全体枠 |

| パラメータ | 既定 | 意味 |
| --- | --- | --- |
| `renderRadius` / `despawnMargin` | 250m / 50m | 合計が管理半径 |
| `renderFraction` | 1 | 歩行者交通量に対する表示倍率(1=等倍、2・4で増やす) |
| `activeHoursPerDay` | 15h | 日次交通量を流量へ変換する活動時間 |
| `maxActivePedestrians` | 1000 | 絶対上限 |
| `rangeScanInterval` | 0.5秒 | 道路スナップショットの更新間隔 |
| `spawnFillRate` / `minimumJourneyTime` | 1/秒 / 6秒 | 補充速度と、到着対象にする最低歩行時間 |
| `walkSpeed` / `walkSpeedJitter` | 1.1m/s / 0.25 | 平均歩行速度と個体差 |
| `bandMargin` / `shoulderWidth` | 0.3m / 1.0m | 歩行帯の縁の余白と、歩道が無い道路の路肩幅 |
| `connectorTension` | 0.3 | 交差点の接続曲線の張り出し |
| `fadeDuration` | 0.4秒 | 発生・到着のスケール補間時間 |

表示のON/OFFトグルは持たない(車両と同じ)。

## W.10. 検証と制限

`unity/Tests/Vehicles/run.ps1` が車両と同じ独立Unityで検証する。歩行帯の解決、反転しても同じ歩道に留まること、一方通行でも両方向に歩くこと、環状路での総数の安定と歩道帯内の横位置・高さ、建物入口からの消滅、閉じた網での維持、モデルの三角形数・寸法・接地と、FBX取り込み後の面の閉鎖・巻き順・法線・部位ごとの外向きを検査する。

未実装・対象外: 駅の入口への出入りとプラットフォーム上の待機、連絡橋の上の歩行、横断歩道・信号、他の歩行者や車との干渉、手足のアニメーション、バス停などの停留所。駅とホームの人流は路線の利用者数から近似できる見込みだが、今は扱わない。
