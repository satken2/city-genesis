# マテリアル共有とエクスポート

モデルの取り込みに共通する、マテリアルの名前と共有の約束である。メッシュの生成時にどのマテリアルを使うかは [R_マテリアルの解決](R_マテリアルの解決.md) に書く。

## マテリアル名

| 名前 | 用途 |
| --- | --- |
| `BD_*` / `PATH_*` / `PROP_*` | 建物・パス・プロップの材質。カテゴリをまたいで同じ材質を使ってよい |
| `MAT_{素材}_{色}` | 新しい共通の PBR 材質 |
| `SLOT_{役割}` | 路線の色など、実行時に値を置き換える材質 |

同じ材質は同じ名前にそろえる。実行時に色を置き換える材質を別の用途と同じ名前にすると、共有している先まで染まるので、役割ごとに名前を分ける。

## 共有の単位

Unity では、名前が同じでも別の Material の実体は共有されず、同じマテリアルの面をまとめる描画の最適化も効かない。複数のモデルで1つの実体を使うには、同じ `.mat` アセットを参照させる（FBX の取り込み設定で、モデルのマテリアルをその `.mat` へ割り当てる）。パスの生成器だけは名前をキーに実体をまとめるので、パスのパーツは名前がそろっていれば共有される。実行時に読む glTF は、別のファイルが持つ同名の Material・Texture が別の実体になる。

## FBXとラッパープレハブ

原本は `blender/` のライブラリ、書き出した FBX は `Assets/Models/`、実行時に読むラッパープレハブは `Assets/Resources/Models/` の同じ相対パスに置く。ラッパーはエディタ拡張 `ModelPrefabGenerator` が FBX に合わせて作る。実行時はモデルをリソースパスで探し、`persistentDataPath` の同じ相対パスに glTF があればプレハブより優先する。生成器はメッシュの頂点を読んで配置を焼き込むので、`Assets/Models` のメッシュは Read/Write Enabled が必須で、エディタ拡張が取り込みのたびに有効にする。接写用の `_close` と遠景用のモデルも同じ経路で取り込む。
