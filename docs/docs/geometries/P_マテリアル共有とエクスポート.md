# マテリアル共有とエクスポート

建物・道路パーツのマテリアルを**複数アセット間で共有**し、重複（＝メモリ・ドローコールの肥大）を防ぐための仕組みと、Blender からのマテリアルエクスポート規約をまとめる。

パーツの制作規格・座標系は [[I_建物パーツ作成マニュアル]]、メッシュ組み立ては [[F_建物メッシュの生成]]、パックとしての配布（base / DLC / Mod）とアセット形式の方針は [[追加コンテンツとアセットパック]] を前提とする。

「生成器が各面にどのマテリアルを割り当てるか」（供給元とフォールバック順）は [[R_マテリアルの解決]] に分離してある。本ドキュメントは、そこで解決された**マテリアル実体を1つに集約する**ための仕組みと制作規約を扱う。

---

## 1. なぜマテリアル共有が要るのか

同じ見た目のマテリアル（例：コンクリート壁）が、パーツやアセットの数だけ別インスタンスとして生成されると、`Material` と参照先 `Texture2D` がその数だけ複製され、ドローコールのバッチングも効かなくなる。**DLC で建物を何十棟追加するようなケースでは、共有の有無がそのままメモリ・描画負荷の差**になる。

マテリアルの同一性は Unity では**オブジェクトの実体（インスタンス）**で判定される。名前が同じでも別インスタンスなら別物として扱われるため、「同名なら勝手にまとまる」ことは**標準では起きない**。共有には、後述の「同名アセットへ寄せる」仕組みを明示的に通す必要がある。

> `BuildingMeshBuilder.MergeSubMeshes` はサブメッシュ統合時に `material.GetEntityId()`（実体ID）をキーにする。**同名でも別インスタンスはマージされない**。共有はあくまで「同じマテリアル実体を参照させる」ことで達成する。

---

## 2. 現状の共有経路（実装済み）

このプロジェクトには、共有を成立させる経路が3つある。

| # | 経路 | 対象 | 仕組み |
|---|---|---|---|
| a | **`sharedMaterials` の直接流用** | 建物の壁・角・地面パーツ | `BuildingMeshUtils.GetModuleMaterials` が `renderer.sharedMaterials` を複製せず返す。同じパーツ（同じ論理パス）は `ModelManager._modelCache` でキャッシュされるため、**同一パーツを使う建物インスタンス間でマテリアル実体が共有**される |
| b | **静的キャッシュのデフォルト系** | フォールバック用・全建物共通素材 | `GetDefaultBuildingMaterial`（`Resources/BuildingMaterial`）、`GetCommonConcreteMaterial`（`Resources/COMMON_CONCRETE`。基盤用）を static フィールドにキャッシュし全建物で1実体を共有 |
| c | **名前キーの共有プール** | 道路・住宅屋根 | `RoadPath.GetOrCreateRoadMaterial`、`HouseRoofBuilder.RoofMaterialCache`。マテリアル**名**をキーに `Dictionary<string, Material>` で集約する |

経路 c が本ドキュメントの中心概念である。実装例：

- **道路** `RoadPath.GetOrCreateRoadMaterial(source)`：`source.name` をキーにキャッシュを引き、無ければ**同名の `Resources` マテリアルを `Resources.Load<Material>(name)` で探して**採用（無ければ source をクローン）、以後そのキーで共有する。マテリアル名を直接渡す入口（`GetOrCreateRoadMaterialByName`）もあり、パスマスターの `body_material` で名指しされた交差点アスファルトが**同じプール**を引く（＝道路本体と同名なら1実体に集約される）。
- **住宅屋根** `HouseRoofBuilder`：`B02_ROOF_01`〜`10` の名前配列を持ち、`Resources/B02/{name}.mat` を名前キーの `RoofMaterialCache` 経由でロード・共有する。実体の共有 `.mat` は `Assets/Resources/B02/` に配置済み。

### 2.1 未カバー：建物の壁・角パーツ（glTF 経路）

建物の壁・角パーツは経路 a（`sharedMaterials` 直返し）のみで、経路 c の**名前ベース共有プールを通っていない**。FBX の場合は §3 の Unity インポート機構で共有できるが、**glTF を実行時ロードする Mod では**、ファイルごとに `Material` が新規生成されるため、名前が同じでも重複する。Mod の重複対策には、道路・屋根と同じ名前プールを建物パーツのロード経路（`ModelManager` / `BuildingMeshUtils`）に導入する必要がある（**未実装**）。

## 3. FBX 同士の共有（base / 公式DLC）

base と公式DLC は FBX を Editor でインポートする（[[追加コンテンツとアセットパック]] §アセット形式とロード経路）。Unity の FBX インポーターには**名前ベースでマテリアルを共有する標準機能**があり、これが FBX 経路の共有の主軸になる。

### 3.1 現在のインポート設定

建物パーツ FBX（`Assets/Models/Buildings/**.fbx`）の `.meta` は次の設定になっている。

```yaml
materials:
  materialImportMode: 2   # マテリアルをインポートする
  materialName: 0          # BasedOnMaterialName（マテリアル名をそのまま使う）
  materialSearch: 1        # RecursiveUp（親フォルダを再帰的に遡って同名マテリアルを探す）
  materialLocation: 1      # External（埋め込みでなく外部 .mat アセットとして扱う）
```

**`materialSearch: RecursiveUp`** により、あるFBXがインポートされるとき、**そのFBXから見て親方向のフォルダに同名の `.mat` があればそれを参照する**。つまり **FBX 間はマテリアル名を揃えれば自動で共有される設定に既になっている**。

ただし現状、壁・角パーツ用に抽出済みの共有 `.mat` はまだ存在しない（`externalObjects` は空、`Materials/` フォルダ無し）。**仕組みは有効だが「マテリアル抽出（Extract Materials）」が未実施**なので、このままでは各FBXが個別にマテリアルを持つ。

### 3.2 FBX 共有の手順（コード変更不要）

1. **Blender 側でマテリアル名を建物横断で統一**する（§5 の命名規約）。
2. どれか1つの FBX を選び、Inspector の **Materials タブ → Extract Materials** で `.mat` を書き出す。書き出し先は**共有したい全FBXの共通の親フォルダ**にする（`RecursiveUp` は親方向しか辿らないため。例：`Assets/Models/Buildings/` 直下、または専用の `Assets/Models/Buildings/Materials/`）。
3. 他のFBXを（再）インポートすると、`RecursiveUp` が親フォルダの同名 `.mat` を見つけて自動的に参照する。→ 同名マテリアルは1実体に集約される。

> 既存の住宅屋根 `Resources/B02/*.mat`（§2）は、この「抽出済み共有マテリアルを名前で参照する」パターンの先行例である。

### 3.3 公式DLC での共有

公式DLC も FBX を Editor でインポートするため、§3.2 がそのまま使える。さらに DLC を AssetBundle / Addressables に焼き込む際、**base ゲームが持つ共有マテリアルを依存参照**させれば、DLC 建物が base のマテリアルを使い回せる（DLC 側にコピーを持たない）。**DLC で何十棟追加してもマテリアル・テクスチャが重複しない**のはこの経路による。

## 4. glTF / glb での共有（Mod）

Mod は実行時に `Siccity.GLTFUtility` で `.glb` をロードする（Editor を通らない）。

- `Importer.LoadFromFile` は**ファイルごとに `Material` / `Texture2D` を新規生成**する。`materialSearch` のような名前解決は働かない。
- `ModelManager._modelCache` のキーは**リソースパス（ファイル単位）**であり、マテリアル名単位ではない。

したがって：

| ケース | 共有 |
|---|---|
| 同じ `.glb` ファイル内の複数メッシュが同一マテリアルを参照 | ✅ される（1ファイル内で1実体） |
| 同じ `.glb` を複数箇所から参照 | ✅ される（`_modelCache` 経由） |
| **別々の `.glb` が同名マテリアルを持つ** | ❌ されない（都度別実体） |

**Blender のライブラリリンクで .blend 間マテリアルを共有しても、glTF エクスポートはファイルごとにマテリアルを焼き込むため、実行時共有には繋がらない**（作業効率には有効）。

glTF 経路で「別ファイルの同名マテリアルを1実体に寄せる」には、§2 c の名前ベース共有プール（`RoadPath.GetOrCreateRoadMaterial` 相当）を `ModelManager` のロード後段に導入する必要がある（**未実装**）。導入すれば、マテリアルを共有実体に差し替えた時点で参照先テクスチャも共有されるため、テクスチャ重複も同時に解消する。

## 5. Blender からのマテリアルエクスポート規約

座標系・FBXトランスフォームの設定は [[I_建物パーツ作成マニュアル]] §5 を参照。ここではマテリアルに絞る。

### 5.1 命名規約（最重要）

共有はすべて**マテリアル名の一致**が起点になる（FBX の `RecursiveUp`、道路・屋根・（将来の）建物の名前プール）。したがって：

- **共有したいマテリアルは、建物・カテゴリを跨いで同一の名前**にする。命名は用途が一意に分かる形にする（例：`Concrete_Gray`, `Glass_Blue`, `Brick_Red`, `B02_ROOF_01`）。
- base ゲームと同じマテリアルを使いたい DLC/Mod は、**base 側と同名**にする。FBX 経路では自動で寄り、名前プール導入後の glTF 経路でも寄る。
- Blender の `.001` サフィックス自動付与（同名データブロック複製時）に注意。エクスポート前に重複を解消し、意図した名前だけを残す。

### 5.2 テクスチャの扱い

- **FBX**：テクスチャはFBXに埋め込まず**外部参照**にし、Unity 側は抽出した共有 `.mat` にテクスチャを割り当てる運用が扱いやすい。同名マテリアルへ寄せれば、そのマテリアルが指すテクスチャも1枚に集約される。
- **glTF/glb（Mod）**：テクスチャはファイルに内包／参照される。名前プール未導入の現状では、**別ファイルは同じ画像でも別 `Texture2D`** になりうる。重複を避けたいテクスチャは、可能な限り**共有マテリアル（＝共有 .glb やアトラス）にまとめる**方向で設計する。

### 5.3 1ファイルにまとめるか、分けるか

- **同一カテゴリの建物を1つの .blend にまとめる**のは制作管理上は有効。ただし**実行時共有に効くのは「同じエクスポート単位（同じ .glb / 同じ Editor 抽出マテリアル）に入るか」**であり、.blend をまとめること自体が直接効くわけではない。
- 現行ローダーは**パーツ単位**でモデルを解決する（`Models/Buildings/{prefix}/{threshold}/{partName}`）。したがって「増殖を止める」現実的な打ち手は、**ファイル構成の工夫よりも §5.1 のマテリアル名統一 ＋（FBXなら）共有 .mat 抽出 ／（glTFなら）名前プール導入**である。

## 6. まとめ（早見表）

| 形式 | 共有の実現方法 | 追加作業 | 状態 |
|---|---|---|---|
| **FBX ↔ FBX**（base / DLC） | マテリアル名統一 ＋ Extract Materials で共通親フォルダに `.mat` 配置（`materialSearch: RecursiveUp`） | Blender命名統一 ＋ 抽出1回。**コード変更不要** | 仕組みは有効、抽出は未実施 |
| **DLC の FBX** | 上記 ＋ AssetBundle/Addressables で base マテリアルを依存参照 | DLCビルドパイプライン | 未実装（[[追加コンテンツとアセットパック]]） |
| **glTF ↔ glTF**（Mod） | 名前ベース共有プール（`RoadPath.GetOrCreateRoadMaterial` 相当）をロード後段に導入 | コード追加 | 未実装 |
| **FBX ↔ glTF** | 実体は別系統のため直接共有は不可 | — | 対象外 |

現状アセットは FBX のみ（`.glb` は0件）。**今すぐ効くのは FBX 経路（マテリアル名統一 ＋ Extract Materials）**。glTF は Mod 実装時に名前プールを併せて導入するのが望ましい。
