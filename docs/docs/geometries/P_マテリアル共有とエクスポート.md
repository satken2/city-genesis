# マテリアル共有とエクスポート

モデルの制作・取り込みに共通するマテリアル名と共有の規約を説明する。メッシュ生成時の解決順は[マテリアルの解決](R_マテリアルの解決.md)、建物の座標系は[パーツ制作規格](I_建物パーツ作成マニュアル.md)に定義する。

## 共有の単位

Unityでは同名でも別のMaterial実体は共有されない。同じアセットを参照するモデル同士はMaterialとTextureを共有できる。建物パーツ・共通素材・パスの実行時共有経路は[解決仕様](R_マテリアルの解決.md)に従う。

FBXの取り込みはマテリアル名を使用し、親フォルダを遡って同名の外部 `.mat` を探す（`materialName: 0`、`materialSearch: 1`、`materialLocation: 1`）。外部 `.mat` が無い場合は各FBXが持つマテリアルを使う。共有する `.mat` は対象FBXの共通の親フォルダに置く。

実行時のglTFロードでは、モデルパスのキャッシュは同じファイルを再利用する。別ファイルの建物パーツが持つ同名のMaterial・Textureは、それぞれ別実体になる。Blenderのライブラリ共有も、書き出した別ファイル間の実行時共有にはならない。

## マテリアル名

| 名前 | 用途 |
| --- | --- |
| `BD_*` / `PATH_*` / `PROP_*` | 既存の材質名。カテゴリを跨いで同じ材質を利用できる |
| `MAT_{素材}_{色}` | 新しい共通PBR材質 |
| `SLOT_{役割}` | 路線色など、実行時に値を置き換える材質 |

同じ材質は同名・同じ値に揃える。異なる用途の実行時色替えに同じ名前を使うと、共有先も染まるため役割を分ける。Blenderの自動サフィックス `.001` を意図した共有名へ混ぜない。テクスチャの有無やシェーダー種別を名前へ含めない。

FBXのテクスチャは外部参照を使う。同じ `.mat` へ集約したモデルはそのテクスチャも共有する。glTFはファイル内包・参照の素材を使い、別ファイルの同じ画像も別Textureになる場合がある。

## FBXとラッパープレハブ

原本は `blender/` のライブラリ、書き出すFBXは `Assets/Models/`、ランタイムで読むラッパープレハブは `Assets/Resources/Models/` の同じ相対パスに置く。

`Assets/Editor/ModelPrefabGenerator.cs` が追加・移動したFBXのラッパーを生成する。純粋なラッパーを同期対象にし、手で変更したプレハブは上書きしない。削除・移動後の孤児プレハブはランタイムの候補として残るため、孤児削除の対象になる。同期・削除の操作は同エディタ拡張に定義する。

`Assets/Models` のメッシュはRead/Write Enabledが必須で、`ModelImportSettings.cs` が有効にする。生成器が頂点を読み、配置行列を焼き込むためである。

接写用の `_close` と遠景用の `_far` は同じ取り込み経路を使う。通常モデルとの原点・寸法・部品構成の契約は[建物パーツ](I_建物パーツ作成マニュアル.md)、[道路](G_道路メッシュの生成.md)、[車両](O_車両の走行描画.md)に従う。
