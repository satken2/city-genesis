# マッシュアップ建物のメッシュ生成（MODEL_MASHUP）

## 概要

学校（校舎＋体育館）や変電所（管理棟＋変圧器）のように、**1つの施設が複数の棟（サブ建物）で構成される建物**に適用する生成方式。

バックエンドは建物が立地する土地区画を **8m×8m の正方形セル**に決定論的に分割し、各セル（サブ建物の寸法によっては複数セル）へ `subbuilding_master` に定義されたサブ建物を割り付ける。区画が三角形なら階段状に、細長ければ一列に、といった任意のセル配置になり、端の余りはそのまま隙間として残る。

このセル分割と割り付けは**すべてバックエンド側で解決済み**であり、フロントエンドには配置結果（サブ建物ごとの座標・回転・階数）だけが `sub_buildings` プロパティとして届く。**Unity 側はセル分割のロジックを持たない**。

各サブ建物は既成建物（[F3_既成建物のメッシュ生成](F3_既成建物のメッシュ生成.md)）と同じ積み上げロジックで組み立てる。塔屋・エントランスは配置しない。フェンスと地面パネル（`draw_floor=yes` の場合）は描画する。遠景も棟ごとの遠景パーツを同じ配置で組み立てる（§8）。

共通仕様（パーツの命名規則・外観バリアントの選択・地面パネル・フェンス）は [F_建物メッシュの生成](F_建物メッシュの生成.md) を参照。本ドキュメントは差分のみを記述する。

接地高は**建物中心位置（center_point）の地形標高**（F §2.4）。コンクリート基盤（F §8.2）は生成しない。

実装は `MashupBuildingMeshBuilder`。露天掘り（MODEL_OPEN_PIT）の前庭に並ぶ設備も同じ `sub_buildings` を同じ規則で組み立てる（[F11_露天掘りのメッシュ生成](F11_露天掘りのメッシュ生成.md)）。

---

## 1. 配置データ（sub_buildings）

建物一覧 API（`GET /buildings/`）のレスポンスで、MODEL_MASHUP の建物には `sub_buildings` プロパティが付与される。サブ建物1棟につき1エントリの配列である。

```json
"sub_buildings": [
  {
    "subbuilding_id": 3,
    "model_prefix": "schoolhouse",
    "position": [12.0, -4.0],
    "rotation": 90.0,
    "floors": 3,
    "height_per_floor": 4.0
  }
]
```

| フィールド | 型 | 説明 |
|---|---|---|
| `subbuilding_id` | int | サブ建物の種類ID（`subbuilding_master` のキー） |
| `model_prefix` | str | パーツ名の解決に使う接頭辞（§2）。`subbuilding_master` に定義された値がバックエンドで解決されて届く |
| `position` | [float, float] | `center_point` 基準の相対XZ座標。サブ建物が専有するセル矩形の**中心**であり、モデル原点をここへ置く |
| `rotation` | float | XZ平面上の角度（度）。壁パーツと同じ回転規約（モデルのX軸を辺方向に向ける。[F_建物メッシュの生成](F_建物メッシュの生成.md) §6）でY軸回転として適用する |
| `floors` | int | 積み上げ階数（1以上）。**親建物の `floors` を棟定義の階数範囲（`min_floors`〜`max_floors`）でクランプした値**がサーバーサイドで解決されて届く（棟ごとには保存されない）。親の階数を変えるとすべての棟が追従し、積み上げできない棟（体育館など）は `max_floors=1` により据え置かれる |
| `height_per_floor` | float | このサブ建物の階高（m）。パーツが1つも見つからない棟の白い箱（§7）の高さにだけ使う。未設定の場合は建物本体のマスター値（F §14）を使う |

- サブ建物は幅・奥行きに応じて複数セル（例: 16m×8m = 2セル）を専有することがある。専有範囲は `position` と実寸パーツから自然に決まるため、フロントエンドがセル境界を意識する必要はない。
- `sub_buildings` が空または未設定の建物（配置計画が未登録の場合）は、敷地装飾のみを描画する（§7）。

配置計画は建物の作成時（手動設置・自動建設のどちらでも）にバックエンドが自動生成する。先頭の棟（施設の顔となる棟）は必ず前面（接道辺）寄りに配置され、各棟はマスターに定義された棟数比（`weight`）を保ちながら、敷地の広さに応じた数だけ配置される（最低・最大配置数は `min_count` / `max_count`）。同じ種類の棟は隣接して並ぶ。敷地の2割程度は空地として残る。

配置は建物の status を問わず後から編集できる。

- `GET /buildings/{agent_id}/sub-buildings` — 現在の配置リストを単体取得（`model_prefix` 等を解決済みの形式。配置が無い建物は空リスト）
- `POST /buildings/{agent_id}/sub-buildings` — サブ建物を1棟追加（`subbuilding_id` と `position` が必須。`rotation` は任意。階数は指定できず、親建物の `floors` から自動導出される）
- `PUT /buildings/{agent_id}/sub-buildings` — 配置リストを一括置換（ペイロードは `{"sub_buildings": [...]}`。各エントリの形式は追加と同一で、空リストを渡すと全撤去になる）
- `DELETE /buildings/{agent_id}/sub-buildings/{index}` — `sub_buildings` 配列のインデックス指定で1棟削除

いずれも建物の `version` が更新されるため、フロントエンドは通常の差分同期でメッシュを再生成すればよい。

棟ごとの定義（寸法・階数範囲・棟数比 `weight`・配置数範囲 `min_count` / `max_count`・表示名）は `GET /api/v1/master/subbuildings` が返すサブ建物マスターを参照する。マスターの底面寸法 `width` / `height` は**セル数単位**（1単位=8m、未定義は1セル）で、`width` が `rotation` の向き＝**モデルのX方向（幅）**、`height` が奥行き方向のセル数である。UI（Tauri）の配置エディタは、建物詳細パネルの「建物情報」タブ末尾にある「建物配置を編集」から開く `mashup_edit` ウィンドウで、このマスターと上記APIを使ってサブ建物の配置（追加・移動・回転・削除）を編集し、保存時に一括置換を送信する。このボタンはマッシュアップ建物に表示し、神モードの「プロパティ編集」と同じ全幅のスタイルを使う。

## 2. パーツの命名と外観バリアント

サブ建物のパーツはリソースパスに `model_prefix` を埋め込んだ動的な命名を用いる。

```
Models/Buildings/{prefix}/{threshold}/mashup-{model_prefix}-base-prebuilt
Models/Buildings/{prefix}/{threshold}/mashup-{model_prefix}-mid-prebuilt
Models/Buildings/{prefix}/{threshold}/mashup-{model_prefix}-top-prebuilt
```

- **prefix** — 通常の解決規則（`a{variant}` → `b{bd_type}`。F §3.2）に従う。
- **threshold** — 既成建物（常に閾値 `0`）と異なり、外観バリアントの閾値選択（F §4）を行う。
  ただし MODEL_MASHUP は建物本体の壁パーツ（`mid-w1`）を持たないため、共通ルールの
  「mid-w1 で建物全体の閾値を確定する」方式ではなく、**サブ建物パーツごとに独立して**
  `variant_number` 以下で存在する最大の閾値フォルダを走査する。`common` へのフォールバックはしない。

## 3. サブ建物の積み上げ規則

1棟ごとに base / mid / top のパーツを下から積み上げる。

| パーツ | Yスケール | XZスケール | 用途 |
|---|---|---|---|
| mashup-\*-base-prebuilt | **なし（実寸）** | なし（実寸） | 1階部分 |
| mashup-\*-mid-prebuilt | **なし（実寸）** | なし（実寸） | 繰り返しフロア1階分 |
| mashup-\*-top-prebuilt | **なし（実寸）** | なし（実寸） | 頂部。完成済みモデル丸ごとでも可 |

- すべてのパーツはXYZいずれもスケールされず、著作実寸のまま描画される。既成建物（[F3_既成建物のメッシュ生成](F3_既成建物のメッシュ生成.md)）と異なり、**mid も階高へYスケールしない**。
- base と top は論理階数（エントリの `floors`）のうち各1階分を消費し、mid が残りを埋める（mid の枚数 = `floors − (baseあり?1) − (topあり?1)`）。
- **各パーツのY位置は著作高さの累積**で決まる（階高グリッドは使わない）。前段のパーツの実寸天端が次段の底面になるため、隙間・埋もれは生じない。各パーツはモデル原点（y=0）を段の接続点（下端）に合わせて積まれる。段を進めるのは存在するパーツだけなので、base/mid が無ければ top が接地する（体育館のような1棟完成モデルを top だけで表現できる）。
- 階高（`height_per_floor`）はパーツが1つも見つからない棟の白い箱（§7）の高さにだけ使う。
- 天面を塞ぐパネルは生成しない（上から見える面はモデル側で閉じる）。

## 4. 配置（位置・回転・接地）

- **位置** — 各パーツのモデル原点（XZ）を `position` へ平行移動する。回転を適用してから平行移動するため、パーツはサブ建物自身の原点を中心に回る。
- **回転** — `rotation` を壁パーツと同じ変換式（モデルのX軸を辺方向に向ける。[F_建物メッシュの生成](F_建物メッシュの生成.md) §6）でY軸回転として適用する。モデルのX方向（幅）が `rotation` の向きに沿い、壁の外面にあたる正面が接道側を向く。壁パーツと同じ座標系で著作したモデルをそのまま使える。
- **接地（Y）** — 建物 GameObject は center_point 位置の地形標高に置かれる（F §2.4）が、土地区画が広く斜面にまたがることがあるため、**各サブ建物は自分の `position` 位置の地形標高へ個別に接地する**（center_point 位置の地形標高との差分をY方向オフセットとして加える）。この標高合わせはLODセルの種類によらず常に行う。

---

## 5. 敷地装飾（フェンス・地面パネル）

モジュラー・既成建物と共通の処理（F §8.1・§9）で、土地区画のポリゴンに沿って描画する。

- **フェンス**（`fence-w*` / `fence-c*`）— 該当パーツがある場合のみ。
- **地面パネル**（`floor`）— マスターの `draw_floor=yes` の建物のみ。マテリアルは `a{variant}` → `b{bd_type}` → `common` のフォールバックで解決し、どこにも無ければ描画しない。
- **タイル**（`tile`）— 敷かない（MODEL_MODULAR_GROUND 専用の要素）。

建物中心位置の地形標高に接地するため、超近景（Dynamic）セルではフェンス・地面パネルが地形に追従する（F §9.4。MODEL_PREBUILT と同じ扱い）。

---

## 6. コライダー

**土地区画のポリゴン**を、描画された最も高いサブ建物の天端（最低でも1階分の高さ）まで押し出した形状を使用する。区画のどこをクリックしても建物を選択できるようにするためである。構成は F §13 に準じる。土地区画が取得できない場合は建物底面ポリゴンにフォールバックする。

---

## 7. フォールバック

- **あるサブ建物の3パーツがいずれも存在しない場合** — そのサブ建物は1セル分（8m×8m）×（floors × 階高）の白い箱で代替し、位置だけを示す。
- **`sub_buildings` が空で、フェンス・地面パネルのパーツも無い場合** — 建物底面ポリゴンの白い箱（`BuildingMeshBuilder.GenerateSimpleBuilding`）にフォールバックする。

---

## 8. 描画LOD

- **接写（Close）** — 同じ配置で、各パーツの `{パーツ名}_close` を優先して解決する（[F_建物メッシュの生成](F_建物メッシュの生成.md) §3.5）。
- **遠景（Far）** — 建物単位の遠景モデル `base/mid/top-prebuilt_far`（[F_建物メッシュの生成](F_建物メッシュの生成.md) §3.5）があればそれを使う。無ければ、各棟を `mashup-{model_prefix}-{base|mid|top}-prebuilt_far` で §3・§4 と同じ配置（位置・回転・棟ごとの接地・積み上げ）で組み立てる（`MashupBuildingMeshBuilder.GenerateFar`）。棟の配置は区画ごとに違うので、建物の中心に置く固定の遠景モデルでは配置を再現できないためである。
  - 遠景パーツは無印と同じ閾値フォルダに置く。閾値フォルダの選択（§2）と mid の枚数（§3）は無印のパーツの有無で決まり、各段は遠景パーツの天端で積み上がる。
  - 無印があるレベルの遠景パーツが1つでも欠けた棟は描かない。欠けた段を詰めて積むと通常と高さが食い違うためである。白い箱（§7）でも代替しない。
  - 敷地装飾（§5）とコライダー（§6）は作らない（遠景の建物はコライダーを持たない）。遠景は共有材質1色で描かれる。
  - 遠景パーツで描ける棟が1つも無い建物は、他の建物と同じく底面を階数×階高で押し出した箱になる。

`_close`・`_far` のパーツは無印と原点・水平範囲・天端を揃える（遠景の底面だけは上げてよい。[I_建物パーツ作成マニュアル](I_建物パーツ作成マニュアル.md) §9）。
