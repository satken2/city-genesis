# Unityの差分ロード

取得範囲、標高の確定、物体の描画品質を分離する。カメラ移動だけでは標高や都市データを変更しない。

## 更新の流れ

1. `CameraCellChecker` が位置・回転・投影条件の変化を通知し、`LodConfig` が常駐集合を計算する。
2. 集合の変更または編集後の再取得で `CellDataLoader` が `LoadBatch` を発行し、旧バッチをキャンセルする。カメラ由来の発行は0.25秒以上の間隔に合流させる(間隔内の通知は最後の1件だけを間隔の終わりに発行する)。編集後の再取得(`ReloadAllData`)は、発行の前に地形の版一覧・建物・区画へ「要再取得」を同期で記録する。
3. 地形APIの派生版を比較し、未取得／変更セルだけを取得・適用する。全景も編集の版が変わった場合に更新する。版一覧はカメラ由来のバッチでは5秒以内なら再利用する。タイルの取得はセル単位のジョブで、バッチの取消しでは止めず、後続のバッチが同じジョブを再利用する。常駐外になったタイルは非表示のままLRU(24枚)に保持し、再入場で版が同じなら取得せずに表示へ戻す。
4. `TerrainManager` は裏で完成したタイルだけを公開し、実際に更新したセル(LRUから復元したセルを含む)を通知する。
5. 既存道路・建物・プロップの地形追従を更新する。中断時の未処理セルは次のバッチへ引き継ぐ。
6. `ParcelManager` の区画取得完了を待って、新しい建物・道路・プロップ等の取得を始める。
7. 物体の描画LODは別のワーカーが判定する。生成済みの同じ形状がキャッシュにあれば再利用する。

地形イベントによる道路・建物の再生成はバッチ中に合流させ、セル枚数分の重複生成を避ける。依存側は下記「地形の版による再構築の省略」で、地形が実際に変わった対象だけを作り直す。すべての生成コルーチンは `RenderWorkScheduler.Start/Stop` を通す。Unityのコルーチン停止だけに資源解放を依存させない。

### 地形追従の中断と再開

`CellDataLoader.CollectDeferredTerrainNotifications` は、道路・建物マネージャーが抑制中に受けたタイル通知を、地形の全ロード完了通知と合わせて追従開始前に統合する。完了後に同じ通知を回収して二周目を起動しない。追従中の通知抑制は継続し、別の通知が残った場合は取りこぼさず後続処理へ渡す。

道路本線は1本ごとに生成要求の適用を記録し、交差点はノードごとに記録する。カメラ移動による取消しではこの記録を保持し、同じ道路版・状態で表現が残っていれば本線を再生成しない。交差点候補は省略した本線も含む全対象道路から回収するため、本線の後で中断しても未処理の交差点が消えない。各処理は1件ごとに共通生成予算へ戻る。記録は道路本体の生成・復元の適用を表し、`SplinePartLod` の非同期区間生成や表示完了は引き続き `PathPresentation` が管理する。

新しいタイルの到着時は、通知抑制中もセル逆引きで周囲3×3の道路とその端点ノードの記録を無効化する。道路の版・状態・端点変更や削除でも関連記録を無効化する。ノードデータ版が変わった場合は次の追従開始で全記録を破棄する。追従全体の完了、強制更新、セッション終了でも解放する。これにより、無関係なタイルの到着では処理済み道路を維持し、接地・接続情報が変わった対象は再処理する。

道路GOのルートには生成時の地形署名・version・status・工事進捗・描画revisionを記録した `PathBuildStamp` が付く。地形ロード完了後の一括追従と、タイル到着だけが理由の再生成キューの項目は、この記録が現在の地形・データと一致すれば作り直さない(`terrainFollow.pathTerrainUnchanged`)。LRU からタイルを復元しただけのセルで道路を作り直さないためである。省いた場合は描画revisionが進まないので、退避キャッシュに残る別LODの道路は古い地形で作られたままのことがある。そのため退避キャッシュから復元するときにも地形署名を比べ、違えば捨てて作り直す(`path.cachedTerrainStale`)。

タイルの到着・橋脚や送電線の隣接通知・近接線路・交差点の切断点の変化による道路の再生成は、通知の中で同期に一括再生成せず、`PathManager.EnqueueTerrainFollowPath` を通して1本のキューへ積む。常駐ワーカーが視野内かつカメラに近い道路から順に、再生成時点のティアとカメラ位置で描画LODを判定して作り直す(ロード範囲外へ出た道路は作らない)。1本の再生成が重く1フレームに数本しか進まないため、「カメラに映っている道路から地形に馴染ませる」この順序が体感品質を決める。並べ替えは列の末尾に達したとき・古い順序のまま10フレーム経ったとき・カメラが50m以上動いたか向きが20度以上変わったときだけ行う。LODバッチ中は、そのバッチで受信したパスと交差点由来の延期分を取り出さない。地形ロード完了後の一括追従も同じ視野優先の順で処理する。

区画はタイルが到着するたびに、そのセルに掛かる区画を待ち行列に積み、ワーカーが予算内で再追従する。再サンプルした高さと形状が枠線の保持値と同じなら(高さ5mm以内)、メッシュ・コライダー・枠線を作り直さない。建物も、記録した地形署名と一致すれば高さ補正も作り直しもしない。

常駐セルへの再入場だけでは道路の形状revisionを進めない。データ版・地形・交差点の変更は既存の強制再生成経路で扱い、変更のない再入場は現在GOまたはLODキャッシュを使う。`Tests/Lod/run.ps1` は実際の本線生成後の取消し・再開、交差点の残作業、再入場時の同一GO再利用、地形と道路版の変更による選択的無効化、二重通知の消化を検証する。

## 版と取得

| データ | 差分の基準 | 通信 |
| --- | --- | --- |
| 表示地形 | 編集セルと隣接依存を含む派生版 | `/terrain/cell-versions` → `/terrain/surface` |
| 全景地形 | 編集の版の変化 | `/terrain/far` |
| 建物 | `version`、描画キーに含む形状・敷地・地形版。カメラ由来のバッチは未ロード・要再取得・ティア変化のセルだけ | 取得セルを覆う矩形群(最大12個)ごとに `/buildings/?bbox=...&limit=500&cursor=0` |
| 道路 | `version` と接地・交差点・接続形状の再生成世代 | `/paths/?bbox=...&limit=500&cursor=0` |
| 区画 | `version`。未取得・要再取得セルの外接矩形を取得し、重心セルで絞り込む。上限到達で二分して取り直す | `/parcels/?bbox=...` |
| 地区 | `version`・全量 | 既存一覧 |
| プロップ | 配置署名と障害物署名 | 配置・障害物の同じスナップショット |

建物・道路の一覧には `next_cursor` がある。nullになるまで取得し、全ページ成功後に一覧から消えたIDを削除扱いにする。ページの失敗や後退したカーソルでは同期を確定しない。都市の状態が変更されたときは旧 `LoadBatch` をキャンセルして新しい一覧を取得する。

カメラ移動だけのバッチでは、建物は取得済みのロード済みセルを取り直さない。バックエンドの変化はエポック完了・編集確定の `ReloadAllData` が要求時に同期で呼ぶ `BuildingManager.MarkLoadedCellsStale` が「要再取得」として記録し、取得に成功して適用されたときにだけ記録を消す(途中でバッチが取消されても次のバッチで取り直す)。取得中に次の再取得要求が来たバッチは、受信データが要求前のものかもしれないので、取得したセルを要再取得に残す。取得セルは行ごとの連続区間から作った矩形群(最大12個。超えたら外接矩形1つ)に分けて要求し、矩形の境界で重複した建物はIDで除く。矩形からはみ出して届いた取得対象外セル(常駐外セルや取り直さないロード済みセル)の建物は生成しない。全消去は進行中の建物取得バッチを止める。

建物のセル離脱は、待ち行列へ積むだけで、分割ワーカー(`BuildingManager+<CellUnloadWorker>`)がフレーム予算内で建物GOを退避キャッシュへ移す。再入場時はキーで復元し、メッシュを作り直さない。アンロード途中で再入場したセルは退避を中断する。道路・ノード・交差点メッシュも同様に、分割ワーカー(`PathManager+<PathUnloadWorker>`)がフレーム予算内で1セルずつ非表示にする。隠す直前に、その道路が常駐セルに跨っていないかを確かめ直す。

区画も同じく、新規に常駐へ入ったセルと要再取得セル(`ParcelManager.MarkLoadedCellsStale`)だけを取得する。常駐外に出た区画は非表示のまま保持し、保持セル数が81を超えたら古いセルの区画から破棄する。地区は全量の版差分で、エポック完了・編集確定で明示的に取り直す。

地形の `/surface` はfloat32 LEの正方格子で、`X-Grid-Rows/Cols` と `X-Cell-Version` を返す。版は表示タイルの公開と同じステップで記録する。

## 地形の版による再構築の省略

地形タイルは LRU からの復元や、版の変わらない再アタッチでも `OnTerrainTileReady` を発火する(復元も「更新セル」に含まれる)。依存側がこの通知だけで作り直すと、カメラを往復させるたびに建物・道路・区画を作り直すことになるので、地形の版を記録して比べる。

- `TerrainManager.GetAttachedTerrainVersion(cell)` は表示中タイルの版(`/terrain/cell-versions` の版。一覧に無いセルは0)。タイルが無い・常駐外・非表示のときは -1。
- `TerrainManager.GetTerrainSignature(範囲またはセル集合)` は、範囲内の各セルの版・全景データの版・全消去の世代(`TerrainEpoch`=clearEpoch)を混ぜた署名。同じ版・同じ全景・同じ世代なら再入場後も同じ値になる。`GetSurfaceStamp` は同じ内容の文字列版で、建物の再利用キーに使う。
- 依存側は生成時(建物は生成・復元・再利用の時点、道路は `PathBuildStamp`、交差点は入力署名、プロップは小区画の stamp、区画は枠線の保持高さ)に記録し、`OnTerrainTileReady` や地形追従で現在値と比べて一致すれば作り直さない。
- `TerrainManager` が無いなど版が不明なときは、省略せずに作り直す。

## セッション切り替え

地形の候補、常駐タイル、全景、描画キャッシュ、空間ハッシュ、進行中ロードを破棄する。`HeightmapTextureManager.Invalidate` はGPU移動窓を無効化する。前の都市の標高・候補・接続点を新しい都市で再利用しない。

全景地形は標高の受信済み版とメッシュの完成済み版を別に保持し、セッション切り替えで両方を未設定へ戻す。新しい都市も版0など同じ番号から始まるため、前の都市の完成版を残してはいけない。標高受信後にカメラ移動で生成を中断した場合は、次のバッチで受信済みデータからメッシュを再生成する。完成前に生成済み扱いにせず、旧セッションで始めた非同期処理の結果も公開しない。生成失敗は再試行し、生成結果が空の場合も正常な完成状態として確定する。

`Tests/Lod/run.ps1` は、同じ版番号の別マップへの切り替え、生成途中の取消しと再開、新しいマップ寸法の反映、空メッシュへの更新、セッション消去後の旧結果破棄を実メッシュ生成で検証する。

`session:reset` はUIが新しいセッションの作成要求を出す直前に送るため、`session:reload` が届くまでカメラ由来のロードを止める（準備中のバックエンドから中途半端なタイルを取り込むと、同じ版のタイルが差分リロードで更新されず残る）。`session:reload` で解除し、`CameraCellChecker` の視点検出を未初期化へ戻す。現在セルが未設定に戻った後はカメラが静止していても次の判定で必ずセル通知が走り、カメラを動かさなくても新しい都市のロードが始まる。

## プロップの差分同期

配置の署名には散布／手置きのID・version(GPU森林は予算から決まる実効本数も)、除外の署名には障害物のkey/signatureを使う。1区画あたりの候補予算は署名に含めない。常駐する小区画数が変わって予算が減ったら既存の点列の先頭を切り詰め、増えたときは1.25倍以上になったときだけ作り直す。散布プレビューが要求されていない間は、先に `/props?bbox=…&limit=1` でプロップの有無を確かめ、無ければ障害物(全区画・道路のポリゴン)を取得しない。障害物だけが変わったときは散布し直さず、同じ候補の表示可否だけを更新する。地形変更では対象セルのYだけを更新する。旧描画バッチは新しいバッチの完成まで保持する。

範囲・予算の詳細は[E_LOD処理](E_LOD処理.md)、配置と除外の規則は[M_地形プロップ](M_地形プロップ.md)を参照。

## 取得と描画完了の区別

建物の遅延生成は、対象セルがロード完了集合へ登録されるまで要求を保持する。未登録セルの要求を選出してから削除してはいけない。一括取得中も生成ワーカーが動くため、背面の建物だけ永久に生成待ちから消える競合になる。次の取得範囲から外れた要求は新しいロード開始時と、ロード結果を適用して登録集合が確定した時点で除く。取得矩形からはみ出して届いた取得対象外セルの建物は、生成も遅延キューへの投入もしない。

道路の `pathVersionCache` は受信版ではなく、生成・復元が完了した版を記録する。API取得や高優先度キューへの投入時には更新しない。同じ版でも描画オブジェクトが存在しない道路は再生成対象とする（意図的な遠景トンネル非表示は除く）。これにより建設計画の更新中にロードが中断されても、次の差分取得で生成できる。道路バッチの終了処理はfinallyで実行し、中断・例外時に地形追従を永久待機させない。

回帰検証は `Tests/Lod/run.ps1`。未ロードセルの建物キュー保持(完了判定を塞がないこと)・適用時の常駐外セル要求の除去と、建設計画中の道路のHTTP取得→生成前中断→同版再取得を検証する。


## ロード遅延の計測

### カメラ移動時の再取得・再生成件数

`UNITY_LOG_TIMING` が有効なら、既存の5秒ごとの `[TIMING] Scheduler` に `count/名前=件数` を追記する。物体ごとのログは出さず、各窓の報告後に件数をゼロへ戻す。無効時は件数を蓄積しない。

| 名前 | 意味 |
| --- | --- |
| `camera.sameCells` / `camera.loadBatches` / `camera.changedCells` | 同一常駐集合で省略した通知数／更新バッチ数／変更セルの延べ数。バッチには明示リロードも含む |
| `building.fetchExistingCells` / `path.fetchExistingCells` | 再取得要求へ含めたロード済みセル数(建物は要再取得・ティア変化のセルだけ)。`fetchNewCells` は未ロード分。取得矩形の範囲やHTTP要求数ではない |
| `building.fetchSkippedCells` | 取得しなかった常駐セル(ロード済みで要再取得でもティア変化でもないセル)の数 |
| `building.outsideFetchSkipped` | 受信したが取得対象外セルにあるため生成しなかった建物の数 |
| `building.received` / `path.received` | ページ受信件数。途中キャンセル・再試行の受信分も含む。建物は全矩形の合計で、矩形境界の重複を除く前の値 |
| `building.dataUnchanged` / `path.dataUnchanged` | 一覧の適用時に再生成不要と判定した件数 |
| `building.lodScanned` / `path.lodScanned` / `roadSegment.lodScanned` | LOD走査へ渡した候補の延べ数。建物はロード済みセルの建物の延べ数、道路本体は生成済みの全道路で、非表示等の早期除外候補も含む |
| `building.deferredLodChanged` | 建物の遅延要求と生成直前の判定が異なった件数 |
| `building.buildRequested` / `path.buildRequested` / `roadSegment.buildRequested` | 生成要求がキャッシュで解決できなかった件数。成功数ではない |
| `building.generated` / `path.generated` | 既存のメッシュ生成時間計測へ報告された件数。道路の遅延区間は別の `roadSegment` 件数で読む |
| `building.reuseActive` / `path.reuseActive` | 現在の管理オブジェクトをそのまま利用した件数（非表示からの復帰を含む） |
| `building.reuseCached` / `path.reuseCached` / `roadSegment.reuseCached` | 退避キャッシュから復元した件数 |
| `path.cachedTerrainStale` | 退避キャッシュの道路が現在の地形署名と合わず、復元せずに破棄した件数 |
| `path.forceRebuildRequested` / `path.lodRebuildRequested` | 道路の強制形状更新／通常LOD切り替えの要求数。重複除外前の値 |
| `path.terrainRebuildRequested` | 強制更新要求のうち地形追従由来の件数 |
| `terrainFollow.interrupted` / `terrainFollow.requestedCells` | 更新バッチへの置換で中断した追従処理数／追従対象セルの延べ数 |
| `terrainFollow.pathCompleted` / `terrainFollow.nodeCompleted` | 道路本線の生成要求適用／交差点処理を完了記録へ追加した件数。非同期の区間表示完了数ではない |
| `terrainFollow.pathResumeSkipped` / `terrainFollow.nodeResumeSkipped` | 中断再開時などに、処理済み記録によって再生成を省略した件数 |
| `terrainFollow.pathInvalidated` | 新しいタイル・道路データ等で個別の道路完了記録を無効化した件数。全体クリアは含まない |
| `renderCache.localEvicted` / `renderCache.globalEvicted` | 個別／全体メモリ上限で破棄した退避オブジェクト数。建物のセル離脱による退避の追い出しもここに出る |
| `terrainFollow.pathTerrainUnchanged` | 地形の記録(`PathBuildStamp`)が現在と一致したため、地形追従の再生成を省いた道路の数 |
| `path.queueRebuildSkipped` | 再生成キューの項目のうち、投入後に最新データで生成済みだったもの、または橋脚通知だけで遠景・GO無しのため省いたもの |
| `intersection.inputUnchanged` | 入力署名が前回と一致したため再計算を省いた交差点の数 |
| `terrain.tileDownload` / `terrain.tileDownloadAborted` / `terrain.tileJobReused` | 地形タイルの取得開始数／常駐外・全消去による取得の中断数／実行中のジョブを後続バッチが再利用した数 |
| `terrain.tileCacheHit` / `terrain.tileCacheEvicted` | 常駐外タイルの LRU から取得せずに復元した数／容量超過で破棄した数 |
| `terrain.cellVersionsFetched` / `terrain.cellVersionsReused` | 地形の版一覧を取得した回数／キャッシュを再利用した回数 |
| `camera.batchDeferred` | カメラ由来のバッチ発行を0.25秒の合流間隔のために保留した回数 |
| `api.bulkCanceled` | 呼び出し側の取消しで中断した一括取得の数 |

追従処理の中断時は、新しい `LoadBatch#` に `FOLLOWUP_RESTART pendingCells=...` も出す。セル数は未完了の追従全体の候補数であり、同じ値でも `pathResumeSkipped` が増えていれば処理済み本線の再生成を省略している。中断回数だけでなく、完了・無効化・省略と `path.terrainRebuildRequested` を比較する。

静止・回転だけ・平行移動・セル境界の往復をそれぞれ5秒以上記録する。`fetchExistingCells` と `dataUnchanged` が多ければ取得範囲の差分化、`terrainFollow.interrupted` と地形由来の強制更新が多ければ中断後の継続単位、退避破棄とキャッシュミスが多ければ保持容量を検討する。CPU時間・最大step・F8のp95/p99も合わせて判断する。建物・区画のカメラ由来の取得は未ロード・要再取得のセルに限っており、編集・エポック実行後の差分更新は「要再取得」の記録(取消しを跨いで保持)で区別している。

### 工程時間

`LocalConstants.UNITY_LOG_TIMING` を有効にすると、Unity ConsoleとEditor.log（Windowsでは `%LOCALAPPDATA%/Unity/Editor/Editor.log`）、製品実行時はPlayer.logに計測を出す。建物パーツの大量ログは計測へ影響するため `UNITY_LOG_BUILDING` を無効にする。

- `LoadBatch#` は同じ更新要求の経過時間を追う。START→TERRAIN_DONEが地形取得・適用、TERRAIN_DONE→FOLLOWUP_DONEが既存物の地形追従、PARCEL_START→PARCEL_DONEが区画待ちである。OBJECTS_STARTは建物・道路の取得開始であり、表示完了ではない。SUPERSEDED/RESETは後続要求への置換またはセッション終了で、表示失敗を意味しない。
- `ApiClient network/` と `deserialize/` は通信・デコードの完了をコルーチンが観測するまでの経過時間。スケジューラーの再開待ちも含むため、サーバーCPU時間とは区別する。
- `Scheduler` は5秒ごとにiterator型別(集約キーは iterator の Type、表示は FullName。例: `BuildingManager+<CellUnloadWorker>`、`VehicleManager+<ScanRoads>`)の同期実行時間 `cpu`、最重ステップ `maxStep`、実行回数 `steps` を集約する。`queueFrames` は実行可能な処理が予算制限により次フレームへ残った回数、`underBudgetQueueFrames` は同期実処理の合計が予算未満でもポンプ全体の時間制限で残った回数。複数ワーカーの合計なので、実フレーム数や壁時計時間への単純換算はできない。cpuが小さく後者が多ければ、待機確認・iterator切替など管理処理の負荷を確認する。maxStepが大きければ当該iteratorの分割不能な同期処理を調べる。
- `buildingsPending` と `pathsPending` は建物詳細・道路地形追従/LOD更新キューの残件数。道路一括生成は別経路なので `pathBatch` とPathManagerの工程ログも合わせて読む。キューが0でも画面内の全オブジェクト表示完了を保証しない。

起動時は視点を固定してログを採り、表示後に回転だけ、次にセルを跨ぐ移動を行う。それぞれのバッチ・待ち数・cpuを比較すると、地形待ち、再取得、描画LOD生成を区別できる。共通予算は目標60FPSなら約4.17ms/フレーム。各ワーカーは最大0.5msまたは1件の処理境界で `Continue` を返して順番を譲り、予算が残れば同じフレームで再開する。明示的なnullは次フレーム待ちのままなので、アイドルや通信完了のポーリングを空回ししない。


## フレーム予算による生成の進行

区画・道路・建物・地形の生成中断は、次フレーム待ちとは区別する。RenderWorkSchedulerの共通ポンプは、初回の起動時に自動生成される常駐GameObject `RenderWorkPump` の `LateUpdate` から1フレームに1回動き、実行可能なiteratorを待ち行列の先頭から1ステップ進めて末尾へ戻す。通信完了待ちや次フレーム待ちは飛ばし、後続の生成を止めない。1つのUnityコルーチンが先頭待ちでフレームを跨ぐ方式にはしない。

同期処理の合計と、待機確認・iteratorの切り替えを含むポンプ全体の経過時間の両方を共通予算で制限する。1件のメッシュ生成やUnity API呼出しの途中では中断できないため、重い1ステップによる予算超過は残り得る。その場合は残りの仕事を次フレームへ送り、maxStepの計測で生成器の分割対象を特定する。

区画はデータが不変でも1件ずつ必ず1フレーム待つ方式を使わず、予算内で差分を適用する。全件の区画適用完了後に建物などを開始する依存順序、地形の完成後差し替え、キャンセル時の未完成データ破棄は保つ。待機中のネストしたiteratorやメッシュもStart/Stopの対で解放する。


## 道路の非同期生成と表示の差し替え

長い道路のSplinePartLodは本体GameObjectの作成後に固定区間を生成するため、本体の作成を表示完了とみなさない。PathPresentation.Replaceで旧道路を保持し、新しい道路の各パーツが初回LODを確定した時点で一括表示する。生成途中の新しいRendererはforceRenderingOffで伏せ、旧道路との重複描画を防ぐ。既存のforceRenderingOff値は復元する。

再生成が連続した場合は未完成の候補から表示中の旧道路を引き継ぎ、未完成の候補だけを退避する。完成時に旧道路をキャッシュへ退避し、アンロード・全消去では保持中の旧道路を非表示にして破棄する。キャッシュからの復元と遠景への切替も同じ入口を通す。建物の主メッシュは同期生成なので、この道路パーツ専用の待ち合わせには含めない。回帰検証はTests/Lod/run.ps1のRoadPresentation。


## 森林GPUの差分更新

範囲配置の木（種類1/2）はPropManagerのスナップショット適用で小区画ごとのForestRenderer.Patchを作る。配置・障害物の署名が同じ場合はGPUバッファを再利用する。DrawWorkerが所属する完成Terrainを解決し、ForestPlacement.computeで散布・除外・高さを計算する。CPU候補がない区画ではカメラ移動によるRebuildBatchesを省く。地形完成通知と編集追従は該当区画をdirtyにし、再生成を予約する。ClearAllCells・区画置換・アンロードはGPUバッファを解放する。F8の森林GPU候補数は割当格子数であり、道路除外後の可視本数や描画三角形数ではない。

## 初期画面の準備完了

`GameStateManager.IsGameStarted()` はデータ取得の許可、`IsWorldVisible` はユーザーへの表示許可として分離する。`LoadingOverlay` は後者まで黒を維持し、`CameraController` と `InputUtil` は表示前の操作を抑制する。ロード中もLOD判定に必要な `Camera.main` を利用できるよう、カメラを有効に保つ。

`CellDataLoader.IsInitialSceneReady` は初回地形処理だけでなく、後続の区画・建物・道路・地区・資源・プロップ、敷地装飾・道路区間・コライダーの描画準備を待つ。カメラ由来のバッチを間引きで保留している間も未完了として扱い、最終視点のバッチを発行する前に準備完了と判定しないようにしている。`RenderWorkScheduler.Start` の任意 `hasPendingWork` は常駐ワーカーの未処理判定で、省略した有限コルーチンは通信待ちを含めて全期間待機対象になる。常駐ワーカーを追加するときは、無限ループ自身を完了条件にしないようこの判定を指定する。一定間隔で起動し直す有限コルーチン(車両・歩行者の道路走査や事前生成など)も常駐扱いで `() => false` を渡す。省略すると走査のたびに `IsInitialSceneReady` が数フレーム偽へ落ち、初期描画の完了判定が明滅する。建物の上限により意図的に保留している視野外の詳細と、元の表示を維持する遠景結合処理は待ち続けない。常駐ワーカーの未処理判定は、ワーカーが今選出できる仕事だけを数える。建物の遅延キューでは未登録セルの要求を判定から外す(取得中のセルは一括取得のコルーチン自体が待機対象になる)。選出できない要求を数えると `game:loaded` が永久に送られず、UIの開始ボタンが出ないまま初期ロードが終わらない。

保存カメラの復元と生成完了を連続3フレーム確認して `game:loaded` を送る。初期ロードとは初期視点の常駐セルと全景の描画準備であり、都市全域の詳細モデルを常駐させる意味ではない。開始後のカメラ移動には通常のLODストリーミングを使う。
