# 天気と環境光

## 責務

天気はUnityだけで管理する描画上の演出である。空、雲、日光、影、遠景の霞、空の反射を変える。生産・消費・交通・災害など経済シミュレーションには影響せず、バックエンドやマスター、都市のセーブデータに天気を記録しない。

`AppRoot` が `WeatherController` を1個生成する。天気の正は `Assets/Scripts/Weather/WeatherPreset.cs` の11個のプリセットである。夕焼けは光の演出を表し、都市の日付やエポック内の時刻とは対応しない。

## プリセットと抽選ウェイト

| ID | 名前 | 確率 | 見た目 |
| --- | --- | --- | --- |
| clear | 快晴 | 32% | 深い青空と明瞭な影 |
| high_clouds | 薄雲 | 15% | 透ける薄雲と明るい日差し |
| fair | 晴れ | 12% | 青空と積雲 |
| broken_clouds | 晴れ間 | 6% | 雲の間からの日差し |
| overcast | 曇り | 10% | 灰色の雲と柔らかい拡散光 |
| rain_clouds | 雨雲 | 5% | 厚い暗雲。降水はしない |
| fog | 霧 | 2% | 日中の白い霧。暖色の朝焼けにはしない |
| sunset | 夕焼け | 3% | 西の低い暖色光と長い影 |
| drizzle | 霧雨 | 7% | 細く少ない雨粒と強めの霞 |
| rain | 雨 | 7% | 中程度の雨粒と曇り空 |
| heavy_rain | 大雨 | 1% | 密な雨粒、暗い空、濃い霞 |

晴れ系の合計は65%、曇り系15%、雨系15%、霧2%、夕焼け3%。`Weight`は相対値で、合計によって正規化される。表の確率は合計100の現在値に対応する。初期天気とエポック抽選は同じウェイトを使う。重みを変更するときはこの表も更新する。

濡れた路面、積雪、雷の発光、夜間照明は含まない。雨の音源には録音に含まれる遠雷や遠方の交通音がある。

## エポックとの連動

起動時に11種類からウェイトに従って1つ選ぶ。以後は既存の `session:reload` / `session:force_reload` を受けて `ApiClient.Get` で `GET /api/v1/city/` の `city.epoch` を読む。天候表示と手動選択は下記の専用IPCで連携する。

- 初回取得はエポック番号の基準値を設定するだけで、再抽選しない。
- 番号が増えた場合、進んだエポック数だけ抽選する。一括実行では最後の結果だけを表示する。
- 各エポックは独立した重み付き抽選で、同じ天気の連続を許す。直前の天気を除外すると快晴など高ウェイトの実際の出現率が下がるため、除外しない。
- 建設・編集後のリロード、重複通知、強制リロードで番号が変わらなければ天気を維持する。
- `session:reset` / `game:end` で取得を中止し、基準値を破棄する。`game:start` で取得を再開する。IPCより後からUnityが起動した場合は `GameStateManager` の開始状態も利用する。
- 通信失敗時は表示を維持し、5秒後に再試行する。取得を同時実行せず、取得中の通知は次回要求にまとめる。
- 古いエポックのセーブを読んだときは基準値を置き換える。天気自体は保存しないため、アプリ再起動後の同じセーブで同じ空になる保証はない。

抽選には専用の `System.Random` を使い、Unity全体の乱数状態を変更しない。天気は通常3秒かけて色・照明方向・霧を補間する。雲の配置と雲影のテクスチャは選択時に切り替わるため、その部分は連続した気象変化ではない。エポック間で雲を時間アニメーションさせず、撮影の構図を安定させる。

## 撮影用の操作

Cockpitの日付の横に絵文字と天候名を表示する。`useHudSession.templateMode`がONのときは標準HTML selectで選択でき、選んだ天候に固定する。自動を選ぶかテンプレートモードをOFFにすると固定を解除し、次のエポックから自動抽選する。天気を変更するHTTP書き込みはない。

Cockpitは幅800px・高さ76pxの独立したWebViewウィンドウである。CSSの絶対配置で候補を外にはみ出させるとウィンドウ境界で切れるため、WebView2の標準選択ポップアップを使う。画面下端では上側の空き領域へ展開され、候補が収まらなければスクロールできる。キーボードで選択・確定・Escで取消しもできる。

`weather:query`（UI→Unity）は現在値の問い合わせ、`weather:set`（UI→Unity）は`{id: string | null}`の選択。nullは固定解除。Unityは選択・固定切替・抽選後および問い合わせ時に`weather:state`（Unity→UI）を返す。応答は`{id, locked, rain, presets:[{id, weight, rain}]}`で、rainは0〜3。IDと候補一覧の正はUnity、表示名と絵文字はTauriにある。未知のIDでは変更せず現在値を返す。Cockpitは購読完了後に問い合わせ、10秒周期の再問い合わせで通知の取りこぼしやUnity再起動から復帰する。UIは応答を受けて表示と雨音を更新する。

3Dビューにキーボードフォーカスがある状態で操作する。Unity EditorではGameビューを選択する。

| 操作 | 動作 |
| --- | --- |
| F9 | 天気パネルを開閉 |
| パネル表示中の F6 / F7 | 前後の天気へ即時変更し、その天気を固定 |
| パネル表示中の F10 | 固定と自動の切り替え |
| パネル表示中の F11 | 再抽選して自動モードに戻る |

固定中もエポック番号は更新し、解除後に過去のエポックを遡って抽選しない。固定設定はUnity起動中のみ保持する。撮影前にF9でパネルを閉じると、天気を維持したまま表示を消せる。TauriのウィンドウやほかのHUDを隠す機能はこのパネルには含まない。まず「晴れ」「夕焼け」で建物に斜光が当たる向きを探し、白い壁や屋根のハイライト、影の中の視認性を実際の都市で確認する。

## レンダリング

`Assets/Resources/Weather/Atmosphere.shader` はURP用のプロシージャルなSkyboxである。Resources経由でロードするため、実行ファイルにシェーダーを含められる。上空と地平線の色、太陽円盤と周囲の散乱光、多重ノイズによる雲、雲の濃淡・透過を1パスで描く。ボリュームをレイマーチする雲ではなく、空の球面上に雲の見た目を近似する方式である。

シーンの `RenderSettings.sun`、または有効なDirectional Lightのうち最も強いものを太陽として使う。追加の太陽を重ねない。方向・色・強度・影の濃さを変え、既存のURPのソフトシャドウ設定を使う。PC用RPAssetの影距離・解像度・カスケード設定はそのまま利用するため、遠景の建物の影が表示される距離は元の描画設定に従う。

地上の雲影には128×128の周期的なグレースケールCookieを使用し、URPの `UniversalAdditionalLightData.lightCookieSize` で投影サイズを指定する。空の雲と同じ被覆率・厚さを使うが、雲形状と地上の影を物理的に1対1で対応させるものではない。[UnityのLight設定](https://docs.unity3d.com/ja/current/Manual/urp/light-component.html)も参照。

環境光は上空と地平線の色から球面調和関数(SH)を作り、`AmbientMode.Custom` と `RenderSettings.ambientProbe` で設定する。霞はLinear Fogで制御する。Fog非対応の独自シェーダーやUnlitの表示は、そのマテリアル自身の実装に従う。64pxのRealtime Reflection Probeは空だけを描き、天気の遷移完了時に分割更新する。都市のメッシュを反射用に再描画しない。ローカルな既存プローブを優先できるよう、天気プローブのimportanceは低くする。

通常フレームで都市オブジェクトを全走査しない。空の描画以外はイベント時・遷移中の設定更新が中心で、雲影テクスチャは選択時だけ生成する。コンポーネントを無効化すると元の空・光・霧を復元し、破棄時には動的マテリアル・テクスチャ・プローブを解放する。

## 降雨と環境音

`WeatherRain`はメインカメラ近傍60m四方に限って雨粒を出す。霧雨160粒/秒、雨750粒/秒、大雨1800粒/秒で最大6000粒。`RainStreak.shader`で輪郭をぼかしたストリークを描き、都市の大きさに比例した生成や物理衝突は行わない。カメラの大移動時は残留粒子を消す。ゲーム終了時・コンポーネント無効化時は停止する。雲は静止しているが雨粒は描画上の時間で動く。

音はTauriのCockpitが所有する`WeatherAudio`で1組だけ再生する。プレイ中はベース環境音を常時ループし、地表へ近づくほど近景音を混ぜる。rain=1/2/3のときは対応する雨音を重ねる。切替は約1.5秒以内のゲイン変化で行う。音量はマスター×効果音の設定に従い、ミュートは即時反映する。セッションがなくCockpitを非表示にすると停止し、破棄後に非同期の再生が完了しても再開しない。長い音源をWeb AudioのPCMバッファに一括展開せず、HTMLAudioElementでストリーミングする。

音源は`tauri/src/assets/sounds/weather/*.opus`。FFmpegでOpus 64kbps(モノラル原本の大雨のみ40kbps)へ圧縮し、先頭末尾2秒の等電力クロスフェードと-24 LUFSへの音量調整を施す。5音源の変換物は合計4,983,929 bytes。原本はDownloadsに残し、リポジトリには入れない。再生成は`tauri/tools/prepare_weather_audio.py`、出所と加工記録は音源フォルダのREADMEと`credits.ts`を参照する。

全体の再生構成・高度ミックス・調整箇所は[サウンドシステム](../programs/サウンドシステム.md)を参照。

## 検証

Tauri側は`node tools/check_weather_audio.mjs`で音量・雨音切替・設定の非同期競合・セッション終了時の停止・解放を確認する。型検査は`npx tsc --noEmit -p tsconfig.json`、配布アセットの生成は`npx vite build`。実際のWebView2での音量バランスと画面下端のselect操作は本編で確認する。

`unity/Tests/Weather/run-unity.ps1` は本編のC#をビルドし、`Temp/WeatherUnityQA` の独立したUnityプロジェクトで検証を開始する。本編シーンや実行中の都市は変更しない。完了時の `result.txt` と `qa.log` を確認する。

初回・重複・一括エポック、固定、セッション変更、無効化時の環境復元、抽選範囲を確認し、簡易建物を置いた同一視点で11種類を `Captures/00.png`〜`10.png` に出力する。これは描画の比較用であり、Steam掲載用の実都市スクリーンショットではない。GPU負荷や実都市のマテリアルとの調和は本編のGameビューで別途確認する。
