# 天気と環境光

## 責務

天気はUnityだけで管理する描画上の演出である。空、雲、日光、影、遠景の霞、空の反射を変える。生産・消費・交通・災害など経済シミュレーションには影響せず、バックエンドやマスター、都市のセーブデータに天気を記録しない。

`AppRoot` が `WeatherController` を1個生成する。天気の正は `Assets/Scripts/Weather/WeatherPreset.cs` の10個のプリセットである。朝・夕の名前は光の演出を表し、都市の日付やエポック内の時刻とは対応しない。

## プリセット

| 番号 | 名前 | 見た目 |
| --- | --- | --- |
| 1 | 快晴 | 深い青空、少ない雲、明瞭な建物の影 |
| 2 | 薄雲 | 淡い青空、透ける薄雲、少し柔らかな日差し |
| 3 | 積雲 | 明るい雲の縁と陰影、強めの日差し |
| 4 | 晴れ間 | 多めの雲と斜めの日差し、地上の雲影 |
| 5 | 曇天 | 青灰色の空、弱い直射光、明るい拡散光 |
| 6 | 雨雲 | 厚く暗い雲、青みを帯びた光、強めの霞 |
| 7 | 朝霧 | 低い暖色の光、白い霞、遠景の低いコントラスト |
| 8 | 朝焼け | 東側の低い日光、桃色の地平線、長い影 |
| 9 | 夕陽 | 西側の金色の日光、暖かい雲、長い影 |
| 10 | 夕焼け | 橙色の低い日光、紫色の上空、赤みのある雲 |

雨雲は空模様を表す。雨粒、濡れた路面、積雪、雷、夜間照明は実装していない。

## エポックとの連動

起動時に10種類から均等に1つ選ぶ。以後は既存の `session:reload` / `session:force_reload` を受けて `ApiClient.Get` で `GET /api/v1/city/` の `city.epoch` を読む。追加のIPCイベントは不要である。

- 初回取得はエポック番号の基準値を設定するだけで、再抽選しない。
- 番号が増えた場合、進んだエポック数だけ抽選する。一括実行では最後の結果だけを表示する。
- 各抽選では直前の天気を除いた9種類から均等に選び、1エポック進めたときの変化を保証する。一括実行の最終結果は実行前と同じになる場合がある。
- 建設・編集後のリロード、重複通知、強制リロードで番号が変わらなければ天気を維持する。
- `session:reset` / `game:end` で取得を中止し、基準値を破棄する。`game:start` で取得を再開する。IPCより後からUnityが起動した場合は `GameStateManager` の開始状態も利用する。
- 通信失敗時は表示を維持し、5秒後に再試行する。取得を同時実行せず、取得中の通知は次回要求にまとめる。
- 古いエポックのセーブを読んだときは基準値を置き換える。天気自体は保存しないため、アプリ再起動後の同じセーブで同じ空になる保証はない。

抽選には専用の `System.Random` を使い、Unity全体の乱数状態を変更しない。天気は通常3秒かけて色・照明方向・霧を補間する。雲の配置と雲影のテクスチャは選択時に切り替わるため、その部分は連続した気象変化ではない。エポック間で雲を時間アニメーションさせず、撮影の構図を安定させる。

## 撮影用の操作

3Dビューにキーボードフォーカスがある状態で操作する。Unity EditorではGameビューを選択する。

| 操作 | 動作 |
| --- | --- |
| F9 | 天気パネルを開閉 |
| パネル表示中の F6 / F7 | 前後の天気へ即時変更し、その天気を固定 |
| パネル表示中の F10 | 固定と自動の切り替え |
| パネル表示中の F11 | 再抽選して自動モードに戻る |

固定中もエポック番号は更新し、解除後に過去のエポックを遡って抽選しない。固定設定はUnity起動中のみ保持する。撮影前にF9でパネルを閉じると、天気を維持したまま表示を消せる。TauriのウィンドウやほかのHUDを隠す機能はこのパネルには含まない。まず「積雲」「夕陽」で建物に斜光が当たる向きを探し、白い壁や屋根のハイライト、影の中の視認性を実際の都市で確認する。

## レンダリング

`Assets/Resources/Weather/Atmosphere.shader` はURP用のプロシージャルなSkyboxである。Resources経由でロードするため、実行ファイルにシェーダーを含められる。上空と地平線の色、太陽円盤と周囲の散乱光、多重ノイズによる雲、雲の濃淡・透過を1パスで描く。ボリュームをレイマーチする雲ではなく、空の球面上に雲の見た目を近似する方式である。

シーンの `RenderSettings.sun`、または有効なDirectional Lightのうち最も強いものを太陽として使う。追加の太陽を重ねない。方向・色・強度・影の濃さを変え、既存のURPのソフトシャドウ設定を使う。PC用RPAssetの影距離・解像度・カスケード設定はそのまま利用するため、遠景の建物の影が表示される距離は元の描画設定に従う。

地上の雲影には128×128の周期的なグレースケールCookieを使用し、URPの `UniversalAdditionalLightData.lightCookieSize` で投影サイズを指定する。空の雲と同じ被覆率・厚さを使うが、雲形状と地上の影を物理的に1対1で対応させるものではない。[UnityのLight設定](https://docs.unity3d.com/ja/current/Manual/urp/light-component.html)も参照。

環境光は上空と地平線の色から球面調和関数(SH)を作り、`AmbientMode.Custom` と `RenderSettings.ambientProbe` で設定する。霞はLinear Fogで制御する。Fog非対応の独自シェーダーやUnlitの表示は、そのマテリアル自身の実装に従う。64pxのRealtime Reflection Probeは空だけを描き、天気の遷移完了時に分割更新する。都市のメッシュを反射用に再描画しない。ローカルな既存プローブを優先できるよう、天気プローブのimportanceは低くする。

通常フレームで都市オブジェクトを全走査しない。空の描画以外はイベント時・遷移中の設定更新が中心で、雲影テクスチャは選択時だけ生成する。コンポーネントを無効化すると元の空・光・霧を復元し、破棄時には動的マテリアル・テクスチャ・プローブを解放する。

## 検証

`unity/Tests/Weather/run-unity.ps1` は本編のC#をビルドし、`Temp/WeatherUnityQA` の独立したUnityプロジェクトで検証を開始する。本編シーンや実行中の都市は変更しない。完了時の `result.txt` と `qa.log` を確認する。

初回・重複・一括エポック、固定、セッション変更、無効化時の環境復元、抽選範囲を確認し、簡易建物を置いた同一視点で10種類を `Captures/00.png`〜`09.png` に出力する。これは描画の比較用であり、Steam掲載用の実都市スクリーンショットではない。GPU負荷や実都市のマテリアルとの調和は本編のGameビューで別途確認する。
