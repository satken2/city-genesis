# 天気と環境光

## 責務

天気・時刻・気候の3つから、Unityの空・雲・日光・影・遠景の霞・空の反射・降水を決める描画上の演出である。生産・消費・交通・災害など経済シミュレーションには影響しない。天気と時刻はバックエンド・マスター・都市のセーブデータに記録しない。気候区分だけは都市（シナリオ）の属性としてバックエンドが保存し、`GET /api/v1/city` の `climate` で読む。

`AppRoot` が `WeatherController` を1個生成する。

| 概念 | 決まり方 | 正 |
| --- | --- | --- |
| 気候 | 都市ごとに固定（シナリオの地形エディタで選ぶ）。季節ごとの天気の出現割合を決める | 区分は都市の `climate`（[地形形状 §D.16](D_地形形状.md#d16-気候区分climate)）、出現割合の表は `Assets/Scripts/Weather/WeatherClimate.cs` |
| 天気 | エポックと無関係に、隣り合う天気へゆっくり移り変わる。1回の持続時間もランダム | 見た目は `WeatherPreset.cs`、移り変わりは `WeatherChain.cs` |
| 時刻 | 一定の速さで進む。日の出から日没まで約10分 | `WeatherClock.cs` |

## 天気の移り変わり

天気はエポックを実行しなくても変わる。1回の天気の長さは、その天気の平均持続時間の0.5〜1.5倍の一様乱数で決める。1回が終わると次の天気を選ぶ。

次の天気は、雲が増えて降り出し、弱まって晴れていく順に隣り合う天気（下表）から1つを候補に選び、メトロポリス法で受け入れを決める。受け入れなければ同じ天気がもう1回続く。1歩ごとの滞在の目標を「出現割合 ÷ 平均持続時間」にしているので、長い時間で見たときに各天気でいる時間の割合が上の表に一致する。候補の選ばれやすさは隣の数に反比例するので、その偏りも受け入れ確率で打ち消している。晴れから大雨へは、晴れ間・雨雲・雨と何段階かを経て移る。

| 天気 | 隣り合う天気 |
| --- | --- |
| 快晴 | 薄雲・晴れ・霧 |
| 薄雲 | 快晴・晴れ・晴れ間・曇り |
| 晴れ | 快晴・薄雲・晴れ間 |
| 晴れ間 | 薄雲・晴れ・曇り・雨雲 |
| 曇り | 薄雲・晴れ間・雨雲・霧・霧雨・小雪 |
| 雨雲 | 晴れ間・曇り・霧雨・雨・小雪・雪 |
| 霧 | 快晴・曇り・霧雨 |
| 霧雨 | 曇り・雨雲・霧・雨・小雪 |
| 雨 | 雨雲・霧雨・大雨・雪 |
| 大雨 | 雨 |
| 小雪 | 曇り・雨雲・霧雨・雪 |
| 雪 | 雨雲・雨・小雪・吹雪 |
| 吹雪 | 雪 |

- 出現割合が0の天気へは移らない。表の全気候・全季節で、割合が正の天気どうしは隣接関係だけでつながっている。
- 今の天気の割合が0（固定を解除した直後や、エポックで季節が変わった直後）なら、次の切り替えで割合が正の隣へ必ず移る。隣がすべて0なら表の割合で選び直す。
- 切り替えは45秒かけて空と雲の色・光の強さ・雲量・雲の厚さ・霞・降水量を補間する。雲の配置は変えないので、同じ場所の雲が厚くなったり薄れたりして見える。雲の配置はエポック明けとセッション開始の選び直しでだけ変わる。
- 抽選には専用の `System.Random` を使い、Unity全体の乱数状態を変更しない。
- 天気の移り変わりは、固定中と暗転中（エポック実行中）は止まる。

## 時刻

時刻はエポックと無関係に一定の速さで進む。日の出から日没までを600秒（6時〜18時。1時間=50秒）とし、太陽は東（方位90°）から昇り、正午に南（高度55°）を通り、西（方位270°）へ沈む。高度は `55°×sin(π×昼の進み具合)` である。

夜は描かない。日没のあとは20秒の薄明を挟み、太陽が西の地平線下（−6°）へ沈んで暗さ0.55まで暗くなったところで東の地平線下へ移り、そのまま日の出に戻る。方位が西から東へ切り替わるのは太陽が地平線下にあって直射光が消えている間なので、影が一瞬で反転して見えることはない。

- 高度22°より低い太陽では、空・雲・地平線・太陽光の色を夕焼けの4色へ寄せる。雲が厚いほど寄せ方を弱める。
- 太陽が低いほど直射光を弱め（高度0°で昼の60%）、地平線下3°で直射光を消す。
- 暗さ（薄明と暗転）に応じて、空・雲・霞・環境光を夜の色へ寄せ、直射光と降水の粒を減らす。
- 光源の高度は2°を下限にして地平線より下から照らさない。空に描く太陽と残照は実際の高度で描く。
- 時刻はセーブしない。セッション開始時は朝（日の出から約1.5時間、7時半ごろ）から始まる。

## エポックとの連動

- エポック実行を確定すると、HTTP処理と `epoch:prepare {id}` による演出を並行して開始する。実行中の通知バブルは出さない。Unityは1.5秒で太陽を日没まで進め、その後0.5秒で全画面の黒幕を不透明にする。環境光の暗さと黒幕の不透明度は独立しており、照明に反応しない描画も黒幕で覆う。
- 黒幕を描画した次のフレームにUnityが `epoch:darkened {id}` を返す。UIはそれまで結果やエラーを表示しない。暗転完了時点で処理済みなら結果画面へ進み、未完了ならエポック用Tipsを表示する。Tipsは処理が完了すると自動で閉じ、成功時は `session:reload` の後に結果画面を開く。
- 処理完了・エポック増分の検出だけでは朝に戻さない。結果画面を閉じると（閉じるボタン・×共通）、Rustが同じ演出IDの終了を一度だけ処理し、`epoch:executing {executing: false}` を送る。Unityは `GET /api/v1/city/` を読み直してから、黒幕を0.5秒で透明にし、太陽を1.5秒で朝へ進める（計2秒）。エポックが進んでいれば、黒幕の裏で新しい季節の出現割合から天気を選び直す。結果がない応答・実行拒否・通信失敗でも演出を終了して操作を戻す。
- Unityが未接続なら演出の応答待ちを省略する。接続後に停止するなどして暗転通知が10秒届かなければファイルログに記録して待機を解除し、実行した処理の結果を保持したままUIを復帰させる。古いIDの暗転・終了通知は現在の演出に適用しない。
- 読み直せなくても日の出へ進め、暗いままにはしない。失敗時は5秒後に再試行し、あとでエポックの進みを読み取った場合は次項の扱いになる。
- UIの演出を保持していないときにエポック増分を読み取った場合も、同じ日没・暗転・日の出を挟んで天気を選び直す。一括実行でも1回の暗転で最後の日付の季節から選ぶ。結果待ちの間は増分を記録するだけで、日没を再実行しない。
- 建設・編集後のリロード、重複通知、強制リロードでエポックが変わらなければ、天気も時刻も変えない。
- セッション開始（`game:start`、またはIPCより後からUnityが起動して `GameStateManager` の開始状態を見た場合）は、最初の読み込みでその都市の気候・季節から天気を選び、時刻を朝にする。ロード画面の裏で行うので切り替わりは見えない。`session:reset` / `game:end` で読み込みを止め、時刻を朝に戻す。
- 読み込みを同時実行せず、取得中の通知は次回要求にまとめる。

## 撮影用の操作

Cockpitの日付の横に絵文字と天気名を表示する。`useHudSession.templateMode`がONのときは標準HTML selectで全13種類から選べ（今の気候・季節で割合が0の天気も選べる）、選んだ天気に即座に切り替えて固定する。固定中は天気の移り変わりとエポック明けの選び直しが止まる。時刻は固定しない。自動を選ぶかテンプレートモードをOFFにすると固定を解除し、その天気から自然な移り変わりを再開する。天気を変更するHTTP書き込みはない。

Cockpitは幅800px・高さ76pxの独立したWebViewウィンドウである。CSSの絶対配置で候補を外にはみ出させるとウィンドウ境界で切れるため、WebView2の標準選択ポップアップを使う。画面下端では上側の空き領域へ展開され、候補が収まらなければスクロールできる。キーボードで選択・確定・Escで取消しもできる。

`weather:query`（UI→Unity）は現在値の問い合わせ、`weather:set`（UI→Unity）は`{id: string | null}`の選択。nullは固定解除。Unityは天気の切り替わり（手動の選択・自然な移り変わりの開始・選び直し）、固定の切り替え、気候・季節による割合の変化、問い合わせのたびに`weather:state`（Unity→UI）を返す。応答は`{id, locked, rain, snow, presets:[{id, weight, rain, snow}]}`で、rain・snowは0〜3、weightは今の気候・季節での出現割合（%）。IDと候補一覧の正はUnity、表示名と絵文字はTauriにある。未知のIDでは変更せず現在値を返す。Cockpitは購読完了後に1回だけ問い合わせる。Unityは起動時にも自分から`weather:state`を送るので、Unityの再起動後もUIは再問い合わせなしで復帰する。

3Dビューにキーボードフォーカスがある状態で操作する。Unity EditorではGameビューを選択する。

| 操作 | 動作 |
| --- | --- |
| F9 | 天気パネルを開閉。天気・固定か自動か・気候・季節・時刻を表示する |
| パネル表示中の F6 / F7 | 前後の天気へ即時変更し、その天気を固定 |
| パネル表示中の F10 | 固定と自動の切り替え |
| パネル表示中の F11 | 今の気候・季節で選び直して自動に戻る |
| パネル表示中の F3 / F4 | 時刻を1時間戻す／進める（昼の間だけ。日の出と日没は越えない） |
| パネル表示中の F5 | 時刻の進行を止める／再開する（エポックの暗転と日の出は止めない） |

固定と時刻の停止はUnity起動中のみ保持する。撮影前にF9でパネルを閉じると、天気と時刻を維持したまま表示を消せる。TauriのウィンドウやほかのHUDを隠す機能はこのパネルには含まない。まず晴れの天気で時刻を動かし、建物に斜光が当たる向き・白い壁や屋根のハイライト・影の中の視認性を実際の都市で確認する。

## レンダリング

`Assets/Resources/Weather/Atmosphere.shader` はURP用のプロシージャルなSkyboxである。Resources経由でロードするため、実行ファイルにシェーダーを含められる。上空と地平線の色、太陽円盤と周囲の散乱光、多重ノイズによる雲、雲の濃淡・透過を1パスで描く。ボリュームをレイマーチする雲ではなく、空の球面上に雲の見た目を近似する方式である。

シーンの `RenderSettings.sun`、または有効なDirectional Lightのうち最も強いものを太陽として使う。追加の太陽を重ねない。方向・色・強度・影の濃さを毎フレーム時刻と天気から決め、既存のURPのソフトシャドウ設定を使う。PC用RPAssetの影距離・解像度・カスケード設定はそのまま利用するため、遠景の建物の影が表示される距離は元の描画設定に従う。天気の影の濃さ（`WeatherPreset.Shadow`）は、日光のうち点として届く割合として扱う。残りの `1 − Shadow` は雲で広がった割合で、グローバル `_SunScatterFraction` として毎フレーム送り、水面はその割合の日光を鋭い光沢にしない（[LOD処理](E_LOD処理.md) の「海面・水面の描画と深度オフセット」）。快晴は0.15、雨は0.84。コンポーネントの無効化時にはこのグローバル値も元へ戻す。

`PC_RPAsset` の影の Depth Bias は1、Normal Biasは0.5とする。斜光での自己遮蔽の誤判定を抑えつつ、過大な補正による影の浮きを避ける。道路・軌道の周期的な縞は補正値だけに頼らず、[道路メッシュ](G_道路メッシュの生成.md)の内部端面除去でも抑える。

地上の雲影には128×128の周期的なグレースケールCookieを使用し、URPの `UniversalAdditionalLightData.lightCookieSize` で投影サイズを指定する。空の雲と同じ被覆率・厚さを使うが、雲形状と地上の影を物理的に1対1で対応させるものではない。天気の移り変わりの途中は、雲量か厚さが一定以上変わるたびに作り直す（最短0.5秒間隔）。[UnityのLight設定](https://docs.unity3d.com/ja/current/Manual/urp/light-component.html)も参照。

環境光は上空と地平線の色から球面調和関数(SH)を作り、`AmbientMode.Custom` と `RenderSettings.ambientProbe` で設定する。霞はLinear Fogで制御する。Fog非対応の独自シェーダーやUnlitの表示は、そのマテリアル自身の実装に従う。64pxのRealtime Reflection Probeは空だけを描く。品質設定（`QualitySettings`）の Realtime Reflection Probes は全品質レベルで有効にする。無効だとこのプローブは使われず、シーン既定の環境反射（編集時の既定スカイボックスから作った青空）が天気に関係なく水面や建物に映る。太陽が動き続けるので3秒ごとに面ごとの分割更新で描き直し、天気を即座に切り替えたときはその場で描き直す。都市のメッシュを反射用に再描画しない。ローカルな既存プローブを優先できるよう、天気プローブのimportanceは低くする。

空・光・霧の設定は時刻とともに毎フレーム更新するが、都市オブジェクトを走査したり、都市のメッシュやマテリアルに触れたりはしない。コンポーネントを無効化すると元の空・光・霧を復元し、破棄時には動的マテリアル・テクスチャ・プローブを解放する。

## 降水と環境音

`WeatherPrecipitation`はメインカメラの近くだけに雨粒と雪片を出し、都市の大きさに比例した生成や物理衝突は行わない。降り方は0〜3の連続値で受け取り、天気が移り変わる途中は前後の天気の間の降り方になる。暗さに応じて粒の量を減らす。

| | 範囲 | 粒の量（段階1/2/3） | 上限 | 描き方 |
| --- | --- | --- | --- | --- |
| 雨 | カメラの前方上空、60m四方の面から降らせる | 160/750/1800粒/秒 | 6000粒 | `RainStreak.shader`で輪郭をぼかしたストリーク |
| 雪 | カメラの前方、80m四方・高さ26mの箱の中に湧かせる | 300/800/1600粒/秒 | 8000粒 | `Snowflake.shader`で縁の柔らかい丸い粒 |

雪片は秒速0.9〜1.6mでゆっくり落ち、ノイズで揺らぐ。吹雪では秒速7mの風で横に流れ、流される分だけ風上から湧かせる。落下が遅いので上空から降らせると寿命が長くなり粒数が膨らむため、箱の中に湧かせて寿命の始めと終わりを透明にする。カメラの大移動時は残留粒子を消す。降り止むときは湧き出しだけを止め、宙に残った粒は寿命まで落とし切る。ゲーム終了時・コンポーネント無効化時は即座に消す。

環境音と雨音はUnityのCameraAmbienceが再生する。雨音は移り変わりの途中を含む今の雨量で、隣り合う2段の雨音を配分して入れ替える。雪の天気では雨音を鳴らさない。カメラ高度は地表から100m〜10mで近景音を混ぜる。Tauriは音量設定だけを送り、天気の表示と音響は独立する。実装・素材・検証は[サウンドシステム](../programs/サウンドシステム.md)を参照。

## 検証

`node tools/check_epoch_flow.mjs`（tauri起点）で、HTTPの即時開始、暗転前の結果保留、早い完了時のTips省略、遅い完了・Tips生成途中の完了・失敗時の自動クローズ、Tipsの初期ロード/エポック切り替え、演出IDの照合と通知待ちの解除を検証する。Unity QAは結果画面を閉じるまでの黒幕保持、描画反映後の完了通知、日没1.5秒・フェード0.5秒と復帰の所要時間を検査する。`Captures/t_blackout.png`では黒幕込みのオフスクリーン描画を検査し、全画素が黒であることを確認する。

Tauri側は`node tools/check_weather_audio.mjs`で音量設定の同期を確認する。型検査は`npx tsc --noEmit -p tsconfig.json`、配布アセットの生成は`npx vite build`。実際のWebView2での音量バランスと画面下端のselect操作は本編で確認する。

`unity/Tests/Weather/run-unity.ps1` は本編のC#をビルドし、`Temp/WeatherUnityQA` の独立したUnityプロジェクトで検証を開始する。本編シーンや実行中の都市は変更しない。完了時の `result.txt` と `qa.log` を確認する。

気候の表（全気候・全季節の合計が100、隣接関係でのつながり、砂漠に大雨が無い・亜熱帯と砂漠に雪が無い・湿潤大陸性の雪は冬だけ）、季節の判定、天気の移り変わり（長時間の滞在割合が表と一致する、割合0の天気へ入らない）、時刻（正午の方位、停止、薄明、暗転と日の出）、エポックとの連動（確定・拒否・通知なしの進み・バックエンド不通）、固定、移り変わりの補間、無効化時の環境復元を確認する。簡易建物を置いた同一視点・正午で13種類を `Captures/00.png`〜`12.png` に、快晴の日の出・夕方・薄明・暗転を `t_sunrise.png`・`t_evening.png`・`t_twilight.png`・`t_night.png` に出力する。これは描画の比較用であり、Steam掲載用の実都市スクリーンショットではない。GPU負荷や実都市のマテリアルとの調和は本編のGameビューで別途確認する。
