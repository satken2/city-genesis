# D. 地形形状

都市の地形（標高）と、地形に付随する海岸線・水面・川・埋立地・都市外の背景地形について、コア・Unity・Tauri が共有する約束をまとめる。Unity が地形をどの範囲・品質で描くかは [E_LOD処理](E_LOD処理.md)、どの順で取得して差し替えるかは [H_バックエンドデータロード](H_バックエンドデータロード.md) を参照する。

## D.1. 何のためのデータか

地形は都市全域の標高をグリッドデータ（ラスター）として持ち、3D描画の地面と、道路・建物の接地を支える。現在の標高は、都市を作ったときの自然地形に、道路の盛土・切土や造成などの工事で書き換えたセルの標高を重ねたものである。保存形式や API の名前にある far（遠景）・near（近景）・dynamic（超近景）は格子の細かさの違いであり、カメラの距離で別の地面へ切り替える描画の段階ではない。

## D.2. マップの寸法と格子

マップの寸法と格子は都市（シナリオ）を作るときに決まり、以後は変わらない。フロントは地形設定の API から読み、決め打ちしない。

| 項目 | 意味 |
| --- | --- |
| `map_width` / `map_height` | マップ（都市の範囲）の東西・南北の長さ（m）。セルサイズの偶数倍 |
| `cell_size` | セルの一辺（m） |
| `far_map_spacing` / `near_map_spacing` / `dynamic_map_spacing` | 遠景・近景・超近景の格子間隔（m）。粗い格子は細かい格子の整数倍 |

## D.3. 標高の基準

標高は海面を0とする絶対標高（m）で、水面の水位・岸壁の天端・土地区画の基準標高・カメラの高さも同じ基準で表す。パス・ノードの座標の Y だけは地面からの相対高さである（[A_パス形状](A_パス形状.md)）。

### D.3.1. 配列の向きと方位

ワールド座標は東が `+X`、北が `+Z`、上が `+Y` で、原点はマップ中心に固定する。標高配列は、近景・遠景・超近景・背景のどれも、行0がZ最小の南端、列0がX最小の西端で、`[0, 0]` が南西隅に当たる。この向きは Unity の俯瞰（北が画面上）・コンパス・カメラの yaw（北=`+Z` を0とする時計回り）と一致する。

外部の標高データ（画像や DEM は北から南の行順）は、保存する前に行を並べ替えてこの向きにする。ゲーム内には行を反転する処理が無い。画面のY軸が下向きの2D表示（Tauri の都市マップ・地形エディタ・サムネイル）は `+Z` が画面の上に来るように変換し、右手系の3D表示（three.js）は東西の鏡像を打ち消して描く。

## D.4. セル

セルは標高の保存単位であり、Unity が地形タイルを作る単位でもある。ゲームのルール上の意味は持たず、道路・建物・土地区画はセルをまたいで置ける。地形を書き換えると、そのセルの版が上がる。

コアのセル番号はマップの南西隅を原点とする0以上の整数、Unity のセル番号はマップ中心を原点とし負の値もとる。マップの縦横がセルサイズの偶数倍なのでマップ中心はセルの境界に来て、両者は整数のずれだけで1対1に対応する。変換は `TerrainManager` の変換関数を使う。

## D.5. 標高の取得

標高を返す API はバイナリで、値はリトルエンディアンの浮動小数点数、並びは D.3.1 の向き（行がZ、列がX）である。

| 取得するもの | 内容 |
| --- | --- |
| セルの現在標高（surface） | セル1つを、隣のセルと境界の格子点を共有する正方格子で返す float32。行数・列数・版はヘッダー `X-Grid-Rows`・`X-Grid-Cols`・`X-Cell-Version` |
| 全域の現在標高（far） | 都市全域の現在標高を遠景の格子で返す float16 |
| 初期地形（near） | 都市を作ったときの自然地形を近景の格子で返す float16。書き換えを含まない |
| 版の一覧（cell-versions） | 版を持つセルとその周囲のセル。一覧に無いセルは版0（未編集） |

セルの境界付近の補間は隣のセルも読むので、セルの版には周囲のセルの書き換えも含まれる。フロントは版を、保持している地形と同じかどうかの比較だけに使う。接地や形状生成に使う高さは現在標高から取り、初期地形や保存用の配列を独自に補間して作らない。

## D.6. 海岸線

海岸線は陸地の範囲を表すポリゴン（GeoJSON 形式の `Polygon` または `MultiPolygon`、ワールド座標のXZ）である。都市を作るときに初期地形の標高0mを境に陸地を取り出し、湖と川の範囲を穴として抜き、マップの矩形で切り取る（マップの縁で切られた辺は岸ではない）。陸地の内外は、穴を含む全リングの偶奇で判定する。

海岸線はセーブに保存され、ゲーム中は埋立の完了（D.12）でだけ広がる。道路の盛土・切土や整地では変わらない。フロントは一度取得した海岸線を使い続けず、`session:reload` のたびに取り直す。海岸線は、土地区画の種別（[B_土地形状](B_土地形状.md)）やパスの水上横断（[J_パスの交差処理](J_パスの交差処理.md)）の基準になる。

## D.7. 水面（湖など）

標高0mの海面とは別に、山上の湖や貯水池のように、海面と異なる水位を持つ平らな水面を置ける。

| 項目 | 意味 |
| --- | --- |
| `id` | マップ内で一意な識別子 |
| `water_level` | 水面の高さ（絶対標高 m） |
| `kind` | 種別のラベル（`"lake"`） |
| `polygon` | 水面の範囲。GeoJSON 形式の `Polygon` または `MultiPolygon`（ワールド座標のXZ。内周リングは穴） |

`polygon` は水面がありうる範囲の上限で、海岸線の穴（水の上）になるのは、その中で地形が水位を下回る部分だけである。Unity は範囲全体に水平な水面を描き、水位より高い地形がその手前に見える。流下方向に水面の高さが変わる川は、水面に含めない。

## D.8. 川

川は、地形エディタが川床を標高へ彫り込んだうえで残す「範囲」と「水面の高さ」である。川床は標高の一部になっているので、ゲームから見た谷は通常の地形と区別されない。彫り込みに使う流路・幅・深さはエディタ内部の中間データで、ゲームには渡さない。

| 項目 | 意味 |
| --- | --- |
| `id` | マップ内で一意な識別子 |
| `kind` | 種別のラベル（常に `"river"`） |
| `polygon` | 川の範囲。形式は水面の `polygon` と同じで、中州は穴 |
| `profile` | 水面の高さのプロファイル線 `[[x, y, z], ...]`。上流から下流の順で、y は絶対標高（m）。下流へ向かって増えない |

範囲の中の任意の地点の水面の高さは、`profile` の折れ線上で最も近い点の y（線分の中は線形補間）とする。この規則は地形エディタ・コア・Unity で共通で、水面の描画もパスの横断判定もこの高さを使う。川の範囲はそのまま海岸線の穴になる。

## D.9. 天然資源とカメラ

天然資源（[21_天然資源](../economics/21_天然資源.md)）の初期配置と、都市を始めたときの3Dカメラも、シナリオが持つ。シナリオの地形 API では次の形で送受信する。

| 項目 | 意味 |
| --- | --- |
| 資源 `id` | 資源の ID の文字列。知らない ID は新しい資源になり、コアが振った ID を保存の応答で返す |
| 資源 `resource_type` | 資源種別（マスターの `resource_master` のキー） |
| 資源 `max_amount` / `recovery_rate` | 埋蔵量の上限と、上限に対する1日あたりの回復の割合 |
| 資源 `polygon` | 資源の範囲。GeoJSON 形式の `Polygon`（ワールド座標のXZ） |
| カメラ `x` / `y` / `z` | カメラの位置（m）。`y` は絶対標高 |
| カメラ `yaw` | 視線の方位（度）。北（`+Z`）を0とする時計回りで、IPC の `camera:state` と同じ |
| カメラ `pitch` | 見下ろし角（度）。正で下向き、90で真下。ロールは常に0 |

カメラの値は float32 に収まる有限の数でなければならない。カメラは都市の `camera`（未設定は `null`）としてセーブにも入り、Unity はカメラが止まるたびに更新し、ロードでは `game:start` の後に読んで視点を戻す。

## D.10. シナリオの地形

ゲームは標高マップを同梱しない。地形はシナリオ（`.cg`）が自己完結で持ち、新しい地形は利用者の標高ファイル（グレースケール PNG・`.npy`）を取り込んでシナリオにする。取り込んだばかりのシナリオは標高と（指定すれば）背景地形だけを持ち、地表種別と気候は既定値で始まる。取り込みの入力は [シナリオ制作と配布](../programs/シナリオ制作と配布.md)、変換の規則は API 資料に定める。

Tauri の地形エディタは、シナリオの地形 API で標高・水面・川・カメラ・地表種別・気候を読み書きする。資源とプロップは神モードのセッションで編集するもので、地形エディタは読み込んだ内容をそのまま送り返す。DLC 由来の暗号化されたシナリオは、地形を持ち出せないよう対象外になる。

パス・建物・書き換えたセル・埋立地のどれかがあるシナリオでは、標高・水面・川を変えられない（ロック）。建設物は建てたときの地形に合わせて造成・接地しているので、下の地形だけを変えると食い違うためである。標高・水面・川を保存すると、コアが海岸線や土地区画の種別などの派生値を作り直す。

## D.11. 地表種別と気候

地表種別は都市の地表の見た目を選ぶ値で、描画だけに使う。都市に1つで、ゲーム中は変わらない。値は都市の `ground_cover` で読み、Unity は地形タイル・超遠景の陸地・都市外の背景に、Tauri の2D表示は標高の配色に同じ種別を使う。

| 値 | 共有定数 | 見た目 |
| --- | --- | --- |
| 1 | `GROUND_COVER_GRASSLAND` | 草原（既定） |
| 2 | `GROUND_COVER_DESERT` | 砂漠 |
| 3 | `GROUND_COVER_LUSH` | 濃い草地 |
| 4 | `GROUND_COVER_SNOW` | 雪原 |
| 5 | `GROUND_COVER_SEMI_ARID` | 乾燥地 |

気候は都市とシナリオが保存する12か月の天気・気温・降水量・日照で、[気候設定](../programs/気候設定.md) に定める。

## D.12. 埋立地

埋立（[造成](../economics/34_造成.md)）が完了すると、工事の範囲が埋立地として登録され、海岸線に足される。埋立地の辺のうち海に面する部分は岸壁になり、Unity はそこにコンクリートの天端と垂直の壁を描く。

埋立地が保存するのは ID・範囲・版だけで、岸壁・壁・帯（天端で覆う範囲）・天端の高さは、コアが現在の海岸線と地形から求めて API で返す派生値である。隣を埋め立てて陸地が広がれば岸壁は消え、その埋立地の版が上がる。フロントは岸壁や帯を自分で判定し直さず、返った派生値を描いて判定にも使う。

岸壁のすぐ内側は埋立後も元の海底の高さのまま残し、それより広い帯がその段差を覆う。Unity の地形タイルは格子点の間を補間して描くので、岸壁の際まで埋立後の高さを書くと、岸壁の外の海に盛り上がりがはみ出して見えるためである。帯の中の地面は「地形と天端の高い方」とし、コアと Unity の接地（[E_LOD処理](E_LOD処理.md)）が同じ規則を使う。

## 都市外の背景地形

都市の範囲は、詳細な標高のマップの範囲と同じである。半島や大陸のように都市の外にも陸が続く地形は、都市の外側に背景地形を置いて描く。背景は詳細な地形と同じ実地形から作るが、編集や造成の対象にはならず、都市の範囲も広げない。継ぎ目を補間しないので、都市の範囲の中にある対岸の陸地も詳細な地形に含めて作る。

背景はシナリオとセーブが持つ。背景の API は標高を float32 のリトルエンディアン（並びは D.3.1）で返し、行数・列数・格子間隔・原点（南西隅のワールドXZ）をヘッダー `X-Grid-Rows`・`X-Grid-Cols`・`X-Grid-Spacing`・`X-Origin-X`・`X-Origin-Z` で返す（背景が無ければ 204）。背景には、都市マップが都市の外の陸地を塗るための粗い海岸線も付く。粗いので都市の境界で都市の海岸線とずれるため、都市の矩形の外だけに使う。

都市の外への道路・線路・建物・土地区画の配置は、テンプレート作成モードだけで行える。道路は完成時に都市の境界で分かれ、外側は共通の「都市外」地区に属する。都市の外では建物の自動発生や設備の老朽化などの自動の変化が起きない。
