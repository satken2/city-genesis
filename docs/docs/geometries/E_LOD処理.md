# LOD処理

#### セル

マップを一定の間隔で、セルという単位に区切って描画処理する。
グラフィックのロードと描画処理は、このセル単位で行われる。

#### 地形の種類(ティア)

地形には以下の4種類が存在する。超近景のはゲーム中に変化するため、セーブデータに含める必要がある。
それ以外の地形は固定である。

| 種類             | 地形の変化                 |
| -------------- | --------------------- |
| 超遠景 (UltraFar) | なし(固定)                |
| 遠景 (Far)       | なし(固定)                |
| 近景 (Near)      | なし(固定)                |
| 超近景 (Dynamic)  | あり(道路の建設等で盛り土や切土ができる) |

#### ティアごとの描画内容

カメラからの距離に応じてセルには`dyanmic`、`near`、`far`、`ultra far`の4種類のティアが割り当てられ、それぞれで描画内容が異なる

|                | 建物                      | 道路                 |
| -------------- | ----------------------- | ------------------ |
| 超遠景 (UltraFar) | 非表示                     | 非表示                |
| 遠景 (Far)       | 白い箱 (DefaultBuilding)   | 始点・終点のみの直線ストリップ    |
| 近景 (Near)      | フル詳細（高さをnear地形に合わせる）    | フル詳細（near地形に追従）    |
| 超近景 (Dynamic)  | フル詳細（高さをdynamic地形に合わせる） | フル詳細（dynamic地形に追従） |

per-cell地形タイル（Terrain）のハイトマップ解像度は**全ティア共通で513**（`TerrainManager.TILE_RESOLUTION`）に統一されている。ティアの違いは「タイルの解像度」ではなく「タイルに流し込むデータの世代（far / near / dynamic のどのマップ由来か）」で表現される。これにより、(a) ティア変更が「既存TerrainDataへの部分SetHeightsストリーミング」だけになりタイルの作り直しが不要になる、(b) 隣接タイルの解像度が常に一致して `Terrain.SetNeighbors` が全境界で機能する。バックエンドから受信した生データの解像度が513と一致しない場合、リサンプリングする。**補間はCatmull-Rom（3次）を用いる**。バイリニアはC0連続（値は繋がるが傾きが折れる）で、低解像度ハイトマップを高解像度タイルへ引き伸ばすと格子ごとに折れ面が出て遠方地形がカクカク／ローポリに見えるため、C1連続で傾きも滑らかに繋がるCatmull-Romで平滑化する。Catmull-Romは制御点（元の格子点）を必ず通るため、格子点のワールド座標では元サンプルと同値になり、隣接タイルとの境界整合（縫合）を崩さない。急勾配でわずかにオーバーシュートし得るため、正規化ハイトマップは `[0,1]` にクランプする。

**バックエンド側の標高リサンプリングも3次スプライン（cubic）**である。ソース標高（例: 10m間隔）から近景・超近景マップを生成する際にバイリニアで引き伸ばすと、折れ面がそのままタイルに焼き込まれる。とくに超近景（Dynamic）タイルはバックエンドで生成された時点の起伏がそのまま届き、Unity側のCatmull-Rom平滑化（近景・遠景の引き伸ばしに適用）の対象外なので救えない。そこでバックエンドの生成も3次にしてC1連続にし、超近景タイルからUnityが計算する法線を滑らかにする。これにより、超近景（cubic生成）と近景（Catmull-Rom平滑化）のティア境界で見た目が揃う。ソース間隔（例: 10m）より細かい起伏は原理的に増えない点は変わらない。

超遠景の地形は、カメラ位置に関わらずマップ全体を常時表示する。遠景のセル単位地形は、バックエンドの `/terrain/far` で取得したマップ全体の遠景ハイトマップを、セルのワールド座標範囲で切り出し、Catmull-Rom補間でセルサイズにリサンプリングして生成する。これにより、遠景セルでもAPIコールなしで地形を表示できる。

## ティアの決定

ティアはカメラからの物理距離と水平方向の視野に基づいて動的に決定される。固定のセル範囲ではなく、以下のパラメータで計算する。

| パラメータ | 値 | 意味 |
|---|---|---|
| DYNAMIC_DISTANCE | 400m | この距離以内のセルは超近景（Dynamic）の対象となる |
| NEAR_DISTANCE | 1000m | この距離以内でDynamicを超えるセルは近景（Near）となる。以遠で視野内なら遠景（Far） |
| FRUSTUM_HALF_ANGLE_DEG | 150° | カメラ前方からこの角度以内のセルを「視野内」とみなす。真後ろ（180°）のセルも含めて広範囲を視野内とし、ティアダウンが極端に発生しないように緩めている |

距離の計算には、セル中心ではなくセルのXZ平面上の四角形と標高範囲で構成されるAABB（軸平行境界ボックス）に対するカメラ位置の最近接点を用いる。これにより、カメラがセル境界ぎりぎりに近い場合でも正確に判定できる。

走査範囲は `NEAR_DISTANCE + 1セル分` に制限され、カメラ周辺の有限範囲のみを対象とする。距離が `NEAR_DISTANCE` を超えて視野外のセルは超遠景（UltraFar）となり、ロード対象セルリスト（`farCells`）には含まれない。

**視野外のセルはティアを1つ下げる**。たとえば、距離的にDynamic対象でも真後ろなど視野外であればNearに、Near対象でも視野外であればFarに抑制される。ただし下限はUltraFarとする。


## カメラ移動時の原則

カメラ移動時は、まずセルのLODティアだけを数値上で再計算する。この段階では地形・建物・道路のGameObjectやメッシュを触らない。前回のティア表と比較して、どのセルにもティア変更がなければ、描画更新は行わずに終了する。

ティア変更がある場合だけ、変更セルを起点として3D更新を行う。複数セルが同時に変化した場合は、セルごとに建物や道路を再生成するのではなく、すべての変更セルをまとめてから対象IDを一意化する。これにより、同じ建物や道路が同じカメラ移動で複数回再生成されることを防ぐ。

建物・道路は地形より先にロードされ、地形の全セルロード完了後に「実際に地形タイルが更新されたセルのうちNearティア以上のセル」内のオブジェクトが最新の地形に合わせて追従更新される（2段階方式）。地形より先に作られた建物・道路は一旦古い高さで生成され、後から追従更新される。追従対象をDynamicセルに限定してはいけない。建物・道路のロード（HTTP）と地形タイル生成は完了順が不定なため、Nearセルでも古い高さで生成された個体が存在し、追従されなければ道路が地形に埋まったまま放置される。Farセルの簡易表示（白い箱・直線ストリップ）は遠距離で高さずれが視認できないため対象外とする。

## アーキテクチャ

```
CameraCellChecker
  └─ CellDataLoader.OnCameraCellChanged(centerCell)
       ├─ CalculateLodCellSets() → LodCellSets { ultraFar, far, near, dynamic }
       ├─ 前回ティア表との差分を計算
       │    ├─ ティア変更なし → ここで終了
       │    └─ ティア変更あり
       ├─ LoadBatch を発行 ── 進行中の旧バッチを Cancel（協調キャンセル用。後述）
       ├─ BuildingManager.LoadLodCells(cellSets, changedCells, batch)  ── 建物・道路・区画・地区を先にロード
       ├─ PathManager.LoadLodCells(cellSets, changedCells, batch)
       ├─ ParcelManager / ZoneManager の LoadLodCells
       ├─ TerrainManager.LoadLodCells(cellSets, isForce, batch) ── 最後に実行
       │    ├─ 不要セルのアンロード＋対象セルのHTTP取得を並行発行(ティアアップのみ。ティアダウンは何もしない)
       │    ├─ 取得・補間済みハイトマップは HeightStreamWorker が視野優先・フレーム予算制で
       │    │    バンド単位の部分SetHeightsによりタイルへストリーミング適用
       │    │    (適用と同時に HeightmapTextureManager.WriteCellHeightRows でCPU高さ配列を行単位更新)
       │    └─ OnAllTerrainLodLoaded(updatedCells) 発火 ── 実際に適用されたセル一覧を渡して地形完了を通知
       └─ OnAllTerrainLodLoaded 受信後（CellDataLoader.TerrainFollowUpCoroutine でフレーム分散）:
            ├─ 初回・強制時のみ全量 RebuildCpuHeightmap（CPUキャッシュからの再書き込み。通常はタイル生成時に更新済みのため不要）
            ├─ BuildingManager.AdjustBuildingHeightsForCellsCoroutine(updatedCells ∩ nearCells)
            │    ── Dynamicセルの建物はメッシュ再生成（フェンス・地面パネル地形追従）、それ以外はY座標調整のみ
            └─ PathManager.RebuildPathShapesForCellsCoroutine(updatedCells ∩ nearCells) ── 道路メッシュを現在のティアで再生成
```

`dynamicCells ⊂ nearCells` の包含関係があるため、`updatedCells ∩ nearCells` は「更新セルのうちNearティア以上（Near/Dynamic）のセル」を意味する。

`OnAllTerrainLodLoaded` は「このロードバッチで実際にハイトマップが適用されたセル」の一覧を引数で渡す。`TerrainManager` はストリーミングワーカーが1セル分の適用を完了するたびに更新セルを記録し、発火時にスナップショットして渡す。受信側はこの集合だけを追従更新の対象とするため、**カメラがセル境界をまたいで可視dynamicセルの集合が変わっても、地形が実際に変化していないセルの建物・道路は再生成されない**。これにより、地形不変のセル跨ぎでの不要な全量再生成（フレームヒッチの主因）を回避する。なお、ティアダウン（Dynamic→Near等）ではデータを適用しないため、対応するイベントも発火しない。

`TerrainManager.LoadLodCells` はコルーチンとして実行される。カメラが移動して新たに `LoadLodCells` が呼ばれた際、前回のコルーチンを明示的に停止し、`settingsLoading` フラグを `false` にリセットする。これにより、コルーチン停止によるフラグの孤児化を防ぎ、次回の設定読み込みが正しく開始される。

**ロードバッチ（LoadBatch）による協調キャンセル**: Unityの `StopCoroutine` は、`StartCoroutine` で起動された子コルーチンまでは停止できない。`TerrainManager` はセルごとの地形フェッチを並行コルーチンとして起動するため、親の停止だけでは旧バッチの子コルーチンが走り続け、新バッチの状態と競合する。これを防ぐため、`CellDataLoader` はロード開始（`UpdateManagers`）のたびに `LoadBatch` を発行して各マネージャーに配り、旧バッチを `Cancel` する。子コルーチンは通信完了後や重い処理の直前に `IsCanceled` を確認して自発的に停止する。ストリーミングワーカーは「**開始前のリクエストのみ**」キャンセルで破棄する。適用を開始したセルは原則完走する（途中放棄すると新旧データが混在した裂けたハイトマップが画面に残るため。残作業は高々9バンドで有界）。例外は不可視の新規タイルで、GameObject化（attach）前ならいつでも安全に破棄できるため、attach直前にもキャンセルを確認し、キャンセル済みバッチの残骸がロード範囲外のセルへ孤児タイルとして登録されるのを防ぐ。キャンセル・失敗しても表示中の旧タイルは無傷のまま残る（「チラつき防止策」参照）。キャンセルはティアのフォールバック（Dynamic→Near→Far）と区別され、キャンセルによる失敗で次ティアのAPIコールが発行されることはない。

地形ロード完了後の追従更新（建物・道路のメッシュ/高さ再計算）は `CellDataLoader.TerrainFollowUpCoroutine` で複数フレームに分散される（`PerformanceConfig.FrameBudgetMs` 超過で `yield return null`）。建物・道路が参照するCPU高さ配列（`HeightmapTextureManager.GetTerrainHeight`）は、地形タイルの生成・再縫合の時点で `TerrainManager` が直接書き込んでいるため、追従更新の開始時点で常に最新である（GPUからの読み戻しは行わない）。カメラが移動して次のロードが始まると、進行中の追従コルーチンは `StopCoroutine` でキャンセルされ仕切り直される。取りこぼした更新セルは `pendingFollowUpCells` に残り、次回完了時に再処理される。また、追従抑制（defer）中に破棄された地形タイル生成イベントのセルは `EndDeferred...` が返却し、未処理であれば追加の追従が1回実行される（取りこぼしへの防御）。

## 主要クラス

- **CameraCellChecker** (`CameraCellChecker.cs`): カメラの水平面（y=0）におけるワールド座標を計算し、セルインデックス変化を検出する。`CurrentWorldPosition` を提供することで、LodConfig がセル境界判定を行えるようにする。
- **LodConfig** (`DataLoaders/LodConfig.cs`): ティア定数・セルセット計算。`CalculateCellSets` はカメラのワールド座標を受け取り、各セルのAABBに対する最近接点までの距離と視野角からティアを決定する。視野外のセルは強制的に1段階ティアを下げる。また、`acquiredCells` を指定した場合、未開放セルはDynamicにならず強制的にNearに抑制される。
- **LodCellSets**: ティア別セルリストのstruct。`farCells` はロード対象セル全体を表す包含集合であり、DynamicやNearのセルも含まれる。`TerrainManager` は `farCells` を `desiredCells` として使用する。
- **BaseApiDataManager**: `LoadLodCells` 仮想メソッド（デフォルトはnearCells）。マージBBOX計算・位置からセルへの変換などの共通ヘルパーを提供。
- **TerrainManager**: per-cell（Dynamic/Near/Far）の地形LOD + ハイトマップストリーミング + 縁ブレンド + 超遠景陸地メッシュ（海岸線ポリゴン由来）。セル単位でDynamic→Near→Farの段階的フォールバック、未開放セルでの404ハンドリング、version差分更新、遅延破棄プール（アンロード用）を管理する。タイル（Terrain GameObject / コライダー）はセルごとに1回だけ生成して永続化し、ティア変更は既存TerrainDataへのデータストリーミングで行う（「ハイトマップのストリーミング適用」参照）。超遠景の陸地メッシュ生成は `UltraFarLandMeshBuilder` に委譲する。
- **BuildingManager**: 遠景=白い箱 / 近景=フル詳細 / 超近景=フル詳細＋フェンス・地面パネルの地形追従（地形更新時にメッシュ再生成）。詳細メッシュの生成は視野優先の遅延キューと個数上限LRUで管理する（「建物の視野ゲート生成と個数上限（LRU）」参照）
- **PathManager**: 遠景=直線ストリップ / 近景=スプライン / 超近景=地形追従スプライン再生成。地形更新起因の再生成は視野優先・フレーム予算制のキューで行う（「道路の視野優先再構築」参照）

## 地形ロードとフォールバック

`TerrainManager` はセル単位で以下の優先順位で地形データを読み込む。いずれの経路もバックグラウンドスレッドで解像度513のハイトマップ配列に補間し、ストリーミング適用キューへ渡す（タイル解像度は全ティア共通で513）。

1. **超近景（Dynamic）**: `/terrain/dynamic` API を呼び出す。未開放セルに対しては404が返されるため、自動的に近景へフォールバックする。
2. **近景（Near）**: `/terrain/near` API を呼び出す。レスポンスヘッダー `X-Grid-Rows` / `X-Grid-Cols` からグリッド寸法を取得し、バイナリデータを補間する。
3. **遠景（Far）**: `/terrain/far` で取得済みのマップ全体の遠景ハイトマップから、セルのワールド座標範囲をCatmull-Rom補間で切り出す（ネットワーク不要）。

このフォールバックにより、未開放セルやネットワークエラー時でも最低限の地形（遠景データ）が表示される。各セルに現在適用されているデータの世代は `cellLodLevel` に記録される。フォールバック連鎖の各段では「既に同等以上の世代が適用済みか」（`HasAppliedGeneration`）を確認し、無駄な再取得・再適用を省く。

**ティアダウンでは何もしない**。カメラが遠ざかってセルのティアが Dynamic→Near/Far に下がっても、タイルには高精細なデータをそのまま保持する（`cellLodLevel` は「これまでに適用した最高の世代」を表す）。精細なデータを粗いデータへ戻すGPUアップロードは純粋な無駄であり、解像度統一によりタイルのメモリは世代に関わらず一定のため、保持コストも増えないからである。データ取得はティアアップ（`current < desiredLod`）時のみ行われる。

## ハイトマップのストリーミング適用（HeightStreamWorker）

旧実装は「ティアごとに解像度の異なるTerrainタイルを作り直す」方式で、ティア変更・新規ロードのたびに TerrainData生成＋フル解像度SetHeights（513²=26万点のGPUアップロード＋LOD/法線再計算）＋コライダーの同期ベイクがメインスレッドに乗り、さらに複数セルが並行ロードで同一フレームに集中するため、セル跨ぎで数百msのフレームヒッチが発生していた。現在は以下のストリーミング方式で、重い処理を複数フレームに分散する。

- フェッチ側コルーチンは補間済みハイトマップを `ApplyHeightsStreamed` で**適用リクエスト**としてキューに積み、完了を待つ。同一セルの未開始リクエストは最新データで置き換えられる。
- 常駐ワーカー `HeightStreamWorker` がリクエストを**1セルずつ直列に**消化する。処理順は視野優先（カメラ前方 `STREAM_VIEW_HALF_ANGLE_DEG`=75°以内のセルを距離順で最優先、視野外は後回し）。視錐台は「適用するか否か」のフィルタではなく処理順の重みであり、視野外のセルも必ず処理される（振り向いても地形が欠けたままにならない）。
- 適用は `STREAM_BAND_ROWS`（57行）のバンド単位の**部分SetHeights**で行い、`PerformanceConfig.FrameBudgetMs` を超えたらフレームを譲る（513²は9バンドに分割され、1バンドはフル解像度の約1/9のコスト）。カメラ移動ロック中（初回ロード・強制全リロード）はカクつきが体感されないため予算を4倍に広げる。
- **新規タイル**は、切り離された（GameObject未接続の）TerrainDataへストリーミングし、全バンド適用後に `AttachTerrainTile` で一括GameObject化する。ストリーミング途中の中途半端な地形が画面に出ず、コライダーの初期ベイクも完成データに対して1回だけ・専有フレームで行われる。CPU高さ配列への書き込みはattach（可視化）後に行う（不可視のうちに書くと、中断時に「地形が無いのに高さだけ残る」ゴーストが発生するため）。
- **既存タイル**（ティアアップ・dynamic差分更新）は、可視のままの既存TerrainDataへ直接バンドを適用する（in-place更新。タイルの作り直し・差し替えは発生しない）。CPU高さ配列も同じバンドを行単位で同期更新する（`WriteCellHeightRows`）。数フレームかけて新旧データの境目がタイル内を走査していくが、同じ地形の精細度違いなので視覚的な破綻は軽微で一時的。
- TerrainData は GameObject の破棄では解放されない独立アセットのため、タイルの破棄は必ず `DestroyTerrainTileObject`（TerrainDataも併せて破棄）を通す。

## 海面・水面の描画と深度オフセット

海面はTerrainとは別の板ポリゴンオブジェクト（シーンに手動配置）として表現され、標高0mの平面（ワールドY=0）に貼られる。

海面以外の水面（湖など）は `WaterSurfaceManager` が `GET /api/v1/terrain/water` から取得したポリゴンを、各水面の `water_level`（Y標高）に置いた水平メッシュとして生成する。マテリアルは海面板のものを借用（借用できなければ `Custom/DepthOffsetLit` のフォールバック）し、海面と同じ深度オフセット階層に乗せる。したがって以下の海面についての説明は、標高0m以外の水面にもそのまま当てはまる（湖底=per-cellタイルとのZ-fighting回避、岸でのワールドYによる自然な前後関係）。水面はマップ固有の静的データなので、海岸線取得と同じセッション初期化タイミングで一度だけ生成する。地形システムはこのオブジェクトを直接管理しないが、深度バイアスの設計が海面の見え方に直結するため、ここに仕様を明記する。

### 課題: per-cell地形と海面のベースYが揃うことによるZ-fighting

per-cellタイル（Far / Near / Dynamic）は、ベースY（`AttachTerrainTile` が設定する `-SeaFloorDepthSpan`）とオフセット正規化の組み合わせにより `worldY = 実標高` となる。標高0m（海面）の点はワールドY=0に来て、海面板（ワールドY≈0）と深度が完全に一致する。このままだと遠距離・低角度カメラで深刻なZ-fightingが発生する。

### 解決策: シェーダーの深度オフセット階層

地形シェーダーと海面シェーダーで `Offset` コマンドを設定し、同一深度での描画順序を制御する。`Offset factor, units` は正値でカメラから遠ざけ（奥）、負値で手前に寄せる。値が大きいほど奥に描画される。

| 描画対象 | シェーダー | Offset | 役割 |
| --- | --- | --- | --- |
| 建物・道路・フェンス等 | `Custom/DepthOffsetSimpleLit` | `-1, -1` | 地形より手前 |
| 海面・水面（湖など） | `Custom/DepthOffsetLit` | `-1, -1` | 地形より手前（水面が水底を覆う） |
| 地形（Far/Near/Dynamicのper-cellタイル） | `Custom/DepthOffsetTerrainLit` | `1, 1` | per-cell地形 |
| 超遠景陸地メッシュ（UltraFar） | `Custom/DepthOffsetSimpleLitFar` | `4, 4` | 最奥 |

同一ワールド深度での優先関係は `オブジェクト ≧ 海面 ＞ per-cell地形 ＞ UltraFar陸地メッシュ` となる。海面と地形の深度差バイアスが `(2, 2)` 以上に拡大し、海面レベルでは海面が地形より手前に描画される。これにより海岸線が地形の標高0等高線に沿って正しく形成される。陸地（地形が海面より高い領域）では地形がワールドYの差で自然に手前に描画される。

海面マテリアルには必ず `Custom/DepthOffsetLit`（または同等の負のOffsetを持つシェーダー）を適用すること。Offsetなしのシェーダーに誤って差し替えると、Farティア以下でZ-fightingが再発する。

## 超遠景（UltraFar）の陸地シルエットメッシュ

UltraFarに求められるのは「遠くに見える陸地のシルエット」だけ（建物・道路は非表示、地形は固定）である。これを**マップ全体1枚のUnity Terrainハイトマップ**で表すのは不向きで、以下の問題があった。

- UltraFarの解像度は極めて粗い（マップ全体で解像度33、サンプル間隔は数百m）。標高0m付近の地形がうねって平らな海面板（ワールドY=0）を突き抜け、本来は海であるべき沖合に陸が飛び出す（カメラを低く下げて浅い角度で海を見ると顕著）。
- かつてはUltraFarだけベースY=`-10`に下げてこの突き抜けを力技で隠していたが、その10mの落差で標高0〜10mの陸地が海面下に沈み、UltraFarの陸地が本来より小さく描画される（Farセルの端が崖状の海岸線になる）問題があった。

そこで現在のUltraFarは、Unity Terrainをやめ、**バックエンドの海岸線ポリゴンから生成した陸地シルエットメッシュ**として描画する（`UltraFarLandMeshBuilder` / `TerrainManager.BuildUltraFarTerrain`）。

### 生成方法

海岸線は近景マップ（`near_map`、10m間隔）から精密に抽出された陸地境界ポリゴンで、`GET /api/v1/terrain/coastline` で取得して `CoastlineStore` に保持される（バックエンドの海岸線抽出を参照）。陸地のAABBをグリッド（既定80m間隔）に切り、各グリッドセルを海岸線でクリップして陸地ポリゴンを切り出す。

- **海岸線クリップ**: 各セルの辺をたどり「陸側コーナー」と「海岸線との交差点」を順に拾うマーチングスクエア的手法で、陸地部分のポリゴンを得る。交差点は `CoastlineStore.SignedDistance`（符号付き距離、陸+/海−）の符号反転位置を線形補間で求めるため、海岸線はグリッド解像度より細かく滑らかに出る。
- **海はメッシュを作らない**: 陸地外にはジオメトリを置かないため、海は既存の海面板がそのまま担う。粗いハイトマップが海面板を突き抜ける問題やZ-fightingが**原理的に発生しない**。
- **起伏**: 各頂点のYを far_map 高さでサンプリングして粗い起伏を表現する。海岸（標高0m付近）の頂点は自然に海面近くに来る。全頂点を微小オフセット（既定1m）持ち上げ、海面板の上に保つ。
- **スムース法線**: 頂点はグリッドセルごとに個別に追加されるため、セル境界の同一ワールドXZ位置に重複頂点ができる。`Mesh.RecalculateNormals`（面法線を頂点で平均するが重複頂点は溶接しない）だとセル境界で法線が不連続になり、遠景陸地がファセット（多面体）状にのっぺり見える。そこで、面積重み付きの面法線を「同一XZ位置」へ集約してから正規化した**スムース法線**を頂点に与える（頂点自体は溶接せず法線値だけを共有）。交差点・コーナー頂点は隣接セルで同一座標が決定論的に再現されるため、量子化キーで確実に一致する。
- **深度順序**: メッシュは `Custom/DepthOffsetSimpleLitFar`（`Offset 4,4`）を使い、per-cellタイル（`1,1`）・海面（`-1,-1`）より奥に描画する。カメラ近傍でper-cellタイルがこのメッシュに重なっても、常にper-cellが手前で勝つ。
- **タイルへの突き抜け対策（ロード済みセルでの沈み込み）**: UltraFar メッシュは far_map 由来の粗い起伏を持つため、per-cell タイル（特に near_map 由来の Near/Dynamic タイル）とは起伏の激しい場所で数十mの高低差が生じ、タイルの上に突き出て斑点状に見えることがある。これを防ぐため、「per-cell タイルが実際にロードされている（可視の）セル」を 1セル=1テクセルの R8 マスクテクスチャ（`_LoadedCellMask`）にしてシェーダーへ渡し、頂点シェーダーがマスクの立っているセルの頂点を `_FarSinkAmount`（既定 50m）地中へ沈める。マスクは `TerrainManager.UpdateLoadedCellMask` が毎フレーム `terrainTiles` の現状から再構築する（内容が前回と同じなら GPU アップロードはスキップ）。タイルの無いセルは沈めないため、カメラ移動やロード遅延で海色の穴が開くことは原理的にない（タイル未ロードの間は UltraFar がそのまま見えるだけ）。
- **マテリアルとテクスチャ**: per-cell タイルと同じメインテクスチャを同じタイリングで適用する。頂点のワールド座標 `(X, Z)` をそのまま UV 座標として設定し、ワールド座標ベースでマッピングする。**法線マップは設定しない**（SimpleLit 系の `_BumpMap` に地形用のカラーテクスチャが流用されると不正な法線で陰影が暗く濁るため。遠景専用なので法線ディテールは不要）。

### 未開放セルの暗色表示

メッシュの各三角形を「開放済み／未開放」の2サブメッシュに振り分け、サブメッシュ別マテリアルの `_BaseColor` で塗り分ける（`RefreshUltraFarLandOverlay`）。開放済みサブメッシュは常に通常色（テクスチャ素の色。テクスチャ未設定時のみ `ultraFarLandColor` のフラット色）。未開放サブメッシュは暗色表示が有効なとき `unacquiredTint` を乗算した「同じ地面テクスチャを少し暗くした」色、無効なとき開放済みと同じ通常色になる。

海岸線がセッション開始時にまだロードされていない場合（海岸線なしのマップ）は、マップ全体を陸として平坦なメッシュを張るフォールバックになる（通常フローでは `FetchAcquiredCells`→`FetchCoastline` がUltraFar生成より前に完了する）。

## 崖（急傾斜）の岩テクスチャ描画

per-cellタイル（Far / Near / Dynamic）の地形シェーダー `Custom/DepthOffsetTerrainLit` は、傾斜（`1 - ジオメトリ法線のY成分`）が閾値を超えたピクセルに岩肌のアルベド＋法線マップをブレンドして崖を表現する（実装は `Assets/Shaders/TerrainCliffRock.hlsl`）。傾斜判定には地面の法線マップで擾乱される前の**ジオメトリ法線**を使う。擾乱後のシェーディング法線で判定すると、法線マップの偏りにより同じ傾斜でも特定の向きの斜面だけ岩化する方向依存の描画バグになるため。

- **トリプラナーマッピング**: 岩テクスチャはUV座標ではなくワールド座標の3軸投影でサンプリングする。Unity Terrain標準のXZ平面投影だと垂直に近い崖面でテクスチャが極端に引き伸ばされるが、トリプラナーなら崖面にも正対投影される。3軸の重みは法線から求め、4乗でシャープ化して投影境界のぼやけを抑える。
- **ライティング前のブレンド**: 岩ブレンドはライティング計算の前にアルベド・法線・スムースネスへ介入する。これにより崖にも太陽光の陰影・法線マップ由来の凹凸・スペキュラが正しく乗る。実現方法は、URPの `TerrainLitPasses.hlsl` にあるライティング呼び出し `UniversalFragmentPBR`（8引数オーバーロード・1箇所のみ）を同名マクロでラッパー関数に差し替えるフック（URPソースのコピー不要）。
- **境界のノイズ乱し**: 傾斜閾値にワールド座標ベースのノイズを加算し、草と岩の境界が等高線状の均一な帯にならないようにする。
- **低地（海岸・海面下）の岩化**: 傾斜条件とは別に、標高が低い土地は傾斜に関係なく岩へ寄せる（草が生えない海岸・浅瀬・海面下を岩肌で表現）。開始標高（既定2m）から最大標高（既定0m=海面）へ徐々にブレンドし、それ以下（海面下）は一律で岩。汀線が真横一直線の帯にならないよう開始標高もノイズで揺らす。傾斜マスクと標高マスクは `max` で合成する（どちらかの条件を満たせば岩）。
- **設定**: 閾値・遷移幅・ノイズ・タイリング周期(m)・法線強度などは `TerrainManager` の `Terrain Cliff Rock Settings`（Inspector）で調整でき、タイルごとの `materialTemplate` に適用される。岩テクスチャはInspector未設定時 `Resources/Textures/cliff-rock-albedo` / `cliff-rock-normal` を自動ロードし、見つからない場合も単色フォールバックで動作する。
- **適用範囲**: 同じシェーダーを使うFar / Near / Dynamicの全ティアに自動適用され、ティア境界でも色調が連続する。超遠景（UltraFar）の陸地メッシュは別シェーダー（`Custom/DepthOffsetSimpleLitFar`）のため対象外（遠距離では崖ディテールの視覚効果が薄いため。地平線際の色調不整合が問題になった場合は同様のマクロフックで拡張可能）。

## 地表のスタイライズ表現

per-cellタイルの地形シェーダー `Custom/DepthOffsetTerrainLit`（実装は `Assets/Shaders/DepthOffsetTerrainLitMacroVariation.hlsl`）は、単一テクスチャの露骨なタイリングを隠し、写真テクスチャの精細さに頼らず「破綻なく整った」非写実（スタイライズ）の地表を作るための層を持つ。アート方向はPC／ハイエンド優先。設定は `TerrainManager` の Inspector（`Terrain Procedural Ground Settings` / `Terrain Macro Variation Settings` / `Terrain Color Grade Settings` / `Terrain Detail Normal Settings`）で調整し、タイルごとの `materialTemplate` に適用される。

- **手続きベースアルベド**: 地面の基本色そのものを多スケールノイズ（fbm）で生成する。大局モザイク（低周波fbm）で草↔乾いた土のパッチを切り替え、細かい斑（高周波fbm）で明色を薄く混ぜてベタ塗り感を消す。`_ProceduralGroundBlend`（0=テクスチャ, 1=完全手続き, 既定 0.85）でTerrainLayer由来のサンプル色と混合でき、1なら拾い物テクスチャの反復が完全に消える。崖の岩ブレンドはこの手続きベース色の上に岩を lerp するので崖の非退行が保たれる。ライティング前（アルベド）に適用する。
- **マクロバリエーション**: ワールド座標の3オクターブ値ノイズ（fbm）で地面の明度とティントを大スケール（既定 数百m 周期）に揺らし、同一テクスチャの反復による単調さを崩す。ライティング後の最終色に適用する。
- **カラーグレード（標高・傾斜ベースの色ランプ）**: 最終色に、標高で低地色↔高地色を補間したティントを乗算し、急斜面にはアースカラーを寄せる。傾斜は面法線を画面微分（ddx/ddy）から復元して求めるため頂点法線に依存しない。スタイライズの肝で、標高・スロープに応じた統一感のある色設計を与える。ティント各色は≈1.0付近を前提にした乗算なので明度を大きく損なわない。強度0で従来の見た目に戻る。
- **平地の手続きディテール法線**: 法線マップテクスチャを使わず、ワールドノイズの勾配で微小な凹凸をライティング前のワールド法線へ与える。完全マットになりがちな平地に、太陽角度の変化で動く柔らかいスペキュラ／陰影の起伏を出す。急斜面（崖）では平坦度で弱め、崖の岩法線ブレンドと競合させない。強度0で無効。
- **スムースネス**: 完全マット（0）をやめ、既定で弱いスペキュラ（0.15程度）を持たせ、上記ディテール法線と併せて陰影に立体感を出す（`ApplyDefaultTerrainMaterial` の TerrainLayer smoothness）。

これらはいずれもテクスチャ素材を追加せずシェーダー内で完結する（手続き的）。地面のベース色を手続き生成にしたことで、拾い物テクスチャの反復に依存せず繰り返しを消せる。より高精細な地表（草／土／砂の実テクスチャによるスロープ・標高ブレンド）はアート素材の調達を前提とした将来拡張であり、崖ブレンドと同じプレライティングフックの上に載せられる設計になっている。

なお超遠景（UltraFar）の陸地メッシュは別シェーダー（`Custom/DepthOffsetSimpleLitFar`）で上記の手続き層を持たないため、当面は地面テクスチャ据え置きである（遠距離では反復が視認されにくい）。地平線際の色調不整合が問題になった場合は、手続きベースアルベド／マクロバリエーションを同シェーダーへ移植する将来拡張として対応できる。

## エポック差分更新（dynamicセルのversion差分）

エポック経過や地形編集で変化し得るのは超近景（Dynamic）タイルだけなので、ロード済みdynamicセルはセルごとの**version**で差分管理し、変化したセルのみ再描画する。この差分チェックは `TerrainManager.LoadLodCells` の冒頭で毎回（カメラ移動・エポック後の `ReloadAllData` とも共通で）実行される。

1. `/terrain/cell-versions` API でマップ全体のdynamicセルversion一覧を一括取得する。
2. 現在ロード済みのdynamicセルについて `CheckAndRefreshDynamicTerrain` を並行実行し、キャッシュ済みversion（`dynamicCellVersions`）と比較する。一括取得にversionが含まれないセルは `/terrain/dynamic` への `HEAD` リクエストで個別確認する（フォールバック）。
3. versionが変わったセルのみ `RefreshDynamicTerrain` で `/terrain/dynamic` を再取得して再描画する。旧タイルは再描画完了まで可視のまま維持され、新タイル生成と同一フレームで差し替えられる（「チラつき防止策」参照）。
4. リフレッシュが失敗・キャンセルされた場合はversionキャッシュを取り消し（ロールバック）、次回のロードバッチで再試行させる。取り消さないと「versionは最新・タイルは古いまま」の状態が恒久化するため。
5. 再取得したデータはストリーミング適用の開始時に隣接タイルの縁とブレンドされる（「地形の縁ブレンド」参照）ため、境界のずれは適用の時点で解消される。

これにより、エポック中に地形が変化しなかったセルには一切触れず、チラつきを防ぎつつ高速に更新できる。

## セル開放状態の可視化

マップ上で未開放セルの位置を視覚的に把握できるよう、`TerrainUnlockOverlay` 機能がTerrainManagerに組み込まれている。仕様は「**未開放セルは通常のテクスチャ付き地面を少し暗くした色、それ以外は通常の色**。表示をOFFにすると全域が通常の色」。

per-cellタイル（Far / Near / Dynamic）の仕様:
- 実装方式: 地形シェーダー `Custom/DepthOffsetTerrainLit` が持つタイル全体への乗算ティント `_TerrainTint`（白=通常色）を使う。未開放セルのタイルは `unacquiredTint` を、開放済みセルは白を、タイルごとの `materialTemplate` に設定する（`ApplyUnlockOverlayToTerrain`）。テクスチャ模様・マクロバリエーション・崖の岩ブレンドは保ったまま全体が一様に暗くなる
- `materialTemplate` は `ApplyTerrainOffsetMaterial` がタイル生成時に必ずクローンする「タイルごとの個別インスタンス」（名前サフィックス ` (TileInstance)` で識別）なので、タイル単位で独立にティントを変えられる
- `Terrain.basemapDistance` は実質無効（100000m）に設定する。デフォルト（1000m）のままだと遠方タイルがベースマップ用シェーダーで描画され、`_TerrainTint` やマクロバリエーション・深度Offsetが適用されなくなるため
- 更新タイミング: `ToggleUnlockOverlay` 呼び出し時や、Terrainタイル生成時に `ApplyUnlockOverlayToTerrain` を実行する

超遠景（UltraFar）の陸地メッシュは Terrain ではないため、サブメッシュ別マテリアルの `_BaseColor` で同じ `unacquiredTint` を乗算する（「未開放セルの暗色表示」参照）。per-cellタイルとUltraFarで同じティント色と同じ地面テクスチャを使うため、ティア境界でも未開放の見た目が揃う。

`ToggleUnlockOverlay` はセル境界線・座標ラベル・開放済み領域の外枠線の表示と連動しており、OFFにすると枠線類が消えると同時に未開放セルも通常色に戻る（全域が通常の色になる）。

これにより、プレイヤーはどのエリアがまだ開放されていないかをカメラ位置に関係なく一目で確認できる。

## セル別ルックアップ

建物と道路は、生成済みデータについてセルからIDを引ける対応表を保持する。セルのティアが変わったときは、この対応表を使って変更セルに関係する建物ID・道路IDを集める。集めたIDは一度集合にまとめ、同じIDを重複して処理しない。

建物は中心点が属するセルに登録する。道路は始点・終点・経由点を結ぶ線分と道路幅から、道路が影響するセルを求めて登録する。道路のLODティアは、道路が通るセルのうち最も高いティアを採用する。

## マージBBOX一括取得

建物、道路、区画のデータは、カメラ周辺の全対象セルのBBOXを結合して1回のAPIコールで一括取得する。マージBBOXを用いることでネットワークレイテンシを削減する。

### LOD tierの判定方法

マージBBOXで一括取得したデータは、各アイテムが属するセルや通過するセルをもとにLOD tierを判定する。

- **建物**: `center_point`の座標から属するセルを計算し、DynamicまたはNearセルならフル詳細、Farセルなら白い箱で描画。
- **パス**: 始点・終点・経由点と道路幅から通過セルを計算し、通過セルのうち最も高いティアを採用する。Dynamicなら地形追従で詳細メッシュを再生成し、Nearなら詳細メッシュ、Farなら簡易表示にする。
- **区画**: LODティア分けがないため、全データを同一の処理で描画。

### バックエンドのlimitパラメータ

一括取得時は1回のクエリで多数のデータを取得するため、各GETエンドポイントに`limit`クエリパラメータを追加している。デフォルト値は建物500、パス100、区画100で、マージBBOX使用時はフロントエンド側から`limit=5000`を指定する。

## 地形の縁ブレンド

タイル解像度は全セル共通のため、境界のLOD継ぎ目（法線・パッチ）は `Terrain.SetNeighbors` が処理する。ただし隣接セル同士で適用済みデータの**世代**（far / near / dynamic）が異なると、同じ境界線上の標高がわずかに食い違い、セル境界に裂け目やV字の谷ができる。これを防ぐのが縁ブレンド（`BlendEdgesTowardAppliedNeighbors`）である。

- これから適用するハイトマップの縁を、**既に画面へ出ている隣接タイルの縁の値に一致させ**、内側のブレンド帯（最大6ピクセル）へ差分を減衰させて馴染ませる。「**後から適用する側が既存に合わせる**」という不変則により、適用済みタイルを後から触り直す再縫合が一切不要になる（適用済みタイルの縁は以後変化しない）。
- 隣接の縁の参照は `originalHeightsCache`（そのタイルに現在適用されているブレンド後のCPU配列＝GPU上の内容と同一）から行う。旧実装の `TerrainData.GetHeights`（GPU→CPUの同期readbackで、レンダースレッドを止めるストール要因だった）は使わない。
- ブレンドはストリーミング適用の開始時（バンド分割の前）にCPU配列へ行われるため、追加のGPUアップロードは発生しない。
- 両隣が同じ世代のデータを持つ場合、境界の値はもともと一致する（同じ元マップの同じ座標をCatmull-Romでサンプリングするため）ので、ブレンドは実質no-opになる。

また、適用されたハイトマップは行単位で `HeightmapTextureManager.WriteCellHeightRows` に渡され、建物・道路が参照するCPU高さ配列がバンド適用と同期して更新される。`TerrainData.GetHeights`（GPU→CPUの同期readback）による読み戻しは行わない。

## 建物の視野ゲート生成と個数上限（LRU）

建物のフル詳細メッシュ生成（`CreateOrUpdateBuildingObject`）は1棟あたり数msかかるため、以下の方式で「カメラに映るものだけを先に」生成する。Far（白い箱）は軽量なので視野に関わらず即時生成し、スカイラインを維持する。

- **視野ゲート**: マージロード・地形追従で詳細メッシュの生成/再生成が必要になった建物のうち、視野外（カメラ前方75°超かつ100m超）のものは生成せず遅延キュー（`deferredDetailBuildings`）へ積む。既存オブジェクトがある場合は古い見た目のまま画面外に残す（視野外で消滅させない）。
- **遅延生成ワーカー**（`DetailGenerationWorker`）: 毎フレーム、フレーム予算内で「視野内かつカメラに近い」建物から順に生成する。視野外の建物も、詳細メッシュ数が上限に達していなければアイドル的に生成する（振り向き時のポップイン軽減）。カメラが回転すると、視野に入った建物が即座にキューの先頭へ来る。
- **個数上限（LRU）**: フル詳細メッシュを持つ建物オブジェクトの数に上限（`maxDetailedBuildingObjects`、既定2000）を設ける。超過時は「視野外で最も長く視野に入っていない」建物からGameObjectを破棄する（最終可視フレームは15フレームごとのスイープで記録）。破棄してもデータキャッシュ・セル逆引きは保持し、遅延キューへ戻すため、視野に入れば再生成される。視野内の建物は破棄しない（視野内だけで上限を超える場合は一時的な超過を許容する）。
- 視野外のため生成を遅延した建物にはversionをキャッシュしない（ワーカーが生成した時点でキャッシュする）。これにより次回のマージロードでも「未生成」と判定され、遅延キューが最新データで更新され続ける。

## 道路の視野優先再構築

道路1本の再生成（スプライン＋SplineMesh群の同期生成）は数msかかり、フレーム予算（約4ms）に対して1フレームに1〜数本しか進まない。このため**処理順**が体感品質を決める。

- 地形タイルのデータ適用イベント（`OnTerrainTileReady`）で交差パスを再生成する経路は、ハンドラ内での同期一括再生成をやめ、キュー（`queuedTerrainFollowPathIds`）へ積んで常駐ワーカー `TerrainFollowRebuildWorker` が視野優先・フレーム予算制で消化する。ワーカーは再生成時点の現在ティアで再構築し（キュー投入時からティアが変わっていることがある）、ロード範囲外に出たパスは再生成しない。
- 地形ロード完了後の一括追従（`RebuildPathShapesForCellsCoroutine`）は、対象パス・交差点ノードを視野優先スコアで昇順ソートしてから処理する。「カメラに映っている道路から地形に馴染む」ため、目の前の道路が埋まったまま長時間放置されない。

## セル開放状態によるティア制限

地形の超近景（Dynamic）データは、セル単位で「開放（acquire）」されたセルにのみ存在する。未開放セルに対して `/terrain/dynamic` API を要求すると404が返される。開放済みセルの一覧は `/terrain/acquired-cells` API で取得できる。

Unity側では、セッション開始時に `/terrain/acquired-cells` から開放済みリストを取得し、`TerrainManager` 内にキャッシュする。このリストは `HashSet<Vector2Int>` として保持される。

`LodConfig.CalculateCellSets` は、このリストを参照して未開放セルのティアを強制的に Near に抑制する。これにより、カメラが未開放セルに接近しても無駄な404 APIコールを防ぎ、メモリ使用量の肥大化を抑制する。

さらに `TerrainManager.LoadCellDataAtTier` でも、Dynamicティアが要求された際に `IsCellAcquired` で二重にチェックし、未開放セルであれば明示的に Near にフォールバックする。LodConfig側とTerrainManager側の二重チェックにより、不整合を防ぐ。

### セル座標系の変換

Unity とバックエンドではセルの座標系が異なる。

- **Unity**: ワールド座標の原点 `(0, 0)` を基準に `FloorToInt(world / cell_size)` でセルを区切る。原点の西南側は負のインデックスになり得る。
- **バックエンド**: マップを左上原点の 2 次元配列として扱い、セルインデックスは常に非負（`0 <= cx < cells_x`, `0 <= cz < cells_y`）。

両者の対応関係は以下の通り。

```
unity_x = backend_x - (cells_x / 2)
unity_z = backend_z - (cells_y / 2)
```

`TerrainManager` は `UnityCellToBackendCell` / `BackendCellToUnityCells` メソッドを提供し、API 通信時にこの変換を吸収する。

- `FetchAcquiredCells` で受け取ったバックエンド座標を Unity 座標系に逆変換して `acquiredCells` にキャッシュする。
- `AcquireCell` やセル開放 UI からの `acquire-cell` リクエストでは、Unity 座標をバックエンド座標に変換して送信する。
- `TerrainInputHandler` は IPC で UI にセル座標を通知する際もバックエンド座標系に変換して送信する。これにより、UI 側は座標変換を意識せず、そのまま `POST /api/v1/terrain/acquire-cell` を叩ける。

**注意**: `BackendCellToUnityCells` は、バックエンドの1セルがUnity座標系では複数セル（最大2x2）にまたがる可能性があるため、覆う全てのUnityセルを列挙して返す。

## LOD遷移

カメラが移動すると `OnCameraCellChanged` が発火する。`CellDataLoader` が各ティアのセルセットを計算し、前回のティア表との差分からティア変更セルを判定する。ティア変更がない場合、地形・建物・道路の更新は行わない。ティア変更がある場合、建物・道路を変更セル起点で更新し、最後に地形を更新する。地形の全セルロード完了後に、実際に地形が更新されたセルのうちNearティア以上のセル内の建物・道路を最新の地形に合わせて追従更新する。

### オブジェクト更新規則

- **建物**: UltraFarになったセルの建物は非表示にする。Farになった建物は簡略メッシュにする。Nearになった建物は詳細メッシュにする（視野外なら遅延キュー経由）。NearとDynamicの間で遷移した建物は、フェンス・地面パネルの地形追従状態が変わるため詳細メッシュを再生成する（[[F_建物メッシュの生成]]の10.4参照）。Dynamicセル内の建物は、Dynamic地形のロード完了後にもメッシュが再生成され、最新の地形に追従する（いずれも視野内は即時、視野外は遅延キュー経由。「建物の視野ゲート生成と個数上限（LRU）」参照）。
- **道路**: UltraFarになったセルだけを通る道路は非表示にする。Farになった道路は簡略メッシュにする。Nearになった道路は詳細メッシュにする。Dynamicになった道路は地形に合わせて詳細メッシュを再生成する（視野内の道路から優先的に処理する。「道路の視野優先再構築」参照）。
- **地形**: ティア変更でタイルは作り直さない。取得した新しい世代のデータを既存タイルへバンド単位の部分SetHeightsでストリーミング適用する（「ハイトマップのストリーミング適用」参照）。
- **フレーム予算**: 地形のストリーミング適用・建物の遅延生成・道路の再構築キュー・地形ロード完了後の追従再生成（`CellDataLoader.TerrainFollowUpCoroutine`）は、いずれも `PerformanceConfig.FrameBudgetMs` を超えるたびに `yield return null` で複数フレームに分散し、重い生成処理が1フレームに集中しないようにする。

### チラつき防止策

- **可視のままのin-place更新**: 地形のLODティア変更時、タイルの差し替えは行わず、可視のままの既存TerrainDataへ新しい世代のデータをバンド単位でストリーミング適用する。タイルが一瞬消えるフレームは原理的に存在しない。新規セルのタイルは切り離されたTerrainDataへ不可視のままストリーミングし、完成後に1フレームでGameObject化するため、中途半端な地形が画面に出ることもない。ロードのキャンセル・失敗時は既存地形がそのまま残り、次のロードバッチのティア差分判定で自然に再試行される。超遠景陸地メッシュの沈み込みマスク（`_LoadedCellMask`）も `terrainTiles` から構築されるため、ロード中にUltraFarメッシュが浮き上がることもない。
- **遅延破棄**: セルがロード範囲から外れた場合も即時破棄せず、`pendingDestroyTerrains` に非表示で退避し、1.5秒経過後に実際のDestroyを行う。`Update` 内で毎フレームタイムスタンプを確認し、期限を超えたものから順に破棄する。
- **オブジェクトプーリング**: 建物・道路・区画のGameObjectをセル範囲外に出ても破棄せず非表示にし、カメラが戻った時に再利用する。
- **2段階の高さ追従**: 建物・道路は地形より先にロードされるため一旦古い高さで生成され得るが、地形ロードが完全に終了した後にNearティア以上のセル内のオブジェクトを最新の地形に合わせて追従更新することで、誤った高さでの表示が残らないようにする。この追従更新は「実際に地形タイルが更新されたセル」だけを対象とする差分方式であり、地形不変のセル跨ぎでは追従更新自体がスキップされる。
- **コルーチンキャンセル**: カメラが別セルに移動した際、前のセル位置での読み込みコルーチンを全てキャンセルし、古いデータの読み込みが残存しないようにする。TerrainManagerでは `StopCoroutine` に加え、`settingsLoading` フラグを明示的にリセットして孤児コルーチンを防ぐ。`StopCoroutine` では停止できない並行子コルーチンは、ロードバッチ（`LoadBatch`）の `IsCanceled` を確認して協調的に停止する（「ロードバッチによる協調キャンセル」参照）。地形ロード完了後の追従更新コルーチン（`TerrainFollowUpCoroutine`）も同様にキャンセルされ、取りこぼした更新セルは `pendingFollowUpCells` に退避して次回ロード完了時に再処理する。建物・道路の追従処理は `IEnumerator` を直接 `yield return` して親コルーチンと同一実行コンテキストで動かすため、親のキャンセルで内側の処理も確実に停止する。
