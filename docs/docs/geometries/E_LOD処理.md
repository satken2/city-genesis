# LOD処理

全建物のFarは共通のprefix解決から `base/mid/top-prebuilt_far` を選び、既成パーツとして組み立てる。名所も通常建物も同じ経路を通る。敷地装飾は生成せず、遠景用パーツが1つも無い場合は簡易形状へ戻る。工事・解体・倒壊は状態に応じた簡易形状を使う。詳細は [[F3_既成建物のメッシュ生成]]。

LODは「取得する範囲」「地形の細分化」「物体の描画品質」を別々に管理する。

## 責務と所有者

| 責務 | 実装 | 判定・データ |
| --- | --- | --- |
| 常駐範囲 | `LodConfig` / `CameraCellChecker` | 視錐台、注視位置、カメラ位置、81セルの上限 |
| 現在の標高 | コアの地形API | 基礎地形＋編集。全解像度で同じ基準面 |
| 地形描画 | `TerrainManager` / Unity Terrain | 共通513格子、Unityの画面誤差による細分化 |
| 接地 | `Utils.GetGroundHeight` | 表示中のTerrain。未常駐部分は編集済み全景 |
| 建物・道路の品質 | `DrawLodEvaluator` | 投影サイズ／道路区間までの距離、ヒステリシス |
| プロップ | `PropManager` | 投影サイズ、実距離によるHidden、固定順位による候補予算、共有モデルのinstancing |
| 生成の時間予算 | `RenderWorkScheduler` | 全生成器の同期処理時間の合算 |

`LodCellSets` の `farCells/nearCells/dynamicCells` と `LodTier` は既存マネージャーへの互換入口として残る。現在の選択器は3集合に同じ常駐セルを渡す。これらから「別の地形ソース」「接地するかどうか」「Farメッシュ固定」を決めてはならない。

## 常駐範囲

カメラ変更の検出は `LodViewState` が担い、用途ごとに3つの判定を使い分ける。取得範囲と視野の判定に使う `Update` は4mの移動、1度の回転、FOV／正射影サイズ、画面縦解像度、アスペクト比、投影方式の変化を検出する。建物の投影比LODに使う `UpdateProjection` は4mの移動、FOV／正射影サイズ、投影方式だけを見て、回転と画面比は見ない(投影比は回転では変わらないため)。道路の距離LODに使う `UpdatePosition` は4mの移動だけを見る。1つの検出状態は1つの判定だけに使う。セル通知は0.1秒間隔で、同じセルの中のズームも再判定する。

注視点は地形コライダーではなく数理平面y=0との交点とする。ロードの有無によって注視点が動き、再ロードが連鎖することを防ぐ。取得候補は注視点周辺（1,100〜2,500m）とカメラ周辺から作り、視野・距離で優先付けして最大81セルを常駐させる。マップ外は要求しない。

回転やズームのわずかな変化で縁のセルが出入りを繰り返さないよう、常駐中のセルにはヒステリシスがある。視錐台・注視半径・カメラ近傍500mの各判定に `RESIDENT_HYSTERESIS_MARGIN`(250m)の余裕を足し、スコアも0.8倍にして残りやすくする。

カメラ由来のロードバッチは0.25秒以上の間隔に合流させる。間隔が空いた後の最初の変化はすぐ発行し、間隔内に来た通知は最後の1件だけを間隔の終わりに発行する(その時点のカメラから常駐集合を計算し直す)。カメラを速く動かしている間に、取得を始めては取り消すバッチを毎回作らないためである。保留中も中心セルは更新するので、その間にエポック完了や編集確定の再取得が来ても最新の視点で集合を作る。

常駐範囲外には全景地形を描く。建物・道路・プロップの表示対象は取得範囲内であり、全都市を無制限に詳細表示する方式ではない。

カメラの遠方クリップ面は、マップの最遠隅と地形の上下端までの距離に1セル分の余裕を加え、視点移動・高度変更に合わせて必要な場合に延ばす。シーンで指定した距離は下限として扱うため、大きなマップでも4.5kmなどの固定距離で全景地形が途切れない。詳細オブジェクトの取得範囲と常駐セル上限は変わらない。

Unityとバックエンドはマップ中心を原点とする固定座標を共有し、カメラが遠くへ移動しても原点を移さない。Transformだけをシフトすると地形セル、未ロード領域の高さ、カメラの保存座標、ドラッグ中の基準点が食い違うため、距離を閾値にした全オブジェクトの移動は行わない。検証は `Tests/Lod/run.ps1` の大規模マップのクリップ範囲とシーンの原点シフト未使用のチェックを含む。

### 通常地形と全景地形の見た目

通常のTerrainタイルとUltraFar陸地メッシュは、同じ地表の色・模様・岩肌・PBR照明を使う。`TerrainSurfaceAppearance.hlsl` が地表種別の手続き色、微細な法線と風紋、傾斜・低標高での岩ブレンドと砂浜、標高色、等高線を共通実装し、`TerrainManager.ApplyTerrainMaterialSettings` が両方に同じパラメータを渡す。地面テクスチャ、金属度、滑らかさも通常地形の設定を使う。都市外の背景地形も同じシェーダーを使い、全景と同じ設定関数(`ApplyFarTerrainMaterialSettings`)で値を直接書き込む。手続き色や色被せの値はシェーダーの Properties に宣言していないため、`new Material(既存マテリアル)` の複製では落ちて見た目がずれる。遠景シェーダーの名前 `Custom/DepthOffsetSimpleLitFar` はシーン参照の互換用に維持するが、Forwardパスは共通のPBR照明を呼ぶ。

双方とも照明・霧を適用した後にマクロバリエーション、標高・傾斜のカラーグレード、等高線を掛ける。全景側は1サブメッシュ・1マテリアルで描く。遠景の粗い形状、ロード済みセル内の沈み込みマスク、深度オフセットは維持するため、形状・法線の精度差は残るが、ロード境界で別の配色へ切り替わることを防ぐ。Forward+向けの共通化であり、未使用のGBufferパスに同じ地表表現を保証するものではない。

沈み込みは `UltraFarTerrainSink.hlsl` を全描画パスで共用する。頂点自身だけでなく、接続面を覆う「遠景格子1区間＋丸め誤差の余裕」の周囲9点がすべてロード済みの場合にだけ頂点を下げる。境界をまたぐ三角形は元の高さを維持するため、片側の頂点だけを沈めて未ロード領域を海面下へ引き込む隙間を防ぐ。周囲の検査間隔がセル幅を超える設定では安全側として沈めない。境界の重複部分では粗い遠景が通常地形より高くなる場合があるが、地表を欠落させないことを優先する。全景メッシュは都市の範囲にしか面を持たないので、都市範囲(`_FarCityRect`)の外側の近傍は境界上のセルとして判定する。マスクの外を未ロードとみなすと、陸地が都市の端まで続くマップで、境界から遠景格子1区間の帯が沈まずに通常地形の上へ突き出る。

`Tests/TerrainAppearance/run-unity.ps1` は独立したUnityプロジェクトで同じ地表をTerrainとメッシュで描画し、霧の有無の両方で画像差とシェーダーエラーを検査する。セル幅と遠景格子幅が割り切れない境界でも、ロード・アンロード・ロード領域移動後に海が露出しないこと、内部の沈み込みは機能すること、都市範囲を渡すと全セルロード時に境界の帯まで沈むことを比較描画で検証する。結果とPNGは `Temp/TerrainAppearanceQA` に出力する。

### 等高線

地形タブの等高線トグルはグローバルの `_ShowContour` を切り替える。通常Terrainと全景メッシュは `TerrainSurfaceAppearance.hlsl` の `ApplyContourLines` を共用する。

カメラから地表の各点まで600m以上では10m間隔の副等高線と50m間隔の主等高線を茶色で描く。150m以内では2m間隔の補助線を加え、10m・50mの線を太くする。近距離の線は濃い青灰色で、明るい縁取りを付けて草地や岩肌と区別する。150〜600mでは両表現を滑らかに補間する。標高間隔自体は補間せず、線の位置を固定してズーム中の移動を防ぐ。

近距離の線幅は画面微分からピクセル単位で決め、水平面の全面着色と急斜面での密集を抑える。`Tests/TerrainAppearance/run-unity.ps1` は近距離・遠距離の線数とコントラスト、平坦面での無着色を描画検証し、比較PNGを出力する。

## 地形の取得と確定

1. `/terrain/settings` と `/terrain/cell-versions` を取得する。版一覧には編集の影響を受けたセルだけが載るため、**一覧に無いセルは版0として扱う**。地形を一度も編集していない都市では一覧が空になる。版一覧は、強制再取得・無効化済み・未取得・前回取得から5秒超のときだけ取り直し、それ以外のカメラ移動ではキャッシュを使う。エポック完了や編集確定の再取得(`ReloadAllData`)と全消去で無効化する。取得中に無効化されたら、その応答では無効化を解除しない。
2. 全景が未取得、または編集の版が変わった場合は `/terrain/far` を再取得する。
3. 未取得／版が変わった常駐セルを `/terrain/surface?cell_x=...&cell_z=...&resolution=513` から取得する。取得はセル単位のジョブで、取得から公開・通知までを同時に進めるジョブは最大4つ。空いた取得枠は視野優先の順に割り当てる。
4. float32 LEを別スレッドで正規化する。寸法・有限値を検査する。受信した高さ配列(1枚約1MB)はプールで再利用する。
5. 表示から切り離したTerrainDataへ57行ずつ `SetHeightsDelayLOD` で書き、`SyncHeightmap` 後にタイルを差し替える。表示・コライダー・接地の参照先は同じフレームで変わる。
6. タイルの公開と同じステップで版・ロード済みセル・更新セルを記録し、次のステップで `OnTerrainTileReady` を通知する。通知の時点で購読者は新しい版を読める。

分割できない `SyncHeightmap`・タイルの公開・`OnTerrainTileReady` の通知は、それぞれ別のステップにする。どれも共通予算の使用が25%以下になるまで最大8フレーム待ってから始める(フレームの後半に重い呼び出しを始めてスパイクを作らないため)。通知は公開順に別の処理が出し、高さの適用は通知を待たずに次のタイルへ進む。通知の前には全消去の世代と表示中のタイルが同じかを確かめ、差し替わっていれば通知しない。全タイルのロード完了イベント(`OnAllTerrainLodLoaded`)は、全タイルの通知が終わってから発火する。

タイルのジョブの寿命はロードバッチではなく「そのセルが常駐している間」である。カメラ移動でバッチが取消されてもジョブは止まらず、後続のバッチが同じジョブの完了を待つ。途中まで進んだ受信・適用を捨てないためである。ジョブを取り消す(通信も中断する)のは、セルが常駐外になったときと全消去のときだけ。

常駐外になったタイルは破棄せず、非表示のまま版と一緒に最大24枚(1枚あたり推定2〜4MB)の LRU に保持する。再入場時に必要な版以上なら、取得・帯の適用・`SyncHeightmap`・コライダー生成をせず、表示と隣接タイルの再接続だけで元に戻す。復元でも `OnTerrainTileReady` は1回発火し、更新セルに含まれるので、依存する建物・道路・区画・プロップは地形の版(下記)を比べて、変わっていなければ作り直さない。強制再取得では LRU を使わない。新しいデータを公開したら同じセルの保持分は破棄し、地表種別の変更は保持中のタイルにも反映する。保持中のタイルは接地・GPU 高さ窓・全景の沈み込みマスクから参照されない。

地形の版は `TerrainManager.GetAttachedTerrainVersion`(表示中タイルの版。タイルが無ければ -1)と、範囲内のセルの版・全景データの版・全消去の世代を混ぜた `GetTerrainSignature` で公開される。同じ版・同じ世代なら再入場後も同じ値になるので、依存側は生成時に記録して比べる。

隣接セルは同じ世界格子から標高を取得する。取得順に依存する縁ブレンド、Dynamic→Near→Farの取得フォールバック、精度が上がった履歴の台帳は使わない。513格子の描画細分化はUnity Terrainに委ね、`heightmapPixelError` は地表面との整合性を優先した設定を使う。

版一覧や必要タイルの取得失敗は2秒後に再試行する。必要タイルが未適用のまま後続生成へ進まない。タイル専用のMaterial・TerrainLayer・代替Textureは `TerrainTileResources` が所有して解放する。

表示が変わらない通常のカメラ移動では標高を再適用しない。地形編集では関連セルの派生版が変わるため、遠景を含めて再取得する。

## 接地と依存順序

地形の確定と既存物体の追従更新を終えてから、区画を取得し、その完了後に建物・道路・プロップの取得へ進む。建物の基準標高に使う区画が未到着のまま新規生成する競合を避ける。詳細は[K_Unity差分ロード整理](K_Unity差分ロード整理.md)。

抑制中のタイル通知は追従開始前に統合する。追従が中断した場合は道路・交差点の処理済み記録を保持し、関係する新しい地形やデータで無効化された対象と未処理分だけを進める。常駐セルへ戻っただけでは道路の形状revisionを更新せず、生成済みLODを再利用する。

CPU接地は `Utils.GetGroundHeight` に統一している。都市内の未常駐セルでは Unity の全Terrain一覧を走査せず、全景の高さを返す。全マップのCPU配列への再サンプリングは行わず、0mも有効な標高として扱う。未常駐部分を通る長い道路は全景地形を参照し、対象セルが到着したら再計算する。これは遠景の近似であり、接近時の精度を代替するものではない。

GPUの区画フィル等には既存の1536m移動窓を使う。窓の外まで精密な接地が保証されるものではない。窓は、窓に重なるセルのタイルの到着・除去と、カメラ移動による再センタリングのときだけ作り直す。全景の沈み込みマスクも、表示中のタイルの集合が変わったときだけ作り直す。

## 物体の描画LOD

| 対象 | 近景・通常 | 遠景 | 境界の扱い |
| --- | --- | --- | --- |
| 建物 | 投影比でNormal/Close。Close部品が無ければ通常部品 | 遠景モデルがあれば使用、無ければフットプリント押し出しの輪郭 | Normal進入0.045／退出0.03、Close進入0.25／退出0.18、接写距離上限150m |
| 道路 | 区間の最近接距離でNormal/Close | 曲線の帯。本体以外の遠景装飾を省略 | Close進入120m／退出160m、Normal進入450m／退出550m |
| プロップ（森林GPU以外） | 投影サイズ、共有モデル | `_far` または簡略化メッシュ。森林の木は極小投影で四角錐 | 実距離でHidden。進入1,500m／退出1,350m |

正射影では投影サイズが距離に比例しない。物理距離の接写上限は別に評価する。

道路本体と固定区間の距離LODは `LodViewState.UpdatePosition` で4m以上の移動だけを検出する。回転・FOV・画面条件だけの変更では距離が変わらないため再走査しない。建物の投影LODは `UpdateProjection` で移動とズームだけを検出し、回転だけでは走査しない。常駐セルの選択は通常の `Update` を使い、回転も検出する。

### 建物

完成したLODを `RenderObjectCache` へ退避し、同じ形状・敷地・地形版で戻ってきた場合は再利用する。建物のキーは、見た目に効くデータ項目(形状・状態・工事進捗・外観・サブ建物・端子/基地ノード)の構造ハッシュ、形状リビジョン、区画ポリゴン・基準標高のトークン、描画LOD、接地範囲の地形版からなる。データの版は含めないので、見た目の変わらない版の更新では作り直さない。形状リビジョンは、データの版が変わらずに見た目だけが変わる場合(車両基地の端子移動)に進める。区画のトークンには地価や接道を入れない。

セルが常駐外へ出ると、建物オブジェクトはその場で破棄せず、フレーム予算で分割して退避キャッシュへ移す(数百棟を1フレームで非表示にするとスパイクになるため)。データとセルの逆引きは残す。再入場したセルの建物はキーでキャッシュから復元し、メッシュを作り直さない。アンロードの途中で再入場したセルは、その時点で退避を中断して表示に戻す。

カメラ移動によるロードでは、建物を取り直すのは未ロードのセル・再取得を要求されたセル・ティアが変わったセルだけで、それ以外のロード済みセルは受信済みのデータとオブジェクトをそのまま使う。バックエンドの変化はエポック完了や編集確定の再取得が「要再取得」として記録し、取得に成功して適用されるまで記録を残す(途中でバッチが取消されても、次のバッチで取り直す)。取得セルは行ごとの連続区間から作った矩形(最大12個。超えたら外接矩形1つ)に分けて要求する。矩形からはみ出して届いた取得対象外セルの建物は生成しない。

描画LODの再判定は、ロード済みセルの建物だけを対象に、共通予算で分割して走査する。回転だけの操作では走査しない。箱(Far)への切り替えはその場で行い、詳細化は遅延キューへ積む。

遅延生成はキュー投入時のLODをそのまま採用せず、生成直前のカメラ・最新の建物データで判定し直す。待機中に離れてFarで足りるようになった建物は、詳細保持上限に達していてもFarへの切り替え・再利用で要求を消化する。未ロードセルの要求は引き続き保持する。

フル詳細のメッシュには視野ゲートと個数上限がある。生成が必要になった建物のうち視野外(カメラ前方75°より外かつ100mより遠い)のものは即時生成せず遅延キューへ積み、常駐ワーカーが視野内かつカメラに近いものから予算内で生成する(上限に余裕があれば視野外もアイドル時に生成し、振り向いたときのポップインを抑える)。フル詳細のオブジェクト数は `maxDetailedBuildingObjects`(既定2000)で上限管理し、超過したら視野外で最も長く視野に入っていない建物からGameObjectを破棄する。表示可能なセルの建物は箱(Far)に置き換える(差分取得ではロード済みセルを取り直さないので、置かないと再入場まで消えたままになる)。範囲外セルや非アクティブのものは退避して版を消し、視野に入れば再生成される。遅延中の建物には版をキャッシュせず、ワーカーが生成した時点で記録する(次のロードでも未生成として扱い、キューを最新データで更新し続けるため)。箱(Far)は軽量なので視野に関わらず即時生成し、上限の対象外である。

対応するモジュラー／既成建物では躯体・コライダーの生成と敷地装飾の生成を分離する。`BuildingExteriorRenderer` が通常モデルのフェンス・地面等を後続の仕事として生成する。地形に沿う地面メッシュは地形格子・三角形の対角線に合わせる。特殊建物やプレビューは各生成器の一体生成を維持する。

遠景建物は `FarBuildingBatcher` が256m区画・同じマテリアル・同じ親ごとに最大64棟ずつ結合する。輪郭は個々のフットプリントを維持する。建物が出入り・変更されたら、その建物を含むバッチ(最大64棟)だけを即座に解体して元の描画へ戻し、削除済みの建物を結合メッシュに残さない。再結合は常駐ワーカーが、汚れたグループだけを予算内(1バッチごとに譲る)で行い、静止中は何も走査しない。32棟未満の端数バッチは、端数同士や未結合の候補とまとめ直す。全サブメッシュを1つに結合し、プロパティブロックを持つレンダラーは結合しない。遠景メッシュ(prebuilt_far を含む)は共有マテリアル1つで描くため、生成時に単一サブメッシュへ畳む。遠景の建物はコライダーを持たないので、生成されたコライダー用メッシュはその場で解放する。結合バッチは遠景建物の表示・位置・マテリアルの変化を自分では検知しないので、それらを変えた側が通知する。詳細保持上限による降格でも輪郭を残す(表示中のセルでは必ず箱に置き換える)。

### 道路

256m以上の通常道路の押し出しパーツを `SplinePartLod` が分割する。全長から128mを目安に決めたスプライン割合を固定して使うため、カメラに合わせて切断位置を動かさない。曲率によって各区間の実長は異なる。論理パス・制御点・交差点アンカーは分割しない。

区間のLODは、全パーツで共有するカメラ移動の世代(4m)が変わるまで再評価しない。静止中の区間ワーカーは予算外のネイティブ待機で眠るので、道路の本数が多くても共通予算を消費しない。区間の優先順位ソートはLOD変更が必要な区間だけを対象にする。各区間の生成直前にもカメラ位置を取り直し、待機中に不要になった詳細パーツを作らない。状態が変わった区間のマテリアル反映と新旧道路の表示切り替えは、その区間の適用時に行う。

破線、single_span、交差点の折り返し生成にはこの分割を適用しない。橋・トンネル・駅の保存標高・交差点切断規則は既存の形状生成器の責務とする。路面本体を固定区間に分けた道路は、親を通常LODに固定して区間だけを切り替える(親を作り直すと全区間・設備・橋脚を再生成するため)。対象は通常道路(model_type=default)だけで、線路・送電線・索道・single_span・角付き折れ線・高さ補正のある道路・工事中の道路は親単位で切り替える。区間に分かれているかは、生成済みなら実物で、未生成なら条件とアンカー長256m以上から推定する。推定が外れても、再判定で1回作り直せば収束する。データ／地形／接続形状の変更は道路キャッシュの世代を更新する。

道路本体の描画LODは、データティアに依らず、アンカー点列(始点・経由点・終点)への3D最近接距離だけで決める。カメラが4m以上動いたら、生成済みの全道路を共通予算のスライスに分けて走査し、LODが変わる道路を作り直す。ロードバッチが始まったら走査を打ち切り、次の周期に走査し直す(切断点が確定する前の形をバッチの生成済みとして数えさせないため)。アンカー点列と長さは道路データのインスタンスごとにキャッシュし、データの変更・地形タイルの到着・アンロード・全消去で捨てる。

道路の中心線(交差点で切る前の点列)も、道路データと通過セルの地形の版が同じ間は再計算しない。交差点の切断点が変わると、その道路の形状の版が進む。車両や公共交通ハイライトはこの版(`GetPathGeometryRevision`)で中心線の変化を検出する。

制限速度標識は接写・通常モデルが表示される範囲だけで表示し、遠景・Hidden・アンロード時には隠す。`PathSpeedLimitOverlay`は生成済みの`DrawLodInfo`を参照し、固定区間を持つ道路では中心位置の本体区間を`SplinePartLod.GetDrawLodAtPosition`で確認する。道路の一端だけが接写でも中心が遠景なら標識は表示しない。距離閾値やヒステリシスを標識側で再実装せず、差し替え生成中は`PathPresentation.IsReady`を待つ。検証は`Tests/SpeedLimitSigns/run.ps1`。

## プロップと森林

範囲配置の森林（種類1/2）はGPU配置を使う。約100mで通常モデルからFar樹冠へ切り替え、CPUの個体候補を作らない。詳細は末尾の「範囲配置の森林」と[M_地形プロップ](M_地形プロップ.md) §M.4参照。

以下は個別配置・森林以外・GPU非対応時の候補経路である。候補配置は保存座標の固定ハッシュで決まる。常駐候補の予算を内容のある小区画へ配分し、`StableSample` が固定順位の小さい点を残す。走査順を逆転しても同じ点が残り、予算を減らした結果は元の部分集合になる。手置きのプロップを散布点より優先する。常駐する小区画の数が変わって1区画あたりの予算が変わっても、配置は作り直さない。予算が減ったら既存の点列の先頭を切り詰め(結果は作り直した場合と同じ)、増えたときは1.25倍以上になったときだけ作り直す。

描画バッチの再評価は、カメラが max(4m, 小区画までの距離×2%) 以上動いたときだけ行う(1,000m先の小区画なら20m)。点ごとのLOD・Hiddenが変わらなければ既存のバッチを使い回し、影の対象だけを更新する。距離や投影サイズによる本数の間引きは行わず、遠景でも常駐候補の本数を保ってメッシュだけを簡略化する。カメラからの実距離が閾値以上の点はHiddenにして描かず、小区画全体が閾値より遠ければ個体判定ごと省く。手置き配置も同じ距離で消える。遠景モデル・区画別instancingと組み合わせて森林の負荷を抑える。詳細は[M_地形プロップ](M_地形プロップ.md)。影は近景のみ、サブメッシュごとの延べ4,096インスタンスを上限とする。UltraFarの全マップ森林専用プロキシは持たない。

## 共通予算・寿命・観測

- 開始は `RenderWorkScheduler.Start(owner, routine, category)`、停止は `Stop(owner, handle)`。Unityの `StopCoroutine` だけでは内側のIEnumeratorが破棄されないため、直接使わない。
- GameObjectの無効化・破棄でも `RenderWorkLifetime` が、そのGameObjectを所有者とする仕事だけを止める。建物の敷地装飾(`BuildingExteriorRenderer`)は例外で、共通のホストGameObjectで実行し、建物GameObjectの無効化で止めて再表示で未完了のジョブから再開する。明示的な子ジョブは `LoadBatch.IsCanceled` も確認する。地形タイルのジョブは例外で、バッチではなくセルの常駐に寿命を合わせる。
- 共通ポンプは、`RenderWorkScheduler` が初回の起動時に自動生成する常駐GameObject `RenderWorkPump` の `LateUpdate` から1フレームに1回動く。
- 同期処理の合計を目標フレーム時間の25%（下限2ms）に抑える。個別処理は0.5msを目安に協調的に譲る。ネイティブAPIの1呼び出しを途中で中断できるわけではなく、最大単工程時間も測る。
- 退避メッシュは建物256MiB・道路128MiB・道路パーツ8MiB、さらに全体512MiBのLRU上限を共有する。計測値は頂点バッファ(ストライド×頂点数)とインデックス数から求めたメッシュの推定量(CPU側に写しを持つメッシュは2倍)に固定管理費を足したもので、Profiler を使わないので製品ビルドでも上限が効く。GPU複製・共有Material・表示中資源の総量ではない。
- 非同期の物理ベイクは `MeshBakeService` が同時2件まで実行する。退避GOが破棄されてもベイク終了まではMeshを保持し、その後解放する。この一時保持は退避キャッシュの上限とは別。
- F8には直近600フレームのp95/p99、共通生成時間、最大単工程、退避メモリ、プロップの描画・影数を表示する。メッシュ数はTerrainのGPU細分化量を含まない。

## 海面・水面の描画と深度オフセット

海面はTerrainとは別の板ポリゴンオブジェクト（シーンに手動配置）として表現され、標高0mの平面（ワールドY=0）に貼られる。

海面の `SeaMaterial` は `Custom/WaterLit`（本体は `Assets/Shaders/Water.hlsl`）を使う。深度色・屈折・岸の泡と、手続き法線によるさざ波をURPのPBRで描画する。`_Smoothness` は0.92で、太陽の細かな光沢や反射の明るさは圧縮しない。フォグはフラグメントのワールド位置から `InitializeInputDataFog` で計算し、PBRの結果へ合成する。大きな海面メッシュの頂点で飽和したフォグ係数を補間すると、カメラの回転やメッシュの分割によって近景まで白くなるため、頂点フォグは使用しない。遠景の霞は天気の開始・終了距離に従って残る。湖・川も同じシェーダーを共有する。

川は `RiverSurfaceManager` が `GET /api/v1/terrain/rivers` から取得した範囲ポリゴンを覆う格子面メッシュ（頂点Y＝水面プロファイル標高、[D_地形形状](D_地形形状.md) §D.11.4）として生成し、海面マテリアルの複製に流れモード（`_FlowEnabled`＝頂点UV2の流下方向へさざ波・泡を流す）を設定して描く。深度オフセットと水際の扱いは以下の湖と同じ。

海面以外の水面（湖など）は `WaterSurfaceManager` が `GET /api/v1/terrain/water` から取得したポリゴンを、各水面の `water_level`（Y標高）に置いた水平メッシュとして生成する。マテリアルは海面板のものを借用（借用できなければ `Custom/DepthOffsetLit` のフォールバック）し、海面と同じ深度オフセット階層に乗せる。したがって以下の海面についての説明は、標高0m以外の水面にもそのまま当てはまる（湖底=per-cellタイルとのZ-fighting回避、岸でのワールドYによる自然な前後関係）。水面はマップ固有の静的データなので、海岸線取得と同じセッション初期化タイミングで一度だけ生成する。地形システムはこのオブジェクトを直接管理しないが、深度バイアスの設計が海面の見え方に直結するため、ここに仕様を明記する。

水面フォグの回帰検証は `unity/Tests/WaterFog/run-unity.ps1`。独立したUnityプロジェクト（`Library/WaterFogQA`）で、近景・遠景それぞれ4方位の視点を描画し、2三角形の海面と細分化した海面の結果を比較する。近景に霧がかからないこと、遠景の霧が残ること、HDRの光沢が残ること、シェーダーにコンパイルエラーがないことを確認する。結果は `result.txt`、比較画像は同ディレクトリのPNGに出力する。

### 課題: per-cell地形と海面のベースYが揃うことによるZ-fighting

per-cellタイル（Far / Near / Dynamic）は、ベースY（`AttachTerrainTile` が設定する `-SeaFloorDepthSpan`）とオフセット正規化の組み合わせにより `worldY = 実標高` となる。標高0m（海面）の点はワールドY=0に来て、海面板（ワールドY≈0）と深度が完全に一致する。このままだと遠距離・低角度カメラで深刻なZ-fightingが発生する。

### 解決策: シェーダーの深度オフセット階層

地形シェーダーと海面シェーダーで `Offset` コマンドを設定し、同一深度での描画順序を制御する。`Offset factor, units` は正値でカメラから遠ざけ（奥）、負値で手前に寄せる。値が大きいほど奥に描画される。

| 描画対象 | シェーダー | Offset | 役割 |
| --- | --- | --- | --- |
| 建物・道路・フェンス等 | `Custom/DepthOffsetLit` | `-1, -1` | 地形より手前 |
| 海面・水面（湖など） | `Custom/DepthOffsetLit` | `-1, -1` | 地形より手前（水面が水底を覆う） |
| 地形（Far/Near/Dynamicのper-cellタイル） | `Custom/DepthOffsetTerrainLit` | `1, 1` | per-cell地形 |
| 超遠景陸地メッシュ（UltraFar） | `Custom/DepthOffsetSimpleLitFar` | `4, 4` | 最奥 |

同一ワールド深度での優先関係は `オブジェクト ≧ 海面 ＞ per-cell地形 ＞ UltraFar陸地メッシュ` となる。海面と地形の深度差バイアスが `(2, 2)` 以上に拡大し、海面レベルでは海面が地形より手前に描画される。これにより海岸線が地形の標高0等高線に沿って正しく形成される。陸地（地形が海面より高い領域）では地形がワールドYの差で自然に手前に描画される。

海面マテリアルには必ず `Custom/DepthOffsetLit`（または同等の負のOffsetを持つシェーダー）を適用すること。Offsetなしのシェーダーに誤って差し替えると、遠景でもZ-fightingが再発する。

## 超遠景（UltraFar）の陸地シルエットメッシュ

UltraFarに求められるのは「遠くに見える陸地のシルエット」だけ（建物・道路は非表示、地形は編集版に応じて更新）である。これを**マップ全体1枚のUnity Terrainハイトマップ**で表すのは不向きで、以下の問題があった。

- UltraFarの解像度は極めて粗い（マップ全体で解像度33、サンプル間隔は数百m）。標高0m付近の地形がうねって平らな海面板（ワールドY=0）を突き抜け、本来は海であるべき沖合に陸が飛び出す（カメラを低く下げて浅い角度で海を見ると顕著）。
- かつてはUltraFarだけベースY=`-10`に下げてこの突き抜けを力技で隠していたが、その10mの落差で標高0〜10mの陸地が海面下に沈み、UltraFarの陸地が本来より小さく描画される（Farセルの端が崖状の海岸線になる）問題があった。

そこで現在のUltraFarは、Unity Terrainをやめ、**バックエンドの海岸線ポリゴンから生成した陸地シルエットメッシュ**として描画する（`UltraFarLandMeshBuilder` / `TerrainManager.BuildUltraFarTerrain`）。

### 生成方法

海岸線は近景マップ（`near_map`、10m間隔）から精密に抽出された陸地境界ポリゴンで、`GET /api/v1/terrain/coastline` で取得して `CoastlineStore` に保持される（バックエンドの海岸線抽出を参照）。陸地のAABBをグリッド（既定80m間隔）に切り、各グリッドセルを海岸線でクリップして陸地ポリゴンを切り出す。

- **海岸線クリップ**: 各セルの辺をたどり「陸側コーナー」と「海岸線との交差点」を順に拾うマーチングスクエア的手法で、陸地部分のポリゴンを得る。交差点はグリッド頂点の符号付き距離（陸+/海−）の符号反転位置を線形補間で求めるため、海岸線はグリッド解像度より細かく滑らかに出る。
- **符号付き距離の一括計算**: グリッド頂点ごとに海岸線の全辺を調べると、所要時間がグリッド頂点数×海岸線の頂点数に比例し、海岸線の入り組んだ広い都市では1分以上かかる。この生成は初期ロードで地形タイルより先に行うため、その間は初期ロードが完了しない。そこで `CoastlineStore.SampleSignedDistanceGrid` がグリッド全体をまとめて求める。陸/海の判定はグリッドの行ごとに海岸線との交差を数える走査線方式、距離は空間ハッシュで近傍の辺だけを調べる方式とし、グリッド間隔より遠い頂点の距離はグリッド間隔で打ち切る。補間に使うのは符号が反転する辺の両端だけで、その辺は海岸線と交わるため両端から海岸線まではグリッド間隔以内に収まる。したがって打ち切っても生成されるメッシュは全辺を調べた場合と同一になる。
- **海はメッシュを作らない**: 陸地外にはジオメトリを置かないため、海は既存の海面板がそのまま担う。粗いハイトマップが海面板を突き抜ける問題やZ-fightingが**原理的に発生しない**。
- **起伏**: 各頂点のYを far_map 高さでサンプリングして粗い起伏を表現する。海岸（標高0m付近）の頂点は自然に海面近くに来る。全頂点を微小オフセット（既定1m）持ち上げ、海面板の上に保つ。
- **スムース法線**: 頂点はグリッドセルごとに個別に追加されるため、セル境界の同一ワールドXZ位置に重複頂点ができる。`Mesh.RecalculateNormals`（面法線を頂点で平均するが重複頂点は溶接しない）だとセル境界で法線が不連続になり、遠景陸地がファセット（多面体）状にのっぺり見える。そこで、面積重み付きの面法線を「同一XZ位置」へ集約してから正規化した**スムース法線**を頂点に与える（頂点自体は溶接せず法線値だけを共有）。交差点・コーナー頂点は隣接セルで同一座標が決定論的に再現されるため、量子化キーで確実に一致する。
- **深度順序**: メッシュは `Custom/DepthOffsetSimpleLitFar`（`Offset 4,4`）を使い、per-cellタイル（`1,1`）・海面（`-1,-1`）より奥に描画する。カメラ近傍でper-cellタイルがこのメッシュに重なっても、常にper-cellが手前で勝つ。
- **タイルへの突き抜け対策（ロード済みセルでの沈み込み）**: UltraFar メッシュは far_map 由来の粗い起伏を持つため、per-cell タイル（特に near_map 由来の Near/Dynamic タイル）とは起伏の激しい場所で数十mの高低差が生じ、タイルの上に突き出て斑点状に見えることがある。これを防ぐため、「per-cell タイルが実際にロードされている（可視の）セル」を 1セル=1テクセルの R8 マスクテクスチャ（`_LoadedCellMask`）にしてシェーダーへ渡し、頂点シェーダーがマスクの立っているセルの頂点を `_FarSinkAmount`（既定 50m）地中へ沈める。マスクは `TerrainManager.UpdateLoadedCellMask` が毎フレーム `terrainTiles` の現状から再構築する（内容が前回と同じなら GPU アップロードはスキップ）。タイルの無いセルは沈めないため、カメラ移動やロード遅延で海色の穴が開くことは原理的にない（タイル未ロードの間は UltraFar がそのまま見えるだけ）。
- **マテリアルとテクスチャ**: per-cell タイルと同じメインテクスチャを同じタイリングで適用する。頂点のワールド座標 `(X, Z)` をそのまま UV 座標として設定し、ワールド座標ベースでマッピングする。**法線マップは設定しない**（SimpleLit 系の `_BumpMap` に地形用のカラーテクスチャが流用されると不正な法線で陰影が暗く濁るため。遠景専用なので法線ディテールは不要）。
- **色**: メッシュ全体を1サブメッシュ・1マテリアルで描き、`_BaseColor` は通常色（テクスチャ素の色。テクスチャ未設定時のみ `defaultTerrainColor` のフラット色）にする。

海岸線がまだロードされていない場合（海岸線なしのマップ）は、マップ全体を陸として平坦なメッシュを張るフォールバックになる。通常フローでは `TerrainManager.FetchCoastline` がUltraFar生成より前に完了する（セッション開始・`session:reload`・全量リロードのいずれの経路でも、地形ロードの前に直接呼ぶ）。

## 崖（急傾斜）の岩テクスチャ描画

per-cellタイル（Far / Near / Dynamic）の地形シェーダー `Custom/DepthOffsetTerrainLit` は、傾斜（`1 - ジオメトリ法線のY成分`）が閾値を超えたピクセルに岩肌のアルベド＋法線マップをブレンドして崖を表現する（実装は `Assets/Shaders/TerrainCliffRock.hlsl`）。傾斜判定には地面の法線マップで擾乱される前の**ジオメトリ法線**を使う。擾乱後のシェーディング法線で判定すると、法線マップの偏りにより同じ傾斜でも特定の向きの斜面だけ岩化する方向依存の描画バグになるため。

- **トリプラナーマッピング**: 岩テクスチャはUV座標ではなくワールド座標の3軸投影でサンプリングする。Unity Terrain標準のXZ平面投影だと垂直に近い崖面でテクスチャが極端に引き伸ばされるが、トリプラナーなら崖面にも正対投影される。3軸の重みは法線から求め、4乗でシャープ化して投影境界のぼやけを抑える。
- **ライティング前のブレンド**: 岩ブレンドはライティング計算の前にアルベド・法線・スムースネスへ介入する。これにより崖にも太陽光の陰影・法線マップ由来の凹凸・スペキュラが正しく乗る。実現方法は、URPの `TerrainLitPasses.hlsl` にあるライティング呼び出し `UniversalFragmentPBR`（8引数オーバーロード・1箇所のみ）を同名マクロでラッパー関数に差し替えるフック（URPソースのコピー不要）。
- **境界のノイズ乱し**: 傾斜閾値にワールド座標ベースのノイズを加算し、草と岩の境界が等高線状の均一な帯にならないようにする。
- **低地（海岸・海面下）の岩化**: 傾斜条件とは別に、標高が低い土地は傾斜に関係なく岩へ寄せる（草が生えない海岸・浅瀬・海面下を岩肌で表現）。開始標高（既定2m）から最大標高（既定0m=海面）へ徐々にブレンドし、それ以下（海面下）は一律で岩。汀線が真横一直線の帯にならないよう開始標高もノイズで揺らす。傾斜マスクと標高マスクは `max` で合成する（どちらかの条件を満たせば岩）。
- **設定**: 閾値・遷移幅・ノイズ・タイリング周期(m)・法線強度などは `TerrainManager` の `Terrain Cliff Rock Settings`（Inspector）で調整でき、タイルごとの `materialTemplate` に適用される。岩テクスチャはInspector未設定時 `Resources/Textures/cliff-rock-albedo` / `cliff-rock-normal` を自動ロードし、見つからない場合も単色フォールバックで動作する。
- **適用範囲**: 同じシェーダーを使うFar / Near / Dynamicの全ティアに自動適用され、ティア境界でも色調が連続する。超遠景（UltraFar）の陸地メッシュも同じHLSLを読み込むため同じ岩ブレンドが掛かる（形状が粗いので崖の細部は出ない）。
- **地表種別による違い**: 岩テクスチャの色に地表種別ごとの色を掛ける（砂漠=砂岩色、濃い草地=苔色など）。また低地（標高による岩化）の分だけは、種別の割合に応じて砂の色へ置き換える（砂漠・乾燥地の砂浜と、浅い海の砂の海底）。傾斜による岩と川床は置き換えない。

## 地表のスタイライズ表現

per-cellタイルの地形シェーダー `Custom/DepthOffsetTerrainLit`（実装は `Assets/Shaders/DepthOffsetTerrainLitMacroVariation.hlsl`）と超遠景の `Custom/DepthOffsetSimpleLitFar` は、単一テクスチャの露骨なタイリングを隠し、写真テクスチャの精細さに頼らず「破綻なく整った」非写実（スタイライズ）の地表を作るための層を持つ。アート方向はPC／ハイエンド優先。

値は2種類に分かれる。地表種別（[D_地形形状](D_地形形状.md) §D.15）で変わる値は `GroundCoverPalette`（`Resources/Terrain/GroundCoverPalette.asset`。種別ごとの `GroundCoverProfile`）が持つ。地面テクスチャとタイリング、テクスチャの使い方、スムースネス、手続きの下地色3色とパッチの周期、ディテール法線と風紋の強さ、照明後の大きな濃淡と色補正の色、岩の色味と砂浜がこれに当たる。アセットが無い・種別が欠けている場合はコードの既定値（`GroundCoverProfile.CreateDefaults`）で描く。種別に依存しない値（大きな濃淡の周期、色補正の標高範囲、ディテール法線の周期、崖の判定）は `TerrainManager` の Inspector に残る。`TerrainManager` は都市の地表種別のプロファイルを選び、`GroundCoverProfile.ApplyTo` でタイルごとの `materialTemplate`・超遠景・都市外背景のマテリアルへ同じ値を設定する。Play中にパレットや Inspector の値を変えると、次のフレームで表示中の地形へ反映する（エディタで調整するため）。Inspector の `groundCoverPreview` に種別を入れると、都市の種別の代わりにその種別で描ける（同じ場所で種別を見比べるため）。

適用先の `materialTemplate` は `ApplyTerrainOffsetMaterial` がタイル生成時に必ずクローンする「タイルごとの個別インスタンス」（名前サフィックス ` (TileInstance)` で識別）で、共有アセットを直接書き換えない。`Terrain.basemapDistance` は実質無効（100000m）に設定する。既定（1000m）のままだと遠方タイルがベースマップ用シェーダーで描画され、以下の手続き層や深度Offsetが適用されなくなるため。

- **手続きベースアルベド**: 地面の基本色そのものを多スケールノイズ（fbm）で生成する。大局モザイク（低周波fbm）で下地色A↔Bのパッチを切り替え、細かい斑（高周波fbm）で明色Cを薄く混ぜてベタ塗り感を消す。`_ProceduralGroundBlend`（0=テクスチャ, 1=完全手続き。草原は0.85）でTerrainLayer由来のサンプル色と混合でき、1なら拾い物テクスチャの反復が完全に消える。崖の岩ブレンドはこの手続きベース色の上に岩を lerp するので崖の非退行が保たれる。ライティング前（アルベド）に適用する。
- **地面テクスチャの使い方**: 草原・濃い草地は草のテクスチャの色をそのまま混ぜる。砂漠・雪原・乾燥地はテクスチャの色を持ち込まず、平均輝度との比（濃淡）だけを下地色へ掛ける（`_GroundTextureColorWeight`。乾燥地は色を一部だけ混ぜる）。草の緑や写真の色味を手続きの配色へ漏らさないためで、色の差が小さい砂のテクスチャは濃淡を強調して使う（`_GroundTextureContrast`）。基準の平均輝度はプロファイルの `textureLuminance` に書き、テクスチャを差し替えたら測り直す。
- **風紋**: 砂漠（と弱く雪原）で、一方向に並ぶ細かい波を法線に与える。向きと位相をノイズで揺らして縞に見せず、画面上で波長が潰れる遠景のモアレを避けるためカメラから40〜90mで消す。
- **マクロバリエーション**: ワールド座標の3オクターブ値ノイズ（fbm）で地面の明度とティントを大スケール（既定 数百m 周期）に揺らし、同一テクスチャの反復による単調さを崩す。ライティング後の最終色に適用する。
- **カラーグレード（標高・傾斜ベースの色ランプ）**: 最終色に、標高で低地色↔高地色を補間したティントを乗算し、急斜面にはアースカラーを寄せる。傾斜は面法線を画面微分（ddx/ddy）から復元して求めるため頂点法線に依存しない。スタイライズの肝で、標高・スロープに応じた統一感のある色設計を与える。ティント各色は≈1.0付近を前提にした乗算なので明度を大きく損なわない。強度0で従来の見た目に戻る。
- **平地の手続きディテール法線**: 法線マップテクスチャを使わず、ワールドノイズの勾配で微小な凹凸をライティング前のワールド法線へ与える。完全マットになりがちな平地に、太陽角度の変化で動く柔らかいスペキュラ／陰影の起伏を出す。急斜面（崖）では平坦度で弱め、崖の岩法線ブレンドと競合させない。強度0で無効。
- **スムースネス**: 完全マット（0）をやめ、弱いスペキュラ（草原は0.15、雪原は0.35）を持たせ、上記ディテール法線と併せて陰影に立体感を出す（`ApplyDefaultTerrainMaterial` の TerrainLayer smoothness、超遠景は `_Smoothness`）。
- **川床・川岸（川マスク）**: `RiverSurfaceManager` が川（[D_地形形状](D_地形形状.md) §D.11）から CPU で生成する全域マスク `_RiverMask`（RG8。R＝川床、G＝カーブ内岸の砂地）をグローバルテクスチャとして渡し、`TerrainRiverBank.hlsl` がプレライティングで参照する。川床は崖の岩ブレンドへ合流させた上で濡れた暗色と高めのスムースネスを乗せ、砂地は範囲の外側の岸帯（既定16m）でベース色を砂色へ寄せる（曲率が強い内岸ほど濃く、距離で減衰）。マスクのテクセルは水面メッシュと同じ4m格子で、川群の外接矩形だけを覆う。色・帯幅・曲率基準は `RiverSurfaceManager` の Inspector（`River Bank Appearance`）。川が無いマップでは無効化され既存の見た目に影響しない。

地面のベース色を手続き生成にしているため、テクスチャ1枚の反復に依存せず繰り返しを消せる。地面テクスチャは1マップ1枚（種別のプロファイルが指定する）で、草原と濃い草地は草、砂漠と雪原は砂、乾燥地は枯れ草のテクスチャを使う（`Resources/Textures/README.md`）。法線マップは使わず、凹凸はディテール法線と風紋で出す。

地表種別ごとの見た目の回帰検証は `Tests/TerrainAppearance/run-unity.ps1`。5種をTerrainと遠景メッシュで描いて平均色の一致と種別どうしの見分けを検査し、起伏と海岸を付けた近景の比較画像 `ground-cover-sheet.png` を出力する。


## 生成処理の協調中断

区画・建物・道路・地形の生成ステップは共通スケジューラーへContinueを返し、同じフレームの予算が残れば他の処理の後で再開する。nullによる次フレーム待ちは周期処理・アイドル・通信のポーリングに用いる。共通ポンプの実行順と計測方法は [Unityの差分ロード](K_Unity差分ロード整理.md) を参照する。フレーム予算は増やさず、細かい生成ステップを予算内にまとめることでロード時間を短縮する。


## 範囲配置の森林

木の範囲配置（種類1/2）はForestRendererでGPU上に散布し、CPUの個体候補・高さ取得・行列生成を省く。約100mを境に通常モデルからFar樹冠へ切り替え、近景と中景で同じ配置を使う。常駐セルと1500mの描画上限は維持する。地形タイルのGPU高さを直接参照し、地形・配置・障害物が変わった小区画だけ再生成する。個別配置・他のプロップとGPU非対応時は従来の候補経路。予算・移行帯・削除選択は[M_地形プロップ](M_地形プロップ.md) §M.4参照。

## 路面標示のLODと画像予算

道路の形状LODと標示画像の解像度は別々に選ぶ。`RoadMarkingContext` の距離・横断座標をClose/Normalの全固定区間で共有するため、約128mの区間境界やLOD切替で破線の位相をリセットしない。Farの簡易帯では標示を省略する。形状切替前にもシェーダーで400〜540mの標示をフェードさせる。交差点も同じ距離フェードを使う。

`RoadMarkingAtlas` は32m四方の画像ページを256 / 512 / 1024pxで保持する。投影サイズが240px超で512px、640px超かつClose退出距離160m未満で1024px。降格側は180 / 500pxとし、微小なズーム往復による再生成を抑える。選択では遠近両投影を扱うが、Farで細部を省く距離規則は共通である。

| プール | R8での最大ページ数 | 用途 |
| --- | ---: | --- |
| 256px | 512 | 小さく映る標示・上位プール満杯時の代替 |
| 512px | 128 | 通常表示 |
| 1024px | 24 | 接写 |

各プールは必要時にTexture2DArrayと生成用RenderTextureを確保する。R8非対応ならRGBAへ切り替え、各ページ数を1/4にする。ミップ全段と生成用画像も予約量に含める。ページ表はGPU画像・Texture2DのCPUコピー・更新用Color配列の合計を4MiB以下に制限し、画像プールとの合計予約量を128MiB以内とする。ドライバーの管理領域やアラインメント、道路メッシュ、標示計画のCPU頂点はこの画像予算に含まない。F8には予約量・ページ表・ページ数・待機・焼き込み・再利用・追い出しを表示する。

ページは内容署名と32m区画で共有し、LODの再生成でも同じ内容なら再利用する。表示中・退避中で画像予算を分けない。使用を終えたページを追い出す際は参照するページ表を無効化してから再利用し、他の道路の標示が現れないようにする。視野内の必要ページを先に保護し、上位プール満杯なら下位へ縮退する。全プールが不足する場合は複雑な標示を省略し、画像を使わない側線・車線境界線は維持する。

可視候補は共有SpatialHashで検索し、視錐台とNormal退出距離550mで絞る。候補収集と焼き込みはRenderWorkSchedulerへ譲りながら進め、GPUへ送る焼き込みは1フレーム2ページ・基底画像1,048,576画素までとする。画像待ちを初期ロードの完了条件にはしない。この制限はGPUの実行時間そのものを保証するものではなく、巨大都市のFPSは対象機器での計測が必要である。

地形の常駐セル数は画像容量の上限として扱わない。高密度の1セルでも上記予算を守る。RenderObjectCacheのメッシュ予算とは独立し、都市切替ではページ表・画像プール・派生材質を解放する。
