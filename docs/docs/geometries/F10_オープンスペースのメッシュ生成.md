# オープンスペースのメッシュ生成

区画の形から配置計画を作り、面メッシュと実寸の装飾パーツを組み合わせる。完成モデルの引き伸ばしは行わない。

| バリアント | model_type | 内容 |
| --- | --- | --- |
| 3001 駐車場 | MODEL_PARKING = 10 | 車路・駐車枠・車止め |
| 3002 駅前ロータリー | MODEL_ROTARY = 11 | 周回車路・中央島・乗降上屋 |
| 3003 舗装広場 | MODEL_MODULAR_GROUND = 4 | アスファルト面のみ |
| 3004 公園 | MODEL_PARK = 12 | 舗装園路・芝生・樹木・ベンチ |

全件がTYPE_OPEN_SPACE、building_shape=full、full_coverage=yes、draw_floor=yes、1階・階高0.3mである。公園の建設費係数は0.08、耐用年数は50年。市場・雇用には参加しない。

## 配置と描画の分離

`OpenSpaceLayout.Create` は建物輪郭・生成方式・visual_variant2から、素材別の面、装飾の位置と向き、駐車枠、アクセスセルを作る。SHAPE_FULLの建物輪郭は区画全面で、頂点0→1が接道側に正規化されているため、区画のロード順に依存せず方向を決められる。

`OpenSpaceBuildingMeshBuilder` は計画をメッシュ化する。地面は共通の地形追従面、模様・園路は細分化した面、装飾はノード変換を含めて結合したFBXを使う。木や上屋は配置点に剛体として接地するため、急斜面では足元の一部が浮く場合がある。

パーツはa{variant}/0に置く。visual_variantは既存の100刻みの閾値走査で各パーツを選ぶ。壁を持たないためmid-w1は不要。Closeは同じ計画のパーツを_closeに差し替え、Normalと位置を変えない。

## 共通の区画内判定と決定論性

接道辺と内側方向に沿う2.5mセルを使う。候補の全頂点・辺の中点が敷地内にあり、辺が外周を横切らない場合だけ採用する。パーツの実FBXの回転後バウンディングボックスにも同じ包含判定を行う。

セル・隣接方向・候補形状の走査順は固定する。境界の許容差は1mmで、回転・平行移動の丸め誤差を吸収する。装飾の選択はセル番号とvisual_variant2の固定ハッシュによる。エージェントID、共有乱数、現在時刻、描画LODは使わない。

装飾の探索範囲は接道側の最大320m四方・128×128セルに制限する。駐車枠・公園装飾は各512個までで、広い敷地の残りには地面のみを描く。地面全面とクリック可能領域はこの上限で縮まない。

## 駐車場

入口に近いセルを起点に、幅5mの縦車路と15m周期の横車路を確保する。入口からつながる車路に面する2.5×5m単位の駐車枠を配置する。白線は枠から内側へ少し下げて描き、奥側に車止めを置く。凹区画で車路のつながらない部分や、奥行きが取れない場所は舗装の余白になる。

枠数は見た目だけに使い、駐車需要・課金・車両シミュレーションには使わない。車両モデルは配置しない。

## 駅前ロータリー

敷地内に収まるカプセル形状を探索し、面積の大きいものを採用する。外周半径7.5〜25m、直線部の半長0〜30mの候補数を制限して探す。外周から5m内側を中央島とし、間にアスファルトの周回車路を張る。

中央島を避ける幅5mの入口車路をセル探索で接続する。成立しない場合は周回路を省き、舗装された車寄せとして地面を残す。敷地外周のくびれをそのまま縮小して車路にすることはなく、三角形・凹区画の端は広場になる。十分な余白があれば上屋を1つ置く。駅の入口座標との自動整列は行わず、接道方向が基準になる。

## 公園

入口から到達可能なセルのうち敷地中央に近いものを中心とし、四方向の端と入口へ幅2.5mの園路を通す。探索木を辿るためL字区画の外側へ飛び出さない。12×12セル以上あり、内周がすべてつながる場合は周回園路を加える。

園路の隣に少数のベンチを園路へ向けて置き、離れたセルに5m周期で樹木候補を置く。一部をハッシュで省いて芝生の余白を残す。小区画は園路だけ、セルが置けなければ地面だけになる。

公園も区画全面が徒歩・自動車共通の通過可能領域である。園路や植栽の形状は経路探索を制限せず、閉じた柵や池は配置しない。通行の意味は [地区と土地区画](../economics/4_地区と土地区画.md) §4.8を参照する。

## パーツ規約

| パーツ名 | 用途・寸法 |
| --- | --- |
| floor | 地面素材。3001/3003はアスファルト、3002はコンクリート、3004は芝生 |
| site_asphalt / site_paving / site_grass / site_marking | マテリアル参照専用。形状は描画しない |
| site_stop | 車止め。幅1.7m・奥行き0.36m・高さ0.14m |
| site_shelter | 乗降上屋。幅5m・奥行き2.8m・高さ2.86m |
| site_bench | ベンチ。幅1.9m・高さ0.9m、Unity +Zが正面 |
| site_tree | 樹木。幅約2.6m・高さ約4.85m |

装飾は水平中心・接地0を原点とし、スケールせず配置する。Blender -YがUnity +Z。正本はgenesis-gallery/library/buildings.blend、著作ジョブはpipeline/jobs/build_open_spaces.py。全13パーツで既存マテリアルを共有する。バリデータはsite-originと頂点予算を検査する。

`site_tree` は144三角形で、樹冠に滑らかな法線、幹に平面法線を使う。幹のPROP_BARKと葉のPROP_LEAF_GREENは森林用の材質を共有する。葉は既存の256×256葉色画像をsRGBで読み、拡散色は白、粗さ0.9、金属度0、UVは2m基準とする。葉カードや追加サブメッシュは使わない。材質の仕様は [地形プロップ](M_地形プロップ.md) §M.5.2を参照する。

## LOD・状態・コライダー

Farは高さ0.3mの板。工事中・解体中は土マウンドのみ、倒壊時は瓦礫マウンドのみで、足場・クレーン・躯体片を付けない。停止中は既存の停止状態の表示を使う。

コライダーは地形に沿う地面と、実際に配置した装飾のバウンディングボックスから生成する。装飾が置けない区画でも地面をクリックできる。生成メッシュと共有FBXを区別し、一時メッシュは結合後に解放する。

## 検証・ギャラリー

unity/Tests/Buildings/run-open-space.ps1は独立Unityで実FBXと本編DLLを読み、長方形・台形・L字・三角形・細長い区画・微小区画・深い切欠きで包含、再生成の一致、回転後の台数、メッシュとコライダーを検査する。画像はunity/Temp/OpenSpaceQAに出力する。

同じ検証で長方形見本の配置をgenesis-gallery/pipeline/layoutsへ書き出す。ギャラリーはこの計画を読み、Python側に配置器を複製しない。配置器の変更後は検証で見本を再出力し、build_gallery.py --only a300を実行する。
