# オープンスペースのメッシュ生成

区画の形から配置計画を作り、面メッシュと実寸の装飾パーツを組み合わせる。完成モデルの引き伸ばしは行わない。

| バリアント | model_type | 内容 |
| --- | --- | --- |
| 3001 駐車場 | MODEL_PARKING = 10 | 車路・駐車枠・車止め |
| 3002 駅前ロータリー | MODEL_ROTARY = 11 | 周回路・島・バス乗降場・縁石で上げた歩道と小物 |
| 3003 舗装広場 | MODEL_MODULAR_GROUND = 4 | アスファルトの地面パネルのみ（本書のビルダーでは描かない） |
| 3004 公園 | MODEL_PARK = 12 | 舗装園路・芝生・樹木・ベンチ |

上の4件はいずれもTYPE_OPEN_SPACE、building_shape=full、full_coverage=yes、draw_floor=yes、1階・階高0.3mである。公園の建設費係数は0.08、耐用年数は50年。市場・雇用には参加しない。

本書のビルダー（`OpenSpaceBuildingMeshBuilder`）が描くのは、MODEL_PARKING・MODEL_ROTARY・MODEL_PARKの3001・3002・3004である。3003はMODEL_MODULAR_GROUNDなので、`BuildingMeshBuilder` はモジュラー建物の生成器へ振り分け、[地面アセットのメッシュ生成](F2_地面アセットのメッシュ生成.md) の方式で描く。a3003/0にはfloorしか無いため、区画の形に沿ったアスファルトの地面パネルだけになる。Far・工事中・解体中・倒壊時の表示は本書のオープンスペースと同じである。

同じTYPE_OPEN_SPACEでも立体駐車場3005は2〜8階の建物（MODEL_MODULAR_FLAT・building_shape=office・full_coverage無し）であり、本書のビルダーではなく [[F1_モジュラー建物のメッシュ生成]] の方式で描く。パーツは通常の解決順（a3005 → b512 → common）に従い、専用フォルダが無ければ公共建物の共通パーツになる。

造成工事の3006（整地工事）・3007（埋立工事）もTYPE_OPEN_SPACE（building_shape=full、1階・階高0.3m、MODEL_MODULAR_GROUND）だが、本書のビルダーでは描かない。範囲の区画を一時的に使う公共工事で、完了すると同時に主体と区画が消えるため、稼働中（STATUS_ACTIVE）にならず完成形を持たないからである。full_coverage・draw_floor も持たない。工事中は土だけの工事現場として描かれ（[F5_工事中建物のメッシュ生成](F5_工事中建物のメッシュ生成.md) §7）、完了後に残るのは書き換えた地形と埋立地の岸壁である（[D_地形形状](D_地形形状.md) §D.17）。

## 配置と描画の分離

`OpenSpaceLayout.Create` は建物輪郭・生成方式・visual_variant2から、素材別の面、装飾の位置と向き、駐車枠、アクセスセルを作る。SHAPE_FULLの建物輪郭は区画全面で、頂点0→1が接道側に正規化されているため、区画のロード順に依存せず方向を決められる。

`OpenSpaceBuildingMeshBuilder` は計画をメッシュ化する。地面は共通の地形追従面、模様・園路は細分化した面、装飾はノード変換を含めて結合したFBXを使う。木や上屋は配置点に剛体として接地するため、急斜面では足元の一部が浮く場合がある。

計画の面は材質・外周・穴（内側の輪）・天端の高さ・側面の材質を持つ。穴のある面は制約付きドロネー分割、それ以外は耳切りで三角形にし、地形格子で切り抜いて天端の高さに置く。UVは局所XZ座標（1m=1）。側面の材質を持つ面は縁石で上げた面で、外周（穴は内側向き）に沿って地面の0.05m下から天端まで側面を張る。側面も1.25m以下に分けて地形に沿わせる。装飾は置いた位置を覆う上げた面の天端に載せる。

パーツはa{variant}/0に置く。visual_variantは既存の100刻みの閾値走査で各パーツを選ぶ。壁を持たないためmid-w1は不要。Closeは同じ計画のパーツを_closeに差し替え、Normalと位置を変えない。

## 共通の区画内判定と決定論性

接道辺と内側方向に沿う2.5mセルを使う。候補の全頂点・辺の中点が敷地内にあり、辺が外周を横切らない場合だけ採用する。パーツの実FBXの回転後バウンディングボックスにも同じ包含判定を行う。

セル・隣接方向・候補形状の走査順は固定する。境界の許容差は1mmで、回転・平行移動の丸め誤差を吸収する。装飾の選択はセル番号とvisual_variant2の固定ハッシュによる。エージェントID、共有乱数、現在時刻、描画LODは使わない。

装飾の探索範囲は接道側の最大320m四方・128×128セルに制限する。駐車枠・公園装飾は各512個までで、広い敷地の残りには地面のみを描く。地面全面とクリック可能領域はこの上限で縮まない。

## 駐車場

入口に近いセルを起点に、幅5mの縦車路と15m周期の横車路を確保する。入口からつながる車路に面する2.5×5m単位の駐車枠を配置する。白線は枠から内側へ少し下げて描き、奥側に車止めを置く。凹区画で車路のつながらない部分や、奥行きが取れない場所は舗装の余白になる。

枠数は見た目だけに使い、駐車需要・課金・車両シミュレーションには使わない。車両モデルは配置しない。

## 駅前ロータリー

接道辺の中点を原点、接道辺の向きをs、敷地の内側をtとする局所座標で、多角形の膨張・収縮と集合演算（NTS。重なり演算は頑健なOverlayNG）から形を作る。敷地の頂点は0.1mm単位にそろえ、接道辺をちょうど t=0 に載せる。すべて局所座標で決まるので、敷地を回転・平行移動しても同じ形になる。左側通行なので周回は上から見て時計回りで、後方（駅側）の外周の乗降場にバスが左側の扉を付けて停まる。駅の入口座標との自動整列は行わず、接道方向が基準になる。

1. **周回路の外周** 敷地を左右の歩道幅（3.5〜5m）だけ内側へ縮め、前面の歩道（4.5〜6m）と駅側の広場（7.5〜10m）の奥行きを切り、左右の余白もさらに0〜2.5mずつずらす。島を置けない細い張り出し（L字の腕など）は周回路から外して広場に残し、四隅をそれぞれ別の半径（基準6〜13mの0.55〜1.45倍）で丸める。
2. **島** 外周から周回路の幅7m（停車帯と走行車線）だけ内側で、角をさらに1.5〜4m丸める。細い継ぎ目で切れた部分も8m²以上なら島として残す。
3. **バス乗降場** 後方の外周を長さ12〜26mにわたって3m外へ広げる。奥に上屋と通路を取れる4.2mが敷地内に残る長さだけ広げる。
4. **出入口** 接道辺と周回路の前面が重なる範囲に置く。十分な幅があれば入口（右）と出口（左）の片側1車線（4.8m）に分け、狭ければ対面2車線（7m）を1本にする。周回路・乗降場・出入口を合わせた形のくぼんだ角は半径3mで丸め、前面道路との角にも四分円のすみ切りを足す。
5. **面** 周回路（アスファルト）を地面に張り、残りの歩道・広場と島は縁石で0.15m上げる。天端は広場が舗装、島が芝で、車道に接する0.3mと島の縁は縁石の帯にする。
6. **路面標示** 周回路の中心の破線（3m・間隔6m）、走行車線の時計回りの矢印4つ、出入口の横断歩道と出口の停止線、乗降場の黄色い枠。横断歩道の両端と乗降場の縁石から0.6〜0.9mには黄色い誘導ブロックを張る。
7. **小物** 島の中央に時計塔（周りを舗装）、島の樹木と左右端の街灯。乗降場の縁石沿いに上屋を6.6m間隔で並べ、列の端に自販機、乗降場の手前にタクシー乗り場の標識。外周の縁石沿いに14m間隔の街灯と歩道のベンチ、車道から離れた広場の余白に樹木と植栽ます、出入口の両脇に車止め。装飾は占有範囲が歩道・島に収まり、既に置いたものと重ならない場合だけ置く。

外周・島・出入口が成立しない場合は歩道と広場の幅を縮めて一度だけ試し直す。それでも入らない敷地は、接道辺沿いに奥行き5mの乗降場（車寄せ）を切り、残りを縁石で上げた歩道にして、上屋・街灯・ベンチ・自販機を置く。接道辺が短いか奥行きが無い敷地は地面だけになる。

歩道幅・広場の奥行き・四隅の丸み・左右の余白・島の丸み・出入口の分け方と位置・小物の間引きは visual_variant2 の固定ハッシュで決まる。

## 公園

入口から到達可能なセルのうち敷地中央に近いものを中心とし、四方向の端と入口へ幅2.5mの園路を通す。探索木を辿るためL字区画の外側へ飛び出さない。12×12セル以上あり、内周がすべてつながる場合は周回園路を加える。

園路の隣に少数のベンチを園路へ向けて置き、離れたセルに5m周期で樹木候補を置く。一部をハッシュで省いて芝生の余白を残す。小区画は園路だけ、セルが置けなければ地面だけになる。

公園も区画全面が徒歩・自動車共通の通過可能領域である。園路や植栽の形状は経路探索を制限せず、閉じた柵や池は配置しない。通行の意味は [地区と土地区画](../economics/4_地区と土地区画.md) §4.8を参照する。

## LOD・状態・コライダー

Farは高さ0.3mの板。工事中・解体中は土マウンドのみ、倒壊時は瓦礫マウンドのみで、足場・クレーン・躯体片を付けない。停止中は既存の停止状態の表示を使う。

コライダーは地形に沿う地面と、実際に配置した装飾のバウンディングボックスから生成する。装飾が置けない区画でも地面をクリックできる。生成メッシュと共有FBXを区別し、一時メッシュは結合後に解放する。

## 検証・ギャラリー

unity/Tests/Buildings/run-open-space.ps1は独立Unityで実FBXと本編DLLを読み、長方形・台形・L字・三角形・細長い区画・微小区画・深い切欠きで包含、再生成の一致、回転後の台数、メッシュとコライダーを検査する。駅前ロータリーは長方形で周回路・上屋・街灯・時計塔・樹木・縁石で上げた面があること、回転・平行移動で周回の有無と装飾の数（丸め誤差で±2まで）が変わらないこと、別の visual_variant2 でも敷地内に収まることも確かめる。画像はunity/Temp/OpenSpaceQAに出力する。

同じ検証で長方形見本の配置をgenesis-gallery/pipeline/layoutsへ書き出す。面は本編と同じ三角形分割（頂点と添字）と穴・側面の材質も含む。ギャラリーはこの計画を読み、Python側に配置器を複製しない。配置器の変更後は検証で見本を再出力し、build_gallery.py --only a300を実行する。

## 道路間口の導出

駅前ロータリーの `Plan.Openings` は最終アスファルト面と接道辺（前面座標のt=0）の交線から作る。すみ切りの線分と車路の線分は、接していれば統合する。両端・中点・幅・敷地外向きの法線・入口/出口の区別を保持するため、設定上の車路幅だけを道路側へ渡す場合に生じる縁石の残りを防げる。幾何演算には面の生成と同じ頑健なOverlayを使う。

敷地内2mのすり付け領域も実際のアスファルト面との共通部分から作り、丸い縁石や歩道へはみ出さない。周回できない車寄せへのフォールバックも、その最終形状から1つの開口を得る。地面だけの微小区画には開口がない。

`BuildingRoadAccessIndex` が配置計画をデータ署名ごとに保持し、道路と建物本体が同じ計画を利用する。形状・位置・外観値・状態を更新すると計画と開口を更新する。駐車場・公園はこの道路開口の生成対象ではない。接続描画の検証は `unity/Tests/BuildingAccess/run.ps1`。
