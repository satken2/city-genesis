# C. 建物形状

土地区画のポリゴンと建築条件から、建物の水平投影（フットプリント）を表す2次元ポリゴンを求める考え方について。幾何処理の集約は `BuildingGeometryService` に置かれ、Shapely による平面幾何の演算を前提とする。パスの曲線や標高の扱いは[[A_パス形状]]、土地区画の路面辺の扱いは[[B_土地形状]]、建物エンティティの意味づけは[[12_建物]]とあわせて読む。

## C.1. 何のための形状か

建物形状は、グラフィック上の建物の占地、経済シミュレーション上の建築面積・延床面積・階高の算出、フロアキャパシティ計算などの入力になる。ここでいう「形状」はあくまで水平面内の輪郭であり、階数や階ごとの用途の内訳は別パラメータで与え、形状生成とは独立に扱われる。

## C.2. 入力となる情報

形状生成には、少なくとも次の情報が必要である。

| 項目      | プロパティ名                                             | 型                                                                  | 説明                                                                                            |
| ------- | -------------------------------------------------- | ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| 敷地ポリゴン  | 土地区画の `polygon`                                    | 2次元頂点列（ポリゴン）                                                       | 土地区画の境界。フットプリントは原則としてこの内部（または境界上）に収まる。                                                        |
| 中心点     | `center_point`                                     | 平面座標（例: `[x, z]`）                                                  | 生成結果をこの点を原点とする**相対座標**に変換するための基準。グラフィックで区画位置と合成。                                              |
| 路面に面する辺 | `facade_edge_index`                                | 外周辺のインデックスの列                                                       | 道路に接すると判定された辺。詳細は[[B_土地形状]]。空や不明な場合、道路基準の配置に頼れないカテゴリは別形状へフォールバックする。                           |
| 建蔽率     | `construction_ratio` または `limit_coverage_ratio` など | 0.0〜1.0 の実数                                                        | 敷地面積に対する水平投影面積の上限の割合。プレイヤー指定建物では前者、自動建設など区画上限を使う経路では後者など、文脈で渡す値が切り替わる。「敷地全体面積 × 建蔽率」が目標面積の上限。 |
| 形状カテゴリ  | 建物マスタの `building_shape`                            | `SHAPE_HOUSE`、`SHAPE_OFFICE`、`SHAPE_COMMERCIAL`、`SHAPE_FULL` のいずれか | バリアントごとにマスタで定まり、上記4区分のどの生成方針を取るかを決める。                                                         |

## C.3. 許容面積と形状の関係

まず敷地ポリゴンの面積に建蔽率を掛じて、フットプリントとして許される面積の上限を求める。各形状カテゴリは、この上限を**目標面積**としてできるだけ近づけつつ、敷地内に収まるポリゴンを構成する。最終的なポリゴンが上限面積より小さくなることは、回転・縮小・敷地との共通部分の取得などの調整の結果として起こりうる。

## C.4. 形状カテゴリごとの方針

### C.4.1. `SHAPE_FULL`（敷地いっぱい）

建物の水平投影を敷地ポリゴンそのものとする。境界にぴったり沿う「区画全体を建物が覆う」イメージ。

### C.4.2. `SHAPE_OFFICE`（回転矩形ベース）

敷地に外接する意味での**最小回転矩形**を基準形状とし、その面積と目標面積の比から一様スケールして大きさを合わせる。スケール後に敷地外へはみ出す場合は、同じ矩形系を保ちつつ敷地内に収めることを優先し、段階的な回転の試行や縮小、最終手段として敷地との共通部分の取得が用いられる。道路の方向性は用いず、細長い敷地でも「建物ブロック」としてまとまった矩形に寄せる意図がある。

### C.4.3. `SHAPE_HOUSE`（路面沿い・セットバック）

道路に面した辺を正面とみなし、その辺に沿った方向と、敷地の内側へ向かう法線方向で直方体候補の向きを決める。路面から一定距離（セットバック）だけ内側に基準点を置き、目標面積に相当する一辺の長さを基に、ほぼ正方形に近い長方形をまず置く。幅と奥行きの比率には乱数でわずかなばらつきを与え、一定確率で角を切り欠いて L 字型にするなど、戸建てのばらつきを表現する。

路面辺が特定できない場合は、`SHAPE_OFFICE` と同様の生成にフォールバックする。候補が敷地からはみ出す場合は、重心まわりの縮小などで収めを試みる。

### C.4.4. `SHAPE_COMMERCIAL`（店舗面の帯状）

路面辺に沿って、両端をわずかに削った有効幅を持たせ、路面から奥方向にも短い隙間（セットバック）を空けた帯状の直方体を敷地内に置く。奥行きは、目標面積を有効幅で割って決める。敷地との共通部分でクリップし、なお面積が上限を超える場合は縮小して上限に近づける。路面に接する「店先」を幾何的に明示したいカテゴリである。

### C.4.5. 不整形区画への四角形フィット（`SHAPE_HOUSE` / `SHAPE_OFFICE` / `SHAPE_COMMERCIAL` 共通）

上記3カテゴリの標準生成は矩形（またはL字）を基本とするため、台形や旧市街のような不整形区画では、縮小の結果として建蔽率の上限を大きく下回ることがある。標準生成の充足率が一定のしきい値を下回った場合に限り、フットプリントを**区画に内接する最大面積の凸四角形**（台形・不等辺四角形）へ差し替え、区画を最大限利用する。

- **矩形優先** — 長方形（house ではL字を含む）で建蔽率目標を十分満たせる区画では発動しない。house の意匠としてのL字切欠きによる面積減は「満たせなかった」とは扱わない。差し替えても面積がわずかしか改善しない場合も標準形状を維持する。
- **頂点は常に4つ** — 区画の輪郭に何頂点あっても、建物は凸な四角形に留まる（星型の区画で星型の建物にはならない）。内角には下限があり、極端な鋭角の建物は作らない。有効な四角形が構成できない区画では標準生成の結果を維持する。
- **セットバックの置き換え** — 差し替え時は house の路面セットバック（5m）は適用されず、区画全周からの小さな一定マージンに置き換わる。不整形区画に密集して詰め建てされた旧市街の街並みを表現する。
- **面積上限の厳守** — 四角形が建蔽率上限を超える場合は、上限に収まるまで縮小される。
- **正面の辺** — 出力ポリゴンは、路面辺に最も近い辺が最初の辺（頂点0→頂点1）になるよう並べられる。エントランス・塔屋の向き規約（[[F_建物メッシュの生成]] §10.3・§11.2）と整合する。

グラフィック側に固有の対応は不要である。壁・角のモジュラー組み立ては N 辺・任意内角に対応しており（[[F_建物メッシュの生成]] §2.3・§7.4）、90°でない角は角パーツのボーン変形で追従する。

## C.5. 複数の路面辺があるときの辺の選び方

`facade_edge_index` に複数の辺が含まれる場合、それらが多角形の周上で**隣接**していれば、角地のように両辺をまとめて正面として扱う。隣接していなければ、候補の中で**最も長い辺**だけを道路側として採用する。これにより、複数道路に面した区画でも、一貫した「正面」と内側方向を定義できる。

内側方向の法線は、辺に直交する2方向のうち、敷地の重心側に入る方を選ぶことで決める。

## C.6. 出力とエージェントデータへの反映

生成されたポリゴンは `center_point` 基準の相対座標に直され、建物エージェントの `polygon`（頂点列）として保存される。同じ形状から建築面積が求められ、階数と掛け合わせて延床面積や高さ（階あたりの高さマスター）、フロアキャパシティの再計算につながる。プレイヤー操作やプレビュー API で建蔽率・階数・バリアント・区画が変わり、形状の再生成が必要になった場合も、同じパイプラインが繰り返される。

## C.7. 本ドキュメントの位置づけ

建物を**どの区画にどのバリアントで建てるか**という選定は、[[14_建物のスポーン]]などの経済・需要側の話である。本稿は、その決定が済んだあと（またはプレイヤーが明示的に建てるとき）に、与えられた区画幾何とパラメータから**見た目と面積の整合が取れたフットプリント**をどう作るかという、幾何レイヤの原則を述べるものである。
