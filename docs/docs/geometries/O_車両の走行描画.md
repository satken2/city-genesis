# O. 車両の走行描画

## O.1. 概要

車両はUnity側だけで生成する描画用オブジェクトである。バックエンドの車種別日次交通量 `path_traffic` に応じた台数をカメラ周辺に配置し、道路の車線と交差点の通過曲線を連続して走らせる。経済シミュレーションやサーバーの永続エンティティには影響しない。

**走行と台数調整は別の処理である。** 交差点への到達時には、移動先の台数超過を理由に車を消さない。不足道路への発生と、過剰な車の沿道到着を一定間隔で調整する。到着予約を持つ車は、建物のある接道街路まで走り、入口から敷地へ入ってから消える。高速道路や空き地では沿道到着しない。

目標は、静止したカメラで見続けたときに交通量相応の水準を保つことである。常に同じ台数を表示するものではない。退出できる建物も管理範囲外への経路もない閉じた道路網では、既存車を残して補充を止めるため、交通量が減っても目標台数まで減らない場合がある。期待台数が1台未満の場合は、車がいる時間といない時間で表現する。道路の分割ごとに最低1台を割り当てない。

当たり判定、信号待ち、追い越し、右折待ちは扱わない。車同士が重なることはある。発生・到着は沿道への出入りを表す演出であり、区画の道路に面した辺に描画用の入口を設定する。FBXの玄関や駐車場入口の位置そのものは使わない。

## O.2. 入力データ

既にロードされている `PathManager` の道路データを使い、車描画専用のAPIは追加しない。

| 入力 | 用途 |
| --- | --- |
| `path_traffic` | 車種別の日次通過トリップ数。目標台数と分岐の重み |
| `travel_direction` | `DIR_BOTH` / `DIR_FORWARD` / `DIR_BACKWARD` による進入方向制限 |
| 始終点ノードID | 同一ノードに接続する次の道路の取得 |
| `path_type`・`status` | `PATH_MOTORWAY` / `PATH_STREET` かつ `STATUS_ACTIVE` の選別 |
| パスマスターの道路幅・歩道幅・側線幅・中央分離帯幅・車線数 | 道路の区画線と共通の車線配置 |
| `CityInfoStore.TrafficHand` | 都市の左側通行・右側通行 |

`path_traffic` は `PathSummary` の型付きフィールドを直接読む。未設定・非有限値・負値は交通量0として扱う。単位の異なる `utilization` を交通量の代用にはしない。

交通量は車種別の道路合計であり、方向別・右左折別の内訳を含まない。双方向道路の発生方向は等確率とし、分岐は接続道路の交通量による確率的な演出とする。集計値だけから個々の車の目的地を復元することはできない。

## O.3. 管理範囲と道路スナップショット

中心は `CameraCellChecker.CurrentWorldPosition`（注視点のy=0平面との交点）。管理半径は `renderRadius + despawnMargin`（既定400m + 80m）とする。**目標台数、発生位置、範囲外デスポーンは同じ管理円を使う。** 余白の車だけを台数に含め、対応する目標を含めない状態は作らない。

0.5秒ごとに `PathManager.GetPathsNearCircle` がセル逆引きから道路候補を取得する。全都市の道路について毎回中心線を再計算しない。候補の中心線を `TryGetPathPolyline` で取得し、累積距離付きの `VehiclePolyline` として範囲内の車で共有する。地形追従済み・交差点切断済みの点列なので、道路メッシュと同じ基準で走行できる。

中心線の各線分とXZ平面の円との交点を解き、円内区間を距離の区間列として保持する。両端点が円外でも途中で円を横切れば検出する。複数回出入りする場合も円外区間を足し込まない。初期配置は各区間の長さに比例して選ぶ。初期の台数枠を満たした後の補充は、有効な建物入口か、進入方向に対応する管理円の境界付近に限る。高速道路の途中や建物のない街路上へ通常補充は行わない。

道路・地形の更新時は、道路上の車を新しい点列の同じ進捗率へ移す。交差点通過中の曲線は完走し、その後のスキャンで最新形状へ追従する。削除・非稼働化・進行方向の禁止を検出した車は除去する。

1フレームで `renderRadius` を超えて注視点が移動した場合は車をプールへ戻し、移動先で補充し直す。ゲーム開始前の状態へ戻ったときも台帳をリセットする。管理円は画面の表示領域そのものではないため、広い俯瞰では管理円の境界が見える場合がある。

## O.4. 道路の区画線と共通の車線モデル

`RoadPath.cs` の `RoadLaneLayout` が区画線境界と車線中心の唯一の定義である。[道路メッシュの生成](G_道路メッシュの生成.md) §8.3 も同じ計算を使う。

道路幅を W、片側歩道幅を SW、側線幅を SL、中央分離帯幅を CW、車線数を L とする。走行帯の外側は `Rout = max(0, W/2 − SW − max(0, SL)/2)`。道路幅は歩道を含む。

| 道路 | 車線の割り当て |
| --- | --- |
| 双方向・L≦1 | 中心線上を走る。対向車も同じ車線を使う |
| 双方向・偶数L | 片側L/2車線。中央分離帯の外側CW/2からRoutまで等分 |
| 双方向・奇数L≧3 | 片側floor(L/2)車線。内側境界をmax(CW/2, Rout/L)として中央の転回用帯を空ける |
| 一方通行 | −Routから+RoutまでをL車線に等分。中央分離帯付きの一方通行は想定しない |
| 有効な走行帯がない寸法 | 中心線上の1車線にフォールバック |

車線番号は進行方向の通行側の路肩を0とする。車線中心は左側通行なら進行方向の左へ、右側通行なら右へ配置する。一方通行では全車線を使うため、中央を超えた車線の符号は反転する。

発生時は利用可能な車線をランダムに選ぶ。トラック・バスは70%の確率で路肩側を選び、それ以外は全車線から抽選する。交差点を渡るときは路肩からの車線番号を維持し、移動先の車線数でクランプする。車線の横位置の変化は通過曲線で接続する。

発生時は路肩から15mかけて車線中心へ寄る。途中で交差点に入る場合は、その時点の横位置から通過曲線を作る。通常走行中の車線変更は行わない。

## O.5. 交通量と台数の安定

### 道路別の期待台数

道路×車種ごとの期待台数は、日次交通量から流量と通過時間を求めて計算する。

**期待台数 = 日次交通量 ÷ (活動時間[h] × 3600) × 管理円内の中心線長[m] ÷ 車種基準速度[m/s] × 演出倍率**

速度は `baseSpeed` に車種係数（乗用車1、トラック・バス0.8、商用車0.9）を掛ける。実際の車速はさらに個体ごとの0.85〜1.15倍のばらつきを持つ。交差点の減速・沿道到着の減速や個体差まで含む厳密な流量再現ではなく、道路の賑わいを制御する目標である。

期待台数の合計が `maxActiveVehicles` を超える場合は、**全道路の期待台数に同じ縮小倍率**を掛ける。道路の走査順に上限を取り合わない。

### 全体の台数枠

`VehiclePopulationBudget` が全道路の期待台数を合計してから整数化する。整数部分は常時の枠、端数は12秒の時間窓ごとに繰り越す。例えば合計0.2台なら、概ね5窓に1窓だけ1台分の枠を持つ。発生・到着の遅れで生じた台秒の差分も端数へ繰り越し、低交通量で到着待ちの車が平均を押し上げ続けないようにする。

期待台数が増えれば整数部分の枠は即座に増やす。減った場合も次の時間窓を待たず上限を下げる。既存車の除去は到着演出を通すため、実台数は枠の変化へ遅れて追従する。絶対上限 `maxActiveVehicles` に達した状態では新規発生させない。

**道路1本ごとに期待台数を切り上げない。** 同じ長さ・交通量の道路を内部的に分割しても、合計した期待台数は同じである。ただし交差点切断で道路長が変わる場合や、通過曲線・右左折の減速時間は別の影響を持つ。

### 不足補充と道路間の偏りの調整

0.25秒の固定周期で、道路×車種の現在台数を実在する車から数え直す。交差点通過中は移動先の道路へ1回だけ計上する。到着予約中・フェード中の車も、消えるまでは実台数と全体枠に含む。

全体枠が不足している場合、初期配置中または補充地点を持つ道路を対象に、道路ごとの「現在台数の不足」と「8秒の指数移動平均の不足」を重みにして発生先を選ぶ。発生は枠の不足量に応じて数回の制御周期で充填する。

全体枠を超えた場合は、共有の退出経路表で出口へ到達可能と判定された車のうち、最低走行時間を満たす車から、平均密度の超過が大きい道路の車を優先して沿道到着を予約する。既に予約済みの車は超過解消予定として扱い、二重に予約しない。入口へ到達するまで時間がかかっても、途中で消して帳尻を合わせない。端数枠はこの到着待ち時間も台秒で繰り越す。

総台数が枠と合っていても、2秒ごとに道路間の偏りを確認する。平均台数が期待値を `max(0.5台, 期待値の25%)` 以上超えた道路があれば、最大1台の到着を予約する。その車が消えた後、不足道路へ補充する。小さな瞬間的超過のたびに車を入れ替えないための許容幅である。

道路別の密度はこの許容幅と走行によって変動する。特に1台未満の道路では瞬間値の一致を要求しない。総数の安定と、車が複数の道路を続けて走ることを優先する。

## O.6. 交差点での分岐と通過

`GetPathsConnectedToNode` の接続インデックスから、管理範囲内の稼働道路を選ぶ。現在の道路を除外し、ノードからの進入方向が `travel_direction` で許される道路だけを候補にする。

通常の車は同じ車種の `path_traffic` を重みにした抽選で次の道路を決める。到着予定の車は、退出先への共有逆探索表で段数が最も小さい進入可能な道路を優先する。交通量0の候補は、正の交通量を持つ候補がない場合だけ均等抽選で使う。描画範囲外やまだスナップショットにない道路には進入しない。

道路端は[交差点ハルの切断点](J_パスの交差処理.md)まで切り詰められているため、車線端同士を通過曲線で結ぶ。

- 退出点P0・進入点P1は、それぞれ道路端に車線の横位置を加えた点。
- 接線T0・T1は、各道路端での走行方向。
- 三次ベジエの制御点はP0、P0+T0×d、P1−T1×d、P1。dは端点間距離×張り出し係数。
- 曲線を32区間に分割して累積距離を持ち、距離に沿って進む。高さも制御点の接線に従う。
- 直進は通常速度、90度以上の転回は既定0.5倍。中間角は線形に補間する。
- 同じ車を維持して「道路→交差点→次の道路」へ状態遷移する。車線端が一致する直進ではゼロ長の接続を即座に通過する。
- フレーム内に区間の端へ到達した場合、未消費時間を次の区間へ渡す。極端なデータで1フレームに128回を超えて道路遷移する車は除去し、無限ループを防ぐ。

候補がない場合、逆方向が許可された街路ではUターンする。高速道路ではUターンしない。進めない車は終端で実寸のまま待機し、接続先がロード・新設されれば走行を再開する。入口のない場所での退出やフェードには切り替えない。信号待ちや他車との交差判定は行わない。

## O.7. 沿道到着・フェード・プール

発生後6秒間は密度調整による到着対象にしない。到着予約は交差点通過中にも保持するが、路肩寄せとフェードは道路上で始める。

退出地点は、進行方向の先にある有効な建物入口から選ぶ。入口が今のパスにない場合は、予約を保持して交差点を通過する。入口の前で路肩へ寄せながら減速し、0.5秒かけて敷地側へ向きを変え、実寸のまま3m/sで敷地内の退出点へ進む。退出点に到着してから0.4秒で縮小する。左右は都市の通行側にある区画だけを使い、対向車線を横切って反対側の敷地へ入らない。

入口は `PATH_STREET` かつ `frontage_allowed=true` の道路に限定する。`GetParcelIdsByFrontPath` と `GetBuildingIdsByParcel` の逆引きで、接道区画に実建物（`is_bd=true`、`STATUS_ACTIVE`）があることを確認する。区画も稼働中であることを要求する。接道IDは離れた区画にも付くため、それだけで入口とはしない。

区画辺の中点を道路中心線へ射影し、道路端から3m以上、道路外縁との差が−1〜4m、高低差が2m以内、辺と道路の方向がほぼ平行（内積の絶対値0.8以上）のものを候補にする。区画辺から道路と反対へ3m進んだ点が実際にその敷地内にあることも確認する。狭すぎる敷地や高架・トンネルとの不自然な接続は採用しない。入口は仮の描画位置であり、実際の玄関・駐車場、歩道の切り下げ、敷地内障害物を探索するものではない。

退出を始める直前にも、建物・区画・接道・接道許可が有効か確認する。未ロードや撤去で条件を満たさなくなった入口へは退出しない。

発生時は0.4秒でスケールを0から1へ立ち上げる。モデルのマテリアルは交換しない。描画範囲外、削除された道路、禁止された走行方向の車は直ちにプールへ戻す。ただし道路脇へ退出中は管理円を出ても退出・フェードを完了させる。退出中の車も消えるまでは全体枠を占める。

実体は車種とバリアント単位でプールし、取得時にスケールを戻す。モデル解決は `VehicleModelResolver` が `ModelManager.GetModel` を通して以下の順で行う。

1. `Models/Vehicles/{車種}/{バリアント}`
2. `Models/Vehicles/{車種}`
3. `Models/Vehicles/{VEHICLE_STANDARD}`
4. 車種別に色分けした箱

バリアントは `Resources/Config/vehicle_model_config.yaml` の設定から選ぶ。FBXと設定の実データがなくても箱で動作する。モデルは実寸で置き、道路幅に合わせて縮めない。

### 入口・退出経路のキャッシュと負荷

道路スナップショット更新後、入口更新用コルーチンが周辺の接道候補を点検する。道路中心線・幅・走行方向、区画version、稼働建物の集合から変更を検出し、変更した区画だけ距離・高低差・敷地内判定を再計算する。入口や道路接続、管理円外へ抜ける端点が変わっていなければ経路表は再構築しない。

経路表は「道路ID＋走行方向」の状態を持つ。建物入口と管理範囲外への出口を始点に、逆グラフを幅優先探索して出口までの段数を全車で共有する。一方通行と街路の行き止まりでの折り返しを反映する。車は交差点で接続道路の段数を比較するだけで、独立した経路探索を行わない。

入口の探索も車が道路へ入ったとき、または共有表の世代が変わったときに限る。選んだ入口への距離を通常の走行で消費するため、毎フレーム建物を走査しない。約1msの作業を目安にコルーチンを次フレームへ譲り、完成した入口表と経路表を一括交換する。単一の区画処理や初回JIT等はこの目安を超える場合があり、厳密なフレーム時間上限ではない。

## O.9. 検証と制限

`unity/Tests/Vehicles/run.ps1` は独立したUnityプロジェクトで本編のビルド済みアセンブリを使い、円との交差・再進入、車線位置、一方通行、通過曲線、残り移動時間、端数枠、環状道路の長時間走行を検証する。本編のシーンや都市データは書き換えない。

道路の細分化で総台数が膨らまないこと、車が繰り返しパスを跨ぐこと、退出先がある場合は交通量0で残留車も到着し、退出先のない閉路では車が維持されることを確認する。テストの道路スナップショットは人工的なものであり、実際の全交差点形状・地形・ロード順を網羅するものではない。

右左折内訳・目的地の再現、信号・衝突、FBXの玄関・駐車場位置との一致、線路上の車両は対象外である。鋭角・極端な異幅交差点では、通過曲線が路面内に収まることを別途確認する必要がある。
