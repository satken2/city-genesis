# O. 車両の走行描画

## O.1. 概要

車両はUnity側だけで生成する描画用オブジェクトである。バックエンドの車種別日次交通量 `path_traffic` に応じた台数をカメラ周辺に配置し、道路の車線と交差点の通過曲線を連続して走らせる。経済シミュレーションやサーバーの永続エンティティには影響しない。

**走行と台数調整は別の処理である。** 交差点への到達時には、移動先の台数超過を理由に車を消さない。不足道路への発生と、過剰な車の沿道到着を一定間隔で調整する。到着予約を持つ車は、建物のある接道街路まで走り、入口から敷地へ入ってから消える。高速道路や空き地では沿道到着しない。

目標は、静止したカメラで見続けたときに交通量相応の水準を保つことである。常に同じ台数を表示するものではない。退出できる建物も管理範囲外への経路もない閉じた道路網では、既存車を残して補充を止めるため、交通量が減っても目標台数まで減らない場合がある。期待台数が1台未満の場合は、車がいる時間といない時間で表現する。道路の分割ごとに最低1台を割り当てない。

一般車は同じ道路・方向・車線の前車との間隔に応じて減速・停止する。交差点の競合予約、信号待ち、追い越し、右折待ちは扱わないため、合流や交差する車両が重なる場合はある。発生・到着は沿道への出入りを表す演出であり、区画の道路に面した辺に描画用の入口を設定する。FBXの玄関や駐車場入口の位置そのものは使わない。

## O.2. 入力データ

既にロードされている `PathManager` の道路データを使う。時間は `POST /api/v1/paths/motion` に周辺のパスIDを渡して2秒周期で取得する。応答は自由走行秒数・混雑込み秒数・論理長・活動時間を含む。論理長 `length_m` は道路の中心線に沿った水平の長さで、2つの秒数と同じ道のりを表す。曲線の道路でも端点間の直線距離ではない。新しい都市への切り替え後は古い応答を破棄する。

| 入力 | 用途 |
| --- | --- |
| `path_traffic` | 車種別の日次通過トリップ数。目標台数と分岐の重み |
| `travel_direction` | `DIR_BOTH` / `DIR_FORWARD` / `DIR_BACKWARD` による進入方向制限 |
| 始終点ノードID | 同一ノードに接続する次の道路の取得 |
| `path_type`・`status` | `PATH_STREET` / `PATH_MOTORWAY` かつ `STATUS_ACTIVE` の選別 |
| パスマスターの道路幅・歩道幅・側線幅・中央分離帯幅・車線数 | 道路の区画線と共通の車線配置 |
| `CityInfoStore.TrafficHand` | 都市の左側通行・右側通行 |

`path_traffic` は `PathSummary` の型付きフィールドを直接読む。未設定・非有限値・負値は交通量0として扱う。単位の異なる `utilization` を交通量の代用にはしない。

交通量は車種別の道路合計であり、方向別・右左折別の内訳を含まない。双方向道路の発生方向は等確率とし、分岐は接続道路の交通量による確率的な演出とする。集計値だけから個々の車の目的地を復元することはできない。

## O.3. 管理範囲と道路スナップショット

中心は `CameraCellChecker.CurrentWorldPosition`（注視点のy=0平面との交点）を、カメラ位置から水平 `maxCenterLead`(300m)以内に寄せた点とする。乗車中は乗車位置を使う(`VehicleManager.ResolveTrafficCenter`)。浅い俯角では注視点が数km先へ飛び、見えない遠方を管理し続けるうえ、ピッチを少し変えただけで中心が大きく跳ぶためである。ロードの中心そのものは変えない。管理半径は `renderRadius + despawnMargin`（既定400m + 80m）とする。**目標台数、発生位置、範囲外デスポーンは同じ管理円を使う。** 余白の車だけを台数に含め、対応する目標を含めない状態は作らない。

0.5秒ごとに `PathManager.GetPathsNearCircle` がセル逆引きから道路候補を取得する。全都市の道路について毎回中心線を再計算しない。候補の中心線を `TryGetPathPolyline` で取得し、累積距離付きの `VehiclePolyline` として範囲内の車で共有する。地形追従済み・交差点切断済みの点列なので、道路メッシュと同じ基準で走行できる。

スナップショットは `RenderWorkScheduler` のワーカー(`vehicleRoads`)で共通予算内に分割して構築し、完成後に一括交換する(途中の集合を車に見せない)。`PathManager.GetPathGeometryRevision` とパスデータが前回と同じ道路は点列を取得し直さない。版が不明(-1)なら点列の完全一致(`VehiclePolyline.SameSource`)で比べて `VehiclePolyline` を使い回す。中心・半径も同じなら道路ごと再利用する。乗車開始だけは、その場で道路を得てから車を置く必要があるので同期版で作る。

中心線の各線分とXZ平面の円との交点を解き、円内区間を距離の区間列として保持する。両端点が円外でも途中で円を横切れば検出する。複数回出入りする場合も円外区間を足し込まない。初期配置は各区間の長さに比例して選ぶ。初期の台数枠を満たした後の補充は、有効な建物入口か、進入方向に対応する管理円の境界付近に限る。高速道路の途中や建物のない街路上へ通常補充は行わない。

道路・地形の更新時は、旧点列上の位置を新点列の元の進捗付近(±(長さの差+10m))へ射影して、道路上の車を移す(`VehiclePolyline.RemapFrom`)。点列のインスタンスが同じなら移さない。交差点通過中の曲線は完走し、その後のスキャンで最新形状へ追従する。削除・非稼働化・進行方向の禁止を検出した車は除去する。

1フレームで `renderRadius` を超えて管理中心が移動した場合は、全消去せずに中心を移し直す。新しい管理円の中にいる車はそのまま走らせ、円外の車は通常のデスポーンに任せる。道路の集合は新しい走査が確定するまで保持し、発生候補を空にしてすぐに再走査し、確定後に初期充填へ戻す。入口の計算結果は区画と形状の署名で有効性を判定しているので保持する。通行方向の変更とゲーム開始前の状態へ戻ったときは全消去して台帳をリセットする。管理円は画面の表示領域そのものではないため、広い俯瞰では管理円の境界が見える場合がある。

## O.4. 道路の区画線と共通の車線モデル

1車線の高速道路流入ランプでは、`PathManager.GetMotorwayMerge` が返す描画専用の合流計画を使う。下流側の接合区間の前半は一定幅の車線を並走し、後半でランプに隣接する本線車線へ寄せる。本線を直進する車も同じ本線点列を参照する。`MotorwayMergeLayout` は区画線と走行位置を共有し、接続ごとの点列をキャッシュする。一般車・ドライブモードは `VehicleManager`、路線バスとハイライトは `TransitRouteGeometry` を経由する。2車線ランプや流出など、対象外の接続は従来の汎用曲線を使う。合流優先権や車両どうしの競合予約を追加するものではない。形状の詳細は[G_道路メッシュの生成](G_道路メッシュの生成.md) §11.7。

`RoadPath.cs` の `RoadLaneLayout` が区画線境界と車線中心の唯一の定義である。[道路メッシュの生成](G_道路メッシュの生成.md) §8.3 も同じ計算を使う。

道路幅を W、片側歩道幅を SW、側線幅を SL、中央分離帯幅を CW、車線数を L とする。走行帯の外側は `Rout = max(0, W/2 − SW − max(0, SL)/2)`。道路幅は歩道を含む。

| 道路 | 車線の割り当て |
| --- | --- |
| 双方向・L≦1 | 中心線上を走る。対向車も同じ車線を使う |
| 双方向・偶数L | 片側L/2車線。中央分離帯の外側CW/2からRoutまで等分 |
| 双方向・奇数L≧3 | 片側floor(L/2)車線。内側境界をmax(CW/2, Rout/L)として中央の転回用帯を空ける |
| 一方通行 | −Routから+RoutまでをL車線に等分。中央分離帯付きの一方通行は想定しない |
| 有効な走行帯がない寸法 | 中心線上の1車線にフォールバック |

車線番号は進行方向の通行側の路肩を0とする。車線中心は左側通行なら進行方向の左へ、右側通行なら右へ配置する。一方通行では全車線を使うため、中央を超えた車線の符号は反転する。

発生時は利用可能な車線をランダムに選ぶ。トラック・バスは70%の確率で路肩側を選び、それ以外は全車線から抽選する。抽選した車線から順に試し、同じ道路・方向・車線の前後8m以内に車がいれば別の車線へ回す。全車線が塞がっていれば、その制御周期では発生しない。交差点を渡るときは路肩からの車線番号を維持し、移動先の車線数でクランプする。車線の横位置の変化は通過曲線で接続する。

発生時は路肩から15mかけて車線中心へ寄る。途中で交差点に入る場合は、その時点の横位置から通過曲線を作る。通常走行中の車線変更は行わない。

## O.5. 交通量と台数の安定

### 道路別の期待台数

道路×車種ごとの期待台数は、日次交通量から流量と通過時間を求めて計算する。

**期待台数 = 日次交通量 ÷ (活動時間[h] × 3600) × 管理円内の中心線長[m] ÷ コアの平均速度[m/s] × 表示標本率**

平均速度は論理長を混雑込み通過時間で割る。通常の車速には同じ平均時間を目標とする制御を使い、個体別のランダム速度倍率は加えない。時間データ未取得時だけ基準速度と車種係数を使う。`renderFraction` は0〜1の表示標本率で、交通量を増幅して架空の渋滞を作らない。バスは路線専用の管理へ移り、一般車の台数枠には含めない。

`RoadMotionControl` は残り距離÷目標残り秒数を要求速度とし、コアの自由走行平均速度を上限にする。前車との車体間隔は標準車長4.5mで近似し、2mの余白と減速度3m/s²、加速度1.5m/s²で追従する。車が遅れた場合も上限を超えて帳尻を合わせず、超過時間を許す。停止車を最低速度で前進させない。一般車のカーブ位置ごとの速度プロファイルや実車長による占有判定は未対応であり、区間全体の平均を合わせる近似である。

期待台数の合計が `maxActiveVehicles` を超える場合は、**全道路の期待台数に同じ縮小倍率**を掛ける。道路の走査順に上限を取り合わない。

### 全体の台数枠

`VehiclePopulationBudget` が全道路の期待台数を合計してから整数化する。整数部分は常時の枠、端数は12秒の時間窓ごとに繰り越す。例えば合計0.2台なら、概ね5窓に1窓だけ1台分の枠を持つ。発生・到着の遅れで生じた台秒の差分も端数へ繰り越し、低交通量で到着待ちの車が平均を押し上げ続けないようにする。

期待台数が増えれば整数部分の枠は即座に増やす。減った場合も次の時間窓を待たず上限を下げる。既存車の除去は到着演出を通すため、実台数は枠の変化へ遅れて追従する。絶対上限 `maxActiveVehicles` に達した状態では新規発生させない。

**道路1本ごとに期待台数を切り上げない。** 同じ長さ・交通量の道路を内部的に分割しても、合計した期待台数は同じである。ただし交差点切断で道路長が変わる場合や、通過曲線・右左折の減速時間は別の影響を持つ。

### 不足補充と道路間の偏りの調整

0.25秒の固定周期で、道路×車種の現在台数を実在する車から数え直す。交差点通過中は移動先の道路へ1回だけ計上する。到着予約中・フェード中の車も、消えるまでは実台数と全体枠に含む。

全体枠が不足している場合、初期配置中または補充地点を持つ道路を対象に、道路ごとの「現在台数の不足」と「8秒の指数移動平均の不足」を重みにして発生先を選ぶ。発生は枠の不足量に応じて数回の制御周期で充填する。

全体枠を超えた場合は、共有の退出経路表で出口へ到達可能と判定された車のうち、最低走行時間を満たす車から、平均密度の超過が大きい道路の車を優先して沿道到着を予約する。既に予約済みの車は超過解消予定として扱い、二重に予約しない。入口へ到達するまで時間がかかっても、途中で消して帳尻を合わせない。端数枠はこの到着待ち時間も台秒で繰り越す。

総台数が枠と合っていても、2秒ごとに道路間の偏りを確認する。平均台数が期待値を `max(0.5台, 期待値の25%)` 以上超えた道路があれば、最大1台の到着を予約する。その車が消えた後、不足道路へ補充する。小さな瞬間的超過のたびに車を入れ替えないための許容幅である。

道路別の密度はこの許容幅と走行によって変動する。特に1台未満の道路では瞬間値の一致を要求しない。総数の安定と、車が複数の道路を続けて走ることを優先する。

## O.6. 交差点での分岐と通過

`GetPathsConnectedToNode` の接続インデックスから、管理範囲内の稼働道路を選ぶ。現在の道路を除外し、ノードからの進入方向が `travel_direction` で許される道路だけを候補にする。

通常の車は同じ車種の `path_traffic` を重みにした抽選で次の道路を決める。到着予定の車は、退出先への共有逆探索表で段数が最も小さい進入可能な道路を優先する。交通量0の候補は、正の交通量を持つ候補がない場合だけ均等抽選で使う。描画範囲外やまだスナップショットにない道路には進入しない。

道路端は[交差点ハルの切断点](J_パスの交差処理.md)まで切り詰められているため、車線端同士を通過曲線で結ぶ。

- 退出点P0・進入点P1は、それぞれ道路端に車線の横位置を加えた点。
- 接線T0・T1は、各道路端での走行方向。
- 三次ベジエの制御点はP0、P0+T0×d、P1−T1×d、P1。dは端点間距離×張り出し係数。
- 曲線を32区間に分割して累積距離を持ち、距離に沿って進む。高さも制御点の接線に従う。
- 接続曲線でも時間制御で求めた速度を使う。コアの加減速込み時間に独立した交差点減速倍率を重ねない。
- 同じ車を維持して「道路→交差点→次の道路」へ状態遷移する。車線端が一致する直進ではゼロ長の接続を即座に通過する。
- フレーム内に区間の端へ到達した場合、未消費時間を次の区間へ渡す。極端なデータで1フレームに128回を超えて道路遷移する車は除去し、無限ループを防ぐ。

候補がない場合、逆方向が許可された街路ではUターンする。高速道路ではUターンしない。進めない車は終端で実寸のまま待機し、接続先がロード・新設されれば走行を再開する。入口のない場所での退出やフェードには切り替えない。信号待ちや他車との交差判定は行わない。

## O.7. 沿道到着・フェード・プール

発生後6秒間は密度調整による到着対象にしない。到着予約は交差点通過中にも保持するが、路肩寄せとフェードは道路上で始める。

退出地点は、進行方向の先にある有効な建物入口から選ぶ。入口が今のパスにない場合は、予約を保持して交差点を通過する。入口の前で路肩へ寄せながら減速し、0.5秒かけて敷地側へ向きを変え、実寸のまま3m/sで敷地内の退出点へ進む。退出点に到着してから0.4秒で縮小する。左右は都市の通行側にある区画だけを使い、対向車線を横切って反対側の敷地へ入らない。

入口の幾何(接道辺→敷地内の点)は `RoadsideAccess` が求め、[歩行者の描画](W_歩行者の描画.md)と共有する。車はパス幾何に対する左右を通行側と走行方向へ読み替える。入口は `PATH_STREET` かつ `frontage_allowed=true` の道路に限定する。`GetParcelIdsByFrontPath` と `GetBuildingIdsByParcel` の逆引きで、接道区画に実建物（`is_bd=true`、`STATUS_ACTIVE`）があることを確認する。区画も稼働中であることを要求する。接道IDは離れた区画にも付くため、それだけで入口とはしない。

区画辺の中点を道路中心線へ射影し、道路端から3m以上、道路外縁との差が−1〜4m、高低差が2m以内、辺と道路の方向がほぼ平行（内積の絶対値0.8以上）のものを候補にする。区画辺から道路と反対へ3m進んだ点が実際にその敷地内にあることも確認する。狭すぎる敷地や高架・トンネルとの不自然な接続は採用しない。入口は仮の描画位置であり、実際の玄関・駐車場、歩道の切り下げ、敷地内障害物を探索するものではない。

退出を始める直前にも、建物・区画・接道・接道許可が有効か確認する。未ロードや撤去で条件を満たさなくなった入口へは退出しない。

発生時は0.4秒でスケールを0から1へ立ち上げる。モデルのマテリアルは交換しない。描画範囲外、削除された道路、禁止された走行方向の車は直ちにプールへ戻す。ただし道路脇へ退出中は管理円を出ても退出・フェードを完了させる。退出中の車も消えるまでは全体枠を占める。

実体は車種と外観(バリアント)単位でプールし、取得時にスケールを戻す。外観の在庫が無ければ同じ車種の在庫で代替し、車の外観番号を実際に使った外観へ書き換える。デスポーンした車はスケール0で即座に隠し、`SetActive(false)` は1フレーム `deactivationBudgetMs`(0.3ms、最低4件)の予算で遅らせて行う。補充は `spawnBudgetMs`(1ms)の予算で打ち切り(1台目は必ず試みる)、超えた分は制御周期の無いフレームで繰り越して消化する。ゲーム開始後、モデルが使えるようになったら環境交通(バス・LRTを除く)の各外観を1台ずつ `vehicleWarmup` ワーカーで事前生成し、走行中に初めての外観を生成するスパイクを避ける。モデル解決は `VehicleModelResolver` が `ModelManager.GetModel` を通して以下の順で行う。

1. `Models/Vehicles/{車種}/{バリアント}`
2. `Models/Vehicles/{車種}`
3. `Models/Vehicles/{VEHICLE_STANDARD}`
4. 車種別に色分けした箱

バリアントは `Resources/Config/vehicle_model_config.yaml` の設定から選ぶ。FBXと設定の実データがなくても箱で動作する。一般車モデルは実寸で置き、道路幅に合わせて縮めない。著作原点と長手軸は読み込みラッパー内で接地中心・+Zへ揃える。公共交通はマスターの公称車長とホーム制約に合わせ、車体の長手方向だけを公称車長へ補正する。

### 入口・退出経路のキャッシュと負荷

道路スナップショット更新後、入口更新用コルーチンが周辺の接道候補を点検する。道路中心線・幅・走行方向、区画version、稼働建物の集合から変更を検出し、変更した区画だけ距離・高低差・敷地内判定を再計算する。入口や道路接続、管理円外へ抜ける端点が変わっていなければ経路表は再構築しない。

経路表は「道路ID＋走行方向」の状態を持つ。建物入口と管理範囲外への出口を始点に、逆グラフを幅優先探索して出口までの段数を全車で共有する。一方通行と街路の行き止まりでの折り返しを反映する。車は交差点で接続道路の段数を比較するだけで、独立した経路探索を行わない。

入口の探索も車が道路へ入ったとき、または共有表の世代が変わったときに限る。選んだ入口への距離を通常の走行で消費するため、毎フレーム建物を走査しない。入口表の更新は `RenderWorkScheduler` の共通予算(`PerformanceConfig.SliceBudgetMs`)で協調中断し(カテゴリ `vehicleAccess`)、完成した入口表と経路表を一括交換する。道路形状の署名には、点列ごとに一度だけ計算する `VehiclePolyline.ShapeHash` を使う。単一の区画処理や初回JIT等は予算を超える場合があり、厳密なフレーム時間上限ではない。

入口表の再公開で同じ入口(同じ区画・距離差0.5m未満)を選び直したときは、路肩への寄せの進み具合を保つ。入口を失ったときや別の入口へ替わるときは、寄せ量を発生時の寄せへ移し、現在の横位置から走行距離に応じて車線へ戻す。

## 路上駐車の描画

路上駐車は走行車両とは別に `ParkedVehicleManager` が表示する。パスの `parked_cars` はその道路に同時に停まっている台数であり、日次交通量から走行台数を求める換算は行わない。道路の一覧・単体取得で受け取り、エポック後は道路メッシュのversionが変わらなくても最新値を反映する。稼働中の生活道路のうち `street_parking_capacity` が正のものだけを対象とする。建物内・敷地内の駐車はこの表示には含めない。

既存の乗用車10外観・商用車2外観・トラック4外観を、それぞれ60%・30%・10%の抽選比率で混ぜる。道路IDと候補番号で外観・候補の優先順位を固定するため、カメラの移動や再ロードで車が入れ替わらない。台数が増えると未使用候補が埋まり、減ると優先順位の低い候補から消える。小数台数は道路IDに固定した確率で丸め、道路ごとの切り上げによる過大表示を避ける。

配置に使うのは道路本体と共通の地形追従・交差点切断済み中心線である。両側の歩道を除いた車道端から0.2m内側へ車体外縁を寄せ、道路端・交差点の切断面から5mを空ける。候補間隔は実モデルの全長に1.2mを足して決める。向きは都市の左右通行に合わせ、一方通行では両側とも許可された向きを向く。高さは中心線に `RoadPartHeights.BODY_ABOVE_SPLINE` を加え、姿勢は道路の勾配に合わせる。

車幅が片側の車道に収まらない場合や、カーブで車体の四隅が歩道・中央分離帯へ張り出す場合はその候補を使わない。内カーブなどで隣の車体に重なる候補も省く。満杯になった後の路駐超過分は表示を頭打ちにし、二重駐車は描かない。シミュレーションの台数はクリップしないため、表示上限と経済上の容量は別である。走行車両・歩行者との衝突回避には組み込んでいない。

管理中心(走行車と同じ `ResolveTrafficCenter`。カメラから水平300m以内に寄せた注視点、乗車中は乗車位置)から480m以内を表示し、0.5秒間隔でセル逆引きから対象道路を取得する。形状が同じなら配置候補を再利用する。形状の比較は `PathManager.GetPathGeometryRevision` とデータの参照が一致するかで行い、一致すれば点列を取得しない(版が不明なら点列の完全一致で比較する)。管理中心が480mを超えて跳んでも配置候補と描画バッチは捨てず、新しいバッチができるまで旧表示を残す。生成と描画行列の更新は共通フレーム予算で分割し、通常モデルをメッシュ・材質別に511件以下のGPUインスタンシングで描く。モデルのロードと接地原点・前方軸の正規化は走行車両の `VehicleModelResolver`、材質抽出は `PropRenderModel` と共有する。個体ごとのGameObject・コライダー・走行音は持たない。道路の非表示指定、アンロード、都市切替では表示も解除する。

`unity/Tests/Vehicles/run.ps1 -ParkingOnly` で実FBX、車種比率、台数と端数、左右通行・一方通行、路面高さ、端部余白、狭い道路、曲線・勾配・車体重複を検証する。

## O.9. 検証と制限

`unity/Tests/Vehicles/run.ps1` は独立したUnityプロジェクトで本編のビルド済みアセンブリを使い、円との交差・再進入、車線位置、一方通行、通過曲線、残り移動時間、端数枠、環状道路の長時間走行を検証する。本編のシーンや都市データは書き換えない。

## O.10. 路線に所属する車両

`TransitDataStore` は `GET /api/v1/transit/lines` を5秒周期と明示的な更新通知で取得し、色帯と車両で共有する。色帯の表示トグルは車両に影響しない。セッション世代を照合し、古いHTTP応答で新しい都市のデータを上書きしない。

`TransitVehicleManager` は稼働中かつ調達両数から1編成以上組める路線を表示する。`train_count` は必要編成数なので表示数には使わず、調達両数÷`cars_per_train` の整数部分を使う。`TransitMotionClock` がコアの等加速度区間と停車時間を時刻から参照し、編成を実効運行間隔（`max(目標運行間隔, 1周の時間 ÷ 編成数)`。コアの `transit_capacity.effective_headway` と同じ式）ずつずらして発車させる。1周を終えた編成は、周期（編成数 × 実効運行間隔）の残りを先頭の停留所で停車して待つ（`TransitMotionClock.Schedule`）。区間ごとの `reversed`（編成の向きが先頭区間と逆か）で運転台と車両の並びを反転する。1周の継ぎ目（先頭の停留所）で折り返さない路線（環状運転など）は `Closed` になり、`TransitRouteGeometry.BuildRuns` が1周の前後に1周ずらした走行区間の写し（`Run.Wrapped`）を並べて、継ぎ目を跨ぐ編成の車端も隣の区間として解く。写しは経路そのものの描画（路線色帯）には使わない。画面外でも同じ時計が進み、毎フレームの距離積分によるずれは蓄積しない。表示上限は300両。極端に編成数が多い場合は候補を決定的に間引き、全編成を毎フレーム列挙しない。上限を超える1編成は表示しない。

鉄道は `TransitRouteGeometry.SampleConsist` が停止中心を基準に前後へ車体を並べる。偶数編成は中央の連結位置、奇数編成は中央車の前後端の経路距離の中点を時計の位置へ合わせる。各車の前後端のワールド座標間距離が公称車長になるよう経路上を探索し、隣接車は同じ車端位置を共有する。時計の論理距離に車長をそのまま足さないため、曲線長・軌道の横位置・接続区間の距離倍率が異なっても連結間隔が伸びない。

車体は前後端の中点へ置き、その弦方向へ向ける。短い地形追従線分の接線を直接車体のピッチに使わず、車長全体で傾きを求める。フレーム履歴や回転の遅延補間を持たず、同じ経路位置は停車・再表示・折り返しでも同じ姿勢になる。これは車端を基準にした剛体の描画近似で、台車の独立旋回・連結器メッシュの変形・車体幅による急曲線の衝突判定は行わない。公称車長を置けない曲線や不足した経路は表示しない。

駅・停留所の停止位置は編成中心として扱い、鉄道とLRT（走行網に線路・モノレールを含む路線種別）では、編成が停留所の乗るパス（駅のホーム、LRTでは交差点で区切られた道路・軌道の1区間）からはみ出さない範囲へコアが中心を寄せる。バスは停留所の位置に止まる。折り返す停留所では停車時間を終えてから逆向きに動き、車体の前後と個体は維持する。路線が停留所を置いた駅のホーム（`platform_width` を持つバリアント）の上だけはパスの通行方向によらず両方向に走れるものとして扱い、止まらないホームでは通行方向を守る（コアの下地経路と同じ規則。停留所のパスは `TransitRouteGeometry.BuildRuns` が停留所間の区間の境目から集めた `Route.StopPaths`）。単線の両端に同じ長さの編成を置き、両停止中心が同一点になる場合は走行距離0となり、運行能力は発生しない。

`PathManager.TryGetPathPolyline` の未切断点列でパス内の距離割合を解決する。接続部では切断区間を補い、鉄道は描画済みレールのSplineComputerをサンプリングする。別パスとの接続が未ロード・未描画なら編成を表示しない。欠けた経路を直線でつないではならない。地形・道路の再生成は0.5秒周期の周辺形状更新で反映する。LRT・鉄道の交差点レールコネクタは、`PathManager.GetNodeIntersectionObject` が返す交差点メッシュ(`NodeMesh_*`)の子 `Rail` から読む。

鉄道・LRTの軌道オフセットは `VehiclePolyline.SampleOffset` で頂点ごとの平均進行方向から求め、隣接するオフセット済み頂点を補間する。線分境界で横位置が飛ばないようにし、レール接続の端部も本線のサンプル位置へ合わせる。一般車・バスの車線サンプリングとは分け、路線ハイライトと鉄道車両は同じ軌道位置を参照する（下記の折り返しの渡り線を除く）。

軌道数2以上のパス（LRTの線路、1本のパスで上下線を持つ鉄道・モノレールの複線）では、パスと進む向きで走る軌道が1つに決まる。進行方向に対して都市の通行側で最も外側の軌道で、線路メッシュのレール接続・車止めと同じ規則（`TrackPath.TrackIndexForTravel`）である。軌道数1のパスは向きによらずその1本を走る。

同じパスの上で停留所に止まって向きを反転すると、走る軌道が入れ替わるので、編成は渡り線で移る。`BuildRuns` は、直前に動いた走行区間と同じパスを逆向きに出発する走行区間に `Run.Turnback` を付ける（1周の継ぎ目で折り返す路線の先頭の区間は、1周の最後の区間と比べる）。停車中と、停車していた編成の先頭（出発方向）の位置までは到着した軌道のまま描き、そこから `TransitRouteGeometry.CrossoverLength`（50m）の区間で出発する軌道へ横位置を移す。停車していた編成の先頭は停止中心から編成の全長（`Route.ConsistLength`＝両数×公称車長）の半分先で、この区間の位置は時計の距離（コアの水平延長）をmとみなして測る。横位置は到着した軌道と出発する軌道の位置をsmoothstepの割合で補間し、接線にも横移動の傾きを含めるので車体の向きも連続に変わる。各車は自分の車端の位置で補間するので、編成は先頭から順に渡り線を通り、連結は `SampleConsist` の剛体配置のまま保たれる。

渡り線の区間がパスの端を越える場合は、次のパスの上でも同じ割合で補間する。到着した軌道の側は、各パスの逆向きの通行側の軌道と、それらをつなぐ描画済みのレール接続（折り返す前に到着したときに通った接続）である。次のパスが単線なら、両側のレール接続はノードで同じ線路へ合流する。到着した軌道の側のレール接続が無いノード（一方通行の線路へ分かれる所など）では、出発する軌道のレール接続を到着した軌道の端へ寄せたものを到着した軌道の側とみなす。出発する軌道のレール接続が無ければ、ほかの接続と同じく編成を表示しない。

渡り線は横位置だけの描画の補間で、時計の距離・停止位置・走行時間には影響しない。バスは停車時間の最後の最大5秒で転回して前向きに走るので、渡り線を持たない。路線色帯（公共交通ハイライト）と経路編集のプレビューは編成を持たない（`ConsistLength`＝0）ので渡り線を描かず、走行区間の向きで決まる軌道を示す。

車体の接地高さは、軌道パーツの原点（スプライン+`RoadPartHeights.TRACK_ABOVE_SPLINE`）に走行面までの高さを足した位置とする。鉄道はレール頭頂の0.2m上、跨座式モノレール（`PATH_MONORAIL`）は軌道桁の天端が軌道パーツの原点なので0mで、車両の原点（走行タイヤの接地面）を桁の天端に置く。交差点のレール接続も同じ高さを使う。

`unity/Tests/Vehicles/run.ps1 -TransitOnly` は実アセンブリで、1・2・3・6両編成、曲線と細かな高低差、論理距離と描画長の倍率差、異なるパスの接続、車端の一致・位置と姿勢の連続性・折り返し・未ロード時の非補完を検証する。実都市の描画負荷や全線路形状を保証する検証ではない。

モデル対応は `Resources/Config/transit_vehicle_models.json` に置く。1001=バス、1002=メトロ、1003=LRT（車種14）、1004=モノレール（車種24）、1005=中距離鉄道、1006〜1008=国際貨物・鉱石・石油の貨物路線（貨物列車。車種22）。外観は路線ごとにプレイヤーが選んだ `vehicle_model`（路線サマリの項目。描画専用で性能には影響しない）を全編成で使い、`vehicle_model_config.yaml` の候補に無い値（未設定の-1・モデル未導入の番号）のときだけ候補から路線IDと編成番号で固定する。旅客列車の先頭・後尾は外観番号の数値名(`0`・`1`…)、中間車は外観0が `middle`、それ以外が `middle_{外観番号}` を使う。全車で外観を揃え、折り返し・再表示でも維持する。中間車の該当外観がなければ `middle` を使う。プールは車種と実体モデル名の組で分ける。外観の変更は路線一覧の次の取得で反映し、表示キーに外観を含めるため旧外観の車体はプールへ戻る。UIの車両選択のカタログ（`tauri/src/data/transitVehicleModels.json`）は路線種別ごとに同じ候補番号を並べる。車体の在庫が無い外観の編成は、1フレームに1編成だけ新しく生成する(乗車中の編成と、一部が表示中の編成は除く)。路線一覧を更新するたびに、運行中の実体モデルごとに1両ずつ、共通予算の中で事前生成する(`transitWarmup`)。旅客列車の後尾の先頭車は反対向きに置く。バスは停車時間の最後の最大5秒を使って折り返し、復路も前向きに走る。メトロと中距離列車のFBX、バスのFBXを既存のModelManagerで読む。未登録種別は表示対象にしない。

貨物は機関車1両と、残りすべてを同種の貨車で構成する。`cars_per_train` は機関車を含む総両数で、4両なら機関車1両と貨車3両になる。`transit_vehicle_models.json` は路線種別ごとに `vehicle_type` と任意の `wagon` を持ち、1006は `wagon`（コンテナ）、1007は `wagon_1`（鉱石用ホッパ）、1008は `wagon_2`（タンク）を使う。機関車の外観0/1/2とは独立した対応である。

各車の実体モデル・塗装対象・後尾の反転は `VehicleModelConfig.GetTransitCarModel` が決め、描画と事前生成が共用する。貨物では固定個体番号0が機関車で、折り返しても同じ車体と向きを維持し、帰路は機関車が後方から押す。乗車視点もこの機関車を追う。貨車にも既存の `SampleConsist`・モデル原点補正・3段階のLODを使い、同じモデルの貨車は機関車の外観や路線をまたいでプールを共有する。貨車モデルが欠落した場合は代替箱を使い、機関車へ置き換えない。

貨物のFBXはすべて20mだが、配置とホーム長判定は路線サマリの `length_per_vehicle` が正である。現行マスターの国際貨物は20m、鉱石・石油は15mなので、後者は機関車も貨車も `FitTransitLength` で15mへ調整する。

UI側のカタログ `tauri/src/data/transitVehicleModels.json` は、路線種別(transit_masterの `transit_path_id`)をキーに `{variant, prop, key}` の列を持つ。`variant` は `vehicle_model_config.yaml` にある車種の候補番号、`prop` はその外観の先頭車を写した自由配置別名のプロップ種別IDで、UIはそのサムネイルを見本画像に使う(未生成なら文言で代替する)。表示名は各言語の `transit.json` の `transit.vehicleModels.<key>`。Unity側で外観を増減したら、このカタログ・`vehicle_model_config.yaml`・表示名の3つを揃える。バックエンドは候補一覧を持たず0以上の整数かだけを検証する。貨物3路線はいずれも0=JR貨物風（見本380）、1=アメリカ風（381）、2=インド国鉄風（394）を選べる。新設・詳細の両パネルはマスターの `freight` で最低両数を2にし、機関車を含む総両数であることを表示する。カタログに候補の無い種別では選択UIを出さない。見本画像は元の塗装で写したもので、実際の車体の帯は路線カラーで塗られる。

公共交通の列車同士の閉塞・単線交換・路線バスと一般車の相互追従は未対応。運行計画に無い待ち時間をUnityだけで追加しない。設計上の理由と時間・流量の契約は [交通シミュレーションと走行描画の整合](T_交通シミュレーションと走行描画の整合.md) を参照する。

### O.10.2. 鉄道車両の接写表示

メトロ20・中距離21・高速鉄道23・トラム14・モノレール24は先頭・中間車と全外観に、貨物22は機関車3外観と貨車3種に`_close.fbx`を持つ。無印は通常モデルとして保持する。モノレール24の接写は308/309の接写版と同じFBXである。20/21/23の接写は通常と同じ寸法表から作り、曲面の分割を細かくして窓枠・扉の目地・台車や屋上機器の細部を足す。22の接写も同じ寸法表から作り、鎧戸の羽根板・碍子の笠・台車のばねと軸箱・コンテナの波板と隅金具・石炭の塊・手すりや梯子を足す。トラム14は通常の車体を曲面で張り直して窓枠・扉取手・台車・空調ファンを足す。原点・向き・寸法は通常版に合わせ、bbox差は各軸0.05m以内。既存材質を共有し、外部画像は使わない。

`VehicleModelResolver`は通常版と接写版を同じルートに置き、Unityの`LODGroup`で画面高に対する投影サイズ25%以上を接写にする。接写版がないモデルは無印を使う。公称車長への伸縮は両方に同じ倍率を適用する。通常版の最終閾値は0で、遠方の表示終了は車両マネージャーの表示範囲に従う。描画LODは経済状態・走行時計・編成位置を変えない。

自由配置用の370〜395にも接写版を同期し、既存プロップの投影LODで切り替える。モノレール308/309は手動配置モデルとして同様に接写版を持つ。著作元は各Blender原本、再生成ジョブは非公開制作ツールの`build_rail_close.py`。接写は約3,300〜12,100三角形、推定頂点予算16,000。実都市での同時描画性能は別途計測する。

### O.10.3. 道路車両の接写・遠景

乗用車10・トラック11・バス12・商用バン13の全18外観は `{外観}_close.fbx` と `{外観}_far.fbx` を持ち、通常と同じ寸法表から作る。`VehicleModelResolver.CreateInstance` は車種別の無印を解決できたとき、鉄道と同じ `LODGroup`(画面高に対する投影サイズ25%以上で接写、3.5%未満で遠景)を組む。公共交通のバスは公称車長への伸縮を全段階に同じ倍率で適用する。

接写は窓を黒い縁取りの内側へ貼り直したガラス、扉・ボンネット・トランクの目地、取手、ワイパー、レンズの厚みと灯室・プロジェクター・デイライトを持つ前照灯、後退灯・方向指示器を持つ尾灯、スポーク・ナット・ブレーキディスクの見えるホイール、枠付きのナンバー、鏡と方向指示器付きのミラーを持つ。トラックは格子の横桟・後扉の錠棒と蝶番・組み合わせ灯、バスは扉のガラス・行先表示・冷房装置の送風口を加える(8,168〜13,952三角形、推定頂点の予算16,000)。遠景は車体の側面形の角柱・窓の台形・車輪の黒い帯だけで、材質は車体・ガラス・タイヤの3〜4種(24〜36三角形)。

接写は通常と原点・配置寸法を各軸5cm以内で一致させる。遠景は原点と水平範囲を通常の0.3m以内に保ち、高さは通常の範囲内に収める。路上駐車(`ParkedVehicleManager`)は通常モデルだけを描く。自由配置の別名350〜367も同じ接写・遠景を同期し、既存プロップの投影LODで切り替える。原本は `blender/vehicles.blend`、生成ジョブは非公開制作ツールの `build_vehicles.py --road-only`(`road_vehicles.py`・`road_buses.py`・`road_trucks.py`)。外部画像・ロゴは使わない。

### O.10.4. 路線カラーの塗装

路線に所属する車両は、車体の帯などを路線カラー（路線サマリの `line_color`）で塗る。対象は路線の全編成の先頭・中間・後尾の全車で、外観の選択（`vehicle_model`）とは独立に常に適用する。`line_color` が空・不正な値のときは元の塗装のまま描く。路線カラーを変えると、路線一覧の次の取得で走行中の車両にも反映される。

## O.11. 走行音

車両はAudioSourceを持たない。`VehicleManager`は配置のたびに、`TransitVehicleManager`は描画した編成ごとに、位置と速度を`VehicleAmbience`へ通知するだけで、音源の選択・距離減衰・速度に応じたピッチとゲインは[サウンドシステム](../programs/サウンドシステム.md)の側で決まる。通知が1秒途切れた車両は自動的に鳴り止むため、描画範囲外への退出やプール復帰で音を個別に止める処理は持たない。

鉄道音は開発者の自録音とモーター音を重ねる。走行音は音程を固定したテンポ違いのループを速度に応じて混ぜ、停車時は消す。モーター音は加速すると再生速度・音程が上がり、停車時は小さく残る。

## LRTの軌道位置

`TransitRouteGeometry.Route.VehicleType`でLRTとバスの走行位置を区別する。LRTの線路(222/242/303/431)は1本のパスで上下線を持つ左右対称の複線で、車両は通行側の軌道を走り、車両と路線ハイライトが同じ経路を共有する(折り返しの渡り線を除く)。軌道中心の横位置の正は`LrtRoadParts.Offset`で、222/242は双方向時の最内車線中心(±2.5625m/±2.541667m。内部でRoadLaneLayoutを利用し、一方通行へ変えても動かさない)、303と431は±1.75m。`VehiclePolyline.SampleOffset`へ渡す符号(正=進行方向右)と都市の通行側から往路・復路の軌道が決まるので、同じパス上で折り返すと往路と復路の軌道が左右で入れ替わり、発車後に編成が渡り線で反対側の軌道へ移る(O.10の折り返しの渡り線)。高さはスプラインからのレール踏面`LrtRoadParts.RailTopAboveSpline`(埋め込み軌道0.125m=路面+0.025m、431は0.475m=軌道原点+0.355m)。停留所のホームは停止位置と同じ「割合×未切断3D点列長」で中心を決めるので、停車した編成とホームの前後位置は揃う([LRT停留所のホーム](G_道路メッシュの生成.md#lrt停留所のホーム))。ただしホームは交差点で切った区間の中に収めるので、交差点に近い停留所では、編成の端がホームの端から交差点側へ出ることがある。交差点では描画済みレールコネクタを使い、未生成なら車体を直線で補完しない。バスは最も路肩側の車線を使う。

## O.12. ドライブモード

コックピットのブルドーザー右隣のステアリングボタンから開始する。選択画面と走行HUDはUnity側の`DriveMode`が表示する。Tauriは現在言語の文言を`drive:open`で渡し、追加のネイティブウィンドウは生成しない。

- 自動車: 乗用車・商用車・トラックから選び、稼働中の道路上をクリックする。開始位置と矢印を確認し、必要なら方向を反転して出発する。一方通行に逆行する向きでは開始できない。
- 鉄道: 稼働中で必要な車両が揃っている路線を選び、その路線の線路上をクリックする。往路/復路のうち選択した進行方向の時計位相から既存の第1編成へ乗車する。バスはこの選択一覧に含めない。停車・折り返し・走行速度は路線の既存データを使い、分岐を手動選択しない。
- Spaceを押している間は一般車と公共交通が5倍速になる。離すかUnityがフォーカスを失うと等倍へ戻る。経済エポック・天気・歩行者・APIのポーリング周期・Unity全体の`Time.timeScale`には影響しない。
- Escまたは終了ボタンで元のカメラ位置・角度・投影方式・ズームへ戻る。

自動車は既存の`Vehicle`を通常の車両一覧へ1台追加する。NPCと同じ車線配置・道路速度・前車追従・交差点通過曲線を使い、乗車中だけ沿道到着予約と管理円外のデスポーンを免除する。走行は1/30秒以下の刻みで追従間隔を再評価するため、早送り中も停止した前車を飛び越えない。信号・交差する車両との衝突回避は通常NPCと同じく扱わない。

交差点手前で進入可能な道路を進行方向に対する角度順に表示する。左右キーで候補を順送りし、上キーで最も直進に近い道を選ぶ。HUDの候補をクリックしてもよい。何も選ばなければ最も直進に近い候補へ進み、交差点進入時に確定して予約を解除する。同じ方向の候補が複数ある場合も別々に選択できる。行き止まりは通常NPCと同じ条件で折り返し、進入可能な接続がなければ待機する。

鉄道の開始位置は`TransitMotionClock`のパスID・向き・パス内比率から等加速度区間の時刻へ逆算する。乗車編成を描画予算で優先し、折り返しでも同じ車両(identity=0)を追う。未ロードのパス・レールコネクタに当たった場合は乗車編成の時計を進めず、最後の編成位置でロードを待つ。失われた路線や車両不足は乗車を解除する。

カメラは車体上から進行方向を見る。自動車の視点高さは車体のRenderer境界から決め、トラックの屋根へ埋まらないようにする。鉄道は接地位置から5m上。位置は遅延させず、回転だけ平滑化する。周辺ロードと交通演出の管理中心はカメラの地面交点ではなく乗車位置にする。開始位置選択中は地図をドラッグ・ズームできるが、通常のオブジェクト選択は停止する。

通常の編集と乗車は同時に行わない。ブルドーザー/地区の常駐モードは入口で解除し、建設パネル等で編集中なら編集終了を促す。選択UI表示中はカメラ保存を止める。別の編集ステートへの遷移・リロードで終了し、都市切替では旧都市の視点を復元しない。乗車情報はバックエンドやセーブに残さない。

検証は`unity/Tests/Vehicles/run.ps1`。進路予約・直進既定値・一方通行の除外・到着予約の免除、鉄道時計の往復位置、折り返しの視点連続性、線路未ロード時の待機、終了時のカメラ復元と入力解除を本編アセンブリで確認する。


鉄道の専用遠景は14/20/21/22/23の全26モデルとモノレール308/309（走行用の24は同じFBX）にある。非公開制作ツールの`build_rail_far.py`が車体箱と左右各一枚の窓帯を著作し、車輪・台車・屋上機器を省略する。貨物22は機関車・貨車の側面形の柱（運転台・フード・コンテナ・タンクの外形）と台枠の帯で作る。原点と水平範囲は通常版を維持し、車輪・集電装置を省くため上下の範囲は通常版の内側でよい。12〜42三角形（モノレールは64三角形以内）、既存材質を共有する。`build_vehicle_props.py`は370〜395の遠景別名も同期する。走行版は画面比率3.5%未満で`_far`を選び、25%以上では存在する`_close`を選ぶ。専用版がないLODは通常へフォールバックする。自由配置はPropRenderModelの既存の投影LODで専用遠景を使う。通常・接写モデルは保持する。

## ロープウェイの循環描画

`RopewayCabinManager`はシーンロード後に自己生成し、601の索道と602の駅の完成済み区間へ小型の搬器を循環させる。運行間隔・路線・車両調達の設定は持たず、交通量や経済エポックとは独立したグラフィック演出である。乗降・停車・運賃・輸送能力を変更しない。

### 完成した駅間の抽出

`RopewayNetworkStore`が既存の`/paths/`を`path_type=PATH_CONVEYOR`で絞り、500件ずつ全ページを5秒周期で取得する。全ページが成功した時だけ一覧を公開し、途中の通信失敗では前の一覧を維持する。都市切替は`TransitDataStore.Session`と取得世代で管理し、遅れて届いた旧都市の応答を捨てる。画面外の駅も判定できるため、セルのロード境界を終点にしない。

`RopewayNetwork`はACTIVEの601/602をノードIDで接続する。連続する602は一つの駅領域として扱い、二つ以上の駅領域がある成分だけを採用する。開いた路線では最初と最後の駅の外側にある枝先を除く。工事中・撤去・断線で二駅を結べなくなった区間は対象外。次数3以上の不正な分岐は推測で接続せず、その成分を除外する。閉路は左右のケーブルそれぞれを独立した周回として扱い、横へ飛び移らない。

### ケーブルと折り返し設備

`RopewayGeometry`は`PathManager.CalculatePathPoints(path, false)`による既存の座標・地形高さ・single_spanの処理を使う。距離補間・射影は`VehiclePolyline`を共有する。左右±2.1m、中心高さは`RoadPartHeights.BODY_ABOVE_SPLINE - 0.04m`。接続点の水平オフセットを共通の断面へ合わせ、同じ点列から表示ケーブルと搬器の吊り点を求める。点列が欠けたり接点が0.2m以上離れたりした場合は直線で補わない。

開いた路線の両終端では、駅外端から内側へ`min(4m, 駅領域の長さ/2)`の位置を滑車中心とする。半径2.1mの水平半円で往復のケーブルをつなぐ。短い駅でも径を縮めず、駅端からの張り出しを許す。駅の建設条件は変更しない。中間駅では折り返さず通過し、閉路には終端設備を置かない。

端部の模型は`p602/terminal_rotor`（水平輪・ハブ・スポーク）と`p602/terminal_support`（台座・駆動部・梯子）。輪だけをケーブル速度÷半径で回転させ、台座は固定する。搬器の`p601/cabin`は吊り点原点で、既存の支持滑車・横梁を避けるよう外側へ0.65mずらしたヨークと吊り金具を持つ。車体は鉛直を保ち、進行方向の水平成分にだけ向ける。

搬器は丸みのある黄土色の腰板・薄い白い屋根・大きな青い窓を持ち、曲面に沿う二重窓枠、扉の合わせ目と取手、隅の保護材、屋根上の支持ヨーク、湾曲した吊り腕、握索部を一体のメッシュで表す。客室の外寸は幅1.96m・奥行き2.32m・高さ2.15m（車底-3.17m〜屋根-1.02m）、腰板は約0.68m。床8cm・天井12cmを見込んだ設計上の室内高は約1.95mとする。客室中心は外側へ0.22m、ヨークは外側へ0.65mとし、客室は駅の柱間へ、吊り機構は横梁の外側へ収める。屋根は窓枠に沿う約0.12m厚の蓋で、庇のような張り出しを持たない。前後の窓枠は角の曲面まで左右へ広がる。ガラスは既存の不透明な`BD_WINDOW`を共有し、内装は持たない。7,224三角形でNormal/Close共通、Farでは非表示。原本は`blender/paths.blend`の`p601/cabin`で、握索部の上端は吊り点から+0.165m。Unity座標の水平範囲はX=-0.75999〜1.19999m、Z=±1.16mで、道路幅への伸縮は行わない。制作ジョブは非公開制作ツールの`build_ropeway_cabins.py`と`ropeway_cabin_surfaces.py`。

### 時間・描画・後始末

搬器は4m/s、目安40m間隔で等間隔に並ぶ。開いた路線は最低2台、閉路は各側最低1台。時計はdoubleの非スケール時間で、画面外でも進む。形状更新時は元の先頭搬器位置を新形状へ射影して位相を引き継ぐ。地形の詳細化ではversionが変わらないため、0.5秒周期の周辺走査で元の点列も比較する。

Normal/Closeの完成済みパスに限り、視点または乗車位置から480m以内の搬器・設備を描画する。Farでは搬器・終端設備を描かず、既存の遠景パスへ戻す。オブジェクト非表示、パス全体の非表示、生成待ちにも追従する。置き換えケーブルは`PathStructureMesh`で作り、元のbody Rendererを一時抑制する。`PathPresentation.SetRendererForceOff`を介して生成待ちと復元を調停し、解除・アンロード・都市切替で元の値を復元する。

搬器個体のGameObject、物理、保存データは作らない。`ModelManager`と`PropRenderModel(GameObject)`から著作原点を保ってモデルを取り出し、511件以下のGPUインスタンシングで描く。可視区間に入る搬器番号だけを距離から求め、都市全域の搬器を毎フレーム列挙しない。形状生成は`RenderWorkScheduler`へ譲り、破棄時には生成メッシュ・専有材質を解放する。

原本は`blender/paths.blend`。通常と接写は同じ搬器・端部モデルを使う。制作スクリプトとAI補助制作の記録は非公開ツール`genesis-gallery/pipeline/jobs/build_ropeway_cabins.py`および`ropeway.md`にある。写真は構造の参考だけに使用し、画像・外部モデルを取り込まない。

## 交差点の路面標示との共有規則

舗装された街路の3本以上の交差点では、RoadMarkingRulesが左右通行・一方通行・完成済みの接続道路から車線ごとの進行可能方向を求める。矢印を置ける25m以上の道路で、一般車と乗車中の車は現在の車線で許可された方向から次の道路を選ぶ。標示と車線中心はRoadLaneLayoutを共有する。シミュレーターの経路探索・輸送量・所要時間を変更する規則ではない。

バスは確定した路線の次の道路を参照し、許可された車線へ交差点手前で滑らかに寄る。寄せる区間は最大30m（区間長の40%まで）、切断端の12m手前で完了する。鉄道・LRTの軌道位置は変更しない。短い道路や方向指定のない交差点は従来の車線を使う。路面の停止線は表示であり、信号待ち・停止による独立した時間を追加しない。
