# B. 土地形状

土地区画のポリゴン生成、分割、既存区画との重複処理、および路面辺の判定について。幾何処理はバックエンドの `geo_parcels.py` に集約され、Shapely による平面幾何の演算を前提とする。パスの形状については[[A_パス形状]]、建物のフットプリント生成には[[C_建物形状]]、土地区画の経済的な意味づけは[[4_地区と土地区画]]とあわせて読む。

## B.1. 何のための形状か

土地区画は、都市内のすべての建物および道路が立地するための地面の区画である。任意のポリゴンで表現され、そのポリゴンは建物のフットプリントの上限（建蔽率の分母）や、道路への接面判定、天然資源との重複判定など、経済シミュレーションやグラフィックの入力として利用される。

## B.2. 土地区画が持つ幾何プロパティ

| プロパティ     | プロパティ名              | 型               | 説明                                                           |
| --------- | ------------------- | --------------- | ------------------------------------------------------------ |
| ポリゴン      | `polygon`           | `[[x, z], ...]` | 土地区画の境界をなす2次元ポリゴンの頂点列。閉じた輪（末点が始点に一致する必要はない）。                 |
| 中心点       | `center_point`      | `[x, z]`        | ポリゴンの重心（Shapely の `centroid`）。地区判定やR-tree空間インデックスのキーとして使われる。 |
| 面積        | `area`              | float           | ポリゴンの面積。Shapely の `Polygon.area` で算出。                        |
| 路面辺インデックス | `facade_edge_index` | `[int, ...]`    | 外周のうち道路に面している辺のインデックス列。建物形状の生成（[[C_建物形状]]）で正面の方向を決めるために使われる。 |
| 標高        | `altitude`          | float           | 土地区画の基準標高。接道（`front_path_id` の道路）の路面高さに基づいて設定され、対象建物の接地面の高さとして使われる（[[F_建物メッシュの生成]] §2.4）。 |

## B.3. 座標系の取り扱い

土地区画の座標は2次元平面 `[x, z]` で表現される。パスやノードは3次元座標 `[x, y, z]`（`y` は高さ）を持つが、土地区画の幾何計算では高さを無視し、`(x, z)` 平面で処理する。海岸線ポリゴンも同じ2次元平面上に定義される。

## B.4. 区画の作成方法

### B.4.1. 空き領域からの区画作成（レイキャスト法）

![parcel2.png](../images/parcel2.png)

ユーザーが指定した地点を基点に、周囲の空き領域をポリゴン化して新しい土地区画を1つ作成する。`get_empty_area` で実装される。

1. 基点を中心とした探索矩形（デフォルト110m四方）を設定する
2. 矩形内の既存土地区画と道路の占有ポリゴンをR-treeで検索し、各々をわずかに膨張（等方スケールで約0.1m拡大）させた障害物ポリゴンとする
3. 基点から360方向にレイを放射し、各レイが障害物または探索矩形の境界に最初に衝突した点を求める（**レイキャスト**）
4. 360個の衝突点からなる粗いポリゴンを生成し、障害物を差し引く
5. 基点を含む連結成分のみを残す

**頂点の平滑化** — レイキャスト直後のポリゴンは360頂点で構成されており、冗長な頂点が多い。以下の処理を頂点数が収束するまで（最大10回）繰り返す。

- **鋭角頂点の除去** — 前後の辺のなす角が15度未満または345度を超える頂点を削除する
- **直線上頂点の除去** — なす角が175〜185度の頂点（ほぼ直線上にある頂点）を削除する
- **近接頂点のマージ** — 連続する2頂点の距離が `NEAR_PARCEL_NODE_THRESHOLD` 未満の場合、基点から遠い方を削除する

最後に Shapely の `simplify`（Douglas-Peucker アルゴリズム）で指定許容値（デフォルト2m）まで簡略化する。

### B.4.2. パス沿いの区画作成

![parcel4.png](../images/parcel4.png)

既存のパス（道路）に沿って、指定した側に連続した台形区画を生成する。`get_path_parcels` で実装される。生成する側はパスの進行方向を基準にした `left` / `right` / `both`（両側）の3通りで、`both` は左右それぞれを独立した帯として生成したうえで、重なりの解消をまとめて1回行う。この3つ以外の値は左側へ倒さず入力エラーとして拒否する。

1. パスの始点・ウェイポイント・終点から座標列を構築する
2. 各セグメントの進行方向に対して、指定側（左右）の単位法線を計算する
3. 折れ点では前後セグメントの法線を平均化して滑らかに接合する
4. 各セグメントを指定された幅で等分割し、各分割区間の両端から法線方向に「道路半幅＋指定された奥行き」だけ伸ばした台形ポリゴンを生成する

生成された台形群からは、道路の占有ポリゴンと既存の土地区画が差し引かれる。区画の前面は実際の路肩に一致し、**奥行きは道路中心ではなく路面際から測る**ため、同じ奥行きを指定すれば道路幅によらず同じ奥行きの区画になる。差し引きで生じた細い突起や、面積が閾値未満の小片は区画にせず破棄する。

### B.4.3. 既存区画の分割

既存の土地区画を複数の小区画に分割する。元の区画は削除され、分割結果が新たな区画として登録される。`geo_parcels.py` に3つの分割アルゴリズムがある。

#### 外周分割（`subdivide_parcels`）

![parcel3.png](../images/parcel3.png)

外周に沿ってシード点を配置し、Voronoi 分割で区画を生成する。街区を区切るような自然な分割に向く。

1. 目標区画数を総面積と目安面積から算出する
2. 外周の**凹頂点**（内角が180度未満の頂点）をシードとして採用する
3. 各辺を均等に区切る追加シードを外周上に配置する
4. すべてのシードを重心方向にわずか（2m）内側にシフトする
5. シードに対して **Voronoi 分割**を計算し、各 Voronoi セルを元のポリゴンで切り抜く
6. Voronoi 分割で取りこぼされた領域があれば最大セルに吸収する

Voronoi の無限遠領域は、`voronoi_finite_polygons_2d` で有限ポリゴンに変換される。これは、無限に伸びる境界線をシード間の中点から十分遠い距離で打ち切る手法である。

#### 矩形分割（`get_rectangle_parcels`）

![parcel1.png](../images/parcel1.png)

最寄りの街路の方向を基準フレームとして、列×帯の格子状に分割する。規則的な街区割りに向く。

1. 最寄り街路の中心線接線方向を主要軸とする（周辺に街路が無い場合のみ**最小回転外接矩形**の長辺方向にフォールバックする）
2. 奥行き方向（主要軸に直交する方向）を、目安面積から求めた理想的な区画奥行きを持つ列へ分割する。奥行きの深い領域では列が3列以上になり、道路に面しない「内陸」の区画も生成される（列数を絞ると極端に細長い短冊状の区画ができてしまうため）
3. 各列を主要軸方向に、面積が目安面積に近づくよう等分割する
4. 各格子セルと元ポリゴンの共通部分を区画とする

#### 矩形ランダム分割（`get_rect_random_parcels`）

矩形分割と同じ格子分割に、区画幅・列境界のゆらぎ（ジッター）を加えたもの。道路には整列するが区画幅・背割り位置が不揃いという、実際の旧市街の地割りに近い分割を生成する。乱数源を固定できるため、プレビューと確定で同じ形状が得られる。

### B.4.4. ブロック一括の区画作成

クリック地点の周囲の道路を検出し、その街区に面する各道路沿いへ区画を並べる。`create_parcel_block` は `get_empty_area` による単一区画の形状生成を経由せず、`get_block_parcels` を直接呼ぶ。街区形状は生成範囲の制限であり、区画の間口方向は実道路の側面から決まる。

1. 探索矩形と交差する道路占有ポリゴンをR-treeで取得し、矩形から差し引く。クリック地点を含む連結成分を対象街区にする。レイキャストを使わないため、L字などの凹街区でもクリック地点から見えない腕を含めて扱える。閉じていない道路配置では探索矩形が上限になる。
2. 各道路の占有境界から対象街区に面する側面区間を抽出する。`_detect_block_frontages` は道路ID、左右、中心線上の区間、街区内側が左になる側面点列を保持する。生成元は稼働中かつ `path_allows_frontage` を満たす街路のみ。探索矩形の辺、道路の終端面、隣の街区の道路側面は生成元にしない。
3. 側面を大きな折れ点で区切り、間口を弧長で等分して指定奥行きだけ内側へ伸ばす。曲線上の頂点を保つ法線オフセット処理は道路沿い作成と共通で、奥行きはどちらも道路際から測る。
4. 角を共有する側面列を別グループに分け、長い通りを含むグループから生成する。後続の側面列は先行区画の帯を避けてから間口を等分する。向かい合う帯が競合する部分だけ、側面サンプルの最近傍領域によって概ね中間で背割りする。競合しない部分は領域制限をかけず、曲線外側などが有限ボロノイの外縁で欠けるのを防ぐ。生成済み区画との差集合で重複を防ぐ。
5. 既存区画を差し引き、細い突起を除去したうえで生成元道路に2m以上面する単純ポリゴンだけを残す。穴のある形状は区画へ変換しない。20m²未満の小片は同じ通りの有効な隣接区画へ共有辺で統合できる場合だけ吸収し、残りは空地にする。既存区画は街区検出を遮らず、変更も削除もしない。

中央の余りは空地にする。道路が見つからない場合や有効な沿道区画が残らない場合は0件を返し、UIで探索範囲・区画寸法の調整を案内する。ランダム分割への自動切り替えは行わない。

設定は探索範囲（横・縦）、間口、奥行き、ばらつき。ばらつき0は均等な間口になり、正の値では間口にゆらぎを加える。乱数は入力から固定し、道路候補もID順に処理するため、都市の状態と入力が同じならプレビューと確定の形状が一致する。

新規作成ボタンは「道路沿い」「ブロック一括」「ランダム」「単一区画」の順。既存区画の矩形分割・ランダム分割は別グループで提供する。任意形状が必要な場合は単一区画を作成してから頂点を編集する。

## B.5. 海岸線との処理

陸上土地区画（`PARCEL_LAND` / `PARCEL_SHORE`）を作成する際、ポリゴン形状は海岸線でクリップされず、入力された形状がそのまま保持される。海岸線は判定にのみ使用し、形状を変形させない。

### 海岸線ポリゴンの取得

海岸線ポリゴンはバックエンド（コアシミュレーター）の `Terrain.compute_coastline_polygon()` で計算され、`city.terrains["coastline"]` に GeoJSON ライクな dict 形式で格納される。フロントエンドからは `GET /api/v1/terrain/coastline` で取得できる。

レスポンス形式:
```json
{
  "type": "Polygon" | "MultiPolygon",
  "coordinates": [...]
}
```

座標系はワールド座標（マップ中心が `(0, 0)`）。複数島がある場合は `MultiPolygon` となる。

### PARCEL_SHORE の自動判定

土地区画作成時に `parcel_type` が未指定の場合、ポリゴンが海岸線の外周と接する（=海岸線を跨ぐ）かどうかで `PARCEL_SHORE`（沿岸区画）か `PARCEL_LAND`（内陸区画）かを自動判定する。これは `touches_coastline()` 関数で判定し、数値誤差対策として 0.5m 以内の近接も「接触」とみなす。`parcel_type` が明示指定されている場合はそれを尊重し、上書きしない。

港湾施設などは `PARCEL_SHORE` の区画にのみ建設可能である。海岸線データが未設定の場合は SHORE 判定を行わない（フォールバック矩形に対する誤判定を防ぐため）。

## B.6. 既存区画との重複処理

新しい土地区画を作成する際、既存の土地区画と重複する領域の処理が必要になる。`handle_overlaps` フラグが有効な場合、以下の処理が行われる。

1. 新しいポリゴンと重複する既存区画をR-treeで検索する
2. 各既存区画との差集合（`difference`）を取ることで、重複部分を除外する
3. 差し引きの結果が MultiPolygon に分割された場合は、面積1m²以上の各ポリゴンを独立した土地区画として登録する
4. すべて差し引かれて空になった場合は区画を作成しない

道路・線路（パス）は土地区画を持たず、土地区画の無い場所にのみ敷設できるため、この重複処理の対象外である。パスの占有範囲が既存の土地区画と重なる場合は、着工時に重なりの程度・所有者・建物の有無に応じて、区画の削除（収用）・重なり部分だけの削り取り（部分収用）・着工待機のいずれかになる。詳細は[[../economics/3_道路網|3_道路網]]の「着工時の土地区画との重なりの扱い」を参照。

## B.7. 路面辺と接道の判定

土地区画の外周のうち、どの辺が道路に接しているか（路面辺 `facade_edge_index`）と、どの道路を接道（`front_path_id`）とするかを判定する。`recalculate_facade_edge_index` で実装される。路面辺は建物形状の生成（[[C_建物形状]]）において、どの辺を「正面」とするかを決めるために不可欠である。

路面辺と接道は異なる距離基準で判定される。

- **路面辺**: 道路に物理的に接している辺だけを抽出するための厳しい基準。辺の中点と道路中心線の距離が「道路幅の半分＋数mの余裕」以下の辺のみが路面辺となる。判定点を辺の中点とするのは、道路沿い区画の側面の辺（道路と直交する辺）も端点は道路際に接しており、辺全体の最短距離では路面辺と誤判定されてしまうためである。
- **接道**: 道路からやや離れた区画にも接道（＝所属地区の伝播経路。[[4_地区と土地区画]]）を保証するための緩い基準。いずれかの辺との最短距離が一定の閾値（100m）以内にある最も近い街路が接道となる。

### 判定アルゴリズム

1. 土地区画のバウンディングボックスにマージンを加えた範囲で、R-treeにより周辺のパスを検索する
2. 検索されたパスのうち街路（`PATH_STREET`）だけを抽出し、3次ベジエ曲線をサンプリングした中心線 `LineString` に変換する（3次元座標は高さを無視して2次元に変換）
3. 土地区画の外周を各辺（`LineString`）に分解する
4. 各辺の中点と道路中心線の距離が「道路幅の半分＋数mの余裕」以下の辺を「路面辺」として判定する
5. いずれかの辺との最短距離が閾値（100m）以内で最も近い街路を接道とする
6. 接道が定まったのに路面辺が1つも無い場合（道路からやや離れた区画）は、接道に最も近い辺1つを路面辺として補完する。これにより接道を持つ区画は必ず1つ以上の路面辺を持つ

複数の辺が路面辺になることがある（角地など）。閾値以内に街路が無い場合は `facade_edge_index` は空リスト、`front_path_id` は未設定となる。

## B.8. リソースとの紐付け

土地区画のポリゴンと重複する天然資源（鉱脈や油田など）を検索し、`resource_id` に `{resource_type: resource_id}` の辞書として設定する。R-treeで候補を絞り込んだのち、Shapely の `intersects` で実際の重複判定を行う。工業バリアントの立地倍率計算で参照される（[[4_地区と土地区画]]）。

## B.9. 地区への自動所属

土地区画が作成または更新されると、中心点から所属する地区（ゾーン）が判定される。ポリゴンの変更時には、所属地区の再計算、建築規制（建蔽率・容積率・高さ制限・建築可能タイプ）の再反映が行われる。

## B.10. 土地区画の削除

土地区画の削除には以下の制約がある。

- 建物が建っている（`usage_id` が `VALUE_NONE` 以外の）区画は、建物が `STATUS_EMPTY` でない限り削除できない
- 削除時は、所有者に対して土地価格と建物の残存価値の合計を買収金として支払う
- 削除後に所属地区の `parcel_ids` から当該区画を除外し、整合性を保つ
