# 建物パーツ作成マニュアル

一点物観光名所（`landmark-*`）は通常・接写・専用遠景のprebuiltを持つ。`_far` は通常版と同じ原点・外寸・積み上げ構成で著作する（外寸許容差0.3m）。接写の外寸許容差は0.05m。都市に各1棟のモデル全体を1パーツへ収めるため、名所1パーツのUnity推定頂点予算は通常12,000・接写40,000・遠景5,000。多数反復される一般建物とは予算を分ける。実測三角形数とUnity頂点数は制作記録へ残す。詳細は [[F3_既成建物のメッシュ生成]]。

オープンスペース用の `site_stop` / `site_bench` / `site_tree` / `site_shelter` は水平中心・接地0を原点に実寸で著作する。Blender -YがUnity +Zで、ベンチの正面もこの向き。全ノード変換を含めて結合し、配置では伸縮しない。`site_asphalt` / `site_paving` / `site_grass` / `site_marking` はfloorと同じマテリアル参照専用。壁パーツは不要。寸法・構成は [[F10_オープンスペースのメッシュ生成]]、検査はバリデータのsite-originと頂点予算で行う。

## 1. 建物モジュラーパーツのコンセプト

都市の底面ポリゴン（footprint）の形状や階数、階高に応じて、3Dモデルをリアルタイムに組み立てるためのモジュラーアセットの制作規格。
各パーツは動的な配置や拡縮が行われるため、特定のサイズや形状に依存せず、常に以下の共通規格に従ってモデリングされる。

---

## 2. 壁パーツ（Wall Part）の制作規格

壁パーツ（`w`）は、建物の直線的な辺を埋めるためのパーツである。辺の長さに応じてX軸方向に並べられ、端数はプログラムにより拡縮されて隙間なく配置される。

### 2.0 サイズの規格（実寸主義）

パーツは**実寸（1 Blenderユニット = 1m）**でモデリングする。

- **幅（X）**: 実寸。この幅が敷き詰めの1ユニットになる（例: 幅4mの窓付き壁タイルは、壁面に約4m間隔で並ぶ）。枚数は「敷き詰め範囲 ÷ 著作幅」の**四捨五入**で決まり、端数はプログラムがX方向に微伸縮（拡大・縮小の両方）して吸収するため、実際の間隔は著作幅から最大 ±25% 程度ずれる。装飾が横に伸び縮みして困る造作は、壁パーツではなく `entrance`（実寸配置。§4.6）で作ること。
- **高さ（Y）**: レベルによって扱いが異なる。下の表を参照。
- **奥行き（Z）**: 実寸。壁の厚みそのものになる。

| レベル | 高さの扱い |
| --- | --- |
| `base-w*` / `base-c*`（1階） | **実寸。そのままの高さで描画される。** 階高に合わせたスケールはかからない（§2.0.1） |
| `mid-w*` / `mid-c*`（中層） | 高さが階高（`height_per_floor`）になるよう**Y方向のみ**スケールされる。実寸で作るのが望ましいが厳密でなくてよい |
| `top-w*` / `top-c*`（最上階） | **実寸。そのままの高さで描画される。**（§2.0.1） |

中層だけスケールされるのは、積む枚数で建物の高さを調整する「詰めもの」だからである。**X・Zは高さに連動してスケールされない**（等方スケールではない）。

なお、この判定は「階のレベル」で行う。`base-w1` を用意せず `mid-w1` へフォールバックさせた場合でも、1階はスケールされず `mid-w1` の著作高さのまま描かれる。

### 2.0.1 スケールされないのは形状だけ（配置位置は階高グリッド）

**各階の床面の高さは常に `階数 × 階高` で決まる。** 1階・最上階のパーツをスケールしないというのは形状の話であって、上の階が持ち上がったり下がったりはしない。したがって著作高さと階高がずれると、そのまま見た目に出る。

- **階高より低く作った場合** — 上の階との間に隙間が空く（階高 4m・`base-w1` が 1m なら 3m の空隙）
- **階高より高く作った場合** — 上の階のパーツに埋もれる（階高 4m・`base-w1` が 10m なら、2階のパーツは 4m の位置から始まるので重なる）

いずれもプログラムは補正しない。**通常は 1階・最上階もその建物の階高に合わせた高さで作ること。** 意図的に隙間や重なりを作る（ピロティ、深い庇、貫通する装飾など）ためにこの仕様を使ってもよい。

1階・最上階では位置違いのパーツ（`base-w1` と `base-w3` 等）の高さを揃えて作ること。揃っていなくてもプログラムは補正せず、そのまま高さの不揃いな壁面になる（階の高さには位置1のパーツだけが反映される）。

XZ実寸が 0.3m 未満のパーツには警告ログが出る。cm単位や 1×1 の単位スケールでエクスポートしてしまった疑いが強いためである。**プログラムは補正しない**ので、必ず実寸で再エクスポートすること（§5 のエクスポート設定を確認する）。

### 2.1 原点（ピボット）の位置

* **X軸（幅方向）**: **中央（Center）**
  * 配置プログラムが壁区間を等分割し、各区間の中心座標を基準として壁パーツを配置・拡縮するため。
* **Y軸（高さ方向）**: **床面（Bottom / 0.0）**
  * 各階の床面高さ（`floorY`）を基準に配置されるため。
* **Z軸（奥行き方向）**: **外壁のアライメントライン（基準面）**
  * 基本的には建物のポリゴン境界となる面に一致させる。

### 2.2 向きと軸

* **ローカルX軸**: 壁の伸びる方向（右方向）
* **ローカルY軸**: 高さ方向（上方向）
* **ローカルZ軸**: 奥行き方向（外壁から内側、または内側から外側への方向）

## 3. 角パーツ（Corner Part）の制作規格

角パーツ（`c`）は、建物の角（ポリゴンの頂点）に配置され、隣接する2つの壁を接続するためのL字型のパーツである。

### 3.1 原点（ピボット）の位置

* **X軸・Z軸（水平面）**: **角の頂点（交点 / 0.0, 0.0）**
  * 建物の底面ポリゴンの頂点座標に直接ピボットを重ねて配置するため。
* **Y軸（高さ方向）**: **床面（Bottom / 0.0）**
  * 壁パーツと同様に、各階の床面高さを基準に配置されるため。

### 3.2 向きと軸

配置プログラムは、角の頂点に隣接する2つの辺（壁方向ベクトル）の二等分線（Bisector）の向きに角パーツの正面を回転させる。
この配置特性から、角パーツのアームは以下のローカル軸に沿ってモデリングする。

標準パイプライン（§5.1設定A）では、**Blenderの +X / +Y にアームを著作する**。
Unityにインポートした `sharedMesh` ではそれぞれ **−X / −Z** になる。
配置回転後は −X アームが送り側、−Z アームが受け側の辺に沿う。
Blender著作座標とUnityメッシュ座標を混同しないこと。

### 3.3 アームの長さの仕様

壁パーツの配置開始位置および終了位置は、角パーツのアームの長さに応じて自動計算される。
* 配置プログラムは、**角パーツを実際に配置した状態の全頂点を、隣接する辺の方向へ射影した最大値**をアームの張り出し量として自動検出する。ローカル軸のバウンディングボックスではないため、庇や胴差しなど辺方向へ伸びる造作もそのまま張り出しとして扱われ、**壁はその先端から始まる**。
* 角パーツのアーム長はモデリング時に任意の長さに設定可能で、**実寸（メートル）がそのままワールド空間のアーム長になる**（角パーツもXZ方向にはスケールされない）。高さの扱いは壁パーツと同じで、中層（`mid-c*`）だけ階高へY方向スケールされ、1階（`base-c*`）と最上階（`top-c*`）は著作高さのまま描画される。**同じ階の壁パーツと高さを揃えて作ること。**
* アームを辺方向へ長く伸ばすほど壁の敷き詰め範囲は短くなる。辺の長さが両端のアーム長の合計以下になる短い辺では、壁パーツは1枚も置かれず角パーツだけで埋まる。
* 角パーツを用意しない建物では張り出しが 0 として扱われ、壁が辺いっぱいに敷き詰められる。

## 4. スキンメッシュ角パーツのボーン（アーマチュア）構造

建物の内角が90度以外（鋭角や鈍角）になる場合、角パーツのL字の開き角を角度に合わせて曲げるためにボーン変形（スキニング）を使用する。

### 4.1 ボーン構成

`SkinnedMeshRenderer` を用いた角パーツでは、以下の2本のボーンをアーマチュアとして構成する。

* **`Bone`**（`bones[0]`）: Blender +X（Unityメッシュ −X）の送り側アーム。
* **`Bone.001`**（`bones[1]`）: Blender +Y（Unityメッシュ −Z）の受け側アーム。

これは§5.1設定Aで書き出した場合の割り当てである。Unityは名前ではなく
`SkinnedMeshRenderer.bones` の順番で回し、0番を +halfDiff、1番を −halfDiff とする。
名前が正しいだけでは不十分で、取り込み後の配列順・ウェイト・実際の開き方も検証する。
**敷地フェンスの角（`fence-c*`）にはこのリグを必須とする**。敷地境界は90度とは限らず、
ボーンなしの丸い90度角を置くと直線の畦や塀から離れる。バリデータは
`fence-corner-rig` でボーンの欠落を検出する。

### 4.2 ボーンの配置と挙動

* **ボーンのルート（基点）の位置**: **角の原点 `(0,0,0)`** に一致させる。
* **ボーンの回転**:
  * 角度が90度からズレた場合、プログラムが `Bone` を +halfDiff、`Bone.001` を −halfDiff だけワールドY軸周りに回転させて開き角を調整する。
  * 直線パーツとの接続端は対応するボーンへ完全に追従させる。丸い中央部は連続ウェイトで両ボーンを混ぜ、角度を開いてもメッシュが裂けないようにつなぐ。

農地 `b32/0/fence-c1` は42頂点の丸い畦で、中央だけウェイトを補間し、両端の断面を
`fence-w1` に揃える。ライブラリのリグ設定は `genesis-gallery/pipeline/jobs/rig_b32.py`。
検証では90度のプレビューだけでなく、鋭角・鈍角・180度に近い角で壁との継ぎ目を見る。

## 4.5 既成建物パーツ（prebuilt）の制作規格

既成建物（MODEL_PREBUILT。[[F3_既成建物のメッシュ生成]]）用のパーツは、モジュラーパーツと異なり底面ポリゴンに沿った動的組み立てを行わず、モデルをそのまま建物原点に積み上げる。

* **base-prebuilt**: 1階部分。**一切スケールされず実寸のまま**配置される。ただし次段（mid）の位置は階高で決まるため、階高とずれた高さで作ると隙間や埋もれが出る（§2.0.1 と同じ仕様）。通常は階高に合わせて作ること。
* **mid-prebuilt**: 繰り返しフロア1階分。配置時に高さが階高になるよう**Y方向のみ**スケールされる（XZは実寸のまま）。階数分繰り返し積まれるため、上下の断面が連続するようにモデリングする。**FBXには必ず1階分だけを入れること**。プログラムはファイル全体を1階分として階高に縮めるため、Arrayモディファイアの繰り返しなどが適用されたままエクスポートすると、全セグメントが1階分の高さに押し潰される。
* **top-prebuilt**: 頂部。base と同じく**一切スケールされず実寸のまま**配置される。尖塔などの装飾に加え、「完成済みの建物モデル丸ごと」を top-prebuilt 1つとして保存する使い方ができる（base/midを置かなければ接地する）。
* **原点**: XZはモデルの中心（建物の center_point に重なる位置）。Yは**原点（0.0）が接続点（接地基準）**になる。地形の凹凸で建物が浮いて見えないよう、**底面は 0.0 より下（地中）へ延ばしてよい**（むしろ推奨。既成建物はコンクリート基盤が生成されないため、地中への延長が基盤の代わりになる）。底面が 0.0 より上にあると接地せず浮くので禁止。
* **複数オブジェクト構成のFBXも可**: 全メッシュがノードのTransform込みで結合されて描画される。
* **天面はモデル側で閉じる**: プログラムは積み上げの天面を塞ぐパネルを生成しないため、上から見える面はモデル側でモデリングしておくこと。
* **敷地の装飾パーツ（任意）**: fence-w1 / fence-c1（土地区画の外周フェンス）・tile（敷地に敷き詰めるタイル）・floor（地面パネルのマテリアル）を同じフォルダに置くと、モジュラー建物と同様に敷地へ配置される。置かなければ何も描画されない。**地面パネルはマスターデータの `draw_floor=yes` の建物でのみ描画される**（未設定は描画しない）。`draw_floor=yes` の場合、floor パーツは `a{variant}`→`b{bd_type}`→`common` の順で解決され、どこにも無ければ描画されない。

## 4.6 エントランスパーツ（entrance）の制作規格

エントランス（`entrance`）は、建物前面の辺（底面ポリゴンの最初の辺）の中央・地面レベルに1棟につき1つだけ置かれるオプションパーツである（[[F_建物メッシュの生成]] §11）。玄関ドア・庇・アプローチ階段などを表現する。

* **スケール**: 一切スケールされない。**実寸**でモデリングする。
* **原点（ピボット）**:
  * **X軸（幅方向）**: **中央（Center）**。前面の辺の中点に原点が重なる。
  * **Y軸（高さ方向）**: **地面（Bottom / 0.0）**。
  * **Z軸（奥行き方向）**: **外壁のアライメントライン（基準面）**。壁パーツ（§2.1）と同じ基準。
* **向きと軸**: 壁パーツ（§2.2）と同一。壁パーツと同じ座標系で著作すれば、そのまま前面の壁面に重なって配置される。
* 辺の長さは建物ごとに異なるため、幅は控えめ（数m程度）に作ると小さな建物でもはみ出しにくい。

---

## 4.7 無地の壁パーツ（generic-wall）の制作規格

無地の壁（`generic-wall`）は、**マテリアルの参照専用**のパーツである。プログラムがプロシージャルに張る壁面（切妻屋根の妻壁。[[F1_モジュラー建物のメッシュ生成]] §3）に、その建物の壁と同じ材質を与えるために使う。

* **形状は使われない**: 配置されるのはプログラムが生成する板で、このパーツのメッシュは描画されない。`ceil` / `floor` と同じ扱い。1枚のポリゴンにマテリアルを割り当てただけのモデルでよい。
* **マテリアル**: **窓や開口の意匠を含めない**、外壁と同じ材質のタイリングテクスチャにする。通常の壁パーツ（`base-w1` 等）の材質を流用すると、妻壁の三角形に窓が並んで不自然になる。
* **UV**: プログラムはワールド座標ベースのUV（1m あたり 0.2）を与えるため、タイリングして破綻しないテクスチャにする。
* パーツを置かなかった場合は、その建物の壁パーツのマテリアルが代わりに使われる（窓が乗るため見た目は妥協になる）。切妻屋根（MODEL_MODULAR_GABLE）・片流れ屋根（MODEL_MODULAR_SHED）の建物には用意することを推奨する。

## 4.8 荷役クレーンパーツ（port_crane）の制作規格

荷役クレーン（`port_crane`）は、港湾（MODEL_PORT。[[F4_港湾岸壁のメッシュ生成]] §6）の岸壁の水際に沿って並べられるオプションパーツである。ガントリークレーン、アンローダー、ジブクレーンなどを表現する。

* **スケール**: 一切スケールされない。**実寸**でモデリングする。
* **原点（ピボット）**:
  * **X軸（幅方向）**: **中央（Center）**。原点が水際の境界線上に乗る。
  * **Y軸（高さ方向）**: **岸壁上面（Bottom / 0.0）**。脚の接地面を 0.0 に合わせる。
  * **Z軸（奥行き方向）**: **水際の境界線**。原点より **+Z 側が海**、**−Z 側が陸（岸壁の上）**になる。
* **向きと軸**: **ローカル +Z が海側**を向く。ローカル X が水際に沿う方向。壁パーツ（§2.2）とは Z の向きの意味が異なるので注意。
  * **Blender で著作するときは −Y が海側**になる。§5.1 の標準設定で書き出した FBX を Unity に読むと Blender の (x, y, z) は Unity の (−x, z, −y) に写るため、Blender の +Y 側に脚や上屋を置き、−Y 側へブームを振り出す。+Y を海と取り違えると、岸壁ではなく海の上に建って陸を向く。
* **幅（X）**: 実寸幅がそのまま設置間隔の基準になる（間隔 = 幅 × 4.5。`PortBuildingMeshBuilder.CRANE_SPACING_RATIO`）。**水際の長さがこの幅に満たない岸壁にはクレーンが1基も置かれない**ため、小さな港にも出したい場合は控えめな幅で作る。
* **張り出し**: ブームを海側（+Z）へ、カウンターウェイトを陸側（−Z）へ伸ばしてよい。海側への張り出しはクリック判定（コライダー）には含まれない。
* **複数オブジェクト構成のFBXも可**: 全メッシュがノードのTransform込みで結合されて描画される。

## 4.9 車両基地パーツ（yard_*）の制作規格

車両基地（MODEL_RAIL_YARD。[[F9_車両基地のメッシュ生成]]）が敷地内へプロシージャルに配置する素材パーツ群。全パーツ共通で、**ローカル +Z が線路方向**（パスの線路パーツと同じ。壁パーツの「X=辺方向」規約とは異なる）、**Y=0 が接地面**、軌間と高さは実寸を保つ。線路・架線は長手方向の端数調整と曲線変形、`yard_beam` は柱間へのXスケールを行う。全メッシュがノードのTransform込みで結合される（port_crane と同じ扱い）。

* **yard_track（線路タイル）**: 1軌道分（レール2本+枕木+道床天端層）を長さ2mのタイルで作る。X中央=軌道中心。レール踏面の高さ・軌間は電化線路パーツ（[[N_線路メッシュの生成]] §1、`build_electric_rail.py` の `GROUND_RAIL_TOP`=0.355 等）と揃えること。ずれると本線との継ぎ目で食い違う。配置はメッシュ bounds でZ始端を再基準化するため原点位置は自由。
* **yard_wire（架線タイル）**: トロリ線+吊架線+ハンガーを yard_track と**同じタイル長（2m）**で作る。Y=0 は線路と同じ接地基準で、トロリ線の高さは著作ジオメトリが持つ（レール面上約5m）。線路と同じ弧長・接線で変形して配置する。レール・道床・架線の長辺は0.5m以下に分割し、曲線でタイルの弦が残るのを防ぐ。
* **yard_pole（架線柱）**: Y=0 が設置面。**「右側用」**（軌道中心側が −X）で著作し、反対側はコードがヨー180°で配置する。
* **yard_beam（門型梁）**: 著作幅 6m（X: −3..+3）で作り、コードが実際の柱間へ**Xスケール**する。梁の高さは著作ジオメトリが持つ。
* **yard_stop（車止め）**: 行き止まり端に置かれる。Z=0 が線路端で、造形は +Z 方向（線路の内側）0〜1m 程度に収める。バッファ高さはレール面に合わせる。
* **yard_shed（検修庫）**: 原点=XZ中心・Y=0接地。幅は線路間隔（5m）×2線分+余裕（現行 11.2m）、全長 24m。**軒の内法はトロリ線（約5.4m）より高く**し、両妻面は全開口にして線路・架線が貫通できるようにする。

## 4.10 タイルパーツ（tile）の制作規格

タイル（`tile`）は、地面アセット（MODEL_MODULAR_GROUND。[[F2_地面アセットのメッシュ生成]] §3）が
土地区画のポリゴン内にグリッド状に敷き詰めるパーツである。畑の畝、太陽光パネルの架台、
油田の汲み上げユニットのように「同じユニットが敷地の広さぶんだけ並ぶ」施設を表現する。

* **スケール**: 一切スケールされない。**実寸**でモデリングする。
* **著作寸法＝配置ピッチ**: メッシュバウンディングボックスの X・Z（Blenderでは X・Y）が
  そのままグリッドの1ステップになる。パーツ間に隙間を空けたい場合は、パーツ自体を
  その間隔を含んだ大きさで作る（プログラムは間隔を足さない）。
* **原点（ピボット）**: 位置は自由。配置時にメッシュ bbox の最小コーナーがグリッドの
  セル隅へ合わせられるため、原点のずれは実害を持たない。
* **Y軸（高さ方向）**: **bbox の最下点が地面に合わせられる**。したがって prebuilt（§4.5）と違い、
  **底面を 0.0 より下（地中）へ延ばしてはいけない**。地中への延長は接地基準を押し下げるのではなく、
  その延長ぶんだけモデル全体を浮かせてしまう。接地面を Z=0 にして著作すること。
* **大きすぎるタイルは1枚も置かれない**: 配置は「土地区画AABBにタイルが丸ごと収まる位置」かつ
  「タイル中心がポリゴン内側」のグリッド点だけに行われる。区画のAABBがタイル1枚に満たないと
  1枚も置かれず敷地が空になるため、**小さい区画でも1枚は載る大きさに抑える**。
* **隣接タイルとの連続**: 配管・畝・柵などタイル境界をまたいでつながって見せたい造作は、
  タイルの辺いっぱい（bboxの端から端）まで通す。隣のタイルの同じ造作と端で接続される。
* **傾斜地では頂点単位で地形に追従する**（[[F_建物メッシュの生成]] §9.4）。背の高い造作は
  斜面でわずかにせん断されるため、極端に高いものはタイルに向かない。
* **複数オブジェクト構成のFBXも可**。ただしノード変換は無視されるため（[[F_建物メッシュの生成]] §6.2）、
  ジオメトリのローカル座標で組んでおくこと。

## 4.11 外階段・階間スロープ（base/mid/top-stair）

`mid-stair` を同じ閾値の `mid-w1` とともに置くと、モジュラー建物の外階段が有効になる。
base/topが無い階はmidを使う。`ceil` は屋根材質の名前であり、階段の終端は `top-stair` とする。

| 項目 | 規約 |
| --- | --- |
| 原点 | 後退前のフットプリントの頂点3（0始まり）。高さ0は各階の床面 |
| Blenderの向き | −Xが頂点3→2、+Yが建物内側、+Zが上。原点を動かさずジオメトリをずらして横位置を指定できる |
| Unityでの向き | 標準FBXの結合後は+Xが頂点3→2、−Zが内側、+Yが上 |
| 水平範囲 | Blender X≤0・Y≥0。横の再基準化・伸縮・反復は行わず、実寸で各階に1個 |
| 垂直方向 | base/topは実寸。midだけ階高÷同じ閾値のmid-w1の著作高さで伸縮する |
| 接続 | 1段の高低差をmid-w1の高さにそろえる。床厚は原点より下へ延ばしてよく、手すりの高さは接続高に含めない |
| 通常・接写 | 同じ原点とbbox。手すり・取付部等の細部を追加してよい |

パーツの最大奥行きが本体の後退量になる。モデル内で横にずらす場合も、元の占有輪郭内へ収める。
固定距離のオフセットなので、可変サイズの全建物で辺中央になるわけではない。
元の辺2全体を後退させ、壁・角・屋根・各階の床に同じ描画輪郭を使う。
本体側の壁は階段の水平幅で開くため、開口を保護する手すり・扉・踊り場はパーツに含める。
本体の床・屋根は階段の帯へ張られない。屋上へ通す場合はtopに終端の踊り場を用意する。
収まらない敷地では縮めずに階段とセットバックを省略する。配置の詳細はF文書§11.4。

## 5. Blenderからのエクスポート設定（FBX）

BlenderからUnity向けにパーツ（壁、角、タイル、既成パーツ等）をエクスポートする際、Blender（Z-Up右手座標系）とUnity（Y-Up左手座標系）の座標系の違いにより、Unityにインポートした際にX軸を中心に-90度回転してしまう問題が発生する。

これを防ぎ、Unity上で `Rotation: (0, 0, 0)`、かつ正しいスケールでインポートするために、以下のいずれかの設定を行う。

### 5.1 設定方法A：エクスポート設定でトランスフォームを適用する（推奨）

BlenderのFBXエクスポートダイアログの「トランスフォーム（Transform）」セクションで、以下を設定する。

* **適用（Apply）**: **「トランスフォームを適用（Apply Transform）」にチェックを入れる**
  * *注意：この項目はチェックボックスの右側に警告マーク（!）が表示される場合があるが、問題なく動作する。*
* **前方（Forward）**: **-Zが前方（-Z Forward）**
* **上（Up）**: **Yが上（Y Up）**

この設定を行うと、Blenderがエクスポート時にメッシュの頂点データをY-Up用に再計算して保存するため、Unity側でモデルを配置した際に回転角度が `(0, 0, 0)` になる。

### 5.2 設定方法B：Unityのインポート設定で軸をベイクする

Blenderから通常設定で出力したFBXファイルをUnityにインポートした後、Unityのインスペクター（Inspector）から直接修正する方法。

1. UnityのProjectウィンドウでインポートしたFBXファイル（例: `tile.fbx`）を選択する。
2. Inspectorの **Modelタブ** を開く。
3. **「Bake Axis Conversion（軸変換をベイク）」** のチェックボックスをオン（有効）にする。
4. 下部の **Apply** ボタンを押す。

これにより、Unity側がインポート処理の段階で `-90度` の回転をメッシュの頂点データ自体に焼き込み、親オブジェクトのRotationを `(0, 0, 0)` にリセットする。

## 9. 建物全般の接写LOD

学校・大学・病院・消防署・警察署・集合住宅・オフィス・工業施設などは、既存の通常用パーツに
対応する `_close` を持つ。商業系はストライプの庇・立体看板、集合住宅は窓前の金属柵・
室外機、オフィスのガラス外壁は金属サッシ、学校は校名看板・柱付き外装、工業施設は屋上ファン・
ダクト・点検通路を接写用に組み込む。窓の額縁・見込み、設備の通風スロットも表現する。
小規模な店舗看板は自作グリフの形状で表現する。モールの広告は後述の共有画像を使う。

通常用の形状・面数を保ち、接写用も原点と配置に使う寸法を一致させる。
壁（base/mid/top-w）と玄関は前方（Blender -Y）へ最大1.5mの追加張り出しを許可する。
幅X・高さZ・背面+Yは維持し、壁の敷き詰め幅や階高を変えない。角・既成・タイル・塔屋は
全bboxを一致させ、屋上設備は遮蔽物の無い屋根上で既存外形内へ収める。角は元のボーン構成とウェイトを保ち、
追加頂点にも元の面からウェイトを補間する。UVと既存マテリアルも引き継ぐ。

材質参照専用パーツや細部を追加しない部品には同形の接写ファイルを作らず、通常用へ
フォールバックする。市政府・戸建て住宅の個別に著作された接写モデルも同じLOD規約を使う。
全建物のFarは独立した低密度のprebuiltモデルを使用でき、未提供の場合はUnityが簡易形状を生成する。接写の細部は遠景の面数を増やさない。通常モデルがモジュラー方式の場合も、遠景用の `base/mid/top-prebuilt_far` を提供できる。

原本は `blender/buildings.blend`。再生成用ジョブは非公開の制作ツール
`genesis-gallery/pipeline/jobs/build_building_lods.py`、制作・検証記録は同ディレクトリの
`building_lods.md` にある。外部素材は追加せず、既存の共有マテリアルを使用する。

### 9.4 中間階の床を持つ建物

`interior-floor` はモジュラー建物の各階床を有効にする任意の参照パーツ。
上面をBlender Z=0、下面を負のZへ置き、その厚みを実寸で使う。厚みは0より大きく階高未満にする。
水平寸法は参照せず、Unityがフットプリントに沿って上面・下面・小口を生成する。
材質スロット0を上面、1を下面と小口へ使う。スロット1が無ければ0を共用する。
原点・厚み・材質はNormal/Closeで共通なので同じ参照ファイルを使えばよい。
`floor`（敷地の地面）と異なりdraw_floorや地形追従の影響を受けない。
生成範囲・平屋根との関係は [[F1_モジュラー建物のメッシュ生成]] の各階の床を参照。
