# Unity入力制御

Unity の3Dビューで受けたマウス・キーボードの入力を、どの対象へどう届けるかの仕組み。3D上の操作が何を意味するかは、Tauri の UI が指示する編集ステートで決まる。見た目の切り替え(表示モード)は別系統で、[Unity表示モード](Unity表示モード.md)に書く。

## 入力の配送

入力は `InputHandler` が一元的に受ける。毎フレーム、カメラからマウス位置へレイを飛ばし、当たった3Dオブジェクトをオブジェクトタイプ(建物・土地区画・パス・ノード・地形・地区)に分類して、そのオブジェクトの入力ハンドラ(`IInputHandler`)へ、オブジェクトタイプごとの入力モードを添えて渡す。ハンドラは入力モードに応じて、詳細パネルを開く通知を UI へ送るか、編集の状態(形・選択・プレビュー)を持つ編集マネージャへ委譲する。

入力モードはオブジェクトタイプごとに独立して持ち、同じオブジェクトでもモードが違えばクリックの意味が変わる。`MODE_NONE` のオブジェクトタイプはレイが素通りするので、編集中は作業に使うオブジェクトタイプにだけ編集用のモードを与え、残りを `MODE_NONE` にしてクリックを奪わせない。全オブジェクトタイプのモードをまとめて切り替える組をモードプリセットと呼ぶ。

選択は、レイが最初に当たった物よりも、地面の上の何を指しているかで決める。地形に埋もれた土地区画は地形に当たった点から平面の内外判定で選び、地下表示の間は地形越しに地中のパスを選ぶ。海面・都市外の背景地形・埋立地の岸壁も地形として扱う。走行中の車両や公共交通の帯のようにコライダーを持たない対象は、入力モードが通常のときだけ、レイキャストより先に画面上の判定で選ぶ。

## クリックとドラッグ

マウスを押した時点ではクリックを発火せず、離すまでの移動が画面上の閾値に満たなければクリック、超えればドラッグとして扱う。右ボタンも同じで、その場で離せば右クリック(形の確定や点の削除)、動かせばカメラの回転になる。カメラ操作(`CameraController`)も同じ保留の方式でドラッグを確定し、カメラのドラッグが確定すると保留中のクリックは捨てる。

編集用のハンドル(制御点・頂点・マーカー)の多くは画面に描くオーバーレイでコライダーを持たないので、編集マネージャが画面座標の当たり判定で掴み、ハンドルの上で押したときはカメラを動かさない。形を描く編集は、左クリックで点を置いていく段階と、右クリックで形を確定した後に点や辺を動かして整える段階からなる。

## 入力ゲート

ポインタが UI の上にあるとき、カメラのドラッグ中、フライ・撮影・ドライブ中、Ctrl のラジアルメニューの表示中、コアとの接続が切れているとき、チュートリアルが操作を制限しているときは、入力モードを変えずに3Dへの入力を止め、保留中のクリックとホバーを捨てる。ゲートが外れれば元の入力状態に戻り、止める前の操作が遅れて確定することはない。フライ・撮影・ドライブ・市民の追従はカメラ側のモードとして扱い、入力モードや IPC のステートを増やさない。

## 編集ステートと UI の同期

UI は `world:change_state` で編集ステート(`STATE_*`)を指示し、`IpcStateCoordinator` がステートに対応するモードプリセットの適用と、編集マネージャの開始・終了をまとめて行う。表示もステートに合わせて切り替わり、通常モード(`STATE_NORMAL`)へ戻ると、すべての編集を終えて全オブジェクトタイプの入力モードを通常に戻し、表示はユーザーが選んでいた状態に戻す([Unity表示モード](Unity表示モード.md))。編集用のウィンドウは閉じても隠れるだけで React のアンマウント処理が走らないので、閉じたときの `STATE_NORMAL` は Rust 側が送る。ステートの一覧とイベントの約束は [IPC連携の整理](IPC連携の整理.md) に書く。

UI との同期は次の原則に従う。

- 3Dでしかできない操作の状態(描いている形、選んでいる点、作成方法・配置方法)の正は Unity が持ち、変わるたびに全体を UI へ送る。パネルの数値入力やボタンは Unity へのコマンドとして送り、Unity が3Dの操作と同じ処理で適用した結果を返す。受け取った値をそのまま送り返さない。
- 確定(コアへの登録)は確定の操作を持つ側が送る。パネルに確定ボタンがある操作は UI が、3D上の操作だけで完結する操作は Unity が送る。
- Unity のローカルな判定は、確定的な制約だけを確定の条件に加え、推定にすぎないもの(線形の警告など)は表示にだけ使う。確定の可否の正はコアの検証結果である。

## 吸着と編集中の設定

地形へのクリック・ホバーには共通の吸着が掛かり、カーソル位置をグリッド・地区の頂点・既存のノードやパスへ引き寄せて書き換える。道路・線路の敷設や建物の配置のように自前の吸着を持つ編集と、吸着すると意図しない位置へ引き寄せられる編集では、共通の吸着を掛けない。吸着先の高さは API が返す相対高さ([パス形状](../geometries/A_パス形状.md))から引き継ぎ、描画用の点列の高さから逆算しない。

曲線と直線、吸着の種類、区画の作成方法、建物の配置方法などの編集中の設定は、3Dビューの中の Ctrl のラジアルメニューで切り替え、現在の設定をカーソルの脇に示す。パスの敷設方法(単一・碁盤状)は、敷くバリアントと同じく建設パネルで選んで編集の初期条件として渡し、Unity は方法ごとのクリック手順で点を置く。メニューと表示の開閉は共通の基底(`EditControlMenuBase`)が持ち、各編集は項目と表示の中身だけを与える。
