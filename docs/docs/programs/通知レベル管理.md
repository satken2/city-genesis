# 通知レベル管理

プレイヤー(市長)に知らせる事象は、緊急度で3つのレベルに分け、レベルごとに別の UI で表す。

| レベル | 定義 | 表現 |
| --- | --- | --- |
| L1 | 知っておくべき継続中の問題や重大な出来事で、常に見えているべきもの | コックピットのアラートアイコンと件数、通知一覧ウィンドウ |
| L2 | 放置すると悪化する傾向 | エポック結果ウィンドウの統計 |
| L3 | どこで起きているかが主な情報の事象 | 3D空間のアラートフラグ([アラートフラグ管理](アラートフラグ管理.md)) |

L3 はその場所をカメラで見ているときにしか気づけないので、都市全体に関わる危機は L1 で、カメラの向きによらず伝える。同じ事象でも深刻さでレベルが変わり、例えば交通事故の発生は L3 だが、死者が出たら L1 になる。

## L1 の重要度

L1 の通知は重要度(`severity`)で2段階に分かれる。`warning` は、築いた都市の機能が損なわれつつあり、かつプレイヤーが数エポックのうちに打てる手がある事象で、コックピットのアイコンを点滅させ、赤い件数で示す。`caution` はそのどちらかを欠く事象で、点滅させずに黄色の件数だけで示す。急ぎでない問題で点滅が常態化すると、本当の危機の合図が薄まるためである。未知の `severity` は、安全側の `warning` として扱う。

## L1 通知の受け渡し

コアはエポックの最後に通知の一覧を作り直し、Tauri は `GET /api/v1/notifications` から取得する。`id` は通知を見分ける安定したキーで、続いている問題の通知は解消するまで同じ `id` で作り直され、出来事の通知は起きたエポックだけ載る。通知一覧から詳細ウィンドウを開く対象は `entity` で、件数をまとめた通知では `null` である。一覧は保存されるので、ロードの直後にも復元できる。コックピットは定期的に取得し、エポックの完了でも取り直し、セッションが切れたら消す。L1 は通知ポップアップを出さず、アイコンと件数で続いている状態を知らせる。操作の結果やクエストの達成などの一時的な知らせは、共通の通知ポップアップ(`utils/notification.ts`)で出す。

コアは文言を組み立てず、通知の種類(`type`)と差し込む値だけを返し、Tauri が i18n キー `notifications.types.<type>` の文言にする(表示言語の知識をコアに持たせないため)。未知の種類は汎用の文言に落とすので、コアが先に新しい種類を返しても UI は壊れない。取得・文言化・詳細ウィンドウとの対応は `utils/cityNotifications.ts` にまとめる。

## 通知の種類

通知の種類には、天然資源の枯渇、公共施設・インフラ施設の運営の支障、衛生の悪化、建物・道路の倒壊や交通事故の死者などがある。場所を持つ warning は、Unity でも対象の位置に示す([アラートフラグ管理](アラートフラグ管理.md#l1警告の位置表示))。件数をまとめた通知も、コックピットの件数では1件と数える。
