# 道路・線路の経路提案

2D編集パネルは平面形状、縦断面、経路提案の順に並ぶ。3セクションとも見出し行の形は共通で、見出しの右に操作説明を置き、平面形状はさらに右端へ「全体表示」を置く。操作説明は幅が足りなければ折り返して全文を表示する。見出し行には地色を敷かず、下の区切り線だけで内容と分ける。経路提案のみ独立したカード(枠線・角丸・地色)として表示する。カードの外周エリアは縦断面と同じ階層に置き、全幅の区切り線で縦断面の描画領域から分離する。外周の余白は上下だけ取り、左右は取らずにカードをパネル幅いっぱいへ広げる。地図・縦断面の描画領域とカード以外は地色を敷かず、ウィンドウの土台の色をそのまま見せる。提案の説明は見出しの右、エラーは操作行に置き、どちらも折り返して全文を表示する。

道路または線路の点配置を右クリックで終えると、「2Dで編集」パネル下部の「経路提案」カードを使用できる。曲線を許可する道路・歩道・線路・モノレールが対象である。高さ固定では指定点すべてのXYZを維持し、高さ調整では中間指定点のYだけを調整する。始点・終点のXYZ、指定点のXZと通過順序はどちらでも固定する。高さ編集不可の規格では高さ固定のみ使用できる。

提案はベジエの制御点を調整し、必要なら指定点間に補助ウェイポイントを追加する。規格の曲線半径・勾配を満たす経路を有限範囲で探し、複線は全線を検証する。地形追従と造成後の路面標高も評価するため、地形追従の平滑化と固定高さが両立しない場合は失敗する。地形追従や道路種類を自動で変更することはない。

成功すると3Dと2Dの編集形状へ反映し、通常どおり手動調整・建設確定ができる。「提案前に戻す」は提案直後の形状を復元する。提案後に別の編集を加えると復元は無効になる。補助点を手動移動すると、次回の提案でも通る指定点になる。保存済みパスを開き直した場合は全点を指定点として扱う。

探索中も編集できる。形状・規格・複線設定を変更した場合や取り消した場合、古い応答は適用しない。見つからなければ元の形状を保持し、探索範囲内で条件を満たせなかった旨を表示する。探索は最大40点・20km・8線、約12秒を目安とし、解が存在しないことや全域最短を保証する機能ではない。建設可否は適用後も通常の全線検証と登録時検証で確認する。

## 通信と責務

探索で候補が得られなかった場合は「経路が見つかりませんでした。」だけを表示する。区間ごとの曲率・勾配の診断は画面へ列挙しない。通信などの例外時も簡潔な失敗メッセージを表示し、例外の詳細はコンソールへ記録する。

UnityのRoadPlanManager.RouteProposal.csが編集点の作成元と復元用スナップショットを保持する。edit_path:update_shapeのroute_proposalに絶対標高の点列、制御点、盛土量、作成元、revision、復元可否と現在の規格・複線・地形追従設定を載せる。通常のselected_pointsと制御点フィールドは従来どおり地面相対高さであり、探索用の絶対座標と混在させない。

Tauriの2D編集パネルにあるuseRouteProposalがPOST /api/v1/paths/propose-routeへ編集形状と敷設設定を送る。成功時は既存のedit_path:shape_commandへop=apply_route、revision、route_jsonを送り、Unityが世代・点数・有限値・固定点を検査して一括反映する。復元はop=undo_routeとrevisionを送る。Rust側は既存の汎用イベント転送を使用する。

探索結果の制御点は自動補完で上書きされないよう手動扱いにする。制御点のYは入口・出口それぞれの値を保持し、造成プレビュー、通常の保存、複線展開でもアンカーYへ置き換えない。

Unityの実行検証はTests/RoadPreview/run-unity.ps1。世代不一致、固定点の不正変更、反映、復元、補助点の手動移動とフェーズ制約を確認する。
