# アラートフラグ管理

建物・道路の `alert` は、直近のエポックで観測された問題を表す整数のビットフィールドである。建設・解体などのライフサイクルは `status`、調達不足・事故・接続不良は `alert` で表す。

## 更新と保存

アラートはエポックごとに更新される。状態系は問題が続く間、イベント系は発生したエポックだけ有効になる。保存したアラートはロード直後にも表示できる。

`alert` だけの変更はオブジェクトの `version` を更新しない。メッシュの差分取得だけではアラートの変化を観測できないため、Unityは専用APIから取得してオーバーレイだけを更新する。

## アラートビット定義

建物と道路のビットは別の名前空間である。値は同期される共有定数 `Constants.cs`・`constants.ts` を参照する。

| 対象 | 定数 | 意味 |
| --- | --- | --- |
| 建物・道路 | `ALERT_*_CONSTRUCTION_SHORTAGE` | 建設・解体のサービス調達不足 |
| 建物 | `ALERT_AGENT_ON_FIRE` / `ALERT_AGENT_ACCIDENTAL_FIRE` | 火災 / 失火 |
| 建物 | `ALERT_AGENT_CRIME` / `ALERT_AGENT_CRIME_SIGN` | 犯罪 / 犯罪の兆候 |
| 建物 | `ALERT_AGENT_INFRA_DISCONNECTED` | 稼働中の施設が必要なインフラ網へ未接続 |
| 建物 | `ALERT_AGENT_LABOR_SHORTAGE` / `ALERT_AGENT_MATERIAL_SHORTAGE` | 労働力 / 原材料の不足が生産を制約 |
| 建物 | `ALERT_AGENT_HIGH_SKILL_SHORTAGE` | 必要な高スキル人材が不足 |
| 建物 | `ALERT_AGENT_BUDGET_CAPPED` | 公共予算不足が稼働計画を制約 |
| 道路 | `ALERT_PATH_ACCIDENT` | 交通事故 |
| 道路 | `ALERT_PATH_NO_STATION_HOUSE` | ホームが駅舎へ所属していない |

## 表示対象

`ALERT_AGENT_ICON_BITS`・`ALERT_AGENT_VFX_BITS`・`ALERT_PATH_ICON_BITS` が空間表示の対象を定める。APIはこれらの対象ビットだけを配信し、表示パネルとUnityは同じ共有定義を使う。生産不足などの詳細用ビットはエンティティの `alert` と[通知](通知レベル管理.md)から参照する。

火災・失火はアイコンの代わりに[炎と煙](../geometries/S_火災エフェクトの描画.md)で表す。表示フィルターはアイコンとエフェクトの両方に適用する。

### L1警告の位置表示

[通知トレイ](通知レベル管理.md)のうち、次のwarningを同じアラート用Canvasへ表示する。cautionは対象外。警告の判断はコアが担当し、UnityはAPIが返す位置と表示ビットを使う。

| 警告 | 位置 | 表示フィルター |
| --- | --- | --- |
| 資源の枯渇予測 | 資源の中心 | `ALERT_DISPLAY_RESOURCE_WARNING` |
| 公共施設の運営不能 | 対象建物の上 | `ALERT_DISPLAY_FACILITY_WARNING` |
| 深刻な衛生悪化 | 警告域の世帯が居住する土地区画の中心。区画につき1個 | `ALERT_DISPLAY_SANITATION_WARNING` |
| インフラ施設の停止・倒壊 | 対象建物の上 | `ALERT_DISPLAY_INFRA_WARNING` |

衛生の位置は被害を受けている居住地を示し、原因となる処理施設の位置を示すものではない。公共交通路線はこの空間警告に含まれない。

資源・区画の描画オブジェクトには依存せず、資源の分布や名前、区画を非表示にしても警告は残る。バブル自体の表示可否はアラート側の設定で制御する。資源の枯渇予測は解消まで表示する。同一建物の複数警告は既存アラート・廃墟アイコンと同じ列に並ぶ。

## API

### `GET /api/v1/alerts`

`?bbox=x1,z1,x2,z2` を指定した場合は `center_point` がその範囲内にある対象のみ返す。省略時は都市全体。

#### レスポンス

```json
{
  "agents": [
    {
      "id": 123,
      "name": "第1小学校",
      "center_point": [120.5, 340.2],
      "status": 4,
      "alert": 3
    }
  ],
  "paths": [
    {
      "id": 456,
      "name": "主要道1号",
      "center_point": [200.0, 100.0],
      "status": 4,
      "alert": 1
    }
  ],
  "warnings": [
    {
      "entity_type": "resource",
      "id": 12,
      "center_point": [300.0, 150.0],
      "warning": 131072
    }
  ]
}
```

- `alert` は int16 のビット和。各ビットの意味は `consts.py` の `ALERT_AGENT_*` / `ALERT_PATH_*` 定数に対応
- 需要量・調達量などの詳細情報は含まない。それらはUI(Tauri)の建物詳細ウィンドウ等で別途取得することを前提とする
- **Unity表示対象ビット(`ALERT_AGENT_ICON_BITS` / `ALERT_PATH_ICON_BITS`)以外はマスクされる**。フィルタ条件は「表示対象ビットが1つ以上立っている」または `status == STATUS_COLLAPSED` で、返却される `alert` 値もマスク後の値になる
- `warnings` はL1由来の位置付き警告。`entity_type` は `agent` / `resource` / `parcel`、`id` はその対象ID、`center_point` は `[x,z]`。`warning` は `ALERT_WARNING_DISPLAY_BITS` に含まれる表示専用ビットの和で、エンティティの `alert` へは書き込まない。同一対象は1件に集約する。対象消失・座標未設定・bbox外は配信しない。L1通知を持たない都市では空配列。

## Unity側の表示

### 表示フィルター

UIは `view:change_view` の `layer=alert`、`sub_mode` に表示するビットの和を10進文字列で送る。建物は下位、道路は `ALERT_PATH_MASK_SHIFT` だけ左へずらして合成する。廃墟の表示はエンティティのalertに含まれない `ALERT_DISPLAY_RUIN` で指定し、建物・道路の双方に効く。マスク0は全種別を非表示にする。

L1由来の4種類は `ALERT_DISPLAY_*_WARNING` の専用領域を使う。表示パネルとUnityの未指定時のマスクは、この4種類もすべてONにする。既存の建物・道路の表示ビットと重ならない値は共有定数から同期する。

### 更新と寿命

`AlertManager` はエポック完了・編集確定・強制ロード・表示フィルター変更で一覧を更新する。カメラ移動と建物生成では最後の応答を再適用し、位置と火災の規模をロード済み形状へ合わせる。セッション消去では取得中の旧結果を捨てる。

アイコンは対象の中心に複数種別を並べ、画面外・背面を隠す。建物・道路の子にせず、LODの退避に巻き込まれない独立したCanvasへ置く。クリックを受けず、通常の入力に干渉しない。`AlertIconFactory` は対象種別とビットの組でSpriteを選び、未設定のSpriteは表示しない。

火災は `FireEffectManager` が同じ応答とフィルターを利用する。独立したHTTP取得を持たず、位置の再適用だけで既存の炎・煙を作り直さない。生成・距離制御は[火災エフェクト](../geometries/S_火災エフェクトの描画.md)に定義する。
