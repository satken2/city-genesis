# チュートリアル基盤

チュートリアルの進行はTauriが管理し、Unityには現在の案内と操作制限だけを送る。シナリオは `tauri/src/tutorial/definitions/*.json`、共通処理は `tauri/src/tutorial/` と `unity/Assets/Scripts/Tutorial/` に置く。シミュレーションの経済ルールは変更しない。

シナリオ作者向けの32ステップ設計と部品表は、リポジトリの `docs/tutorials/` にある。これはMkDocsのソース階層外に置いた作業資料であり、本ページが公開サイト上の実装契約である。

## 進行と条件

専用Tutorialウィンドウの `useTutorialGuide` が定義を読み、`legacyStep` が現在の番号と一致したステップの案内と完了判定を担当する。未登録のステップは既存の `tutorialSteps.ts` が担当する。代表例は基本編の道路配置と、インフラ編の初期配置・民家詳細・指定区画の発電所・工期スキップ。

ステップは複数の操作段階に分かれる。表示中のウィンドウ、選択中の道路種別、配置頂点数から段階を再計算し、閉じる・取消では前の段階に戻る。最後の段階は説明を読んだ後の完了ボタンで確定する。保存した道路のIDがある場合はAPIで対象を確認する。

道路配置は「始点を左クリック→終点を左クリック→右クリックで形状確定→建設パネルで確定→チュートリアルの完了」の順で案内する。終点配置と形状確定は別の段階で、2点を置くだけではパネルの確定へ進まない。道路APIの `curved` は0/1で返るため、読み取りアダプタでbooleanへ揃えてから条件と比較する。他の項目の型や座標は厳密に比較する。

判定エンジンは都市の読み取りとローカルの対象ID束縛だけを行う。都市を変更する初期配置・完成代行は独立アクションであり、実行順は `setup` → 段階条件 → `beforeCheck` → `complete` → `afterCheck`。合格前に完成が必要な接続判定と、説明の読了後に行う工期スキップを区別できる。

名前付き対象と作成中の記録は `tutorial_runtime_v1:<scenario>:<saveId>` へ保存する。成功済みの作成を再実行しない。応答喪失などでPOSTの結果が不明な作成は記録を残して停止し、無条件の再POSTで重複を作らない。完成代行は対象の現状を確認してから実行する。書き込み直前には現在のセーブIDを確認する。都市データとlocalStorageを一括保存する仕組みではないため、削除された対象や結果不明の初期化を検出した場合は新しいチュートリアル都市で再開始する。

## UIへの適用

App直下の `TutorialLayer` が各WebViewで同じスナップショットを購読する。`highlight` は強調のみ、`related` は登録済み操作と指定ウィンドウ全体を許可、`strict` は登録済みの個別操作だけを許可する。対象は `data-guide`、HUDでは既存のボタンIDで解決し、翻訳文やCSS階層に依存しない。

未許可の操作はDOMキャプチャと `inert` でクリック・キーボード・フォーム経路を止める。既存のdisabledを変更しない。終了時はこの層が設定した属性だけを解除する。タイトルバー、明示した離脱操作、チュートリアル・通知・Tipsは制限対象外。設定・保存・復旧・終了の経路を保つため、システムトレイ、設定、クレジット、セーブ/ロード、セーブ一覧、新規ゲーム、確認ダイアログも制限しない。除外は `dom.ts` が共通で適用し、シナリオの許可リストに左右されない。UI案内の状態はメモリ上だけに置き、アプリ再起動後に以前の制限を復元しない。

チュートリアルの終了ボタンはセッション終了要求の処理中だけ無効化する。HTTPエラーや通信失敗では通知して再試行可能にし、セッション終了・別の都市への切替では終了中フラグと確認状態を戻す。常駐WebViewを非表示のまま再利用しても、前の終了状態を持ち越さない。

WebViewは閉じても破棄されないことがある。表示状態の観測では `isVisible()` を確認し、Rustの `close_window_by_label` は `tutorial:window_visibility` をTutorialへ通知する。対象IDを含むので、別の建物の詳細や閉じたパネルで条件を満たさない。

## 通信

| 経路・イベント | 内容 |
| --- | --- |
| Tauri内部 `tutorial:guide_state` | 現在のステップ・段階・UI許可・Unity案内の全スナップショット |
| Tauri内部 `tutorial:guide_query` | 新しいWebViewの再同期、表示状態・道路編集中の状態の再観測 |
| Tauri内部 `tutorial:guide_observe` | 表示ウィンドウ、対象ID、道路種別・形状、保存成功した道路ID |
| Rust→Tutorial `tutorial:window_visibility` | キャッシュされたポップアップの明示的な閉鎖通知 |
| Tauri→Unity `ui:action` / `tutorial:apply` | `params` に `active/runId/revision/saveId/scenario/stepId/phaseId/ui/world` |
| Unity→Tauri `tutorial:applied` | 適用した `runId/revision`。RustからTutorialへ中継する |

同一実行内の古いrevisionと終了済みrunIdを捨てる。新しい実行中に届く以前の解除通知も無視する。段階変更時と `graphic-reconnected` でだけ送信し、周期送信は行わない。Unityの `session:reset` と `game:end`、Tauriの終了・ステップ変更・再試行では制限を解除する。

## Unityの操作制限

`TutorialRuntime` は最初の有効な指示で生成される。マーカーは `OverlayMeshRenderer` による描画物で、都市ノード・コライダー・PathManagerの実体に登録しない。マーカー座標は地面相対の `[x,y,z]`。

`world.mode` は `observe`、`blocked`、`path`。`blocked` では共通のワールド入力を止める。`path` では道路エディタの入口で始点・終点の左クリックと半径を検査する。始点は水色、終点は黄色で実際の受理半径を表示し、クリック位置を定義の正確な座標へ吸着させる。2点の配置後だけ右クリックを許可し、通常の道路編集と同じく最後の点を終点として形状確定する。この右クリックの位置は形状に影響しないため、円内に限定しない。

v1の道路は始終点2つの地上直線。追加頂点、曲線、高さ・盛土、ドラッグ、ラジアル設定、2D編集からの変更を制限する。通常の建設検証に加えてUnityの `can_confirm` とTauriのHTTP送信直前でも指定形状を検証する。対象バリアント・頂点・制御点・盛土・地形追従の上書きが条件から外れると確定しない。チュートリアルが無効なときはこれらの判定を素通りする。

カメラ操作をチュートリアルのワールド編集ゲートに含めない。Unityはシナリオの進捗や完了条件を判断せず、通常のステート遷移は既存の仕組みを使用する。

## 検証と拡張

JSON Schemaに加え、安定IDの重複、未登録の操作名、存在しない定数・束縛、地上直線制約を検査する。`npm run test:tutorial` は条件・副作用・戻り方・DOM操作制限・解除と、全定義の翻訳キー・ウィンドウ名・設計32ステップを確認する。`unity/Tests/Tutorial/run-unity.ps1` は独立Unityプロジェクトで本編アセンブリを実行する。`Tests/Tutorial/README.md` に試験の範囲を記載する。

新しいシナリオを追加するときは、まず作者向け設計書と能力一覧を確認する。未登録のUI対象は通常コンポーネントに安定した属性を付けるだけにし、シナリオ固有の判断を持ち込まない。Unityで新しい種類の制約が必要な場合は、専用モジュールの型・Schema・受信側・編集の接点・試験をまとめて拡張する。
