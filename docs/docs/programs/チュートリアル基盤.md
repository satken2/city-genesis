# チュートリアル基盤

チュートリアルは、教材ごとに用意した都市の上で、Tauri が案内と操作の制限を進める仕組みである。

| モジュール | 役割 |
| --- | --- |
| Tauri | 教材の定義を読み、ステップの進行・案内・達成の判定・UI の操作制限を担う。共通処理は `tauri/src/tutorial/`、定義は `tauri/src/tutorial/definitions/*.json` |
| Unity | Tauri から届いた現在の指示に従い、マーカー・カメラの案内とワールド操作の制限だけを適用する(`unity/Assets/Scripts/Tutorial/`)。進行や合否は判断しない |
| コア | 教材の都市を開き、教材固有の達成判定(読み取りだけ)と、定義が明示的に呼ぶ代行アクションを提供する |

チュートリアルは、セッションの作成でチュートリアルモード(`PLAY_MODE_TUTORIAL`)と教材 ID(`tutorial_id`)を指定して始める。コアは同梱の教材の都市をシナリオと同じ手順で開く(シナリオの一覧には出ない)。全ステップを終えると Tauri が教材の達成クエストを完了させ(これがクリアの記録になる)、終了の操作でセッションを通常モードへ切り替える。都市はそのまま通常のプレイとして続く。モードごとの違いは[プレイモード](プレイモード.md)にまとめる。

## 定義と進行

定義はステップの並びで、各ステップは段階からなる。段階は、案内文(`textKey`)、UI の操作制限(`ui`)、Unity への指示(`world`)、次の段階へ進む条件(`until`)を持ち、ステップは達成条件(`complete`)を持てる。定義は決まった種類の条件と操作の組み合わせだけで書き、任意のコードや URL は受け取らない。読み込むときに JSON Schema と意味の検査を通し、Schema の検証は事前に生成したコードで行う(UI の CSP が `eval` を許さないため)。Schema を変えたら `npm run gen:tutorial-validator` で作り直す。

段階は、表示中のウィンドウ、選択中のパスの種類、HUD のモードなどの現在の状態から、その都度計算し直す。パネルを閉じたり操作を取り消したりすれば前の段階へ戻るので、案内が画面とずれない。

判定は都市を読むだけで書き換えない。コアが初期配置した対象は、チュートリアルの API の `targets` の名前(`support.*`・`lesson.*`)で参照し、教材固有の判定は `checks.<キー>` を読む。都市を書き換える処理(対象の作成、工期の省略、コアの代行アクション)は判定から分けたアクションにし、実行する時点を定義で明示する。作成の結果は Tauri 側に記録し、同じ作成を二度送らない。

## 操作の制限と案内

UI では、各 WebView の `TutorialLayer` が同じ案内の状態を購読し、要素に付けた操作名(`data-guide`。同じ名前の要素が並ぶものは値 `data-guide-value` も持つ)で許可と強調を当てる。方針は、強調だけの `highlight`、許可した操作とウィンドウ全体を通す `related`、許可した個別の操作だけを通す `strict` の3つである。保存・復旧・終了の経路は常に残す。各コンポーネントは安定した操作名を付けるだけにし、教材固有の判断や独自の強調を持たない。

Unity には、段階が変わったときと再接続したときに、現在の指示(`tutorial:apply`)を送る。指示は実行 ID と版を持ち、Unity は古い指示を捨てる。`world.mode` は、制限しない `observe`、ワールドの操作を止める `blocked`、指定したパスだけを敷かせる `path` のどれかである。座標は地面からの相対の `[x, y, z]` で、カメラの `yaw` は北を0とする時計回り、`pitch` は見下ろし角(度)。マーカーは描画物で、都市のデータには登録しない。
