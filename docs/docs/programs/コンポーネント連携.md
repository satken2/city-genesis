# コンポーネント連携

City Genesis は、都市データを持つコア、操作 UI を描く Tauri、3D の描画と空間の入力を受け持つ Unity の3つのプロセスで動く。経済の計算はコアだけが行い、UI と描画はコアの応答を表示する。

| 経路 | 通信 | 役割 |
| --- | --- | --- |
| Tauri・Unity → コア | HTTP | 都市データの取得、編集の確定、エポックの実行 |
| Tauri ⇔ Unity | [IPC](IPC連携の整理.md) | 編集状態・選択・表示・ロードの進み具合の同期 |

コアは URL で接続される相手で、UI・グラフィックのプロセスやクライアントの PC を前提にしない。コアが管理するファイル(セーブ・シナリオ)は UI もコアの API を通して扱い、クライアントの PC についての値(メモリや GPU など)は Tauri が自分で測る。

## 起動順序

Tauri がストアの起動対象で、全プロセスの親になる。インストール先の `Core/` にコア、`Graphics/` に Unity の実行ファイルがあれば子として起動し、無ければ外部で起動済みとみなして接続だけする(開発時に手で起動したコアや Unity Editor)。起動は、ストア連携の初期化、コアの起動と応答待ち、Unity の起動、Tauri と Unity の版の照合と IPC の確立の順に進む([バージョニングと互換性](バージョニングと互換性.md))。

| 対象 | 接続先の受け渡し |
| --- | --- |
| コア | 環境変数 `GENESIS_API_PORT`(待ち受けるポート)、起動引数 `--attached`(標準入力が閉じたら終了する)。ストアが管理するフォルダは `GENESIS_DLC_DIR`・`GENESIS_WORKSHOP_DIR` |
| Unity | 起動引数 `--api-base-url` |
| コアを起動しない Tauri | 環境変数 `GENESIS_UI_API_BASE_URL`。無ければ `http://127.0.0.1:5000` |

## ローカルAPIへの接続

コアは `127.0.0.1` だけで待ち受け、認証を求めない。同じ PC のサードパーティ製プログラムも同じ API で都市を閲覧・編集できる。API の資料(Swagger `/docs` と OpenAPI `/openapi.json`)は開発版・製品版・モック版のどれでも参照できる。

HTTP は各モジュールの共通の窓口から送る(窓口が版のヘッダーを付ける)。コアの版情報は Rust が起動時に取得して共有し、各 WebView が個別に取得しない。

| クライアント | 窓口 |
| --- | --- |
| Tauri の WebView | `utils/api.ts` の `fetchApi`(または設定済みの `fetch`)。API の画像も `<img src>` で直接読まず、`useApiImageUrl` で Blob URL にする |
| Tauri の Rust | 共通の版照合済み HTTP クライアント |
| Unity | `ApiClient` |

呼び出す URL は、末尾の `/` まで OpenAPI のパスに揃える。`/api/v1/city/`・`/api/v1/score/` の末尾を省くと、HTTP 307 による転送で余分な通信が発生する。

応答の辞書型の数値(車種別の交通量 `path_traffic` など)は、無限大を保存型の有限の上限に置き換え、0 の項目は省いて返す。上限に張り付いた値(`path_traffic` なら 65,504)は正確な値ではなく、それ以上という意味である。

### CORSとWebViewのCSP

CORS は Tauri の WebView のオリジンと開発サーバーだけを許可する(Unity と Rust の HTTP は CORS の対象外)。配布ビルドの WebView の CSP は、スクリプトを自身のバンドルに、通信を自身・IPC・ローカルホストに限り、実行時にコードを作る `eval`・`new Function` を許さない。開発サーバーでは CSP の掛かり方が違うので、CSP に関わる変更は配布ビルドで確かめる。

## セッション状態の管理

`GET /api/v1/sessions` の `current_save_id` が null ならゲームは始まっていない。`current_save_id` は上書き保存の先でもあり、別名で保存すると変わるので、別の都市への切り替え(ロード・新規作成)は都市を開くたびに変わる `session_id` で判定する。UI の各画面は Rust の共通の監視が配るセッション状態を参照し、独自の監視を持たない。

ゲームが始まっていない間に使える API は、システム・セッション・セーブ・シナリオ・パラメーター・テンプレート・マスター・プロフィールだけで、都市のデータを返す API は 503 `NO_SAVE_LOADED` を返す。ゲームのセッションとシナリオの処理(地形の編集・取り込み)は同時に行えず、競合する要求は 409 `SESSION_ACTIVE` になる。[読み取り専用モード](プレイモード.md)で管理者の秘密を示さない書き込みは 403 `READ_ONLY`、重なったエポックの実行は 409 `EPOCH_ALREADY_RUNNING` になる。

## プロセスの監視と終了

Tauri が子プロセスを監視する。Unity が異常終了したら起動し直し、Unity は自分でセッションを確かめて都市に戻る。コアとの通信が途切れたら操作を止め、続けて通じなければ、製品版はアプリを終え、開発版はトップメニューへ戻って再接続を待つ。

アプリの終了は発生源(終了ボタン・ウィンドウの×・子プロセスの終了など)によらず Tauri がまとめ、Unity へ `system:shutdown` を送り、自分で起動したコアには標準入力のパイプを閉じて伝える。コアはエポックの実行が終わるのを待ち、ゲーム中なら緊急オートセーブを残して終わる。Tauri が異常終了しても OS がパイプを閉じるので、コアは同じ手順で終わる。外部で起動したコアは止めない。

## 観察専用の起動

Unity を起動引数 `--viewer` で起動すると、都市を見せるだけのグラフィックになる(作業用とは別に同じコアへつなぎ、定点のカメラで録画するときなどに使う)。MMF は1組の Tauri・Unity だけをつなぐので、観察専用の Unity は MMF を開かず、Unity の中の Tauri の代役がコアの状態を見て、初期ロードや読み直しを Tauri と同じイベントで自分へ送る。編集の指示は届かず視点もコアへ保存しないので、都市を書き換えない。

## Steam認証

Steam 版の Tauri が Steam の認証チケットをコアへ送り、コアが検証する。UI は結果をセッションの `verification_status` で表示し、検証の処理を持たない。認証されると、所有している DLC のシナリオを開けるようになる。Unity もオーバーレイのために SteamAPI を初期化するが、認証には関わらない。

ストアの SDK を使う処理は Tauri のストア連携に閉じ、ビルドの feature で選ぶ(Steam 版は `steam`)。feature の無いビルドはストアの SDK を含まず、コアは未認証として動く。セーブの暗号化・出自・公式署名は[セーブデータ仕様](セーブデータ仕様.md)にある。

## ブラウザ版

同じ UI とグラフィックを、ブラウザの1ページで動かす構成もある。ゲームの内容と流れは exe 版と同じで、違うのは各部の置き場所と、Unity・UI 間の運び方だけである。

| 要素 | exe 版 | ブラウザ版 |
| --- | --- | --- |
| コア | Tauri が子プロセスとして起動する | ページの外で動くコアに URL でつなぐ(`tauri/web/.env` の `VITE_CORE_API_URL`) |
| グラフィック | Unity の Windows ビルド | 同じ Unity プロジェクトの Web ビルド(WebGPU)。ページ全面の canvas に描く |
| UI のウィンドウ | Tauri の WebView ウィンドウ | canvas に重ねた iframe |
| ウィンドウ管理・セッション監視・IPC の中継 | Rust(`tauri/src-tauri`) | Web シェル(`tauri/web/shell`) |
| Unity ⇔ UI | MMF | 同じページの JS |

UI のコード(`tauri/src`)は exe 版と共通で、Web ビルドのときだけ `@tauri-apps/*` を `tauri/web/tauri-shim` の実装に差し替える。Web シェルは Rust と同じ規則で動き、OS に依存する機能は、ブラウザに同等のものがあればそれを使い、無ければ失敗として返す。

`npm run build:web:core` で作る、開発用のコアが配る版にだけ、Unity の代わりに都市の2D地図を置いた開発用の地図ページを入れる(エポックを回した都市を別の端末から確かめるためのもので、製品のビルドには含めない)。
