# コンポーネント連携

City Genesis は、都市データを保持するコア、操作UIを描くTauri、3D描画と空間入力を担当するUnityの3プロセスで動く。

| 経路 | 通信 | 役割 |
| --- | --- | --- |
| Tauri・Unity → コア | HTTP | 都市データの取得、編集の確定、エポック実行 |
| Tauri ⇔ Unity | MMFによるIPC | 編集状態・選択・表示・ロード状況の同期 |

経済計算はコアが担当し、UIと描画は応答を利用する。[IPCの通信契約](IPC連携の整理.md)、[UI共通基盤](UI共通基盤.md)、[プレイモード](プレイモード.md)はそれぞれ別ページに定義する。

コアは URL で接続される相手で、UI・グラフィックのプロセスやクライアントの PC を前提にしない(別のマシンのサーバーとして動くこともありうる)。セーブ・シナリオなどコアが管理するファイルは UI もコアの API を通して扱い、直接読まない。クライアントの PC についての値(3D のメモリ、PC 全体のメモリ・ビデオメモリ、CPU・GPU の名前)は Tauri が自分で測る。

## 起動順序

Tauri がストアの起動対象で、全プロセスの親になる。インストール先は次の構成で、Tauri は決まった場所に実行ファイルがあれば子として起動し、無ければ外部で起動済みとみなして接続だけする(開発時に手で起動したコアや Unity Editor)。

```
<インストール先>/
├── city-genesis.exe   Tauri
├── Core/              コア(genesis.exe と同梱物)
├── Graphics/          Unity(Realcity.exe と同梱物)
└── dlc/               DLC のシナリオ(ストアが置く)
```

1. Tauri がストア連携を初期化する。Steam の外から起動したときは連携なしで続ける。
2. Tauri がlocalhostの空きポートを決めてコアを起動し、版情報に応答するまで待つ。
3. コアの応答後に Unity を起動する。子プロセスは Steam 関連を含む Tauri の環境変数を継承する。
4. Tauri と Unity が接続先と版を確認し、IPCの接続を確立する。トップメニューは最初のセッション状態の配信で表示される。

| 対象 | 接続先の受け渡し |
| --- | --- |
| コア | 環境変数 `GENESIS_API_PORT`(待ち受けるポート)、起動引数 `--attached`(標準入力が閉じたら終了する)。ストアが管理するフォルダは `GENESIS_DLC_DIR`・`GENESIS_WORKSHOP_DIR` |
| Unity | 起動引数 `--api-base-url` |
| コアを起動しない Tauri | 環境変数 `GENESIS_UI_API_BASE_URL`。無ければ `http://127.0.0.1:5000` |

接続可否と再接続時の照合は[バージョニングと互換性](バージョニングと互換性.md#4-プログラム間の互換性)に従う。Unityは採用したAPIベースURLだけをログに残し、認証情報を含み得る起動引数全体を出力しない。

## ローカルAPIへの接続

コアは `127.0.0.1` だけで待ち受ける。同じPCのサードパーティ製プログラムも同じAPIで都市を閲覧・編集できる。接続窓口は次のとおり。

| クライアント | HTTP窓口 |
| --- | --- |
| TauriのWebView | `utils/api.ts` の `fetchApi`、または設定済みの `fetch` |
| TauriのRust | 共通の版照合済みHTTPクライアント |
| Unity | `ApiClient` |

APIの画像は `useApiImageUrl` が取得したBlob URLで表示する。ユーザーデータの保存先は[ファイル配置](ファイル配置.md)に従う。版情報はRustが起動時に取得して共有し、各WebViewが個別に取得しない。

### 一括取得の応答形式

建物・パス・区画・地区・ノードの一括取得はJSONとMessagePackに対応する。要求の `Accept: application/x-msgpack` に対して、応答の `Content-Type` が `application/x-msgpack` ならMessagePackとして読む。フィールドの意味は両形式で同じである。MessagePackの整数の辞書キーは、受信側で文字列キーとして扱う。

### CORSとWebViewのCSP

CORSはTauriの各オリジンとlocalhostの開発サーバーを許可し、Cookieによる資格情報は扱わない。エラー応答にもCORSヘッダーが付き、UIが理由を読める。UnityとRustのHTTPはCORSの対象外である。

製品版WebViewのCSPは、スクリプトを自身のバンドル、画像を自身・data・blob・localhost、通信を自身・IPC・localhostに制限する。インラインスタイルは許可する。実行時にコードを生成する `eval`・`new Function` は許可しない。チュートリアルのSchema検証は事前生成したコードを使う。開発サーバーと製品版ではCSPの適用が異なるため、CSPの確認対象は配布ビルドである。

Swagger `/docs` とOpenAPI `/openapi.json` は、開発版・製品版・モック版で参照できる。ReDoc `/redoc` と `/data/*` は開発版の対象である。

## セッション状態の管理

`GET /api/v1/sessions` の `current_save_id` がnullならゲーム未開始、非nullならゲーム進行中である。`current_save_id` は上書き保存の先でもあり、別名保存では新しいファイルのIDに変わる。別の都市への切り替え(ロード・新規作成)は、都市を作る・読み込むたびに変わる `session_id` で判定し、別名保存を切り替えと取り違えて都市を読み直さない。UIはRustの共通監視から配信される `session-state` を参照する。各画面は独立した監視やセッション状態の正を持たない。マスターデータは、それを参照するウィンドウだけが、共通監視が通信を確認している間に取得する。取得に失敗しても独自に再試行せず、通信の回復を待って取り直す。

ゲーム未開始ではシステム・セッション・セーブ・シナリオ・パラメーター・テンプレート・マスターのAPIを使える。都市データを返すAPIは503 `NO_SAVE_LOADED` になる。シナリオの地形編集中もゲームのセッションは開始されず、都市APIは利用できない。編集の処理中に競合する書き換えは409 `SESSION_ACTIVE` になる。

シナリオの選択中は現在の都市を保持する。開始の確定後に版・保存データを検証し、Unityのリセットと初期ロードを行う。初期ロードの完了は[データロード](../geometries/H_バックエンドデータロード.md#初期ロードの完了)で判定する。Unityの `game:loaded` を受けるまでロード表示を維持し、初期パラメーター設定やHUDの操作を開始しない。

`POST /api/v1/epochs` の実行は同時に一つで、競合する要求は409 `EPOCH_ALREADY_RUNNING` になる。

## プロセスの監視と終了

Tauri が子プロセスを監視する。

- Unity の正常終了(3D のウィンドウを閉じた)とコアの終了は、アプリ全体の終了として扱う。
- Unity の異常終了では Unity を起動し直す。都市の状態はコアにあるので、起動し直した Unity は自分でセッションを確かめて都市に復帰する。短時間に繰り返すときはアプリ全体を終了する。再起動時は `system:graphic_ready` を再同期の起点とし、UIがポップアップと編集状態を初期化する。正常停止は `system:graphic_stopped` で通知する。
- コアとの通信断では表示と操作を停止し、復旧時に共通の接続・セッション確認を通す。

アプリ全体の終了は Tauri が統括し、終了ボタン・ウィンドウの×・子プロセスの終了など発生源によらず同じ手順に合流する。Tauri は画面を消し、Unity へ `system:shutdown` を送り、自分で起動したコアの標準入力のパイプを閉じる。コアはエポック実行の完了を待ち、ゲーム中なら緊急オートセーブを残して終了する。Tauri はコアの終了を待ってから自身を終了する。Tauri が異常終了したときも OS がパイプを閉じるので、コアは同じ手順で終了する。Unity は Tauri の終了とともに OS が終了させる(Windows の Job Object)。外部で起動したコアは Tauri の終了で止めない。

## Steam認証

Steam 版の Tauri が Steam の認証チケットを取得し、コアの準備後に `POST /api/v1/system/verify` に `{app_id, ticket}` を送る。認証結果はセッション応答の `verification_status` で参照する。認証されたDLCの所有状況はシナリオの読込可否に使われる。Unity も Steam オーバーレイのために SteamAPI を初期化するが、認証には関わらない。

ストアの SDK を使う処理は Tauri のストア連携に閉じ、ビルド時の feature で選ぶ(Steam 版は `steam`)。feature を付けないビルドはストアの SDK を含まず、コアは未認証として動く。ストアが管理するフォルダ(DLC・Workshop)もストア連携がストアから得て、コアへ渡す。

UIは認証状態を共通セッション通知から表示し、検証処理を再実装しない。セーブの暗号化・出自・公式署名は[セーブデータ仕様](セーブデータ仕様.md)に定義する。

## ブラウザ版

同じUIとグラフィックを、ブラウザの1ページで動かす構成もある。ゲームの内容と流れ(トップメニューでシナリオを選んで始める)はexe版と同じで、違うのは各部の置き場所と、Unity・UI間の運び方だけである。

| 要素 | exe版 | ブラウザ版 |
| --- | --- | --- |
| コア | Tauriが子プロセスとして起動する | ページの外で動くコアにURLでつなぐ。URLは `tauri/web/.env` の `VITE_CORE_API_URL` で、相対URLはページの場所から解決する |
| グラフィック | UnityのWindowsビルド | 同じUnityプロジェクトのWebビルド(WebGPU)。ページ全面のcanvasに描く |
| UIのウィンドウ | TauriのWebViewウィンドウ | canvasに重ねたiframe。ウィンドウ1枚がiframe 1枚 |
| ウィンドウ管理・セッション監視・IPCの中継 | Rust(`tauri/src-tauri`) | Webシェル(`tauri/web/shell`)。Rustと同じ規則で動く |
| Unity ⇔ UI | MMF | 同じページのJS。Envelopeとイベントは同じ |

UIのコード(`tauri/src`)はexe版と共通で、Webビルドのときだけ `@tauri-apps/*` を `tauri/web/tauri-shim` の実装に差し替える。イベントの宛先の規則・コマンドの名前と引数・ウィンドウの配置の規則はTauriと同じにする。

モニターは表示領域1枚として扱う。OSに依存する機能は、ブラウザに同等のものがあればそれを使い、無ければ失敗として返す。

| 機能 | ブラウザ版 |
| --- | --- |
| URLを開く | 新しいタブで開く |
| フライ・撮影中のUIの非表示 | UIの層を隠す |
| アプリの終了 | ページ内のUnityを止め、UIを消す |
| アプリの設定 | ブラウザの `localStorage` に保存する |
| PCの統計 | 測れない項目はnull |
| セーブフォルダを開く・ファイルダイアログ・ウィンドウの最小化 | 失敗を返す |

コアのCORSは開発サーバー(1420番)を許可している。ブラウザ版の開発サーバーも同じ番号で動くので、exe版の `npm run tauri dev` とは同時に動かせない。

ページから読むファイルは相対パスで参照するので、ビルドしたページはどの場所に置いても動く。

### 開発用の地図ページ

`npm run build:web:core` は、開発用のコアが自分で配る版(`tauri/dist-web-core`)を作る。コアは `/api/v1/debug/web/` でこの版を配り、ページとコアが同じ場所になるので、接続先はページからの相対URLにしている(`tauri/web/.env.core`)。コアはループバックだけで待ち受けるので、別の端末から開くにはコアへ届く経路(リバースプロキシなど)を別に用意する。

この版にだけ、エポックを回した都市を外出先のスマホなどから確かめるための開発用の地図ページ(`tauri/web/debug-map.html`、実装は `tauri/web/debug-map/`)を入れる。製品のビルド(exe版・通常のブラウザ版)には含めない。同じWebシェルを使い、差し替えるのはグラフィックとウィンドウの置き方だけである。

- グラフィック: Unityの代わりに都市の2D地図を置く。地図はUnityと同じEnvelopeでWebシェルとやり取りし、Unityが準備を終えて返す合図(`system:graphic_ready`・`game:loaded`・`epoch:darkened`)はすぐに返す。Unityへ送られる `session:reload` は同じ名前のイベントで地図へ渡す。建物・パスのタップで、3D画面のクリックと同じ詳細ウィンドウを開く。
- ウィンドウの置き方: コックピットの代わりの上部バー(日付・エポックの実行数・実行)を画面上端に置き、他のウィンドウは種類ごとの定位置に置く(`tauri/web/debug-map/layout.ts`)。
- 地図と上部バーの中身は、ページの入口が `src/extraWindows.ts` に登録してから共通のUIを読み込む。`src/` は登録されたものを描くだけで、この2つを知らない。
