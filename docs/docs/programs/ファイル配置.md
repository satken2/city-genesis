# ファイル配置とデータ管理責任

## 概要

ゲームで扱うデータは複数のプログラム（バックエンド Python / Tauri フロントエンド）にまたがって管理される。各プログラムが独立してデータを保存し始めると管理が複雑になるため、**どのプログラムが何を記録するか**をここで定義する。

## ロード画面と画像のHTTPキャッシュ

セーブデータのロード画面(`SaveListWindow`)は、開くたびに`GET /api/v1/saves`と`GET /api/v1/sessions`を`cache: "reload"`で取得する。ブラウザに保存された応答を使わず、上書き保存・削除・現在のロード状態を反映する。一覧とセッション情報は独立して取得結果を扱うため、片方が失敗してももう片方は表示する。

地形画像(`/terrain/maps/{id}/thumbnail`)とセーブ・シナリオ画像(`/saves/{id}/thumbnail`)には`Cache-Control: private, max-age=7200, must-revalidate`を付ける。画像は2時間キャッシュでき、期限後はサーバーへの確認を必要とする。未登録画像の404は`no-store`とし、後から作った画像を古い404で隠さない。通常の画像表示ではURLを固定し、表示のたびにランダムなクエリを付ける処理は行わない。

## データ管理責任の分担

| データ種別                     | 管理責任               | 保存場所             |
| ------------------------- | ------------------ | ---------------- |
| ゲームの都市状態（セーブデータ）          | **バックエンド（Python）** | AppData（ユーザーデータ） |
| シナリオテンプレート（ユーザー作成）        | **バックエンド（Python）** | AppData（ユーザーデータ） |
| シナリオテンプレート（組み込み）          | **バックエンド（Python）** | インストール先同梱        |
| マップデータ（与論島・青ヶ島等）          | **バックエンド（Python）** | インストール先同梱        |
| 地形エディタの作業コピー（編集用ローカルコピー）  | **Tauri（フロントエンド）** | AppData（ユーザーデータ） |
| 音量・ディスプレイ番号・言語・チュートリアル完了等 | **Tauri（フロントエンド）** | Tauri が管理        |

バックエンドはゲームシミュレーションに関わるデータのみを管理し、UI・操作系の設定はすべて Tauri 側に委ねる。

## バックエンドが管理するファイル

### セーブデータ・ユーザーテンプレート（AppData）

ユーザーごとに異なるデータは OS の標準的なアプリデータ領域に保存される。

| プラットフォーム | ベースパス |
|----------------|-----------|
| **Windows** | `%LOCALAPPDATA%\UrbanGenesis\`（例: `C:\Users\{ユーザー名}\AppData\Local\UrbanGenesis\`） |
| **macOS** | `~/Library/Application Support/UrbanGenesis/` |
| **Linux / Steam Deck** | `$XDG_DATA_HOME/UrbanGenesis/`（未設定時は `~/.local/share/UrbanGenesis/`） |

ベースパス配下のディレクトリ構成:

```
UrbanGenesis/
├── saves/                    # 通常セーブデータ（.cg ファイル） … バックエンド管理
│   └── saves_metadata.json   # セーブ一覧メタデータ
├── templates/                # ユーザーが作成したシナリオテンプレート（.cg ファイル） … バックエンド管理
│   └── saves_metadata.json   # テンプレート一覧メタデータ
└── terrain_editor/           # 地形エディタの作業コピー … Tauri 管理
    └── {editor_id}/          # 取り込みごとに発行されるUUIDの作業ディレクトリ
        ├── meta.json         # 設定値(マップサイズ・グリッド間隔等)と取り込んだ配置情報
        └── near.bin          # 近景標高マップ(float16 LE)のローカルコピー
```

`saves/` と `templates/` はバックエンド(Python)が読み書きし、`terrain_editor/` は Tauri(Rust)が読み書きする。
地形エディタを開くと、バックエンドの `GET /api/v1/terrain/maps/{id}/near` などから取得したデータを
`terrain_editor/{editor_id}/` へ書き出し、エディタウィンドウがそれを読み込む。以降の編集はメモリ上で完結し、
バックエンドのゲーム状態には影響しない。作業コピーは初期データの受け渡し専用で、編集途中の保存・再開には使わない
(編集結果は「.npyへエクスポート」で書き出す)。

デバッグ起動・プロダクション起動で保存先は同一（パスの分岐なし）。

### 組み込みテンプレート（インストール先同梱）

ゲームに最初から付属するシナリオテンプレートは実行ファイルと同じ場所に配置する。

```
<インストール先>/
└── city/
    └── template/            # 組み込みテンプレート（.cg ファイル）
        └── saves_metadata.json
```

Steam 配布時はこのディレクトリごとパッケージに含める。ユーザーはこれらを削除できない。ロード時は組み込みテンプレートとユーザーテンプレートが自動的にマージされて一覧表示される。

### マップデータ（インストール先同梱）

地形ファイルは `assets/terrains/` に集約する。

```text
assets/terrains/
├── original/                 # 編集禁止。標高 .npy だけを保持
│   ├── map_yoron.npy
│   └── map_aogashima.npy
├── original_terrains.yaml    # 原本を複製するための寸法・解像度
├── terrain_maps.yaml        # ニューゲーム用コピーの登録表
├── map_yoron.npy            # ゲーム用の標高コピー
├── map_yoron.png            # ゲーム用サムネイル
└── map_yoron.resources.json # 川・水面・資源・プロップ等の付随データもここ
```

両登録表の `file_name` は `assets/` 基準（例: `terrains/map_yoron.npy`）。Steam配布には `assets/` ごと含める。原本は標高のみで、川・水面・資源・プロップ・カメラ・サムネイルを持たない。原本を上書きする編集・エクスポートは禁止する。

エディタは原本を標高だけの新規IDの作業コピーとしてAppDataへ複製する。ニューゲームはゲーム用コピーの登録表だけを参照する。ゲーム用コピーをエクスポートすると同じ場所の `terrain_maps.yaml` に登録され、原本や原本の設定は変更されない。サムネイルは `.npy` と同名の `.png` を `/terrain/maps/{id}/thumbnail` から配信し、存在しなければプレースホルダーを表示する。

地形エディタのロード画面は「既存マップを編集」（川、資源、プロップなどを含みます）、「オリジナル地形」（純粋な地形データです）の順に表示する。既存マップの川・水面・カメラは `/terrain/maps/{id}/features` から、資源・プロップは各専用APIから取り込む。編集中の内容を残すにはエクスポートする。

## 版定義と配布シナリオ

公開リポジトリ直下の `version.json` がTauri・Unity共通のフロント版と通信契約を定める。`tauri/tools/sync-version.mjs` が配布設定とUnityの定数を同期する。コアの実際の版はHTTPで取得する。

自作テンプレートはユーザーデータ `templates/`、取り込んだ作品は `downloaded_scenarios/` に分ける。更新前の原本退避は `saves/backups/`。配布用 `.cgscenario` は選択した1作品のアーカイブとマニフェストを含み、端末の一覧索引を含めない。
