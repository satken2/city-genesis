# ファイル配置とデータ管理責任

## 概要

ゲームで扱うデータは複数のプログラム（バックエンド Python / Tauri フロントエンド）にまたがって管理される。各プログラムが独立してデータを保存し始めると管理が複雑になるため、**どのプログラムが何を記録するか**をここで定義する。

## ロード画面と画像のHTTPキャッシュ

セーブデータのロード画面(`SaveListWindow`)は、開くたびに`GET /api/v1/saves`と`GET /api/v1/sessions`を`cache: "reload"`で取得する。ブラウザに保存された応答を使わず、上書き保存・削除・現在のロード状態を反映する。一覧とセッション情報は独立して取得結果を扱うため、片方が失敗してももう片方は表示する。

地形画像(`/terrain/maps/{id}/thumbnail`)とセーブ・シナリオ画像(`/saves/{id}/thumbnail`)には`Cache-Control: private, max-age=7200, must-revalidate`を付ける。画像は2時間キャッシュでき、期限後はサーバーへの確認を必要とする。未登録画像の404は`no-store`とし、後から作った画像を古い404で隠さない。通常の画像表示ではURLを固定し、表示のたびにランダムなクエリを付ける処理は行わない。画像APIも認証トークンが必要なので、UIは `<img src>` にAPIのURLを直接書かず、fetch で取得した Blob URL を表示する([コンポーネント連携](コンポーネント連携.md#ローカルapiの認証))。

## データ管理責任の分担

| データ種別                     | 管理責任               | 保存場所             |
| ------------------------- | ------------------ | ---------------- |
| ゲームの都市状態（セーブデータ）          | **バックエンド（Python）** | AppData（ユーザーデータ） |
| 自作シナリオ                    | **バックエンド（Python）** | AppData（ユーザーデータ） |
| コミュニティのシナリオ（Steam Workshop） | **Steam**（ゲームは読むだけ） | Steam Workshop の購読フォルダ |
| DLCのシナリオ                  | **Steam**（ゲームは読むだけ） | インストール先の `dlc/` |
| オリジナル地形（与論島・青ヶ島等の標高とサムネイル） | **バックエンド（Python）** | インストール先同梱        |
| ローカルAPIの認証トークン            | **バックエンド（Python）**（UI・グラフィックは読むだけ） | AppData（ユーザーデータ） |
| 地形エディタの作業コピー（編集用ローカルコピー）  | **Tauri（フロントエンド）** | AppData（ユーザーデータ） |
| 音量・ディスプレイ番号・言語・チュートリアル完了等 | **Tauri（フロントエンド）** | Tauri が管理        |
| 3D画面の表示ディスプレイ・解像度          | **Unity（グラフィック）**  | Unityプレイヤーが終了時に記録（Windowsではレジストリ） |

バックエンドはゲームシミュレーションに関わるデータのみを管理し、UI・操作系の設定は Tauri 側に委ねる。3D画面の表示先だけは、Unityプレイヤー自身の記録に任せる。

## バックエンドが管理するファイル

### セーブデータ・自作シナリオ（AppData）

ユーザーごとに異なるデータは OS の標準的なアプリデータ領域に保存される。

| プラットフォーム | ベースパス |
|----------------|-----------|
| **Windows** | `%LOCALAPPDATA%\UrbanGenesis\`（例: `C:\Users\{ユーザー名}\AppData\Local\UrbanGenesis\`。環境変数 `LOCALAPPDATA` が無ければ `%APPDATA%\UrbanGenesis\`） |
| **macOS** | `~/Library/Application Support/UrbanGenesis/` |
| **Linux / Steam Deck** | `$XDG_DATA_HOME/UrbanGenesis/`（未設定時は `~/.local/share/UrbanGenesis/`） |

ベースパス配下のディレクトリ構成:

```
UrbanGenesis/
├── api_token                 # ローカルAPIの認証トークン … バックエンドが起動ごとに書く
├── saves/                    # 通常セーブデータ（.cg ファイル） … バックエンド管理
│   ├── saves_metadata.json   # セーブ一覧メタデータ
│   └── backups/              # 版の異なるコアで初めて開く前に退避した原本
├── scenarios/                # 自作シナリオ（.cg ファイル） … バックエンド管理
│   └── saves_metadata.json   # シナリオ一覧メタデータ
└── terrain_editor/           # 地形エディタの作業コピー … Tauri 管理
    └── {editor_id}/          # 地形エディタを準備するたびに発行されるUUIDの作業ディレクトリ
        ├── meta.json         # 編集対象のシナリオID・ロック情報・設定値と、水面・川・資源・プロップ・カメラ・地表・気候
        └── near.bin          # 近景標高マップ(float16 LE)のローカルコピー
```

`saves/` と `scenarios/` はバックエンド(Python)が読み書きし、`terrain_editor/` は Tauri(Rust)が読み書きする。バックエンド・UI・グラフィックは同じ規則でベースパスを決める(Windowsは OS の既知フォルダより環境変数を優先する)。ずれるとトークンファイルを読めず、手動起動したクライアントの要求が401になる。

`api_token` はバックエンドが起動のたびに作るトークンで、書き込みは一時ファイルからの置き換えで行う(読み手が書きかけの値を掴まないため。Windows以外では所有者だけが読める権限にする)。バックエンドが子プロセスとして起動したUI・グラフィックは環境変数でトークンを受け取るので、このファイルを読むのは環境変数を持たないクライアント(開発時やモックで手動起動したUI・グラフィック)である([コンポーネント連携](コンポーネント連携.md#ローカルapiの認証))。

地形エディタを開くと(シナリオ管理の「地形を編集」)、Tauri がバックエンドの `GET /api/v1/scenarios/{id}/terrain` から取得したデータを
`terrain_editor/{editor_id}/` へ書き出し、エディタウィンドウがそれを読み込む。以降の編集はメモリ上で完結し、
「シナリオに保存」で `PUT /api/v1/scenarios/{id}/terrain` へ送るまでシナリオは変わらない。作業コピーは初期データの受け渡し専用で、
編集途中の保存・再開には使わない(「シナリオに保存」が成功したときだけ、Tauri が保存した内容に合わせて書き換える)。どのウィンドウにも結び付かず作成から1時間を過ぎた作業コピーは、次に地形エディタを準備するときに Tauri が削除する。

デバッグ起動・プロダクション起動で保存先は同一（パスの分岐なし）。

### コミュニティ・DLCのシナリオ（Steamが管理）

コミュニティ(Steam Workshop)とDLCのシナリオは Steam が配置・更新するフォルダに置かれ、ゲームは読むだけで書き込まない。一覧では自作シナリオと合わせて表示される。ID・読み取り専用の扱いは[シナリオ制作と配布](シナリオ制作と配布.md#保存元と置き場)を参照する。

```
<インストール先>/
└── dlc/
    └── {pack_id}/
        └── {stem}.cg                     # DLCのシナリオ(公式署名つき。多くは暗号化されている)

steamapps/workshop/content/<AppID>/
└── {item_id}/
    └── {stem}.cg                         # コミュニティのシナリオ
```

`<インストール先>` はバックエンドの実行ファイルがあるフォルダ。Workshop のフォルダは、ゲームが Steam ライブラリの `steamapps` 配下にインストールされているときだけ決まる。

### オリジナル地形（インストール先同梱）

地形ファイルは `assets/terrains/` に集約する。

```text
assets/terrains/
├── original/                 # 編集禁止。開発者用の標高原本と、背景の標高・遠景用海岸線
│   ├── map_yoron.npy
│   ├── map_aogashima.npy
│   ├── map_hongkong_bg.npy              # 背景標高(遠景)
│   └── map_hongkong_bg.coastline.json   # 背景の遠景用海岸線
├── original_terrains.yaml    # 標高原本の寸法・解像度(開発者用)
├── terrain_maps.yaml         # オリジナル地形の登録表
├── map_yoron.npy             # オリジナル地形の標高
└── map_yoron.png             # オリジナル地形のサムネイル
```

オリジナル地形は、標高(`.npy`)とサムネイル(同名の `.png`)と、登録表 `terrain_maps.yaml` に書く範囲・寸法などのメタデータだけからなる。水面・川・資源・プロップ・カメラは持たず、シナリオが持つ([地形形状](../geometries/D_地形形状.md) §D.14)。登録表の地表種別・気候は、その地形から作る新しい都市の初期値に使うだけである。登録表の `file_name` は `assets/` 基準（例: `terrains/map_yoron.npy`）。Steam配布には `assets/` ごと含める。

サムネイルは `/terrain/maps/{id}/thumbnail` から配信し、存在しなければUIがプレースホルダーを表示する。オリジナル地形はシナリオ管理の「地形を取り込む」とチュートリアルが使い、ゲームから書き換える手段は無い。

`original/` と `original_terrains.yaml` は開発者が標高を作り直すための保管庫で、ゲームは読み込まない。ただし背景地形([地形形状](../geometries/D_地形形状.md#都市外の背景地形))の標高と遠景用海岸線だけは `original/` から読む。

## 版定義

公開リポジトリ直下の `version.json` がTauri・Unity共通のフロント版と通信契約を定める。`tauri/tools/sync-version.mjs` が配布設定とUnityの定数を同期する。コアの実際の版はHTTPで取得する。
