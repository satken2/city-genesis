# 達成目標と住民満足度スコア

`AchievementsWindow`は、都市づくりの方向性を示す目標と、住民の暮らしの評価を左右に配置する。スコアの概念は[施政スコア](../economics/23_施政スコア.md)、目標の状態は[達成クエスト](../economics/24_達成クエスト.md)を参照する。UIの表示名は「住民満足度スコア」で、APIのcity_score系の名称は変えない。

## 左ペイン：達成目標

シナリオ紹介と目標カードを表示し、進行中・未解放・達成済み・期限切れの順に並べる。同じ状態のカードはAPIの順序を保つ。名称と説明は折り返して全文表示し、状態を文字でも示す。紹介文と目標の名称・説明は作者が書く多言語テキストで、表示言語の文を出し、無ければ英語の文を出す(`utils/locale.ts` の `resolveLocalizedText`)。進捗はサーバのprogressを参照する。未達成の隠し目標は通常プレイでは名前・説明・条件・進捗を伏せる。シナリオ紹介は表示だけで、テンプレート作成時も編集しない(紹介文を編集するのは紹介情報ウィンドウだけ。[シナリオ制作と配布](シナリオ制作と配布.md#紹介情報))。テンプレート作成時はその案内を出し、目標の追加・編集・削除ができる。

## 右ペイン：住民満足度スコア

減点後の1世帯あたりスコアを最大2点の主指標として表示する。半円メーターはスコア÷2の割合を百分率で示し、元の点数を併記する。メーターの横には満足度に対応する顔を配置する。主指標の表示名は「1世帯あたり満足度」。横に「全世帯合計」と生活水準・住環境・「事故・災害による減点」の数値内訳を示す。通常時の主指標・推移・満足度内訳には総括説明を添えず、集計世帯数も表示しない。エポック未実行なら評価前の案内を出し、実行済みでも世帯数が0なら主指標はダッシュ表示とする。

推移は単一軸のグラフで、生活水準と住環境を正方向に積み上げ、倒壊減点を負方向に描く。白い線が減点後の確定スコアを示す。1世帯あたり表示では正方向の軸上限を2点に固定し、各エポックの世帯数で内訳を割る。都市合計への切替時は絶対量を表示する。線はどちらの表示でもAPIの確定値を使う。

世帯満足度の内訳は栄養・医療・娯楽余暇・住環境の平均値を百分率と高さ16pxの横棒メーターで示し、横に顔を配置する。住環境は正規化後の値で、各項目には評価対象を説明する短文を添える。これらの平均値には倒壊減点を適用しない。当期の焼失・倒壊一覧は詳細開閉内に表示する。

左右ペインは独立してスクロールする。極端に狭い表示（540px以下）は縦配置へ切り替える。配色は共通のflatトークン、文言は全7言語のachievements.jsonを用いる。

## 履歴API

`GET /api/v1/score`のhistoryは各エポックのcity_score・city_score_per_household・city_score_qol・city_score_env・city_score_collapse_penalty・city_score_household_countを含む。最新の内訳を過去へ流用しない。historyが空なら未実行として扱う。

## 共通の表情と配色

`common/SatisfactionFace`は0〜1のvalueから「げっそり・不満・ふつう・満足・大満足」の5段階の絵文字（😵→😢→😐→😊→🥰）を選ぶ。補正後の値が0のときだけ☠️を表示する。境界値は20%・40%・60%・80%で、境界は上の段階に含む。範囲外は0〜1に補正し、非有限値は0とする。画像への変更はこの部品内で行う。getSatisfactionAppearanceは同じ基準による色を返し、半円と横棒にも適用する。色は赤・橙・黄・黄緑・緑に対応する共通flatトークンとその混色。表情の読み上げ名とツールチップは全7言語のsatisfaction.jsonを使う。世帯数が0または未実行なら表情を評価しない。

## エポック結果の通知データ

`POST /api/v1/epochs` のレスポンスには `completed_quests`（新規達成）と `failed_quests`（期限切れ失敗）が含まれる。各要素は通知用ペイロードで、達成時の実測値・報酬・演出情報を持つ。

```json
{
  "completed_quests": [
    {
      "id": 1,
      "name": {"ja": "人口10,000人到達", "en": "Population 10,000"},
      "description": {"ja": "都市の人口が10,000人に到達する", "en": "Reach a population of 10,000"},
      "latch": true,
      "notify": "modal",
      "tier": "gold",
      "category": "人口",
      "hidden": false,
      "reward": {"type": "grant_money", "amount": 100000},
      "achieved_values": {
        "0": {"current": 10234, "target": 10000, "compare": ">="}
      },
      "completed_epoch": 42,
      "status": "completed"
    }
  ],
  "failed_quests": []
}
```

`achieved_values` は達成時点の各条件節の実測値（条件木内の位置をキーとする辞書）で、お祝いウィンドウが「実測値 10,234 / 目標 10,000」のような表示に使う。

## 達成と失敗の通知

`notify="toast"` の達成と全失敗は、エポック完了直後にトーストで知らせる。結果ウィンドウでは達成・失敗と、進捗70%以上のアクティブな目標を表示する。結果を閉じた後、`notify="modal"` の達成をtier降順でお祝いウィンドウに表示する。実測値と報酬は通知データを使う。

## クエストの編集

テンプレート作成モードでは目標を追加・編集・削除できる。名前と説明は[共通の多言語入力](UI共通基盤.md#言語と作者のテキスト)を使う。条件は、平坦なall/any条件のフォームと、notや入れ子も扱えるJSONエディタで編集する。条件の意味は[達成クエスト](../economics/24_達成クエスト.md#243-判定条件の3層構造)を参照する。

## クエストAPI

| メソッド | パス | 説明 |
| --- | --- | --- |
| `GET` | `/api/v1/quests` | 全クエストを取得（達成判定後に `progress` / `clause_states` を付与） |
| `GET` | `/api/v1/quests/{quest_id}` | 特定のクエストを取得 |
| `POST` | `/api/v1/quests` | 新しいクエストを作成（テンプレートモードのみ） |
| `PATCH` | `/api/v1/quests/{quest_id}` | 既存のクエストを更新（テンプレートモードのみ。条件を変更すると履歴・連続カウントはリセットされる） |
| `DELETE` | `/api/v1/quests/{quest_id}` | クエストを削除（テンプレートモードのみ） |
| `PUT` | `/api/v1/quests/{quest_id}/complete` | 特定のクエストを強制的に完了（`is_force_completable = true` のみ。報酬も発火する） |
| `POST` | `/api/v1/quests/{quest_id}/complete` | 同上（POST/PUT両方対応） |

`GET /api/v1/quests` が各クエストに付与する表示用フィールド:

| フィールド | 説明 |
| --- | --- |
| `progress` | クエスト全体の進捗率 0..1（`all`=全節の最小、`any`=最大、`streak`=経過/window、達成済みは常に1.0） |
| `clause_states` | 各条件節の評価状態のリスト（現在値・目標値・比較演算子・mode・window・streakカウント・進捗率） |
