# セーブデータ仕様

本ページは現行の保存形式を説明する。コアの版番号、互換性の保証、更新前バックアップと画面表示の設計方針は[バージョニングと互換性](バージョニングと互換性.md)を参照する。アーカイブのメタデータが版情報の正であり、ロード前に本体を検査する。

## セーブファイルの形式

セーブデータは拡張子 `.cg` の ZIP ファイルとして保存される。ZIPの圧縮レベルは6（deflate）。DLC由来の都市は、同じ ZIP を暗号化した形式で保存される（[暗号化されたファイル](#暗号化されたファイル)）。どちらの形式もコアだけが開き、UIとグラフィックは `.cg` を直接読まずにAPIを使う。

## ZIP 内部構造

| ファイル名 | 内容 |
|---|---|
| `soa.npz` | 全テーブルのSoA配列（numpy savez_compressed） |
| `scalars.npz` | SoAではない通常スカラー値を列指向numpy配列として格納 |
| `variable/{table}.msgpack.gz` | 可変長プロパティ（polygon, list, dict等）をmsgpack+gzipで圧縮 |
| `city.json` | Cityシングルトン（都市名、税率、人口統計、海岸線・湖・川、埋立地等） |
| `params.json` | Parametersシングルトン（`GENERAL_PARAMS`, `RATIO_PARAMS`, `TIME_VARYING_CONSTANTS`） |
| `metadata.json` | 都市情報、コア版、シナリオの紹介情報・作品リビジョン |
| `thumbnail.png` | 一覧用の画像(任意)。保存したときの3Dビュー(シナリオは作者が選んだ画像のこともある)。外部ファイルなしで持ち運べる |
| `terrain/settings.json` | Terrainシングルトンの設定値（マップサイズ、グリッド間隔等） |
| `terrain/far_map.npy` | 遠景用標高マップ（numpy。float16 または float32） |
| `terrain/near_map.npy` | 近景用標高マップ（numpy。float16 または float32） |
| `terrain/background.npy` | 都市外の背景地形の標高（50m格子の numpy。背景のある都市だけ） |
| `terrain/background.json` | 背景格子の南西隅のワールドXZ `origin` と遠景用海岸線 `coastline`（背景のある都市だけ） |
| `terrain/dynamic/cell_{id}.npz` | 地形を編集したセルの超近景標高。初期標高と違う格子点だけの差分（numpy 圧縮。[地形](#地形)） |
| `official.json` | 公式シナリオだけが持つ公式署名（[公式署名](#公式署名)）。プレイヤーの保存では書かれない |

## セーブデータ一覧メタデータ（saves_metadata.json）

一覧API（`GET /api/v1/saves`・`GET /api/v1/scenarios`）は、各 `.cg` の `metadata.json`（暗号化されたファイルは平文ヘッダー）から毎回組み立てる。保存ディレクトリの `saves_metadata.json` は、保存する一覧情報だけを起動時と保存・削除・紹介情報や画像の更新時に書き出す再生成可能なキャッシュで、一覧もロードも読まない。互換性・パック所有状況など、実行環境による判定結果はキャッシュに保存しない。

通常セーブとシナリオは同じコンテナ形式を使うが、一覧用メタデータの項目集合は異なる。保存・一覧・キャッシュの書き出しで同じ項目集合を使う。

| 項目 | 通常セーブ | シナリオ | 用途 |
| --- | --- | --- | --- |
| `id`・`is_scenario` | ○ | ○ | ファイルのIDと保存種別 |
| `language` | ○ | ○ | 都市内の固有名詞の言語。シナリオでは開始時に付け直すかの判断にも使う |
| `saved_at` | ○ | ○ | 最終保存日時 |
| `created_core_version`・`saved_core_version`・`last_simulated_core_version` | ○ | ○ | 互換性・バランス変更の比較に使う版情報 |
| `has_thumbnail` | ○ | ○ | 一覧画像の有無 |
| `required_packs`・`derived_from` | ○ | ○ | 必要パックと、引き継ぐ出自 |
| `scenario_title` | ○ | ○ | タイトル。通常セーブ一覧にも元シナリオのタイトルを表示する |
| `city_name` | ○ | — | プレイヤーが確定した都市名。1つの文字列 |
| `save_name` | ○ | — | 通常セーブ一覧の見出し |
| `population`・`current_date`・`epoch` | ○ | — | 都市の進行概要。`current_date` はゲーム内の基準日からの経過日数 |
| `simulation_days` | ○ | ○ | 通常セーブでは確定したエポック日数、シナリオでは開始時の初期値 |
| `autosave` | 任意 | — | 自動保存の識別 |
| `scenario_description`・`scenario_objective` | — | ○ | 多言語の紹介文と目標の説明文 |
| `scenario_city_name` | — | ○ | 都市名入力欄の多言語初期値 |
| `scenario_fixed_options` | — | ○ | 作者が固定した開始設定 |
| `ground_cover`・`climate`・`asset_region` | — | ○ | 地表・気候・アセット地域の開始時の初期値 |
| `map_width`・`map_height` | — | ○ | シナリオ選択画面に表示するマップの大きさ(m) |
| `author`・`scenario_id`・`content_revision` | — | 任意 | 作者と配布作品のID・改訂番号 |

通常セーブのメタデータの例:

```json
{
  "id": "my-save",
  "is_scenario": false,
  "city_name": "MyCity",
  "save_name": "GrowCity",
  "population": 1910,
  "current_date": 91620,
  "epoch": 303,
  "simulation_days": 30,
  "language": "ja",
  "saved_at": "20261003_215934",
  "scenario_title": {"en": "Harbor", "ja": "港町"},
  "created_core_version": "1.0.0",
  "saved_core_version": "1.0.0",
  "last_simulated_core_version": "1.0.0",
  "has_thumbnail": true,
  "required_packs": [],
  "derived_from": {"origin": "local", "scenario_id": "yoron", "content_revision": 1, "official": false}
}
```

シナリオのメタデータの例:

```json
{
  "id": "yoron",
  "is_scenario": true,
  "language": "ja",
  "saved_at": "20261003_215934",
  "scenario_title": {"en": "Harbor", "ja": "港町"},
  "scenario_description": {"en": "An island that builds its city without trade."},
  "scenario_objective": {"en": "Population over 10,000."},
  "scenario_city_name": {"ja": "与論町", "en": "Yoron Town"},
  "scenario_fixed_options": ["climate"],
  "simulation_days": 30,
  "map_width": 7000,
  "map_height": 7000,
  "ground_cover": 1,
  "climate": 2,
  "asset_region": 1,
  "scenario_id": "yoron",
  "content_revision": 1,
  "created_core_version": "1.0.0",
  "saved_core_version": "1.0.0",
  "last_simulated_core_version": null,
  "has_thumbnail": true,
  "required_packs": [],
  "derived_from": null
}
```

`save_name` は別名セーブ(`POST /api/v1/saves` の本文 `{"name": "..."}`)で付ける。上書き保存と終了時の緊急保存は名前を引き継ぎ、名前が無ければ都市名を一覧の見出しにする。シナリオは `save_name` を持たず、紹介文のタイトルを見出しにする。

`required_packs` と `derived_from` は都市の出自（[出自](#出自)）。`language` は都市内の固有名詞が付いている言語であり、多言語の紹介文の表示言語とは独立している。別の言語でシナリオを始めると都市内の名前を付け直す（[シナリオ制作と配布](シナリオ制作と配布.md#ゲーム開始時の言語と開始設定)）。

`scenario_title`・`scenario_description`・`scenario_objective` と `scenario_city_name` は作者が書く多言語テキスト（`{言語コード: 文}`。`ja`・`en`・`es-419`・`zh-Hans`・`zh-Hant`・`fr`・`ko`）。表示言語の文が無ければ英語を使うため、タイトルは常に、ほかは1言語でも書けば英語が必須。空の言語は保存しない。`scenario_objective` は説明文で、達成の判定はクエストが担う。

`scenario_city_name` は開始時に都市名入力欄へ入れる初期値で、プレイヤーが確定した名前は通常セーブの `city_name` になる。プレイ中の都市名は1つの文字列で、表示言語に応じて切り替わらない。初期値が未指定のシナリオでは、制作中の都市名を英語の代替表示と制作言語の初期値へ引き継ぐ。

`scenario_fixed_options` は `simulation_days`・`climate`・`ground_cover`・`asset_region` のうち作者が固定した項目の一覧。固定していない項目はプレイヤーが開始時に選べる。マップの大きさ・地表・気候はシナリオ選択画面の表示にも使う。

都市本体の値は一覧用メタデータと独立している。マップの大きさは `terrain/settings.json`、地表・気候・アセット地域・元の地形名 `terrain_source` は `city.json` から復元する。シナリオの人口・ゲーム内日時・エポック数も `city.json` に保持し、開始する都市の状態として復元する。通常セーブの紹介文も `city.json` に保持し、プレイ中の表示に使う。

### サムネイル画像

セーブデータおよびシナリオ（テンプレート）にはサムネイル画像（PNG）を関連付けることができる。画像は `.cg`（ZIP）のルートに `thumbnail.png` として格納し、本体内の画像を優先する。本体に画像が無いファイルに限り、同名の外部 `{save_id}.png` を読む。外部の画像を使うのはセーブと自作シナリオだけで、コミュニティ・DLCのシナリオでは無視する（配布物の横に置いた画像で紹介の見た目を差し替えさせないため）。画像を更新すると本体へ格納し、外部の画像は削除する。暗号化されたファイルの画像は平文のヘッダーにも入っているので、鍵が無くても表示できる。

- `GET /api/v1/saves/{save_id}/thumbnail`（シナリオは `?template=true`）で画像を取得する。
- `POST` / `PUT /api/v1/saves/{save_id}/thumbnail`（シナリオは `?template=true`）で画像を保存する。シナリオは自作だけが対象で、コミュニティ・DLCは422 `SCENARIO_READ_ONLY`。
- セーブ・シナリオ保存の直前に、UIがグラフィックへ3Dビューの撮影を頼む([IPC連携の整理](IPC連携の整理.md)の `camera:capture_thumbnail`)。グラフィックは撮った画像を `PUT /api/v1/sessions/thumbnail`(本文はPNG)でコアへ預け、次の保存(通常・別名・シナリオ・緊急のどれか1回)がそれを本体へ入れる。撮れなかった保存には、ロードしたファイルの画像か上書きするファイルの画像が入る(どちらも無ければ画像の無いファイルになる)。「シナリオとして保存」で作者が画像を選んだときは、撮影の代わりにその画像を預ける。「都市を編集」で開いたシナリオの上書き保存は撮影せず、シナリオの画像を引き継ぐ。
- テンプレート作成モード中は `GET /api/v1/templates/thumbnail` および `POST /api/v1/templates/thumbnail` で現在のテンプレートに対する画像の確認と設定が行える。
- ニューゲーム画面では、シナリオ固有のサムネイル画像が存在すれば最優先で表示し、未設定の場合は舞台となる地形マップのサムネイルにフォールバックする。

紹介文・初期の都市名・固定した開始設定の実体は `City` のプロパティ（`city.json` に保存され、`GET /api/v1/city` で読める）で、シナリオのメタデータへは一覧表示のために複製される。ニューゲーム画面のシナリオ詳細パネルはセーブ本体（`.cg`）を開かずに描画するため、この複製が必要となる。紹介文は英語のタイトル以外は任意なので、UIでは欠落を空欄として扱う。紹介文を文字列で持つ（多言語テキストでない）保存ファイルは破損として扱い、読み込みを拒否する。コア版の欠落も別に検査し、読み込みを拒否する。

### 一覧APIのエントリ

`GET /api/v1/saves`・`GET /api/v1/scenarios` の各エントリは、上のメタデータに次の項目を加えたものである。読み込めないファイルも理由付きで一覧に残る。

| 項目 | 内容 |
| --- | --- |
| `id` | 一覧・APIでのID。シナリオは保存元付き（[シナリオ制作と配布](シナリオ制作と配布.md#保存元と置き場)） |
| `origin` | シナリオだけが持つ保存元 `local` / `workshop` / `dlc` |
| `read_only` | シナリオだけが持つ。保存元が `workshop`・`dlc` なら真 |
| `encrypted` | 暗号化されたファイルなら真 |
| `required_packs` | 都市を開くのに必要な追加パックのID（昇順） |
| `pack_status` | 必要パックごとの所有状況。`owned`（所有）/ `not_owned`（未所有）/ `unverified`（製品版で、有効なSteam認証の結果がまだ無いため所有を確かめられない） |
| `official` | シナリオだけが持つ。有効な公式署名があれば真 |
| `derived_from` | 都市の元になったシナリオ（[出自](#出自)） |
| `has_thumbnail` | 画像があるか |
| `compatibility` | 読み込めるかと、読み込めない理由（`loadable`・`code`・`message` ほか。[バージョニングと互換性](バージョニングと互換性.md)） |

読み込めない理由は次の順で判定し、最初に当たったものを `compatibility.code` に入れる。

1. ファイルと版の検査（破損 `SAVE_CORRUPT`、版不明・新しい版・MAJOR違いなど）
2. 必要パックの所有（未所有 `SCENARIO_PACK_NOT_OWNED`、所有を確かめられない `SCENARIO_PACK_UNVERIFIED`）
3. 置き場が `dlc` のシナリオだけ、公式署名（無効・無し・署名のパックが必要パックに無い `SCENARIO_SIGNATURE_INVALID`）

暗号化が壊れている・改ざんされている・ヘッダーと中身で必要パックが食い違うファイルは `SCENARIO_ENCRYPTION_INVALID` になる。ロードAPIも同じ判定を都市の初期化より前に行うので、読み込めないファイルを開こうとしても現在の都市は変わらない。

## 通常セーブとシナリオテンプレートの違い

通常セーブとシナリオテンプレートは同一のファイルフォーマットを使用する。主な違いは以下のとおり。

| 項目                          | 通常セーブ            | シナリオテンプレート                                                       |
| --------------------------- | ---------------- | ---------------------------------------------------------------- |
| 保存先                         | ユーザーフォルダの `saves/` | 自作はユーザーフォルダの `scenarios/`、コミュニティは Steam Workshop の購読フォルダ、DLC はインストール先の `dlc/<pack_id>/`（[シナリオ制作と配布](シナリオ制作と配布.md#保存元と置き場)） |
| ロード後の上書き保存の先（`GET /api/v1/sessions` の `current_save_id`） | セーブID | プレイは新しく採番したID（まだ保存していない都市として扱い、元のシナリオを上書きしない）。「都市を編集」は自作シナリオのID（`local~<id>`）で、上書き保存はそのシナリオへ書く |

進行状態を表すフラグ `city.city_hall_placed`（市庁舎配置＝都市創設済みかどうか。保存対象）は、通常セーブ・シナリオテンプレートともに保存時の値をそのまま復元する。シナリオをプレイとして始めるときも、テンプレート作成モードで開くときも同じで、市庁舎の無いシナリオ（地形だけのシナリオなど）は未創設のまま始まる。

なおゲームバランスパラメータ（シミュレーション日数など）は都市創設（市庁舎配置）の前まで変更でき、創設後はロックされる（テンプレート作成モードは常に変更可能）。

## 暗号化されたファイル

DLC由来の都市（`required_packs` が空でない都市）は、通常保存・別名保存・シナリオ保存・自動保存・終了時の緊急保存のどの経路でも、暗号化した形式で保存される。中身は平文の `.cg` と同じ ZIP で、それを必要パックの鍵で暗号化している。

- ファイルの先頭には平文のヘッダーがあり、一覧用のメタデータ（`metadata.json` の一覧項目）とサムネイル画像を持つ。そのため鍵が無くても、一覧APIとサムネイルAPIは暗号化されたファイルを表示できる。
- 本体（都市のデータ）は、必要パックをすべて所有しているときだけ開ける。パックの鍵はSteam認証の結果として、そのパックを所有しているユーザーにだけ届く（[コンポーネント連携](コンポーネント連携.md#steam認証)）。
- ヘッダーは暗号化の検証対象に含まれるので、必要パックや一覧用メタデータを書き換えたファイルは開けなくなる。チャンクの並べ替え・切り詰めも検出する。
- 平文の `.cg` なのに `metadata.json` が必要パックを名乗るファイルは、改ざんとして `SCENARIO_ENCRYPTION_INVALID` で拒否する（暗号化を外して配るのを防ぐため）。
- 紹介情報・画像の更新は暗号化されたまま行われる。

一覧用の `saves_metadata.json` は再生成可能なキャッシュであり、ロード時の判定には使わない。ここで必要パックや出自を書き換えても、DLCの所有制限は外れない。ロードとシナリオへの書き出しは `.cg` 本体の情報を使う。

## 出自

都市は、どのシナリオから始まったかを `metadata.json` の2項目に記録する。ロードでこの値を読み、以後の保存に引き継ぐ。ユーザー操作で出自を消す経路は無い。出自は読み込んだ都市に属するので、セッションを終える（`DELETE /api/v1/sessions`）か別の都市を始めると、次の都市には持ち越さない。

| 項目 | 内容 |
| --- | --- |
| `required_packs` | 都市を開くのに必要な追加パックのID（昇順・重複なし）。DLCのシナリオから始めた都市に付き、その都市から作ったシナリオにも付いて回る |
| `derived_from` | 元になったシナリオ `{"origin", "scenario_id", "content_revision", "official"}`。シナリオから始めていない都市と、元シナリオを持たない原本シナリオでは `null` |

`derived_from` は次の規則で決まる。有効な公式署名があるシナリオから始めた都市はそのシナリオ自身を記録する（`official: true`）。署名が無ければ、ファイルに記録済みの出自を引き継ぐ。どちらも無ければ、自作・チュートリアルを含むすべてのシナリオで自身を記録する（`official: false`）。通常保存・別名保存・緊急保存・派生シナリオへの保存でも、この記録を引き継ぐ。平文のファイルの `derived_from` は書き換えを検出できないので、公式の進行などの判定の根拠には使わない。

既存のシナリオへの上書き（地形・紹介情報の編集、「都市を編集」で開いたシナリオの上書き保存）は、そのシナリオの出自を保つ。標高マップから新しく作るシナリオは元シナリオがないため `null` で保存し、編集してもその値のまま。そのシナリオからゲームを始めた都市には、開始元のシナリオを記録する。

出自とは別に、都市は今回始めたシナリオのID（`scenario_id`）とクリア済みかどうか（`scenario_cleared`）を `city.json` に持つ。`derived_from` は派生元を辿った元のシナリオ、`scenario_id` は今回の開始元であり、派生シナリオから始めたときは異なる。シナリオ・チュートリアルから始めるたびに、`scenario_id` を記録し直し、`scenario_cleared` を未達成に戻す。クリアの定義と、都市と独立したプレイヤーの記録は[達成クエスト](../economics/24_達成クエスト.md)の24.12節を参照する。

## 公式署名

公式シナリオは ZIP メンバー `official.json` に公式署名を持つ。署名は `official.json` 以外の全メンバーの展開後のハッシュを並べたものに対する開発者の署名で、シナリオID・版・（DLCなら）パックIDも署名に含む。メンバーを1つでも足す・消す・変えると無効になる。

暗号化されたファイルでは、平文のヘッダーの一覧用メタデータとサムネイルが、中身の `metadata.json`・`thumbnail.png` と一致することも有効の条件にする。ヘッダーは署名の対象外なので、署名済みの中身を偽の紹介文や画像で包み直したファイルを「公式」と表示させないためである。

- 有効な署名を持つファイルは、保存元にかかわらず一覧で `official: true` になる。
- 置き場が `dlc` のファイルは、有効な署名があり、署名のパックIDが必要パックに含まれるときだけ読み込める。
- プレイヤーの保存（`save_game` のすべての経路）は `official.json` を書かない。公式シナリオから始めた都市や、それをシナリオとして保存したものは公式にならない。

## 地形

都市の地形はすべて `.cg` に入る。ゲームは標高マップを同梱せず、地形はセーブ・シナリオの中身からだけ戻す。

- **近景・遠景**（`near_map.npy`・`far_map.npy`）は都市の範囲の初期地形。
- **背景地形**（`background.npy`・`background.json`）は都市の外の50m格子の標高と遠景用海岸線（[地形形状](../geometries/D_地形形状.md#都市外の背景地形)）。
- **編集セル**（`dynamic/cell_{id}.npz`）は、道路や造成で地形を書き換えたセル（既定は500m四方・1m格子）の標高。近景から作る初期標高とビット単位で違う格子点だけを、差分として持つ。

| 編集セルのキー | 内容 |
|---|---|
| `edited` | 格子点ごとの「初期標高と違う」フラグを行優先に並べ、`np.packbits` で詰めた uint8 配列 |
| `values` | `edited` が立つ格子点の float32 標高を行優先に並べたもの |
| `version` | セルの版。地形を書き換えるたびに1増える |

書き換えた格子点は値そのものを持つので、編集した標高の精度は落ちない。書き換えていない格子点は、ロード後に同じ近景から同じ計算で作り直す。全格子を float32 で持つと1セル約0.8MBになるが、差分なら数十分の一で済む。

## 海岸線と埋立地

海岸線・湖・川（`City.terrains` の `coastline`・`water_surfaces`・`rivers`）と、埋立地（`City.reclaimed_lands` と次に採番するID `City.reclaimed_land_next_id`）は `city.json` に保存される。

- **海岸線はロードで作り直さない。** 海岸線を地形から抽出するのは新規都市の作成時だけで、以後は埋立の完了で埋立地の範囲が足されて広がる。広がった海岸線は初期地形（`terrain/near_map.npy`）からは再現できないため、セーブに入っている値が正で、ロードではそのまま戻す。
- **埋立地は範囲・ID・版だけを保存する**（`{reclaimed_land_id, polygon, version}` の列。[地形形状](../geometries/D_地形形状.md) §D.17.1）。岸壁区間・帯・壁・天端の高さは保存せず、ロード後も現在の海岸線と地形から求める。
- 造成（整地・埋立）で書き換えた地形は、ほかの地形の編集と同じく編集セルの標高（`terrain/dynamic/cell_{id}.npz`）として保存される。工事中の造成は通常の建物と同じく経済主体と区画として保存され、ロード後も工事を続ける。

## 追跡中の市民

[市民の追跡](市民の追跡.md)の追跡リストは、市民IDの並び `City.tracked_citizen_ids`(追加した順)として `city.json` に保存される。市民IDは削除後も再利用されないので、亡くなった市民のIDが別人を指すことはない(一覧に出さず、次に一覧を書き換えるときに外す)。プレイヤー個人の状態なので、シナリオとして保存するときは空にする。

## 保存対象外のプロパティ

再計算可能なキャッシュデータは保存対象外とし、ロード後のシミュレーションフェーズで自動的に再計算される。除外定義は `assets/save_exclusions.yaml` に記載されており、主に以下が対象。

- 経路探索キャッシュ（`global_route`, `automobile_local_route`, `pedestrian_local_route` 等）
- ヒートマップ（`noise_heatmap`, `air_pollution_heatmap`, `crime_heatmap`）

## 互換性とシナリオの配布

APIの一覧には `compatibility` を付ける。本体の版が不明・不正、実行コアより新しい、MAJORが異なる場合は読み込まない。バランス変更の確認は最終実行版を基準とする。シナリオの保存元・紹介情報の入力・投稿は[シナリオ制作と配布](シナリオ制作と配布.md)を参照する。
