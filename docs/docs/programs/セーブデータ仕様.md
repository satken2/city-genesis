# セーブデータ仕様

## セーブファイルの形式

セーブデータは拡張子 `.cg` の ZIP ファイルとして保存される。ZIPの圧縮レベルは6（deflate）。

## ZIP 内部構造

| ファイル名 | 内容 |
|---|---|
| `soa.npz` | 全テーブルのSoA配列（numpy savez_compressed） |
| `scalars.npz` | SoAではない通常スカラー値を列指向numpy配列として格納 |
| `variable/{table}.msgpack.gz` | 可変長プロパティ（polygon, list, dict等）をmsgpack+gzipで圧縮 |
| `city.json` | Cityシングルトン（都市名、税率、人口統計等） |
| `params.json` | Parametersシングルトン（`GENERAL_PARAMS`, `RATIO_PARAMS`, `DEFAULT_VALUES`, `TIME_VARYING_CONSTANTS`） |
| `metadata.json` | メタデータ（一覧表示用の都市名、人口、エポック数等） |
| `terrain/settings.json` | Terrainシングルトンの設定値（マップサイズ、グリッド間隔等） |
| `terrain/far_map.npy` | 遠景用標高マップ（numpy float16） |
| `terrain/near_map.npy` | 近景用標高マップ（numpy float16） |
| `terrain/dynamic/cell_{id}.npz` | 各セルの超近景標高マップ（numpy int16、圧縮） |

## セーブデータ一覧メタデータ（saves_metadata.json）

セーブデータ一覧画面を素早く表示するため、セーブファイルとは別に `saves_metadata.json` を保存ディレクトリに配置する。このファイルには全セーブのサマリーが記録される。

```json
{
  "{save_id}": {
    "id": "...",
    "city_name": "...",
    "population": 12345,
    "current_date": 20250601,
    "epoch": 5,
    "simulation_days": 90,
    "saved_at": "2025-06-01T12:00:00",
    "language": "ja"
  }
}
```

## 通常セーブとシナリオテンプレートの違い

通常セーブとシナリオテンプレートは同一のファイルフォーマットを使用する。違いは以下の2点のみ。

| 項目 | 通常セーブ | シナリオテンプレート |
|------|----------|------------------|
| 保存先 | `AppData/saves/` | `AppData/templates/`（ユーザー作成）または `<インストール先>/city/template/`（組み込み） |
| ロード後の `gd3.current_save_id` | セーブIDをそのまま設定 | `init_game()` で採番したUUIDを維持（元テンプレートを上書きしない新規セーブ扱い） |

進行状態を表すフラグ `city.city_hall_placed`（市庁舎配置＝都市創設済みかどうか。保存対象）は、通常セーブ・シナリオテンプレートともに保存時の値をそのまま復元する。ロード側は進行フラグに一切手を触れない。シナリオを「プレイ」として開始する場合の創設状態の上書きは、`sessions` コントローラがロード後に別途 `city_hall_placed=True` を強制することで行う。

なおゲームバランスパラメータ（シミュレーション日数など）は都市創設（市庁舎配置）の前まで変更でき、創設後はロックされる（テンプレート作成モードは常に変更可能）。

## 保存対象外のプロパティ

再計算可能なキャッシュデータは保存対象外とし、ロード後のシミュレーションフェーズで自動的に再計算される。除外定義は `assets/save_exclusions.yaml` に記載されており、主に以下が対象。

- 経路探索キャッシュ（`global_route`, `automobile_local_route`, `pedestrian_local_route` 等）
- ヒートマップ（`noise_heatmap`, `air_pollution_heatmap`, `crime_heatmap`）
