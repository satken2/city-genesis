# セーブデータ仕様

都市の保存単位と、一覧・保存・読み込みの考え方を説明する。版情報と読み込めるかの判定は[バージョニングと互換性](バージョニングと互換性.md)、シナリオの保存元と制作の流れは[シナリオ制作と配布](シナリオ制作と配布.md)、保存先のフォルダは[ファイル配置](ファイル配置.md)を参照する。

## 保存ファイル

都市は丸ごと1つの `.cg` ファイルに保存し、通常セーブもシナリオも同じ形式である。ファイルを読み書きするのはコアだけで、UIとグラフィックはコアに都市を読み込ませてからAPIで取得する。地形も都市の一部としてすべてファイルに入り(初期地形・都市外の背景地形・書き換えた標高・海岸線・水面・川・埋立地)、ロードではファイルの中身だけから戻す([地形形状](../geometries/D_地形形状.md))。経路探索の結果やヒートマップのように再計算できる値は保存せず、コアが計算し直す(ヒートマップはロードの後、エポックを実行するまで空である)。

## 通常セーブとシナリオ

通常セーブはプレイ中の都市の続きを、シナリオは新しいゲームの開始点を保存したものである。

上書き保存の先(`current_save_id`)は、通常セーブをロードすればそのセーブで、シナリオから始めれば元のシナリオではなく、まだ保存していない新しいセーブである。シナリオ管理の「都市を編集」で開いたときだけシナリオが保存先になり、`current_save_is_scenario` が真になる。シナリオは保存した状態のまま始まるので、市庁舎の無いシナリオは未創設で始まる。

## 一覧の項目

`GET /api/v1/saves`・`GET /api/v1/scenarios` の一覧は、ファイルに入っている一覧用の情報に、コアがその場で判定した読み込み可否と所有状況を加えたものである。読み込めないファイルも理由付きで残り、`compatibility.code` には最初に当たった理由が1つだけ入る。ロードも同じ判定を都市の初期化より前に行うので、読み込めないファイルを開こうとしても現在の都市は変わらない。

読み違えやすい項目として、`language` は都市内の固有名詞の言語で UI の表示言語とは独立しており、`saved_at` は保存した実時間でゲーム内の日付(`current_date`)とは別である。`simulation_days` は通常セーブでは確定したエポック日数、シナリオでは開始時の初期値を表す。`pack_status` の `unverified` は、製品版で Steam 認証の結果がまだ無く所有を確かめられない状態である。

## 保存に入る画像

保存の直前に、UIがグラフィックへ3Dビューの撮影を頼み(IPCの `camera:capture_thumbnail`)、グラフィックが撮った画像をコアへ預ける(`PUT /api/v1/sessions/thumbnail`)。預けた画像は次の1回の保存に入り、撮れなかった保存には前の画像が引き継がれる。作者がシナリオの画像を選んだときは、撮影の代わりにその画像を預ける。

## 暗号化と出自

DLCのシナリオから始めた都市は、必要パック(`required_packs`)を出自として記録し、以後のすべての保存へ引き継ぐ。ユーザーの操作で消す経路は無い。必要パックのある都市は、どの保存の経路でも暗号化して保存される(一覧の `encrypted`)。一覧用の情報と画像は鍵なしで読めるので一覧には出るが、都市を開けるのは必要パックをすべて所有しているときだけである。パックの鍵は Steam 認証で所有者にだけ届く([コンポーネント連携](コンポーネント連携.md))。必要パックや一覧用の情報を書き換えたファイルと、暗号化を外して必要パックを名乗るファイルは開けない(`SCENARIO_ENCRYPTION_INVALID`)。
