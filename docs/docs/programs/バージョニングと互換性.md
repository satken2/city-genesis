# バージョニングと互換性

コアとフロントの版番号の規則と、プログラムどうし・セーブとの互換性の保証を定める。セーブの中身と一覧の項目は[セーブデータ仕様](セーブデータ仕様.md)を参照する。

## 版を表す番号

| 番号 | 識別するもの | 決めること |
| --- | --- | --- |
| `core_version` | コアの配布物(実行プログラムと、それが使うマスターデータ・標準パラメータの組) | セーブを読み込めるか、ゲームルール・バランスが変わったか |
| `frontend_version` | Tauri と Unity を合わせたフロントの配布物 | コアと接続できるか |
| `ipc_contract_version` | Tauri と Unity の間の IPC の契約(正の整数) | Tauri と Unity が接続できるか |

`core_version` と `frontend_version` は `MAJOR.MINOR.PATCH` の形で互いに独立して進み、3つの整数を順に比べる(文字列として比べない)。製品の基準版は双方 `1.0.0` である。モックかどうか、エポックを実行できるかは、版番号ではなく版情報の `build_kind`・`simulation_available` で判断する。

コアの番号は、上がった部分で保証が決まる。

| 上がった部分 | 保証されること |
| --- | --- |
| PATCH | セーブの互換性を保ち、ゲームルール・バランスも変わらない |
| MINOR | セーブの互換性を保つ。ゲームルール・バランスは変わり得る |
| MAJOR | 前の MAJOR のセーブは通常のロードでは引き継げない |

フロントの番号は、修正で PATCH、機能の追加で MINOR、操作体系やフロントが保存する設定との互換を保てない変更とコアの MAJOR への追従で MAJOR を上げる。UI だけ・描画だけの変更でも、配布する組には同じ番号を付ける。正は公開リポジトリ直下の `version.json` で、変えたら `tauri/` で `npm run sync:version` を実行し、Tauri の配布設定と Unity の製品バージョンへ写す(`FrontendVersion.cs` は生成物)。コアの版はフロントに焼き込まず、実行時にコアの版情報の API から取得する。

## プログラム間の互換性

起動できるのは、フロントの MAJOR がコアの MAJOR 以上で、Tauri と Unity の `ipc_contract_version` が一致する組だけである。版を取得できない・読めないときは、互換であると推測しない。IPC の契約はイベントの意味・ペイロードの型・共有する ID の意味を含み、相手の実装を変えないと動かなくなる変更で番号を上げる。IPC Envelope の `version` はこの判定に使わない。

Tauri(Rust 側)と Unity は、起動時にそれぞれコアの版を取得して照合し、フロントの方が古ければ、待っても版は変わらないのでプログラム全体を終了する。コアはアプリの実行中に差し替わらないので、取得した版は終了まで使い回す。Tauri と Unity は起動の通知(`system:graphic_ready`・`system:ready`)で互いの版と契約番号を照合し、照合が済むまでゲーム用の IPC を扱わない。

## セーブとの互換性

読み込めるのは、ファイルを最後に保存したコアの版(`saved_core_version`)が実行中のコア以前で、MAJOR が同じセーブである。読み込めることは旧版と同じ結果になることを意味せず、ロードした都市は実行中のコアのルールとマスターで計算される。

その都市のエポックを最後に計算したコアの版(検証結果の `balance_core_version`)と実行中のコアの MAJOR・MINOR が違えば、ゲームルール・バランスが変わり得る(`balance_changed`)。このときロードにはプレイヤーの明示の承諾(`accept_balance_change`)が要る。保存した版ではなく最後に計算した版と比べるのは、ロードして保存しただけで確認が出なくなるのを防ぐためである。

保存したコアと違う版のコアで開くときは、元のファイルを変える前に、原本の複製をセーブフォルダの `backups/` に作る。旧ルールで遊び続けるには、この複製と、旧版のコア・フロントの組を使う。
