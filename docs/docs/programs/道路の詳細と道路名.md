# 道路の詳細と道路名

道路(名前付き道路)は、交差点で分かれた複数のパス(区間)を1本の道路としてまとめる名札である。概念・所属の規則・API の値の定義は[道路網](../economics/3_道路網.md)を参照する。このページは、Tauri と Unity が道路をどう見せ、どう編集し、互いにどう同期するかを扱う。

## 責務と変更の通知

道路の作成・改名・色の変更・所属の変更・削除は、すべて UI が道路の API(またはパスの API の `road_id`)で行う。Unity は道路を読んで描くだけで、所属を書き換えない。区間が0本になった道路はコアが削除する。

道路や所属を変えたウィンドウは、Tauri のグローバルイベント `roads:changed` で他のウィンドウに知らせ、Unity へ `world:refresh_roads` を送る。Unity のブルドーザでのパスの削除は UI を通らないので、削除したパスが道路の区間だったときは Unity が `world:roads_changed` を送り、Rust がそれを `roads:changed` として全ウィンドウへ流す。受け手はペイロードを見ずに取り直す。所属の変更ではパスの `version` が上がらないので、パスの `road_id` を表示する画面も `roads:changed` を受けて取り直す。

Unity は道路の一覧(`GET /api/v1/roads/`)を都市全体でまとめて取り、初回のロード・全体の再読み込み・`world:refresh_roads` で取り直す。一覧の `version` が変わらなければ3Dの道路名ラベルを作り直さない。一覧を周期的に取り直したり、IPC で周期的に送ったりはしない。

## 表示名

道路・区間の名前は空文字のことがあり、表示する側が翻訳済みの仮の名前(道路の番号など)を補う。道路名・インターチェンジ名・一般の区間の名前には自動で付く名前が無く、入っているのは作者やプレイヤーが付けた名前だけなので、シナリオを別の言語で始めても付け直さない([シナリオ制作と配布](シナリオ制作と配布.md))。名前の無い道路は、2D地図・3Dの道路名ラベルにも場所の検索にも出さない。番号だけのラベルは場所を示す役に立たず、地区名や施設名の置き場を奪うためである。

## 道路詳細と3Dの強調

道路詳細(`road_detail`)は道路ごとに開け、複数の道路を同時に開ける。`GET /api/v1/roads/{id}` を、`roads:changed` とエポックの終了で取り直し、404 になったら削除済みとして表示する。なお、パスの車種別の交通量(`path_traffic`)は保存型の上限(65,504)で頭打ちになるので、その値は「それ以上」を表す下限として扱う。

開いている間は、IPC の `world:set_road_focus` で道路の区間を3Dの強調帯として示す。3Dの強調帯は1本だけなので、複数の道路詳細を開いているときはフォーカスを得たパネルが自分の道路を送り直し、内容が変わらなければ送らない。閉じたときの強調の消去と区間編集の打ち切りは、Rust が閉じた道路の `road_id` を付けて行う。

## 区間編集モード

道路詳細から、3Dビューで区間をクリックして所属を付け外しするモード(`STATE_EDIT_ROAD_MEMBERS`)に入れる。Unity はクリックを `edit_road:toggle_path` で知らせるだけで、所属は UI が `POST /api/v1/roads/{id}/members` で変え、結果の全集合を `edit_road:set_members` で送り返す。Unity の帯はその応答を受けてから変わる。

モードは UI の知らない理由(Esc・他のモードへの切り替え・セッションのリセットなど)でも終わるので、Unity は理由を問わずモードを抜けるたびに `edit_road:ended` を1回送り、パネルはそれを受けて編集中の表示を片付ける。開始時にパネルが付けた `session_id` を Unity がそのまま返し、パネルは遅れて届いた前回の終了で新しい編集を落とさないよう照合する。パネルからの終了は `STATE_NORMAL` ではなく `edit_road:cancel` で送り、Unity が UI の知らないうちに別のモードへ移っていても、それを打ち切らない。Unity の区間編集モードは1つだけなので、あるパネルが編集を始めたら他のパネルは自分の編集中の状態を捨てる。

各イベントとペイロードの定義は Tauri の送信関数(`tauri/src/utils/ipc.ts`)のコメントにある。IPC の仕組みは [IPC連携の整理](IPC連携の整理.md) を参照する。
