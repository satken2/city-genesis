# 道路の詳細と道路名

道路（名前付き道路）は、交差点で分かれた複数のパス（区間）を1本の道路としてまとめる名札である。概念・所属の規則・API・応答の値の定義は[道路網の「道路(名前付き道路)」](../economics/3_道路網.md#35-道路名前付き道路)を参照。このページは、それを見せる・編集するための Tauri と Unity の実装（道路詳細パネル、区間編集モード、パス詳細と建設パネルでの所属の選択、3Dの強調帯と道路名ラベル、2D都市マップ）と、その間のIPCを扱う。

## 表示名

道路・区間の名前は空文字のことがあり、表示側が翻訳済みの仮の名前を補う。道路名・インターチェンジ名・一般の区間の名前には自動で付ける名前が無く、入っているのは作者やプレイヤーが付けた名前だけなので、シナリオを別の言語で始めても付け直さずに残す([シナリオ制作と配布](シナリオ制作と配布.md#ゲーム開始時の言語と開始設定))。

- 道路: 名前が空なら `road.unnamed`（ja「道路 #{{id}}」）。`roadDisplayName` が行う。Unity のツールチップは多言語リソースを持たないため日本語固定の「道路 #id」を使う。
- 区間（パス）: `name` が空で道路に属していれば `path.titleInRoad`（ja「{{road}}(区間 #{{id}})」）、属していなければ `path.titleWithId`（ja「パス #{{id}}」）。`name` が空でなければそのまま出す。パス詳細のヘッダと、予算ウィンドウ（`CityBudgetWindow`）の道路の行はこの規則に従う。予算の対象一覧（`GET /api/v1/city/budgets/agents`）はパスの `name` を空文字のまま返し、所属道路の `road_id` と `road_name` を添えるので、予算ウィンドウはそれを使って補う（道路名が空なら `road.unnamed`）。
- 名前の無い道路は、2D地図の道路名ラベル・3Dの道路名ラベル・場所検索のどれにも出さない（番号だけのラベルは場所を示す役に立たず、地区名や施設名の置き場を奪うため）。

## 道路詳細パネル

`window_type` は `road_detail`（`single_per_entity`・右パネル。`entity.type` は `road`、`entity.id` は道路ID）。パス詳細から開くことがあるのでミューテックスは付けない。道路ごとに1枚ずつ、複数の道路の詳細を同時に開ける。見た目は路線詳細・パス詳細と同じ右パネルの語彙（下線式タブ・セクション・小型ボタン）に揃え、ヘッダ（アイコンは延長の長い方の種別、名前の横に「4車線道路 ほか」のような車線構成の要約）の直下に道路色の帯を敷く。

- 取得は `GET /api/v1/roads/{id}`。Tauri のグローバルイベント `roads:changed` と、エポック実行の終了（`epoch:executing` の `executing: false`）で取り直す。
- 404 になったら（区間が0本になって道路が消えた、または削除された）「この道路は削除されました」を表示し、区間編集モード中なら終える。
- 開いている間は3Dビューに道路の強調帯を出す（`world:set_road_focus`）。道路・色・区間の集合が変わったときだけ送り直し、同じ内容は送らない。3Dの強調帯は1本だけなので、複数の道路詳細を開いているときはフォーカスを得たパネルが自分の道路を送り直す。
- 閉じられたウィンドウは非表示で残り、リスナーも生きている。非表示のパネルは強調帯や Unity のステートを操作しない（表示中の別のパネルの強調や編集を壊すため）。アンマウント時にも何も送らない。閉じたときの後始末は Rust が行う（[パネルを閉じたときの後始末](#パネルを閉じたときの後始末)）。

### タブ

| タブ（id） | 内容 |
|---|---|
| 基本情報（`basic`） | 延長・平均交通量・最大混雑度・渋滞損失のタイルと、区間数・経由地区・車線構成・制限速度の範囲・所要時間（混雑込み／自由走行）・旅行速度・走行台キロ・混雑区間の延長・平均耐久度と低耐久の区間数・事故のあった区間・計画中・工事中の延長・この道路を走る路線の表。最大混雑度のタイルはその区間のパス詳細を開く。所要時間が算出できないときは、計画中・工事中の区間を含む場合と、稼働していない・通れない区間を含む場合とで理由を分けて示す |
| 全体図（`map`） | 都市マップの部品 `CityMapCanvas` を埋め込み、区間を道路色の帯で強調し（`focusPathIds`・`focusColor`）、他の道路・線路を薄くする（`focusDimOthers`）。延長の候補は `previewPathIds` で同じ色の破線にする。地図のベクターは表示範囲で取得されるので、表示範囲は道路の `bbox`（候補があれば候補の範囲も合わせたもの）に余白を足して合わせる |
| 路線図（`diagram`） | 縦型のストリップマップ（[路線図](#路線図ストリップマップ)） |
| 交通量（`traffic`） | キロ程を横軸にした指標のグラフ（[交通量グラフ](#交通量グラフ)） |
| 設定（`settings`） | 道路名（空欄で未命名）、道路の色（`ROAD_COLOR_PALETTE` の見本から選ぶ）、起点と終点の入れ替え、区間の編集（[区間編集モード](#区間編集モード)）、端から直進方向への延長、道路の削除（2段階の確認。区間は名もなき道として残る） |

変更に成功したら `notifyRoadsChanged(roadId)` を呼ぶ（[変更の通知](#変更の通知)）。

### 直進方向への延長の提案

設定タブの「端から直進方向へ延長」は `GET /api/v1/roads/trace?road_id=` を呼び、返った候補（すでに道路に属する区間を除く）をパネル上部の「直進方向に n区間 を追加できます」の帯と、全体図の破線、3Dに示す。3Dでは、区間編集モード外なら候補を含めた集合で `world:set_road_focus` を送り、区間編集モード中なら `edit_road:set_members` の `preview_path_ids` で送る。「追加する」で `POST /api/v1/roads/{id}/members` の `add` に候補を渡す。

パス詳細の「所属道路」で新しい道路を作ると、道路詳細が `params.extra = {offerTrace: true, seedPathId}` 付きで開く。このときは設定タブを開き、`trace?path_id={seedPathId}&road_id={id}` の候補を「直進方向の n区間 も同じ道路にしますか?」として一度だけ提案する。

trace の応答は候補の区間の中心線を囲む範囲 `bbox`（[minx, minz, maxx, maxz]。候補が無ければ `null`）を持ち、全体図は道路の `bbox` とこれを合わせた範囲を表示範囲にする（`resolveTraceBbox`）。応答に `bbox` のキーが無いとき（`bbox` を返さないバックエンドのとき）に限り、候補の区間を1本ずつ取得して端点の範囲で近似する。

### 路線図（ストリップマップ）

`RoadStripMap` は道路を起点から終点へ上から下に1本の線として描くSVGで、地理的な曲がりは表さずキロ程だけを縦軸にとる。

- 左: キロ程の目盛りと、制限速度が変わる所の小さな標識。
- 中央: 区間の線。太さは車線数、色は混雑度（50%未満=緑、50〜80%=黄、80%以上=赤。パス詳細・統計ウィンドウの道路の混雑率と同じ閾値）。稼働していない区間（計画中・工事中など）は灰色の破線、容量の無い区間は灰色。並行区間（上下線）は基準線の右に並べ、一方通行には進む向きの矢印を付ける。トンネル・橋は線の両脇の縁取りで示す。
- 中央右: 起点・終点、交差する道路（名前付きなら道路色で、クリックでその道路の道路詳細を開く。無名の街路・高速道路は「名前のない街路 #path_id」など、線路は踏切）、IC/JCT（地図・3D・交差点詳細と同じ表示名。未命名は種別の略号とID）、停留所（クリックで路線詳細）、区間名（橋・トンネル）、塊の途切れ（「未接続 約○m」）。
- 枝線（`branch`）は、区間の `attach_km`（基準線に取り付くキロ程。道路の全長の範囲に収める）の位置に、名前・交通量・混雑度のラベル行として積む。`attach_km` が無ければ基準線へ投影した範囲の起点側の端に置く。同じ位置の枝はパスIDの順に並べる。行ごとに接続線と、区間長に比例した短い横棒を描く。基準線からほぼ直角に出る枝は投影範囲がほぼ0なので、縦の線で描くと点に潰れて見分けられないため。
- 右: 区間ごとの交通量の棒と「台/日・混雑度%」。並行区間も自身の行（▲/▼）を持ち、基準線の区間と同じ位置では縦に積む。
- 縦方向はキロ程に比例させつつ、隣り合う目印どうしが文字の重ならない最低限の間隔を保つよう区分線形に引き伸ばす。塊の間の途切れは実距離によらず一定の長さに縮める。目盛りの間隔は一様でなくなるが、目盛りの数値は正しいキロ程を指す。
- 区間をクリックするとその区間のパス詳細（`path_detail`）を開く。

### 交通量グラフ

`RoadTrafficProfile`（recharts）は横軸をキロ程にとり、基準線と並行区間の値を区間ごとの階段状グラフで描く。指標は切り替え式で、交通量（車種別の積み上げと容量の線。上下線が分かれている道路では方向別の合計の線を重ねる）、混雑度（%。1で頭打ちにしない。50/80/100%の参照線を引き、軸は参照線まで必ず広げる）、旅行速度（混雑込み＝区間長÷所要時間と、自由走行の破線）、騒音、耐久度、路上駐車（駐車台数と容量の線）。上下線が分かれている区間の下り・上りは別系列（双方向の区間は「双方向」の系列）。稼働していない区間は交通が無いので耐久度以外の値を出さず、塊の途切れで線が切れる。ツールチップに区間名・ID・値を出し、クリックでその位置の区間のパス詳細を開く。recharts は CSS 変数を解決できないので色は直値で持つ。

## 区間編集モード

道路詳細の設定タブの「区間を編集」で始まる、3Dビューで区間をクリックして所属を付け外しするモード。UI と Unity の責務はパスの結合相手の選択と同じで、**Unity はクリックを知らせるだけ、所属の変更は UI が API で行い、結果の全集合を Unity へ送り返す**。

1. 開始: パネルが `world:change_state`（`STATE_EDIT_ROAD_MEMBERS`、params `{road_id, color, path_ids, session_id}`）を送る。`session_id` は開始のたびにパネルが採番する正の整数で、時刻から採り、直前の番号とは重ならないようにする（閉じて開き直した同じ道路のパネルは前回の番号を覚えていないため）。Unity は入力プリセット `ROAD_MEMBER_EDIT`（パスだけ `MODE_EDIT_ROAD_MEMBERS`、建物・区画・ノード・地形・地区は `MODE_NONE`）にし、表示は道路の敷設と同じ建設系の表示プリセット（計画中の区間も選べる）にする。所属区間を道路色の帯で示す。パネルを操作し続けられるよう、このステートでは Unity のウィンドウを前面に出さない。ヒントバーには道路名を含めた操作の案内を出す。同時に他の道路詳細パネルへ Tauri のイベント `road:member_edit_started`（`{label}`）を送り、それを受けたパネルは自分の編集中の状態を捨てる（Unity の区間編集モードは1つだけで、`edit_road:toggle_path` は全ウィンドウに届くため）。
2. クリック: 街路・高速道路の区間にホバーすると白い線で強調し、操作の案内（「クリックでこの道路に追加」「クリックでこの道路から外す」「クリックでこの道路へ付け替え(現在: ○○)」、Shift+クリックの案内）をツールチップに出す。それ以外の種別はツールチップで拒否し、強調もしない。クリックすると `edit_road:toggle_path`（`{path_id, path_name, path_type, shift}`）を UI へ送る。区間以外のクリックとドラッグ編集は無効。
3. 付け外し: パネルは所属していれば `remove`、していなければ `add` で `POST /api/v1/roads/{id}/members` を呼ぶ。`shift=true` なら `trace?path_id=&road_id=` の結果（クリックした区間を含む）をまとめて `add` する。別の道路の区間は確認なしで付け替え、「○○から付け替えました」をパネルに一行出す。連打で順序が前後しないよう1件ずつ順に処理する。成功したら `edit_road:set_members`（`{road_id, path_ids, preview_path_ids}`。差分ではなく全集合）を送り、Unity はそれを受けてから帯を変える（クリック直後には変わらない）。失敗したら道路を取り直す。
4. 終了: パネルの「完了」は `edit_road:cancel`（`{road_id}`）を送る。`STATE_NORMAL` を送らないのは、UI の知らないうちに Unity が別のモード（道路の敷設など）へ移っていた場合にそれを打ち切らないため。Unity はその道路の区間編集モード中のときだけ終了して通常モードへ戻す。モードは `STATE_NORMAL`・他のステートへの直接の遷移・Unity にフォーカスがあるときの Esc・セッションのリセット・別の道路（または同じ道路の別の `session_id`）での開始でも終わる。**理由を問わず、モードを抜けるたびに Unity は `edit_road:ended`（`{road_id, session_id}`）を1回送り**、パネルは自分の道路の今回の編集なら何も送り返さずに編集中の表示と案内を片付ける。`session_id` は、終わったモードの開始時に受け取った値を Unity が型を変えずに返したもので（開始時に無ければ省く）、パネルは開始時の値と一致するときだけ受け入れる（遅れて届いた前回の終了で新しい編集を落とさないため）。`session_id` が含まれていない・正の整数でないときは道路IDだけで判断する。
5. 道路の消滅: 付け外しで区間が0本になって道路が削除されたら（`{road: null, deleted: true}`）、パネルはモードを終えて削除済みの表示にする。

モードが終わっても、道路詳細の強調帯（`world:set_road_focus`）は残る。区間編集中は、古いままの強調の集合で外した区間が残って見えないよう、強調帯を描かずに区間編集の帯だけを描く。

## パス詳細と建設パネルでの所属

- **パス詳細**: 街路・高速道路のパスに「所属道路」行（`RoadMembershipRow`）を出す。選択肢は「なし(名もなき道)」・既存の道路（表示名の順）・「＋ 新しい道路…」。既存の道路を選ぶと `PATCH /api/v1/paths/{id}` の `road_id` で保存し、「なし」は `road_id: null`。新しい道路は名前（空欄なら番号で表示、`ROAD_NAME_MAX_LENGTH` まで）を入れて `POST /api/v1/roads/`（`path_ids` はこのパス1本）で作成し、続けて道路詳細を延長の提案付きで開く。所属しているときは「道路の詳細」リンクを出す。`roads:changed` を受けるとパスの `road_id` だけを取り直す（所属の変更ではパスの `version` が変わらないため）。
- **パス建設パネル**: 街路・高速道路の新規敷設のときだけ「所属道路」を選べる（既存パスの形状編集では所属を変えない）。敷設中の形状の始点・終点が1m格子で変わったら、少し待ってから `POST /api/v1/roads/extension-candidates` に問い合わせ、ユーザーがまだ選択を触っていなければ最初の候補を自動で選んで「「○○」を延長します」と示す（選び直せる）。既存の道路は確定送信の各パスに `road_id` として載せ、新しい道路は確定で作られたパスIDの一覧で `POST /api/v1/roads/` を呼ぶ（区間の無い道路は作れないため、作成は敷設の後になる）。確定のたびに選択は提案からやり直す。線路・インフラの建設パネルには出さない。

## 3Dの強調帯と道路名ラベル

### 道路一覧の取得

`RoadManager` は `GET /api/v1/roads/` を都市全体まとめて取得して保持する。セルロードの初回と全体の再読み込み（エポック完了・編集の確定）、UI からの `world:refresh_roads` で取り直し、応答の `version` が前回と同じならラベルを作り直さない。取得中に再要求が来たら、完了後に1回だけ取り直す。セッションの切り替え・全体の再読み込み・ゲーム終了で破棄し、切り替え前の要求の応答は捨てる。道路の一覧を周期的に取り直したり、IPC で周期的に送ったりはしない（MMFの容量制限）。

### 道路名ラベル

名前の付いた道路の `label_points` ごとに、画面空間のラベル（ScreenSpaceOverlay の Canvas。地区名ラベルより手前、インターチェンジのラベルより奥）を出す。

- 文字は道路色を白へ寄せた色に黒い縁取り。道路の向きをスクリーンへ投影した角度に回転させ、逆さにならないよう (-90°, 90°] に収める。
- カメラ背面・画面外・一定距離より遠いものは出さず、カメラに近い順に置いて、先に置いたラベルと回転込みの外接矩形が重なるものは隠す。同時に出す数にも上限がある。インターチェンジのラベルとの重なりは避けない。
- 高さは近くの所属区間の描画中心線から拾い、区間が未ロードなら地表の高さを使ってあとで取り直す。
- 表示条件はインターチェンジのラベルと同じ（世界表示中・ドライブ中でない・道路と地形の入力モードがともに通常・道路レイヤーが非表示でない）。編集モードでは隠すので、uGUI のラベルが道路編集のクリックを奪うことはない。当たり範囲は文字の大きさに詰める。
- クリックで `world:select_object`（`{window_type: "road_detail", entity: {type: "road", id: "<road_id>"}}`）を送り、UI が道路詳細を開く。

### 強調帯

`RoadFocusOverlay` は区間の中心線（トリムしない描画中心線）に沿った帯を、公共交通ハイライトと同じ `OverlayMeshRenderer` の ZTest Always で地形・建物の上に描く。画面上の幅はズームによらず一定で、暗い縁取りの上に色の帯を重ねる（公共交通の帯より手前）。

- **強調**: `world:set_road_focus` の区間を道路色で。送られるたびに全置換する。`world:clear_road_focus` で消す。`road_id` が付いていれば、強調中の道路がそれと同じときだけ消す（別の道路詳細パネルの強調を消さないため）。
- **区間編集**: 所属区間を道路色、`preview_path_ids` の候補を半透明の道路色で。ホバー中の区間は白い細線で、ホバーが変わってもホバー線だけを作り直す。
- 未ロードの区間は描かない。区間の形状の版とロード状態を定期的に比べ、区間のロードや形状の変化で作り直す。セッションのリセットで強調・区間編集ともに消す（パスIDの集合なので、別の都市では別の区間を指してしまうため）。
- 干渉の警告用の `world:highlight_objects` とは別の仕組みで、互いに影響しない。

## IPCイベント

MMF 上のイベント（[IPC連携の整理](IPC連携の整理.md)の一覧にも載せている）。UI→Unity は既存の `send_window_action` を使い、専用の Rust コマンドは持たない。Unity→UI の `edit_road:toggle_path`・`edit_road:ended` は Rust（`ipc.rs`）が同名のイベントとして全ウィンドウへ中継し、`world:roads_changed` は Tauri のグローバルイベント `roads:changed` として流す。

| イベント | 方向 | ペイロード・意味 |
|---|---|---|
| `world:set_road_focus` | UI → Unity | `{road_id, color, path_ids}`。道路詳細が開いている道路の区間を強調帯で示す（全置換） |
| `world:clear_road_focus` | UI → Unity | `{road_id?}`。強調を消す。`road_id` があれば強調中の道路と同じときだけ、無ければ無条件 |
| `world:refresh_roads` | UI → Unity | `{}`。道路一覧を取り直させる（`version` が同じならラベルは作り直さない） |
| `world:change_state`（`STATE_EDIT_ROAD_MEMBERS`） | UI → Unity | `{state, road_id, color, path_ids, session_id}`。区間編集モードの開始 |
| `edit_road:set_members` | UI → Unity | `{road_id, path_ids, preview_path_ids}`。区間編集モードの所属区間と候補の全集合。モード中でない・別の道路宛ては無視 |
| `edit_road:cancel` | UI → Unity | `{road_id}`。その道路の区間編集モード中なら終了して通常モードへ戻す。モード外・別の道路の編集中・`road_id` の無いものは無視 |
| `edit_road:toggle_path` | Unity → UI | `{path_id, path_name, path_type, shift}`。区間編集モードで街路・高速道路の区間がクリックされた。`shift` は Shift キーの押下 |
| `edit_road:ended` | Unity → UI | `{road_id, session_id?}`。区間編集モードが終わった（理由を問わず、抜けるたびに1回）。`session_id` は開始時の値をそのまま返したもの |
| `world:roads_changed` | Unity → UI | `{}`。ブルドーザで道路の区間を削除した（[変更の通知](#変更の通知)）。Rust が `roads:changed` として全ウィンドウへ流す |
| `world:select_object`（`road_detail`） | Unity → UI | `{window_type: "road_detail", entity: {type: "road", id}}`。3Dの道路名ラベルがクリックされた |

### パネルを閉じたときの後始末

ポップアップは閉じても破棄されず非表示になるだけで、React のアンマウント処理が走らない。そのため `road_detail` のウィンドウが閉じられると、Rust（`window.rs` の `close_window_by_label`）が閉じた道路の `road_id` を載せて `world:clear_road_focus` と `edit_road:cancel` を送り、閉じるパネル自身にだけ Tauri のイベント `road:panel_closing` を送る。パネルはこれを受けて編集中の表示・候補・ヒントバーの案内を片付ける。ヒントバーの案内は、他のパネルが出した案内を消さないよう、自分が出した文言と一致するときだけ消す。`road_detail` は `EDIT_MODE_WINDOW_TYPES` に入れない（パネルを閉じても道路の敷設など他の編集モードは終わらせない）。

## 変更の通知

道路・所属を変えたウィンドウは `notifyRoadsChanged(roadId?)` を呼ぶ。これは Tauri のグローバルイベント `roads:changed`（`{road_id?}`）を出し、Unity へ `world:refresh_roads` を送る。

- 受け手: 道路詳細（取り直し）、パス詳細（`road_id` の取り直し）、所属の選択肢（道路一覧の取り直し）、2D都市マップ（道路一覧とパスの取り直し）。
- 送り手: 道路詳細の各操作、パス詳細の所属の変更、パスの建設・編集の確定（種別や所属の選択を問わない）、パスの削除・撤去・造り替え・計画と着工の切り替え、パスの分割・結合の確定。パスの分割・結合・削除でも区間の集合や道路の存在が変わるため。
- Unity のブルドーザでのパスの削除は UI を通らない。削除したパスが道路の区間だったときは、Unity が削除の成功後に `world:roads_changed` を送り（続けて削除しても1通にまとめる）、Rust がそれを `roads:changed` としてペイロードのまま全ウィンドウへ流す。受け手はペイロードを見ずに取り直すので、UI の操作による変更通知と同じように扱われ、区間が0本になって消えた道路の道路詳細は削除済みを表示する。Unity は差分リロードで自分の道路一覧を取り直すので、この経路では `world:refresh_roads` を送らない。

## 2D都市マップ

詳細は[都市マップの検索と経路案内](都市マップの検索と経路案内.md#道路名と区間の強調)。

- 「幹線道路」レイヤーは、高速道路と、道路に属する区間（`road_id` が1以上）だけを描く。判定はパス一覧の `path_type` と `road_id` で行い、マスターは参照しない。
- 幹線道路レイヤーには道路名のラベルが追従する。道路名は道路の向きに回転させ、逆さにならないよう±90°に収める。配置の優先度は 地区名 → 駅・インターチェンジの記号 → 駅・インターチェンジの名前 → 道路名 → 施設記号 → 施設名。
- 場所検索の候補に道路（`kind: "road"`）が含まれ、選ぶと道路全体の範囲に合わせて区間を道路色で強調する。
