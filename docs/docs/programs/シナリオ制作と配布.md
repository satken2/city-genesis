# シナリオ制作と配布

シナリオは、開始時の都市を保存したテンプレートと紹介情報の組である。通常セーブと同じ `.cg` 形式を使う。`template_mode` は現在のセッションの編集モードであり、保存データへ編集権限として永続化しない。版と互換性は[バージョニングと互換性](バージョニングと互換性.md)を参照する。

## 制作と保存

1. トップのエディタから新しい都市を作るか、シナリオ管理で作品を編集用に開く。
2. 都市、パラメーター、クエストを設定する。達成条件の説明文は紹介用であり、実際の判定は都市内のクエストに設定する。
3. セーブメニューの「テンプレートとして保存」を選ぶ。テンプレート作成モードで利用できる。
4. ローカル保存が成功すると紹介情報ウィンドウが開く。タイトル、説明、達成条件の説明、作者、分類、言語、画像を編集できる。
5. 必要ならシナリオ管理から書き出す、または設定された投稿先へアップロードする。保存だけでは外部送信しない。

テンプレート保存は通常のセーブ先を変更しない。自作シナリオの編集では同じ `scenario_id` を維持して `content_revision` を増やす。同梱・ダウンロード作品の編集は自作の新しいIDへ保存する。都市の版情報は作者の入力欄にせず、コアが設定する。

紹介情報ウィンドウは保存済みテンプレートを編集するため、ゲーム開始前にも利用できる。紹介文はアーカイブの都市情報とメタデータを同時に更新し、プレイ中の達成目標画面と一致させる。画像も `.cg` 内の `thumbnail.png` に格納する。

## シナリオ管理

トップメニュー右下は左から `D`（開発時のみ）、シナリオ管理、設定、終了。左下には接続先のコア版とUI版を表示する。

管理ウィンドウは「すべて・同梱・ダウンロード・自作」で絞り込むカード一覧。画像は共通の `ScenarioThumbnail`、版情報は `SaveVersionInfo`、紹介文の入力は達成目標画面と共通の `ScenarioTextFields` を使う。ウィンドウ枠・再利用・閉じる操作は既存レジストリ方式に従う。

カードからプレイ、都市編集、自作の紹介情報編集、書き出しができる。アップロードは自作のみ。版不明や破損も一覧に残し、読み込めない理由を表示する。プレイ・編集の開始前に都市切替とバランス変更の確認を行う。

| 保存元 | 保存場所 | 一覧・APIでのID |
| --- | --- | --- |
| 同梱 | インストール先の `city/template/` | `builtin~<id>` |
| 自作 | ユーザーデータの `templates/` | `local~<id>` |
| ダウンロード・取り込み | ユーザーデータの `downloaded_scenarios/` | `downloaded~<内容を識別するid>` |

一覧は本体のメタデータから復元でき、外部の `saves_metadata.json` はキャッシュとして扱う。保存元を分けるため、同じ元IDの作品が同梱作品を隠すことはない。取り込んだ更新版は別ファイルになり、既存の都市や原本を上書きしない。

## 持ち運び用パッケージ

「書き出す」は保存ダイアログで選んだ場所へ `.cgscenario` を出力する。ZIP内の構成は `manifest.yaml` と `scenario.cg`。画像・作者・紹介情報・コア版は内側の `.cg` に含まれる。全都市の索引やユーザーの他のセーブは含めない。

マニフェストは[追加コンテンツとアセットパック](追加コンテンツとアセットパック.md)の `pack_id`・`display_name`・`version`・`type`・`entries` を使い、`scenarios` 配列を追加する。現在の書き出しは1作品の `mod` パックで、モデル用 `entries` は空配列。`scenarios` の各要素に `scenario_id`、`content_revision`、`file`、`sha256`、`size`、`required_pack_ids` を持つ。パックの `version` は内容リビジョンの文字列。

取り込みは `.cgscenario` とテンプレート `.cg` に対応する。ファイル種別、必須データ、サイズ、ZIP内の危険なパス・重複名、NumPyのオブジェクト配列、圧縮データ、版情報を検査する。マニフェストがある場合はハッシュ・サイズ・作品ID・リビジョンの一致も検査する。追加パックの解決機構はまだないため、依存がある作品は拒否する。取り込みサイズの上限は512MiB。

作者名・分類は紹介情報であり、作者の本人確認や公式認定の証明には使わない。利用者がファイルへ `official: true` を書いても公式権限として扱わない。

## 投稿先の接続契約

投稿先サービスは固定しない。コアの実行環境に `CITY_GENESIS_SCENARIO_UPLOAD_URL`（HTTPSのPOST先）を設定する。必要なら `CITY_GENESIS_SCENARIO_UPLOAD_TOKEN` を設定し、Bearer認証で送信する。UIへトークンは返さない。未設定のときはアップロードを無効化し、書き出しを利用できる。

投稿は `.cgscenario` のバイナリを `Content-Type: application/vnd.city-genesis.scenario+zip` でPOSTし、原本のハッシュを `Idempotency-Key` に付ける。サービス側は成功時にJSON `{ "id": "投稿ID" }` を返す。リダイレクトには追従しない。投稿前にタイトル・作者名を検査し、UIでは投稿先ホストへの送信を確認する。エラーでもローカルのテンプレートは残る。

これは接続用の共通HTTP契約であり、Steam WorkshopのSDK実装やコミュニティサイトそのものを含まない。投稿IDの永続管理、認証画面、作品の検索・オンラインカタログからの直接ダウンロードは、採用するサービスと合わせて定義する。

## API

| API | 動作 |
| --- | --- |
| `POST /api/v1/templates` | テンプレート保存。成功時に `id` / `save_id` を返す |
| `GET /api/v1/scenarios` | `scenarios` と `upload_available`・`upload_host`・`max_package_bytes` |
| `PATCH /api/v1/scenarios/{id}` | 自作のタイトル・説明・達成説明・作者・分類・言語を更新 |
| `PUT /api/v1/saves/{id}/thumbnail?template=true` | 自作の保存済み画像を更新 |
| `GET /api/v1/scenarios/{id}/export` | パッケージを書き出す |
| `POST /api/v1/scenarios/import` | バイナリを検査して取り込む |
| `POST /api/v1/scenarios/{id}/upload` | 設定先へ自作作品を送信する |
| `GET /api/v1/saves/{id}/validation?template=true` | ロード前検証 |
| `POST /api/v1/sessions?template_id=...&template_mode=...` | プレイ・編集として開始する |

紹介情報変更後はUI内の `scenarios:changed` イベントで一覧を更新する。画像URLのリビジョンは内容更新によるキャッシュ更新に使い、ランダムなクエリは付けない。

## 公式配布とミッション定義

制作物の出発点はすべて同じローカルテンプレート。開発者は検証済みの `.cg` を本体へ同梱でき、オンライン配布する場合も同じパッケージを使用できる。ローカル制作とコミュニティ投稿はプレイヤーにも開かれる。

公式ミッションにはテンプレートとは別に、`mission_id`、必要レベル、前提ミッション、完了に必要なクエストID、クリア報酬などの開発者用カタログが必要である。配置方針は非公開の開発資料で定める。都市内クエストの数値条件はカタログへ重複定義しない。

**公式進行カタログ・オンラインの公式認証・レベル報酬はこの管理画面の実装には含まれない。** 同梱という保存元だけでレベル報酬を与えず、コミュニティ作品からも公式進行を変更しない。これらを導入するときは作品リビジョンと検証済みハッシュを対応させ、進行中のミッションを最新定義で上書きしない。

## 検証

UIの保存元フィルター・投稿可否・紹介情報送信・ロード確認は `tauri/` の `npm run test:scenarios` で検証する。配布番号の同期検査は `node tools/sync-version.mjs --check`、翻訳キーは `python tools/check_i18n_parity.py`。
