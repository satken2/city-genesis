# シナリオ制作と配布

シナリオは、開始時の都市を保存したファイルと紹介情報の組である。通常セーブと同じ `.cg` 形式を使う。`template_mode`(神モード)は現在のセッションの編集モードであり、保存データへ編集権限として永続化しない。ファイルの中身・暗号化・公式署名は[セーブデータ仕様](セーブデータ仕様.md)、版と互換性は[バージョニングと互換性](バージョニングと互換性.md)を参照する。

## 保存元と置き場

シナリオには3つの保存元がある。形式はどれも同じ `.cg` で、保存元は「誰がそのファイルを管理するか」を表す。

| 保存元(`origin`) | 置き場 | 一覧・APIでのID | 変更 |
| --- | --- | --- | --- |
| 自作 `local` | ユーザーフォルダの `scenarios/<id>.cg` | `local~<id>` | できる |
| コミュニティ `workshop` | Steam Workshop の購読フォルダ `steamapps/workshop/content/<AppID>/<item_id>/<stem>.cg` | `workshop~<item_id>~<stem>` | 読み取り専用 |
| DLC `dlc` | インストール先の `dlc/<pack_id>/<stem>.cg` | `dlc~<pack_id>~<stem>` | 読み取り専用 |

- ユーザーフォルダの場所は[ファイル配置](ファイル配置.md)の OS 別の表に従う。
- IDの各区間は `[A-Za-z0-9_-]` の1〜128文字。`~` を含まないIDは自作としてだけ解決する(インストール先に置かれたファイルを自作と取り違えないため)。ほかの保存元を名乗るIDや形の崩れたIDは `INVALID_SAVE_ID` になる。
- コミュニティとDLCのフォルダは Steam が管理し、ゲームは読むだけで書き込まない。これらのシナリオの削除・紹介情報や画像の編集・上書き・アップロードは 422 `SCENARIO_READ_ONLY` で拒否される。手を加えたいときは「コピーして編集」で自作シナリオにする。
- Workshop のフォルダは、ゲームが Steam ライブラリの `steamapps` 配下にインストールされているときだけ決まる。開発・検証では環境変数 `GENESIS_WORKSHOP_DIR` で別のフォルダを指定できる。
- 公式かどうか・DLC由来かどうかは置き場では決まらず、ファイルの公式署名と暗号化で決まる([セーブデータ仕様](セーブデータ仕様.md#暗号化されたファイル))。置き場が `dlc` のファイルは、有効な公式署名があり、その署名のパックが必要パックに含まれるときだけ読み込める。
- 本体に組み込まれたシナリオは無い。本体が同梱する教材は[チュートリアル](チュートリアル基盤.md)だけで、シナリオの一覧には出ない。

## 制作と保存

1. 出発点を作る。シナリオ管理の「地形を取り込む」でオリジナル地形から新しい自作シナリオを作るか、既存のシナリオを「都市を編集」または「コピーして編集」で開く。
2. 地形(標高・水面・川・資源・プロップ・カメラ・地表・気候)は、自作カードの「地形を編集」から地形エディタで編集し、「シナリオに保存」で書き込む([地形データ作成マニュアル](../geometries/L_地形データ作成マニュアル.md))。
3. 都市、パラメーター、クエストは神モードのセッションで設定する。達成条件の説明文は紹介用であり、実際の判定は都市内のクエストに設定する。
4. セーブメニューの「テンプレートとして保存」(`POST /api/v1/templates`)で保存する。神モードのときだけ使える。
5. 保存が成功すると紹介情報ウィンドウが開く。タイトル、説明、達成条件の説明、作者、分類、言語、画像を編集できる。
6. 必要なら設定された投稿先へアップロードする。保存だけでは外部へ送信しない。

オリジナル地形は標高・サムネイル・範囲や寸法のメタデータだけを持ち、水面・川・資源・プロップ・カメラを持たない([地形形状](../geometries/D_地形形状.md) §D.14)。地形から作ったばかりのシナリオはこれらが空で、地表種別と気候はオリジナル地形の値で始まる。

「テンプレートとして保存」は通常のセーブ先を変更しない。自作シナリオを開いて保存すると同じIDへ上書きし、`content_revision` を1つ上げる。コミュニティ・DLCのシナリオを開いた都市は、新しいIDの自作シナリオとして保存され、元のファイルは変わらない。都市の版情報は作者の入力欄にせず、コアが設定する。

シナリオ保存と「コピーして編集」は、都市の出自(必要パック `required_packs` と元のシナリオ `derived_from`)を引き継ぐ。ユーザー操作で出自を消す経路は無い。DLC由来の都市は自作シナリオとして保存しても暗号化されたままで、そのパックを所有する人だけが開ける。

紹介情報ウィンドウは保存済みシナリオを編集するため、ゲーム開始前にも利用できる。紹介文はアーカイブの都市情報とメタデータを同時に更新し、プレイ中の達成目標画面と一致させる。画像は `.cg` 内の `thumbnail.png` に格納する。紹介情報・画像の更新は暗号化の有無と必要パックをそのまま保つ。

作者名・分類は紹介情報であり、作者の本人確認や公式認定の証明には使わない。公式かどうかは公式署名だけで決まり、メタデータに何を書いても公式にはならない。

## シナリオ管理

トップメニュー中央のボタンは上から「ニューゲーム」「ロード」「シナリオ管理」。右下は左から `D`(開発時のみ)・設定・終了、左下は接続先のコア版とUI版を表示する。シナリオ管理(`scenario_manager`)はUIだけで開き、Unityを起動しない。都市を開くときは `create_session` が Unity を起動する。

管理ウィンドウは共通の `FlatTabs` で「シナリオ」「地形を取り込む」の2タブに分かれる。ウィンドウ枠・再利用・閉じる操作は既存のレジストリ方式に従う。

### シナリオタブ

`GET /api/v1/scenarios` の全保存元を1つの一覧にしたカードを並べる。カードには画像(`ScenarioThumbnail`)、保存元と公式の札(`ScenarioOriginBadges`)、タイトル・説明・作者、版情報と必要パック・所有状況(`SaveVersionInfo`)を出す。版不明・破損・パック未所有も一覧に残し、読み込めない理由を表示する。クリックしたカードは選択状態になり、左端の実線ブロックで強調して見える位置までスクロールする。

| カード | ボタン |
| --- | --- |
| 自作(`origin` が `local` で `read_only` でない) | 「都市を編集」「地形を編集」「紹介情報」「アップロード」 |
| コミュニティ・DLC | 「コピーして編集」 |

- 読み込めないカードのボタンは押せない。「アップロード」は投稿先が設定されているときだけ押せる。
- 「都市を編集」「コピーして編集」は確認ダイアログとロード前確認(`utils/saves.ts` の `prepareSaveLoad`)を経て、`create_session {templateId, templateMode: true, acceptBalanceChange: true}` で神モードのセッションを開く。開始すると開いているポップアップをすべて閉じるので、確認文で地形エディタの未保存の編集が失われることを伝える。
- 「地形を編集」は Tauri コマンド `prepare_scenario_terrain_editor` でシナリオの地形を作業コピーへ書き出し、返された作業コピーのIDで地形エディタ(`terrain_editor`)を開く。セッションは使わない。DLC由来の(暗号化された)自作シナリオは地形エディタの対象外で、カードは一覧の要素の `encrypted` を見てこのボタンを押せなくし、理由をツールチップで示す(コアも409 `SCENARIO_ENCRYPTED` で断る)。
- 「紹介情報」は `scenario_metadata` を開き、`params.extra.scenarioId` を渡す。

### 地形を取り込むタブ

`GET /api/v1/terrain/maps` のオリジナル地形をタイル(サムネイル・翻訳名・大きさ)で並べ、詳細欄は持たない。地表・気候は出さない。登録表の値は新しい都市の初期値で、シナリオを作ったあとは地形エディタで決めるからである。一覧は初めてタブを開いたときに取得し、タブを離れても選択を保つ。「シナリオを作成」はタブ上部のツールバーに置き、地形を選ぶまで押せない。

「シナリオを作成」は `POST /api/v1/scenarios/from-terrain` に `{terrain_map_id, title: 地形の翻訳名, language: アプリ設定の言語}` を送る。成功したら一覧を取り直し、シナリオタブへ切り替えて新しいカードを選択状態にし、`scenarios:changed` を送る。

## 投稿先の接続契約

投稿先サービスは固定しない。コアの実行環境に `CITY_GENESIS_SCENARIO_UPLOAD_URL`(HTTPSのPOST先)を設定する。必要なら `CITY_GENESIS_SCENARIO_UPLOAD_TOKEN` を設定し、Bearer認証で送信する。UIへトークンは返さない。未設定のときはアップロードを無効にする。

投稿できるのは自作シナリオだけで、タイトルと作者名が必要。`.cg` のバイト列をそのまま `Content-Type: application/vnd.city-genesis.cg` でPOSTし、ファイルのSHA-256を `Idempotency-Key` に付ける。DLC由来の都市は暗号化されたまま送られる。サービス側は成功時にJSON `{ "id": "投稿ID" }` を返す。リダイレクトには追従しない。UIでは投稿先ホストへの送信を確認する。エラーでもローカルのシナリオは残る。

これは接続用の共通HTTP契約であり、Steam WorkshopのSDK実装やコミュニティサイトそのものを含まない。

## API

| API | 動作 |
| --- | --- |
| `GET /api/v1/scenarios` | `scenarios`(IDをキーにした一覧)と `upload_available`・`upload_host`・`max_package_bytes`。暗号化されたシナリオも鍵なしで載る |
| `POST /api/v1/scenarios/from-terrain` | `{terrain_map_id, title, language}` から新しい自作シナリオを作り `{"id": "local~<id>"}` を返す。ゲームは始まらない。未登録の地形は404 `NOT_FOUND` |
| `GET /api/v1/scenarios/{id}/terrain` | 自作シナリオの地形を地形エディタの形式で返す([地形形状](../geometries/D_地形形状.md) §D.14.3) |
| `PUT /api/v1/scenarios/{id}/terrain` | 地形エディタの編集内容を自作シナリオへ保存する。`content_revision` が1つ上がる |
| `PATCH /api/v1/scenarios/{id}` | 自作のタイトル・説明・達成説明・作者・分類・言語を更新 |
| `POST /api/v1/scenarios/{id}/upload` | 設定先へ自作シナリオを送信する |
| `POST /api/v1/templates` | 神モードの都市を自作シナリオとして保存する。成功時に `id` / `save_id` を返す |
| `PUT /api/v1/saves/{id}/thumbnail?template=true` | 自作シナリオの画像を更新 |
| `DELETE /api/v1/saves/{id}?template=true` | 自作シナリオを削除 |
| `GET /api/v1/saves/{id}/validation?template=true` | ロード前検証 |
| `POST /api/v1/sessions?template_id=...&template_mode=...` | プレイ・編集として開始する |

シナリオの地形APIと from-terrain はゲームのセッションを使わない。ゲームのセッションが読み込まれている間は409 `SESSION_ACTIVE` で断る。処理の間はコアが一時的に都市を組み立てるが、`GET /api/v1/sessions` の `current_save_id` は `null` のままで、都市のデータを返すAPIは503 `NO_SAVE_LOADED` を返す(UnityとUIがゲーム開始と誤認しないため。[コンポーネント連携](コンポーネント連携.md#セッション状態の管理))。対象は自作シナリオだけで、コミュニティ・DLCは `SCENARIO_READ_ONLY`、存在しない自作シナリオは404 `NOT_FOUND`、DLC由来の暗号化された自作シナリオは409 `SCENARIO_ENCRYPTED`([地形形状](../geometries/D_地形形状.md) §D.14.3)。

紹介情報・地形の変更後はUI内の `scenarios:changed` イベントで一覧を更新する。画像URLのリビジョンは内容更新によるキャッシュ更新に使い、ランダムなクエリは付けない。

## 公式シナリオとミッション定義

公式シナリオは、開発者が非公開のツールで公式署名を付けたシナリオである。署名だけを付けたもの(無料)と、署名したうえでパック鍵で暗号化したもの(DLC)がある。保存元にかかわらず、有効な署名があれば一覧で `official: true` になる。公式署名はファイルの全メンバーのハッシュに対する署名なので、中身を1バイトでも変えると無効になる。暗号化されたファイルでは、一覧に出す平文のヘッダー(紹介文とサムネイル)が中身と一致することも条件になる([セーブデータ仕様](セーブデータ仕様.md#公式署名))。プレイヤーの保存は署名を書かないため、公式シナリオから作った都市やそのコピーは公式にならない。

公式ミッションにはシナリオとは別に、`mission_id`、必要レベル、前提ミッション、完了に必要なクエストID、クリア報酬などの開発者用カタログが必要である。配置方針は非公開の開発資料で定める。都市内クエストの数値条件はカタログへ重複定義しない。**公式進行カタログ・レベル報酬はこの管理画面には含まれない。** 保存元や札だけでレベル報酬を与えず、コミュニティ作品からも公式進行を変更しない。

## 検証

UIのタブ・カード構成、保存元ごとのボタン、地形を編集の呼び出し、地形からの作成とカードの選択、投稿可否・紹介情報送信・ロード確認、ニューゲームのタブと開始は `tauri/` の `npm run test:scenarios` で検証する。配布番号の同期検査は `node tools/sync-version.mjs --check`、翻訳キーは `python tools/check_i18n_parity.py`。
