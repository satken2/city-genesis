# シナリオ制作と配布

本ページは、シナリオテンプレートの制作から同梱・オンライン配布・コミュニティ共有までの設計方針を定める。**テンプレート保存の基盤以外の公開・取り込み・公式ミッション管理は実装前の設計である。** 現行の保存形式は[セーブデータ仕様](セーブデータ仕様.md)、更新時の扱いは[バージョニングと互換性](バージョニングと互換性.md)を参照する。

## 1. 都市を作る操作と、公開する操作

公式制作者もプレイヤーも、同じシナリオエディタで都市を作る。共通の流れは「地形または既存テンプレートから編集開始 → 都市・パラメータ・目標・紹介文を設定 → ローカルにテンプレート保存」である。保存したテンプレートを配布する段階で、公開先ごとの情報を付ける。

`template_mode` は、建設やパラメータ・クエスト編集の制限を緩める**編集中のセッション状態**であり、公式コンテンツを意味するフラグではない。現行実装でもセーブへは保存されない。`.cg` の都市・地形・パラメータ・クエストを保存する形式は、通常セーブとテンプレートで共通である。

テンプレートにはメタデータの `is_scenario` が付くが、これも保存用途の識別にすぎない。公式かどうか、誰が公開したか、公式の進行報酬を与えられるかは、配布元と登録情報で決まる。

## 2. どこで何を設定するか

| 情報 | 作る場所 | 内容 |
| --- | --- | --- |
| 都市の開始状態 | シナリオエディタ | 地形、道路、建物、人口、資金など |
| 都市内のゲームパラメータ | テンプレートモードのパラメータ設定 | その都市で使う保存対象の設定値。ゲーム全体の配布マスターを編集する操作とは異なる |
| 都市内の達成目標 | テンプレートモードのクエスト編集 | 人口、収支などの判定可能な条件、期限、都市内の報酬など |
| 紹介文・画像 | テンプレートモードのシナリオ紹介 | タイトル、説明、目標の説明文、サムネイル |
| 共通の配布情報 | テンプレートの公開・書き出し操作 | 作品ID、内容の版、作者、分類、必要パック、対応・検証したコア版など |
| 公式ミッションの進行情報 | 開発者が管理する公式カタログ | 開始に必要なレベル、前提ミッション、全体のクリア条件、初回クリアによるレベル付与など |

シナリオ紹介の `scenario_objective` は文章であり、そこへ「人口1万人」と書くだけでは達成判定されない。都市内クエストで判定条件を作り、公式カタログの `completion_rule` がどのクエストの達成をミッション全体のクリアとするかを参照する。クエストの数値条件を公式カタログへ重複して書かない。

公式カタログの `required_level` や `grant_level` はプレイヤー全体の進行に属する。テンプレート作者が都市の資金を設定できることと、公式のプレイヤーレベルを付与できることは別である。コミュニティ作品でも都市内の目標は設定できるが、公式の進行を変更する権限は持たない。

## 3. ローカル保存後の3つの経路

すべての経路に、ローカルでの制作・保存が先にある。公式向けだけ特別な都市ファイルを作る必要はない。

| 経路 | 制作者の操作 | 配布するもの |
| --- | --- | --- |
| 公式・本体同梱 | 開発者がテンプレートを検証し、公式カタログへ登録して製品へ組み込む | テンプレート、画像、配布情報、公式ミッション定義 |
| 公式・オンライン追加 | 開発者が同じ検証・登録を行い、公式配布先へ公開する | 同じ内容に、ダウンロード先・サイズ・ハッシュなどの取得情報を付ける |
| ローカル利用・コミュニティ共有 | プレイヤーがテンプレート保存し、必要なら書き出し・投稿する | テンプレート、画像、共通の配布情報。公式の進行情報は付与しない |

ネットワークへの公開は保存とは別の操作とし、ローカル保存だけで投稿しない。コミュニティ用の投稿先は、この設計では特定サービスに固定しない。

同梱とオンラインで、ミッションの意味やファイル形式を変えない。差は入手経路にある。同じミッションを同梱版とオンライン更新版で提供する場合も、安定したミッションIDを使い、内容の版で識別する。

現行の同梱テンプレートの配置は `<インストール先>/city/template/`、ローカル制作物はユーザーデータの `templates/` である。オンライン追加物はユーザー領域の導入済みコンテンツとして管理し、インストール先や制作中のテンプレートへ直接上書きしない。

## 4. 配布用メタデータ

### テンプレートから自動取得する情報

タイトル・説明文・サムネイル・地形・言語・最終保存コア版は、保存したテンプレートから取得する。配布のたびに作者が入力し直したり、コア版を自己申告したりする必要はない。プレイヤーが追加で入力するのは、主に作者表示名・分類・公開用の補足などである。

配布用に書き出す対象は選択したテンプレート1件とその関連ファイルに限定する。`saves_metadata.json` はそのPCの一覧用索引であり、全件を丸ごと投稿するファイルではない。

### 共通の配布情報と公式カタログ

配布用情報は[追加コンテンツとアセットパック](追加コンテンツとアセットパック.md)のマニフェストを拡張し、シナリオへの参照を扱う。既存の `pack_id`・パックの `version` を利用し、シナリオ用のエントリを追加する。アセットパックの既存の形式と重複するパック台帳は新設しない。

| 情報 | 管理する内容 |
| --- | --- |
| 作品の識別 | 安定した `scenario_id` と `content_revision`。ローカルのセーブIDや投稿サイトのIDとは分ける |
| 紹介 | 作者表示名、タイトル・説明、言語、分類、サムネイルへの参照 |
| 実体 | 対象の `.cg` と画像の参照、サイズ、ハッシュ。書き出し時に計算する |
| 依存・互換性 | 最終保存コア版、必要パック、検証したコア版。最終保存版は `.cg` と一致することを確認する |
| 投稿先の情報 | 投稿ID、投稿アカウント、公開日時、配布URLなど。公開先が管理する |

公式カタログはこれらの共通情報を参照し、`mission_id`、対象の作品と内容の版、`required_level`、`prerequisite_mission_ids`、`completion_rule`、`grant_level` などを加える。ゲーム内の編集画面に公式カタログの手編集機能を必須とせず、最初は開発者用の定義ファイルで管理できる。

カタログから参照した内容の版と、配布するテンプレートのハッシュを対応させる。`official: true` のような自己申告フィールドや、由来を確認していないファイルのハッシュだけでは公式と判定しない。公式表示と進行報酬の適用は、同梱された公式登録情報、または真正性を確認した公式配布情報に基づく。オンラインの公式カタログは認証された配布経路と検証可能な署名等でその由来を確認する設計とする。

コミュニティから入手したコピーや、公式テンプレートを編集して派生させた作品を、公式ミッションとして登録し直すことはできない。派生作品には別の作品IDを付け、公式の進行対象から外す。

## 5. 更新とプレイ開始

コアの版と、シナリオの内容の版は異なる。例えば、コア `1.12.5` で制作した作品に対し、道路配置や目標を修正して `content_revision` を上げても、コアのリリース番号は変わらない。

「このコアでファイルを読み込める」と「このコアで公式ミッションの難度・解法を検証した」も分ける。前者はセーブ互換性の規則、後者は公式コンテンツの検証記録で確認する。単に同じMAJORであることをもって、バランスまで検証済みとは表示しない。

プレイ開始時は、元テンプレートを残して新しいセーブIDの都市を作り、テンプレートモードをOFFにする。公式ミッションとして開始した場合は、作品ID・内容の版・対応する公式定義をコア側で確定し、その実行の進行判定へ結び付ける。プレイ中に編集モードへ切り替えた都市は、自由編集の派生として扱う。

公式・コミュニティの更新は、これから開始するためのテンプレートを更新する。すでにプレイヤーが進めている都市を新しい開始データで置き換えない。公式の進行判定も、開始時の内容の版に対応する定義を維持し、カタログの最新版を読んで無言で目標を変更しない。

## 6. 現行実装で確認できる範囲

- トップメニューのエディタから「シナリオエディタ」を開き、`NewGameWindow` を `isScenarioEditor=true` で使って編集を開始する入口がある。通常プレイ中のテンプレートモード切替ボタンはデバッグ実行時だけ表示される。
- パラメータ設定、クエスト編集、達成目標画面のシナリオ紹介・サムネイル編集は存在する。紹介文の保存は現在の都市を更新する操作であり、都市ファイルの保存は別に必要である。
- テンプレートを保存する `POST /api/v1/templates` と、テンプレート一覧を取得する `GET /api/v1/saves?template=true` がある。
- 現行の `SaveLoadWindow` の保存ボタンは通常セーブ向けであり、「テンプレートとして保存」の選択肢はない。テンプレートモードをONにするだけで、通常の保存ボタンの保存先が変わるわけではない。
- 同梱テンプレートとローカルテンプレートの一覧をまとめて表示する仕組みはある。公式ミッションのカタログ、オンライン取得、配布パッケージの書き出し・取り込み、コミュニティ投稿はこの設計で追加する機能である。
- 現行の一覧は `saves_metadata.json` を読むため、別の保存先へ `.cg` だけをコピーしても一覧には登録されない。同梱物の組み立て・外部テンプレートの取り込みでは、選択したファイルからその配置先の索引を生成・更新する。制作者に索引全体の手編集やコピーを要求しない。

制作画面には「作業を保存」「テンプレートとして保存」「共有用に書き出す」を用途が分かる形で用意する。公式への登録・公開は開発者の配布工程で行い、ローカル制作とコミュニティ共有はプレイヤーも同じ仕組みで利用できるようにする。
