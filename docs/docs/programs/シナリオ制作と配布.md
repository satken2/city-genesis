# シナリオ制作と配布

シナリオは、新しいゲームの開始点として保存した都市と、その紹介情報の組である。ファイルは通常セーブと同じ `.cg` で、一覧の項目と暗号化は[セーブデータ仕様](セーブデータ仕様.md)、版と互換性は[バージョニングと互換性](バージョニングと互換性.md)を参照する。

## 保存元と置き場

保存元は「誰がそのファイルを管理するか」を表す。置き場のフォルダは[ファイル配置](ファイル配置.md)を参照する。

| 保存元(`origin`) | 管理する者 | 一覧・APIでのID |
| --- | --- | --- |
| 自作 `local` | プレイヤー | `local~<id>`(`~` を含まないIDも自作として扱う) |
| コミュニティ `workshop` | Steam Workshop | `workshop~<item_id>~<stem>` |
| DLC `dlc` | Steam | `dlc~<pack_id>~<stem>` |

ゲームから変更できるのは自作だけである。コミュニティとDLCのシナリオ(`read_only` が真)はプレイを始めることだけができ、変更の操作は 422 `SCENARIO_READ_ONLY` で断られる。プレイした都市を「シナリオとして保存」すれば自作シナリオになる。公式かどうか・DLC由来かどうかは置き場ではなく、公式署名と暗号化で決まる。ゲームに組み込まれたシナリオは無く、同梱の教材は一覧に出ない[チュートリアル](チュートリアル基盤.md)だけである。デバッグ起動のコアだけは、開発用の都市を保存元 `debug`(読み取り専用)として一覧に加える。

## 制作と保存

シナリオは、標高ファイルを取り込んで新しく作るか([地形形状](../geometries/D_地形形状.md))、プレイ中の都市を「シナリオとして保存」して作る。自作シナリオは「都市を編集」で神モードのセッションとして開いて都市・パラメーター・クエストを整え、地形エディタで地形を編集する。シナリオ管理と地形エディタはUIだけで完結し、Unityを使わない。地形エディタはゲームのセッションを使わずにシナリオを読み書きするので、ゲーム中は使えない。DLC由来の(暗号化された)自作シナリオは、地形を平文で持ち出せないよう地形エディタの対象外である。

都市を既存のシナリオへ書くのは「都市を編集」で開いたシナリオの上書き保存だけで、「シナリオとして保存」「別のシナリオとして保存」は常に新しい自作シナリオを作る。シナリオを書き換えるたびに、コアが `content_revision` を上げる。シナリオを作成・変更・削除したら、UIの中で `scenarios:changed` を送り、一覧を表示しているウィンドウが取り直す。

## 紹介情報

紹介情報は、タイトル・説明・達成条件の説明・初期の都市名(多言語テキスト。タイトルと、書いた項目には英語の文が要る)、作者、開始設定、画像からなる。紹介文を編集する窓口は紹介情報ウィンドウだけである。達成条件の説明は紹介用の文で、判定は都市内のクエストが担う。開始設定は、シミュレーション日数・気候・地表・アセットの地域の開始時の値と、プレイヤーが変えられるかを決め、変えられない項目の一覧が `scenario_fixed_options` になる。都市内の名前の言語はシナリオを作った時点で決まり、紹介情報では変えられない。

## ゲーム開始時の言語と開始設定

シナリオから始めるとき、プレイヤーは都市の言語・都市名と、作者が固定していない開始設定を選ぶ。固定した項目を変えようとしたり値域の外を送ったりすると、都市を読み込む前に 422(`SCENARIO_OPTION_FIXED`・`SCENARIO_OPTION_INVALID`)で断られる。

選んだ言語がシナリオの言語と違うと、コアは都市を読み込んだ直後に都市内の固有名詞を付け直す。対象は自動で名前を付ける仕組みがある名前(地区・経済主体・住民・駅舎・公共交通の路線・自然発生の道路など)で、作者が付けた名前も置き換わる。名前付きの道路やインターチェンジのように作者やプレイヤーが付けた名前しか入らないものと、多言語テキストの紹介文・クエストは残る。付け直しはセッションを開始する要求の中で終わるので、グラフィックとUIは付け直した後の名前しか見ない。

## 公式シナリオと配布

公式シナリオは、開発者がファイルの中身全体に公式署名を付けたシナリオで、署名だけの無料のものと、さらにパックの鍵で暗号化したDLCがある。中身を1か所でも変えると署名は無効になる。有効な署名があれば保存元にかかわらず一覧の `official` が真になり、DLCの置き場のシナリオはそのパックの有効な署名があるときだけ読み込める。プレイヤーの保存は署名を書かないので、公式シナリオから作った都市やシナリオは公式にならない。作者名は公式の証明にならない。

署名と暗号化は、コアがデバッグ起動のとき(一覧の `signing_available`)だけシナリオ管理から行え、UIは鍵ファイルのパスだけをコアへ送る。自作シナリオのアップロードは、コアに投稿先が設定されているとき(`upload_available`)だけ使え、`.cg` をそのまま送る。保存しただけでは外部へ何も送らない。
