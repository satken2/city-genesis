# プレイモード

セッションのモードを `play_mode` で持つ。共有定数は `PLAY_MODE_NORMAL=0`、`PLAY_MODE_SCEARIO=1`、`PLAY_MODE_TUTORIAL=2`、`PLAY_MODE_READ_ONLY=3`。シナリオモードは制作・編集用で、配布済みシナリオを遊ぶときは通常モードを使う。教材は `tutorial_id` で識別する。読み取り専用モードは公開サーバーで不特定多数に都市を見せるためのもので、ゲームのルールは通常モードと同じ(下表の通常の列に従う)。モードはセーブへ保存せず、通常セーブのロードとセッション終了で通常モードへ戻る。チュートリアル完了時は都市を保って2から0へ切り替える。

システムトレイの先頭には、チュートリアルと読み取り専用モードのときにモードを表すアイコンを出す。

| 操作・制限 | 通常(0) | シナリオ(1) | チュートリアル(2) |
| --- | --- | --- | --- |
| 建設資金の審査 | 行う | 免除 | 免除 |
| 市庁舎設置前のHUD操作ロック | 行う | 免除 | 免除 |
| 市庁舎設置前のエポック実行 | 不可 | 可 | 可 |
| 創設後のパラメータ編集 | 不可 | 可 | 不可 |
| God Editによる任意プロパティの編集・通常の更新制限の免除 | 不可 | 可 | 不可 |
| 天然資源の作成・編集・削除、入居する経済主体の作成 | 不可 | 可 | 不可 |
| クエストの作成・編集・削除、未達成の隠しクエストの表示 | 不可 | 可 | 不可 |
| `template_only`施設の設置・編集・削除 | 不可 | 可 | 不可 |
| 一括完成・街路自動生成・民間施設への一括変更・市民スキル構成の編集 | 不可 | 可 | 不可 |
| プロップの範囲散布UI・天候の手動切り替え | 不可 | 可 | 不可 |
| ブルドーザによる即時削除 | 不可 | 可 | 不可 |
| 1回のエポック実行数のUI上限 | 10 | 10,000 | 10 |
| 新規建築の確定後 | パネルを閉じる | 連続配置 | パネルを閉じる |
| シナリオの固定した開始設定 | 守る | 制作として開く | 守る |

## 読み取り専用モード

1つのコアを大勢で見るときに都市が書き換えられないよう、読み取り専用モードではコアが書き込みを断る。管理者だけが、コアの起動時に設定された秘密をヘッダー `X-Admin-Secret` で示して操作できる。

- 秘密の無い書き込みは403 `READ_ONLY` になる。書き込みとみなすのはGET・HEAD・OPTIONS以外の要求と、デバッグAPIのすべてである。例外として、都市を書き換えない見学用の問い合わせ `POST /api/v1/paths/motion`(車の動き)・`POST /api/v1/citizens/pick`(車・歩行者の抽選)・`POST /api/v1/navigation/route`(経路案内)は秘密なしで使える。
- 読み取り専用モードへは、秘密を示した `PATCH /api/v1/sessions` でだけ入れる。秘密が設定されていないコアでは入れない。抜けるときも書き込みなので秘密が要る。
- `POST /api/v1/sessions` で都市を開くと、モードはその要求で決まり、読み取り専用は外れる。開いた後に入り直す。

UIは、アイコンパネルの都市に物を作る操作(造成・パスの建設・土地区画・地区の編集・建物の建設・プロップの配置)と、システムトレイのシステム統計・設定・システムメニューを出さない。それ以外の操作はUIに残り、実行するとコアが403で断る。

## シナリオ編集ウィンドウ

シナリオモードでは、システムトレイに「シナリオ編集」への入口を1つ表示する。「都市編集」タブに一括完成・民間施設への一括変更・路地自動作成・天然資源編集・経済主体作成・パラメータ編集をまとめる。地図や3D上の選択を使う操作は、ここから既存の専用ウィンドウを開く。対象の詳細画面に付随する編集操作は、その画面で行う。

デバッグ実行では、通常モードの同じアイコンからシナリオモードに入ってウィンドウを開ける。通常モードへ戻す操作はシナリオ編集ウィンドウに置く。一括操作中は既存の `epoch:executing` 通知でHUDをロックし、完了後にUnityへセッションの再読み込みを送る。

### 市民スキル構成の編集

「市民スキル」タブでは、定住済み・就労可能年齢・非在学の住民を対象に、高度人材の割合と専門分野別の内訳を指定する。未入居の移民と観光客は対象に含めず、住宅待ちになった定住者は含める。基礎スキルは専門分野の内訳に含めない。複数の高度な専門スキルを持つ市民は、最も高い専門分野に一度だけ数える。

画面は現在の人数と内訳、指定比率から算出した適用後人数を表示する。各比率は百分率で、専門分野の内訳は高度人材全体を母数にして合計100%とする。「適用」を押すまでは入力値だけを保持し、押した時点の住民を一度だけ変更する。人数の端数を配分し、専門分野別の人数合計を高度人材の総数に合わせる。

既存の専門分野と熟練度をできるだけ保ち、不足する専門分野には大学卒業時の水準を付与する。高度人材の割合を下げる場合は超過分を標準水準へ戻し、対象の高度スキルは割当先の専門分野に揃える。年齢・世帯・勤務先・学校は変えず、雇用の移動は次のエポックに任せる。変更後のスキル値は都市データとして保存されるが、指定比率を維持する設定は保存しない。

`GET /api/v1/templates/citizen-skills` は `eligible_citizens`（対象人数）、`high_skill_citizens`（高度人材数）、`high_skill_ratio`（対象人数に占める割合）、`min_working_age`、`majors`（`skill_id`・`citizens`・高度人材内の `ratio`）を返す。`POST` は `high_skill_ratio` と、全専門スキルIDをキーとする `major_ratios` を受け取り、適用後の同じ構成と `updated_citizens`（スキルを変更した人数）を返す。通常・チュートリアル・読み取り専用モードは403、不正な比率や対象人数ゼロは拒否する。エポック実行とスキル編集は同じ排他を使い、同時実行は409で拒否する。

## 街路の自動生成

シナリオ編集ウィンドウから路地作成ウィンドウを開く。地図上で多角形の範囲を指定し、道路種別・生成パターン・街路間隔・向きを選んで作成する。生成パターンの既定値は「地形で曲がる格子」。

| 表示名 | APIの `pattern` | 街路の特徴 |
| --- | --- | --- |
| 地形で曲がる格子 | `relaxed_grid` | 格子の方向を保ちながら、地形に応じて曲がる |
| 等高線を優先 | `contour` | 勾配を抑え、等高線に沿う方向を優先する |
| スプロール風 | `organic` | 地形に沿いながら、不規則に曲がり枝分かれする |
| a：街区内の格子 | `block_grid` | 外周道路の方向に合わせ、縦横の細街路で街区を分ける |
| b：短冊 | `block_strips` | 外周道路の方向に合わせ、平行な細街路で街区を分ける |
| c：外周追従 | `block_perimeter` | 外周に沿う周回街路と接続路を配置し、広い中心部にも街路を置く |

選択肢は「地形に沿う街路」と「街区内の細街路」に分かれる。地形に沿う3パターンは現在の地形（造成済み部分を含む）を参照し、海・湖・川、使用中の敷地と急斜面を避ける。範囲内の既存道路から街路を伸ばし、既存道路のない範囲では陸上から伸ばす。街路間隔は枝分かれの間隔にも使う。地形や既存道路の条件により、範囲全体を埋め尽くすとは限らない。

向かい合う街路の先端は直進で接続できる。鋭角の接続と交差点の密集を避け、小さすぎる街区や細長い街区、短い未接続の枝を整理する。整理の目安は街路間隔と道路幅に応じて変わり、既存道路と長い行き止まりは残す。

街区内の3パターンでは、幹線に囲まれた街区全体を指定範囲に含める。地上の接道可能な既存道路（計画中・建設中も含む）が囲む街区ごとに、1車線街路を作成する。範囲の辺で道路のない閉路を補わず、既存街路で既に分かれた部分は別の街区として扱う。

「街路間隔」に代わって「区画寸法の目安」を表示し、既定20m、15〜25mの範囲で指定できる。道路の両側に奥行き約20mの接道区画を置ける密度を目安とし、外周道路の幅と街区の大きさに合わせて間隔を調整する。道路種別の選択肢は接道可能な1車線街路に限定し、向きの指定は表示しない。各街区の外周に合わせて配置し、地形によって方向を変えない。海・川・建物のある敷地・敷設できない勾配などは共通の検証で棄却する。土地区画そのものは作成せず、端部まで厳密な20m四方の区画を保証するものではない。

`POST /api/v1/templates/street-grid` に `points`（ワールドX/Zの頂点列）、`path_variant`、`pattern` を送る。地形に沿う方式では `spacing`（m）と `angle_deg`（省略時は自動）を使い、街区内方式では `parcel_size`（区画寸法の目安、既定20m）を使う。`pattern` の省略時は固定格子を生成する。成功時は作成件数・パスID・候補数・棄却理由・向きと選択された `pattern` を返す。街区内方式は対象街区数の `blocks` も返し、向きは最初の対象街区の値になる。対象街区がないときは0件とその理由をUIに表示する。通常モードとチュートリアルでは403を返す。

作成した街路は計画中で登録する。地図と3Dで確認して不要な街路を削除し、シナリオ編集の「一括完成」で竣工させる。

## 民間施設への一括変更

シナリオ編集ウィンドウに「民間施設に一括変更」ボタンを表示する。
`POST /api/v1/templates/privatize-facilities` は、次の2群の `public_facility` を0にする。

- `TYPE_BUILDING` の全施設。
- `TYPE_STANDARD` のうち、供給商品の `regulated=false`、インフラ財の供給・消費なし、`template_only=false` のすべてを満たす施設。建物とテナントの両方を含む。

対象はステータスを問わず、施設名やバリアントIDの固定一覧ではなくマスター属性から判定する。
供給商品が未定義の一般施設は対象外。変更するのは公共施設フラグだけで、敷地の所有者・残高・
工事や稼働の状態は変わらない。市有地に立つ施設は変更後も市有地に立つ。

APIは通常モード・チュートリアルで403を返し、成功時は `privatized_agents` に実際の変更件数を返す。
既にフラグが0の施設は数えない。UIは実行中のHUD操作をロックし、完了後にUnityへセッションの
再読み込みを送って変更件数を通知する。
