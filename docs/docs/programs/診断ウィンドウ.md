# 供給状況と診断API

## 詳細パネルの供給図

経済主体詳細(`AgentDetailPanel`)は「需給・取引」タブの先頭に供給図を表示する。「インフラ接続」セクションがある施設では、接続状態・受入れ量のバッジの下に置く。路線詳細(`TransitDetailPanel`)では「基本情報」タブの先頭に置く。施設の警告カードと路線の運休・車両不足の注意は、タブの外のヘッダー下に表示する。

対象はインフラ財・車両財の生産施設、資源財・インフラ財・車両財を原材料に持つ施設、および公共交通路線。資源そのものの詳細には表示しない。独立した `diagnosis` ウィンドウは登録しない。

図は**資源財・インフラ財・車両財だけ**を上流へたどり、選択対象が供給するインフラ財・車両財の直接の消費先を右端に加えた一系列である。各箱への入力線は一つまでとし、通常商品やサービス財の調達・消費先は図に含めない。例えば、水道ポンプでは「水資源 → 取水施設 → 水道ポンプ」、取水施設を選んだ場合も同じ系列を表示する。変電所が供給する通常の電力へは進まない。海水淡水化施設のように天然資源を材料に持たない施設へ、資源の箱を補わない。

- 選択対象のアイコン枠はオレンジ色にする。
- 同じ財を供給する施設は都市全体で一つの箱に集約する。上流は財ごとの共通名・共通アイコンを使い、施設の種類や件数で切り替えない。例えば太陽光・風力のいずれも「発電所」の箱になる。個別の名前・アイコンは選択対象だけに使う。箱の下には稼働施設数と全市の前回生産量を表示する。
- 下流の直接の消費先も全市で一箱にまとめ、財ごとの共通名・共通アイコンと稼働数を使う。消費先がない場合も箱を残してグレーにし、線に `×` を表示する。下流箱には生産量や不在の説明文を付けず、その先へは展開しない。
- 箱の下には施設名・稼働施設数・生産量(資源では残量)を表示し、箱の上の役割名と施設名の下の状態名は表示しない。
- 施設や資源がない箱、非稼働の箱はグレーにする。接続が切れた線は赤い破線と `×`、不足・容量制約の候補は黄色と `!` で示す。両マークは同じ大きさの円の中心にSVGの図形として描き、文字のフォント・ベースラインに依存させない。接続状態は線のツールチップと読み上げ用のラベルにも付ける。

全市の生産量は規模の参考値であり、選択対象に届く量ではない。線の状態は、その入力を必要とする施設の接続条件に対応する。下流の線は選択施設と消費先の接続を判定する。資源残量は上流施設の区画が利用できる資源について表示し、同じ資源を複数施設が使っても重複加算しない。

## 部品と取得のタイミング

| 部品 | 責務 |
|---|---|
| `components/supply/SupplyChainGraph.tsx` | 上流・選択対象・直接の消費先を一列の箱と太い直線で描画する |
| `components/supply/SupplyChainSection.tsx` | 取得済みの供給図と取得中・待機・失敗の表示をまとめる |
| `hooks/useSupplyGraph.ts` | ウィンドウ表示時と対象変更時の取得、要求取消を担当する |
| `components/supply/supplyGraph.ts` | レスポンス型と表示対象の判定 |

取得フックは詳細パネル側に置く。ウィンドウを開いた時と、開いたまま表示対象を変更した時にだけAPIを呼び、そのウィンドウ内では取得済みの図を使う。タブの切り替え、エポック完了、フォーカス復帰、施設や路線の編集では再取得しない。更新ボタンとポーリングは設けない。

`App` はウィンドウの開き直しを `open_seq` で識別し、詳細パネルを再マウントする。対象変更・アンマウント時には古い要求を取消し、遅れて返った図が新しい対象を上書きしないようにする。APIが `pending=true` を返した場合は待機表示にするが、自動再取得は行わない。

図は上下の余白を抑え、必要な横幅を確保して長い系列を横スクロールで表示する。太い接続線をアイコン枠の左右中央へ直接つなぎ、丸い端点は付けない。受入れ実績が正で、不在・非稼働・未接続ではない線だけに明るい縞を重ね、上流から下流へ流す。線の太さとアニメーション速度は一定で、量に応じた変更は行わない。実績なし・受入れ量ゼロの線は静止する。動きの抑制設定では縞も静止する。枠と線の配置は共通のサイズ変数で揃える。描画部品は通信・ウィンドウ操作・施設リンク・展開表示を持たない。

## 表示する時点

生産量・受領量・警告・配送流量は最後に完了したエポックの実績。接続・施設の稼働状態・資源残量は取得時の状態。需要は次回の計画値である。エポック未実行では生産実績を0として表示せず、`—` とする。

不足と容量制約は時点の異なる値から推定するため、「可能性」として表示する。パスの飽和だけで、選択対象の不足の原因を断定しない。

供給図はAPI要求の間だけ構築する。都市の保存値やシミュレーションフェーズに、図のための常時保持する値を追加しない。

## API: `GET /api/v1/agents/{agent_id}/diagnosis`

このAPIは手書きのJSONを返す。生成された `single_agent` の型とは分けて、`SupplyResponse` として扱う。

| フィールド | 型・意味 |
|---|---|
| `agent_id`, `name` | 対象のIDと名前 |
| `epoch` | 最後に完了したエポック番号 |
| `pending` | 実行中など、整合した分析を返せない場合に `true` |
| `alert` | 対象の警告ビット |
| `graph` | 以下の供給図。非対象・待機時は `null` |
| `roots` | 症状別の診断木。供給図の描画には使用しない |

待機時は `graph=null`、`roots=[]`、`alert=0` になる。分析中にエポックが進んだ場合も、途中の結果を返さず待機を返す。

### graph

| フィールド | 意味 |
|---|---|
| `selected_id` | 選択中の箱のID(`selected`) |
| `nodes` | 上流・選択対象・直接の消費先の順に並ぶ箱の配列 |
| `edges` | 同じ順序で隣接する箱を結ぶ線の配列 |
| `has_results` | 完了済みのエポック実績があるか |

箱は `id`、`kind`(`facility`/`resource`/`consumer`)、`role`、`selected`、`state`、`product_id` を持つ。施設には `count`、`active_count`、全市の前回生産量 `production` を返す。実績がない場合の生産量は `null`。下流の `consumer` 箱の `product_id` は受け取る財を指し、生産量は `null`。資源には `resource_amount` を返す。選択対象には `agent_id`、`name`、`variant`、路線なら `path_variant` を返す。上流の共通名は `supplyGraph.facilities.<product_id>`、下流の共通名は `supplyGraph.consumers.<product_id>`、共通アイコンは `SupplyChainGraph` の財別の対応表で定義する。

接続線のフィールド:

| フィールド | 意味 |
|---|---|
| `source`, `target`, `product_id` | 供給元箱、供給先箱、入力する財 |
| `transport` | `resource`(区画から採取)、`infrastructure`(インフラ網)、`vehicle`(走行網) |
| `state` | 接続・供給状態 |
| `recipient_count`, `reachable_count` | 入力を必要とする施設・路線の数と、届く供給施設の数。資源では利用できる施設数 |
| `received`, `demand` | 接続できる受領施設の前回受領量(`null`=実績なし)と受領施設全体の次回需要。特定の供給元からの配送量ではない |
| `path_ids` | 容量制約の候補パスID。最大8件 |

`state` は `ok`、`unknown`、`missing`、`inactive`、`partial`、`limited`、`disconnected`、`supply_shortage`、`capacity_limited`。文言は `supplyGraph.state.*` に定義する。`unknown` は実績がない場合や原因を確定できない場合にも使う。

### roots

診断木のノードは `{type, params, targets, children}`。`type` は `diagnosis.nodes.<type>` の翻訳に対応し、`params` は数量・件数などの埋め込み値、`targets` は施設・パス・ノードへの参照、`children` は原因側のノード配列である。供給図は警告の有無にかかわらず返される。

## 検証

`npm run test:supply` は一列の箱と線、不在・接続切れ・容量制約の表示、受領実績によるアニメーション、下流箱の集約表示、対象切り替え時の要求取消、タブやエポックに依存しない取得回数、ウィンドウ再表示時の取得を確認する。
