# 供給状況と診断API

## 詳細パネルの供給図

経済主体詳細(`AgentDetailPanel`)と路線詳細(`TransitDetailPanel`)は、ヘッダーの直下に供給図を表示する。対象はインフラ財・車両財の生産施設、インフラ財・天然資源を原材料に持つ施設、および公共交通路線。資源そのものの詳細には表示しない。独立した `diagnosis` ウィンドウは登録しない。

図は選択対象から必要な入力を上流へたどり、資源、生産施設、中継施設・車両基地、路線を矢印で結ぶ。入力はマスターの材料と供給財に従うため、取水施設の水源と海水淡水化施設の入力、発電方式ごとの燃料、路線種別ごとの車両を同一視しない。

- 選択対象のアイコン枠はオレンジ色にする。
- 同じ財を供給する施設は都市全体で一つの箱に集約する。種類が一つなら施設種別名、複数なら「財名の供給施設」を使う。箱の下には稼働施設数と全市の前回生産量を表示する。
- 箱を押すと、種類別の施設数・生産量、入力の受領量と次回需要、供給元施設へのリンクを表示する。リンクは最大8件。経済主体詳細では現在のパネルの履歴に追加し、路線詳細では経済主体詳細を開く。
- 施設や資源がない箱、非稼働の箱はグレーにする。接続が切れた辺は赤い破線と `×`、不足の候補は黄色と `!`、容量制約の候補は太い黄色の破線と `!` で区別する。状態名も表示し、色だけに依存しない。
- 現在の施設の警告([[アラートフラグ管理]])と、路線の運休・車両不足は図の下に表示する。

全市の生産量は規模の参考値であり、選択対象に届く量ではない。辺の状態はその入力を必要とする施設の接続条件・供給範囲に対応する。資源残量も、上流施設の区画が利用できる資源について表示する。同じ資源を複数施設が使っても残量を重複加算しない。

## 部品と更新

| 部品 | 責務 |
|---|---|
| `components/supply/SupplyChainGraph.tsx` | 集約済みの `graph` を描画する。通信とウィンドウ操作は持たず、施設への遷移は `onNavigate` に委譲する |
| `components/supply/SupplyChainSection.tsx` | 見出し、再取得、待機・失敗表示、図の下の警告をまとめる |
| `hooks/useSupplyGraph.ts` | API取得、変更通知、エポック実行中の待機、対象切り替え時の要求取消を担当する |
| `components/supply/supplyGraph.ts` | レスポンス型、表示対象の判定、循環を除いた列配置 |

表示時、選択対象・詳細データの変更時、再取得ボタン、ウィンドウが再びフォーカスを得たときに取得する。`roads:changed`、`transit:lines_changed`、`supply:changed` とエポック完了でも、表示中のパネルだけが再取得する。一定間隔のポーリングは行わない。非表示のパネルでは取得しない。

`utils/api.ts` はバックエンドへの施設・建物・パス・路線・資源・区画・都市の更新が成功したとき、Tauriアプリ内の `supply:changed` を通知する。読み取り、失敗、プレビューなど都市を更新しない要求は対象外。Unityからの直接編集は、パネルへ戻ったときの取得で反映する。

`epoch:executing` を受けると実行中の分析要求を取消し、警告も一時的に隠す。APIが `pending=true` を返した場合も待機表示にする。完了通知で再取得するほか、完了通知を受け取れなかった場合は再取得ボタンで回復できる。選択対象の切り替え後に古い要求が完了しても、古い図を表示しない。

図は必要な横幅を確保し、長い連鎖は横スクロールにする。SVGでアイコン枠の間に辺を描き、`ResizeObserver` でパネル幅・文字サイズ・言語による配置の変化に追従する。循環する辺は折り返しと `↻` で示す。

## 表示する時点

生産量・受領量・警告・配送流量は最後に完了したエポックの実績。接続・施設の稼働状態・資源残量は表示時の状態。需要は次回の計画値である。エポック未実行では生産・受領実績を0として表示せず、`—` と「実績なし」を表示する。

接続を直すと構造の表示は変わるが、警告や受領実績は次のエポックまで残ることがある。不足と容量制約は時点の異なる値から推定されるため、「可能性」として表示する。パスの飽和だけで、選択対象の不足の原因を断定しない。

供給図の作業データはAPI要求の間だけ構築する。都市の保存値やシミュレーションの各フェーズに、図のための常時保持する値を追加しない。

## API: `GET /api/v1/agents/{agent_id}/diagnosis`

このAPIは手書きのJSONを返す。生成された `single_agent` の型とは分けて、`SupplyResponse` として扱う。

| フィールド | 型・意味 |
|---|---|
| `agent_id`, `name` | 対象のIDと名前 |
| `epoch` | 最後に完了したエポック番号 |
| `pending` | 実行中など、整合した分析を返せない場合に `true` |
| `alert` | 対象の警告ビット |
| `graph` | 以下の供給図。非対象・待機時は `null` |
| `roots` | 症状別の診断木。報告する症状がなければ空配列。路線の運休・車両不足の文言にも使用する |

待機時は `graph=null`、`roots=[]`、`alert=0` になる。分析を始めた後にエポックが進んだ場合も、途中の結果を表示しないため待機を返す。

### graph

| フィールド | 意味 |
|---|---|
| `selected_id` | 選択中の箱のID(`selected`) |
| `nodes` | 選択対象、供給財ごとの施設群、資源財ごとの箱 |
| `edges` | 供給元から供給先への入力関係。同じ組合せは一つに集約する |
| `has_results` | 完了済みのエポック実績があるか |
| `truncated` | 上流表示の深さ上限に達したか。該当時は供給元の詳細へ進む案内を表示する |

箱のフィールド:

| フィールド | 意味 |
|---|---|
| `id`, `kind`, `role`, `selected`, `state` | 箱のID、`facility`/`resource`、役割、選択中か、状態 |
| `product_id` | 供給する財。資源の箱では資源財 |
| `agent_id`, `name`, `variant`, `path_variant` | 選択対象の識別情報。`path_variant` は路線の場合 |
| `count`, `active_count` | 施設総数・稼働数。資源では利用候補の資源数 |
| `production` | 集約施設の全市の前回生産量。未実行では `null` |
| `variants` | `{variant, count, active_count, production}` の内訳。施設がない場合は候補種別を件数0で返す |
| `agent_ids`, `facilities` | 施設IDと、リンク用の `{id, name}`。最大8件 |
| `resource_amount`, `resource_ids` | 利用候補の資源残量とID(資源箱のみ) |
| `importer_count` | 市場で扱う入力の輸入拠点数 |

辺のフィールド:

| フィールド | 意味 |
|---|---|
| `source`, `target`, `product_id` | 供給元箱、供給先箱、入力する財 |
| `transport` | `resource`(区画から採取)、`infrastructure`(インフラ網)、`vehicle`(走行網)、`market`(市場) |
| `state`, `cycle` | 状態と、循環する関係か |
| `recipient_count`, `reachable_count` | 入力を必要とする施設・路線の数と、届く国内供給施設の数。資源の辺では利用できる資源を持つ施設数 |
| `received`, `demand` | 前回受領量(`null`=実績なし)と次回需要 |
| `path_ids` | 容量制約の候補パスID。最大8件 |
| `import_supply` | 市場の輸入供給量(返される場合)。全市の参考値 |

`state` は `ok`、`unknown`、`missing`、`inactive`、`partial`、`limited`、`disconnected`、`unavailable`、`supply_shortage`、`capacity_limited`、`unmatched`。文言は `supplyGraph.state.*` に定義する。`unknown` は不具合とは限らず、実績がない場合や原因を確定できない場合にも使う。

### roots

診断木のノードは `{type, params, targets, children}`。`type` は `diagnosis.nodes.<type>` の翻訳に対応し、`params` は数量・件数などの埋め込み値、`targets` は施設・パス・ノードへの参照、`children` は原因側のノード配列である。施設の不調はアラートビット、路線の不調は `line_paused_<reason>` や `line_vehicle_shortage` が起点になる。供給図は警告の有無にかかわらず返される。

## 検証

`npm run test:supply` は集約箱の配置、循環、接続切れと容量制約の表示、受領量・需要の区別、要求取消と非表示・エポック実行中の更新制御を確認する。`npm run test:api-client` は更新成功時だけ再分析通知が発生することも確認する。
