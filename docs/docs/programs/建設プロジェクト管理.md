# 建設プロジェクト管理（タグと表示フィルタ）

複数の工事（建物・道路）を「ひとつの再開発計画」としてまとめて扱うための仕組み。
建物と道路に **タグ** を1つ付けられるようにし、タグ単位で建設費と工期を集計して
「建設プロジェクト」ウィンドウに並べる。あわせて、3Dビューの表示・非表示を
**オブジェクト単位／タグ単位** で切り替えられる。

!!! info "2つの状態の置き場所が違う"
    - **タグ**はバックエンドが持ちセーブに含まれる（エポックをまたぐ計画なので消えては困る）。
    - **表示・非表示**はグラフィック（Unity）がセッション内だけ持ち、バックエンドにもセーブにも一切残らない。

## タグ

- 実体は建物（`EconomicAgent`）と道路（`Path`）の非SoAプロパティ `tag`（空文字＝タグなし）。**1オブジェクトにつき1つだけ**。
- 付け外しは通常のPATCH（`PATCH /api/v1/agents/{id}` / `PATCH /api/v1/paths/{id}` の `tag`）。
  正規化（前後の空白除去・空白の畳み込み・32文字上限）と都市側の候補一覧への登録があるため、
  バックエンドは生の `setattr` ではなく `crud_tags.apply_tag` を通す。
- 新設時は作成リクエストに `tag` を載せれば、作成と同時に付く（`POST /api/v1/buildings/`・
  `POST /api/v1/buildings/direct` のボディ、`POST /api/v1/paths/` の各パス）。不正なタグ名は作成前に弾く。
  市庁舎のように作成と同時に竣工するものには付かない（エラーにはしない）。
- 都市（`City.tag_names`）は**プルダウンに出す候補名を出現順で覚えているだけ**の索引で、
  どのオブジェクトに付いているかの真実源は常にエンティティ側の `tag`。
  1件も付いていないタグも候補として残す（付け外しのたびに選択肢が消えると付け直せないため）。

### タグを付けられる対象

タグは「これから建てる・いま建てている市の工事」をまとめるためのもので、付けられるのは次の両方を満たすものだけ。

| 条件 | 建物 | 道路 |
| --- | --- | --- |
| 市の資産 | 市政府の施設（`public_facility`）だけ。民間の建物は市の建設予算に計上されず、束ねる意味がない | 常に市の資産なので条件なし |
| ステータス | 着工保留中（`STATUS_PENDING`）・計画中（`STATUS_SCHEDULED_CONSTRUCTION`）・建設中（`STATUS_CONSTRUCTING`） | 同左 |

判定はバックエンドの `crud_tags.is_taggable` が正で、UIの `utils/constructionTags.ts` の
`TAGGABLE_STATUSES` / `isTaggable` はその写し（一致させる契約）。対象外へのタグ付けは `ValidationError`
で拒否する（外すのは状態を問わず受け付ける）。

**付いたタグは、竣工・倒壊などで対象外になっても外れない。** 対象外になると新たに付けたり
付け替えたりはできなくなるが、既存のタグは残り、プロジェクトの表で竣工済みの行として数え続ける
（進捗「◯ / ◯ 件 完了」を見せるため）。タグが外れるのはプレイヤーの操作（タグの削除、PATCHでの空文字）だけ。

候補名（`City.tag_names`）は1件も付いていなくても残る（次の工事に同じタグを付け直せるように）。

### エンドポイント

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/api/v1/tags` | タグ候補の一覧（`name` / `agent_count` / `path_count`）。プルダウンの選択肢 |
| GET | `/api/v1/tags/projects` | タグ別の工事一覧と集計（`?tag=` で1件に絞り込み） |
| GET | `/api/v1/tags/object` | 建物・道路1件の現在のタグ（`?kind=agent|path&id=`） |
| DELETE | `/api/v1/tags/{tag}` | タグを候補から削除し、付いている建物・道路からも外す |

いずれも手書きのプレーンJSON（`endpoints.yaml` の自動生成スキーマを使わない）。

!!! warning "`tag` は単体取得のレスポンスに含まれない"
    `GET /api/v1/agents/{id}` などは `response_model` でフィルタされるため、
    スキーマに無いフィールドを手で注入しても**黙って落ちる**。
    現在値は専用の `GET /api/v1/tags/object` から引くこと。
    一括取得（bbox）にもタグは載せない（グラフィック側はタグを知る必要がない。後述）。

## 集計（建設費と工期）

`GET /api/v1/tags/projects` がタグごとに返す。

- **建設費の見込み額合計**（`total_remaining_cost`）＝未完了アイテムの残り事業費の合計
- **工期**（`max_remaining_epochs`）＝未完了アイテムの残りエポック数の**最大値**（全部が終わるまでのエポック数）
- 残りエポックが算出できないアイテム（建設スピード0など、このままでは終わらない工事）は
  最大値の計算から外し、件数だけ `stalled_count` で返す（合計を無限にしないため）

1件あたりの見積もりは `app/services/utility/construction_estimate.py` が唯一の算出元で、
公共工事の資金審査（`construction_funding` の拘束額）と算式を共有する。

- 着工済み（建設中）… 必要体積 − 取得済み体積
- 未着工（着工保留中・計画中）… 着工処理（ConstructionStartPhase ステップ1）と同じ式で先行推定
- 竣工済み … 0（表には竣工済みの行として残り、進捗の件数に数えるが、建設費・工期の集計対象外）

## 表示・非表示

3Dビューの表示制御は2系統ある。**レイヤー単位**（表示オプションパネルの色モード・
表示フラグ。`view:change_view`）と、ここで足した**オブジェクト単位**（`view:set_object_filter`）で、
両者は直交する。オブジェクト単位のフィルタが立っているものは、色モードや
計画中表示フラグに関わらず消える（クリックも拾わない）。

```
UI(建設プロジェクト / 各詳細パネル)
   │ view:set_object_filter {hidden_building_ids, hidden_path_ids}   ← 差分ではなく全集合
   ▼
Unity IpcViewCoordinator → ObjectVisibilityFilter
   │ VisualModeObject.SetFilterHidden / 遠景は MeshRenderer.enabled
   ▼
UI ← view:object_filter_state {hidden_building_ids, hidden_path_ids}  ← 状態の正はUnity
```

- **送るのはタグ名ではなくIDの集合**。グラフィック側にタグの概念を持ち込まないための設計で、
  「そのタグに今どのオブジェクトが属するか」の解決はUIが行う。
- **差分ではなく毎回「今隠しているものの全集合」を送る**（追加・削除の取りこぼしで表示が食い違わないように）。
- 状態の正はUnity側にあり、パネルは開いたときに `view:query_object_filter` で問い合わせる
  （表示オプションの `view:query_state` と同じ形）。複数のパネルが同じ状態を見る。
- 差分ロード（bbox ストリーミング）で後から生成されたオブジェクトにも効くよう、
  生成側（`BuildingManager` / `PathManager`）が生成直後にフィルタを引く。
- セッションのリセット（新規都市・ロード）で必ずクリアする。IDは都市ごとに別物のため。

### 遠景LODの建物

遠景の建物は `VisualModeObject` を持たない（`FarBuildingBatcher` が64棟ずつ輪郭メッシュを
結合するため）ので、`MeshRenderer.enabled` を直接落として隠す。結合バッチは `enabled` の変化を
自分では検知しない（毎フレームのポーリングはしない）ので、フィルタを反映した側（`BuildingManager`）が
直後に `FarBuildingMember.RefreshObject` で結合バッチへ通知し、バッチから外させる。

### 既知の制限

- アラートアイコン（`AlertManager` のビルボード）は表示フィルタと連動しない。非表示にした
  建物のアラートアイコンは出たままになる（レイヤー単位の「建物を非表示」でも同じ挙動）。

## UI

| 場所 | 内容 |
| --- | --- |
| アイコンパネル「建設プロジェクト」 | `construction_projects` ウィンドウ。タグ1つ＝カード1枚で、見出しに集計（見込み額合計・工期・進捗）と目アイコン（タグ単位の表示切替）、中身に工事の表（行ごとに目アイコン・対象・状態・残り建設費・残り工期） |
| 建物／道路の詳細パネル | `common/TagRow`（＝`TagSelect` ＋ 個別の表示切替）。プルダウンで既存タグを選ぶか「＋ 新しいタグ…」で新規作成する。**タグを付けられる対象（上記）のときだけ行ごと出す**（竣工後はタグの付け替えができないため。タグ自体は残る。竣工後は個別の表示切替も出ないので、建設プロジェクトウィンドウの行の目アイコンか「すべて表示に戻す」で切り替える） |
| 建物建設パネル／道路・インフラ建設パネル／軌道建設パネル | 「建設プロジェクト」欄（`common/TagPicker`）で、設置する建物・敷くパスに付けるタグを先に選ぶ。確定時に作成リクエストの `tag` に載せる。新規の設置だけで、既存の建物・パスの編集では出さない。道路・軌道は連続設置の間も同じタグを保持する |

タグの選択UIは2層になっている。`TagPicker` は値を持つだけのプルダウン（候補の取得と「新しいタグ」の入力を受け持つ）で、
建設パネルはこれを直接使う（新しく入力したタグは設置するまで候補に無いので、選択中の名前を選択肢に足して表示する）。
`TagSelect` は `TagPicker` に「1件の現在値の取得と、選んだ時点のPATCH保存」を足した詳細パネル用の包み。

タグの変更はウィンドウをまたぐため、保存（または建設パネルからのタグ付き設置）に成功した側が
グローバルイベント `tags:changed` を送出し、開いている建設プロジェクトウィンドウとタグ選択が一覧を取り直す。
建設プロジェクトウィンドウはエポック完了（`epoch:executing` の `executing=false`）でも取り直す
（残り工期・建設費・竣工件数が進むため）。
