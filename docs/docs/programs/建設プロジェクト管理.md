# 建設プロジェクト管理(タグと表示フィルタ)

複数の工事(建物・道路)を1つの再開発計画として扱うため、建物と道路にタグを1つ付けられる。タグごとに建設費と工期を集計して建設プロジェクトウィンドウに並べ、3Dビューの表示・非表示をオブジェクト単位・タグ単位で切り替えられる。

タグと表示・非表示は置き場所が違う。タグはコアが持ち、エポックをまたぐ計画なのでセーブに含まれる。表示・非表示は Unity がセッションの中だけで持ち、コアにもセーブにも残らない。

## タグ

タグは建物・道路の `tag`(空文字はタグなし)で、付け外しは `PATCH /api/v1/agents/{id}`・`PATCH /api/v1/paths/{id}` の `tag`、新設では作成の要求の `tag` で行う。新たに付けられるのは市の公共工事のうち着工保留中・計画中・建設中(`STATUS_PENDING`・`STATUS_SCHEDULED_CONSTRUCTION`・`STATUS_CONSTRUCTING`)のものだけで、UI の `utils/constructionTags.ts` の判定はコアの規則の写しとして一致させる。付いたタグは竣工・倒壊で対象外になっても外れず、プロジェクトの表で竣工済みの件数として数え続ける。

タグの API(`/api/v1/tags`)は手書きの JSON で、自動生成のスキーマに載らない。建物・道路の単体取得の応答にも `tag` は含まれないので、現在のタグは `GET /api/v1/tags/object` から取る。

タグ別の集計(`GET /api/v1/tags/projects`)の `total_remaining_cost` は未完了の工事の残り事業費の合計、`max_remaining_epochs` は未完了の工事の残りエポック数の最大値(全部が終わるまでの期間)である。このままでは終わらない工事は最大値から外し、件数だけを `stalled_count` で返す。エポックはプレイヤーに見せない内部の単位なので、画面では月数に直して出す。

エポック実行結果(`epoch_report`)では、タグの付いた工事をタグごとの1行(`construction_projects`)にまとめ、個別の行にはタグの無い工事だけを出す。その進捗率(`before_pct`・`after_pct`)は、メンバーの建設体積で重み付けした平均である。

## 表示・非表示

オブジェクト単位の表示・非表示は、IPC の `view:set_object_filter` で、隠す建物・道路のIDの全集合を Unity へ送って決める。レイヤー単位の表示制御(`view:change_view`)とは直交し、ここで隠したものは色モードや計画中の表示によらず消え、クリックも拾わない。

- タグ名ではなくIDの集合を送る。Unity にタグの概念を持ち込まず、タグに今どのオブジェクトが属するかは UI が解決する。
- 差分ではなく毎回全集合を送り、追加・削除の取りこぼしで表示が食い違わないようにする。
- 状態の正は Unity にある。パネルは開いたときに `view:query_object_filter` で問い合わせ、`view:object_filter_state` で受け取る。隠す指定は差分ロードで後から生成したオブジェクトにも効き、セッションのリセットで消える(IDは都市ごとに別物のため)。

タグの変更はウィンドウをまたぐので、変更に成功したウィンドウが Tauri のグローバルイベント `tags:changed` を送り、建設プロジェクトウィンドウとタグの選択肢が取り直す。
