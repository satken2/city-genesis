# UI共通基盤

Tauri の UI は複数の WebView(ウィンドウ)で構成する。Rust がウィンドウの生成・配置・再利用と共有状態を管理し、React が各ウィンドウの内容を描く。個別の画面は、ここに書く共通のウィンドウ管理・通信・表示部品を使う。

## ウィンドウの管理

ポップアップの種別・初期サイズ・配置・インスタンスポリシーは `src-tauri/config/window-registry.json`、同時に開けない組は `window-mutex-groups.json` で定義する。生成と表示は `open_window` を通し、初期データは `get_window_context` で受け取る。新しく開く画面へのデータはコンテキストに含め、購読開始前のイベントに依存しない。

閉じたポップアップは破棄せず、非表示にして再利用する。再表示では `window-context-updated` と `open_seq` で React の状態を初期化する。閉じたときの編集終了・ハイライト解除は Rust が行い、React のアンマウントに依存しない。非表示のポップアップもイベントの購読を続けているので、Unity への送信などの副作用は表示中かを確かめてから行う。Unity の編集ステートは1つしかないので、編集画面のウィンドウは互いに排他にする。

常駐の HUD は、アイコンパネル・コックピット・システムトレイ・表示トレイの4ウィンドウに分かれる。透明な WebView もクリックを受けるので、各ウィンドウはパネルの実面積に合わせる。表示先のモニター・HUD を避けた配置・最前面の指定・位置の記憶は Rust の共通処理が決め、DPI の異なるモニターをまたぐので位置は物理座標で扱う。

ウィンドウの外へ候補を展開する選択メニューは、Tauri のネイティブメニューを使う。ブラウザ版は同じ API の差し替えから Web シェルの前面に表示し、呼び出し元の iframe の大きさで候補が切られないようにする。

## 共有データと通信

HTTP と IPC の窓口は [コンポーネント連携](コンポーネント連携.md) に従う。セッションと版情報を各画面へ複製せず、プレイモードは `usePlayMode` で参照する([プレイモード](プレイモード.md))。受信した IPC の状態をそのまま送り返して往復のループを作らない。

ウィンドウをまたぐ変更は、変更に成功したウィンドウが Tauri のグローバルイベント(`roads:changed`・`tags:changed`・`tracking:changed` など)で知らせ、受け取ったウィンドウが表示を更新する。セッションの定期取得を待たずに他のウィンドウへ反映するためである。

統計はエポックと接続先ごとのキャッシュ(`useEpochCachedStats`)を通して取得する。表示する値は API の確定値を使い、欠測と0を区別する。履歴の内訳に最新期の値を流用しない。

## 共通スタイル

配色・影・状態色は `App.css` の共通トークンを使う。トップメニュー系は `--flat-*`、設定フォームは `SettingsRow` と `SettingsForm.css`、タブは `FlatTabs` を利用する。個別の画面で同じ意匠を定義し直さない。

本文・通常の表の項目と値・入力欄・操作ラベルの文字サイズは、全画面で `1rem` に揃える。`FontSizeContext` がグローバル設定をルートの文字サイズへ反映するので、各画面で本文全体に拡大率を掛けない。見出しや主要な集計値は大きく、補足・バッジ・グラフの目盛りは小さくして情報の役割を区別し、これらも rem で指定する。

本文に連動する寸法は rem で指定し、px しか受け取らないグラフの寸法は `useRemPx` で換算する。例外として、固定サイズの常駐ウィンドウ、設定フォームの余白や操作部、位置計算に使うチュートリアルの強調表示は、それぞれの固定寸法に合わせる。

狭いウィンドウでは、CSS のメディアクエリでウィンドウの幅に応じて段組みを組み替える。判定はウィンドウの幅だけで行い、実行環境を見ない。スクロールバーは、右端の操作部を隠すオーバーレイ表示を避けるため、`App.css` の共通指定(WebView2 の `::-webkit-scrollbar`)を使う。

## 言語と作者のテキスト

UI の文言は i18n リソースを使い、全対応言語でキーを揃える。対応言語と Intl のロケールは `utils/locale.ts` の定義を使う。

シナリオの紹介やクエストの名前・説明は作者が書く多言語テキストで、UI の翻訳リソースとは別に扱う。`resolveLocalizedText` は表示言語の文を選び、無ければ英語に戻す。入力には `LocalizedTextFields` を使い、英語を必須とする。
