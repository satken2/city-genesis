# テンプレート作成支援(一括完成・路地作成・経済主体作成・観光名所の設置・即時削除)

シナリオ(テンプレート=初期セーブデータ)を作る制作者向けの都市開発支援機能。テンプレート作成モードのときだけ使える。道路網を手作業で1本ずつ敷いて工期を待つ手間を減らし、「幹線だけ人が引く → 路地は自動で埋める → 一括で完成させる → エポックを大量に回して都市を育てる → シナリオとして保存する」という流れで初期都市を量産することを目的とする。シナリオにだけ置ける観光名所のようなテンプレート専用バリアントの設置も、この道具立ての一部である。作り直したい建物や道路は、ブルドーザで稼働中のものも即時に削除できる。

シナリオの地形(標高・水面・川・資源・プロップ・カメラ・地表・気候)は、神モードのセッションではなく、シナリオ管理の自作カードの「地形を編集」から地形エディタで編集する([シナリオ制作と配布](シナリオ制作と配布.md)、[地形データ作成マニュアル](../geometries/L_地形データ作成マニュアル.md))。

## プレイモード

セッションのモードは整数 `play_mode` 1項目で持つ。共有定数は `PLAY_MODE_NORMAL=0`、`PLAY_MODE_GOD=1`、`PLAY_MODE_TUTORIAL=2`。`template_mode` や `is_tutorial` は使わず、教材を識別する `tutorial_id` は別に指定する。モードはセーブへ保存せず、通常セーブのロードとセッション終了で通常モードへ戻る。チュートリアル完了時は都市を保って2から0へ切り替える。

| 操作・制限 | 通常(0) | 神(1) | チュートリアル(2) |
| --- | --- | --- | --- |
| 建設資金の審査 | 行う | 免除 | 免除 |
| 市庁舎設置前のHUD操作ロック | 行う | 免除 | 免除 |
| 市庁舎設置前のエポック実行 | 不可 | 可 | 可 |
| 創設後のパラメータ編集 | 不可 | 可 | 不可 |
| God Editによる任意プロパティの編集・通常の更新制限の免除 | 不可 | 可 | 不可 |
| 天然資源の作成・編集・削除、入居する経済主体の作成 | 不可 | 可 | 不可 |
| クエストの作成・編集・削除、未達成の隠しクエストの表示 | 不可 | 可 | 不可 |
| `template_only`施設の設置・編集・削除 | 不可 | 可 | 不可 |
| システムトレイの一括完成・路地格子作成 | 不可 | 可 | 不可 |
| プロップの範囲散布UI・天候の手動切り替え | 不可 | 可 | 不可 |
| ブルドーザによる即時削除 | 不可 | 可 | 不可 |
| 1回のエポック実行数のUI上限 | 10 | 10,000 | 10 |
| 新規建築の確定後 | パネルを閉じる | 連続配置 | パネルを閉じる |
| 建物の敷地内判定・上空クリアランス、パスの形状・設備・標高・状態、区画の接道・都市外編集の制限 | 行う | 既存の免除を適用 | 行う |
| シナリオの固定した開始設定 | 守る | 制作として開く | 守る |

チュートリアルの左側アイコンパネルは通常モードと同じ構成で、資源編集・パラメータ編集・経済主体作成は表示しない。教材ごとのアイコン構成やモード権限の追加設定は持たない。既存の案内・達成判定・完成代行は[チュートリアル基盤](チュートリアル基盤.md)の仕組みを使う。

## テンプレート専用バリアント

経済主体マスター(`agent_master`)の `template_only` が真のバリアントは、シナリオ制作のための道具であって市長がプレイ中に建てる施設ではない。テンプレート作成モードのときだけ設置・編集・削除でき、通常プレイでは次のように一律に締め出される。

- 建物建設パネルのバリアント候補に現れない。
- バックエンドが作成・更新・削除を400で拒否する(建物系の入口は `BUILDING_VALIDATION_ERROR`、経済主体系の入口は `VALIDATION_ERROR`)。形状プレビューと建設費見積は確定操作ではないためこの拒否を通らず、確定の時点で止まる。エージェントの削除処理自体も保護対象としてスキップされるので、破綻などによる自動消滅も起きない。
- 民間の自動建設(スポーン)の候補列挙からも、実際に経済主体を作る段からも外れる。

判定はマスターのこのキーだけで行い、UI・バックエンドともバリアントIDの直接比較は持たない。現在このキーが立っているのは、建物の**観光名所**(variant 1070)・**国境検問所**(variant 4)・**国境貨物駅**(variant 1081)と、建物に入居する**都市外旅客輸送拠点**(variant 1069)・**陸路輸送**(variant 405)。

### 観光名所

大展望塔や古城のようなアイコニックな観光施設。名所ごとにバリアントを増やすとバリアントが際限なく膨張するため、経済主体バリアントは「観光名所」1つだけにして、その中のどの名所かを **`landmark`** という直交軸で切り替える。`landmark` は観光名所マスターのIDで、0は「観光名所ではない」を表す予約値である。

観光名所マスターの1行が決めるのは次のものに限る。受入能力(延床面積 ÷ 単位生産あたりの必要床面積)のような経済側の性質は、名所では変わらない。

| キー | 内容 |
| --- | --- |
| `display_name` / `description` | 名所の表示名と説明 |
| `agent_variant` | 所属する経済主体バリアント(観光名所 = 1070) |
| `model_prefix` | 3Dモデルのパーツフォルダ `landmark-{model_prefix}` に埋め込む識別子 |
| `width` / `depth` | 敷地の固定寸法(m) |
| `floors` | 論理階数 |
| `height_per_floor` | 階高(m)。バリアントの値より優先される |
| `cost_multiplier` | 建設費乗数。バリアントの `cost_ratio` に掛けたものが建設体積に乗る |

現在の5行は、1=大展望塔(60m×60m・4階) / 2=巨大記念像(40m×40m・3階) / 3=古城(100m×100m・4階) / 4=大聖堂(80m×50m・4階) / 5=古代遺跡(120m×120m・1階)。

設置そのものは建物建設の通常の経路(土地区画への建設・直接配置)にそのまま乗り、どの名所かを `landmark` で指定する点だけが違う。名所軸を持つバリアントでは `landmark` の省略も0も拒否されるため、必ずどれか1つを選ぶ。底面は名所行の `width` × `depth` に固定されて建ぺい率も幅・奥行きの指定も効かず(観光名所バリアントは `resizable=false`)、階数も名所行の `floors` に固定される。同じ名所は都市に1基までで、建設時とプレビュー時の双方で拒否される。

## UI

### 建物の連続配置(`building/BuildingConstructionPanel.tsx`)

神モード(`play_mode=PLAY_MODE_GOD`)の新規建設は、区画配置・自由配置・道路沿い配置のいずれも、確定後にパネルを閉じず、同じ種類の建物を続けて配置できる。建物バリアント・階数・建ぺい率・直接配置の寸法と向き・配置方法・コピー元・タグは保持し、設置位置とプレビューの検証結果を解除する。外観3軸(`visual_variant`・`visual_variant2`・`visual_variant3`)は建設成功ごとに独立した0〜1の乱数で再抽選し、次の建物へ送る。コピー建設ではコピー元と同じ外観を保つため再抽選しない。

成功後は既存の `edit_building:placement_command {variant, reset: true}` でUnityの位置選択を解除し、`session:reload`で建設結果を反映する。`STATE_NORMAL`への遷移や建物詳細パネルの自動表示は行わず、次の区画・地点の選択を待つ。観光名所を建てた場合は配置済みID一覧にも追加し、同じ名所を再選択できないようにする。通常・チュートリアルモード・既存建物の編集・市庁舎の移転は、確定後にパネルを閉じる。

### システムトレイのボタン

画面右下のシステムトレイ(`hud/SystemTray.tsx`)は、神モードのときだけ次の2つのボタンを表示する。通常・神モードを切り替えるボタンはデバッグ実行時だけ表示し、チュートリアル中は表示しない。製品版の `PATCH /api/v1/sessions` は通常モードへの復帰だけを許可する(それ以外は403 `PLAY_MODE_FORBIDDEN`)。神モードで都市を開く入口は、シナリオ管理の「都市を編集」「コピーして編集」(`POST /api/v1/sessions` の `play_mode=PLAY_MODE_GOD`)である。

| ボタン | 動作 |
| --- | --- |
| 一括完成 | `POST /api/v1/templates/complete-construction` を呼び、計画中・建設中の全パスと全建物を即時竣工させる。実行中はエポック実行と同じ `epoch:executing` イベントでHUDをロックし、完了後にUnityへ `session:reload` を送って地形・道路を再読み込みさせる。竣工した本数・棟数と、着工できずに残った件数を通知で知らせる |
| 路地作成 | `street_grid` ウィンドウを開く(下記) |

ボタン数で横幅が変わるため、トレイは自分の実測幅をTauriコマンド `resize_system_tray` で通知し、Rust側がウィンドウ幅を合わせて右下へ寄せ直す(透明な余白がUnityへのクリックを吸わないようにするため。アイコンパネルの高さと同じ仕組み)。

### エポック数の上限解除

エポック実行確認ウィンドウ(`taskbar/EpochConfirmWindow.tsx`)のエポック数は通常10までだが、テンプレートモードでは上限を外し、数値を直接入力できる(安全弁として10,000まで。バックエンドも `POST /api/v1/epochs` の `count` を1〜10,000に制限する)。都市を育てるために数百エポックを一気に回す用途で、1回のHTTPリクエストで完了まで待つ。

### 路地作成ウィンドウ(`template/StreetGridWindow.tsx`)

都市マップ(`map/CityMapCanvas`)を埋め込み、その上で範囲の多角形を頂点指定する。

- 左クリック=頂点追加 / 右クリック・Delete・Backspace=最後の頂点を削除 / 空白を左ドラッグ=パン / ホイール=ズーム。クリックとパンは押下位置から離した位置までの画面上の移動量(4px)で区別する。
- 開いた時点の3Dカメラ位置を中心に地図を寄せる(`camera:state` の初回受信時のみ)。
- ツールバーで格子間隔(20〜500m、既定80m)・路地の種類(街路のうち高架・地下でなく接道できるもの)・向き(最寄りの道路に揃える/角度指定)を選び、「作成」で `POST /api/v1/templates/street-grid` を呼ぶ。
- 路地は**計画中(STATUS_SCHEDULED_CONSTRUCTION)**で作られる。作成後はUnityへ `session:reload` を送って3Dに反映し、制作者が不要な路地をブルドーザで消してから、システムトレイの「一括完成」で竣工させる。
- 結果として計画した本数と棄却した本数(理由別)を表示する。

### ブルドーザの即時削除(`hud/Cockpit.tsx`)

コックピットのブルドーザボタンは、神モードのとき建物と道路をステータスを問わず即時に削除する。ON/OFFの切替は通常と同じで、ON中に3Dビューの対象をクリックすると、確認も取り消しも無く消える。UIはONにするときだけ `STATE_REMOVE_OBJECTS` に `instant_remove: true` を付け、Unityはその指定に従って削除対象を広げる(Unityは神モードかを知らない。[IPC連携の整理](IPC連携の整理.md))。ヒントバーとツールチップも即時削除用の文言に切り替わる。チュートリアルは通常モードと同じ取り壊し操作を使う。

- 対象は空き地の区画・建物・道路と線路・地形プロップ。区画は通常どおり空き地だけで、建物と道路が即時削除で広がる。
- 建物は入居テナントの経済主体と、世帯テナントの市民ごと消える。港のような輸出入拠点も消せる。区画は消さずに空き地として残り、地形は元に戻さない。
- 道路は、端点が他のどのパスにも使われなくなったノードも一緒に消える。そのパスを通る路線や、駅舎の所属は、通常のパス削除と同じ連鎖で更新される。
- 消せないものは、市庁舎・中央銀行・市の代理主体・国境検問所(建物)と、公共交通の区間パス(路線の持ち物なので、路線を編集・削除する)。
- 範囲配置のプロップだけは、このモードでも確認ダイアログを挟んでから範囲ごと消す。

### 経済主体作成パネル(`template/AgentCreationPanel.tsx`)

建物ではない経済主体(民間施設=TYPE_STANDARD / 輸出入拠点=TYPE_TRADE)を、既存の建物(共有建物 TYPE_BUILDING か、国境検問所のような TYPE_DEFAULT の建物)へ入居済み・稼働中の状態で1件作る。アイコンパネル(`hud/hudCommon.ts` の `MENU_ICONS`)の製作者向けグループにある「経済主体の作成」から開く(`agent_creation` ウィンドウ。テンプレートモードのときだけ表示)。通常プレイではスポーン→転居の2フェーズを経て建物に入る施設を、シナリオ制作では待たずに置くためのもの。

- 操作の流れ: 種別(民間施設/輸出入拠点)→ バリアント(プルダウン。その種別の `building=false` のもの)→「建物を選択」→ 3Dビューで入居先の建物をクリック → 占有階数 → 作成。
- **建物の選択は建物建設パネルの「既存建物をコピー」と同じUnityの選択モードを借りる**(`building_construction:pick_source` → `MODE_PICK_BUILDING` → `building_construction:copy_source`)。Unity側は「建物を1つ選ぶ」だけの汎用動作で、パネルは通知の `source_agent_id` だけを使う。同じ通知を2つのパネルが受けないよう、`agent_creation` と `building_construction` は `window-mutex-groups.json` で同時に開けない。選択待ちのままパネルを閉じたときは Rust側(`window.rs` の `EDIT_MODE_WINDOW_TYPES`)が `STATE_NORMAL` を送って選択モードを解く。
- **占有量の実体は面積(m²)で階の概念は無い**が、制作者には階数で指定させ、占有面積 = 階数 × 建物の1フロア面積(`base_area`)として送る。上限は選択中バリアントの `space_type` の空き面積(`capacity − occupied`)÷ 1フロア面積。非共有建物(`shared_building=false`)は1テナントが全床を占有する契約なので階数は固定表示で、既に入居者がいれば作成できない。TYPE_DEFAULT の建物(国境検問所)は市庁舎にいる支援拠点などと同じく所在だけを表す入居で、床種別と空きを扱わない。階数の上限は建物の階数で、空き面積は表示せず、同じ建物へ何件でも入居させられる。バリアントの `space_min` / `space_max` を外れる面積は作成ボタンを無効にして理由を表示する。
- 作成後は建物情報を取り直して空きを更新するので、同じ建物へ続けて入居させられる。3Dの再読み込みは不要(建物ではない経済主体は描画対象ではない)。

### 観光名所の選択(`building/BuildingConstructionPanel.tsx`)

建物建設パネルは、テンプレート作成モードのとき `template_only` のバリアントも候補に含める。選択中のバリアントを `agent_variant` に持つ行が観光名所マスターにあれば、名所セレクタを説明カードに出す(ID昇順)。

- 選択肢のうち `GET /api/v1/buildings/placed-landmarks` が返したIDは、既に都市にあるので無効化する(一覧の取得に失敗したときは無効化せず、バックエンドの拒否に任せる)。
- 名所を選ぶと階数と幅・奥行きの入力はロックされ、名所の固定値で表示される。選択値はプレビュー(区画・直接配置)・建設費見積・確定送信のすべてに `landmark` として載せる。
- 選択の変更は `edit_building:update_landmark` でUnityへ伝え、プレビューメッシュを名所専用のモデルへ差し替えさせる。直接配置の敷地寸法はUnity側が観光名所マスターから作り直し、`placement_state` で返す。
- 既存の建物を編集で開いたときは、自分自身を一点物の判定から外すため、プレビューと建設費見積に `exclude_agent_id` を添える。
- 「既存建物をコピー」の選択モードは観光名所を受け付けない。名所軸を持つバリアントと、通常プレイでの `template_only` バリアントが選ばれた通知は取り込まず、理由を通知して無視する。

## API

`/api/v1/templates/` 配下はいずれもテンプレート作成モード以外では403を返す。観光名所まわりのエンドポイントはモードに関わらず使える(設置そのものはバリアント単位のゲートで拒否される)。

### `POST /api/v1/templates/complete-construction`

計画中・建設中の全パス・全建物を、実プレイと同じ「着工フェーズ → 竣工フェーズ」を通して即時完成させる。そのため区画の収用・削除、路盤と交差点の地形平坦化、交差ノードの生成と交差点での分割まで通常どおり起きる。建物が立つ区画を横切るパスのように着工条件を満たさないものは計画中のまま残る。

レスポンス: `completed_paths` / `completed_buildings` / `remaining_paths` / `remaining_buildings`。シミュレーション本体を含まないモック配布ビルドでは501(`SIMULATION_DISABLED`)。

### `POST /api/v1/templates/street-grid`

リクエスト: `points`(範囲多角形の頂点 `[[x, z], ...]`、3点以上)、`spacing`(格子間隔m)、`path_variant`(街路のバリアント)、`angle_deg`(格子の主軸角度。省略で最寄り街路に揃える)。

格子線は互いの交点と既存道路の中心線との交点で分割し、1本ずつ独立したパスとして登録する。端点は既存道路の中心線へ吸着(15m)させるので、幹線に沿って描いた範囲の路地は一括完成時にT字で幹線へ接続される。海岸線の外・急勾配(バリアントの最大勾配)・川の横断・既存道路との平行な重複・建物のある区画への侵入は棄却する。

レスポンス: `path_ids` / `created` / `candidates` / `rejected`(理由別の本数) / `axis_angle_deg`。

### `POST /api/v1/templates/tenant-agent`

リクエスト: `variant`(経済主体のバリアント。type が TYPE_STANDARD / TYPE_TRADE かつ `building=false`)、`building_agent_id`(入居先の建物。TYPE_BUILDING か TYPE_DEFAULT の建物で、稼働中か休止中)、`floors`(占有する階数。共有建物と TYPE_DEFAULT の建物で有効。省略時1)。

スポーン・転居フェーズが行う入居の帳簿処理を1回で行う: 占有面積(= 階数 × `base_area`。非共有建物は容量の全量)の決定と `space_min` / `space_max` の検査、建物の `occupied[space_type]` への加算、地区・区画・座標の継承、家賃(建物の㎡単価)と賃金(地区平均)のシード、創業計画(確保面積いっぱいの生産目標と、それに見合う雇用枠)、`STATUS_ACTIVE` 化(理由=REASON_USER)。休止中(`STATUS_PAUSED`)の建物へ入居させた場合は建物も再稼働する。TYPE_DEFAULT の建物では床種別と空きを検査せず(階数は建物の階数まで)、`occupied` にも加算しない。空き不足・種別不一致・面積範囲外は 400(`VALIDATION_ERROR`)。

レスポンス: `agent_id` / `name` / `variant` / `building_agent_id` / `space_type` / `realestate_amount` / `floors`(実際に占有した階数) / `vacancy_after`(入居後の同種別の空き面積。TYPE_DEFAULT の建物は `null`)。

### `DELETE /api/v1/agents/{agent_id}` と `DELETE /api/v1/paths/{path_id}`

通常は着工前・計画中・保留中のものしか削除できないが、テンプレート作成モードでは、ブルドーザの即時削除として次のように動く。他のモードの動作は変わらない。

- **`agents`**: 建物(`is_bd`)を、ステータスを問わず、入居テナントの経済主体と世帯テナントの市民ごと削除する。建物ではない経済主体は通常の削除条件に従う。市政府・中央銀行(TYPE_CITY)と、代理主体・国境検問所(TYPE_DEFAULT)は、建物自身でも入居テナントでも含まれていれば、何も変更せず400で拒否する。輸出入拠点(港)は消せる。区画は消さずに `usage_id` を外して空き地にし、建物が所有していた区画は中央銀行へ移す(公共施設の敷地は市有のまま)。削除した主体を雇用先・在籍先にしていた市民は無職・未就学に戻り、残高は中央銀行(公共施設は市政府)へ移るので通貨量は保たれる。レスポンスは `message` に `deleted_agents`(建物とテナントの数)・`deleted_citizens`・`freed_parcel_ids` を加えたもの。
- **`paths`**: パスをステータスを問わず削除し、端点が孤立したノードを消す。外部接続・施設の接続端子・公共交通の停留所のノードは網の側の持ち物なので残す。公共交通の区間パス(`PATH_TRANSPORT`)は400で拒否する。経路・近隣区画の接道と横断・駅舎の所属・名前付き道路は、通常の削除と同じ `path.deleted` の連鎖で更新する。レスポンスは `message` に `path_id`・`deleted_node_ids` を加えたもの。

どちらも地形は元に戻さず、取り消せない。

### `GET /api/v1/master/landmarks`

観光名所マスターを、名所IDをキーとした辞書として `landmarks` に返す。値は `display_name` / `description` / `agent_variant` / `model_prefix` / `width` / `depth` / `floors` / `height_per_floor` / `cost_multiplier`。他のマスター取得と同じく、テンプレート作成モードかどうかに関わらず取得できる。

### `GET /api/v1/buildings/placed-landmarks`

すでにこの都市に存在する観光名所のID一覧を昇順で返す(`landmark_ids`)。稼働中・建設中・計画中・倒壊のいずれも「存在する」として数えるので、ここに含まれる名所は建てられない。これもモードに関わらず取得できる。

### 建設系エンドポイントの `landmark`

建物の建設(`POST /api/v1/buildings/`)、直接配置(`POST /api/v1/buildings/direct`)、プレビュー2種(`POST /api/v1/buildings/preview` と `POST /api/v1/buildings/preview-direct`)、建設費見積(`POST /api/v1/buildings/construction-cost`)は `landmark` を受け取る。指定した名所の `width` × `depth` が底面に、`floors` が階数に、`cost_multiplier` が建設体積の乗数になり、見積・プレビュー・確定が必ず同じ形と同じ金額になる。プレビュー2種と建設費見積は `exclude_agent_id` も受け取り、編集対象の建物を一点物の判定から外すために使う。建てた後の名所は `single_agent` / `multi_agent` スキーマの `landmark` から読める。

## 制約

- 路地作成は道路だけを作る。沿道の土地区画は作らないので、区画は土地区画作成パネル(ブロック一括・道路沿い)で別途作る。
- 一括完成はセーブデータ上の状態を直接進めるため元に戻せない。実行前にセーブしておくこと。
- ブルドーザの即時削除も元に戻せず、道路や建物が変えた地形も戻らない。消す前にセーブしておくこと。
- 経済主体作成は既存の入居先建物への入居だけを行う。専用建物(施設と建物が一体のバリアント)は建物建設パネルで建てる。世帯・学校・市政府は対象外。
- 国境検問所は自動の転居の入居先にならないので、陸路輸送・都市外旅客輸送拠点はこのパネルで入居させる。入居面積は階数(論理2階まで)× 1フロア面積で、空きを持たないので同じ建物へ何件でも入る。
- 観光名所は市政府の公共施設としてしか存在しない。建設系エンドポイントで作る建物は常に公共施設として登録され、民間の自動建設では建たない。
- 同じ観光名所は都市に1基まで。名所の種別(`landmark`)は建物の作成後に変更できないため、別の名所にしたいときは解体して建て直す。テンプレート作成モードでも変更は拒否される。
- 観光名所はコピー建設(既存建物の実寸コピー)のコピー元にできない。
- 底面が固定のバリアント(観光名所を含む)は、テンプレート作成モードに限り土地区画からはみ出したまま配置できる。通常プレイでは区画に収まらなければ建設できない。
