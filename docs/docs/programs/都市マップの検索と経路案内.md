# 都市マップの検索と経路案内

都市マップ(`city_map`)は、左の検索・経路案内と右の2D地図で構成する。場所の検索で施設・地区・駅・停留所・道路を選んで地図を合わせ、2地点の間の行き方を徒歩・公共交通か自動車で示す。

## 構成

`CityMapWindow` が地図・ツールバー・左ペインを組み立て、検索と経路の状態と通信は `CityMapNavigation.tsx` の `useMapNavigation` が持つ。状態はウィンドウの中だけに持ち、セーブに書かない。Unity には経路を描かせず、カメラも動かさない。

地図を描く `CityMapCanvas` はツールバーを持たない描画部品で、路線地図・道路の全体図・形状編集・統計の地区地図・地区編集など、局所の地図が要るパネルにも埋め込む。表示するレイヤーは props で選び、パネル固有の重ね描きはワールド座標のまま描画コールバックで行う。ヒートマップ・インフラ表示・地区の値塗りは、どれも地図を塗る表示なので同時に使わない。props の意味と再描画・再取得の条件は、このコンポーネントのコメントが正である。

## 地図の方位と座標

地形の標高配列は行0が南端で、列は西から東、行は南から北へ並ぶ。ワールド座標では列が +X、行が +Z なので、地理的な北は +Z・東は +X で、Unity の俯瞰・コンパス・カメラの yaw(北 = +Z を0とする時計回りの方位角)と一致する。2D地図は常に北が上で、Canvas の Y 軸は下向きなので、ビュー変換の Y 倍率を負にして +Z を画面の上に描く。個々の座標は反転させず変換行列で吸収するので、道路・建物・区画などはワールド座標のまま描け、文字や画像だけはその描画に限って Y の反転を打ち消す。ヒートマップの格子も同じ向き(行0が南)である。

## 場所の検索と経路案内

`/api/v1/navigation` の場所検索・地図上の地点の選択・経路の API は、一般のプレイヤー向けで、デバッグ機能の有効化を要さない。経路の地点は種類(`kind`)と ID で指定し、実体はコアが ID から場所を解決する。検索の候補には名前の付いた道路も入るが、道路は経路の地点にならないので、道路名の表示位置を座標の地点(`point`)として送る。

経路は直近の一括経路計算の時点の道路網で引く。その後の道路の編集や路線の変更は、次の計算まで案内に反映されない。UI は状態の API で計算の時点(`snapshot`)とシミュレーション中かを確かめ、変わったら経路を取り直す。示す経路はゲームが経路計算で選ぶもの(地区を結ぶ部分は地区の対ごとに1本)を見せるためのもので、任意の2地点の厳密な最短経路は保証しない。

経路は、インターチェンジの中も実際に走るランプや本線に展開した区間(`legs`)の列で返り、区間の形(`points`)はワールド座標の `[x, z]` の列である。`path_forward` は `path_ids` と同じ並びで各パスを始点→終点の向きに進むかを表し、公共交通の区間では `null` である。所要時間として出すのは物理的な時間の `minutes` で、`cost_minutes` は経路を選ぶための重み付きの値なので所要時間として出さない。

## 地図に重ねるデータ

- 陸地と水域は `GET /api/v1/terrain/coastline` の現在の海岸線(初期地形の陸地に、完了した埋立地を足したもの)で塗る。都市の矩形の外は、背景地形の遠景用海岸線(`GET /api/v1/terrain/background/coastline`)で陸地を塗る。標高の色分けと等高線は近景標高マップ(初期地形)から描くので造成や道路工事を反映せず、埋立地は `GET /api/v1/terrain/reclaimed-lands` の範囲を陸の色で上から塗る。
- 幹線道路は、高速道路と、道路(名前付き道路)に属する区間(`road_id` が1以上)である。判定はパスごとの `path_type` と `road_id` で行い、マスターは参照しない([パスとノード](../economics/3_パスとノード.md))。道路名は `GET /api/v1/roads/` の `label_points` の位置に、`angle_deg`(ワールドの XZ 面での道路の向き)へ回転させて描く。道路とインターチェンジ(`GET /api/v1/interchanges/`)はどちらも件数が少ないので都市全体を取り、道路は `roads:changed` を受けて取り直す。
- 公共交通の路線は `GET /api/v1/transit/lines/geometry` の走行形状で描く。停留所の間を直線で結ぶのではなく、下地の道路・線路に沿った折れ線を巡回の順に並べたものなので、単線を並べた複線の行きと帰りは別の線路の上に描かれる。
- 環境のヒートマップは、`GET /api/v1/city/heatmaps/{kind}` が原点(南西の隅)・実寸・LOD の一覧を返し、`GET /api/v1/city/heatmaps/{kind}/{lod}` が行優先の uint16(リトルエンディアン)で値を返す(0 が負荷なし、65535 が最悪)。発生源の強度(`GET /api/v1/city/environment-sources/{kind}`)は都市全体の最大値に対する値なので、表示範囲を動かしても色の意味は変わらない。
- インフラの表示は、インフラ財の網を `GET /api/v1/stats/infrastructure` から、財の供給施設と効果範囲を `GET /api/v1/buildings/service-coverage/{product_id}` から描く。範囲の内外はコアが敷地の土地区画で判定するので、境界の近くでは輪郭の内側に見える建物が範囲外になることがある。
