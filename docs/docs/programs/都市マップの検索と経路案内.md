# 都市マップの検索と経路案内

都市マップは左の検索・経路案内と右の地図から構成する。検索候補から施設、地区、駅、停留所、道路を選ぶと、その地点（道路なら道路の区間）を強調し、地図の表示範囲を移動する。「ここへの行き方」で目的地を保持したまま経路入力へ切り替える。出発地・目的地は検索と地図クリックの両方で指定でき、入れ替えもできる。移動手段は徒歩・公共交通と自動車の2種類で、入力確定後に自動検索する。

## 実装の責務

検索・経路案内ペインはゲーム共通の`App.css`の`--flat-*`トークンで配色し、濃紺の背景、角丸のない操作部品、青い選択面と左端のアクセントで状態を示す。地図上の経路と地点マーカーも同じトークンを参照し、出発地は緑、目的地は黄で表示する。公共交通は設定された路線色を優先する。

`CityMapWindow`は地図・ツールバー・左ペインを組み立てる。ツールバー(レイヤー・ヒートマップ・全体表示・再読み込み)は`CityMapControls`が持つ。検索と経路の状態・HTTP通信は`CityMapNavigation.tsx`の`useMapNavigation`、描画基盤は`CityMapCanvas`が担当する。状態はウィンドウ内だけに保持し、セーブデータへは書き込まない。Unityへの経路描画やカメラ移動は行わない。

地図はマウスとタッチで操作でき、1本指(左ボタン)でパン、2本指でピンチズームする。`CityMapCanvas.onMapClick`は左ボタン・タップの移動が5px未満の場合に通知し、ピンチに入った操作はクリックにしない。ドラッグ中に一度でも閾値を超えると、押下地点へ戻ってから離してもクリックにしない。従来のカスタムドラッグ用コールバックとは独立しており、経路選択中も通常のパンができる。地図選択はEscまたはキャンセルボタンで解除する。

ズームには`fitBounds`、経路・選択ポリゴン・A/Bマーカーには`overlayDraw`を利用する。既存のUnityカメラ位置マーカーも同じ描画コールバックで重ねる。線幅とマーカーは画面ピクセルで一定にする。地図の変換はY反転を含むので、文字はその描画に限りY反転を打ち消して正立させる。徒歩と道路への接続は点線、自動車は青、公共交通は路線色で描く。案内区間をクリックするとその区間だけを強調して表示範囲を合わせる。

## 公共交通路線レイヤー

ツールバーの「公共交通路線」レイヤーは、都市内の全路線を実際の下地道路・線路に沿った帯として描く。停留所間を直線で結ぶ路線図ではなく、車両が走る経路そのものを示す。データは`GET /api/v1/transit/lines/geometry`が返す走行形状で、バックエンドが各路線の停留所間走行プロファイル(`journeys`)を下地パスのベジエ形状から切り出した`[x, z]`折れ線である。路線は停留所を巡回順にたどって先頭へ戻るループで、区間ごとの形状が巡回順に並ぶ。単線のパスを並べて敷いた複線は上下線が別々のパスなので行きと帰りが別の線路上に描かれ、1本のパスで上下線を持つ複線（鉄道・モノレールを1本で敷く複線、LRT）とバスなどの街路走行は行きと帰りが同じ道路・線路に重なる。

稼働中の路線は路線カラーの帯で、各停留所間の中点に進行方向の矢印を置く。運休中の路線は灰色の破線になり、下地経路が成立せず走行形状を持たない路線は区間の端点を結ぶ直線を灰色の破線で描いて位置だけを示す。停留所は路線カラーのリングで、複数路線が共有する停留所は白いリングにする。

同じレイヤーは路線詳細の「路線地図」タブにも使われ、当該路線を主役にして巡回の先頭の停留所を緑、車両が折り返す停留所（往復運行の端）を赤のリングで強調し、周辺の他路線は薄く描く。路線の新設・設定変更・廃止のあとはウィンドウ内イベントで形状を取り直す。形状は都市全体を一括で取得するため、地図の表示範囲を動かしても再取得しない。

## 地図の方位と座標

地形の標高配列は行0が南端で、列は西→東、行は南→北に並ぶ。ワールド座標への変換は`x = 列 × 間隔 − 幅/2`、`z = 行 × 間隔 − 高さ/2`なので、地理的な北は`+Z`、東は`+X`となり、Unityの俯瞰・コンパス・カメラyawと一致する。都市マップと埋め込み地図は北上固定で、CanvasのY軸は下向きなので、ビュー変換のY倍率を負にして`+Z`を画面の上に描く。個々の座標は反転せず変換行列で吸収するため、道路・建物・区画などの描画はワールド座標のまま行う。

画面座標は`screenX = (x − offsetX) × zoom`、`screenY = (offsetY − z) × zoom`で、`offsetY`は画面上端のワールドZ(表示範囲の北端)である。クリック、パン、カーソル中心のズーム、範囲フィット、道路形状編集のヒット判定、静的・アニメーションの重ね描きは同じ変換を使う。Unityカメラのyawは北(`+Z`)を0度とする時計回りの方位角で、カメラマーカーは`(sin(yaw), cos(yaw))`のワールド方向をこの地図変換へ渡す。

## HTTP契約

いずれも`/api/v1/navigation`配下の一般プレイヤー向けAPIで、デバッグ機能の有効化を必要としない。手書きの要求・応答型を使用し、生成ファイルは編集しない。

| API | 内容 |
|---|---|
| `GET /places?q=…&limit=20` | 都市全体の場所検索。候補は最大50件。名称・種別・地区名・座標・選択用ポリゴンを返す。ポリゴンはワールド座標の[x,z]列で、建物の中心座標基準のローカル底面ポリゴンもサーバー側でワールド座標へ直して返す。名前の付いた道路は`kind`=road（`id`=道路ID、座標=最初の道路名の表示位置、地区=最もIDの小さい区間の所属地区、ポリゴンは空）として含まれ、名前の無い道路は含まれない。道路・駅・停留所の地区は、その道路（駅舎・ホーム）の両面が同じ地区のときのその地区で、2地区の境界にあるものは地区を持たない |
| `GET /pick?x=…&z=…&radius=…` | クリック付近の施設・駅・停留所、または名前のない座標地点を返す。radiusは1〜100m |
| `GET /status` | session、snapshot、epoch、ready、busyを返す |
| `POST /route` | origin、destination、modeを受け、区間列を返す読み取り専用API。同じ経路計算は[市民の追跡](市民の追跡.md)の行程にも使う |

地点の要求は`kind`（agent/zone/stop/station/point）、`id`、`x`、`z`。実体を選んだ場合はIDからサーバー側で場所を解決する。任意地点だけが要求座標を使う。道路は経路の地点にならないため、道路を出発地・目的地に選んだときは、候補の座標（道路名の表示位置）をpointとして送る。modeはpedestrianまたはautomobile。

成功時はstatus=ok、snapshot、epoch、minutes、distance_m、fare、cost_minutes、legsを返す。各区間はkind、points（ワールド座標の[x,z]列）、path_ids、path_forward（path_idsと同じ並びで、各パスを始点→終点の向きに進むか。公共交通の区間はnull）、line_id、name、color、minutes、distance_m、from_stop、to_stopを持つ。kindはwalk、drive、transit、conveyor、access、turn。cost_minutesは経路選択用の値であり、所要時間として表示しない。

自動車の経路探索はインターチェンジ（IC/JCT）を1つの交差点として扱うが（[道路網](../economics/3_道路網.md#インターチェンジとジャンクション)）、応答ではインターチェンジ内の移動も実際に走るランプや本線ごとのdrive区間に展開して返す。インターチェンジの入口と出口を直線で結ぶ区間は作らない。

失敗はnot_ready（経路未計算）、busy（シミュレーション中）、unreachable（接続なし）、no_access（道路へ接続できない）、place_missing（実体削除）、geometry_unavailable（公共交通の走行形状なし）で区別する。

## 経路の時点と表示上の意味

経路は直近の一括経路計算時点の道路網を使う。その後の道路編集・路線変更は、次の経路計算まで案内へ反映されない。画面には計算時点と、所要時間が目安であることを表示する。都市をロードした直後など表示用経路情報が無いときは、シミュレーション実行後に利用できる旨を案内する。

推奨経路は1本。ゲームの経路計算を可視化するため、任意2地点の厳密な最短経路を保証しない。地区をまたぐ経路はゲームが地区の対ごとに1本選ぶもの（地区の典型的な出発地から典型的な目的地までの負担が最も小さい行き方。歩く時間は長いほど重く評価され、公共交通は待ち時間と運賃を加味する）で、出発地・目的地の地区内の区間だけを指定した地点に合わせて付け足す。表示する所要時間は物理時間で、この選択に使った負担の重み付けは含まない。駅舎を乗らずに通り抜ける区間([駅の出入口](../economics/29_駅と駅舎.md#297-駅の出入口))は、運賃を0とし、所要時間に待ち時間を含めない。道路までの接続は点線で示し、道路のない場所を車で走れることを意味しない。駅舎に所属するホームの停留所への接続は、駅舎の出入口を折れ点にして描く。公共交通の下地形状が無い場合は、停留所同士の直線で代用せず表示不可として返す。

検索は220msのデバウンス、通信はAbortControllerで競合を防ぐ。状態APIを3秒間隔で確認し、都市切替時は地点選択を消し、スナップショットの更新やシミュレーション中への遷移で経路を失効させる。再読み込みは地図・経路・候補を更新する。日本語を原本として全7言語に`mapNavigation`を持つ。

## 地図座標の検証

`tauri`で`node tools/map-orientation-test.mjs`を実行する。実コンポーネントの描画とポインタイベントをDOM・通信の代替環境で動かし、北(`+Z`)が上であること、地名ラベルが正立して地点と同じ位置に出ること、クリックと道路編集の座標一致、パン、カーソル中心ズーム、範囲フィット、アニメーション重ね描きの一致をDPR=2で検証する。あわせて、幹線道路レイヤーが高速道路と道路に属する区間だけを描き、`road_id`の無い街路（-1・0）はすべての道路レイヤーで一般道路の色になることを、実際の`hasRoad`で確かめる。

## ベースマップの描画

都市マップと埋め込み地図では、レイヤーがONでも細部の形状は拡大率に応じて表示する。拡大率はステータス表示と同じ`zoom × 100%`で、100%はワールド座標1mを画面上の1pxに対応させる。

| 形状 | 表示する拡大率 |
| --- | --- |
| 幹線道路以外の街路・歩道 | 30%超 |
| 建物の底面形状・公園の面 | 70%超 |
| 土地区画の枠線 | 100%超 |

閾値ちょうどでは表示せず、ズームアウトで閾値以下になると非表示にする。幹線道路・線路・駅、施設の記号と名前、ヒートマップ、選択や編集中の重ね描きにはこの形状の閾値を適用しない。施設の記号と名前は後述の表示基準に従う。レイヤーのON/OFF状態はズームで変更しない。

都市マップと埋め込み地図は、薄緑（`#d3f8e2`）で均一に塗った陸地、青い海・川・湖、淡灰色の建物と一般道路、濃灰色の高速道路で表示する。幹線道路は**高速道路と、道路（名前付き道路）に属する区間**（パス一覧の`road_id`が1以上）で、道路に属する街路は一般道路より濃い灰色にする。判定はパスごとの`path_type`と`road_id`で行い、マスターは参照しない（[道路網の幹線道路](../economics/3_道路網.md#幹線道路)）。「幹線道路」レイヤーは幹線道路だけを、「すべての道路」レイヤーはそれ以外の道路（道路に属さない街路・歩道）を描くので、高速道路の表示は幹線道路レイヤーに従う。標高色分けは共通で既定OFF。「海岸線」の切り替えは岸の輪郭だけに作用し、陸地と水域の面は常時残る。

`GET /terrain/coastline`の陸地Polygon/MultiPolygonをeven-oddで塗り、内周リングの川・湖を水域として抜く。標高表示をONにした場合も陸地でクリップするため、内陸の水域を標高色で埋めない。海岸線を取得できない場合は標高配列の陸海色を代用する。通常表示の陸地色はポリゴンと標高配列で同じ定義を使い、取得状況によって色が変わらないようにする。岸の形はAPIが返す現在の海岸線で、新規都市の初期地形から抽出した陸地に、完了した埋立地の範囲を足したもの（[地形形状](../geometries/D_地形形状.md) §D.17.4）。標高表示がOFFなら、埋立地は海岸線ポリゴンの塗りで自動的に陸地色になる。

都市の外は、背景地形の遠景用海岸線(`GET /terrain/background/coastline`。[地形形状](../geometries/D_地形形状.md#都市外の背景地形))を都市の矩形の外だけ陸地色で塗る。標高表示の有無によらず同じ陸地色で、標高色分け・等高線・グリッド・海岸線の輪郭は都市内だけに描く。都市の陸地との境目に水色の筋が出ないよう、都市の矩形を1画素縮めた外側を塗って境界の画素を重ねる。背景の無いマップでは都市の外は水域になる。都市の矩形(詳細地形の範囲)は、どこまでを都市として使えるかが分かるように、レイヤーの設定に依らず灰色の点線で常に囲む。点の大きさと間隔は画面上で一定で、道路・線路の上、ラベルの下に描く。遠景用海岸線はマップ作成時に作られた固定のデータだが、セッションが変わるとマップも変わりうるので、初期化と再読み込みのたびに取り直す。

標高表示をONにすると、都市内の陸地の最低・最高標高を基準に、低地の薄いベージュから高地の緑へ色分けする。地表種別によらず同じ配色を使い、斜面の勾配から北西の光による陰影を重ねて尾根と谷を見せる。勾配は標高格子の実距離で求めるため、ズームで陰影の強さは変わらない。色と陰影は地形取得時に画像へ焼き込み、パン・ズームではその画像を拡縮する。

標高色分けと等高線は近景標高マップ（`GET /terrain/near`。初期地形）から描くので、造成・道路工事による地形の変化は反映しない。埋立地の範囲は初期地形では海なので、標高表示をONにすると海の色で塗られてしまう。そこで `GET /terrain/reclaimed-lands` の `polygon` を読み、標高表示がONのときだけ、標高色の上から埋立地の範囲を陸の最低標高の色（薄いベージュ）で塗る。埋立地の高さ（天端の高さ）は保存されない派生値なので、実際の標高の色にはしない。範囲に元から陸だった部分が含まれていても、範囲全体を同じ色で塗る。埋立地の一覧は地形・海岸線と一緒に、初期化と再読み込みのたびに取り直す。

建物はローカル底面ポリゴンを中心座標へ平行移動し、淡灰色の面と細い輪郭で描く。公園はバリアントの`model_type=MODEL_PARK`で判別し、陸地より一段濃い緑（`#a8dab5`）の面にする。公園も建物レイヤーで表示を切り替える。マスターデータが後から届いた場合も分類を更新する。

道路は占有ポリゴンを優先し、終端を丸い線端で膨らませない。ノードIDを共有する2本の道路が向かい合う接続では、中心線から共有断面を作り、太い道路の幅を細い道路の幅へ滑らかに絞る。遷移距離は太い側の幅の1.5倍を基本とし、短区間では半長までに制限する。曲線は保存済みベジエ制御点を優先し、平坦度0.15mを基準に細分化する。これは2D地図用の表現であり、Unityの歩道・交差点メッシュそのものではない。多方向の交差点は各道路の占有面の重なりで表現する。実幅が画面上1px未満の遠景だけ、平らな端の最小幅中心線を補う。

鉄道は灰色の実線。公共交通レイヤーではその上に路線カラーの4px帯と7pxの白い縁取り、停留所の白い芯を描く。運休・走行形状なしの路線は従来の灰色破線で区別する。環境オーバーレイ・地区の値塗りは公園を含む地表の上、道路と建物の下に敷く。

道路面の検証は`tauri`で`node tools/map-road-surface-test.mjs`を実行する。平らな終端、4mから24mへの幅遷移、短区間、曲線、共有断面の一致を確認する。座標と操作は上記`map-orientation-test.mjs`で検証する。

## 環境オーバーレイと発生源

環境ボタンは騒音・大気汚染・治安・日照の排他選択で、区画形状によらず表示用格子の画像を地図へ重ねる。値は0〜1の固定の悪さスコアで、0は透明、負荷が上がるほど色と不透明度を強める。日照は影時間割合から得た悪さを示す。地形と同じく行0が南端で、原点と実寸を使って配置する。計算範囲外は塗らない。

表示用LODはエポック中に作られる。最細の格子でも5m以上、最大辺は2000画素で、引いた視点では低解像度を取得する。UIは画素の画面上の大きさからLODを選び、取得した画像の色付け結果をキャッシュする。パン・ズームでは画像を拡縮し、同じLODを再取得・再着色しない。環境の選択変更・再読み込みではキャッシュを破棄する。

「発生源」のスイッチをONにすると、騒音・汚染は建物の底面と道路・線路を拡散前の強度で塗り分ける。パスの保存済み強度と稼働中の建物のマスター強度を使い、都市全体で同じ最大値を色の基準にするため、表示範囲を動かしても色の意味は変わらない。負荷ゼロの物体は通常の色を保つ。日照・治安はスイッチの位置によらずオーバーレイを表示する。発生源も既存のレイヤー表示設定に従うが、通常表示の細部を省く縮尺でも形状を表示する。

| API | 応答 |
| --- | --- |
| `GET /api/v1/city/heatmaps/{kind}` | `origin_x`・`origin_z`（南西の原点）、`width_m`・`height_m`（実寸）、固定レンジ`min=0`・`max=1`、`levels`（`rows`・`cols`・`spacing`） |
| `GET /api/v1/city/heatmaps/{kind}/{lod}` | 選択LODの行優先uint16 LEバイナリ。0=負荷なし、65535=最悪 |
| `GET /api/v1/city/environment-sources/{kind}` | `path_ids`・`path_values`、`building_ids`・`building_values`と実値レンジ`min`・`max`。値は都市全体の最大強度に対する0〜65535 |

格子の`kind`は`noise`・`pollution`・`crime`・`sunshine`、発生源は`noise`・`pollution`だけを受け付ける。格子未計算は空の`levels`、存在しないLODは404。格子はセーブ対象外で、ロード後は次のエポックまで未計算となる。検証は`tauri`で`node tools/map-heatmap-test.mjs`と`node tools/map-orientation-test.mjs`を実行する。

## 地区名・公共施設・駅

地区の中心点に地区名を白い縁取りの文字で表示する。地区枠線の表示とは独立している。公共施設は実際の中心座標に丸いマーカーを置き、名前を添える。病院は医療の十字、警察は盾、消防は炎、学校・大学は卒業帽、駅は列車の専用記号を使用する。発電所・変電所・取水施設・地下水／水道ポンプ・下水処理場・ゴミ処理場・市庁舎にも専用記号を用意する。

その他の施設は`public_facility`が真なら中央に丸を持つ汎用マーカーで表示する。電波塔、車両基地、バス車庫、美術館、展望台、客船ターミナルなどが該当する。分類は翻訳された名前ではなく種別・バリアントに基づく。記号は`mapSymbols.ts`で定義した独自ベクターで、外部地図サービスの画像を取り込まない。

施設記号は建物レイヤー、駅記号は駅レイヤーに追従する。駅は駅舎ごとに1記号を置き、所属するプラットフォーム群の凸包を赤い半透明の面と輪郭で示す。施設名は保存名、未設定の場合はマスターの表示名を使う。配置の優先度は 地区名 → 駅・インターチェンジの記号 → 駅・インターチェンジの名前 → 道路名 → 施設記号 → 施設名 で、施設名は記号の左右どちらかに収まる側へ描く。画面外や重なる表示は省く。施設記号はzoom 0.04以上、施設名は0.1以上で表示し、ズームしても文字と記号の画面上の大きさは固定する。

インターチェンジ(IC/JCT)は、バックエンドがランプ用バリアントの道路群から自動検出したものを`GET /api/v1/interchanges/`で都市全体まとめて取得し、中心座標に緑の丸とクローバー型の記号を置いて名前を添える。未命名のものは種別の略号とID(`IC #3`・`JCT #5`)で表す。件数が少ないため、地区と同じくベクターの取得や再読み込みのたびに取り直し、エポック実行や道路編集による検出結果の変化に追従する。取得に失敗しても他のレイヤーの描画は止めない。記号と名前の配置優先度は駅の次、道路名と施設記号より前で、インターチェンジレイヤーに追従する。

## 道路名と区間の強調

道路（名前付き道路。[道路網](../economics/3_道路網.md#35-道路名前付き道路)）の名前は、`GET /api/v1/roads/`の`label_points`の位置に描く。道路一覧は件数が少ないので都市全体をまとめて取得し、インターチェンジと同じくベクターの取得や再読み込みのたびに取り直す。取得に失敗しても他のレイヤーの描画は止めない。道路名は幹線道路レイヤーに追従する。

- 文字は道路色で白い縁取りを付け、`angle_deg`（ワールドXZでの道路の向き）に沿って回転させる。地図は+Zを上に描くので画面の角度は符号が逆になり、文字が逆さにならないよう(-90°, 90°]に畳む。
- 名前の無い道路は描かない（Unityの3Dラベル・場所検索とも共通）。
- 衝突判定は、回転した文字の基線に沿って文字の高さ四方の箱を並べて近似する（外接矩形1つだと斜めの長い名前が周囲を広く塞ぐため）。文字の両端が画面の端に掛かるもの、先に置いたラベルと重なるものは省く。道路ID・位置の順に置き、取得順で配置の勝ち負けが揺れないようにする。

道路の作成・改名・所属の変更・削除では、Tauriのグローバルイベント`roads:changed`を受けて道路一覧とパスだけを取り直す（所属が変わるとパスの`road_id`、つまり幹線の分類も変わるため。区画・建物・地区は取り直さない）。取り直す範囲は取得済みの範囲のままで、取得済みの表示は消さずに上書きする。区間編集モードではクリックのたびに通知が届くので、150ms以内の通知はまとめる。読み込み中なら終わってから取り直す。非表示の地図ウィンドウは取り直さず、フォーカスを得たときに取り逃した分を反映する。

`CityMapCanvas`は1本の道路の区間を強調するpropsを持つ。

| props | 内容 |
|---|---|
| `focusPathIds` | 強調する区間のパスID。白い縁取りの上に道路色の帯を、道路・線路・公共交通路線の上、ラベルの下に描く |
| `focusColor` | 帯の色（道路の色）。未指定なら`ROAD_COLOR_PALETTE`の先頭 |
| `previewPathIds` | 確定前の候補（直進方向への延長の候補）。同じ色の破線で描く |
| `focusDimOthers` | trueなら、強調か候補があるときに他の道路・線路を薄くする |

帯は取得済みのパス（表示範囲の周辺）から組み立てるので、範囲の外の区間は描かれない。道路・線路のレイヤーをすべてOFFにしていても、強調か候補があればパスを取得する。道路詳細パネルの全体図はこれらをすべて使い（[道路の詳細と道路名](道路の詳細と道路名.md#タブ)）、都市マップは場所検索で選んだ道路に`focusPathIds`と`focusColor`だけを使う。

場所検索で道路（`kind`=road、候補の左に`═`の記号）を選ぶと、`GET /api/v1/roads/{id}`で`bbox`と`path_ids`を取り、道路全体が収まるよう表示範囲を合わせて区間を強調する。強調は、その道路が目的地、または経路案内中の出発地として選ばれている間だけ出す。

## レイヤーの初期状態とツールバー

既定でONにするのは建物、駅、インターチェンジ、すべての道路、幹線道路、線路の6種類。公共交通路線、土地区画、地区枠線、海岸線の輪郭、標高、等高線、グリッドはOFF。陸地・水域の面、都市の範囲の点線、地区名は常時表示する。

レイヤー・ヒートマップ・全体表示・再読み込みは角丸のアイコンボタンで表示する。説明はホバー時のツールチップで読み取れ、キーボード操作時はフォーカス枠とアクセシブル名を持つ。トグルの選択状態は色・枠と`aria-pressed`で表す。ヒートマップは従来どおり排他選択。

`node tools/map-labels-test.mjs`は施設分類、海外でも読める学校記号、地区名の座標、表示の衝突回避と画面外除外、駅・インターチェンジの記号と名前→道路名→施設の配置優先度、名前の無い道路を描かないこと、道路名の回転が正立に収まることを検証する。

## 埋め込み地図（CityMapCanvas）の契約

2Dパス形状編集パネルでは、アンカーとベジエ制御点を結ぶハンドル線を、不透明な濃い紫（`#7c3aed`）の点線で重ね描きする。淡い地形色の上でも制御点とのつながりを判別できる配色にする。

`map/CityMapCanvas` はツールバー等を持たない純粋な描画部品で、局所地図が必要なパネル（路線地図・道路の全体図・形状編集・統計の地区地図・路地作成）はこれを埋め込む。周辺の道路・区画・建物はレイヤーに任せ、敷設中の要素などは `overlayDraw` でワールド座標に重ね描きする。

- レイヤーは `layers` prop で個別にON/OFFする。埋め込みの共通既定は上記の6種類のみONで、公共交通路線（`transitLines`）は都市全体の形状取得を伴うため既定OFF。
- `overlayDraw` の描画内容を変えたら `overlayVersion` を進めて再描画を要求する（コールバックの差し替えだけでは再描画しない）。連続アニメーションは `animatedOverlayDraw`（マウス操作を透過する第2キャンバスに毎フレーム描く。ベース地図は再描画されない）。
- 表示範囲の追従は ref の `fitBounds(bounds)` で行う（ビュー変換だけを更新する）。`initialBounds` prop は初期化用で、毎回変えると地形・ベクターの再取得が走る。
- `onPointerDown` が `true` を返したドラッグはパンにせず呼び出し側に委ねる（ノード移動など）。右クリックは常に既定メニューを抑止する。
- ヒートマップは `heatmap` prop（`none`/`noise`/`pollution`/`crime`/`sunshine`）の排他選択で、複数ONにできるレイヤーとは別系統。値は区画単位（[環境](../economics/19_環境.md#196-ヒートマップによる空間計算)）なので区画ポリゴンの塗り分けで描き、段階に量子化して同色の区画を1回の fill にまとめる。塗りは相対値なので、実値のレンジと件数を `onHeatmapStats` で通知して凡例に併記する（件数0=未計算）。ヒートマップON中は区画レイヤーがOFFでも区画データを取得する。
- 地区単位の値塗りは `zoneFill` prop（`{values: Map<zone_id, 0〜1>, ramp?}`）。ヒートマップと排他で、地区枠線より先に敷く（枠線と併用でき、枠線OFFでも地区データを取得する）。既定ランプは低=赤・高=緑で、悪さスコアを塗るヒートマップとは向きが逆。正規化と実値レンジの保持は呼び出し側の責務。`overlayDraw` で地区を塗ってはいけない（全レイヤーの後に呼ばれるので道路・建物・枠線まで覆う）。
- `interactive=false` で静的な埋め込み表示になり、方位コンパス（`showCompass`。省略時は `interactive` に追従）も出ない。
