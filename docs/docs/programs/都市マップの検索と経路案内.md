# 都市マップの検索と経路案内

都市マップは左の検索・経路案内と右の地図から構成する。検索候補から施設、地区、駅、停留所を選ぶと、その地点を強調し、地図の表示範囲を移動する。「ここへの行き方」で目的地を保持したまま経路入力へ切り替える。出発地・目的地は検索と地図クリックの両方で指定でき、入れ替えもできる。移動手段は徒歩・公共交通と自動車の2種類で、入力確定後に自動検索する。

## 実装の責務

検索・経路案内ペインはゲーム共通の`App.css`の`--flat-*`トークンで配色し、濃紺の背景、角丸のない操作部品、青い選択面と左端のアクセントで状態を示す。地図上の経路と地点マーカーも同じトークンを参照し、出発地は緑、目的地は黄で表示する。公共交通は設定された路線色を優先する。

`CityMapWindow`は地図・ツールバー・左ペインを組み立てる。検索と経路の状態・HTTP通信は`CityMapNavigation.tsx`の`useMapNavigation`、描画基盤は`CityMapCanvas`が担当する。状態はウィンドウ内だけに保持し、セーブデータへは書き込まない。Unityへの経路描画やカメラ移動は行わない。

`CityMapCanvas.onMapClick`は左ボタンの移動が5px未満の場合に通知する。ドラッグ中に一度でも閾値を超えると、押下地点へ戻ってから離してもクリックにしない。従来のカスタムドラッグ用コールバックとは独立しており、経路選択中も通常のパンができる。地図選択はEscまたはキャンセルボタンで解除する。

ズームには`fitBounds`、経路・選択ポリゴン・A/Bマーカーには`overlayDraw`を利用する。既存のUnityカメラ位置マーカーも同じ描画コールバックで重ねる。線幅とマーカーは画面ピクセルで一定にする。文字描画にもY反転は加えない。徒歩と道路への接続は点線、自動車は青、公共交通は路線色で描く。案内区間をクリックするとその区間だけを強調して表示範囲を合わせる。

## 公共交通路線レイヤー

ツールバーの「公共交通路線」レイヤーは、都市内の全路線を実際の下地道路・線路に沿った帯として描く。停留所間を直線で結ぶ路線図ではなく、車両が走る経路そのものを示す。データは`GET /api/v1/transit/lines/geometry`が返す走行形状で、バックエンドが各路線の停留所間走行プロファイル(`journeys`)を下地パスのベジエ形状から切り出した`[x, z]`折れ線である。複線の往路・復路は別の線路上に描かれ、バスなどの街路走行は往路と復路が同じ道路に重なる。

稼働中の路線は路線カラーの帯で、各停留所間の中点に進行方向の矢印を置く。運休中の路線は灰色の破線になり、下地経路が成立せず走行形状を持たない路線は区間の端点を結ぶ直線を灰色の破線で描いて位置だけを示す。停留所は路線カラーのリングで、複数路線が共有する停留所は白いリングにする。

同じレイヤーは路線詳細の「路線地図」タブにも使われ、当該路線を主役にして始点を緑、終点を赤のリングで強調し、周辺の他路線は薄く描く。路線の新設・設定変更・廃止のあとはウィンドウ内イベントで形状を取り直す。形状は都市全体を一括で取得するため、地図の表示範囲を動かしても再取得しない。

## 地図の方位と座標

地形の標高配列は先頭行が北、列は西→東、行は北→南に並ぶ。ワールド座標への変換は`x = 列 × 間隔 − 幅/2`、`z = 行 × 間隔 − 高さ/2`なので、地理的な北は`-Z`、東は`+X`となる。都市マップと埋め込み地図は北上固定で、Canvasの下向きY軸に`+Z`を対応させる。元の標高・道路・建物などの座標やセーブデータは変更しない。

画面座標は`screenX = (x − offsetX) × zoom`、`screenY = (z − offsetY) × zoom`。クリック、パン、カーソル中心のズーム、範囲フィット、道路形状編集のヒット判定、静的・アニメーションの重ね描きは同じ変換を使う。Unityカメラのyawは`+Z=0度`の回転角であり、地理的な北を基準とする方位角ではない。カメラマーカーは`(sin(yaw), cos(yaw))`のワールド方向をこの地図変換へ渡す。

## HTTP契約

いずれも`/api/v1/navigation`配下の一般プレイヤー向けAPIで、デバッグ機能の有効化を必要としない。手書きの要求・応答型を使用し、生成ファイルは編集しない。

| API | 内容 |
|---|---|
| `GET /places?q=…&limit=20` | 都市全体の場所検索。候補は最大50件。名称・種別・地区名・座標・選択用ポリゴンを返す |
| `GET /pick?x=…&z=…&radius=…` | クリック付近の施設・駅・停留所、または名前のない座標地点を返す。radiusは1〜100m |
| `GET /status` | session、snapshot、epoch、ready、busyを返す |
| `POST /route` | origin、destination、modeを受け、区間列を返す読み取り専用API |

地点の要求は`kind`（agent/zone/stop/station/point）、`id`、`x`、`z`。実体を選んだ場合はIDからサーバー側で場所を解決する。任意地点だけが要求座標を使う。modeはpedestrianまたはautomobile。

成功時はstatus=ok、snapshot、epoch、minutes、distance_m、fare、cost_minutes、legsを返す。各区間はkind、points（ワールド座標の[x,z]列）、path_ids、line_id、name、color、minutes、distance_m、from_stop、to_stopを持つ。kindはwalk、drive、transit、conveyor、access、turn。cost_minutesは経路選択用の値であり、所要時間として表示しない。

自動車の経路探索はインターチェンジ（IC/JCT）を1つの交差点として扱うが（[道路網](../economics/3_道路網.md#インターチェンジとジャンクション)）、応答ではインターチェンジ内の移動も実際に走るランプや本線ごとのdrive区間に展開して返す。インターチェンジの入口と出口を直線で結ぶ区間は作らない。

失敗はnot_ready（経路未計算）、busy（シミュレーション中）、unreachable（接続なし）、no_access（道路へ接続できない）、place_missing（実体削除）、geometry_unavailable（公共交通の走行形状なし）で区別する。

## 経路の時点と表示上の意味

経路は直近の一括経路計算時点の道路網を使う。その後の道路編集・路線変更は、次の経路計算まで案内へ反映されない。画面には計算時点と、所要時間が目安であることを表示する。都市をロードした直後など表示用経路情報が無いときは、シミュレーション実行後に利用できる旨を案内する。

推奨経路は1本。ゲームの経路計算を可視化するため、任意2地点の厳密な最短経路を保証しない。道路までの接続は点線で示し、道路のない場所を車で走れることを意味しない。公共交通の下地形状が無い場合は、停留所同士の直線で代用せず表示不可として返す。

検索は220msのデバウンス、通信はAbortControllerで競合を防ぐ。状態APIを3秒間隔で確認し、都市切替時は地点選択を消し、スナップショットの更新やシミュレーション中への遷移で経路を失効させる。再読み込みは地図・経路・候補を更新する。日本語を原本として全7言語に`mapNavigation`を持つ。

## 地図座標の検証

`tauri`で`node tools/map-orientation-test.mjs`を実行する。実コンポーネントの描画とマウスイベントをDOM・通信の代替環境で動かし、北上、クリックと道路編集の座標一致、パン、カーソル中心ズーム、範囲フィット、アニメーション重ね描きの一致をDPR=2で検証する。地理的な向きは元の標高配列の行順を基準とし、Unityのカメラ方位だけから北を判断しない。

## ベースマップの描画

都市マップと埋め込み地図は、薄緑（`#d3f8e2`）で均一に塗った陸地、青い海・川・湖、淡灰色の建物と一般道路、濃灰色の高速道路で表示する。幹線街路は一般道路より濃い灰色とする。標高色分けは共通で既定OFF。「海岸線」の切り替えは岸の輪郭だけに作用し、陸地と水域の面は常時残る。

`GET /terrain/coastline`の陸地Polygon/MultiPolygonをeven-oddで塗り、内周リングの川・湖を水域として抜く。標高表示をONにした場合も陸地でクリップするため、内陸の水域を標高色で埋めない。海岸線を取得できない場合は標高配列の陸海色を代用する。通常表示の陸地色はポリゴンと標高配列で同じ定義を使い、取得状況によって色が変わらないようにする。岸の形はAPIが返す初期地形に基づく。

建物はローカル底面ポリゴンを中心座標へ平行移動し、淡灰色の面と細い輪郭で描く。公園はバリアントの`model_type=MODEL_PARK`で判別し、陸地より一段濃い緑（`#a8dab5`）の面にする。公園も建物レイヤーで表示を切り替える。マスターデータが後から届いた場合も分類を更新する。

道路は占有ポリゴンを優先し、終端を丸い線端で膨らませない。ノードIDを共有する2本の道路が向かい合う接続では、中心線から共有断面を作り、太い道路の幅を細い道路の幅へ滑らかに絞る。遷移距離は太い側の幅の1.5倍を基本とし、短区間では半長までに制限する。曲線は保存済みベジエ制御点を優先し、平坦度0.15mを基準に細分化する。これは2D地図用の表現であり、Unityの歩道・交差点メッシュそのものではない。多方向の交差点は各道路の占有面の重なりで表現する。実幅が画面上1px未満の遠景だけ、平らな端の最小幅中心線を補う。

鉄道は灰色の実線。公共交通レイヤーではその上に路線カラーの4px帯と7pxの白い縁取り、停留所の白い芯を描く。運休・走行形状なしの路線は従来の灰色破線で区別する。ヒートマップ・地区の値塗りは公園を含む地表の上、道路と建物の下に敷く。

道路面の検証は`tauri`で`node tools/map-road-surface-test.mjs`を実行する。平らな終端、4mから24mへの幅遷移、短区間、曲線、共有断面の一致を確認する。座標と操作は上記`map-orientation-test.mjs`で検証する。

## 地区名・公共施設・駅

地区の中心点に地区名を白い縁取りの文字で表示する。地区枠線の表示とは独立している。公共施設は実際の中心座標に丸いマーカーを置き、名前を添える。病院は医療の十字、警察は盾、消防は炎、学校・大学は卒業帽、駅は列車の専用記号を使用する。発電所・変電所・取水施設・地下水／水道ポンプ・下水処理場・ゴミ処理場・市庁舎にも専用記号を用意する。

その他の施設は`public_facility`が真なら中央に丸を持つ汎用マーカーで表示する。電波塔、車両基地、バス車庫、美術館、展望台、客船ターミナルなどが該当する。分類は翻訳された名前ではなく種別・バリアントに基づく。記号は`mapSymbols.ts`で定義した独自ベクターで、外部地図サービスの画像を取り込まない。

施設記号は建物レイヤー、駅記号は駅レイヤーに追従する。駅は駅舎ごとに1記号を置き、所属するプラットフォーム群の凸包を赤い半透明の面と輪郭で示す。施設名は保存名、未設定の場合はマスターの表示名を使う。地区名を優先し、次に駅・施設記号を配置してから、左右どちらかに収まる施設名を描く。画面外や重なる表示は省く。施設記号はzoom 0.04以上、施設名は0.1以上で表示し、ズームしても文字と記号の画面上の大きさは固定する。

インターチェンジ(IC/JCT)は、バックエンドがランプ用バリアントの道路群から自動検出したものを`GET /api/v1/interchanges/`で都市全体まとめて取得し、中心座標に緑の丸とクローバー型の記号を置いて名前を添える。未命名のものは種別の略号とID(`IC #3`・`JCT #5`)で表す。件数が少ないため、地区と同じくベクターの取得や再読み込みのたびに取り直し、エポック実行や道路編集による検出結果の変化に追従する。取得に失敗しても他のレイヤーの描画は止めない。記号の配置優先度は駅の次、施設記号より前で、インターチェンジレイヤーに追従する。

## レイヤーの初期状態とツールバー

既定でONにするのは建物、駅、インターチェンジ、すべての道路、幹線道路、線路の6種類。公共交通路線、土地区画、地区枠線、海岸線の輪郭、標高、等高線、グリッドはOFF。陸地・水域の面と地区名は常時表示する。

レイヤー・ヒートマップ・全体表示・再読み込みは角丸のアイコンボタンで表示する。説明はホバー時のツールチップで読み取れ、キーボード操作時はフォーカス枠とアクセシブル名を持つ。トグルの選択状態は色・枠と`aria-pressed`で表す。ヒートマップは従来どおり排他選択。

`node tools/map-labels-test.mjs`は施設分類、海外でも読める学校記号、地区名の座標、表示の衝突回避と画面外除外、駅→インターチェンジ→施設の配置優先度を検証する。
