# 市民の追跡

3Dビューを走る車と歩行者から市民を選び、その市民の訪問先と経路を市民パネルで見たり、カメラで追いかけたりする機能。選んだ市民は追跡リストに残せる。

車と歩行者はパスの交通量から再現した描画専用の個体で([車両の走行描画](../geometries/O_車両の走行描画.md)・[歩行者の描画](../geometries/W_歩行者の描画.md))、市民の身元を持たない。身元はクリックしたときに初めてコアが推定する。推定も行程も、コアが直近のエポックで計算した経路を読むだけで、都市の状態は変えない。

## 交通演出の一時停止

市民を選べるのは、交通演出を一時停止している間だけである。一時停止は Unity の中で完結し、`Time.timeScale` ではなく交通演出の時計 `TrafficClock` で止める。`Time.timeScale` はカメラ操作や通信の再試行の待ち時間まで止めてしまうためで、交通の演出を動かすコードは経過時間に `TrafficClock` の倍率を掛ける。一時停止はセーブしない。

## 市民の推定と行程

一時停止中に自家用車か歩行者をクリックすると、Unity は個体の手段・今いるパス・進む向き・直前に通ってきたパスをコアへ送り(`POST /api/v1/citizens/pick`)、コアがそのパスの交通量への寄与に比例して市民とその移動を選ぶ。結果は `world:select_object`(`citizen_detail`)で市民パネルに渡り、推定できなかったときは `citizen:pick_failed` で理由をコックピットに知らせる。

行程(`GET /api/v1/citizens/{id}/itinerary`)は、自宅と勤務先・学校・店の訪問先と、自宅との往復の経路である。抽選も行程も保存しない推定で、応答の `status` は `ok` のほか、`busy`(エポック実行中)・`not_ready`(都市のロード直後など、経路の計算前)・`none`(抽選で、手段の合う住民がいない)・`no_home`(住宅待ちで住む建物が無い)・`missing`(市民がいない)を返す。

移動の区間(`legs`)は[都市マップの経路案内](都市マップの検索と経路案内.md)の区間と同じ形である。`steps` は Unity が車・歩行者に辿らせるパスの列で、徒歩・自動車の区間のパスに両端の建物の接道パスを足したものである。接道パスとして足した要素の `leg` は -1 で、公共交通など車・歩行者として描けない区間は `steps` に入らない。

## 追従と追跡リスト

カメラでの追従は Unity の `CitizenFollow` が行う。UI は `citizen:follow`・`citizen:unfollow` を送るだけで、Unity が行程を自分で取得し、指名した車・歩行者とカメラで追う(経路を IPC で運ばない)。追従の開始・終了は理由を問わず Unity が `citizen:follow_state` で全ウィンドウへ知らせ、これが状態の正になる。後から開いたウィンドウも今の状態を知れるよう、通知を受けたウィンドウが追従中の市民IDを共有の保存先に書く。

追跡リストは追加した順に都市のデータとしてセーブに残り、シナリオとして保存するときは空にする([セーブデータ仕様](セーブデータ仕様.md))。追跡リストを変えたウィンドウは Tauri のグローバルイベント `tracking:changed` で他のウィンドウに知らせる。
