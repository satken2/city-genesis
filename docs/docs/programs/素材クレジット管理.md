# 素材クレジットの管理

## 概要

本作は画像・効果音・BGM・3Dモデル・テクスチャ・フォントなど、外部から取得した素材を多数利用している。これらのライセンスには **「利用に際してクレジット表記が必要」** と定めるもの（CC BY 系、各素材サイトの独自規約など）があり、表記を欠いた状態での配布はライセンス違反になる。

表記義務を果たすための画面が **クレジットウィンドウ** で、掲載内容は Tauri 側のデータファイル 1 本に集約されている。

**クレジットウィンドウが扱うのは素材（アセット）だけで、ゲームエンジンやOSSライブラリは載せない。** それらの著作権表示・ライセンス条文は、画面ではなく配布物への同梱で満たす（後述）。

## 掲載データの所在

| 項目 | 場所 |
| --- | --- |
| 掲載データ（唯一の正） | `tauri/src/data/credits.ts` の `CREDIT_ENTRIES` |
| 作者名待ちのFlaticonアイコン | 同ファイルの `FLATICON_PENDING_SLUGS`（表記が完成するまで掲載しない残作業リスト） |
| 描画コンポーネント | `tauri/src/components/taskbar/CreditsWindow.tsx` |
| ウィンドウ定義 | `tauri/src-tauri/config/window-registry.json` の `credits` |
| 到達経路 | 設定ウィンドウ → 「情報」グループ → クレジット |

設定ウィンドウはトップメニューのオプションボタンとゲーム中のシステムトレイの両方から開けるため、**ゲーム開始前でもプレイ中でもクレジットに到達できる**。

バックエンド（コアシミュレータ）は関与しない。クレジットは表示専用の静的データであり、シミュレーション状態と無関係だからである。

ニューゲームのクリア済みバッジは `tauri/src/assets/images/ui/badge.png` を使用する。出所は [Magnific / Badge（3135728）](https://www.flaticon.com/free-icon/badge_3135728) で、Flaticon Free Licenseとして作者名を含む表記を `CREDIT_ENTRIES` に登録している。

## 1件の記載内容

`CreditEntry` のフィールドは次のとおり（詳細は `credits.ts` の型定義とコメント）。

| フィールド | 内容 |
| --- | --- |
| `title` | 一覧の見出しになる名前（素材名・素材セット名・ライブラリ名） |
| `category` | 掲載カテゴリ。見出しの表示順は `CREDIT_CATEGORY_ORDER` が決める |
| `author` / `source` | 作者名・権利者名 / 配布元の名称 |
| `url` | 配布元URL。指定すると見出しが既定ブラウザで開くリンクになる |
| `license` | ライセンス名（`CC BY 4.0` / `MIT` など） |
| `requiredText` | 規約が特定の文面を要求している場合、その文面 |
| `note` | 使用箇所などの補足 |

カテゴリ見出しと項目ラベルだけが i18n（`credits.*`）で、**作者名・ライセンス名・`requiredText` は翻訳しない**。「この表記のとおりに書くこと」を条件とする素材があるため、原文のまま出す。

## 記載の原則

- **表記が不要な素材も、出所が分かっているものは載せる。** 後から規約が変わった場合や出所を問われた場合に追跡できるようにするため。表記が必須な行だけを選り分けようとすると、判断ミスが即ライセンス違反になる。
- **素材の追加・差し替えと同じコミットで `credits.ts` を更新する。** 素材だけ先に入れると、表記漏れが誰にも気づかれないまま配布物に混入する。
- **出所を確認できない素材は使わない。** ファイル名を変えてしまった等で配布元が辿れなくなった素材は、掲載データに書くべき内容が埋まらない。その時点で「使ってよい素材」であることを示せないので、下記の手順で出所を確定させるか、差し替える。
- **自作の素材は載せない。** クレジットは他者の成果物を利用する際の出所表記であり、自前のBlenderスクリプトやAI補助で作ったモデル・画像・音には表記すべき相手がいない。自作物を混ぜると外部素材に見えて出所調査を混乱させる。AI生成物はクレジットではなくSteamの開示記録として別枠で扱う。

## 出所が分からなくなった素材の扱い

1. **同一ファイルの再発見を試みる。** 画像なら Google レンズ等の画像検索、音声なら取得候補サイト内での試聴照合で配布元を特定する。特定できたら規約を確認し、`credits.ts` に追記する。
2. **特定できないものは差し替える。** 出所不明の素材は「クレジット表記が必要だったかどうか」すら判定できないため、権利上のリスクを抱え続けることになる。ライセンスが明快な素材（CC0 / パブリックドメイン、または配布元と規約が記録できるもの）へ置き換える。
3. **以後は取得時点で記録する。** ダウンロードした直後に `credits.ts` へ行を足すのが最も確実（あとで思い出せる保証はない）。ファイル名を変更する場合も、変更後の名前で記録する。

なお、地形テクスチャについては `unity/Assets/Resources/Textures/README.md` に出所の記録がある。ディレクトリ単位の出所メモは、コード側がファイル名を前提に読み込んでいる等の事情を併記できるので、クレジットデータと併存させてよい（**クレジットウィンドウに出す必要がある行は `credits.ts` にも書く**）。

## 配布元ごとの要注意点

| 配布元 | 注意点 |
| --- | --- |
| Flaticon（無料プラン） | **作者名を含む表記が必須**。要求フォーマットは `designed by <作者名> from Flaticon`。ゲーム・アプリの場合は**クレジット画面とストアページの説明の両方**に載せる必要がある。作者名はアイコンごとに異なるため、アイコン単位で記録する。有料プランで取得し直すと表記義務が外れる |
| Freesound | **音源ごとにライセンスが違う**（CC0 / CC BY / CC BY-NC が混在）。CC BY は表記必須、**CC BY-NC は商用利用そのものが不可**なので、見つけたら使用箇所を確認して差し替える |
| AI生成画像 | クレジット表記の義務は基本的に生じないが、**Steam はストアページでのAI生成コンテンツの開示を求める**。クレジットとは別枠で「どのアセットがAI生成か」を記録しておく |
| 画像検索からの直接保存 | ストックフォトのプレビュー画像など、**ライセンスを取得していない素材**が紛れ込みやすい。参考資料として保存したものが、いつの間にか制作物に流用されていないか確認する |

## OSSライブラリ・ゲームエンジンの扱い

**これらはクレジットウィンドウには載せない。** MIT / BSD / Apache-2.0 などの許諾型ライセンスが求めるのは「著作権表示とライセンス条文全文の同梱」であり、作者名を画面に並べても条文が欠けていれば義務を果たしたことにならない。逆に、一部のライブラリだけを画面に出すと網羅しているように見えてしまう。

したがって配布前に、依存ライブラリの一覧とライセンス条文を機械的に収集し、テキストファイルとして配布物へ同梱する（npm 側・pip 側・Cargo 側・Unity パッケージ側の 4 系統がある）。手で書き出すと必ず漏れるので、各パッケージマネージャのライセンス収集ツールを使うこと。

## 地形マップの標高データ

ゲームは標高マップそのものを同梱しないが、同梱するチュートリアルの都市（`.cg`）には地形が入っている。今入っている実在の地形は与論島（チュートリアルの舞台）だけで、平坦な舞台は人工の地形なので掲載しない。利用者が自分で取り込む地形は配布物に入らないので載せない。シナリオやDLCとして実在の地形を同梱するときは、同梱と同じコミットで提供元を `credits.ts` に載せる。

| 対象 | 提供元 | 種別 |
| --- | --- | --- |
| 与論島（チュートリアルの舞台） | 国土地理院 標高タイル（基盤地図情報数値標高モデル） | DTM |

カテゴリは `data`（地形・地理データ）。素材ファイルではなく数値データだが、外部から取得した他者の成果物であることに変わりはないため、他の素材と同じく掲載する。

### 出典表示だけでは足りない

標高データの提供元は、出典表示に加えて別種の義務を課すことが多い。**どれも「クレジットに1行足す」では満たせない**。以前に使った提供元の義務を、実在の地形を同梱するときの参考として残す。

| 提供元 | 出典表示に加えて必要なもの |
| --- | --- |
| 国土地理院 | 加工した場合に**加工した旨の記載** |
| USGS 3DEP | **改変内容の記述**（どう改変したかを書く義務がある）、USGS公認と誤認させない旨 |
| 香港 DATA.GOV.HK | **知的財産権が政府および関係機関に帰属する旨の承認**、帰属先は政府・関係機関・DATA.GOV.HK の三者 |
| Copernicus DEM | 改変して配布する場合は**未改変時とは別の指定文言**、加えて**免責文言**をライセンス表示か法的通知に入れること |

規約が示す表記例はそのまま `credits.ts` の `requiredText` に入れているので、翻訳・省略をしないこと。

> 地理院タイル（標高タイル（基盤地図情報数値標高モデル））を加工して作成

### 元データに混ざる第三者データ

Copernicus DEM には、欠測を他所のDEMで埋めた画素が混ざる。サントリーニでは切り出した範囲の陸地に ASTER GDEM と SRTM30 由来の画素が実在したため、同梱していたときはその2件も独立したエントリとして掲載していた。**提供元が1つでも、実際に配布物へ入る成果物が1つとは限らない**ので、付属の品質レイヤ（穴埋めマスク）を確認すること。

## 自作3Dモデルの扱い

道路工事車両（舗装機・ローラー・ショベル・移動式クレーン）、オープンスペースの敷地装飾（Buildings/a3001〜a3004）、駅階段プロップ（Props/101〜104）、高架下駅舎の連絡通路（Paths/p2003・p2013）は、いずれも自前のBlenderスクリプトによるプロシージャル制作で、外部モデル・画像のダウンロードは無い。
