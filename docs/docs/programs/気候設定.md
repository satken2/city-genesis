# 気候設定

都市の気候は、名称と12か月分の天気の出現割合・平均気温・降水量・日照で構成する。天気の種類と気候プリセット(ケッペンの気候区分ごとに1つ)はコアが管理し、都市とシナリオはプリセットからコピーした実データを保存する(プリセットのIDや参照は保存しない)。風速は気候に含めず、気候によらずエポックごとに決まる([生産活動](../economics/9_生産活動.md))。コアは月別の平均値を生産用のエポック気候の基準に使い、Unity は同じ月の出現割合を[描画中の天気](../geometries/U_天気と環境光.md)に使う。

## データの意味

都市の気候は `GET /api/v1/city/` の `city.climate` で、1月から12月の順に並ぶ月ごとの値(`months`)を持つ。天気の出現割合(`weather`)は全天気IDの出現時間の割合で、0〜100の整数を合計100にする。

エポックの開始時に確定したそのエポックの気候は、同じ応答の `city.epoch_*` である。降水量(`epoch_precipitation`)は月に相当する mm で表し、最初のエポックの前はどれも `null` である。

## 画面とコア・Unity の連携

シナリオ作成モードの気候設定ウィンドウ(`climate_settings`)は、編集をウィンドウ内の下書きに持ち、適用したときだけ `PUT /api/v1/city/climate` で都市の気候を丸ごと置き換えて、Unity へ `session:reload` を送る。適用しても確定済みのエポック気候は変わらず、Unity も今の天気を抽選し直さずに、次の移り変わりから新しい割合を使う。それ以外のモードの気候ウィンドウ(`climate_effects`)は、`GET /api/v1/city/climate-effects` が返す施設ごとの生産倍率を並べる。倍率はコアが生産と同じ計算で返すので、UI では計算しない。

シナリオの地形編集やゲームの開始も同じ実データを扱い、プリセットを選んだときだけ、それをコピーして置き換える。
