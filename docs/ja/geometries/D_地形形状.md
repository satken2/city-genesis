# D. 地形形状

都市の地形（標高）と、地形に付随する海岸線・水面・川・埋立地・都市外の背景地形について、コア・Unity・Tauri が共有する約束をまとめる。Unity が地形をどの範囲・品質で描くかは [E_LOD処理](E_LOD処理.md)、どの順で取得して差し替えるかは [H_バックエンドデータロード](H_バックエンドデータロード.md) を参照する。

## D.1. 何のためのデータか

地形は都市全域の標高をグリッドデータ（ラスター）として持ち、3D描画の地面と、道路・建物の接地を支える。現在の標高は、都市を作ったときの自然地形に、道路の盛土・切土や造成などの工事で書き換えたセルの標高を重ねたものである。保存形式や API の名前にある far（遠景）・near（近景）・dynamic（超近景）は格子の細かさの違いであり、カメラの距離で別の地面へ切り替える描画の段階ではない。

## D.2. マップの寸法と格子

マップの寸法と格子は都市（シナリオ）を作るときに決まり、以後は変わらない。フロントは地形設定の API から読み、決め打ちしない。マップの縦横（`map_width`・`map_height`）はセルの一辺（`cell_size`）の偶数倍で、遠景・近景・超近景の格子間隔は粗いものが細かいものの整数倍である。

## D.3. 標高の基準

標高は海面を0とする絶対標高（m）で、水面の水位・岸壁の天端・土地区画の基準標高・カメラの高さも同じ基準で表す。パス・ノードの座標の Y は基準面からの相対高さである（[A_パス形状](A_パス形状.md)）。

### D.3.1. 配列の向きと方位

ワールド座標は東が `+X`、北が `+Z`、上が `+Y` で、原点はマップ中心に固定する。標高配列は、近景・遠景・超近景・背景のどれも、行0がZ最小の南端、列0がX最小の西端で、`[0, 0]` が南西隅に当たる。この向きは Unity の俯瞰（北が画面上）・コンパス・カメラの yaw（北=`+Z` を0とする時計回り）と一致する。

外部の標高データ（画像や DEM は北から南の行順）は、保存する前に行を並べ替えてこの向きにする。ゲーム内には行を反転する処理が無い。画面のY軸が下向きの2D表示（Tauri の都市マップ・地形エディタ・サムネイル）は `+Z` が画面の上に来るように変換し、右手系の3D表示（three.js）は東西の鏡像を打ち消して描く。

## D.4. セル

セルは標高の保存単位であり、Unity が地形タイルを作る単位でもある。ゲームのルール上の意味は持たず、道路・建物・土地区画はセルをまたいで置ける。地形を書き換えると、そのセルの版が上がる。

コアのセル番号はマップの南西隅を原点とする0以上の整数、Unity のセル番号はマップ中心を原点とし負の値もとる。マップの縦横がセルサイズの偶数倍なのでマップ中心はセルの境界に来て、両者は整数のずれだけで1対1に対応する。変換は `TerrainManager` の変換関数を使う。

## D.5. 標高の取得

標高を返す API はバイナリで、リトルエンディアンの浮動小数点数を D.3.1 の向きに並べる。現在標高は、作成時の自然地形（初期地形。近景の格子）を補間した面に、工事で書き換えたセルの細かい格子を重ねたものである。Unity は初期地形と書き換えたセルを丸めない float32 で取得し、コアと同じ補間の規則で常駐セルのタイルを手元で作る。カメラを動かしてもコアに問い合わせずに済むようにするためで、補間の規則はコアと Unity で揃え、片方だけ変えない。都市全域の現在標高（遠景の格子）は float16 である。版の一覧に無いセルは版0（未編集）とする。

セルの境界付近の補間は隣のセルも読むので、セルの版には周囲のセルの書き換えも含まれる。フロントは版を、保持している地形と同じかどうかの比較と、書き換えたセルを取り直すかどうかの判断だけに使う。

## D.6. 海岸線

海岸線は陸地の範囲を表すポリゴン（GeoJSON 形式の `Polygon` または `MultiPolygon`、ワールド座標のXZ）である。湖や川などの穴と複数の陸地を含むので、外周だけでなく全体を扱う。マップの境界に沿う辺は、水際とは区別する。

海岸線は標高とは別の地理データで、フロントが地形から作り直すものではない。`session:reload` のたびに取り直し、水域の表示や敷設プレビューに使う。区画の種別は海岸線から推測せず、区画の取得値を使う（[B_土地形状](B_土地形状.md)）。

## D.7. 水面（湖など）

標高0mの海面とは別に、山上の湖や貯水池のように、海面と異なる水位を持つ平らな水面を置ける。水位（`water_level`）は絶対標高で、範囲（`polygon`）は海岸線と同じ形式（内周リングは穴）の、水面がありうる上限である。Unity は範囲全体に水平な水面を描き、水位より高い地形がその手前に見える。流下方向に水面の高さが変わる川は、水面に含めない。

## D.8. 川

川は、地形エディタが川床を標高へ彫り込んだうえで残す「範囲」と「水面の高さ」である。川床は標高の一部になっているので、ゲームから見た谷は通常の地形と区別されない。彫り込みに使う流路・幅・深さはエディタ内部の中間データで、ゲームには渡さない。

川の範囲（`polygon`）は水面と同じ形式で中州が穴になり、水面の高さは `profile`（上流から下流の順の `[x, 絶対標高, z]` の点列で、下流へ向かって増えない）で表す。範囲の中の任意の地点の水面の高さは、`profile` の折れ線上で水平に最も近い点の高さとする。この規則は地形エディタ・コア・Unity で共通で、水面の描画もパスの横断判定もこの高さを使う。

## D.9. 天然資源とカメラ

天然資源（[財の供給と輸送](../economics/17_財の供給と輸送.md)）の初期配置と、都市を始めたときの3Dカメラも、シナリオが持つ。カメラは位置（`y` は絶対標高）、`yaw`（D.3.1 と同じく北を0とする時計回りの度）、`pitch`（見下ろし角の度。正で下向き、90で真下）で表し、ロールは持たない。カメラは都市の `camera`（未設定は `null`）としてセーブにも入り、Unity はカメラが止まるたびに更新し、ロードでは `game:start` の後に読んで視点を戻す。

## D.10. シナリオの地形

ゲームは標高マップを同梱しない。地形はシナリオ（`.cg`）が自己完結で持ち、新しい地形は利用者の標高ファイル（グレースケール PNG・`.npy`）を取り込んでシナリオにする。取り込んだばかりのシナリオは標高と（指定すれば）背景地形だけを持ち、地表種別と気候は既定値で始まる。シナリオの位置付けは[セッションと保存](../programs/セーブデータ仕様.md)、取り込みの項目は API 資料を参照する。

海底もシナリオの標高の一部で、港を建てられる水深（[B_土地形状](B_土地形状.md)）は保存された海底で決まる。実在地域の海底には水深データを補間して用いることができ、陸上の勾配だけから水深を推定できるとは限らない。提供元と加工内容はシナリオのクレジットに記載する。

標高ファイルの取り込みと地形エディタの海底生成（陸の勾配に合わせる）は、陸の勾配を海へ延ばす同じ規則を使う。この生成操作は既存の水深も作り直すため、水深データを持つシナリオの海底を保持したいときには実行しない。

Tauri の地形エディタは、シナリオの地形 API で標高・水面・川・カメラ・地表種別・気候を読み書きする。資源とプロップはシナリオ制作モードのセッションで編集するもので、地形エディタは読み込んだ内容をそのまま送り返す。DLC 由来の暗号化されたシナリオは、地形を持ち出せないよう対象外になる。

地形の編集には、建設物と地面の整合を保つための制限がある。フロントはシナリオの地形 API が示す編集可否に従い、保存後の表示には再取得したデータを使う。

## D.11. 地表種別と気候

地表種別は都市の地表の見た目を選ぶ値で、描画だけに使う。都市に1つで、ゲーム中は変わらない。値は都市の `ground_cover` で読み、Unity は地形タイル・超遠景の陸地・都市外の背景に、Tauri の2D表示は標高の配色に同じ種別を使う。

| 共有定数 | 見た目 |
| --- | --- |
| `GROUND_COVER_GRASSLAND` | 草原（既定） |
| `GROUND_COVER_DESERT` | 砂漠 |
| `GROUND_COVER_LUSH` | 濃い草地 |
| `GROUND_COVER_SNOW` | 雪原 |
| `GROUND_COVER_SEMI_ARID` | 乾燥地 |

気候は都市とシナリオが保存する12か月の天気・気温・降水量・日照で、[天気と環境光](U_天気と環境光.md) に定める。

## D.12. 埋立地

埋立地（[地区と土地区画](../economics/4_地区と土地区画.md)）の岸壁は、地形と組み合わせて描く構造物である。Unity は API が返す岸壁の形状を使い、コンクリートの天端と垂直の壁を描く。

岸壁・壁・帯（天端で覆う範囲）・天端の高さは API から受け取り、描画と判定に使う。フロントは埋立地の範囲や海岸線からこれらを求め直さない。更新の取り込みは[バックエンドデータロード](H_バックエンドデータロード.md)に従う。

帯の中では天端が地面を覆うため、接地する高さは「地形と天端の高い方」である。Unity の接地は共通の処理を使い、地形の標高だけに置かない（[E_LOD処理](E_LOD処理.md)）。

## 都市外の背景地形

都市の範囲は、詳細な標高のマップの範囲と同じである。半島や大陸のように都市の外にも陸が続く地形は、都市の外側に背景地形を置いて描く。背景は詳細な地形と同じ実地形から作るが、編集や造成の対象にはならず、都市の範囲も広げない。継ぎ目を補間しないので、都市の範囲の中にある対岸の陸地も詳細な地形に含めて作る。

背景はシナリオとセーブが持つ。背景の API は標高を float32 のリトルエンディアン（並びは D.3.1）で返し、行数・列数・格子間隔・原点（南西隅のワールドXZ）をヘッダー `X-Grid-Rows`・`X-Grid-Cols`・`X-Grid-Spacing`・`X-Origin-X`・`X-Origin-Z` で返す（背景が無ければ 204）。背景には、都市マップが都市の外の陸地を塗るための粗い海岸線も付く。粗いので都市の境界で都市の海岸線とずれるため、都市の矩形の外だけに使う。

都市の外への道路・線路・建物・土地区画の配置は、シナリオ制作モードだけで行える。描画と表示には、コアから取得したパス・区画・地区の関係を使う。
