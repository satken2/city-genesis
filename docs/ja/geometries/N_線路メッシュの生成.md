# 線路メッシュの生成

パスマスターの `model_type` が `track` のバリアント（線路 `PATH_TRACK` とモノレール `PATH_MONORAIL`。ホームを持つ駅パスを含む）は `TrackPath` が描く。描画点列・LOD・コライダー・地下区間の分割・パーツの探し方は道路と共通である（[G_道路メッシュの生成](G_道路メッシュの生成.md)）。道路と違い、軌間や架線の断面はバリアントの幅で変わってはならないので、道床は全幅に合わせて伸ばすが、軌道・架線・ホームは実寸のまま並べる。

線路の見た目は、ノードにつながるパスや近くを並走する線路にも左右される。それらの情報は `PathManager` が供給し、供給元の無い環境（メッシュ確認用のシーンなど）では単独の線路として描く。

## パーツ

プレハブは `Models/Paths/p{path_variant}/{パーツ名}` を探し、無ければ `Models/Paths/p{path_type}/{パーツ名}` を使う。`body`・`track` は、地表より高い区間では `body_elevated`・`track_elevated` があればそれを使う。橋脚・トンネルの側壁と天井・坑口は道路と共通のパーツである。

| パーツ | 役割 |
| --- | --- |
| `body` | 道床（高架の `body_elevated` は桁とスラブ） |
| `track` | 1軌道分のレールと枕木（モノレールでは軌道桁） |
| `rail` | 分岐器・平面交差のレール |
| `wire`・`pole`・`beam` | 架線・架線柱・門型の梁 |
| `wall` | 高架の高欄・防音壁（橋梁では主構のトラス） |
| `arcade` | アーチ高架などの連続した支持構造 |
| `platform`・`platform_wall`・`platform_foundation` | ホームの淵・外縁・外壁の下部 |
| `platform_panel` | ホームの上面の材質（置かずに材質だけを使う） |
| `buffer_stop`・`platform_end` | 車止め・ホーム端の柵 |

プレハブが無いパーツは描かない。道床も軌道も無いときだけ、ゲームを続けられるよう白い帯で代わりに描く（モノレールは道床を持たない）。

## 地上・高架・地下と電化

地上・高架・地下はバリアントではなくアンカーの相対高さで決まるので（[A_パス形状](A_パス形状.md)）、1本の線路の中で区間ごとに描き分ける。地表より高い区間には高架用のパーツと高欄を使い、完全に埋まった区間には架線柱を立てない。電化はマスターの `wire_spacing` で決まり、空なら非電化で架線・架線柱を描かない。

## 軌道の位置

軌道の位置は専用のパラメータを持たず、道路の車線と同じくマスターの `width`・`lanes`・`center_width` から導く。`lanes` が2のバリアントは、1本のパスが上下線の2軌道を持つまとめた複線で、常に双方向に走れる。パスと進む向きが決まれば走る軌道は1つに決まり、2軌道なら進む向きに対して通行区分の側を走る。本線・レールのつなぎ・車止め・車両の走行描画（[O_車両の走行描画](O_車両の走行描画.md)）は、この位置と規則を `TrackPath` の同じ実装から求める。

## ノード

線路のノードは分岐器や平面交差になる。交差点の外周は道路と共通の仕組みで作り、線路では道床の見た目になる。レールは、列車が実際に進める向きの組にだけ敷く。進めるかどうかは経路探索と同じ転回の角度の制約と、各パスの通行方向（`travel_direction`）で決めるので、見た目と列車の動きが一致する。鉄道の線路では、どのレールにも使われない軌道の端に車止めを置く。

## 駅パスとホーム

駅パスは `platform_width` を持つ線路のバリアントである。`width` は通常の線路と同じなので前後の線路とそのままつながり、ホームは道床の外へ `platform_width` だけ張り出す。単線の駅は `platform_side`（`PLATFORM_SIDE_*`）でホームの側を決め、内側・外側を都市の通行方向（`traffic_hand`）と `travel_direction` から左右へ解決する。この解決はコアが駅パスの敷地を求める規則と同じで、片方だけ変えると敷地と見た目が食い違う。

複線の駅は、上下線の外側にホームを持つ相対式か、上下線の間に1面を持つ島式になる。軌道数2の駅は相対式で、そのうち `center_width` が正の駅は島式である。単線の駅を2本並べた複線では、上下線とも内側にすれば向き合うホームが1枚の島として描かれる島式に、外側にすれば相対式になる。

## 近接線路の結合描画

単線を2本並べた複線は、そのままでは単線が並ぶだけの見た目になるので、近くを並走する同じ種類の線路を1つのコリドーとして描き、道床をつなげて線路の間の高欄や架線柱を省く。この結合は描画だけのもので、コアのデータや経路探索には影響しない。並走する線路が変わっても自分の version は変わらないので、Unity は線路のデータが変わるたびに近くの線路を描き直す。完成前の線路（`STATUS_TEMPORARY`・`STATUS_SCHEDULED_CONSTRUCTION`・`STATUS_PENDING`・`STATUS_CONSTRUCTING`）と敷設プレビューの線も仮の相手として結合し、仮の相手が消えれば元の形に戻る。
