# 建物メッシュの生成方式

建物の組み立て方は `model_type` で決まる。ただし、建設中・解体中・倒壊の状態は方式より先に効き、完成形の代わりに現場や瓦礫を描く。入力・パーツの命名・外観バリアント・描画LODなど、全方式に共通する約束は [建物メッシュの生成](F_建物メッシュの生成.md) を参照する。

## モジュラー建物

底面の外周に壁・角のパーツを階ごとに並べる、通常の建物の方式である。敷地装飾・塔屋・玄関・外階段・基盤の扱いは共通で、4方式の違いは屋根にある。

| model_type | 屋根 |
| --- | --- |
| `MODEL_MODULAR_FLAT` | 平屋根 |
| `MODEL_MODULAR_HOUSE` | 寄棟状の三角屋根 |
| `MODEL_MODULAR_GABLE` | 切妻屋根（勾配面2枚と妻壁） |
| `MODEL_MODULAR_SHED` | 片流れ屋根（薄い1枚と妻壁） |

屋根は形のパーツを持たずに生成し、屋根面のマテリアルを `ceil`、妻壁のマテリアルを窓の無い `generic-wall` から取る。勾配屋根の立ち上がりは階高に比例させ、階数の多い建物だけ屋根が巨大にならないようにする。`interior-floor` があれば各階に床を張り、平屋根ではその床が屋上を兼ねる。`building_shape` が `SHAPE_FULL`（区画いっぱいの底面。[建物形状](C_建物形状.md)）なら、最上階1階分の壁・角に屋根と塔屋を載せた形で描く。

## 既成建物とマッシュアップ建物

既成建物（`MODEL_PREBUILT`）は、電波塔・像・観覧車など、壁の組み立てに向かない建物に使う。完成形に近い `base-prebuilt`・`mid-prebuilt`・`top-prebuilt` を中心に積み、区画に合わせて伸縮させずに正面の辺へ向きを合わせる。`base` と `top` が1階分ずつ、`mid` が残りの階数を受け持つ。ファイルのある段だけを積むので、完成した建物を `top-prebuilt` 1つで表せる。外観バリアントは持たず、`0` フォルダを使う。観光名所も名所ごとのフォルダで同じように積む。

マッシュアップ建物（`MODEL_MASHUP`）は、学校の校舎と体育館のように、1つの施設を複数の棟で描く。棟の配置はコアから `sub_buildings` で届き、プレイヤーが後から編集できる。棟の幅・奥行きはサブ建物マスターの `width`・`height` で、単位は一辺 `MASHUP_CELL_SIZE` のセル数である。`position` は親の `center_point` を原点とする棟の中心のXZ、`rotation` はXZ平面の +X から反時計回りの角度（度）で、棟の幅がこの向きに沿う。棟の階数は保存せず、親の階数をサブ建物マスターの階数の範囲に収める。

棟には `mashup-{model_prefix}-base-prebuilt` などを使い、既成建物と同じように積む。ただし、どの段も実寸のまま下の段の天端に置き、番号のフォルダはパーツごとに選ぶ。各棟は自分の位置の地形標高に接地し、遠景も棟ごとの配置を保つ。既成建物のクリック判定は底面を描いた段の天端まで、マッシュアップは区画を最も高い棟の天端まで押し出すので、実寸のモデルや棟の間の空き地も施設として選べる。既成建物の道路への間口は、地上に置く段のモデル内の目印から得る。

## 地面アセットとオープンスペース

地面アセット（`MODEL_MODULAR_GROUND`）は、畑・庭・舗装広場のように建物本体を持たない施設に使う。土地区画の全体にフェンス・地面パネル・実寸のタイルを置き、クリック判定にも区画の形を使う。区画を引けないときは建物の底面を使う。

駐車場（`MODEL_PARKING`）・駅前ロータリー（`MODEL_ROTARY`）・公園（`MODEL_PARK`）は、区画の形から配置計画を作り、地形に沿う面と実寸の小物を組み合わせる。面は `site_asphalt`・`site_grass` などのマテリアル、小物は `site_bench`・`site_tree` などのモデルを使う。同じオープンスペースの種別でも、舗装広場や立体駐車場などはマスターの `model_type` に従って地面型やモジュラーの方式で描く。

配置は接道辺を基準にした区画内の格子と `visual_variant2` から決まり、建物ID・ロード順・描画LODには左右されない。駐車枠・園路・植栽は見た目だけのもので、駐車や通行のシミュレーションには使わない（公園も区画全体を通行できる。[地区と土地区画](../economics/4_地区と土地区画.md)）。ロータリーは、配置計画の舗装面と接道辺が交わる範囲を道路への間口にする。

## 地形や線路とつながる施設

### 港湾岸壁

港（`MODEL_PORT`）は、船が着く水際と、その陸側で荷を扱うヤードからなる。水際に荷役設備 `port_crane`、区画の辺0（道路側）に施設 `port_building` を置き、その間の空きに段積みのコンテナ `port_container{n}` または地面に並べる荷 `port_cargo{n}` を置く。荷の種類は港ごとの `a{variant}` が持ち、配置は区画・水際の形と通常モデルの寸法、`visual_variant2` から決まる。道路への間口は `port_building` の中の目印から得る。

天然の海岸では、コアが決めた岸壁の線（建物の `berth_line`。海岸線で切らずに届く区画（[土地形状](B_土地形状.md)）の水際の両端を結ぶ弦を海側へずらした直線）で海側を切り、岸壁の板を海底まで押し出す。コアはこの線のすぐ外で港の水深を判定するので、Unity は線を自分で求めない。上面は `floor` のマテリアルで陸側の敷地と一続きに見せる。埋立地の上の港は、[地形が描く岸壁](D_地形形状.md)を使い、板を作らない。埋立地の変化は建物の version に表れないため、埋立地の中身が変わったら港も描き直す。水際は[入港船の接岸位置](V_環境演出の乗り物.md)にも使う。

### 車両基地

車両基地（`MODEL_RAIL_YARD`）は、敷地内の線路を接続端子ノードへ収束させて描く。留置線・集約線・分岐の曲線、架線と柱、車止め、検修庫を `yard_*` パーツで並べ、引き込み線は端子につながる線路の軌道数に合わせる。設備は地形に沿わせ、地面パネルは `a{variant}` 自身の `floor` だけを使う。クリック判定は架線柱の高さまで底面を押し出し、架線や検修庫も選べるようにする。

端子は `depot_node_id`（無ければ `infra_node_id`）で、電化した基地では走行網と送電網に共通のノードになる（[財の供給と輸送](../economics/17_財の供給と輸送.md)）。端子の位置や接続線路は建物の version を変えずに変わるので、その変化を建物側へ知らせて描き直す。

### 露天掘り

露天掘り（`MODEL_OPEN_PIT`）の穴は地形そのもので、建物として描くのは、掘らずに残す接道側の前庭の設備だけである。穴は採掘に応じて版が変わった地形セルを取り直して描き（[LOD処理](E_LOD処理.md)・[財の供給と輸送](../economics/17_財の供給と輸送.md)）、設備は `sub_buildings` として届く棟をマッシュアップと同じ規則で組み立てる。

建物の中心は穴の中にあるため、中心の高さで区画を押し出すと前庭に届かず、平面や白い箱は穴を塞いでしまう。クリック判定には地形に沿う区画の面と設備ごとの外接箱を使う。地面パネルは前庭と穴を含む区画全体に敷く。

## 工事中・解体中・倒壊

完成形を描かない状態では、敷地を覆う土や瓦礫を共通の土台にし、状態に応じた足場・建機・躯体を載せる。地面型・オープンスペース・港・車両基地・露天掘りは、土や瓦礫だけで表す。

| 状態 | 描画 |
| --- | --- |
| 建設中（`STATUS_CONSTRUCTING`） | 土の地面パネル、`scaffold-wall`・`scaffold-corner` の足場、一定以上の階数で `crane-*` のタワークレーン |
| 解体中（`STATUS_DEMOLISHING`） | 土の地面パネル、`demo-scaffold-wall`・`demo-scaffold-corner` の足場、`demo-ceil` の天面と、その上に載せる `excavator` のショベルカー |
| 倒壊（`STATUS_COLLAPSED`） | 荒い瓦礫の盛り上がりと、あれば `collapse` の躯体。焼失（`status_reason` が `REASON_FIRE`）は焦げた瓦礫の材質 |

足場の段数は `construction_progress`（建設・解体に必要な体積のうち調達済みの割合。百分率）から決める。建設中は進捗とともに積み上がり、解体中はまだ取り壊していない割合の階数だけが残る。どちらも最低1階分を描き、進捗や竣工で建物の version が上がると差分ロードで描き直す。工事系パーツは建物のフォルダに無ければ `common` を探し、それでも無いものは省く。
