# 建物メッシュの生成方式

建物の組み立て方は `model_type` で決まる。ただし、建設中・解体中・倒壊の状態は方式より先に効き、完成形の代わりに現場や瓦礫を描く。入力・パーツの命名・外観バリアント・描画LODなど、全方式に共通する約束は [建物メッシュの生成](F_建物メッシュの生成.md) を参照する。

## モジュラー建物

底面の外周に壁・角のパーツを階ごとに並べる、通常の建物の方式である。敷地装飾・塔屋・玄関・外階段・基盤の扱いは共通で、4方式の違いは屋根にある。

| model_type | 屋根 |
| --- | --- |
| `MODEL_MODULAR_FLAT` | 平屋根 |
| `MODEL_MODULAR_HOUSE` | 寄棟状の三角屋根 |
| `MODEL_MODULAR_GABLE` | 切妻屋根（勾配面2枚と妻壁） |
| `MODEL_MODULAR_SHED` | 片流れ屋根（薄い1枚と妻壁） |

屋根は形のパーツを持たずに生成し、屋根面のマテリアルを `ceil`、妻壁のマテリアルを窓の無い `generic-wall` から取る。勾配屋根の立ち上がりは階高に比例させ、階数の多い建物だけ屋根が巨大にならないようにする。`interior-floor` があれば各階に床を張り、平屋根ではその床が屋上を兼ねる。`building_shape` が `SHAPE_FULL`（区画いっぱいの底面。[建物形状](C_建物形状.md)）なら、最上階1階分の壁・角に屋根と塔屋を載せた形で描く。

### 建物のまわりの駐車場

外観フォルダに区画線の材質 `site_marking` を持つモジュラー建物は、柵・散布パーツ・地面パネルの代わりに、土地区画の全体を駐車場として描く。配置計画の作り方と部品の持ち方は[ガソリンスタンド](#ガソリンスタンド)と同じで、底面の正面の辺が面する区画の辺を接道辺として扱う。

敷地は全体を舗装し、縁に縁石付きの植え込みを巡らせて、接道辺に車の出入口を開ける。駐車枠は、建物の正面に沿う歩道の前、空いた地面の向かい合わせの列、敷地の縁に引き、枠の後ろに車路を空ける。奥行きの浅い敷地では、出入口とその先の道路を車路に使う。正面の歩道には出入口の近くに店先の物 `site_clutter1`… を、植え込みには立て看板 `site_sign`・照明 `site_light`・低木 `site_shrub1`…・木 `site_tree1`… を置く。

停まっている車 `site_car1`… は、駐車枠ごとに決まった稼働率を超えたときだけ描く。建物の稼働率が上がるほど車が増え、休止中や入居の無い建物には1台も停まらない。

## 既成建物とマッシュアップ建物

既成建物（`MODEL_PREBUILT`）は、電波塔・像・観覧車など、壁の組み立てに向かない建物に使う。完成形に近い `base-prebuilt`・`mid-prebuilt`・`top-prebuilt` を中心に積み、区画に合わせて伸縮させずに正面の辺へ向きを合わせる。`base` と `top` が1階分ずつ、`mid` が残りの階数を受け持つ。ファイルのある段だけを積むので、完成した建物を `top-prebuilt` 1つで表せる。外観バリアントは持たず、`0` フォルダを使う。観光名所も名所ごとのフォルダで同じように積む。

マッシュアップ建物（`MODEL_MASHUP`）は、学校の校舎と体育館のように、1つの施設を複数の棟で描く。棟の配置はコアから `sub_buildings` で届き、プレイヤーが後から編集できる。棟の幅・奥行きはサブ建物マスターの `width`・`height` で、単位は一辺 `MASHUP_CELL_SIZE` のセル数である。`position` は親の `center_point` を原点とする棟の中心のXZ、`rotation` はXZ平面の +X から反時計回りの角度（度）で、棟の幅がこの向きに沿う。棟の階数は保存せず、親の階数をサブ建物マスターの階数の範囲に収める。サブ建物マスターの `loose` が有効な棟（積んだ山や置いた重機など）は、配置の位置と向きから、建物と棟ごとに決まった量だけずらして描き、格子にそろえない。遠景も同じ位置と向きに置く。

棟には `mashup-{model_prefix}-base-prebuilt` などを使い、既成建物と同じように積む。ただし、どの段も実寸のまま下の段の天端に置き、番号のフォルダはパーツごとに選ぶ。棟のモデルは専有するセルより小さく作り、余りが棟どうしの隙間になる。`lane` パーツがあれば、隣り合う棟のセルの境目に沿って敷き詰める。各棟は自分の位置の地形標高に接地し、遠景も棟ごとの配置と実寸の底面を保つ。既成建物のクリック判定は底面を描いた段の天端まで、マッシュアップは区画を最も高い棟の天端まで押し出すので、実寸のモデルや棟の間の空き地も施設として選べる。既成建物の道路への間口は、地上に置く段のモデル内の目印から得る。

## 地面アセットとオープンスペース

地面アセット（`MODEL_MODULAR_GROUND`）は、畑・庭・舗装広場のように建物本体を持たない施設に使う。土地区画の全体にフェンス・地面パネルを置き、底面の正面の辺に沿った格子で区画に収まる位置へ実寸のタイルを敷き詰め、クリック判定にも区画の形を使う。タイルは遠景モデルと同じ向きに置く。区画を引けないときは建物の底面を使う。

駐車場（`MODEL_PARKING`）・駅前ロータリー（`MODEL_ROTARY`）・公園（`MODEL_PARK`）は、区画の形から配置計画を作り、地形に沿う面と実寸の小物を組み合わせる。面は `site_asphalt`・`site_grass` などのマテリアル、小物は `site_bench`・`site_tree` などのモデルを使う。公園の木・低木・広場の施設・遊具・花壇は、種類ごとに `site_tree1`・`site_feature1` のような番号付きのモデルで、1から連番である分だけ使う。同じオープンスペースの種別でも、舗装広場や立体駐車場などはマスターの `model_type` に従って地面型やモジュラーの方式で描く。

配置は接道辺を基準にした区画の形と `visual_variant2` から決まり、建物ID・ロード順・描画LODには左右されない。公園は、入口と広場を曲線の園路で結び、敷地が広いほど入口・広場・園路が増える。モデルフォルダに競技場の面のマテリアル（`site_diamond`・`site_track`・`site_pitch`・`site_court`）があれば、敷地に収まる競技場を広い順に置き、残りの敷地を公園にする。小物はモデルの実寸に合わせて置き、木の濃さは `visual_variant3` で変わる。駐車枠・園路・植栽は見た目だけのもので、駐車や通行のシミュレーションには使わない（公園も区画全体を通行できる。[地区と土地区画](../economics/4_地区と土地区画.md)）。ロータリーは、配置計画の舗装面と接道辺が交わる範囲を道路への間口にする。

## 供給処理施設

変電所（`MODEL_SUBSTATION`）・水道ポンプ（`MODEL_WATER_STATION`）・下水処理場（`MODEL_SEWAGE_PLANT`）・ゴミ処理場（`MODEL_WASTE_PLANT`）は、オープンスペースと同じく区画の形から配置計画を作る。設備の配置はコアから届かず、プレイヤーが編集することもない。

どの施設も、接道辺に門を開け、門から敷地の片側に沿って構内道路を奥へ通し、設備の列を手前から奥へ並べていく。列は部品を実寸のまま収まるだけ繰り返すので、設備の数は区画の広さで決まり、不整形な区画では収まらない設備だけが抜ける。施設ごとの違いは、手前から並べる列の中身だけである。奥行きの足りない区画では手前の列だけが残り、深い区画では構内道路を挟んで同じ並びを繰り返す。左右の向きは `visual_variant2` で決まる。

設備は `site_office`・`site_transformer` のような `site_{名前}` のモデルで、接写の `_close` と遠景の `_far` を同じ原点・底面で持てる。設備は建物のメッシュに結合し、配管や構内灯のような小物は公園の木と同じく共有モデルで描く。外周の柵は敷地装飾の `fence-w` を門の位置で開けて使い、門には `gate` を置く。各設備は自分の位置の地形標高に接地し、遠景は設備ごとの `_far` を同じ配置に置く。モデルフォルダに無い部品は置かない。

## ガソリンスタンド

ガソリンスタンド（`MODEL_GAS_STATION`）も区画の形から配置計画を作る。配置はコアから届かず、プレイヤーが編集することもない。建物の底面は土地区画より小さいので、配置計画は底面ではなく土地区画の全体を敷地にし、底面の正面の辺が面する区画の辺を接道辺として扱う。区画を引けないときは底面を使う。

敷地は全体をコンクリートの土間にし、縁に縁石付きの植え込みを巡らせて、接道辺に車の出入口を開ける。奥の角に売店 `site_store` を置き、給油場は、屋根1区画とアイランド・給油機2基を1つにした `site_canopy` を、売店と道路の間（そこに入る数が少なければ売店の横）へ前後左右に隙間なく連ねて1枚の屋根にする。区画の数は敷地の面積に比例し、屋根の縁の帯 `site_fascia` は隣に区画の無い辺にだけ付く。敷地が狭いほど、売店の前の駐車枠、売店の順に諦め、売店の代わりに事務所 `site_office` を置き、最後は給油場だけになる。

周りには、価格看板 `site_sign`、地下タンクの注油口 `site_fill` と通気管 `site_vent`、空気入れ `site_air`、ごみ置き場 `site_dumpster` を置き、売店の前・空いた地面・敷地の縁に駐車枠を引く。売店の前の物 `site_clutter1`…、停まっている車 `site_car1`…、植え込みの低木 `site_shrub1`… と木 `site_tree1`… は、番号付きの部品を1から連番である分だけ使う。部品の持ち方と描き方は供給処理施設と同じで、給油場・売店・事務所・看板が遠景 `_far` を持つ設備、ほかは共有モデルで描く小物である。外周の柵と門は持たない。

## 地形や線路とつながる施設

### 港湾岸壁

港（`MODEL_PORT`）は、船が着く水際と、その陸側で荷を扱うヤードからなる。水際に荷役設備 `port_crane`、区画の辺0（道路側）に施設 `port_building` を置き、その間の空きに段積みのコンテナ `port_container{n}` または地面に並べる荷 `port_cargo{n}` を置く。荷の種類は港ごとの `a{variant}` が持ち、配置は区画・水際の形と通常モデルの寸法、`visual_variant2` から決まる。道路への間口は `port_building` の中の目印から得る。

天然の海岸では、建物の `berth_line` として返る岸壁の線で海側を切り、岸壁の板を海底まで押し出す。Unity はこの線を自分で求めず、建設のプレビューも応答が返す線を使う。区画の形と岸壁の線の意味は[土地形状](B_土地形状.md)を参照する。上面は `floor` のマテリアルで陸側の敷地と一続きに見せる。埋立地の上の港は、[地形が描く岸壁](D_地形形状.md)を使い、板を作らない。埋立地の変化は建物の version に表れないため、埋立地の中身が変わったら港も描き直す。水際は[入港船の接岸位置](V_環境演出の乗り物.md)にも使う。

### 車両基地

車両基地（`MODEL_RAIL_YARD`）は、敷地内の線路を接続端子ノードへ収束させて描く。留置線・集約線・分岐の曲線、架線と柱、車止め、検修庫を `yard_*` パーツで並べ、引き込み線は端子につながる線路の軌道数に合わせる。設備は地形に沿わせ、地面パネルは `a{variant}` 自身の `floor` だけを使う。クリック判定は架線柱の高さまで底面を押し出し、架線や検修庫も選べるようにする。

端子は `depot_node_id`（無ければ `infra_node_id`）で、電化した基地では走行網と送電網に共通のノードになる（[財の供給と輸送](../economics/17_財の供給と輸送.md)）。端子の位置や接続線路は建物の version を変えずに変わるので、その変化を建物側へ知らせて描き直す。

### 露天掘りと採石場

露天掘り（`MODEL_OPEN_PIT`）と採石場（`MODEL_QUARRY`）は、地形そのものを掘る。掘った形は、採掘に応じて版が変わった地形セルを取り直して描く（[LOD処理](E_LOD処理.md)・[財の供給と輸送](../economics/17_財の供給と輸送.md)）。建物として描くのは、掘らずに残る前庭の設備と、敷地に散らばる重機・岩・資材、掘っている場所で働く重機である。前庭は底面の正面の辺からの帯で、奥行きは露天掘りが `OPEN_PIT_YARD_DEPTH`、採石場が `QUARRY_YARD_DEPTH` である。

| 方式 | 掘り方 | 掘る範囲 |
| --- | --- | --- |
| 露天掘り | 下へ掘り下げる。平地では段々の穴になる | 前庭からさらに `OPEN_PIT_RIM_MARGIN` 奥。区画の境界からも同じだけ離す |
| 採石場 | 奥の山を前庭の高さまで階段状に切り崩す。床は前庭から水平に続き、平地は掘らない | 前庭のすぐ奥。区画の境界から `QUARRY_RIM_MARGIN` 離す |

前庭の設備は、供給処理施設と同じ規則で区画の形と部品の実寸から並べる。配置はコアから届かない。露天掘りは、掘り出した岩が穴から門へ流れる順に、穴の縁に沿う搬出路、受入口を穴へ向けた破砕プラント `site_crusher`、そこから高架の搬送コンベヤ `site_conveyor` でつながる製品の山 `site_stockpile1`…、製品を積み出す構内道路、通り側の事務所・整備工場と続く。間口が広ければ、破砕プラントと山の組を繰り返す。採石場は前庭が1列で、門の脇の事務所と、受入口を切羽へ向けた破砕・ふるいのプラント `site_plant` を間口に沿って置き、その間に製品の山と沈殿池が入る。

設備の間の空いた地面には、停めた重機（`site_truck`・`site_loader` など）と、岩 `site_rock1`…・ずりの小山 `site_heap1`…・資材 `site_clutter1`… を、向きと位置をそろえずに散らす。岩と小山は敷地の縁と掘る範囲にも置く。番号付きの部品は、1から連番である分だけ使う。これらは公園の木と同じく共有モデルで描き、遠景には出さない。掘っている場所で働く重機（ショベルとダンプの組）は、今の地形から掘っている高さ（露天掘りは最も低い所、採石場は床）を探して置くので、掘り進むにつれて移る。

建物の中心は掘る範囲の中にあるため、中心の高さで区画を押し出すと前庭に届かず、平面や白い箱は穴を塞いでしまう。クリック判定には地形に沿う区画の面と設備ごとの外接箱を使う。地面パネルは前庭と掘る範囲を含む区画全体に敷く。

## 工事中・解体中・倒壊

建設中・解体中は、敷地を覆う土を土台にし、状態に応じた足場・建機を載せる。地面型・オープンスペース・港・車両基地・露天掘り・採石場は土だけで表す。倒壊はどの方式でも瓦礫の山で表す。

| 状態 | 描画 |
| --- | --- |
| 建設中（`STATUS_CONSTRUCTING`） | 土の地面パネル、`scaffold-wall`・`scaffold-corner` の足場、一定以上の階数で `crane-*` のタワークレーン |
| 解体中（`STATUS_DEMOLISHING`） | 土の地面パネル、`demo-scaffold-wall`・`demo-scaffold-corner` の足場、`demo-ceil` の天面と、その上に載せる `excavator` のショベルカー |
| 倒壊（`STATUS_COLLAPSED`） | 建物の容積に見合う量の瓦礫と砂が安息角で積もった山。高い建物ほど高く広く積もり、底面の外の区画や道路へ不揃いに広がる。接写では、底面の中に鉄筋の出た折れた柱が残る。焼失（`status_reason` が `REASON_FIRE`）は焦げた材質 |

足場の段数は `construction_progress`（建設・解体に必要な体積のうち調達済みの割合。百分率）から決める。建設中は進捗とともに積み上がり、解体中はまだ取り壊していない割合の階数だけが残る。どちらも最低1階分を描き、進捗や竣工で建物の version が上がると差分ロードで描き直す。工事系パーツは建物のフォルダに無ければ `common` を探し、それでも無いものは省く。
