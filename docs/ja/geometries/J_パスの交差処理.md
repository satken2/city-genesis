# パスの交差処理

パスの交差・接続の意味と、Unity の敷設プレビューとコアの検証結果の扱いをまとめる。形状データの意味は[A_パス形状](A_パス形状.md)、描画の組み立ては[G_道路メッシュの生成](G_道路メッシュの生成.md)を参照する。

## 交差と接続

道路網はノードとパスのグラフである。平面上で線が交わることと、通行できる接続があることは区別する。Unity は取得したノードとパスの関係を使い、見た目の重なりから接続を作り直さない。計画中・建設中のパスは、完成した道路網と同じ接続情報を持つとは限らない。

平面交差は同じ高さで接続する交差点や踏切、立体交差は高さを分けて独立して通る状態を指す。通行空間の重なりは敷設時の干渉として扱う。インフラや駅舎など、道路とは接続の意味が異なるパスもあるため、すべてのパスに道路の交差点描画を当てはめない。

インフラのパスでは端点と接続ノードの y が異なることがある。Unity は端点をデータの高さのまま描き、高低差をつなぐ部品を追加しない。

## Unity のプレビューで共有する形状

敷設中の吸着や干渉表示は、保存形状と同じ座標・高さの約束に従う。特に地形に沿わない区間では、相対高さ y を補間した値だけで路面の高さを比べない。アンカーの基準面が異なるため、交点での絶対標高を使う必要がある。通行空間の高さはマスターの `height` を参照し、判定には共通の形状計算を使う。

線路の接続では、位置だけでなく高さや接線の整合もプレビューに必要になる。水域を渡るパスでは、地面と水面を区別する。こうした操作の補助に使う計算と許容誤差は Unity の編集処理・共通の形状計算・共有定数を参照し、画面ごとに別の規則を持たせない。

## 検証結果の扱い

Unity の判定は操作中の推定であり、最終的な可否はコアの応答に従う。`POST /api/v1/paths/validate` は都市を変更せずに検証結果を返す。ローカルのプレビューで問題がなくても、岸壁や造成中の土地などに関する違反が返ることがあるため、API の結果を反映する。

接続形状の違反を表す `junction_violations` と、占有の干渉を表す `colliding_path_ids` は区別して表示する。接続違反の位置は `[x, 路面の絶対標高, z]` であり、保存されるパスの相対高さとは異なる。水域や土地などの違反も、応答の対象種別に対応する ID として解釈し、パス ID と混同しない。項目の一覧は API 資料を参照する。

碁盤状などの敷設では、`POST /api/v1/paths/layout` が返すパスの一覧を検証・確定の入力に使う。フロントは同じ配置を別の規則で作り直さない。プレビュー・確定・結果の再取得の責務は[IPC連携](../programs/IPC連携の整理.md)に従う。
