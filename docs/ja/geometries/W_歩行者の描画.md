# W. 歩行者の描画

歩行者は、Unityがカメラの周辺だけに描く描画専用の演出で、経済シミュレーションやコアの永続データには影響しない。人数は、パスの `path_traffic` のうち歩行者(`VEHICLE_PEDESTRIAN` のキー)の1日あたりの通過数から決める。

考え方は[車両の走行描画](O_車両の走行描画.md)の一般車と同じで、歩行と人数の調整は別の処理であり、建物の入口(`RoadsideAccess`)と管理範囲の中心も一般車と共有する。違いは、`PATH_STREET` と `PATH_WALKWAY` の歩道の帯の中を一方通行でも両方向に歩くこと、速さはコアの歩行速度と同じ値を平均とする一定の速さで所要時間の取得が要らないこと、信号や衝突を扱わず人も車もすり抜けることである。実装は `PedestrianManager`。

新しく管理する区間への配置も一般車と共通で、道路データの走査が確定した時点で区間全体に人数を分散する。通常の人数調整に使う入口・境界からの流入を待たない。

## 駅と停留所を使う人

駅と停留所を使う人も歩行者の演出で、人数は路線一覧の停留所ごとの1日の乗車回数(`stop_points` の `ridership`)から決める。降車の回数は返らないので、乗車と同じ数とみなす(往復の帰りは同じ停留所で降りるので、1日で見ると停留所ごとの乗車と降車はほぼ等しい)。歩行者と同じ表示倍率・上限の割合で間引き、個体は市民にも、場面をまたいだ個体どうしにも対応しない。

ホームで待つ人数は、毎秒の乗車数と前の便の発車からの経過時間の積である。車両と同じ路線の時計で決まるので、編成が停まると、降りる人がドアから出て、待っていた人がドアへ入る。バス停と駅舎の入口は道路の歩行者とつながる場所で、前を通る歩行者が「乗車数 ÷ 道路の歩行者交通量」の確率で並ぶか入り、降りた人や駅から出てくる人は道路の歩行者になる。道路全体の人数は通常の人数調整が合わせるので、交通量どおりのままである。駅舎の入口は、建屋を置いた端から最寄りの歩行者道路へ下ろした垂線の足に置く。地下の停留所には描かない。

## 描画とモデルの命名

歩行者はGameObjectを持たず、全員をGPUインスタンシングで描く。手足はボーンを使わず、姿勢の違う3つのモデルを歩いた距離に応じて差し替えるコマ送りで動かす。モデルは `Assets/Models/Props/` に固定名で置き、Unityは `pedestrian_0` から番号が欠けるまで順に読む(1つも無ければ人型の箱で描く)。原本は `blender/props.blend`。

| モデル名 | 姿勢 |
|---|---|
| `pedestrian_{n}` | 両足を揃えた姿勢 |
| `pedestrian_{n}_right` | 右足を前へ出した姿勢 |
| `pedestrian_{n}_left` | 左足を前へ出した姿勢 |
