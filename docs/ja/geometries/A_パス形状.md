# A. パス形状

パス（道路・線路など）の形状データの表し方と、Unity とコアが同じ形を得るための約束について。パスの種類と役割は[パスとノード](../economics/3_パスとノード.md)、交差と接続は[J_パスの交差処理](J_パスの交差処理.md)を参照。

## 座標と高さ

パスの点は `[x, y, z]`（m）で、y は**基準面からの相対高さ**であり絶対標高ではない。基準面は、海・湖の水の上では水面、それ以外（川を含む）では地面である。アンカー（`start_point`・`end_point`・ウェイポイントの `position`）の y はアンカー直下の基準面から、制御点の y はその制御点が属するアンカーの直下の基準面から測る。制御点の直下を基準にすると、アンカーの間の起伏が曲線に入り込み、保存された形と食い違う。水の上でも、橋脚の長さやトンネルの深さの基準は水底の地面である。

1本のパスには地上・高架・地下の区間が混在できる。高さの編集には `path_master` の `height_editable`・`min_height` などの設定を使う。アンカーの y による高さの指定と、地表の道路の盛土・切土は区別する。

## 曲線と制御点

パスはアンカーの間を1本ずつの3次ベジエでつないだ形で、アンカー i から i+1 へのベジエは、アンカー i・その出口制御点（`start_control` または `control_out`）・アンカー i+1 の入口制御点（`end_control` または `control_in`）・アンカー i+1 の4点で決まる。`curved` が偽のパスはアンカーの間を直線で結び、制御点を使わない。

Unity は保存された制御点を優先する。省略された制御点の補完と接続先への向き合わせには、プレビューと描画で共通の形状計算を使う。コアとの整合も必要なので、片方だけ規則を変えない。具体的な計算は Unity の形状計算・編集処理のソースを参照する。

## 地形追従（follow_terrain）

アンカーの間（スパン）は、両端のアンカーの y が0で、かつパスが地形追従するときだけ基準面に沿う。それ以外の非追従スパンは、アンカーと制御点を所属アンカーの基準面で絶対標高にしたものだけから補間し、途中の地形を見ない（直線のパスは両端の絶対標高を直線で結ぶ）。地形追従するかはパスの `follow_terrain` で決まり、-1（未設定）なら `path_master` の `follow_terrain` に従う。追従しないパスは、y が0のままでも谷では橋、丘では切り通し・トンネルになる。

## 盛土と設計縦断

地表のパスの盛土・切土は `embankment_heights`（アンカーごとの高さ m。正が盛土、負が切土）として指定する。Unity は取得した造成後の地形を使い、描画時に盛土・切土や平滑化を重ねて適用しない。

設計縦断（`station_grade_profile`）は、地形から独立した路面の基準線で、点列は `[x, 絶対標高, z]` である。これを持つパスの描画では、アンカーの相対高さや地形より設計縦断を優先し、基準線へ水平に射影した標高を使う。点列の間隔が一定であると仮定せず、取得した形を使う。

## 長さと占有範囲

`length` は始点から終点までの直線距離（`curved` が偽ならアンカーを結ぶ折れ線の長さ）で、曲線に沿った長さではない。`polygon` はパスが水平面で占める範囲であり、重なりや干渉を表すためのデータである。路面の描画は中心線とマスターの寸法を使う。

## 敷設できる形

Unity の編集では、マスターが示す曲線・勾配・高さなどの制約を操作の補助に使う。最終的な可否はコアの検証結果に従う。判定とプレビューの役割は[J_パスの交差処理](J_パスの交差処理.md)、都市の範囲は[D_地形形状](D_地形形状.md)を参照。
