# LOD処理

Unity の描画では、どのセルのデータを持つか（常駐範囲）、地形をどう描くか、物体1つをどの細かさで描くか（描画LOD）を、それぞれ独立に決める。データの取得と差し替えの順序は [バックエンドデータロード](H_バックエンドデータロード.md)、地形データの形式と座標の約束は [地形形状](D_地形形状.md) を参照する。

## 責務と所有者

| 責務 | 主な実装 | 決め方 |
| --- | --- | --- |
| 常駐範囲 | `LodConfig` / `CameraCellChecker` | 注視点とカメラの周りから、視野と距離で常駐セルを選ぶ |
| 地形の描画 | `TerrainManager` / Unity Terrain | 常駐セルは現在標高のタイル、その外は超遠景の陸地と背景地形 |
| 接地 | `Utils.GetGroundHeight` | 表示中の地形タイル。無ければ全域の現在標高か背景地形 |
| 建物・道路の描画LOD | `DrawLodEvaluator` | 建物は画面上の大きさ、道路は最も近い点までの距離 |
| プロップ | `PropManager` | 画面上の大きさと実距離 |
| 生成の時間予算 | `RenderWorkScheduler` | 全生成器の同期処理時間の合計 |

常駐セルの集合（`LodCellSets`）と `LodTier` に残る far・near・dynamic の名前は既存のマネージャーへの互換の入口で、どの集合にも同じ常駐セルが入る。これらの名前から、地形の取得元・接地するかどうか・遠景のメッシュに固定するかを決めてはならない。

## 常駐範囲

常駐セルは、カメラの注視点の周りとカメラの近くから候補を作り、視野と距離で順位を付けて上限の数まで選ぶ。注視点は、地形のコライダーではなく高さ0の数理平面と視線の交点にする。地形のロードで注視点が動き、それがまたロードを起こす連鎖を断つためである。常駐中のセルは少し外れても残りやすくし、カメラのわずかな変化で縁のセルが出入りを繰り返さないようにする。

常駐範囲の外は、超遠景の陸地と背景地形が地面を、都市全域の超遠景が建物と地上の道路を埋める。カメラの遠方クリップは、マップと背景の最も遠い隅まで届くように延ばす。

Unity とコアはマップ中心を原点とする座標を共有し、Unity はカメラが遠くへ動いても原点を移さない。Transform だけを動かすと、地形セル・未ロード部分の高さ・保存するカメラの座標・ドラッグの基準点が食い違うためである。

## 地形の描画

常駐セルの地形は、どのセルも同じ解像度のタイルでコアの現在標高から作り、画面上の細かさの調整は Unity Terrain に任せる。隣のセルと境界の格子点を共有するので、継ぎ目で高さがずれない。

常駐範囲の外の陸地は、都市全域で1つの超遠景の陸地メッシュで描く。メッシュはコアの海岸線の内側だけに張り、海は海面の板に任せるので、粗い起伏が海面を突き抜けて沖に陸が現れることがない。常駐タイルが表示されているセルでは、超遠景の陸地をシェーダーで地中へ沈めてタイルの上に突き出さないようにする。

常駐セルのタイル・超遠景の陸地・都市外の背景地形は同じ地表の表現（手続きの色、崖の岩、砂浜、標高と傾斜による色、等高線など）を共有し、ロードの境目で配色が切り替わらない。地表種別ごとの配色と質感は、共通のシェーダーを変えずに `GroundCoverPalette` で調整する。`TerrainManager` が3種類の地面のマテリアルへ同じ値を設定する。

## 接地

CPU で地面の高さを求めるときは `Utils.GetGroundHeight` に統一する。表示中の地形タイルがあればその高さ、無ければ都市の中では全域の現在標高、都市の外では背景地形の高さを返し、埋立地の帯の中では地形と岸壁の天端の高い方を返す（[地形形状](D_地形形状.md)）。全域の現在標高で仮に接地した物体は、詳細なタイルが届いたら置き直す。区画の塗りなど GPU で地形に沿わせる描画は、カメラの周りの移動窓の高さテクスチャを使う。

## 物体の描画LOD

建物・道路は1つずつ、接写（Close）・通常（Normal）・遠景（Far）を選び、プロップはさらに描かない（Hidden）を持つ。建物は画面上の大きさ、道路はアンカー点列までの最近接距離、プロップは画面上の大きさと実距離で選ぶ。昇格と降格のしきい値に差を付けて境界での切り替わりの繰り返しを防ぎ、組み立ての重い接写は目の前の少数に限る。値は `DrawLodConfig` にある。建物の遠景と接写のパーツは [F_建物メッシュの生成](F_建物メッシュの生成.md)、道路の遠景は [G_道路メッシュの生成](G_道路メッシュの生成.md) に定める。

遠景から通常・接写へ上げるのは、建物が接地する・道路が通る常駐セルの地形タイルが公開されてからにする。全域の現在標高で作った詳細な形を、タイルの到着ですぐ作り直さないためである。長い通常の道路は路面を固定のスプライン区間に分け、区間ごとに描画LODを切り替える。

道路の描画中心線（交差点で切った後の点列）は、道路データと通過セルの地形の版が同じ間は計算し直さない。中心線が変わると道路の形状の版が進むので、車両や公共交通のハイライトなど道路に沿って描くものは、この版で中心線の変化を知る。

## 都市全域の超遠景

建物と地上の道路は、常駐範囲に関係なく都市全域を最初から描く（`CityOverviewManager`）。コアの全域の概観一覧を地形セルごとの結合メッシュにまとめ、建物は遠景と同じ高さの箱、道路は遠景と同じモデル・板にし、高さは全域の現在標高に置く。実物（遠景・通常・接写のどれか）を表示している建物・道路と、表示フィルタで隠したものは除き、二重に描かない。一覧はエポック完了・編集の確定のたびに取り直し、変わったセルだけを作り直す。

## プロップと森林

範囲配置の森林は GPU で散布する。それ以外のプロップは、保存座標から決まる固定の順位で常駐の候補を間引き、予算が変わっても同じ点が残るようにする。詳細は [地形プロップ](M_地形プロップ.md) に定める。

## 生成の予算と寿命

描画物の生成はフレームの時間予算を共有する。生成のコルーチンは `RenderWorkScheduler` で開始・停止し、すべての生成器の同期処理の合計を、実際のフレーム時間の一定割合（目標フレーム時間での値を下限とする）に抑える。Unity の `StopCoroutine` だけでは内側の処理が破棄されないので直接使わず、所有する GameObject が無効化・破棄されたときもその仕事を止める。地形タイルの公開、土地区画の配置、建物データの取り込みは、他の生成より先に進める（物体の詳細は地形を、建物の生成は区画と建物データを待つため）。建物の地面パネルや一部の敷地装飾、歩行者や一般車の演出のように後から現れてよい仕事は優先度を下げ、通常の生成が使い残した予算でだけ進める。後回しの敷地装飾は、カメラに近い建物から作る。

退避した描画物のメッシュは、対象ごとと全体の上限を持つ LRU で保持し、上限は PC のメモリ量から決める。

## 海面・水面の描画と深度オフセット

海面は、シーンに置いた標高0m（ワールドY=0）の板である。湖・川の水面も同じ水面シェーダー（`Custom/WaterLit`）で描く。地形タイルは海底を表すために負の標高まで描くので、標高0mの地形と海面は同じ深度に来る。この重なりで面がちらつかないよう、シェーダーの深度オフセットで同じ深度での前後を決める。

| 描画対象 | シェーダー | 同じ深度での前後 |
| --- | --- | --- |
| 建物・道路などの物体 | `Custom/DepthOffsetLit` | 地形より手前 |
| 海面・湖・川 | `Custom/WaterLit` | 地形より手前（水面が水底を覆う） |
| 常駐セルの地形タイル | `Custom/DepthOffsetTerrainLit` | 物体・水面より奥 |
| 超遠景の陸地 | `Custom/DepthOffsetSimpleLitFar` | 最も奥 |

この順序により、海岸線は地形の標高0mの等高線に沿って現れる。物体や水面のマテリアルを深度オフセットの無いシェーダーに差し替えると、遠景で Z-fighting が起きる。

## 路面標示のLODと画像予算

路面標示の画像の解像度は、道路の形の描画LODとは別に、画面上の大きさで選ぶ。標示の画像は内容ごとに共有するページへ焼き込み、固定の画像予算の中で保持し、足りなければ解像度を下げるか複雑な標示を省く。標示の画像を待つことは、初期ロードの完了条件にしない。
