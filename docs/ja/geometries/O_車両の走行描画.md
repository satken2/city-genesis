# O. 車両の走行描画

道路を走る一般車、路上駐車、路線に所属するバス・列車、索道の搬器を、Unityがカメラの周辺だけに描く。どれも描画専用で、経済シミュレーション・コアの永続データ・セーブには何も書き戻さない。交通量・所要時間・運行の正はコアにあり、Unityはそれを道路と線路の上の動きとして再現する。時間と流量の契約は [交通シミュレーションと走行描画の整合](T_交通シミュレーションと走行描画の整合.md) に定める。

## 一般車

入力は、パスの `path_traffic` と、`POST /api/v1/paths/motion` が返す通過秒数(自由走行と混雑込み)と `length_m` である。`path_traffic` は車種ID(文字列のキー)ごとの1日あたりの通過数で、方向別・右左折別の内訳は持たない。`length_m` は中心線に沿った水平の長さで、2つの秒数と同じ道のりを表す(端点間の直線距離ではない)。

道路ごとの台数は、日次の交通量を活動時間で割った流量に、管理範囲の中の区間を通過する時間を掛けた値を目安にし、全道路の合計を整数化して全体の枠にする(道路ごとに切り上げない)。初回表示・カメラ移動・道路データの追加で新しく管理する区間には、最初からその密度で走行中の車を分散して置く。すでに管理している区間の個体は維持し、新しい区間の配置は交通演出の時計の停止中も行う。車体の生成はフレームごとの時間予算に従う。

走行と台数の調整は別の処理で、車は交差点で消えずに次の道路へ進み、通常の台数の過不足は建物の入口と管理範囲の境界での出入りで直す。建物の入口は区画の道路に面した辺に描画用に設ける位置で(`RoadsideAccess`。歩行者と共有)、建物モデルの玄関の位置は使わない。

管理範囲はカメラの注視点を中心とする円で(乗車中は乗車位置、市民の追従中は追従している対象)、路上駐車と歩行者も同じ中心を使う。車線の範囲は道路の区画線と同じ定義(`RoadLaneLayout`)を共有し、走行位置はその車線内、駐車位置は車道端を基準に求める。交差点では同じ車種の交通量を重みにした抽選で次の道路を選ぶ。信号・譲り合い・衝突は扱わない。どれも描画の規則で、コアの経路探索や所要時間は変えない。

一般車と歩行者は交通量を再現する描画上の個体で、特定の市民と一対一には対応しない。市民を選ぶ操作ではコアから推定結果を受け取り、追従中はその行程を描く。推定も追従も都市の状態を変更しない。

## 路上駐車の描画

`parked_cars` は、その道路に同時に停まっている台数(合法な分と容量を超えた分の合計)で、日次の交通量のような換算はしない。`ParkedVehicleManager` が、`street_parking_capacity` が正の街路に静止した車を並べ、表示は容量で頭打ちにする。並びは道路IDから決めるので、カメラの移動で入れ替わらない。

## 路線に所属する車両

`TransitVehicleManager` は、稼働中の路線について、調達した車両で組める編成だけを描く。表示する編成数は、調達した車両数 `vehicle_count` を1編成の両数 `cars_per_train` で割った整数で、`train_count`(運行に必要な編成数)ではない。各編成の位置はコアの走行プロファイル `journeys` と停車時間から時刻で求めるので、画面外でも同じ時計で進み、誤差が溜まらない。停留所の停止位置は編成の中心を表す。軌道の選び方と横位置は線路・軌道のメッシュと同じ定義を使い([線路メッシュの生成](N_線路メッシュの生成.md))、経路の一部が未ロードなら、その編成は描かない(欠けた経路を直線で補わない)。

外観は路線ごとにプレイヤーが選ぶ `vehicle_model` を使い、描画と走行音だけに効く。車体の帯などは路線カラー `line_color` で塗る。路線種別と車種、外観の候補、塗る部位、走行音の対応は `Resources/Config/` の設定ファイルに持ち、外観の番号はUIの選択肢(`tauri/src/data/transitVehicleModels.json`)と揃える。

公共交通のハイライトも車両と同じ走行形状を使い、停留所を直線で結んだ別の経路を作らない。

## モデルの命名

モデルは `Assets/Models/Vehicles/{車種}/` に置き、原本は `blender/vehicles.blend`。Unityは `{車種}/{外観}`、`{車種}`、乗用車(`VEHICLE_STANDARD`)、箱の順に探すので、モデルが無くても動く。

| モデル名 | 役割 |
|---|---|
| `0`・`1`… | 外観ごとの車体。列車では先頭車で、最後尾はUnityが反転して使う |
| `middle`・`middle_{外観}` | 列車の中間車(外観0は `middle`) |
| `wagon`・`wagon_{n}` | 貨物列車の貨車 |
| `{モデル名}_close`・`{モデル名}_far` | 接写・遠景(任意) |

自由配置用に、同じ形状を数値IDの別名として[地形プロップ](M_地形プロップ.md)に登録している。

## 交通演出の時計

一般車・公共交通・索道・航空機と船・歩行者は、Unity全体の `Time.timeScale` ではなく交通演出の時計 `TrafficClock` で進む。交通の一時停止はこの時計だけを止める。走行音は車両ごとに鳴らさず、位置と速度を共通の音声管理へ通知する([サウンドシステム](../programs/サウンドシステム.md))。

## ドライブモード

プレイヤーは車を走らせたり、列車に乗ったり、走行中の車両の運転を眺めたりできる(`DriveMode`)。既存の交通演出の個体をそのまま使う描画だけの機能で、乗車中は管理範囲の中心を乗車位置へ移す。乗車の状態はコアにもセーブにも残さない。開始はUIとの往復で始まる([IPC連携の整理](../programs/IPC連携の整理.md))。

## ロープウェイの循環描画

`RopewayCabinManager` は、完成した索道(`PATH_CONVEYOR`)で2つ以上の駅をつなぐ区間に搬器を循環させる。運行間隔・車両・輸送力を持たないグラフィックの演出で、交通量やエポックとは独立している。搬器と終端設備のモデルは `Models/Paths/` に置く。
