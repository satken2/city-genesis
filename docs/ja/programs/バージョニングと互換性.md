# バージョニングと互換性

コア、フロント、IPC は別の版で互換性を表す。接続できること、セーブを読み込めること、同じゲームルールで動くことを区別する。

| 番号 | 表すもの |
| --- | --- |
| `core_version` | コアと、それが使うマスターデータ・標準パラメータの組 |
| `frontend_version` | Tauri と Unity を合わせたフロントの配布物 |
| `ipc_contract_version` | Tauri・Unity 間の通信契約 |

## プログラム間の互換性

コアとフロントの版は独立した `MAJOR.MINOR.PATCH` で、数値として比較する。フロントの MAJOR がコアの MAJOR 以上で、Tauri と Unity の IPC 契約番号が一致する組を使う。版を取得・解釈できないときに互換と推測しない。

フロントの版と IPC 契約番号の正は公開リポジトリの `version.json` で、配布設定と Unity の定数はそこから同期する。コアの版は実行時に取得し、フロントに固定しない。

IPC 契約はイベント名だけでなく、項目の型や ID の意味を含む。相手の実装を変えないと動かなくなる変更では契約番号を上げる。通信開始時の照合は[IPC連携](IPC連携の整理.md)に従う。

## 版を上げる意味

コアの PATCH はセーブ互換性とゲームルールを保ち、MINOR はセーブ互換性を保ちながらルールやバランスを変え得る。MAJOR をまたぐセーブは通常のロードでは引き継げない。

フロントは修正で PATCH、機能追加で MINOR、操作体系・保存設定の非互換変更やコアの MAJOR への追従で MAJOR を上げる。UI だけ・描画だけの変更でも、配布する組には同じ版を付ける。

## セーブの互換性とルールの変更

通常のロードで読めるのは、保存したコアが実行中のコア以前の版で、MAJOR が同じセーブである。読み込んだ都市は実行中のルールで動くため、読み込み可能でも以前と同じ結果になるとは限らない。

ルール変更の確認は、最後に保存した版ではなく、最後にエポックを計算した版を基準にする。ロードして保存しただけで確認を省略できないようにするためである。UI はコアの `balance_changed` を表示し、必要な場合はプレイヤーの承諾を得て読み込む。[セッションと保存](セーブデータ仕様.md)も参照する。
