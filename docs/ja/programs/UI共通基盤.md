# UI共通基盤

Tauri の UI は複数の WebView で構成する。Rust がウィンドウの寿命・配置と共有状態を管理し、React が内容を描く。ブラウザ版では Web シェルが同じ管理責任を持つ([コンポーネント連携](コンポーネント連携.md))。

## ウィンドウの寿命

ウィンドウの種類・配置・同時に開ける組は共通の管理で定める。新しく開く画面の初期データはウィンドウのコンテキストで渡し、購読前に送ったイベントへ依存しない。

ポップアップは閉じても非表示で再利用されるため、React のアンマウントと操作の終了は一致しない。再表示時には対象と編集状態を初期化し、非表示中のイベントが Unity への操作などの副作用を起こさないようにする。閉じるときの編集終了・ハイライト解除はウィンドウ管理が担う。

透明な WebView も入力を受けるので、常駐 UI のウィンドウは実際のパネル面積に合わせる。モニターや DPI をまたぐ配置は共通の管理に任せ、画面ごとに位置を補正しない。

## 共有状態とデータの表示

セッション・版情報・プレイモードは共通の状態を参照し、画面ごとに取得や判定を複製しない。編集と表示の同期は[IPC の原則](IPC連携の整理.md)に従う。ウィンドウをまたぐ変更は、変更に成功した側がグローバルイベントで知らせ、受け手が表示を更新する。

統計は接続先とエポックに対応する共通のキャッシュを使い、API の確定値を表示する。欠測と0を区別し、過去の内訳に最新期の値を流用しない。

2D地図は共通の `CityMapCanvas` を使い、各画面が必要なレイヤーと重ね描きを与える。地図の座標・方位は[地形形状](../geometries/D_地形形状.md)と共有し、画面ごとに別の座標規約を作らない。経路案内はコアが返す計算時点の結果で、道路編集の即時反映や任意の2地点の厳密な最短経路を前提にしない。所要時間と経路選択用の重みも区別する。

## 共通スタイル

色・影・状態色は共通トークン、フォームやタブは共通部品を使い、各画面で同じ意匠を定義し直さない。本文・通常の項目や操作ラベルは共通の基準サイズに揃え、見出し・集計値・補足は情報の役割に応じて大小を付ける。

文字サイズはルートの設定に追従し、本文と連動する寸法は rem を基本にする。OS のウィンドウ配置など物理座標が必要な箇所とは分けて扱う。狭いウィンドウへの対応は実行環境ではなく、ウィンドウの幅で決める。具体的なトークンと寸法の扱いは共通スタイルと部品のソースを参照する。

## 言語と作者のテキスト

UI の文言は i18n リソースに置き、対応言語でキーと[ゲーム用語](../contributing/翻訳用語対応表.md)を揃える。言語やロケールの対応も共通定義を使う。

シナリオやクエストの紹介文は作者が入力する多言語データで、UI の翻訳リソースとは別に扱う。共通の入力・解決処理を使い、表示言語の文が無ければ必須の英語へ戻る。都市内の固有名詞の言語も UI の表示言語とは独立している。
