# IPC連携

IPC は Tauri と Unity の操作状態をつなぐ。都市データは両者がコアの HTTP API から取得し、IPC では対象の ID、操作の指示、編集中の状態を運ぶ。プロセス全体の関係は[コンポーネント連携](コンポーネント連携.md)を参照する。

## 通信の構成

デスクトップ版は方向ごとに独立した MemoryMappedFile(MMF)、ブラウザ版は同じページの JavaScript を使う。どちらも共通の Envelope で送り手・宛先・イベント名・ペイロードを表し、上位の操作は運び方を区別しない。

MMF は読み手がいない間も送信を溜める有限のバッファで、各方向の読み手は1つだけである。通常の UI・Unity の組に別の Unity を参加させたり、相手の不在中に状態を周期送信したりしない。接続を確立して[互換性](バージョニングと互換性.md)を確認してから操作を始める。

イベント名は `対象:動作` で揃える。UI からの操作は共通の `ui:action` に包まれ、Unity 側が振り分ける。Unity からの通知は Rust または Web シェルが受け、UI の各ウィンドウへ中継する。この中継も通信契約の一部である。

| 領域 | 契約を確認するソース |
| --- | --- |
| UI の送受信 | `tauri/src/utils/ipc.ts` |
| デスクトップの転送と Envelope | `tauri/src-tauri/src/ipc.rs`・`messages.rs` |
| Unity の送受信と Envelope | `unity/Assets/Scripts/IPC/` |
| ブラウザの中継 | `tauri/web/shell/` |

個別イベントの意味・ペイロードはソースのコメントを正とし、ここには一覧を持たない。

## 状態を同期する原則

- 状態の正は片側に置く。編集中の形状や表示は Unity が持ち、UI は指示を送り、通知された結果を表示する。
- 状態の通知は現在の全体、操作の指示は変えたい項目を送る。通知をそのまま送り返さず、操作と通知の往復を循環させない。
- 変更時と問い合わせ時に同期する。後から開いたウィンドウは購読を始めてから現在の状態を問い合わせ、過去に一度だけ届いた通知に依存しない。
- 非同期の結果は要求の世代と照合する。古い検証結果やロード完了が、新しい編集や都市へ適用されないようにする。
- 応答を待つ要求には、失敗や取消しでも応える。再接続時は現在の状態を送り直す。

## 編集ステートと確定

Unity の編集ステートは同時に1つで、対象ごとの[入力モード](Unity入力制御.md)と[表示モード](Unity表示モード.md)をまとめる。UI は編集の目的と初期条件を伝え、Unity が入力・表示・編集状態を整える。

コアへの確定送信は、確定の操作を持つ側が担当する。パネルに確定ボタンがある編集は Tauri、3D操作だけで完結する編集は Unity が送る。プレビューと確定を区別し、最終的な可否はコアの応答に従う。

確定後の後始末とデータの再取得は、共通の終了処理でまとめて進める。非同期の再取得と状態の切り替えを別々に走らせない。取消しは対象の編集だけを終え、すでに始まった別の操作を巻き込まない。[ウィンドウを閉じるときの管理](UI共通基盤.md)も、この終了処理へ合流する。

## 接続とロードの区別

Unity の接続準備ができたことと、都市の描画が完了したことは別の状態である。再接続では接続の確立からやり直し、設定を同期して都市をロードする。描画側の完了条件は[バックエンドデータロード](../geometries/H_バックエンドデータロード.md)に定める。
