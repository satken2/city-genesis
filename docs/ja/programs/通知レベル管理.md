# 通知とアラート

都市の問題は、緊急度と場所の重要性に応じて伝える。画面上の一時的な操作結果と、都市で続いている問題の通知は別の仕組みとして扱う。

## 伝え方の役割

| レベル | 伝えるもの | 表現 |
| --- | --- | --- |
| L1 | 常に把握しておくべき問題や重大な出来事 | 常駐のアイコン・件数と通知一覧 |
| L2 | 放置すると悪化する傾向 | エポック結果の統計 |
| L3 | どこで起きているかが重要な事象 | 3D空間のアラート |

場所の表示だけではカメラの外にある問題に気付けないため、都市全体の危機は L1 でも伝える。同じ事象でも深刻さによって伝え方が変わる。

L1 の `warning` は、都市の機能が損なわれつつあり、プレイヤーが近いうちに手を打てる問題を表す。`caution` と区別して注意を促し、急ぎでない問題で強い警告が常態化しないようにする。重要度の判断はコアが担う。

## 通知データと文言

フロントはコアが返す現在の通知を表示し、発生条件を計算し直さない。続いている問題と、そのエポックだけの出来事を区別し、都市を切り替えたら以前の通知を引き継がない。

コアは通知の種類と差し込む値を返し、UI が表示言語の文言へ変換する。未知の種類でも汎用の文言で表示できるようにし、コアの更新により通知全体が表示不能にならないようにする。操作結果などの一時的な知らせは、UI の共通通知処理を使う。

## 3D空間のアラート

`status` は建設・稼働・解体などのライフサイクル、`alert` は調達不足や事故など観測された問題を表す。アラートは直近のエポックの状態であり、描画中に独自の判定で発生・解消させない。

アラートだけの変化ではメッシュ用の版は変わらない。Unity は専用の API から取得し、描画物の差分更新とは独立して表示を更新する。建物と道路のビットは別の名前空間で、共有定数を使って解釈する。

場所を持つ重要な通知も空間に表示できるが、エンティティ自身のアラートとは区別する。表示対象・フィルタ・個別の演出は共有定数と描画側のソースを正とし、表示モードの管理は[Unity表示モード](Unity表示モード.md)に従う。
