# コンポーネント連携

City Genesis は、都市の状態と経済計算を持つコア、操作 UI を担う Tauri、3D描画と空間の入力を担う Unity で構成する。フロントはコアの結果を表示し、プレイヤーの操作をコアへ送る。経済の計算や編集の可否をフロントで再実装しない。

| 経路 | 通信 | 役割 |
| --- | --- | --- |
| Tauri・Unity → コア | HTTP | 都市データの取得、編集の確定、エポックの実行 |
| Tauri ⇔ Unity | [IPC](IPC連携の整理.md) | 選択、編集中の状態、表示、ロードの進行の同期 |

## HTTP と共有状態

コアは URL で接続する相手として扱う。UI や Unity と同じ PC にあることを前提にせず、コアが管理するファイルも API を通して扱う。クライアントのメモリや GPU などは Tauri が自分で測る。

HTTP は各モジュールの共通窓口を使い、版のヘッダーや接続先の扱いを揃える。Tauri の WebView は `fetchApi`、Rust は版照合済みの共通クライアント、Unity は `ApiClient` を使う。コアの版情報とセッション状態は Tauri が共通に取得・共有し、各画面が独自の監視を持たない。セッションの意味は[セッションと保存](セーブデータ仕様.md)に定める。

ローカル配布のコアは `127.0.0.1` で待ち受け、通常の API は同じ PC の外部プログラムからも使える。フロントの開発にも製品版のコアを使う。個別のパス・項目・エラーは、配布物の Swagger(`/docs`)・OpenAPI(`/openapi.json`)を参照する。

WebView の CORS と CSP はブラウザ側の制約であり、Rust・Unity の HTTP とは分けて考える。配布版の UI は実行時のコード生成を許可しない。開発サーバーと配布版では制約が異なるため、通信や依存ライブラリの変更は配布版でも確認する。

## プロセスの寿命

デスクトップ版は Tauri が入口となり、同梱のコアと Unity を子プロセスとして起動・監視する。コアへの接続を確立してから Unity を起動し、[互換性](バージョニングと互換性.md)の照合後にゲーム用の通信を始める。開発中に外部で起動したコアや Unity Editor に接続する構成も取れる。

接続先は起動側が渡す。コアの待受ポートは `GENESIS_API_PORT`、Unity の接続先は `--api-base-url`、外部コアへ接続する Tauri の接続先は `GENESIS_UI_API_BASE_URL` で指定する。

接続の喪失中は操作を止め、Unity の再起動時はコアから都市を取得し直す。アプリの終了は発生源によらず Tauri に集約し、自分で起動したプロセスへ終了を伝える。コアには実行中の処理と保存を終える時間を与える。

観察専用の Unity(`--viewer`)は都市を描くための別クライアントで、通常の Tauri・Unity 間の IPC に参加しない。編集やカメラ位置の保存も行わず、作業中のクライアントと同じ都市を観察できる。

## データの管理責任

| データ | 管理するもの |
| --- | --- |
| 都市、セーブ、自作シナリオ、プレイヤーのプロフィール | コア |
| 言語・音量などの UI 設定、地形エディタの作業コピー | Tauri |
| 3D画面の表示先・解像度 | Unity |
| 購読したシナリオと DLC の配置 | ストア |

都市をまたぐプロフィールと、都市ごとのセーブは別のデータである。編集中の表示などセッション内だけの状態は、永続データと区別する。Tauri の地形編集も、作業コピーの内容をコアの API へ送って確定する。

コアと Tauri が共有するユーザーデータ領域は `UrbanGenesis/` で、Windows は `%LOCALAPPDATA%`(無ければ `%APPDATA%`)、macOS は `~/Library/Application Support`、Linux は `$XDG_DATA_HOME`(未設定なら `~/.local/share`)を基準にする。保存先と UI が開くフォルダが食い違わないよう、同じ規則で解決する。

ストア連携は Tauri に集約し、認証チケットとストアが管理するフォルダをコアへ渡す。所有権や読み込み可否の判定はコアが返す結果を使う。ストアの実績もコアが判定してプロフィールに記録し、Tauri はその記録をストアへ写すだけにする。

## ブラウザ版

ブラウザ版は同じ UI と Unity を1ページで動かす。Unity の canvas に UI の iframe を重ね、Tauri の Rust に相当するウィンドウ管理・セッション監視を Web シェルが担う。コアにはページの外のサービスとして URL で接続する。

UI はビルド時に Tauri API をブラウザ向け実装へ差し替え、Unity・UI 間は MMF の代わりに JavaScript で通信する。環境の違いは共通の窓口に閉じ、各画面に別の状態管理や通信規則を持たせない。
