# セッションと保存

セッションは現在開いている都市と操作の文脈、セーブはその都市を後で再開するための記録である。保存と読み込みはコアが担当し、フロントは API を通して扱う。

## セッションの識別

都市を開くたびに変わる `session_id` で、別の都市への切り替えを識別する。上書き保存先の `current_save_id` は別名保存でも変わるため、都市の同一性の判定に使わない。都市を切り替えたら、以前の都市の ID・キャッシュ・進行中の要求を引き継がない。マスターも都市ごとに違いうる（コアはゲームを始めるたびに読み直す）ので、切り替えたら取り直す。

UI は共通のセッション状態を参照し、ゲーム開始前と都市を操作できる状態を区別する。都市を開いていない間の都市 API、エポック実行中の再実行、ゲーム中のシナリオ地形編集など、実行できない操作はコアが拒否する。

## 通常セーブとシナリオ

通常セーブは都市の続きを、シナリオは新しいゲームの開始点を表す。どちらも地形を含む都市を `.cg` として保存する。シナリオからプレイを始めても元のシナリオは上書きせず、新しいセーブとして扱う。シナリオそのものの編集とは区別する。

一覧にあることと読み込めることは同じではない。フロントはコアが返す互換性・所有状況・編集可否を表示し、独自に判定し直さない。シナリオ一覧の並び順もコアが決めるため、フロントは受け取った順で表示する。保存時刻は実時間で、都市内の日付とは別である。[バージョニングと互換性](バージョニングと互換性.md)も参照する。

シナリオの管理元、公式性、必要な DLC は別の属性である。編集できるのは自作のシナリオだけで、ゲームに同梱したものとストアが管理するものは読み取りだけを行う。作者名や置き場所から公式と判断せず、必要な DLC の有無もコアの判定を使う。紹介文などの多言語データは[UI共通基盤](UI共通基盤.md)に従う。シナリオのクレジットは提供元が指定する文面なので、多言語データにせず原文のまま表示する。

## プレイモード

| モード | 操作の文脈 |
| --- | --- |
| 通常 | 都市を運営する |
| シナリオ | 都市や開始条件を制作・編集する |
| チュートリアル | 教材の案内に沿って操作する |
| 読み取り専用 | 都市を変更せずに観察する |

プレイモードはセッションに属し、セーブに固定された属性ではない。UI は共有状態からモードを参照して操作の入口を切り替え、許可の最終判断はコアに任せる。チュートリアルを終えた都市は通常プレイとして続けられる。

## 保存する状態と表示の状態

建設プロジェクトのタグや市民の追跡リストは都市の記録である。一方、カメラでの追従、個体の非表示、描画中の天気などは演出・操作の状態として扱う。具体的な表示状態の寿命は[Unity表示モード](Unity表示モード.md)に従う。

保存画像は Unity または作者が用意し、UI がコアの保存と連携させる。フロントが `.cg` を直接組み立てることはない。また、ロードして都市が戻ってもすべての統計が計算済みとは限らず、ヒートマップは次のエポックまで空になり得る。未計算と0を区別して表示する。
