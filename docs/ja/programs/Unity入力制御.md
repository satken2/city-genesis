# Unity入力制御

Unity の入力基盤は、3Dビューの操作を対象と編集中の目的に応じて届ける。入力の意味を決める入力モードと、見せ方を決める[表示モード](Unity表示モード.md)は別の責務である。

## 入力と編集の分担

入力は共通の窓口で受け、対象の種類ごとの入力ハンドラへ配送する。ハンドラは詳細表示の通知や編集マネージャへの委譲を行い、編集中の形状・選択・プレビューは編集マネージャが持つ。

入力モードは対象の種類ごとに持つ。同じ対象でも編集中の目的によりクリックの意味が変わり、操作対象でない種類は入力を奪わないようにする。これらをまとめて切り替える単位がモードプリセットである。

## 選択とカメラ操作

クリックとドラッグは共通の判定で区別し、一度の操作が編集とカメラ移動の両方へ届かないようにする。編集ハンドルや画面に重ねた対象の選択も、この入力の調停に参加する。

UI 上の操作、カメラ操作、通信の喪失、チュートリアルの制限などによる入力停止は、入力モード自体の変更と区別する。停止時に保留中の操作を捨て、再開後に古いクリックが確定しないようにする。観察用のカメラモードも、都市を編集するステートとは分けて扱う。

## UI との境界

UI は編集ステートと初期条件を指示し、Unity が入力・表示・編集状態をまとめて切り替える。形状の正は Unity に置き、パネルの数値入力も3D操作と同じ編集処理へ反映する。状態の通知、確定送信、取消しの責務は[IPC連携](IPC連携の整理.md)に従う。

フロントのプレビューは操作を助けるためのもので、確定の可否の正はコアにある。推定による警告をコアの確定的な制約と同一視しない。吸着や配置にも[共有の座標と高さ](../geometries/A_パス形状.md)を使い、描画上の位置から別の定義を作らない。
